# 讓別人跑完整任務，修正後再測一次

能自己點通，不代表第一次使用的人知道怎麼做。本堂把登入、長列表、詳情、確認、Swap與滾動放進同一套任務測試。你會先寫預期，再記實際，挑出問題、修正並重跑，最後以新任務驗收獨立能力。

## 開始前，先找到材料與起點

前堂Login與返回已指向List Long，SCROLL-01能捲到底，Confirm和Swap均可開。缺任何一項先按表中回修位置補，不把測試簡化成只有一個Overlay按鈕。

先開啟[本堂起始材料（HTML）](../../courses/uiux-designer/assets/B6-prototype-task-test/START-HERE.html)，讀取輸入與圖層名稱；操作在你的 Figma 檔或本堂指定工具完成。完成後到[本堂完成檢查表（可儲存／下載）](../../courses/uiux-designer/assets/B6-prototype-task-test/reference/TASK-TEST-FORM.html)記錄實際結果。

## 先檢查起點，不在測試中教人怎麼點

給受測者任務：「你是工作室行政人員，找到『整理交付包』，檢視期限，把它標記完成，再確認狀態。」不說「點左邊第二個綠色Button」。只給Preview連結、任務文字與示範資料；測試者記錄，不代操作。

如果無法邀請他人，先做作者自測並明記「本人自測」，仍可發現連線問題；但不能據此寫成他人已理解或真人試跑通過。公開分享前依自己的帳號確認Prototype view權限；不能編輯不代表不能預覽。

## 完整測試步驟：先寫預期，後填實際

| 編號／起點 | 操作任務 | 預期結果 | 需要觀察 |
|---|---|---|---|
| T01／Login | 進入待處理清單 | 看見List Long與三筆主資料 | 起始點、Button熱區、目的地 |
| T02／List Long | 找到T01並檢視期限 | Detail是T01，期限今天18:00 | Row能點、內容不是T02 |
| T03／Detail | 開確認、取消 | 先見Confirm，取消只回Detail | 背景仍在、沒有跳Login |
| T04／Detail | 再開確認並確認完成 | List Done：T01已完成、Toast結果 | 狀態文字與結果可辨認 |
| T05／List Long | 捲至最後一筆 | 能讀完整列，Header／Nav／FAB固定 | 中段／底部、不只第一屏 |
| T06／Detail | 開說明選單→檢視說明→關閉 | Menu換Help、最後回Detail | Swap來源是已開Overlay |
| T07／List Long | 找T02、看期限、返回 | T02詳情，回長清單 | 不同資料、返回目的地 |
| T08／Horizontal分支 | 左右滑動三張卡片 | 第一與最後一張都可看完 | 外框354、內容624 |

T04後可重啟TASK-01回待處理流程；T05及T07不假設List Done有相同長列表。這個原型用Frame模擬狀態，重新開始會回預設資料，需要在測試紀錄說明。

## 示範：一筆紀錄要能支援修復

講師故意把T01 Row的Destination改成None，執行T02。完整示範紀錄如下；這是課堂示範，不是代填你的實際結果。

| 欄位 | 示範值 |
|---|---|
| Expected預期 | 點T01看到Screen / Detail |
| Actual實際 | 點選後仍停在Screen / List Long |
| 操作證據 | Preview停在List；Interactions的Destination=None |
| 判斷 | 熱區被觸發，但沒有有效目的地 |
| 修復 | 選Row / T01，把Destination改為Screen / Detail |
| 回歸 | 從Login重跑T01→T02→T03→T04，確認沒有影響取消與完成 |

「怪怪的」「應該可以」不能支援下一步修正。寫下具體畫面、哪個動作與可見結果，才知道問題來自內容、熱區、連線、狀態或佈局。

## 跟著做：測試、排序、修復與回歸

1. 開啟[任務測試表](../../courses/uiux-designer/assets/B6-prototype-task-test/reference/TASK-TEST-FORM.html)，先讀每列預期。填受測者、日期、Figma檔／Preview連結與畫面尺寸。
2. 依T01–T08執行，每一步記實際結果、停在哪裡、受測者怎麼理解、有沒有給提示。若給了提示，記「提示後完成」，不能改寫成獨立完成。
3. 挑出三類問題：阻斷（不能完成，如Destination None）、主要（能完成但容易誤解，如確認後沒有狀態文字）、較小（不影響完成的視覺一致性）。先修阻斷，不先修圓角。
4. 每個問題對應回修位置：Layout回第03／07／13堂，Component回第04／05堂，目的地回第10堂，Overlay回第12堂。寫現象與具體層名，不只寫「請工程師修」。
5. 修後跑直接受影響那一步，再從Login重跑整條任務；涉及滾動時額外跑T05，涉及Swap時額外跑T06。留修改前後記錄，不覆蓋失敗。
6. 下載檢查表JSON，另存截圖，請另一位同學只讀記錄指出你修了什麼。記錄要能讓人重現，不能只有全部勾選。

## 整合作品：新情境下獨立完成

將工作室任務改成「活動報名確認」。下載[12筆虛構報名資料CSV](../../courses/uiux-designer/assets/shared/SIGNUP-DATA.csv)，以id對應姓名、備註與狀態。S02與S10是長備註，S12用來檢查最後一列；手機360×800；確認說明改為「將此報名標記為已確認」。沿用元件與已學方法，獨立完成List、Detail、可取消Dialog、成功回饋、長內容與固定導覽。選一筆不同資料作測試，不照原T01逐字複製。

完整參考結果是本課主線作品：請比對[主線畫面示意](../../courses/uiux-designer/assets/shared/screens-reference.svg)與[本地可操作網站參考](../../courses/uiux-designer/web-starter/index.html)。網站只示範部分核心流程，第16堂會解釋與完整Figma原型的差異；它不能替你證明Figma連線已經成功。

| 評分項目 | 可觀察判準 | 分數 |
|---|---|---|
| 內容與視覺 | 色彩／字型有角色，長備註可讀，狀態有文字 | 20 |
| 元件與版面 | 來源可更新，狀態可選，長列／增刪不重疊 | 20 |
| 任務流程 | 起點→List→正確Detail→Dialog取消／確認→結果 | 25 |
| 滾動與回饋 | 到最後一筆，固定導覽不遮擋；回饋可辨認 | 15 |
| 測試與交付 | 實際結果、問題、修復、完整回歸與可重開檔 | 20 |

達80分且沒有阻斷任務才算通過；有阻斷就回該操作單元修復再測。無效連線、無法看最後一筆、取消離開錯誤畫面、確認後沒有結果都屬阻斷或必要功能缺失，不能用其他項目高分抵消。請說明兩項取捨（例如長按鈕改垂直、用Instant降低動態負擔），不是只複製樣式。

## 常見測試誤判

只錄畫布箭頭，沒有Preview：補實際點選；只重跑修過的Row，沒驗取消：補完整迴歸；想把未執行欄勾完：寫原因與補測位置；同學無法開啟：檢查分享權限或用同一裝置Preview，但記明測試方式。下一堂將這份修正版與測試紀錄放進交付包。

## 自己完成：改變條件再檢查

由同學選一筆你不知道的任務執行，並故意從Detail直接開始測返回。再依上述整合作品的新情境做360版本，減少講義提示，自行選擇版面與回饋。交出一次無提示或明記提示的紀錄、至少一個修復前後比較與完整回歸；沒有受測者時明記本人自測，另留他人測試待辦。

## 完成條件與理解檢查

- T01–T08都有實際觀察或明確未執行原因，包含長列表與前課固定元素成果。
- 至少一個真實或刻意植入故障有定位、修復與從Login開始的迴歸。
- 整合作品符合新情境、360限制、可取消確認與結果，評分≥80且沒有阻斷。

**想一想：**點選T01修好後，為什麼還要測取消與確認完成？
