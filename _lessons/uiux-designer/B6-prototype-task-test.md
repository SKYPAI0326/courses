# 用任務測試找出問題，修正後再測一次
副標：工作室行政人員要完成一筆待辦，你要暫時放下作者視角，找出流程中真正讓操作停住或猶豫的地方。
本堂完成物：一份完整的單人任務測試紀錄；一個問題的修正前後比較；完成評分與重測的報名確認 App

## 從能捲到底的完整流程開始

工作室待處理清單已經能從登入進入長清單，再前往詳情、開啟確認彈窗、取消或完成任務。頁首、底部導覽與漂浮按鈕也能在長清單中保持合適位置。畫面都連起來後，接下來要回答的問題不再是「有沒有連線」，而是行政人員只看任務時，是否知道該從哪裡開始、每一步代表什麼、最後是否真的完成。

這堂會用上次完成的登入、長清單、詳情、確認與完成結果進行單人測試。先從[本堂起始材料](../../courses/uiux-designer/assets/B6-prototype-task-test/START-HERE.html)確認測試起點，再開啟[任務測試紀錄表](../../courses/uiux-designer/assets/B6-prototype-task-test/reference/TASK-TEST-FORM.html)填寫每一步的預期、實際與修復結果。一路做好的報名確認 App 則使用[整合作品評分表](../../courses/uiux-designer/assets/B6-prototype-task-test/reference/CAPSTONE-SCORE.html)，在修正後重新計分。

## 測試時，暫時忘記答案

設計畫面的人很熟悉每個按鈕與連線，因此很容易把「我知道怎麼點」誤認為「畫面有說清楚」。單人測試的目的，是用時間間隔、任務卡與逐步紀錄拉開距離，讓熟悉感少一點，讓猶豫、點錯與看不懂的文字浮出來。

第一個工具是任務卡。任務卡只寫要完成的工作，不寫按鈕位置或操作順序。例如：「找到『整理交付包』，看期限，把它標記完成。」這句話交代資料、資訊與結果，卻沒有透露該點哪一列、哪個顏色或哪個圖示。回來測試時，你只能依畫面提供的線索做決定。

第二個工具是時間間隔。寫完任務卡後先暫停操作，至少休息一段時間，最好隔天再回來。重新開始時只打開任務卡與 Preview，邊操作邊把想法說出來。例如：「我在找期限」「這兩個按鈕看起來都像完成」「我以為取消會回清單」。同時記下停頓位置、第一次點錯的地方與看不懂的字。

第三個工具是走查清單。完成任務後，再逐畫面檢查容易漏掉的固定問題：按鈕文字有沒有動詞、目前在哪一頁是否看得出來、錯誤訊息有沒有說明修法、取消後是否回到原處、最後一筆是否看得到。任務操作反映自然行動，走查清單則補上系統性的檢視，兩者一起使用會比反覆隨手點擊更有方向。

找到問題後要先分級，因為修正順序會影響能否繼續測：

| 等級 | 判斷方式 | 例子 | 處理順序 |
|---|---|---|---|
| 做不下去 | 任務無法走到下一步或結果錯誤 | 點「整理交付包」卻進入另一筆詳情 | 先修，修後立即重測 |
| 做得到但容易誤會 | 可以完成，但需要猜測或走冤枉路 | 確認後沒有清楚的狀態文字 | 第二順位修正 |
| 小問題 | 不影響完成，但降低一致性或閱讀品質 | 同類卡片的圓角不一致 | 核心流程穩定後再修 |

例如，按鈕圓角不一致很顯眼，卻不一定會阻止任務；目的地連錯則會讓流程直接中斷。先修做不下去的問題，才能讓後續步驟有可測的路徑。修完也要先重做受影響的那一步，再從登入重跑整條任務，確認修正沒有改壞取消、確認、捲動或完成結果。

## 示範：用一張任務卡完成一次測試循環

先看本堂規格表。這張表集中測試範圍、紀錄欄位與合格門檻，操作時依名稱填寫即可。

| 項目 | 主線設定或內容 | 完成時看得到什麼 |
|---|---|---|
| 任務卡 | 「找到『整理交付包』，看期限，把它標記完成」 | 只有目標，沒有點擊提示 |
| 起點 | 登入畫面，流程名為「完成一筆任務」 | Preview 從登入開始 |
| 主要路徑 | 登入 → 長清單 →「整理交付包」詳情 → 確認彈窗 → 完成清單 | 每一步都對應同一筆任務 |
| 期限 | 今天 18:00 | 詳情畫面能讀到明確期限 |
| 取消路徑 | 詳情 → 確認彈窗 → 取消 → 原詳情 | 背景資料與狀態保持原樣 |
| 完成路徑 | 詳情 → 確認彈窗 → 確認 → 完成清單 | 狀態文字與成功結果可辨認 |
| 長清單檢查 | 中段、底部、最後一筆 | 固定元素留在原位，資料可讀可點 |
| 橫向檢查 | 三張卡片的第一張與最後一張 | 左右滑動後都能完整看見 |
| 紀錄欄位 | 預期、實際、猶豫或點錯、問題等級、修正、重測 | 每個問題都能回到具體畫面與設定 |

1. 在任務測試紀錄表填入日期、作品檔名與畫面尺寸；表單上會留下這次測試的基本環境。
2. 寫下任務卡「找到『整理交付包』，看期限，把它標記完成」；任務文字會只描述目標。
3. 關閉設計畫面並暫停操作一段時間；再次打開時不會緊接著剛才的連線記憶。
4. 回來後按 Shift+Space 開啟 Preview；編輯器內會顯示原型預覽。
5. 從「完成一筆任務」流程開始；畫面會回到登入起點。
6. 只看任務卡進行第一個動作；你會依登入畫面的主要按鈕判斷入口。
7. 每次猶豫時立刻說出原因；紀錄表會留下當下看到的字與你的判斷。
8. 點選「整理交付包」；詳情應顯示同一筆任務與今天 18:00 的期限。
9. 開啟確認彈窗後先選取消；畫面應回到原本的任務詳情。
10. 再次開啟確認彈窗並完成任務；完成清單會顯示這筆任務的狀態與成功結果。
11. 回到長清單並捲到最後一筆；頁首、底部導覽與漂浮按鈕會維持位置。
12. 左右滑動橫向卡片；第一張與最後一張都會完整進入視窗。

完整走完後，再用走查清單逐畫面看一次。若某一步發生問題，請寫「點了什麼、原本預期什麼、實際去了哪裡或看見什麼」。像「點『整理交付包』後出現第二筆詳情」就能回到目的地檢查；只寫「怪怪的」則無法知道該修文字、熱區、目的地或狀態。

示範一個可控制的故障。先在紀錄表寫下「整理交付包」原本連到的詳情畫面，再把目的地故意改成第二筆任務的詳情。從登入開始操作時，畫面會顯示錯的內容。依序檢查熱區、觸發、動作、目的地與起點，找到目的地不符後改回原本詳情。修正後先重做點選該列，再從登入跑過取消、確認與完成結果。

這個故障練習直接在現有檔案中完成，並且在修改前先寫下原值。它的重點是練習用紀錄找回正確設定，再驗證修正影響，而不是靠記憶猜原本連到哪裡。

## 跟著做：從紀錄、分級到完整重測

你已經看過一次完整循環，現在以較少提示完成自己的測試。每一步先決定要確認的結果，再到 Preview 或編輯器找相應位置。

1. 先為工作室流程寫一張只有目標的任務卡；完成後，讀者看不到任何按鈕位置或操作順序。
2. 安排一段與設計操作分開的時間；回來時，只保留任務卡與 Preview 在眼前。
3. 從登入開始操作，並把每次停頓說出來；紀錄中會留下你當下看不懂的內容。
4. 完成「整理交付包」的期限查看、取消與確認；每一條路徑都會有預期與實際結果。
5. 在長清單中段與底部停下；紀錄中會分別出現固定元素與最後一筆的觀察。
6. 用走查清單逐畫面檢查文字、位置、錯誤修法、取消結果與最後一筆；自然操作沒碰到的項目會在這裡補齊。
7. 把問題放進三個等級；清單最上方會是阻止任務繼續的項目。
8. 選一個最嚴重的問題回到對應圖層或互動；修正前後值會寫在同一筆紀錄裡。
9. 先重做受影響的那一步；畫面會顯示新的直接結果。
10. 再從登入重跑整條任務；取消、確認、長清單與完成結果都會有新的重測紀錄。
11. 下載紀錄 JSON，再用表單的載入功能開回來；原先填寫的內容應重新出現在欄位中。

如果修正的是文字，重測時仍要確認按鈕是否可點與結果是否正確。如果修正的是目的地，重測時還要確認取消會回原處、確認會更新正確任務。一次修正可能改變後續畫面，因此「受影響的一步」與「整條任務」都要跑，兩者解答的問題不同。

## 看兩份測試紀錄，判斷哪一份能幫你修正

版本一寫：「清單有點難用。後來有完成。按鈕可能要更清楚。」它沒有記錄在哪個畫面停下、點了什麼、看見哪個結果，也沒有說明修正後重跑了哪些路徑。

版本二寫：「從登入進入長清單後，我先點了『確認活動報名資料並補上聯絡電話』，因為它與『整理交付包』使用相同的強調樣式。回到清單後點『整理交付包』，詳情顯示期限今天 18:00。修正兩列的文字層級後，我從登入重跑，取消回原詳情，確認後進入完成清單。」

哪一份紀錄比較能支持下一步修正？請從「位置」「行動」「可見結果」「重測範圍」四個角度判斷。

<details><summary>看判斷理由</summary><p>版本二較好。它指出發生問題的畫面、第一次選擇、造成誤會的視覺線索、正確內容與修正後重跑範圍，因此可以回到具體圖層調整，也能判斷修正是否影響取消與確認。</p></details>

再看一組修正順序。版本一先統一所有卡片圓角，再處理點錯目的地。版本二先改回正確目的地並重跑整條任務，之後才整理圓角。哪個順序更合適？

<details><summary>看判斷理由</summary><p>版本二較合適。連錯目的地會讓任務做不下去，應優先恢復流程；圓角差異屬於不影響完成的小問題，可以等主要路徑通順後再處理。</p></details>

## 卡住時，從紀錄缺口回頭補

| 看到的現象 | 通常的原因 | 怎麼修 |
|---|---|---|
| 任務還沒開始就知道每一步 | 寫完任務卡後立刻測，作者記憶仍很鮮明 | 關閉設計畫面並隔開一段時間，回來只看任務卡 |
| 紀錄只有「成功」或「失敗」 | 沒寫點擊位置與畫面結果 | 補上畫面名稱、動作、預期、實際與停頓原因 |
| 點任務列後進入錯的詳情 | 互動的目的地連到另一筆資料 | 依熱區、觸發、動作、目的地、起點順序檢查並改回 |
| 修正後該步正常，後面卻出錯 | 只重做單一步驟 | 先確認直接結果，再從登入重跑取消、確認與完成結果 |
| 最後一筆仍看不完整 | 固定導覽遮住內容或安全空間不足 | 回到長清單調整末端空間，再測中段與底部 |
| 表單換電腦後沒有內容 | 只保存於原瀏覽器 | 下載紀錄 JSON，並用載入功能確認能重新開啟 |

## 換你做：報名確認 App

活動主辦單位的行政人員要在手機上找到一筆報名、查看備註、取消一次確認，再完成確認。你一路做好的報名確認 App 已包含十二筆資料、狀態標籤、長備註、彈窗、回饋與可捲動清單。現在把它當成整合作品，使用同一套單人測試方法找出一個問題，修正後重新測試。

要達成的條件：

- 寫一張只描述工作目標的任務卡，指定姓名與要完成的結果，不提示點擊順序。
- 隔開一段時間後，從報名 App 的起點開啟 Preview，邊做邊記下猶豫、點錯與看不懂的文字。
- 用固定走查清單檢查按鈕動詞、目前頁面、錯誤修法、取消結果與最後一筆。
- 至少記錄一個具體問題，標出等級、所在畫面、修正前後與重測結果。
- 修正後先重做受影響的步驟，再從起點重跑整條任務。
- 在整合作品評分表逐項操作後計分；每項符合完整條件得 5 分，未符合得 0 分。
- 總分達 80 分以上，而且沒有做不下去的問題，才完成這次整合作品檢查。

整合作品還要通過以下自我檢查：

- 360×800 的畫面中，張家豪與蔡庭安的長備註都能完整閱讀。
- 待確認與已確認都有文字，不只靠顏色區分。
- 從清單選定一筆後，詳情的姓名與備註對應同一筆資料。
- 確認彈窗顯示「將此報名標記為已確認」，取消後仍停在原詳情。
- 確認後顯示該筆已確認狀態與成功結果，沒有改到另一筆資料。
- 清單能捲到劉思妤那筆，固定元素也沒有遮住資料或動作。
- 測試紀錄 JSON 能重新載入，修正前後與重測內容都找得到。
- 評分表記下兩項設計取捨與理由。

<details><summary>真的卡住再看：提示</summary><p>先選一位有明確備註的人名來寫任務卡；操作時若找不到問題，就用走查清單逐畫面看文字、取消、結果與最後一筆，再從最嚴重的一項開始修。</p></details>

## 把問題變成可重測的修正

工作室流程現在不只是在編輯畫布上連得起來，還留下了一份能說明「在哪裡猶豫、改了什麼、改後是否仍走得完」的測試紀錄。報名確認 App 也經過同樣的任務操作、走查、修正與重測，評分表把內容、元件、流程、捲動、回饋與交付整理在同一個完成判準裡。

下一堂會把修正後的 Figma 檔、畫面輸出、規格表、測試 JSON 與圖像素材整理成交付資料夾。今天記下的畫面名稱、問題位置與修正結果，會成為接手說明的一部分，讓檔案重新開啟後仍知道從哪個流程開始、哪些路徑已經走過。

完成條件：

- 工作室流程有完整的任務卡、實際操作、走查、問題分級與重測紀錄。
- 至少一個問題保留修正前後，並從登入重跑取消、確認、長清單與完成結果。
- 報名確認 App 在 360×800 下完成單人測試與修正。
- 整合作品達 80 分以上，且沒有做不下去的問題。

想一想：目的地修正後，點一次任務列已經正確，為什麼還要從登入重跑取消與確認？

## 講師授課筆記（不進講義）

先用正文入口題檢查前提，再以短示範讓學員同步操作。每次核心狀態改變立即檢查；主要時間用於自行製作、同儕解釋、錯誤修復與新條件作品。先核對學員真實工具權限與檔案；未達完成條件回到本堂修復位置，不以教師代做當成完成。此稿為作者設計與自審，真人理解／遷移與平台實測須另留證據。
