## 教學流程（Teaching Flow）

> **course_type = skill-operation**：破題 → 概念 → 操作示範 → 動手練習 → 檢核。
> **本節完成物**：`視覺資產組-v1/`，包含可編輯來源檔、向量資產、社群圖卡、版面與來源說明。

### 破題 / Hook

阿凱拿到一張 AI 生成的氣氛圖，直接把它放大當成社群封面，再把所有服務說明塞進畫面。結果是：圖像細節放大後變模糊，主標與背景對比不足，來源紀錄也沒有跟著輸出檔保存。素材能放進畫面，不代表它已經是可交付的視覺資產。

阿凱回到 CH2-2 的訊息定位，確認這張圖卡主要要讓受眾理解「零散資料如何被整理成內容主題」。他把畫面拆成三個工作：用向量圖形表示流程關係，用影像或自製截圖提供內容證據，再用排版安排主標、步驟與 CTA。每個元素都要回答「它支持哪個受眾判斷」。

你要使用 Affinity 完成一組 `視覺資產組-v1/`。本單元重點是資產的用途、結構、來源、可編輯性與輸出條件。裝飾效果只在不影響訊息與可讀性時加入。

### 概念 / Concepts

#### 視覺資產

**視覺資產**是能在特定溝通位置重複使用、具有檔案來源與輸出條件的圖形、影像、版面或元件。它可以是 Logo、圖示、圖卡、縮圖、字幕底圖、流程圖或影片使用的畫面。

- **用途**：讓內容製作有可管理、可修改、可輸出的材料，而非每次從零開始拼貼。
- **正例**：可編輯的流程圖來源檔、輸出的社群圖卡、文字與來源說明都保存在同一資產組。
- **非例**：只保存一張壓縮後的截圖，沒有來源檔、字型、素材來源與使用位置。
- **你的判斷**：另一位同學能否找到來源、知道用途、修改主標並重新輸出？不能時，資產組不完整。

視覺資產的價值在於支持訊息與工作重做，不以裝飾數量或特效多寡判斷。

#### 向量圖形（vector）

**向量圖形**用路徑、節點與幾何關係描述形狀，放大或縮小時能維持邊緣清楚。它適合 Logo、圖示、箭頭、流程框、線條與簡化的幾何圖形。

- **用途**：建立可調整尺寸與顏色的形狀，支持流程、分類與品牌識別。
- **正例**：用三個可編輯的向量框表示「輸入 → 整理 → 產出」，每個框保留文字與顏色設定。
- **非例**：把一張低解析度的流程截圖放大後當成 Logo 或流程元件，邊緣模糊且無法單獨修改。
- **你的判斷**：能否只改一個節點、顏色或文字而不破壞其他元素？不能時，來源檔結構需要整理。

向量適合表達關係與形狀，不負責取代需要細節的照片或真實畫面。向量圖示也要遵守來源與授權紀錄。

#### 影像素材（raster image）

**影像素材**由像素組成，常見於照片、截圖、掃描與 AI 生成圖片。影像適合呈現質感、細節與實際畫面，放大超過原始解析度時可能失真。

- **用途**：提供受眾需要看到的實際材料、場景或畫面證據。
- **正例**：使用 CH2-4 建立的去識別資料表截圖，裁切成社群圖卡中的證據區塊。
- **非例**：將未確認來源的網路圖片當成客戶工作現場，或把小尺寸圖片放大到文字無法辨識。
- **你的判斷**：原始檔、來源、使用範圍與輸出尺寸是否足以支持這個畫面？不能時，換素材或降低它在畫面中的證據地位。

匯入影像前先看來源與用途。影像可作為示意時，保留示意標示；需要支持真實主張時，使用可查證材料。

#### 排版（layout）

**排版**是安排文字、圖形、影像、留白與閱讀順序的工作。它把訊息層級轉成受眾能掃讀的畫面結構。

- **用途**：讓受眾先看到核心訊息，再理解支援內容與下一步。
- **正例**：上方主標說明問題，中段流程圖提供證據，下方 CTA 指向服務說明；三層位置與字級有差異。
- **非例**：所有文字使用相同大小，Logo、主標、說明與 CTA 平排在同一層，受眾不知道先讀哪裡。
- **你的判斷**：縮小畫面或快速掃讀時，受眾能否指出主標、主要證據與 CTA？不能時，排版層級需要調整。

排版先處理閱讀順序，再處理美感。文字不能因為想放更多內容而縮到無法閱讀。

#### 元件與樣式

**元件**是可以重複使用的圖形、文字區塊、按鈕、標籤或版面組合；**樣式**是套用在元件上的顏色、字體、線條、間距與狀態規則。

- **用途**：讓同一套內容在多個版本中維持一致，降低修改與重做成本。
- **正例**：建立同一個 CTA 標籤元件，之後只改文字與連結位置；主標與步驟標籤使用固定字級與間距。
- **非例**：每一格都手動調整字距與顏色，下一版修改時同一個 CTA 出現三種大小。
- **你的判斷**：改一次樣式後，相關畫面能否同步維持一致？不能時，拆出可重用元件。

本單元不追求建立完整品牌系統，先讓一組課程資產具備可讀、可修改與可延伸的基本結構。

#### 輸出格式與來源檔

**來源檔**保留圖層、文字、向量路徑、影像位置與可修改設定；**輸出檔**是放進社群、影片或簡報的使用版本。兩者用途不同，應同時保存。

- **正例**：保存可編輯的 Affinity 來源檔，再輸出 PNG 圖卡與 SVG 向量資產，檔名含版本與用途。
- **非例**：只交一張 JPG，之後需要改字時無法找回文字與圖層，也不知道圖片來源。
- **你的判斷**：三個月後重新開檔，能否知道哪個是來源、哪個是輸出、哪個版本可放在哪個位置？不能時，補檔名與說明。

正式課要依課程端輸出檢核表確認格式、尺寸與壓縮條件。版本尚未鎖定時，在檔案說明中保留待確認欄位。

#### AI 生成圖像放入視覺資產

AI 生成圖像可以作為構圖草稿、氛圍背景或明確標示的示意元素。匯入 Affinity 後仍要保留 CH2-4 的來源與 AI 紀錄，並檢查畫面是否產生錯字、錯誤手指、虛構品牌或可能被誤認的真實場景。

- **適合**：作為不支持真實成果的背景或構圖參考，或在圖卡中明確標示「示意」。
- **需要替換**：畫面需要呈現真實客戶、實際產品、真實案例、真實數據或已承諾的成果。
- **操作結果**：匯入圖像後，在 `來源與限制.md` 中寫明工具、日期、主要指示、人工修正與使用範圍；若無法保留這些資訊，素材降級為參考，不進正式輸出。

### 操作示範 / Demo

#### 示範輸入與輸出

沿用 CH2-4 的素材取得紀錄與 CH2-2 的訊息定位：

- **核心訊息**：把零散資料整理成兩週可發布的內容主題與樣稿。
- **主要任務**：受眾理解。
- **畫面證據**：輸入資料、整理動作、三個內容主題、樣稿與檢查表。
- **輸出組**：`視覺資產組-v1/`
  - `source/內容整理流程-v1.afdesign`
  - `vector/流程箭頭與圖示-v1.svg`
  - `social/內容整理流程卡-v1.png`
  - `README.md`
  - `來源與限制.md`

檔案副檔名與實際版本依教室安裝的 Affinity 工具確認；上列是交付結構示例。

#### 示範操作

**步驟 1：建立來源檔與資料夾。**

先建立 `視覺資產組-v1/source/`、`vector/`、`social/` 三個資料夾。來源檔使用含版本的檔名，並在 `README.md` 寫出本組資產的主要任務與下游使用位置。

**步驟 2：設定畫布用途。**

建立社群圖卡畫布，填寫用途、預定尺寸與待確認格式。若平台格式卡尚未鎖定，使用課程端已驗證的工作尺寸，並在 README 保留來源與日期。

**步驟 3：先放核心訊息。**

把「有服務資料，卻不知道下一則內容要寫什麼？」放在第一閱讀位置。主標區留出足夠空間，避免先放 Logo、裝飾或背景圖。

**中間結果**：縮小畫布後仍能看到受眾問題；如果主標被背景吃掉，先調整對比與留白，不急著增加效果。

**步驟 4：建立向量流程元件。**

用向量圖形建立三個步驟框與箭頭：整理材料、分組主題、準備樣稿。每個框保留可編輯文字與固定間距，箭頭只表示順序，不增加無關裝飾。

**步驟 5：放入影像證據。**

匯入 CH2-4 的自製資料表示例或已確認素材，裁切成能看出欄位與主題的大小。若畫面是示意，保留「課程示例／示意」標籤。

**步驟 6：建立支援文字。**

在三個步驟旁補上短句，說明受眾從輸入到產出會看到什麼。文字內容沿用定位卡，不新增未確認的成果、數字或保證。

**步驟 7：放入 CTA。**

在下方建立 CTA 元件：「查看服務範圍與交付方式」。位置與文字要能在縮小畫面後被辨識；連結若未確認，在 `來源與限制.md` 標記待補。

**步驟 8：整理圖層與命名。**

將圖層依 `背景／核心訊息／流程圖／證據／CTA／備註` 分組。圖層名稱說明內容，不使用「圖層 1」「矩形 4」這類無法接手的名稱。

**步驟 9：建立向量輸出。**

將流程箭頭與圖示另存為可重用的向量資產，檔名為 `流程箭頭與圖示-v1.svg` 或依教室工具實際格式調整。來源檔與輸出檔分開保存。

**步驟 10：建立社群圖卡輸出。**

輸出 `內容整理流程卡-v1.png`。輸出前檢查文字、圖片、邊界、透明度與是否保留示意標籤；以課程端檢核表確認格式。

**步驟 11：完成來源與限制說明。**

把每一個外部或 AI 元素連回 CH2-4 的素材編號，列出來源、日期、使用範圍、人工修改與不可支持的主張。

**步驟 12：用受眾判斷驗收。**

縮小圖卡、關掉背景或遮住裝飾後，請同學回答：這張圖要給誰看？要理解什麼？哪一項證據支持主張？下一步在哪裡？

#### 示範完成品判斷

| 檢查項目 | 完成結果 | 修正方向 |
|---|---|---|
| 核心訊息 | 縮小後仍能讀到受眾問題 | 保留主標位置 |
| 向量流程 | 三個步驟框可各自修改 | 保留命名與間距規則 |
| 影像證據 | 能看見示例資料與內容主題 | 保留示意標籤與來源編號 |
| CTA | 動作與位置清楚，網址待補 | 不新增未確認連結 |
| 來源檔 | 圖層與來源說明齊全 | 交付 source 與 README |
| 輸出檔 | 用途與版本清楚 | 通過格式卡後再公開 |

#### 正例與非例

| 項目 | 正例 | 非例 |
|---|---|---|
| 主標 | 指出受眾問題與內容主題 | 只放品牌口號 |
| 向量 | 可修改的流程框與箭頭 | 放大模糊的流程截圖 |
| 影像 | 有來源、用途與示意狀態的資料表畫面 | AI 客戶成果圖當真實證據 |
| 排版 | 核心、證據、CTA 有明確閱讀順序 | 所有文字同大小同顏色 |
| 檔案 | 有來源檔、輸出檔、README 與來源限制 | 只交壓縮後 JPG |
| AI | 保存工具、日期、指示與人工修正 | 只說「AI 生成」沒有版本紀錄 |

### 動手 / Hands-on

請使用 CH2-3 的分鏡與 CH2-4 的素材來源紀錄，完成一組視覺資產。若 Affinity 尚未安裝或版本未驗證，先完成文字版版面規劃與資料夾結構，並依恢復路徑交付可檢查的中間成果。

#### 任務：完成視覺資產組-v1

成果資料夾：`視覺資產組-v1/`

**步驟 1：建立資產任務表。**

列出本組要支持的受眾、主要任務、核心訊息、下游位置與最少成果。先選一個社群／影片可共用的畫面，不要同時做完整品牌套件。

**步驟 2：核對素材來源。**

從 CH2-4 複製素材編號、檔名、來源與限制。狀態為待確認或不可使用的素材不得直接放入正式來源檔；先用文字框或自製示例替代。

**步驟 3：建立資料夾與來源檔。**

建立 `source/`、`vector/`、`social/` 與 `README.md`。來源檔名稱包含資產主題與版本，並記錄主要工具與課前鎖定的版本。

**步驟 4：設定畫布與版面區塊。**

畫出核心訊息、支援證據與 CTA 三個區域。先用灰階或低彩度檢查閱讀順序，確認主標與證據的優先級。

**Checkpoint 1**：縮小畫面到預覽大小，請同學指出主標、證據與 CTA。指出順序不一致時，先修排版。

**步驟 5：建立向量元件。**

製作至少一個可重用的流程圖形或圖示，使用命名、固定間距與可修改顏色。不要把流程關係壓成單張不可編輯圖片。

**步驟 6：放入一項影像證據。**

使用來源明確的自製、教師提供或 AI 示意素材。裁切與調整只服務畫面任務，不能讓證據變成無法辨識的背景。

**步驟 7：整理文字與 CTA。**

從定位卡複製核心與支援訊息，壓縮成適合畫面的字數。CTA 使用已確認文字；位置或連結未確認時，在畫面與 README 同時標記待補。

**步驟 8：建立元件與圖層命名。**

依內容用途命名圖層與群組，並保存一個可修改的文字版本。圖層命名要讓未參與製作的人能判斷用途。

**步驟 9：輸出向量資產。**

將流程圖形或圖示輸出成可重用格式，檔名與來源檔版本一致。輸出後重新開啟檢查文字、線條、透明背景與比例。

**步驟 10：輸出社群圖卡。**

依課程端已驗證的尺寸與格式輸出一個版本。未驗證的規格不自行宣稱固定，寫入待確認欄位並保留來源日期。

**步驟 11：補 README 與來源限制。**

README 寫明資產用途、檔案清單、下游位置、版本、修改方式與待確認項目；來源說明寫明素材編號、來源、日期、使用範圍、AI 紀錄與不可支持的主張。

**Checkpoint 2**：請同學接手來源檔，完成「改主標、換一個向量顏色、重新輸出」三個動作。任何無法修改或找不到來源的地方都要修復。

**步驟 12：完成訊息與輸出檢核。**

關閉裝飾層、縮小畫面、檢查無聲觀看與來源紀錄，再將狀態標成「可直接使用」「待確認」或「退回修正」。

## 常見錯誤 3 條（Common Pitfalls）

1. **錯誤現象**：畫面加入大量陰影、漸層與裝飾，核心訊息、證據與 CTA 變得難以辨識。
   **原因**：把視覺效果當成完成條件，沒有用訊息層級檢查畫面。
   **解法**：先關閉裝飾層，縮小畫面確認主標、證據與 CTA，再只保留支持閱讀與辨識的效果。

2. **錯誤現象**：只保存輸出的 JPG 或 PNG，沒有 Affinity 來源檔與圖層命名。
   **原因**：把一次性畫面當成可交付資產，後續無法修改尺寸、文字、向量或素材。
   **解法**：保留來源檔、輸出檔、README 與來源限制說明；依 `source/`、`vector/`、`social/` 分類並建立版本對照。

3. **錯誤現象**：AI 生成圖像被放在真實案例位置，檔案說明只寫「AI 圖片」。
   **原因**：沒有寫出生成圖支持的訊息與不能支持的主張，受眾可能把示意理解為真實成果。
   **解法**：標示 AI 示意並保存工具、日期、指示、修改與範圍；需要真實證據時改用可查證、已授權或自行建立的材料。
