## 教學流程（Teaching Flow）

> **course_type = skill-operation＋整合交付**：破題 → 概念 → 操作示範 → 動手整合 → 交付檢核。
> **本節完成物**：`可行銷內容組-v1/`，包含短影音、平面素材、來源紀錄、行銷判斷與可重做說明。

### 破題 / Hook

阿凱已經完成一支短影音、一張社群圖卡與多份過程文件。雯姊收到資料夾後卻無法直接使用：影片檔名看不出主版或短版，圖卡沒有說明適用位置，來源紀錄分散在不同檔案，行銷判斷只剩「畫面好看、可以提高曝光」。

阿凱需要把單件成果整理成一個可接手的內容包。接手者要知道這組內容給誰看、要完成什麼影像任務、各檔案如何配合、素材能否使用、使用時要注意什麼，以及如果工具或素材失效要從哪裡恢復。

本單元的任務是完成 `可行銷內容組-v1/`，再用一份行銷判斷說明回答：

- 這組內容要給誰看，處理什麼問題？
- 影片與平面素材各自完成哪一項任務？
- 哪些證據支持核心訊息？
- 哪些素材是示意、已授權或自行製作？
- 內容應放在哪個情境，下一步是什麼？
- 同學接手時如何開啟、修改、輸出與檢查？

### 概念 / Concepts

#### 可行銷內容組

**可行銷內容組**是一組能在指定受眾、使用位置與行動情境中被使用，且來源、版本、限制與交付方式清楚的內容資產。它可以包含短影音、圖卡、文字、素材紀錄與判斷說明。

- **用途**：把單件作品整理成可被使用、交接、修改與評估的工作包。
- **正例**：短影音與圖卡共用同一核心訊息，檔案名稱清楚，來源與 AI 紀錄可查，README 說明平台位置與 CTA。
- **非例**：資料夾裡有多張圖片與影片，但沒有用途、版本、來源與下一步；接手者必須重新猜測。
- **你的判斷**：換一位同學接手，他能否在 3 分鐘內說出這組內容做什麼、用在哪裡、怎麼驗收？不能時，交付包仍不完整。

內容包可以依出口不同而呈現為求職作品、企業專案、自由工作交付或個人品牌素材。共同要求是內容目的、可觀察成果與證據清楚。

#### 交付鏈

**交付鏈**是把上游判斷、製作成果、來源紀錄與下游使用方式連在一起的關係。Part 2 的交付鏈為：

```text
PRAC1 Brief
  → CH2-1 影像任務判斷表
  → CH2-2 影像定位卡
  → CH2-3 腳本與分鏡
  → CH2-4 素材取得與來源紀錄
  → CH2-5 視覺資產組
  → CH2-6 剪輯判斷表
  → CH2-7 Windows 本機影片
  → PRAC2 可行銷內容組
```

- **用途**：讓每個成果都有輸入與理由，發現問題時能回到正確節點修復。
- **正例**：影片 CTA 不清楚時，先查 PRAC1／CH2-2 的下一步與定位，再修 CH2-6 判斷與 CH2-7 時間軸。
- **非例**：只在最後加一個「歡迎洽詢」文字，沒有回看受眾情境與行動位置。
- **你的判斷**：每個輸出檔能否指出來自哪個上游判斷、交給哪個下游單元？不能時，補交付鏈說明。

#### 行銷判斷說明

**行銷判斷說明**是用受眾、問題、訊息、證據、渠道位置與下一步解釋內容選擇的文件。它不是成效保證，也不是「畫面好看」的感想。

- **用途**：讓內容使用者理解為什麼這樣製作、在什麼情況使用，以及要觀察什麼訊號。
- **正例**：「給第一次接觸工作室的小型團隊負責人；影片先說明零散資料整理流程，圖卡補上輸入／成果，CTA 引導查看服務範圍；觀察受眾是否能指出服務處理什麼與下一步位置。」
- **非例**：「風格清新，應該可以提升曝光與轉換。」沒有交代受眾、證據、位置與可觀察結果。
- **你的判斷**：讀者能否依說明選擇使用影片或圖卡，並指出要檢查的行為？不能時，說明仍然是感想。

行銷判斷應使用可以在課程或工作中取得的證據，例如受眾能否重述訊息、是否找到 CTA、是否能辨識流程與交付物。不能承諾未測量的觸及、轉換或營收。

#### 一致性檢查

**一致性檢查**是比較不同資產是否共同使用同一組受眾、問題、核心訊息、證據與 CTA。它不要求所有素材長得一樣，而是要求訊息與行動不互相矛盾。

| 檢查項目 | 短影音 | 平面圖卡 | 說明 |
|---|---|---|---|
| 受眾 | 小型團隊負責人 | 相同 | 不在不同資產間任意換受眾 |
| 核心訊息 | 零散資料整理成主題與樣稿 | 同一主張的流程／成果摘要 | 可改寫句子，但不改變主張 |
| 證據 | 輸入、整理、成果 | 流程圖與資料表示例 | 都能連回同一工作 |
| CTA | 查看服務範圍與交付方式 | 同一位置或對應文字 | 依畫面形式調整表達 |
| 限制 | 示意標籤、來源 | 同上 | 不把 AI 示意變成真實案例 |

一致性檢查發現差異時，先判斷是平台轉譯，還是主張改變。平台轉譯可保留；主張改變要回到定位卡與 Brief 修正。

#### 使用位置與行動

**使用位置**是內容出現的渠道、情境或交付場合；**行動**是受眾看見內容後可採取的下一步。內容包要寫清楚兩者，才能被正確使用與驗收。

- **正例**：短影音用於第一次接觸的社群貼文，圖卡用於貼文輪播或提案附件，兩者都引導查看服務範圍。
- **非例**：同一張圖卡同時標註「社群封面、廣告素材、提案頁、網站首圖」，卻沒有檢查尺寸、語境與 CTA。
- **你的判斷**：使用者能否依 README 選出一個檔案放到指定位置，並知道受眾下一步？不能時，補使用條件。

本單元不要求學員真的上傳外部平台或花費廣告預算。要完成的是可使用的資產、位置判斷與可驗證的行動設計。

#### AI 在整合交付中的角色

AI 可協助做內容版本比較、字幕草稿、命名建議、README 初稿或檢查表整理。它提供加速與比較材料，不能替代受眾判斷、來源確認、實際輸出檢查與交付責任。

- **可使用**：比較 30 秒與 15 秒版本的訊息保留、把來源紀錄整理成表格、檢查 README 是否缺少欄位。
- **需人工確認**：核心主張、客戶案例、數字、素材授權、AI 示意標籤、CTA 連結與輸出能否播放。
- **紀錄要求**：保存工具、日期、輸入範圍、提示詞／指示、採用內容、人工修改與未採用原因。

可使用的提示詞示例：

```text
請依下列內容包資料，建立一份交付檢查清單。
檢查欄位：受眾、核心訊息、短影音、平面素材、來源、AI 紀錄、CTA、檔名、版本、使用位置、恢復路徑。
限制：只能整理已提供的資訊；不可新增成效數字、客戶成果、授權結論或平台規格。
內容包資料：＿＿
```

### 操作示範 / Demo

#### 示範輸入

阿凱的上游成果如下：

- `影像任務判斷表-v1.md`：主要任務為受眾理解，次要任務為品牌認知與行動促成。
- `影像定位卡-v1.md`：核心訊息為把零散資料整理成兩週可發布的內容主題與樣稿。
- `腳本與分鏡表-v1.md`：30 秒主版、15 秒短版，流程角度。
- `素材取得與來源紀錄-v1.md`：自製資料表、課程示例圖卡、AI 構圖示意，AI 圖僅作構想。
- `視覺資產組-v1/`：流程向量、社群圖卡、README、來源限制。
- `剪輯判斷表-v1.md`：主版／短版取捨、無聲檢查與 CTA。
- `短影音-v1/`：可重開專案、主版影片、短版影片、字幕與輸出檢核。

#### 示範整合步驟

**步驟 1：建立交付資料夾。**

建立：

```text
可行銷內容組-v1/
├─ 01-video/
├─ 02-visual/
├─ 03-source/
├─ 04-decision/
├─ 05-readme/
└─ 06-verification/
```

每個資料夾只放對應成果。來源檔與輸出檔不混在同一層，README 會建立完整對照。

**步驟 2：整理影片交付。**

將 `短影音-v1/export/` 的主版與短版複製到 `01-video/`，將可重開專案與必要素材路徑說明放在 `01-video/project/`。檔名包含用途與版本，例如 `內容整理流程_main-v1.mp4`、`內容整理流程_short-v1.mp4`。

**步驟 3：整理平面資產。**

將 `視覺資產組-v1/vector/` 與 `social/` 複製到 `02-visual/`，保留來源檔在 `02-visual/source/`。README 標示每個圖卡適用位置與限制。

**步驟 4：集中來源紀錄。**

把素材取得紀錄、AI 紀錄、音訊來源、示意標籤與使用條件放入 `03-source/`。若 AI 圖只作構想，寫入不可支持的主張，避免後續使用者把它當成真實案例。

**步驟 5：集中行銷判斷。**

將影像任務、定位、腳本、剪輯取捨與行銷判斷說明放入 `04-decision/`。每份文件開頭寫出用途與上／下游關係。

**步驟 6：建立 README。**

README 先寫受眾與核心訊息，再列檔案清單、使用位置、CTA、來源限制、工具版本、恢復路徑與驗收方式。讀者先看 README 就能決定從哪個檔案開始。

**步驟 7：做一致性檢查。**

將影片、圖卡與說明中的受眾、核心訊息、流程、成果與 CTA 逐項對照。若短影音說「兩週可發布」，圖卡不能改成「立即提升營收」；若一項素材是 AI 示意，三處說明都要保持相同狀態。

**步驟 8：做檔案與路徑檢查。**

在另一個個人資料夾複製整個 `可行銷內容組-v1/`，依 README 開啟影片與圖卡，檢查專案是否能找到素材。原始資料夾不動，避免把可恢復版本覆蓋。

**步驟 9：做受眾檢查。**

請同學只看影片與圖卡，不看說明，回答受眾、問題、服務處理方式、成果與 CTA。將回答與行銷判斷說明比較。

**步驟 10：做來源與 AI 檢查。**

任選兩項素材追到來源，確認使用條件、修改、示意狀態與可用範圍。AI 內容不能以「AI 生成」四字結束紀錄。

**步驟 11：做版本檢查。**

檢查主版與短版是否保留核心訊息、必要證據與 CTA；平面資產是否具備來源檔與輸出檔；檔案名稱是否區分用途與版本。

**步驟 12：建立修正版與驗收紀錄。**

將同儕指出的問題整理成 `06-verification/修正紀錄-v1.md`，只修正可被證據支持的問題。更新 README 的版本與狀態，不刪除原始可恢復檔案。

#### 示範行銷判斷說明

```markdown
# 行銷判斷說明 v1

## 受眾與情境
第一次接觸弄一下行銷工作室、手上有零散服務資料的小型團隊負責人。

## 內容任務
主要任務是受眾理解：讓對方知道零散資料如何被整理成內容主題與樣稿。
次要任務是品牌辨識與行動促成：看見工作室名稱，並查看服務範圍與交付方式。

## 資產分工
- 短影音：用流程與畫面變化說明輸入、整理與產出。
- 平面圖卡：在社群貼文或提案附件中快速呈現三段流程與成果。
- README：說明使用位置、版本、來源與恢復方式。

## 可觀察驗收
- 同學能說出服務處理什麼問題。
- 同學能指出輸入、整理與產出的證據。
- 同學能找到 CTA 與服務說明位置。
- 接手者能依 README 開啟檔案、追到來源並知道示意素材限制。

## 限制
AI 生成畫面只作構想或示意，不支持真實客戶成果；未確認的連結、數字與外部授權不進正式主張。
```

#### 正例與非例

| 項目 | 正例 | 非例 |
|---|---|---|
| 資產組 | 影片、圖卡、來源與判斷共同使用一個核心訊息 | 每個檔案各自說不同服務 |
| 行銷說明 | 說明受眾、問題、證據、位置與下一步 | 只寫畫面好看、應該增加曝光 |
| README | 接手者能找到檔案、工具、來源與恢復方式 | 只有檔案名稱，沒有用途 |
| AI | 記錄用途、工具、日期、人工修改與限制 | 只在檔名加 AI，沒有真實性判斷 |
| 驗收 | 同學依檔案完成播放、理解與接手 | 製作者口頭補充後才看得懂 |

### 動手 / Hands-on

請整合 PRAC1 與 Part 2 的成果，完成一組自己的 `可行銷內容組-v1/`。你可以使用求職作品、企業專案、自由工作或個人品牌／微型創業等應用情境；受眾、問題、成果與下一步要保持具體。

#### 任務：完成可行銷內容組-v1

**步驟 1：建立上游清單。**

列出你實際使用的 PRAC1、CH2-1、CH2-2、CH2-3、CH2-4、CH2-5、CH2-6、CH2-7 檔案與版本。缺少的檔案標記待補，不用口頭說明代替。

**步驟 2：確認共同 Brief。**

寫出受眾、問題、核心訊息、可交付成果、主要影像任務與 CTA。若影片與圖卡使用不同版本，先修正共同 Brief 或標記版本差異。

**步驟 3：建立六個交付資料夾。**

建立 `01-video/`、`02-visual/`、`03-source/`、`04-decision/`、`05-readme/`、`06-verification/`，將檔案依用途複製。保留上游原始位置，不移動或覆蓋原檔。

**步驟 4：整理影片。**

放入主版、短版、專案檔與字幕／文字，檔名含用途與版本。播放一次，記錄目前狀態與待修正項目。

**步驟 5：整理平面資產。**

放入圖卡輸出、向量資產、可編輯來源檔與 README。檢查圖卡與短影音的核心訊息、受眾與 CTA 是否一致。

**步驟 6：整理來源與 AI。**

集中素材取得、音訊、外部素材與 AI 紀錄。每個 AI 元素補用途、日期、工具、主要指示、人工修改、使用範圍與不可支持的主張。

**Checkpoint 1**：任意選兩個輸出檔，能否追到共同 Brief、分鏡、素材來源與版本？不能時，先補檔案對照表。

**步驟 7：撰寫行銷判斷說明。**

用受眾、問題、內容任務、資產分工、使用位置、CTA、可觀察驗收與限制完成一頁說明。避免用「提升曝光」「增加轉換」取代具體觀察方式。

**步驟 8：撰寫 README。**

README 列出開始閱讀順序、檔案清單、工具與版本、使用位置、輸出狀態、來源限制與恢復路徑。讀者不應需要問你「這個檔案是做什麼的」。

**步驟 9：做一致性檢查。**

比較影片、圖卡、README、來源與行銷說明中的受眾、主張、證據、CTA、AI 狀態與限制。將不一致內容分成平台轉譯、版本差異或錯誤。

**步驟 10：做接手檢查。**

把整個資料夾複製給同學，不提供口頭說明。請同學完成播放、指出訊息、找來源、辨識示意、找到 CTA 與說明恢復方式。

**Checkpoint 2**：同學若在 3 分鐘內仍找不到主版、來源或下一步，優先修正 README 與資料夾結構，再修視覺效果。

**步驟 11：修正一個可驗證問題。**

依同學回饋選一個問題修正，例如補 CTA 位置、改檔名、補來源、修正字幕或更新 README。記錄修改前後與理由，不一次更動無法追蹤的多個變因。

**步驟 12：封存可交付版本。**

將資料夾標成 `可行銷內容組-v1`，完成 `06-verification/自我檢查-v1.md` 與 `修正紀錄-v1.md`。保留原始素材、來源檔與最後輸出，確認下一個社群單元可讀取 PRAC2 的 Brief、短影音、圖卡與判斷說明。

#### 恢復路徑

- **缺少某個上游檔案**：在 README 標記缺少的單元與影響範圍，使用本檔內嵌示例完成資料夾結構；缺少的影片／圖卡不得標成已完成。
- **影片能播放但來源不完整**：保留輸出檔，將它標為待確認，回到 CH2-4 補來源或替換素材，再更新版本。
- **圖卡與影片主張不同**：回到 PRAC1、CH2-2 與 CH2-6，比較是平台轉譯還是錯誤改寫；必要時建立 v2，不直接覆蓋 v1。
- **同學無法接手**：先修 README、檔案名稱、資料夾與來源對照，再修美術或效果；接手問題不靠口頭補充解決。
- **Affinity 或 OpenShot 無法使用**：保存既有來源檔、預製輸出與文字版判斷，標記實際工具 BLOCK；不把預製檔冒充個人完成的工具實作。
- **AI 紀錄缺少提示詞或修改**：補上可取得的生成紀錄；若無法還原，將素材降級為待確認／不可用，改用自製或已確認來源素材。
- **沒有外部上傳平台**：以本機資料夾與播放／接手驗證完成交付，不把公開上線當成 PRAC2 的必要條件。

- 課前準備一組完整參考包與一組故意缺欄位的錯誤包，讓學員依接手驗證找出來源、版本、CTA 與恢復路徑問題。
- PRAC2 不要求外部上傳、付費投放或真實成效數字。驗收集中在內容目的、資產可用性、來源可追溯與接手可行性。

- AI 工具可協助檢查欄位與比較版本，教師驗收時要求學員指出人工判斷與來源證據。
- PRAC2 通過後，將 `共同 Brief`、`短影音`、`平面圖卡`、`來源紀錄` 與 `行銷判斷說明` 標記為 Part 3 的上游輸入；未通過的項目不要默默帶入下一科。

## 常見錯誤 3 條（Common Pitfalls）

1. **錯誤現象**：交付包有很多檔案，卻沒有共同受眾、核心訊息、使用位置與 CTA。
   **原因**：把產出數量當成交付完整度，沒有把上游判斷帶到資產與 README。
   **解法**：先寫共同 Brief 與資產分工，再整理檔案；每個輸出都要回答給誰看、處理什麼、下一步在哪裡。

2. **錯誤現象**：影片與圖卡分別使用不同成果數字、不同服務範圍或不同 CTA。
   **原因**：平台製作各自進行，缺少一致性檢查；AI 或後續改寫新增了未確認資訊。
   **解法**：逐項比較受眾、主張、證據、限制與 CTA；平台轉譯可以不同，服務主張與真實狀態要一致。

3. **錯誤現象**：README 寫得完整，但同學仍找不到來源、無法播放或不知道哪個檔案是主版。
   **原因**：只寫敘述，沒有用實際接手路徑驗證檔名、資料夾、權限與輸出。
   **解法**：把整個交付包複製給同學，請他不看口頭補充完成六項接手任務；依失敗位置修資料夾、來源、專案或 README。

## 檢核題 2 條（Quiz）

**Q1（概念驗證）**：下列哪一項最能判斷一組內容是否具備可交付性？

- [ ] A. 檔案數量很多，畫面效果豐富
- [ ] B. 製作者能口頭說明每個檔案的用途
- [x] C. 接手者能找到檔案、理解受眾與 CTA、追到來源、播放或修改成果，並知道恢復路徑
- [ ] D. 每個檔案都使用同一種視覺效果

**答案理由**：可交付性需要讓內容被使用、接手、修改與驗收；檔案數量、效果與製作者口頭補充不能取代可尋址的交付證據。

**Q2（應用驗證）**：短影音與圖卡對同一服務使用不同 CTA。你要先檢查哪些內容，再決定是否保留差異？

- **預期答案要點**：比較兩個資產的使用位置、受眾當下判斷與下一步；確認差異是平台／情境轉譯，還是核心服務主張改變；若只是平台表達不同，補 README 說明；若造成服務範圍或行動矛盾，回到 Brief／定位卡修正並重做驗收。
