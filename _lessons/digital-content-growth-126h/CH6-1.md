## 教學流程（Teaching Flow）

> **course_type = concept-application**：情境回顧 → 概念整理 → 教師示範 → 個人整合 → 同伴檢核。
> **本節完成物**：`整合價值主張表-v1.md`。

### 情境回顧 / Hook

學員完成很多產物：服務假設、影像內容、社群主題、SEO 頁面、GA4 觀察與廣告投放包。當有人問「你到底能提供什麼？」如果只能逐項展示工具，對方仍看不出受眾問題與交付價值。

本單元把不同科目的產物放回同一個受眾情境，整理出可以繼續製作、接案、求職或提案的主題。成果不限制學員未來的出口，先讓能力與證據能被看懂。

### 概念 / Concepts

#### 受眾問題

**受眾問題**是特定角色在特定情境中想完成、卻受到阻礙的任務。

- **用途**：作為內容、服務與渠道選擇的共同起點。
- **正例**：小型品牌負責人每週需要規劃內容，卻沒有可交接的流程。
- **非例**：海外市場很大，所以大家都需要行銷。
- **你的判斷**：角色、情境、阻礙與證據是否清楚？

#### 價值主張

**價值主張**是向特定受眾說明可協助完成什麼、用何種方式、產生何種可觀察結果的短句與證據組合。

- **用途**：讓對方快速理解服務或能力的工作範圍。
- **正例**：協助小型品牌把零散社群內容整理成可執行的月度流程，交付內容主題、素材方向與追蹤規格。
- **非例**：提供全方位、專業、有效的數位行銷服務。
- **你的判斷**：對方看完能否知道服務對象、工作與交付物？

#### 能力證據

**能力證據**是能支持你完成某項工作主張的成品、測試紀錄、分析表或交接文件。

- **用途**：把「我會」轉成他人可檢查的成果。
- **正例**：SEO 與追蹤決策包、兩輪廣告決策紀錄、社群內容日曆。
- **非例**：只列出會使用的軟體名稱，沒有任何成品。
- **你的判斷**：證據能看出你做了什麼、如何判斷與如何修正嗎？

#### 證據強度

**證據強度**是根據來源、可重做程度、實際條件與限制，判斷一份材料能支持多少主張。

- **用途**：避免把練習資料、教師示範與正式客戶成果混在一起。
- **正例**：將教師 Demo Account 標為操作與閱讀能力證據，並標記無法代表自有成效。
- **非例**：將模擬廣告結果寫成實際投放成效。
- **你的判斷**：這份證據能支持能力、方法，還是商業結果？

### 教師示範 / Demo

#### 七步驟示範

1. 從 PRAC1 選出一個受眾與服務問題。
2. 從 PRAC3 選一組內容與社群資產。
3. 從 PRAC4 選一個頁面與追蹤決策。
4. 從 PRAC5 選一個市場與廣告測試。
5. 找出四份產物共同回答的問題。
6. 寫出價值主張與三項能力證據。
7. 標記已驗證、教師資料支持、待確認與 BLOCK。

#### 示範表

| 欄位 | 示範內容 |
|---|---|
| 受眾 | 需要穩定內容流程的小型品牌負責人 |
| 問題 | 內容主題、素材與追蹤彼此分散 |
| 協助方式 | 整理主題、素材方向、頁面與事件規格 |
| 交付物 | 內容日曆、頁面檢查表、追蹤決策包 |
| 證據 | PRAC3、PRAC4、PRAC5 產物 |
| 限制 | 部分資料為教師示範或模擬，不代表客戶成效 |

#### AI 輔助點

可將前置產物摘要交給 AI，要求它找共同受眾、重複工作與價值主張候選。學員需回到原始文件核對，刪除沒有證據支持的形容與成果宣稱。

### 個人整合 / Hands-on

#### 任務

完成 `整合價值主張表-v1.md`，包含受眾、問題、價值、工作範圍、交付物、能力證據、證據狀態與三個仍待驗證問題。

#### 最短操作路徑

1. 選一個共同受眾與問題。
2. 合併四份實作產物。
3. 寫價值主張與交付物。
4. 選三項能力證據。
5. 標記證據狀態與限制。
6. 請同伴用一句話重述你的價值。

#### 檢查點與修復

| 檢查點 | 通過證據 | 發現問題時的處理 |
|---|---|---|
| 受眾具體 | 角色、情境、問題完整 | 收窄描述 |
| 價值可讀 | 有工作與交付物 | 刪除空泛形容 |
| 證據可查 | 能連回前置產物 | 補檔名與版本 |
| 限制誠實 | Demo、模擬、正式分開 | 降低主張強度 |

## 講師授課筆記（不進講義）

1. 先要求學員整理共同問題，再談職涯出口或商業模式。
2. 觀察是否把平台名稱當成價值，必要時追問交付物與受眾結果。
3. 鼓勵多種出口：接案、職務作品、內部提案、個人服務或後續創業。
4. AI 只能協助聚合與改寫，主張由學員用產物證據決定。

## 商業情境案例（Case）

#### 案例：能力展示的重新整理

小組原本列出「會拍攝、剪輯、經營社群、SEO、GA4、投廣告」。重新整理後，改成「協助小型品牌把內容主題、頁面與追蹤安排成可測試的行動流程」，並以內容日曆、頁面檢查表、追蹤決策包作為證據。

## 動手練習題（Hands-on Exercise）

1. 把一個軟體清單改寫成三個交付物。
2. 為價值主張找出支持與不支持的證據。
3. 請同伴只看表格重述受眾、問題與價值。
4. 用 AI 找空泛語句，再逐句補上證據。

## 常見錯誤 3 條（Common Pitfalls）

1. **把工具清單當成能力證明**：修復方式是展示成品與判斷紀錄。
2. **受眾描述過寬**：修復方式是補上角色、情境與問題。
3. **忽略證據狀態**：修復方式是分開教師資料、模擬結果與正式成品。

## 檢核題 2 條（Quiz）

1. **題目**：價值主張至少要讓讀者知道什麼？  
   **參考答案**：服務誰、處理什麼問題、用什麼方式工作，以及會交付什麼。
2. **題目**：模擬廣告結果能支持哪類主張？  
   **參考答案**：能支持規劃與判讀方法的展示；不能直接支持正式商業成效。
