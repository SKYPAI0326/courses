## 教學流程（Teaching Flow）

> **course_type = skill-operation＋整合交付**：破題 → 概念 → 操作示範 → 動手整合 → 交付檢核。
> **本節完成物**：`社群經營方案-v1/`。

### 破題 / Hook

阿凱完成了三平台貼文、兩週月曆、互動回應規則與一份數據表，檔案散落在不同資料夾。雯姊想知道下週要發布什麼、誰回應留言、哪些內容能承接到 LINE、數字可以說明什麼，阿凱只能逐一打開檔案口頭解釋。

PRAC3 要把零散文件組成一套可接手的社群經營方案。方案要讓下一位工作者知道：平台各自負責什麼、內容支柱處理什麼、兩週怎麼安排、互動如何處理、數據如何回顧、LINE 何時延伸，以及每個判斷的來源與限制。

### 概念 / Concepts

#### 社群經營方案

**社群經營方案**是把平台角色、內容架構、發布流程、互動規則、成效觀察與後續行動整合在同一份交付包中。它說明工作如何被執行與修正，不保證平台結果。

- **正例**：方案內有策略摘要、平台任務、內容支柱、月曆、回應規則、資料字典、下一輪假設與 LINE 情境。
- **非例**：只有一份貼文清單或平台帳號名稱，沒有責任、來源與回顧方式。
- **你的判斷**：接手者能否依方案完成一列內容、處理一筆互動並提出下一輪行動？不能時，方案缺少流程或證據。

#### 上游成果與下游交接

PRAC3 要保留 Part 3 各單元的來源關係：

```text
PRAC1 Brief → CH3-1 平台任務 → CH3-2 內容支柱
PRAC2 內容包 → CH3-3 跨平台改編 → CH3-4 月曆
CH3-5 互動風險 → CH3-6 成效紀錄 → CH3-7 LINE 延伸
```

每一項方案結論都要能追到上游檔案。若缺少資料，標待確認或 BLOCK，不用口頭補出不存在的證據。

#### 策略摘要

**策略摘要**是用一頁說明受眾、問題、內容主張、平台分工、承接、觀察方式與限制的文件。它讓讀者先掌握方案，再查看細節。

- **正例**：寫明 IG 初步理解、FB 完整說明、Threads 問題探索、LINE 同意後回訪，並列出兩週內容與檢查條件。
- **非例**：寫「經營四平台、提高曝光、打造品牌」，沒有受眾任務與工作路徑。
- **你的判斷**：讀者看完摘要能否說出下週先做什麼與如何知道完成？

#### 整合驗收

**整合驗收**是用同一組條件檢查策略、內容、流程、互動、資料與承接是否互相支持。檢查內容包含核心訊息一致、素材來源、CTA、責任、資料定義與恢復路徑。

| 驗收面向 | 問題 |
|---|---|
| 受眾與定位 | 所有平台是否服務同一個具體情境？ |
| 內容與支柱 | 每列內容是否能回到一個支柱？ |
| 渠道與承接 | CTA 是否把人帶到合理的下一步？ |
| 互動與風險 | 回應與升級規則是否可執行？ |
| 數據與假設 | 觀察是否有定義、範圍與限制？ |
| LINE 延伸 | 同意、頻率與退出是否清楚？ |
| 可接手性 | 另一人能否找到檔案並執行？ |

### 操作示範 / Demo

#### 示範資料夾

```text
社群經營方案-v1/
├─ 01-summary/策略摘要-v1.md
├─ 02-platform/平台任務表-v1.md
├─ 03-pillars/內容支柱與定位-v1.md
├─ 04-calendar/社群內容月曆-v1.md
├─ 05-content/跨平台內容改編包-v1/
├─ 06-risk/互動與風險處理表-v1.md
├─ 07-metrics/成效紀錄與下一輪假設-v1.md
├─ 08-line/LINE承接與回訪-v1.md
├─ 09-source/來源與AI紀錄/
└─ 10-verification/驗收與修正/
```

#### 示範整合步驟

**步驟 1：建立策略摘要。**

把受眾、問題、核心訊息、平台角色、兩週節奏、LINE 條件與成效限制寫在一頁。

**步驟 2：建立平台與支柱對照。**

確認 IG、FB、Threads 與 LINE 各有任務；確認三至四個內容支柱有題目與邊界。

**步驟 3：放入內容月曆。**

將兩週內容、狀態、素材、CTA、責任、審查與回顧放入月曆，保留待確認項目。

**步驟 4：放入互動與風險規則。**

將理解問題、錯誤回報、負評、敏感資訊與退出情境放入方案，指定公開／私訊／轉交／停止。

**步驟 5：放入成效紀錄。**

將資料字典、內容比較、可說明／尚不能說明、下一輪單變因假設放入方案。

**步驟 6：放入 LINE 延伸。**

只保留已同意情境、內容目的、頻率、退出與回訪理由。沒有真實名單時標為模擬設計。

**步驟 7：做一致性檢查。**

比較摘要、月曆、內容、CTA、風險與數據假設。若摘要寫「查看服務範圍」，月曆不能改成「保證成交」；若素材是 AI 示意，各檔案都要保持狀態一致。

**步驟 8：做接手驗證。**

請同學依 README 任選一列內容，找到素材、檢查來源、說出回應路徑與記錄位置。

#### 示範策略摘要

```markdown
# 社群經營方案摘要 v1

## 受眾與問題
剛推出服務、已有零散資料、需要開始發布內容的小型團隊負責人。

## 內容主張
把零散資料整理成兩週可發布的內容主題與樣稿。

## 渠道分工
- Instagram：觸及與初步理解
- Facebook：完整說明與討論
- Threads：問題探索與互動
- LINE：已同意者的檢查表交付與回訪

## 兩週行動
以整理方法、內容判斷、交付案例、發布回顧四個支柱安排內容。

## 觀察方式
依資料字典區分觸及、互動、導流與模擬轉換；缺失資料保留待確認。

## 限制
不承諾營收或平台成效；AI 與模擬素材標示清楚；敏感資訊不在社群收集。
```

#### 正例與非例

| 項目 | 正例 | 非例 |
|---|---|---|
| 摘要 | 一頁說明受眾、平台、內容、承接、觀察與限制 | 只列平台與發布次數 |
| 月曆 | 每列有狀態、責任與回顧 | 只有日期與標題 |
| 互動 | 有分類、回應、升級與紀錄 | 所有問題都回歡迎私訊 |
| 數據 | 有字典、期間與假設 | 高觸及直接等於成功 |
| LINE | 同意、內容、頻率、退出與回訪 | 直接建立名單並頻繁發送 |

### 動手 / Hands-on

請將 CH3-3、CH3-4、CH3-5、CH3-6、CH3-7 的成果整合成 `社群經營方案-v1/`。

#### 步驟 1–12

1. 建立資料夾與 README。
2. 列出所有上游檔案、版本與缺口。
3. 撰寫策略摘要。
4. 整合平台任務與內容支柱。
5. 放入兩週月曆與發布流程。
6. 放入三平台內容改編與來源。
7. 放入互動／風險與回應範本。
8. 放入成效資料字典與下一輪假設。
9. 放入 LINE 承接／回訪／退出設計。
10. 完成跨檔案一致性檢查。
11. 進行同儕接手與角色演練。
12. 修正一個問題並封存 v1。

**Checkpoint 1**：同學能否只看摘要找到本週第一則內容與檢查點？

**Checkpoint 2**：同學能否依情境表處理一筆負評、一筆敏感資訊與一筆 LINE 退出？

**Checkpoint 3**：同學能否指出一個可說明與一個尚不能說明的數據結論？

#### 恢復路徑

- 缺少上游成果：用示例完成索引與交付結構，缺口標 BLOCK。
- 平台任務矛盾：回到 CH3-1 與策略摘要，先修平台角色再修月曆。
- 月曆與內容不同步：以檔名／版本對照表重新建立索引。
- 數據定義缺失：保留描述性觀察，停止假設直到字典補齊。
- 互動情境沒有責任：補公開、私訊、轉交、停止與回顧角色。
- LINE 無法驗證：維持情境模擬，不宣稱已完成真實發送。

### 交付檢核 / Verification

- [ ] 策略摘要可在一頁說清楚受眾、問題、內容、渠道、承接與限制。
- [ ] 五項上游成果都有索引與版本。
- [ ] 兩週月曆可由另一人接手。
- [ ] 三平台內容與核心訊息一致。
- [ ] 互動與風險規則可處理四種情境。
- [ ] 數據紀錄有定義、期間、限制與下一輪假設。
- [ ] LINE 設計有同意、頻率、退出與回訪理由。
- [ ] 來源／AI 紀錄可追溯。

交接時保留三種狀態：可直接使用、待確認、BLOCK。每個待確認項目要有下一個查核動作與負責角色；沒有查核路徑的項目先移出主版本。

## 動手練習題（Hands-on Exercise）

完成 `社群經營方案-v1/`，進行同儕接手、互動角色與數據限制驗收。

## 常見錯誤 3 條（Common Pitfalls）

1. **現象**：檔案很多但無法接手。**原因**：沒有摘要、索引與版本。**解法**：先整理資料夾、README 與上游對照。
2. **現象**：數據區寫滿結論。**原因**：忽略定義與資料限制。**解法**：分成可說明、尚不能說明與下一輪假設。
3. **現象**：LINE 設計直接使用真實名單。**原因**：把情境設計誤當工具實作。**解法**：使用模擬同意／退出狀態，保留權限與前測 BLOCK。

## 檢核題 2 條（Quiz）

**Q1**：社群經營方案最重要的整合證據是什麼？

- [x] A. 受眾、內容、平台、互動、數據、承接與檔案可以互相對照並由他人接手
- [ ] B. 發布平台越多越完整
- [ ] C. 貼文數量越多越成功
- [ ] D. 所有欄位都由 AI 產生

**Q2**：數據資料缺少導流欄位，但月曆已發布內容，你要如何寫方案？

- **預期答案要點**：保留已可說明的觸及／互動資料，明確標記導流缺口，下一輪補連結或來源追蹤設計；不把導流或轉換寫成已完成結果。
