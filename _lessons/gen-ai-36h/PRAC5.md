# 交付人工覆核後分流的流程

<!-- learner-content:start -->
## 用固定案例驗收，不靠流程圖打分
必做成果是一條Make流程：人工覆核後新列觸發、阻擋、防重、分流、紀錄與未寄出草稿。準備[表格配置](../assets/part5-sheet-layout.md)、[九欄示例](../assets/part5-reviewed-queue.csv)、[T01–T07 CSV](../assets/part5-test-cases.csv)、[實跑Blueprint](../assets/reference-make-blueprint.json)與[人工重建指南](../assets/part5-rebuild-guide.md)。匯入Blueprint後，先重選自己的Google連線與試算表ID，不能把講師的執行結果當成自己的驗收。沒有帳號連線只可交設計與欄位演練，不能驗收外部自動化。

獨立重建時先跑最小讀取與寫入，再加Filter、Router、防重及Drafts。主線沒有Google Forms舊列更新觸發的假設，也不用JSON Parse才可完成分流。九欄值保持一致，review_status只有待覆核、已覆核。

## 一次一列，逐案留下結果
| 案例 | 應有紀錄 | 草稿與限制 |
|---|---|---|
| T01詢問 | 業務 | 一份給虛構測試地址、未寄出 |
| T02抱怨 | 客服，人工處理 | 無草稿 |
| T03合作 | 合作 | 一份給虛構測試地址、未寄出 |
| T04其他 | 待處理 | 無草稿 |
| T05未覆核／錯分類 | 被擋 | 不分流、不建草稿 |
| T06相同鍵 | 重複 | 不新增草稿 |
| T07草稿表名故意設錯後恢復 | 保留錯誤、恢復原分類 | 最多一份有效草稿，紀錄狀態回寫 |

每案保存輸入、execution ID或截圖、結果行與判定。尚未跑填尚未實跑，不借用參考答案填成實際結果。重點核對「未覆核不能通過」及「恢復不重復」，任一失敗先修好再交付。

## 遇到失敗，自己定位
無輸出查起點與空列；欄位錯查映射；分流錯查category值；重復查source_key；部分成功先查下游結果。用CH5-4的恢復表說明從哪一步重跑，不把改來源時間當解決。

提供的Blueprint來自已通過T01–T07的教學Scenario，已移除原連線ID、帳號標籤與試算表ID。它仍需在你的工作區重新連線、填入自己的表格ID並試跑；如果匯入或欄位對不上，照重建指南逐步設定。講師另有五份AI秘書進階範例，含Gmail寄送、Gemini或Telegram模組，見[進階藍圖對照](../assets/part5-existing-blueprints-guide.md)，本節不直接執行那些寄送支路。

## 交付與下一步
交付表格樣本、Scenario說明、七案紀錄與恢復說明。只完成正常四案也要標T05–T07待驗。講師已在教學工作區試跑；開課當日仍需重查連線與介面，個人成果狀態由各自的實際證據決定。

下一部分將這些工具與流程放進個人清單，記清楚何時使用、如何查結果與失敗恢復，而不是再做一套相同流程。
