# 流程失敗時：查紀錄，再從失敗處恢復

<!-- learner-content:start -->
## 綠勾之外，還要能說明失敗在哪
沿用已跑通的教學流程，完成一次失敗與恢復的記錄。先讀[人工重建與恢復步驟](../assets/part5-rebuild-guide.html)與[T07測試](../assets/part5-test-cases.csv)。只在教學資料測試；沒有 S3 正常草稿及防重兩項成功紀錄時，先回 CH5-3 的 S3 建置，不急著加錯誤情境。

把故障分成三類：資料不合格在Filter擋；連線或權限錯在模組失敗；部分成功要核對下游是否已寫入。不同故障不能都用再按Run once處理。

## 示範：從執行記錄往回查
點最近一次execution，查輸入bundle、最後成功模組與第一個錯誤模組。紀錄來源鍵、stage、錯誤訊息、ProcessingLog與Drafts是否已有行。

| 現象 | 修復位置 | 重跑前核對 |
|---|---|---|
| 未覆核被擋 | Source人工核對 | 不改Filter繞過；通過後才追加新列 |
| Google寫入無權限 | Google連線或目標表 | 保留來源鍵，恢復同一教學表權限 |
| 紀錄已寫、草稿失敗 | 草稿步驟 | 查同鍵草稿是否存在，再恢復 |
| 相同來源重複 | 防重查詢 | 不改提交時間避開防重 |

## 跟著做：安全暫停並恢復
先停Scenario排程，確認只有一筆虛構測試。在Scenario settings開啟儲存未完成執行。把詢問路的Drafts目標表暫改成不存在的教學表名，再執行T07；這會讓草稿寫入報錯，上游紀錄保留「待建立」。開啟 Incomplete executions 的該筆 Details，在這份失敗執行內將錯誤模組修回 Drafts 並 Save，再按 Run once 從失敗步驟繼續；主流程也修回正確目標供未來新列使用。只改主流程再按 Retry，可能仍用失敗時舊設定。介面若與教材不同，先停下確認，不憑記憶重跑整筆。

成功後檢查ProcessingLog仍只有一列、draft_status變「已建立」，Drafts只有一份同鍵的「未寄出」草稿，未完成執行顯示Resolved。若已多出結果，先標測試錯誤並追查防重或恢復位置，不刪資料掩蓋問題。確認恢復路徑後才重新啟動排程。

## 自己試：寫一份接手說明
寫下觸發來源、九欄規格、最後成功紀錄、常見錯誤、停止方式與恢復位置。接手者應能依來源鍵找回一筆資料，知道不寄真客戶。

每週維護只需查連線、限額、異常與未完成執行；規則改變先更新測試再開放。n8n或Slack等第二套系統只在主線通過後選做，不要求兩引擎同時維護。下一份獨立演練以七案證據驗收。
官方操作依據：[手動解決未完成執行](https://help.make.com/manage-incomplete-executions)。本課表名設定錯誤使用 Details 內修正並保存；單純 Retry 適合暫時連線錯誤。畫面沒有對應控制項就停在查錯與保存證據，交講師核對帳號，不重跑全流程。
