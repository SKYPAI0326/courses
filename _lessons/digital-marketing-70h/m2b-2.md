## 1. 一張表記住：看失敗的樣子選技法

### 為什麼五要素寫清楚了，還是會不合用？

五要素能把「要做什麼」講清楚，但單一提示詞、一次生成，還是有四個常見上限：

- **你心裡的格式或語氣很難用文字描述**。你說「口語一點」，AI 理解的口語不一定是你公司習慣的口語。
- **AI 會把查得到的事實和自己的推測寫在一起**，一次生成的結果你很難分辨哪句有根據。
- **你自己也沒想到漏了什麼條件**，AI 常常不會停下來問，而是自己補一個合理的猜測繼續寫。
- **大方向對，但局部不合格**：某一句太長、某個條件寫錯。這時整份重寫反而容易把對的地方改壞。

所以這一節不是背四個新名詞，而是學會**先看結果「壞在哪」，再挑對應的那一招**。

### 對照表（本節最重要的一張表）

| 失敗的樣子 | 用哪一招 | 你要要求 AI 交出、並親眼看到的成果 |
|---|---|---|
| 欄位、格式或語氣不符合你要的樣子 | **給範例**（多範例提示，Few-shot） | 新產出和範例「同格式、同語氣」，但內容是新的 |
| 結論裡事實和推論混在一起，看不出哪句有根據 | **拆步驟** | 中間成果：證據表、標了「推論」的句子、共同比較欄位、成功條件檢查 |
| 缺少會改變交付結果的條件（例如對象、期限沒講） | **先追問** | AI 先問你問題，而且每題都說得出「答案會改變交付的哪一部分」 |
| 方向對，但局部不合格 | **逐輪迭代** | 每輪只改一個指定問題，其他部分保持不變 |

**四招可以分開用。** 不必每次全上；看到哪種失敗就用哪一招。也可以組合，例如逐輪迭代的某一輪，用的是「拆步驟」來修。

### 四個英文詞，一句話記法

| 詞 | 中文 | 一句話記法 |
|---|---|---|
| Zero-shot Prompting | 零範例提示 | 只給指令，**不給範例**（shot 可以想成「示範一次」，zero 就是零次示範） |
| Few-shot Prompting | 多範例提示 | 指令之外，**附幾組「輸入 → 理想輸出」的範例** |
| Prompt Chaining | 提示詞串接 | 把一件事**拆成好幾則提示詞依序送出**，上一步的產出當下一步的材料 |
| Reasoning Model | 推理模型 | 回答前會**先在內部推理**的模型，介面上常寫「思考」或「Thinking」 |

> 記不住英文沒關係。寫紀錄時，「使用的技法」那一欄寫中文就可以：給範例、拆步驟、先追問、逐輪迭代。


## 2. 技法一：給範例（零範例 vs. 多範例）

### 定義

- **零範例提示**：只寫指令（五要素），不附範例，讓 AI 自己決定怎麼寫。
- **多範例提示**：在指令後面附上幾組「原本的樣子 → 我要的樣子」，讓 AI 從範例學格式和語氣。

Google 的 Gemini 提示策略文件就是這樣區分：含有幾個範例的提示詞叫 few-shot，沒有範例的叫 zero-shot；範例能幫模型抓到格式、措辭與範圍。

### 什麼時候用？

當你發現「事實大致對，但寫出來**不像我們要的樣子**」：欄位順序不對、語氣太正式或太油、長度差很多。這種「樣子」用文字形容很難，直接給範例最快。

### 關鍵：範例要寫明「學什麼、不學什麼」

AI 看範例時，不知道你要它學的是「句型」還是「內容」。如果不講，它可能把範例裡的日期、事件、人名一起搬進新產出。所以附範例時，一定加兩行：

```
要學的：（例如）日期時間的寫法、短句、口語、「不能／照常／找誰」這種直接說法、保留所有條件
不要學的：（例如）範例裡的日期、事件內容、聯絡窗口名稱，這些都不要出現在新產出裡
```

### 給幾組？太多會怎樣？

- Anthropic 的官方提示建議寫「3–5 個範例效果最好」，並要求範例**貼近實際用途**、**彼此有差異**（涵蓋不同情況，避免 AI 抓到你不想要的規律），並用標籤把範例和指令分開。
- Google 的文件建議範例的**結構和格式要一致**，並提醒範例放太多，模型可能開始**過度貼合**（overfit）範例。

「過度貼合」用白話說就是：AI 太認真模仿範例，連不該學的地方都照抄。最常見的樣子：

- 範例都是一句話，AI 就把一則有八個條件的長公告**硬壓成一句**，條件掉了。
- 範例都有「請洽行政窗口」，AI 就在新公告也寫「行政窗口」，即使原文寫的是人資。

**做法：** 從 3 組開始試；看到過度貼合，不是一直加範例，而是在「不要學的」補一句，或加一條限制（例如「條件多時可以分點，不必壓成一句」）。

### 推理模型要不要給範例？

OpenAI 的推理模型最佳實務說，推理模型**通常不需要範例**就能有好結果，建議**先不放範例寫一次**；如果需要更複雜的輸出格式再加幾個範例，而且範例要和指令一致，不一致可能讓結果變差。

這和 Google 文件「建議一律放範例」的說法不同，因為兩份文件談的模型與情境不一樣。本課的實務做法是：**先零範例跑一次，看結果；格式或語氣不合，再加範例比較。** 這正好就是 Part D 第一輪要你做的事。


## 3. 技法二：拆步驟（要可查核的中間成果）

### 什麼時候用？

當結果是「一大段看起來很順的結論」，但你分不出**哪句是素材裡的事實、哪句是 AI 推出來的**。這時不要只叫它「寫好一點」，而是把一件事拆成幾步，**每一步交一個你看得到、對得回素材的中間成果**。

### 要它交哪種中間成果？

| 中間成果 | 長什麼樣子 | 適合 |
|---|---|---|
| **證據表** | 每一列：結論｜素材原文依據｜出處 | 摘要、整理、研究 |
| **假設標記** | 素材裡沒有、AI 自己推的句子，前面加「［推論］」 | 任何會混入猜測的工作 |
| **共同比較欄位** | 先定好欄位，每個選項都填同一組欄位 | 比較三款產品、三家競品 |
| **成功條件** | 先列「怎樣才算合格」，產出後逐條打勾 | 改寫、文案、公告 |

### 不要求它「公開內部思考」

要拆步驟，不等於叫 AI「把你的思考過程一字不漏寫出來」。OpenAI 的推理模型文件明白寫，對推理模型說「一步一步想」或「解釋你的推理」**沒有必要**，有時甚至會讓表現變差。而且一段寫得很流暢的解釋，**不等於證據**；你能查核的是證據表、引用的原文、成功條件，而不是 AI 寫的心路歷程。

| 不建議這樣寫 | 建議這樣寫 |
|---|---|
| 「請一步一步思考，並寫出你完整的推理過程。」 | 「先列一張證據表（結論｜原文依據），我確認後再寫摘要。」 |
| 「解釋你為什麼這樣判斷。」 | 「素材裡沒有直接寫的句子，前面標［推論］。」 |

### 提示詞串接：把一件事拆成幾則訊息

**提示詞串接**就是不要一則提示詞包山包海，而是分成幾則依序送，上一則的產出變成下一則的材料。Google 的文件建議多步驟任務「讓每一步成為一則提示詞，再依序串起來」；Anthropic 的文件說，最常見的串接模式是**自我修正**：起草 → 依準則檢查 → 依檢查結果修改，而且分開做的好處是每一步都能**檢查中間產出**。

你在聊天介面上可以這樣做，三則訊息分開送：

```
第 1 則：請依素材起草（貼素材與五要素）。
第 2 則：請用下面三條準則，逐條檢查你剛才的草稿，每條寫「合格／不合格＋原因」，先不要修改。
         準則：①（ ）②（ ）③（ ）
第 3 則：只修「不合格」的項目，合格的部分不要動。
```

### 非行銷例子：整理一般專案進度

**狀況：** 你把三週的會議紀錄丟給 AI，要它「整理專案進度」，結果寫出：「整體進度順利，但設計稿延遲，預計將影響上線時程。」你看不出「將影響上線」是會議上有人說的，還是 AI 自己推的。

**失敗的樣子：** 事實和推論混在一起 → 用**拆步驟**。

```
請分兩步做，先只做第 1 步：
第 1 步：從會議紀錄列出證據表，欄位：工作項目｜目前狀態｜會議紀錄原文依據（第幾週）。
        紀錄裡沒寫的狀態，填「紀錄未提」，不要自己推。
第 2 步（等我確認第 1 步後再做）：根據證據表寫三句進度摘要；
        任何證據表裡沒有直接依據的句子，前面標［推論］。
```

**要看到的成果：** 一張每列都對得回原文的表；摘要裡「影響上線時程」如果沒人講過，會被標成［推論］，你就知道要去問專案負責人。

### 推理模型與介面上的「思考」

ChatGPT、Claude、Gemini 現在都有會先在內部推理的模式，介面上常見的字樣是「思考」「Thinking」「延伸思考」，位置通常在**模型選單**或**輸入框旁的工具按鈕**。各家介面常改版，名稱和位置可能和你看到的不同。

**本節練習不需要開這個選項。** 找不到就用預設模型完成即可。如果你有開，記得兩件事：不必叫它公開推理；可以先零範例試，不足再給範例。


## 4. 技法三：先追問（以及用角色幫你挑毛病）

### 什麼時候用？

當你交辦的內容**可能缺了一個會改變結果的條件**，而你自己不確定缺什麼。AI 常常不會停下來問，而是多半會自己補一個合理猜測，寫出一份「看起來完整」的東西。

### 做法：在提示詞最後加一句

```
在開始寫之前，先問我三個問題，問的必須是「答案不同，交付內容就會不同」的事。
等我回答後再開始寫。
```

### 拿到問題後，要檢查問題是不是真的有影響

AI 問的三題不一定都有用。每題用一句話檢查：**「這題我回答 A 或回答 B，產出會不一樣嗎？」**

- 會不一樣 → 好問題，認真回答。
- 不會不一樣（例如「您希望語氣專業嗎？」而你已經寫了語氣）→ 這題是湊數，跳過不答，直接說「這題不影響，請照原指令」。

### 進階：讓 AI 當反問者，每題標出交付欄位

如果你要的是表格、紀錄這類有欄位的東西，可以要求 AI 每題都說明「這題的答案會影響哪一欄」，你就不會被一堆問題淹沒：

```
請扮演反問者，一次只問我一題。
每題請標出：這題的答案會改變交付內容的哪一欄（例如：適用對象、生效日期、例外情況）。
問到你認為不再有會改變交付的問題時，就停止並說「可以開始寫了」。
```

### 非行銷例子：公告缺少生效對象

（本講義自編的例子，不是課程練習資料。）

主管丟給你一句話要你寫公告：「下個月起，加班要事先在系統申請。」你直接叫 AI 寫，它會寫成「全體同仁」。但實際上可能只適用計時人員，或排除主管職。

加上「先問三個問題」後，好的追問會像這樣：

1. 這項規定適用全體員工，還是只有特定職別？（影響：公告的**適用對象**）
2. 「下個月起」是哪一天生效？（影響：**生效日期**）
3. 臨時被要求加班、來不及事前申請時怎麼處理？（影響：**例外情況**）

這三題你都答不出來 → 這不是 AI 的問題，是**素材本身缺資訊**，要回去問主管。這就是「先追問」最大的價值：在發布前把缺口找出來。

### 角色設定 vs. 人物誌：不一樣的東西

| | 角色設定 | 人物誌（Persona） |
|---|---|---|
| 是誰 | **AI 自己**扮演的身分 | **讀者／顧客**的樣子 |
| 寫法 | 「你是負責審稿的人資窗口……」 | 「讀者是阿傑，32 歲，怕買錯壺嘴……」 |
| 作用 | 決定 AI 用什麼標準做事 | 決定內容要對誰說、解決誰的擔心 |

**有效的角色要附「判準」**。只寫「你是資深人資專家」，AI 只會換個語氣；要寫出這個角色會用什麼標準檢查：

```
不夠有效：你是資深人資專家，請檢查這則公告。

有效：你是每天要回答同事請假問題的人資窗口。請用以下標準檢查這則公告：
① 原文的每個條件都還在 ② 期限都寫成具體日期或時間 ③ 沒有加入原文沒有的規定。
每條寫「合格／不合格＋哪一句」。
```

### 兩個對立角色互相挑戰

想找出盲點時，可以讓 AI 同時扮演兩個立場相反的角色互相挑戰。**限制一定要寫：不能增加材料中不存在的事實。** 不然 AI 為了辯贏，會自己編出「根據過去經驗，很多同事會……」這種素材裡沒有的說法。

```
請扮演兩個角色檢查下面的公告改寫版：
A：希望公告越短越好的行政同事。
B：發布後要回答所有請假問題的人資窗口。
兩人輪流各提兩個質疑。規則：
- 每個質疑都要引用原文或改寫版的句子。
- 不能增加原文中不存在的事實、規定或數字。
最後列出兩人都同意要改的地方。
```


## 5. 技法四：逐輪迭代（一次只修一個問題）

### 什麼時候用？

大方向已經對了，但還有幾處不合格。這時不要說「整份再改好一點」，因為 AI 會整份重寫，原本對的地方可能被改壞，你也不知道哪裡變了。

### 逐輪迭代四步

每一輪都照這四步：

1. **挑一個問題**：從所有問題裡，挑出「最影響使用」的那一個（怎麼挑見下方）。
2. **寫追加提示詞**：只要求修這一個問題，並**寫明保留不動的部分**。
3. **對照檢查**：兩件事都要看：指定的問題解決了嗎？保留的部分有沒有被改到？
4. **記錄**：填七欄紀錄，把仍不確定的寫進「仍待確認」。

追加提示詞的固定骨架：

```
只修一個問題：（具體指出哪一句、哪裡不對）。
請改成：（你要的樣子或規則）。
保留不動：（列出不能改的部分）。
其他地方不要修改，改完請標出你改了哪一句。
```

最後一句「標出你改了哪一句」很好用：你不用逐字比對，就知道這輪動了什麼。

### 不知道先修哪個？照這個順序

| 優先 | 問題類型 | 為什麼先修 |
|---|---|---|
| 1 | **事實錯或漏**：條件不見、日期時間錯、多了原文沒有的規定 | 讀者會照著做錯事 |
| 2 | **意思被改**：例如「兩個工作日」變「兩天」、「之後」變「起」 | 看起來對，其實意思變了，最難發現 |
| 3 | **結構難讀**：全部擠成一大段、重要的事放最後 | 讀者會漏看 |
| 4 | **語氣、字數** | 不影響正確，但影響好不好讀 |

同一級有兩個問題時，選**影響最多人**的那個。

### 修完又冒出新問題怎麼辦？

很正常。先看新問題是怎麼來的：

- **是這輪修改造成的**（保留的部分被改壞了）→ 下一輪先修它，並在追加提示詞把那部分加進「保留不動」。
- **是原本就有、你這輪才看到的** → 寫進「仍待確認」或排到下一輪，不要在同一輪一起修。

### 什麼叫「收斂」？

收斂代表**每一輪剩下的問題越來越少、越來越小**：指定的問題被解決，保留的部分沒有被改壞，下一輪要修的問題比上一輪不重要。如果三輪後剩下的只是語氣、字數這類小事，或已經符合你的成功條件，就可以停。

### 三輪還在重複同一個錯誤：停下來，回頭查

如果連續三輪都在修同一件事（例如一直漏掉同一個條件），通常不是提示詞措辭的問題，而是源頭有問題。依序檢查：

1. **素材**：原文本身是否寫得含糊、互相矛盾，或你貼的版本不完整？
2. **條件**：你的要求是否互相衝突？例如「一句話講完」又要「保留所有八個條件」。
3. **範例**：範例是不是讓 AI 過度貼合了？例如範例都是一句話。

查完後，**另開一個新對話，重新貼上來源和修正後的提示詞**。舊對話裡累積了錯誤版本，AI 會一直受它影響。


## 6. 示範：山徑咖啡首頁標題三輪迭代

（以下 AI 回覆是講義為了示範而寫的樣子，你實際跑出來的字句會不同；請看的是「每輪怎麼挑問題、怎麼寫追加提示詞、怎麼記錄」。）

### 背景

山徑咖啡（模擬品牌）首頁標題目前是「找到你的下一把手沖壺。」，太泛，沒有講到這次的主推：新手升級手沖壺三款、20 分鐘試握體驗。素材有四份：首頁標題、三份模擬訪談、品牌與產品事實、三則已核准文案句。

### 先對照：零範例 vs. 多範例

**零範例提示：**

```
請根據下面的資料，替山徑咖啡首頁寫兩個新標題。
（貼入：首頁標題、三份訪談、品牌與產品事實）
```

示範結果：「品味每一滴，從一把好壺開始」「為你的咖啡時光，挑一把對的壺」。
問題：好聽但空泛，沒用到訪談裡「怕選錯、想先摸過再買」的擔心，也看不出品牌已核准的寫法。這是**語氣與格式不符** → 用給範例。

### 第一輪：多範例提示，要求附來源

```
請替山徑咖啡首頁提出兩個新標題，每個標題附上來源（引用哪份訪談的哪句話，或哪一條產品事實）。

素材：
（貼入：首頁標題、三份訪談、品牌與產品事實）

下面三則是已核准的文案句，請參考它們的寫法：
<範例>
1. 問題開頭：「想升級手沖壺，卻不知道三款怎麼選？」
2. 細節開頭：「三款手沖壺，價格從 NT$1,680 到 NT$3,280。」
3. 對比開頭：「不是先猜哪把適合，而是預約 20 分鐘試握與注水體驗再決定。」
</範例>

要學的：三種開頭方式（問題、細節、對比）、直接對讀者說話、具體不空泛。
不要學的：不要直接重用這三句的原句；不要每個標題都放價格。
```

示範結果：

- A：「三款手沖壺不知道怎麼選？先免費試握 20 分鐘再決定」（來源：阿傑「能先拿在手上試，我才敢買」；門市服務）
- B：「新手升級手沖壺，同一個人、同一個水量，三款注水實測給你比」（來源：柏翰訪談）

### 第二輪：只修「範圍」

檢查來源時發現：A 寫了「免費」，但產品事實沒寫試握是否收費，阿傑的訪談甚至說他「不確定門市試握是否要付費」；B 承諾了「三款注水實測」，但素材裡沒有品牌已做好實測內容。兩個標題都**承諾了素材範圍以外的東西**，這屬於優先順序第 1 級（事實），先修。

```
只修一個問題：範圍。兩個標題都承諾了資料裡沒有的內容（A 的「免費」、B 的「三款注水實測」）。
請改成只承諾資料裡有的事：三款、價格區間、可預約 20 分鐘試握與注水體驗。
保留不動：A 的問題開頭、B 的對比方向、每個標題附來源。
其他地方不要修改，改完標出你改了哪幾個字。
```

示範結果（各標題的來源省略未列）：

- A：「三款手沖壺不知道怎麼選？先預約 20 分鐘試握與注水再決定」
- B：「不必看規格猜，三款新手升級壺，到門市握過、注過水再挑」

### 第三輪：只修「字數」

範圍對了，但 A、B 兩個標題都太長，放不進首頁。這一輪示範假設首頁標題要在 20 字以內（實際上限要看網站版面，所以也記進「仍待確認」）。

```
只修一個問題：字數。每個標題 20 字以內（標點與數字各算一字）。
保留不動：A 的「預約試握」承諾、A 的問題開頭、B 的對比方向、每個標題的來源。
不得新增資料沒有的內容。改完請標出每個標題的字數。
```

示範結果（各標題的來源省略未列）：

- A：「三款手沖壺怎麼選？先預約試握 20 分鐘」
- B：「別看規格猜，握過、注過水再挑壺」

### 示範的七欄紀錄

**第 1 輪**

| 欄位 | 內容 |
|---|---|
| 輪次 | 1 |
| 本輪問題 | 零範例版本語氣空泛，沒用到訪談中的擔心，也不像品牌已核准的寫法 |
| 使用的技法 | 給範例（多範例提示），並要求每個標題附來源 |
| 追加提示詞 | 附三則已核准文案句；要學：三種開頭、直接對讀者說、具體；不要學：重用原句、每個都放價格 |
| 修改結果 | A：三款手沖壺不知道怎麼選？先免費試握 20 分鐘再決定／B：新手升級手沖壺，同一個人、同一個水量，三款注水實測給你比 |
| 保留不動的部分 | 第一輪無前版；素材與五要素不變 |
| 仍待確認 | 來源是否都對得上素材（下一輪檢查） |

**第 2 輪**

| 欄位 | 內容 |
|---|---|
| 輪次 | 2 |
| 本輪問題 | 範圍：A 的「免費」、B 的「三款注水實測」都不在素材中 |
| 使用的技法 | 逐輪迭代（只修範圍） |
| 追加提示詞 | 只修範圍；只能承諾三款、價格區間、20 分鐘試握與注水；保留開頭方式與來源 |
| 修改結果 | A：三款手沖壺不知道怎麼選？先預約 20 分鐘試握與注水再決定／B：不必看規格猜，三款新手升級壺，到門市握過、注過水再挑 |
| 保留不動的部分 | A 問題開頭、B 對比方向、每個標題附來源 |
| 仍待確認 | 試握是否收費（阿傑的疑問，需問門市；確認前標題不寫免費） |

**第 3 輪**

| 欄位 | 內容 |
|---|---|
| 輪次 | 3 |
| 本輪問題 | 字數：A、B 都太長，首頁放不下 |
| 使用的技法 | 逐輪迭代（只修字數） |
| 追加提示詞 | 只修字數，每個標題 20 字以內；保留 A 的預約試握承諾、開頭方式、來源；不得新增資料 |
| 修改結果 | A：三款手沖壺怎麼選？先預約試握 20 分鐘／B：別看規格猜，握過、注過水再挑壺 |
| 保留不動的部分 | A 的預約試握承諾、A 問題開頭、B 對比方向、來源 |
| 仍待確認 | 20 字是示範假設，實際上限要看網站版面；試握收費仍未確認 |

**看出收斂了嗎？** 第一輪修的是整體方向，第二輪修事實範圍，第三輪只剩字數：問題一輪比一輪小，保留的部分沒有被改壞。


## 7. 練習：用 Part D 公告做三輪迭代

（練習資料為課堂模擬資料，不是真實組織、人物或成效。）

### 練習資料（直接複製）

**待改寫公告**

```text
自 2026 年 12 月 1 日起，員工請假改由新版人事系統提出。一般假別須於休假開始前完成申請並送交直屬主管；連續三日以上的休假，另須在系統附上工作交接內容。因突發疾病無法事前申請者，應於當日 10:00 前以電話或公司通訊軟體通知主管，並在恢復上班後兩個工作日內補登。已於舊系統核准且休假日在 12 月 1 日之後的案件不必重送；仍停留在草稿或退回狀態的案件，須改到新版系統重新提出。操作問題可在上班時間洽人資服務窗口。
```

**三組已核准範例**

```
範例一
正式公告：本公司將於 2026 年 11 月 8 日 09:00 至 12:00 進行會議室預約系統維護，維護期間暫停新增、取消及修改預約；既有預約不受影響，如有臨時需求請洽行政窗口。
同事版：11 月 8 日 09:00～12:00 會議室系統維護，這段時間不能新增、取消或改預約；原有預約照常，臨時需求請找行政窗口。

範例二
正式公告：因年度盤點作業需要，器材借用櫃將於 2026 年 11 月 15 日全天暫停借出及歸還服務；原訂於該日歸還者，可順延至 11 月 16 日 17:00 前完成，不列入逾期。
同事版：11 月 15 日器材櫃全天盤點，不能借出或歸還；原本當天到期的器材，可在 11 月 16 日 17:00 前歸還，不算逾期。

範例三
正式公告：為配合大樓消防設備檢查，2026 年 11 月 20 日 13:30 至 15:30 將分區進行警報測試；測試期間可能出現短暫警鈴聲，除另有廣播通知外，同仁無須疏散。
同事版：11 月 20 日 13:30～15:30 會分區測試消防警報，期間可能短暫響鈴；除非另有廣播通知，否則不用疏散。
```

### 先準備：條件核對清單

改寫最常出的錯是**漏條件、改到意思**。先把原文拆成八個條件，每次 AI 給新版本，就拿這張清單逐條打勾。這張清單本身就是第 3 節說的「成功條件」。

| # | 原文條件 | 核對時注意 |
|---|---|---|
| 1 | 2026 年 12 月 1 日起，請假改用新版人事系統 | 日期有沒有寫對 |
| 2 | 一般假別：休假**開始前**完成申請，並送交直屬主管 | 「開始前」「直屬主管」有沒有不見 |
| 3 | 連續三日以上：另須在系統附上工作交接內容 | 「三日以上」有沒有被改成「超過三天」 |
| 4 | 突發疾病：**當日 10:00 前**用電話或公司通訊軟體通知主管 | 時間、兩種通知方式 |
| 5 | 突發疾病：恢復上班後**兩個工作日內**補登 | 「工作日」有沒有被改成「天」 |
| 6 | 舊系統已核准、休假日在 12 月 1 日之後：不必重送 | 兩個條件要同時成立 |
| 7 | 仍在草稿或退回狀態：改到新系統重新提出 | 有沒有和第 6 點混在一起 |
| 8 | 操作問題：上班時間洽人資服務窗口 | 有沒有被改成範例裡的「行政窗口」 |

（第 4、5 點都是突發疾病的規定，分成兩列比較好逐條核對。）

> **原文本身就有兩處含糊**：「連續三日」是工作日還是日曆日？「12 月 1 日之後」包不包含 12 月 1 日當天？原文沒說，AI 也不知道。如果 AI 自己幫你決定了（例如寫成「12 月 1 日起」），這是改到意思；正確做法是保持原文說法，並把這個疑問寫進「仍待確認」，由人資決定。

### 第 1 輪：零範例和多範例各跑一次，選一版

**步驟 1｜開一個新對話，貼零範例提示：**

```
請把下面這則正式公告，改寫成同事一看就懂的版本。
讀者：公司一般同事，多半用手機快速看過。
要求：保留所有條件、日期、時間與適用情況；不要新增原文沒有的規定；用短句、口語。
原文沒寫清楚的地方，照原文的說法寫，不要自己補。

公告：
"""
（貼上待改寫公告）
"""
```

把結果複製到你的紀錄檔，標「零範例版」。

**步驟 2｜另開一個新對話，貼多範例提示。**（另開新對話，是為了不讓 AI 看到上一版，兩版才能公平比較。）

```
請把「待改寫公告」改寫成同事一看就懂的版本。
讀者：公司一般同事，多半用手機快速看過。
要求：保留所有條件、日期、時間與適用情況；不要新增原文沒有的規定。
原文沒寫清楚的地方，照原文的說法寫，不要自己補。

下面三組是已核准的「正式公告 → 同事版」範例。
要學的：日期時間的寫法（例如「11 月 8 日 09:00～12:00」）、短句口語、「不能／照常／不算」這種直接說法、原文的條件一個都不少。
不要學的：範例裡的日期、事件內容與「行政窗口」等名稱都不要出現在新版本；範例都只有一句，但待改寫公告條件比較多，可以分成幾行或分點，不必壓成一句。

<範例>
（貼上三組已核准範例）
</範例>

<待改寫公告>
（貼上待改寫公告）
</待改寫公告>
```

把結果複製到紀錄檔，標「多範例版」。

**步驟 3｜比較兩版，選一版繼續。** 兩版各用條件核對清單打勾，再看語氣像不像範例。選「漏得少、意思沒被改、比較好讀」的那版。之後的第 2、3 輪，就在**產生那一版的對話**裡繼續。

> 不一定是多範例版贏。如果零範例版條件比較完整，就選零範例版，並在紀錄寫出原因。這個比較本身就是第一輪的重點。

**步驟 4｜填第 1 輪紀錄。** 「追加提示詞」欄可以寫「多範例提示（全文見附件）」再摘要學什麼／不學什麼；「修改結果」貼你選中的版本；「本輪問題」寫你比較後看到的差異。

### 第 2 輪、第 3 輪：每輪只修一個最影響使用的問題

**步驟 1｜找問題。** 用條件核對清單和第 5 節的優先順序表，列出目前版本的所有問題，挑最優先的**一個**。

改寫公告常見的問題（你的版本不一定會出現，請以實際結果為準）：

- 某個條件不見了（第 1 級）
- 「兩個工作日」變成「兩天」，或「12 月 1 日之後」變成「12 月 1 日起」（第 2 級）
- 「已核准」和「草稿／退回」兩種舊案件寫在同一句，看不出各自怎麼做（第 2～3 級）
- 範例的「行政窗口」跑進來（第 1 級，多了原文沒有的資訊）
- 全部擠成一大段，手機上不好讀（第 3 級）

**步驟 2｜選技法，寫追加提示詞。** 大多數時候用逐輪迭代的骨架就夠；遇到特定狀況可以換成別的技法：

| 你看到的問題 | 這一輪可用的技法 | 追加提示詞範例 |
|---|---|---|
| 漏了某個條件 | 逐輪迭代 | 「只修一個問題：漏了『連續三日以上須附工作交接內容』。請補回去。保留不動：其他所有句子與分點方式。改完標出新增的那一句。」 |
| 漏了好幾個，或一直漏 | 拆步驟 | 「先不要改寫。第 1 步：把原文列成條件清單，每列一個條件。我確認後，第 2 步再依清單改寫，每個條件都要出現。」 |
| 意思被改了 | 逐輪迭代 | 「只修一個問題：『兩天內補登』要改回『恢復上班後兩個工作日內補登』。保留不動：其他所有句子。」 |
| 你不確定某處該怎麼寫（例如 12/1 當天算不算） | 先追問 | 「這則公告改寫前，先問我會影響內容的問題，每題標出影響哪一句。」問完你答不出來的，寫進「仍待確認」 |
| 想知道讀者會卡在哪 | 角色（附判準） | 用第 4 節「人資窗口」的檢查提示詞，再挑它指出的最重要一點來修 |

**步驟 3｜對照檢查。** 兩件事：指定問題解決了嗎？「保留不動」的部分還在嗎？再用條件核對清單打勾一次，確認沒有新漏掉的條件。

**步驟 4｜填紀錄。** 第 3 輪重複步驟 1～4。

> 如果到第 3 輪還在重複同一個錯誤，照第 5 節「三輪還在重複同一個錯誤」那段處理：檢查素材、條件、範例，然後開新對話重貼來源。這件事本身也要寫進紀錄。

### 每欄的寫法：流水帳 vs. 看得出改了什麼

| 欄位 | 寫成流水帳 | 看得出改了什麼 |
|---|---|---|
| 本輪問題 | 「覺得不夠好，請它再改。」 | 「第 5 點『兩個工作日內』被改成『兩天內』，意思變了。」**指出哪一句、錯在哪** |
| 使用的技法 | 「請 AI 修改。」 | 「逐輪迭代（只修這一句）」**寫四招之一** |
| 追加提示詞 | 「我叫它改好一點。」 | **貼出你實際送出的那段話**，下一節要收進提示詞庫 |
| 修改結果 | 貼整份全文，不標記 | 貼全文，並把**這輪改到的那句**用粗體或括號標出來 |
| 保留不動的部分 | 空白 | 「分點方式、第 1～4 點、第 6～8 點」**和你提示詞裡寫的一致** |
| 仍待確認 | 「無」 | 「『連續三日』是工作日或日曆日，原文未說明，需問人資。」**原文或素材本身答不了的事** |

**自我檢查三句：** 別人只看你的「本輪問題」欄，能不能指到原文的哪一句？「追加提示詞」欄是不是能直接複製再用？三輪的「本輪問題」是不是一輪比一輪小？三句都是「是」，你的紀錄就不是流水帳。


## 9. 收尾：把有效的追加提示詞留下來

三輪做完，回頭看「追加提示詞」欄，挑出**真的讓結果變好**的那幾句，存到你自己的檔案。存的時候把具體內容換成空格，下次換個主題也能用。例如：

```
只修一個問題：（哪一句、錯在哪）。
請改成：（規則）。
保留不動：（列出）。
其他地方不要修改，改完標出你改了哪一句。
```

```
要學的：（格式、語氣、寫法）。
不要學的：範例裡的事實、日期、事件與名稱都不要出現在新產出。
```

```
在開始寫之前，先問我三個問題，問的必須是「答案不同，交付內容就會不同」的事。
```

下一節 2B-3 要建立五則通用工作提示詞，其中「改寫」那一則用的正是這份 Part D 公告，今天存下的句子會直接派上用場。

**和小組作業的關係：** 模組最後的作業要用 AI 查自己組產品的競品資料，並上台分享一個「AI 說錯、被我們抓到」的例子和修正後的提示詞。到時候：AI 給的競品資料事實和推論混在一起，就用**拆步驟**要證據表；不確定要查哪些項目，就用**先追問**；結果大致對但有錯，就用**逐輪迭代**一次修一處，並保留紀錄，那份紀錄就是上台的素材。


## 10. 常見卡關

**Q：術語太多，現場怎麼知道該用哪一招？**
A：不用想名詞，只問自己「它壞在哪？」然後查第 1 節的對照表：樣子不對 → 給範例；分不出事實和推論 → 拆步驟；缺條件 → 先追問；只有局部不對 → 逐輪迭代。

**Q：問題好幾個，不知道先修哪個？**
A：照第 5 節優先順序：事實錯漏 > 意思被改 > 結構難讀 > 語氣字數。

**Q：修完冒出新問題？**
A：是這輪改壞的，下一輪先修，並加進「保留不動」；是原本就有的，排下一輪或寫進「仍待確認」。不要在同一輪一起修。

**Q：找不到「思考」選項？**
A：本節練習不需要。介面常改版，找不到就用預設模型完成。

**Q：AI 回答時又自己補了原文沒有的東西？**
A：在追加提示詞加一句：「原文沒寫的不要補，照原文說法寫；不確定的地方列在最後讓我確認。」

**Q：三輪了還是一直錯同一個地方？**
A：停止追加。檢查素材、條件、範例，開新對話重貼來源與修正後的提示詞，並把這件事寫進紀錄。
