# 用 ta-work 建立辦公行政工作助理

你已經會寫 prompt、整理文書、表格、簡報與會議資料。這節把這些能力接成一位可重複使用的辦公助理：Gemini Notebook 保存公司允許使用的文件，`ta-core` 管來源與寫入邊界，通用 `ta-work` 負責行政與專案工作方法。

## 本節完成後，你能做到什麼

- 安裝或以手動備援載入 `ta-core` 與通用 `ta-work`。
- 鎖定一個工作筆記本，完成唯讀清單與來源邊界測試。
- 依週工作清單與會議紀錄產出可查核的行政優先事項。
- 先預覽、再確認受控沉澱，並完成一份職務客製化草案。

## 你要留下的成果

**起始材料：**

- [下載 ta-core.md](../../courses/office-ai/assets/skills/ta-core.md)：來源檢索、防污染與回寫規則。
- [下載通用 ta-work.md](../../courses/office-ai/assets/skills/ta-work.md)：辦公與專案協作規則。
- [下載一週工作清單](../../courses/office-ai/assets/datasets/week-tasks-sample.txt)：本次行政整理輸入。
- [下載 Q2 業績檢討會議逐字稿](../../courses/office-ai/assets/datasets/meeting-transcript-sample.txt)：本次決議查核輸入。

**第一個動作：**先在 Gemini 開啟 Skills 設定，確認是否能新增或啟用 Skill。此時先不要建立、修改或刪除任何 Notebook 內容。

**第一個可觀察結果：**你會看到 Skills 管理入口，或確認目前帳號沒有該入口。兩種結果都有可執行的下一步。

**完成物：**一張「辦公助理驗收卡」與一份「職務客製化草案」。驗收卡保存本次鎖定的筆記本、使用來源、唯讀結果、缺資料測試、產出與寫入紀錄；草案記錄你的職務、三項核心任務與防錯紅線。

## 三層分工

| 層級 | 負責內容 | 本次使用方式 |
|---|---|---|
| Gemini Notebook | 長期保存可信工作文件 | 放範例週工作清單與會議逐字稿 |
| `ta-core` | 找來源、標示依據、阻止污染、控制回寫 | 先列來源再回答；無資料就明說；寫入前先確認 |
| 通用 `ta-work` | 用辦公與專案視角分析、規劃與草擬文件 | 整理優先事項、檢查決議、列風險與待確認欄位 |

後續若改成法務、PM、行政或活動企劃，只調整 `ta-work` 的領域細節。`ta-core` 的來源邊界與回寫規則要完整保留。

## 先把 Skill 準備好

### 路徑 A：帳號有 Skills 入口

1. 在 Gemini 設定中開啟 Skills 管理頁。
2. 建立或編輯 `ta-core`，貼入 `ta-core.md` 的完整內容並啟用。
3. 建立或編輯 `ta-work`，貼入通用 `ta-work.md` 的完整內容並啟用。
4. 到連接器／Apps 設定確認 Gemini Notebook 已啟用。介面名稱可能因帳號語言或組織設定不同。

**快速檢查：**回到新對話，輸入 `@ta-core @ta-work`。輸入框或回覆區應顯示兩個 Skill 已被辨識。

**卡住時：**若找不到 Skills、無法儲存或連接器被管理員停用，停止修改設定，改走路徑 B。不要用其他人的帳號代替你的工作帳號，也不要上傳公司機密測試。

### 路徑 B：帳號沒有 Skills 或連接器入口

1. 開啟一個全新 Gemini 對話。
2. 貼入 `ta-core.md` 與 `ta-work.md` 全文，前面加上：「本對話請遵守以下兩份規則。」
3. 在 Gemini Notebook 網頁版查詢來源，將回答與引用段落貼回 Gemini 對話。
4. 需要沉澱時，把核准內容人工追加到一份 Markdown 筆記，再上傳或更新 Notebook。

這條備援保留來源邊界、辦公分析與人工確認能力。自動列出筆記本及自動回寫功能可能無法使用，驗收卡要如實標記「手動備援」。

## 第一輪只讀不寫

在新對話輸入：

```text
@ta-core @ta-work
列出目前可用的筆記本與每本來源數。這一輪只讀，不要新增、修改、重新命名或刪除任何內容。
```

**預期結果：**助理列出筆記本名稱與來源數，不執行任何寫入。若清單中有多個名稱相近的筆記本，助理應停下來讓你選擇。

接著輸入：

```text
請鎖定《辦公行政工作庫》。先列出來源名稱，不要修改資料。
```

若你尚未建立這本練習筆記本，可在 Gemini Notebook 手動新建，並加入本頁提供的兩份範例資料。免費帳號以每本 50 筆來源為基準，本練習只使用 2 筆。

### Checkpoint：筆記本與來源鎖定

現在應看到：目標筆記本名稱、來源清單，以及「未修改資料」的回報。若看到錯誤筆記本或來源不完整，回到鎖定指令重新指定；來源未齊全前不要進入下一步。

## 用兩份工作資料做行政摘要

輸入完整任務：

```text
根據《辦公行政工作庫》中的一週工作清單與 Q2 業績檢討會議逐字稿，整理下週三項行政優先工作。

每項請包含：
1. 工作事項
2. Notebook 依據與來源名稱
3. 已知日期或狀態
4. 仍待確認的欄位
5. 建議的人工查核點

只使用 Notebook 內資料。缺少日期、負責人或定案狀態時標〔待確認〕，不要自行補寫。
```

**預期結果：**輸出應包含三項工作、兩份來源的引用線索，以及清楚的〔待確認〕欄位。內容可以重組，不能把「原則同意」寫成「已正式決議」，也不能發明截止日。

**快速檢查：**逐項點回來源，核對日期、負責人與決議語氣。任何一項找不到原文，就先刪除或改標〔待確認〕。

## 故意問一題資料裡沒有的事

輸入：

```text
公司國內出差每天補助多少？只根據目前鎖定的 Notebook 回答。
```

目前兩份範例資料沒有出差補助規定。合格回答應先說：

> 目前連結的 Notebook 資料沒有足夠依據回答這一點。

助理可以在你要求後提供【最新網路補充】或【模型推論與延伸】，但不能把通用行情寫成公司制度。

### Checkpoint：防污染測試

現在應看到明確的缺資料宣告。若助理直接報出一個金額，回到 `ta-core` 檢查四階來源順序與無依據宣告，再開新對話重測。未通過前不要使用它處理真實公司規定。

## 確認後才寫入

先要求預覽：

```text
把剛才確認過的三項行政優先工作整理成 Markdown 預覽。請說明預計寫入哪一本 Notebook、來源名稱，以及要新建來源或追加至既有文字來源。現在不要寫入。
```

檢查預覽中的日期、來源與〔待確認〕欄位。若內容正確，再明確下令：

```text
確認寫入《辦公行政工作庫》。請追加到文字來源〈每週行政追蹤〉文末，標記今天日期；不要建立新來源。完成後回報來源名稱與目前來源數。
```

若目標來源是 PDF、網頁或其他不可直接覆寫的格式，改成建立一份 Markdown 補充筆記。助理不應聲稱已直接改掉原始 PDF。

**通過標準：**寫入前有預覽與目標確認；寫入後能在指定文字來源看到新增段落；使用追加模式時，筆記本來源總數維持不變。

## 從通用版改成你的版本

通用 `ta-work` 內建五項客製化參數。先完成自己的草案：

| 參數 | 你的內容 |
|---|---|
| 職務／專業領域 | 例：行政專員、專案助理、業務助理 |
| Notebook 主要資料 | 例：SOP、會議紀錄、公告範本、專案規格 |
| 最常需要協助的三項任務 | 例：查制度、整理追蹤事項、草擬通知 |
| 防錯紅線 | 例：不可發明日期、不得把草案當定案、個資先去識別化 |
| 預設輸出結構 | 例：結論、Notebook 依據、待確認、下一步 |

### 嘉年華版本為什麼會出現

課堂示範帳號中的嘉年華 `ta-work` 是通用版經過客製化後的結果：

| 保留不變 | 依需求替換 |
|---|---|
| Notebook 內部資料最高權威 | 角色改為嘉年華活動企劃／專案協作 |
| 無依據先宣告，外部資料另標 | 核心任務改成攤位、流程、供應商與時程協調 |
| 寫入前先確認，支援追加 | 防錯紅線改成預算、場地、責任人與定案狀態 |
| 風險與待確認欄位 | 輸出格式改成活動工作分解與追蹤表 |

嘉年華版本證明同一個通用底座能配合使用者需求修改。正式模板仍是本頁下載的通用 `ta-work.md`。
