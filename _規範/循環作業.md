# 循環作業（任務佇列與分派）

一個工作範圍只有一份任務佇列，卡片依類型交給既有執行器。本檔只定義卡片格式、分派表與證據等級；各執行器怎麼跑，以它自己的文件為準，不在這裡重寫。

- 事故與學員卡關先走 `_規範/飛輪規則.md` 的分流；需要改東西的才開成卡片。
- 分工依據是 `courses/course-manager/docs/course-production-tool-human-ai-matrix-v0.1.md`（人類 H／AI A／機械 M／外部 E）。
- 狀態：2026-11-02 起試行，第一個案例為 `courses/canva-video-teaching/_local/loop-backlog.md`。

---

## 佇列位置

| 範圍 | 佇列檔 |
|---|---|
| 單一課程 | `courses/{slug}/_local/loop-backlog.md` |
| 全站規範、lint、共用腳本 | `_規範/_local/loop-backlog.md` |

`_local/` 已 gitignore，佇列屬內部文件，不進學員網站。講義文字改善的單章 run 仍由 Course Iteration System 自己的狀態檔管理；本佇列的卡片只記錄指向哪個 run 與結果，不複製它的狀態。

## 卡片格式

```markdown
## {代號}-{編號} {標題}
- 類型：{分派表的卡片類型}
- 來源：{從哪裡發現：實測紀錄、驗證報告、課堂觀察、事故分流}
- 範圍：{會動到的檔案或對象}
- 預期變動：{完成後只應該變動哪些檔案或內容}
- 驗收：{指令或可觀察條件}
- 證據要求：{結案所需的最低證據等級}
- 相依：{前置卡片或無}
- 狀態：todo / doing / blocked / provisional / done
- 結果：{實際證據、卡點、新開的卡}
```

每個欄位都有用途：驗收和預期變動用來判斷是否真的完成，證據要求決定由誰結案，來源讓每張卡都能追溯，範圍和相依決定能否交給夜班。

## 分派表

| 卡片類型 | 執行器 | 矩陣能力 | 結案證據要求 |
|---|---|---|---|
| 講義文字改善 | Course Iteration System「課程迭代」「文案迭代」（`courses/course-manager/docs/course-loop-quickstart.md`） | E1、E2 | 人工閱讀確認（H3） |
| 講義套用到 HTML | Course Iteration System「講義套用」 | F2 | 隔離預覽通過，再由人工比較 |
| 規則可機器化 | `docs/lint-page.py` 或 `docs/` 腳本 | E2、G3 | 機器驗證，誤報由人判斷 |
| 交付物重建（下載包、搜尋索引、sitemap） | 對應產生器腳本 | H1 | 機器驗證，加上線上比對 |
| 學員能否完成 | 獨立 AI 試走（course-validator） | G4 前置 | 只算模擬證據；G4 需真人 |
| 平台實測、真人試走 | 人 | D6、G4 | 真人 |
| 教學判斷、取捨、發布 | 人 | A、C、H1 | 人工決定 |

不在表內的類型，先寫進卡片的「類型」並標「需人判斷」，累積到第二次出現才考慮補進本表。

## 證據等級

| 等級 | 來源 | 能證明 | 不能證明 |
|---|---|---|---|
| M 機器 | lint、測試、雜湊、線上比對 | 是否符合已寫下的規則 | 內容是否正確、學員是否看懂 |
| A 自查 | 作者 agent 在原 context 檢查 | 明顯遺漏 | 作者自己的盲點 |
| A 隔離 | fresh context 的試走者或審查者，只拿到成果與驗收條件 | 文字可讀性、一致性、漏洞 | 真實環境操作、視覺品質、新手實際卡點 |
| E 真人 | 真人學員、講師、領域專家 | 實際能否完成 | 只涵蓋實測過的範圍 |
| H 決定 | 使用者 | 接受取捨、風險與發布 | — |

- 卡片的證據沒達到「證據要求」，狀態只能是 `provisional`（暫定完成），並同時開一張由對應等級確認的卡。
- 急件可以用 A 隔離證據先推進，但依矩陣 G4，AI 模擬永遠不能取代真人試走；暫定項目在下次回報時一併列出，直到補驗。
- 多個 agent 意見一致仍屬 A 等級。

## 運作規則

1. 夜班只領類型可交給執行器、證據要求為 M 或 A、相依已完成的卡，依編號順序。
2. 夜班從 `main` 開 worktree 作業，不動主 checkout。
3. 收工前跑完驗收，並比對實際變動與「預期變動」；多出未預期的變動就不算完成。
4. 碰到教學判斷改標「需人判斷」後跳過；同一根因失敗兩次就停下，寫明卡點。
5. 範圍外的發現開新卡，不順手修。
6. 每個佇列第一張夜班卡完成後，先由人看過再放行後續。
7. merge、push、部署、對外發送一律由人放行。
