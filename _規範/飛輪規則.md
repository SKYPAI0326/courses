# 飛輪規則（錯誤轉改進）

錯誤或學員卡關發生時，先分流再動手。本檔只收原則，以及已機器化、待機器化規則的指標；不再為每次事故新增一節。

---

## 分流

每次事故依序判斷，停在第一個符合的步驟：

1. **違反下方既有原則** → 修正該實例（講義、試跑包、腳本或任務卡），不新增條文。
2. **可由機器檢查** → 寫進 `docs/lint-page.py` 或 `docs/` 下的腳本，本檔只留一行指標。
3. **工具或平台知識**（某軟體的預設值、錯誤訊息對應、外部服務門檻）→ 寫進 Obsidian 知識庫（先進 `00-收件匣/`），並把修正做進該課的試跑包或講義。
4. **確實沒有原則涵蓋** → 才修改本檔原則，並寫明新原則防的是哪一類錯誤。

---

## 原則

### 一、學員要能獨立走完主流程

商業培訓學員（行銷、營運、知識工作者、主管）要的是能用的結果，時間預算約課堂 3 小時、在家 1 小時，環境卡關就可能放棄整門課；課程進行時旁邊也沒有 Claude。主流程因此必須是多數學員不靠協助就能走完的路徑。

- **主流程門檻**：列出每一步的外部門檻（綁卡、買網域、OS 版本、網路環境、要會的技能），乘起來估算通過率。90% 以上寫成主流程；50–90% 降為 `<details>` 折疊的進階；低於 50% 拿掉，或標明「本節純概念說明，不需實作」。
- **三層結構**：環境建置、整合服務、API 串接類單元分為主流程（步驟最少、立刻看到成果）、進階（完整或生產級設定）、備用方案（標明「主流程完全不通才用」）。
- **排錯只給單一動作**：允許「重新下載最新 zip 覆蓋整個資料夾，再雙擊 `start.command`」「再雙擊一次，依對話框按一個按鈕」「按下這個按鈕」。禁止要學員開終端機跑 `sed`／`awk`、手動編 yaml／.env／.json、執行指令組合，或給「方案 A 重下／方案 B 手動修」二選一。
- **新卡關的處理順序**：能在試跑包預設值避免 → 改預設；能由啟動腳本偵測（grep logs）→ 加偵測與 GUI 對話框；兩者都做不到 → 才寫成單一動作的排錯，無法自修的錯誤跳「請聯絡講師」並說明要貼哪幾行 logs。
- **原理同步提供但不強制**：每個交付物附「為什麼這樣設」「怎麼改」，沒看也能用；想深入的學員有進階段落或 Builder Track 評量可選。對商業培訓而言，「沒心的拿模板，有心的學原理」是合適的定位，不要求學員一定要學原理。
- **修補累積就重整**：同一單元累積 3 個以上主流程修補時，整章改寫成新主流程，不再加第 4 個揭露框或替代段落。

檢核問題，全部為「是」才合格：

1. 學員下載資源後，30 分鐘內能看到成品嗎？
2. 卡關時能不開終端機、不打指令、不編 yaml 就解決嗎？
3. 想學原理的學員能自己查到完整解釋嗎？
4. 主流程的外部門檻乘起來，90% 學員過得去嗎？

適用範圍：商業培訓課程。自學工程師導向的課程仍可強調原理深度。
案例：2026-04-30～05-02 n8n 課連續 8 次學員卡關；m1-2-tunnel 由 7 步重整為 3 步，完整 Tunnel 降為進階。

### 二、外部服務門檻誠實揭露

外部 SaaS 的免費門檻會變動。每個註冊步驟前寫明當下實際門檻（綁卡、手機驗證、付款資料），不用「依當前規則可免費使用」這類模糊說法；替代路徑只給一條。門檻資料有時效：在該課 `_change-log.md` 記錄回檢日期，超過 90 天要重新驗證。學員回報「要綁卡」「政策變了」時，先更新揭露，再確認替代路徑仍然存在。

### 三、交付證據取自學員的終點

「檔案存在」不等於學員拿得到、跑得動。需要學員下載、解壓、執行的交付物（試跑包、workflow 範本、範例專案、素材包）都要過三層：

| 層級 | 檢核問題 | 驗收動作 |
|------|---------|---------|
| L1 檔案就位 | 檔案、子資料夾、README 都在嗎？ | `ls` 確認 |
| L2 打包可下載 | 講義頁有單一按鈕下載完整包嗎？ | 有 `<a href="...zip" download>` 主按鈕，不是 N 個個別檔連結 |
| L3 解壓可執行 | macOS 解壓後 `.command` 能雙擊執行嗎？ | README 第一次啟動段有 `chmod +x` 與 `xattr -d com.apple.quarantine` 指引 |

含執行檔的試跑包，講義頁要有：zip 主按鈕、macOS chmod 提示 `<details>`、個別檔備援 `<details>`（附「需自建子資料夾」提示）。
評估報告寫法：L1–L3 都過寫「✓ 試跑包完整交付」；缺 L2 或 L3 寫「⚠️ 檔案就位但學員下載動線斷裂」；缺 L1 寫「❌ 試跑包尚未建立」。
有部署的交付物，驗收的最後一步是比對線上檔案，例如下載檔雜湊。

### 四、學員頁只放學員視角

教案 `_lessons/{slug}/{unit-id}.md` 的內部欄位不一定都該渲染。教學流程、商業情境案例、動手練習、真實錯誤與修復、檢核與遷移要完整渲染；試跑包需求清單（Verification Asset Spec）、「為什麼這樣設計」等課程設計理由只給 PM 與講師，不渲染。派給 `course-lesson-writer`、`build-course-page` 的 prompt 要明確列出不渲染的區塊；已誤渲染就整段移除並重編後續 section。例外：原屬試跑包段、實際是學員工具的內容（如三行診斷指令），改寫成學員視角後保留。
案例：2026-04-23 n8n 課 m1-1 三頁誤渲染講師清單與設計理由，刪 76 行修復（commit 01a92bf）。

## 已機器化（只留指標）

- **密碼關卡**：`bash docs/audit-gates.sh`，偵測 placeholder hash、雙重 gate、K key 與 `inject_gate.py` 不一致、任何密碼都通過。新課上線前、`inject_gate.py` 改完都要跑；`course-web-builder` 不嵌 gate，統一由 `course-register` 與 `inject_gate.py` 注入。
- **push 後確認遠端收到**：`bash docs/safe-push.sh`，比對本地與遠端 HEAD，並檢查 open PR 是否含最後一個 commit；跑完才通知可以 merge。修補類 commit 不和註冊或大量內容 commit 放在同一個 PR。若 PR 已先被 merge，把遺漏的 commit cherry-pick 到新分支另開 PR，並在說明中註明。
- **複製按鈕定位**：機器檢查見 `docs/lint-page.py`；人類規範見 `_規範/design-tokens.md` §3。
- **學員頁不得出現的教案內部字眼**（原則四）：機器檢查見 `docs/lint-page.py` 的 `check_internal_course_terms`（WARN）；正當用法見 `_規範/design-tokens.md`「教案內部字眼防火牆」。
