# 講義改寫 SOP — PM 規格制

> 本檔是**既有課程講義整課改寫**的流程真相源：怎麼診斷、誰寫規格、誰承作、驗到什麼程度、怎麼上線。
> 視覺規則仍以 `design-tokens.md` 與 `docs/lint-page.py` 為準；內容組織原則見 `操作型講義.md`。本檔只管改寫流程與規格書。
> 由 2026-11-01 `gen-ai-36h` 全課 28 頁改寫經驗萃取（commits `afd5dc6f`、`cc2b60f6`、`679a75bc`，merge `c28dda49`）。完整過程與證據見 `courses/gen-ai-36h/_review/2026-11-01/`。

---

## 0. 何時採用

### 適用
- 整門課或整個 Part 要重寫，不只是改措辭。
- 講義有下列任一症狀：像待辦清單、突然開始突然結束；學員多數時間在人工閱讀、核對、手算、手填表，而不是指揮 AI；正文充斥案例碼、測試碼、檔名、英文欄名。
- 以「學員用 AI 完成工作」為核心、有素材包與答案檔的操作型課程。

### 不適用
- 只修錯字、局部措辭：用文案流程即可。
- 沒有素材包的課：先補素材，否則承作模型會自行編造案例。
- 新開課：走 `課程製作團隊系統手冊.md`。

## 1. 角色分工

| 角色 | 由誰擔任 | 負責 |
|---|---|---|
| 產品經理（PM） | Claude（主 session） | 診斷、寫大綱草案與規格書、檢查、退回、寫入與上線 |
| 承作者 | GPT-5.6 Sol（reasoning effort high），經 Codex 執行 | 依規格書改寫學員正文，頁尾附自我檢查與事實核對 |
| 使用者 | 課程負責人 | 確認大綱方向、平台方案取捨、合併 main 與跳過檢查等不可逆操作 |

**為什麼這樣分**：實驗顯示，承作模型只拿到簡短說明（「不要像清單、要以 AI 為主、不要編號」）時，產出不合格；拿到 PM 寫的詳細規格書就合格，速度也快。現有課程技能沒有「以 AI 為主」的規則，部分條文（凍結欄名、要求顯示檔名）還會推高編號，所以**改寫時不套用 course-* 技能**。

## 2. 流程

| 步驟 | 做什麼 | 完成判準 |
|---|---|---|
| 0 診斷 | 跑代理指標（識別碼密度、人工詞與 AI 詞比例、限制語數）；讀大綱標題與每頁完成物 | 判斷問題在上游（大綱、完成物、教案骨架、素材命名）還是只在文字 |
| 1 大綱 | 重寫 Part 名、單元標題、每頁要教會的 AI 能力與完成物（主項必須是 AI 做出的成果）；同步課程 CLAUDE.md 的主軸 | **使用者確認**後才改正式檔 |
| 2 落筆層 | 確認學員正文的唯一來源（例如 `_lessons/<slug>/`），以及 HTML 怎麼產生；HTML 若曾被直接修改，記下會被覆蓋的部分 | 有一個明確的來源檔與轉製方式 |
| 3 規格書 | 依第 3 節寫；性質相近的 Part 可以合寫一份 | 每頁設計、素材、必守規則、交付格式齊全 |
| 4 承作 | 每個 Part 交給承作者一次；彼此獨立的 Part 可並行 | 每頁有學員正文＋自我檢查＋事實核對 |
| 5 PM 檢查 | 用腳本檢查硬規則；抽查數字、日期、欄位是否和素材一致 | 沒有硬規則問題、事實無誤；有明確問題才退回，**最多一次** |
| 6 寫入與轉製 | 寫進來源檔、教案改成指向來源、更新 meta 與首頁卡片；轉製 HTML；lint 結果與改版前比對 | lint 不新增問題；只有預期的頁面被修改 |
| 7 commit | 逐檔 stage；搜尋索引只收本次頁面的條目；改寫前的備份不進 repo | 只含本次檔案 |
| 8 上線 | 在乾淨的臨時 worktree 合併到 main，重建索引與 sitemap 後 push | push 檢查通過，Pages 部署完成 |

## 3. 規格書必備內容

範本：`courses/gen-ai-36h/_review/2026-11-01/part34/改寫規格書-Part3-4.md`（多 Part 合寫）、`.../part5/改寫規格書-Part5.md`（含平台與資料分配表）。

1. **頁面設計表**：每頁新標題、副標、要教會的 AI 能力、完成物、要拿掉或改掉的做法。
2. **素材表**：每頁用哪些素材檔。事實以素材與答案檔為準，現有正文只用來理解案例。
3. **必守規則**（每條都來自真實出過的錯）：
   1. **核對交給 AI**：要 AI 附出處、列出沒有依據的句子、開新對話校對。學員只抽看 AI 標出的 3 處以內。
   2. **看執行結果也交給 AI**：工具或流程跑完，把結果貼給 AI 對照預期，學員只看 AI 列出的不一致。
   3. **每次開新對話或換工具，寫明要貼什麼**。
   4. **案例附人物或資料表**：第一次出現時附表；文件用內容稱呼，不用檔名或代碼。
   5. **PRAC 頁不先給答案**：只給「要達成什麼」清單；參考寫法放頁尾，前面加「先完成自己的版本，真的卡住再看」；不附完整範例輸出，改給自我檢查清單；正文與提示詞都不寫出答案；完成後才開答案檔，比對也交給 AI。
   6. **單人可完成**：「請同伴」一律改成「開新對話請 AI 扮演同事、委託人或第一次使用的人」。
   7. **提示詞以動詞開頭**，不用「你是…」。
   8. **不出現代碼與章節編號**：跨頁引用寫內容，例如「整理工作訊息那一節學過的三個問題」。
   9. **每個小節最多一句限制語**，其餘改成正面寫法。
   10. **檔案交給 AI 的方式寫清楚**：CSV、md 複製全文貼進對話；HTML 存檔後用瀏覽器打開。工具做不到就換免費工具，不寫「手動完成」。
   11. **敘事骨架**：第一段寫工作情境；每段第一句接住上一段；最後一段收回成果並接下一頁。第一個 `##` 之前只放標題、副標、本節完成物三行。
4. **有狀態的流程加資料分配表**：每頁送進工具的是哪幾筆、預期結果是什麼、哪些留到後面。沒有這張表，前後頁一定互相矛盾。
5. **平台事實裁定**：素材互相矛盾時，以實際跑過的設定為準，並寫進規格書。平台的介面位置只寫素材或官方說明能支持的部分，其餘標「畫面以實際為準」。
6. **交付格式**：`# 標題`、副標、`本節完成物：…`、各 `##` 小節、提示詞放 ``` 框；頁尾「## 自我檢查」與「## 事實核對」。只寫指定的輸出檔，不 git add、不 commit、不詢問使用者、不用 course-* 技能。

派工時明確指定承作模型：`--model gpt-5.6-sol --effort high`，並要求前景跑完。

## 4. 驗證政策（精簡）

- **預設只做**：PM 腳本檢查硬規則＋事實抽查；有明確問題退回一次。
- **預設不做**：雙模型盲評、多輪冷讀、模擬試讀。這些每輪都會找到新的小問題，投入大、改變不了交付決定。
- **例外**：有狀態的自動化流程（例如 Make），請一位評分者依實際設定逐步推演一次資料狀態。gen-ai-36h 的 Part 5 有三個阻斷問題（一次只讀一列、讀過的列不再觸發、試算表 ID 有兩處），都是這樣抓到的。
- **新增任何驗證前先問**：它能改變交付決定嗎？不能就不做。

---

## 5. 必須先問使用者的事

- 大綱方向：Part 名、標題、完成物。
- 平台方案取捨，例如自動化流程要不要加 AI 模組；提出方案與證據，交使用者裁決。
- 不可逆或略過保護的操作：合併 main、`--no-verify`、刪檔、修改別人未追蹤的檔案。

其他事項（措辭、規則細節、驗證層級）由 PM 決定，記在該課的改寫記錄表。

## 6. 常見坑

| 坑 | 症狀 | 做法 |
|---|---|---|
| HTML 與上游脫節 | HTML 被直接改過，從上游重轉會蓋掉 | 步驟 2 先定落筆層 |
| 轉製程式缺陷 | 只轉部分頁時證據檔被整份覆蓋；練習順序時數錯 | 改寫前先用一頁在複本上試轉，比對外殼與元件 |
| 開場段被丟掉 | 轉製只轉 `##` 小節內容 | 規則 11；寫入腳本把開場段併進第一節 |
| 跨頁狀態矛盾 | 已處理的資料被重貼、故障練習與路線不一致 | 規格書第 4 項分配表 |
| PRAC 洩漏答案 | 範例、參考寫法、素材編號、訊息稱呼透露答案 | 規則 5；素材本身的洩漏另案修素材 |
| 混合工作區 | 別人有未提交修改；索引、sitemap 重建混入他人內容 | 改寫前備份別人改過的檔；逐檔 stage；索引只收本次條目 |
| push 檢查擋下 | 未追蹤檔違規、索引與工作區不一致 | 在乾淨 worktree 合併與 push |
| 驗證成癮 | 一個上午只完成三分之一 | 第 4 節 |
