# 文件更新了：讓 NotebookLM 比較新舊版本，整理現在有效的條件
新文件只改了一部分。請 NotebookLM 列出哪些條件被取代、哪些仍然有效。
本節完成物：NotebookLM 整理的版本比較表與現行條件摘要；附帶：AI 起草的採購追問信

## 新文件來了，先分清它改了什麼

星河成果展的承辦人已收到新版範圍更新，但舊核准仍保留部分有效條件，供應商報價和會議摘錄又各有不同權限。若把「日期較新」當成唯一判斷，NT$25,000 的未接受報價可能被誤寫成新版核准金額。這一節會讓 NotebookLM 比較四份來源，交付版本比較表、現行條件摘要和採購追問信。

這次比較會用到以下人物與資料：

| 人物或資料 | 角色與用途 |
|---|---|
| 許主任 | 核准原始基準與範圍更新；會議中再次說明預算和下單狀態 |
| 採購同仁 | 說明供應商報價，提出詢問修正版的方向 |
| 核准範圍 | 提供原始日期、人數、期限、支出上限與採購程序 |
| 範圍更新 | 明確取代三個欄位，並保留其他核准條件 |
| 供應商報價 | 提供商品規格、報價總額與有效期限 |
| 採購會議摘錄 | 記錄暫停下單、比較方案與仍待指派的工作 |

開啟上一頁建立的「星河工作包」。如果需要重新下載來源，可從[星河成果展素材入口](../assets/workplace-cases/part3-demo/START-HERE.html)取得；開始前勾選核准範圍、範圍更新、供應商報價和採購會議摘錄四份內容。

## 讓 NotebookLM 產出版本比較表

四份資料已經選好，現在先讓 AI 判斷每個條件屬於被取代、仍有效或未決。留在「星河工作包」，保持四份來源全數勾選，再貼上：

```
比較星河成果展四份來源，整理成版本比較表。表格列出「條件、原內容、後續內容、目前狀態、判斷理由、引用」。

至少涵蓋活動日期、人數上限、海報初稿期限、場地與印刷支出上限、供應商報價、供應商選擇與是否能下單。把目前狀態分成「被新版取代」「仍然有效」「未決」，並以來源明確取代或核准的內容作為改變狀態的依據。不同性質的金額分列，各自保留欄位名稱與狀態。
```

NotebookLM 應把三個時程與人數欄位列為被新版取代，把支出上限列為仍然有效，並把供應商選擇與追加款保留為未決。這張表不是按文件日期排序，而是看每份文件明確改動了哪個欄位。

## 請 AI 先找出混用版本的風險

版本比較表已經完成，現在讓 NotebookLM 自己找出可能把舊值、新值或不同金額混在一起的地方。留在「星河工作包」，保持四份來源全數勾選，再貼上：

```
檢查上一張版本比較表。列出可能混用舊版與新版、把報價誤當核准、把提案誤當決定的地方；逐項說明正確寫法並附引用。若表內結論超出來源，就直接提出修正版。
```

看完 AI 的檢查結果，只點開它標為「被新版取代」的三處引用：活動日期、人數上限、海報初稿期限。這三處應該都回到範圍更新的明確取代表，而不是只回到舊核准或供應商報價。

如果其中一處引用沒有直接支持取代關係，就把該列退回 NotebookLM 修正。完成後保留修正版比較表，接著把它濃縮成同事可以直接採用的現行條件。

## 把版本比較表濃縮成現行條件摘要

修正版比較表已經分清新舊與權限，現在請 NotebookLM 只留下目前工作真正要用的條件。留在「星河工作包」，仍勾選四份來源，再貼上：

```
整理一份「目前有效條件摘要」，只採用修正版比較表內有引用支持的內容。分成「目前採用」「仍然有效」「尚未決定」「可立即進行的下一步」四段。每個條件附引用，並保留核准上限、供應商報價與差額各自的名稱和狀態。最後列出任何需要主管決定或指派的事項。
```

合格摘要會清楚說明目前活動安排與有效支出上限，也會保留報價尚未接受、追加款未核准和詢價責任人待指派的狀態。這份摘要可以直接附在追問信前，讓收件人先看懂現況再回答問題。

## 讓 AI 起草一封能推進工作的追問信

現行條件摘要已指出未決事項，最後請 NotebookLM 把它們改寫成一封有收件目的的採購追問信。留在「星河工作包」，保持四份來源全數勾選，再貼上：

```
起草一封給活動負責人的內部追問信。先用三句內摘要目前有效的活動條件、核准支出上限與未接受報價，再詢問：
- 由誰負責取得減項報價與第二家報價？
- 希望何時收到可比較的報價？
- 既有展示架由誰向場地方確認？
- 若方案仍超過核准上限，要減項還是另提追加核准？

語氣簡潔、可直接回覆。每個事實在句末附引用；未決事項寫成問題，不要代替活動負責人做決定。
```

把版本比較表、現行條件摘要和追問信放在一起，接手者就能看出哪些條件已更新、哪些仍有效、哪些要等回覆。下一頁會換成海岸志工日資料，讓你獨立完成同一套查證與交接。
