# 用 NotebookLM 為海岸志工日整理可接手的筆記
換一組資料，獨立讓 NotebookLM 整理已定事項、還不能採用的說法和待追問事項。
本節完成物：NotebookLM 產出的海岸志工日現況筆記（附引用）與待確認清單

## 接手一個資料分散的志工活動

你剛接手海岸志工日，下一位承辦人需要知道目前哪些安排已核准、哪些說法還沒有依據，以及採購為什麼停住。資料分散在專案簡報、核准變更、供應商報價和交通會議紀錄裡；這次要獨立讓 NotebookLM 產出附引用的現況筆記與待確認清單。

先認識這次會遇到的人與資料：

| 人物或資料 | 角色與用途 |
|---|---|
| 林主任 | 志工服務專案負責人；核准專案基準與後續變更 |
| 場務同仁 | 確認既有接駁資源是否可用 |
| 志工窗口 | 依已確認資訊更新志工提醒稿 |
| 採購同仁 | 比較交通方案、報價和核准範圍 |
| 專案簡報 | 提供活動基準、支出上限與發布條件 |
| 核准變更 | 記錄新版集合地點、提醒稿期限與未決事項 |
| 供應商報價 | 提供接駁服務、價格與有效期限 |
| 交通會議紀錄 | 區分已決事項、預計回覆與待指派工作 |

開啟[海岸志工日素材入口](../assets/workplace-cases/part3-solo/START-HERE.html)，下載四份工作來源。建立名為「海岸志工日交接」的 NotebookLM 筆記本，加入專案簡報、核准變更、供應商報價和交通會議紀錄；如果 Markdown 檔無法上傳，就打開檔案，複製全部文字貼進新增來源，並用文件內容命名來源。

## 讓 AI 整理目前能採用的事項

筆記本已經建立，第一步要讓 NotebookLM 找出目前可採用的條件，並把舊說法和不同權限的金額分開。留在「海岸志工日交接」，勾選四份工作來源，完成以下目標：

- 讓 AI 整理活動安排、提醒稿、交通狀態與支出條件。
- 讓每個結論附上能直接支持它的引用。
- 讓 AI 區分「已核准」「仍有效」「未確認」。
- 讓 AI 把核准上限與供應商報價分開呈現。
- 讓 AI 將來源沒有寫的內容保留為未知。

先完成自己的提問；需要提示時，頁尾有「卡住時的參考寫法」。完成後保留 NotebookLM 產出的第一版現況筆記，下一步會請 AI 專門找出不能採用的說法。

## 請 AI 找出還不能採用的說法

第一版現況筆記已經整理出已知事項，現在要讓 NotebookLM 檢查是否把預計回覆寫成已確認，或把報價寫成已核准。留在「海岸志工日交接」，仍勾選四份工作來源，完成以下目標：

- 讓 AI 逐項檢查現況筆記是否超出來源。
- 讓 AI 列出容易混淆的舊版資訊、預計回覆、報價和提案。
- 讓 AI 對每個問題提出修正文句並附引用。
- 讓 AI 標出影響活動發布或採購決定的三個關鍵點。
- 只點開 AI 標出的三處引用，確認原文支持修正版。

把需要修正的內容交回 NotebookLM 更新，保留修正版現況筆記。這樣下一位承辦人看到的會是「目前能採用什麼」，而不是一份混合已知與猜測的摘要。

## 讓 AI 產出待確認清單

修正版現況筆記已排除沒有依據的說法，接下來要把未知事項變成能推進工作的待確認清單。留在「海岸志工日交接」，仍勾選四份工作來源，完成以下目標：

- 讓 AI 列出交通、詢價、責任人、期限與核准方面的未知事項。
- 讓每一項寫明應詢問的角色、詢問原因和目前已知範圍。
- 讓每一項寫明收到什麼證據才算確認。
- 讓 AI 依「先影響發布、再影響採購、最後影響交接」排序。
- 讓 AI 把現況筆記與待確認清單合併成可接手版本。

合格的結果要能回答：

- 哪些活動與文件條件目前可以採用？
- 哪些交通與採購說法仍缺少證據？
- 哪一份來源支持每個結論？
- 下一位承辦人應先問誰、取得什麼資料？
- 在收到新證據前，哪些內容應維持待確認？

## 完成後，讓 AI 對照教師答案

可接手版本已完成，現在才開啟素材入口中的教師答案。把答案加入「海岸志工日交接」後，勾選四份工作來源與教師答案，並把自己的可接手版本貼進新的提問，完成以下目標：

- 讓 AI 比對自己的版本與教師答案，列出一致、遺漏、超出來源三類結果。
- 讓 AI 為每個差異指出對應來源與修正理由。
- 讓 AI 只修正有證據支持的內容，保留文字風格不同但意思相同的部分。
- 讓 AI 產出最後版現況筆記與待確認清單。

最後開新對話，把最終版貼給 AI，要求它扮演第一次接手這個活動的承辦人，指出仍看不懂或無法採取下一步的地方。依回饋做最後一次修訂後，你就完成了從多份來源找答案、辨認版本與證據權限、用引用交接未知事項的整套能力；下一個主題會把需求交給 AI，做成可以實際操作的工作小工具。

## 卡住時的參考寫法

先完成自己的版本，真的卡住再看。

整理目前能採用的事項：

```
整理海岸志工日目前可採用的現況筆記。涵蓋活動安排、提醒稿、交通狀態與支出條件；把結果分成「已核准」「仍有效」「未確認」。每個結論附引用，並將核准上限與供應商報價分開呈現。來源沒有寫的內容保留為未知。
```

找出還不能採用的說法：

```
檢查上一份現況筆記是否把舊版資訊、預計回覆、供應商報價或會議提案誤寫成目前可採用的結論。列出問題、修正句與引用，並標出最影響發布或採購決定的三個關鍵點。
```

產出待確認清單：

```
整理仍會影響海岸志工日發布、採購與交接的未知事項。每項列出要問的角色、詢問原因、目前已知範圍、需要取得的確認證據與優先順序。最後把修正版現況筆記和待確認清單合併成可接手版本。
```

完成後比對教師答案：

```
比較下方可接手版本與已勾選的教師答案，將結果分成「一致」「遺漏」「超出來源」。逐項附上支持判斷的來源與修正理由，再產出只修正有證據問題的最後版本。

我的可接手版本：
［貼上自己的現況筆記與待確認清單］
```

檢查接手者是否看得懂：

```
扮演第一次接手海岸志工日的承辦人，閱讀下方現況筆記與待確認清單。指出哪些地方仍無法判斷目前狀態、責任角色或下一步，並提出具體改寫建議。

最終版：
［貼上最後版現況筆記與待確認清單］
```

## 自我檢查

### 學員動作分類與比例

| 分類 | 本頁動作 | 次數 |
|---|---|---:|
| AI 產出 | 產出現況筆記、待確認清單、最後版交接筆記、第一次使用者回饋 | 4 |
| AI 協助判斷 | AI 找出不能採用的說法；學員抽看三處引用；AI 比對教師答案 | 3 |
| 純人工 | 無 | 0 |
| 工具操作（不計） | 下載與加入來源、勾選來源、貼上自己的版本 | 3 |

計入比例的動作共 7 次，其中 7 次屬於 AI 產出或 AI 協助判斷，比例為 100%；每個小節的純人工動作為 0。

### 規格逐條檢查

| 規格 | 是否做到 | 本頁做法 |
|---|---|---|
| 1. 核對交給 AI | 是 | 要 AI 檢查超出來源的說法與比對教師答案，學員只抽看三處引用 |
| 2. 看工具結果也交給 AI | 是 | 要 AI 判斷現況筆記、差異和接手可讀性 |
| 3. 新對話或換工具交代輸入 | 是 | 每次寫明「海岸志工日交接」與需勾選的來源；新對話寫明要貼最終版 |
| 4. 案例附人物或資料表 | 是 | 案例首次出現即提供人物與資料用途表 |
| 5. PRAC 頁規則 | 是 | 正文只列目標，提示詞集中頁尾；沒有完整範例輸出或案例答案 |
| 6. 單人可完成 | 是 | 以新對話中的 AI 扮演第一次接手的承辦人 |
| 7. 提示詞以動詞開頭 | 是 | 使用「整理」「檢查」「比較」「扮演」開頭 |
| 8. 不用代碼溝通 | 是 | 正文與提示詞均用文件內容稱呼來源 |
| 9. 限制語密度 | 是 | 每個小節最多一句限制語警語 |
| 10. 寫清楚檔案怎麼交給 AI | 是 | 說明 Markdown 無法上傳時複製全文貼入來源，並說明如何貼自己的版本 |
| 11. 開場與收尾 | 是 | 開場交代交接情境，收尾回扣來源查證能力並接到工作小工具 |
