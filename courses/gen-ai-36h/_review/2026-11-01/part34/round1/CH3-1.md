# 用 NotebookLM 回答工作問題，並附上原文出處
把星河成果展的採購文件放進 NotebookLM，請它回答問題、標出引用；文件沒寫的，請它直接說沒寫。
本節完成物：NotebookLM 產出的採購問答（每題附引用）；附帶：NotebookLM 整理的待追問清單

## 先把工作文件變成可追查的答案

你接手星河成果展的印刷採購，主管想知道目前活動安排、預算和報價狀態。這些資訊散在核准範圍、更新通知、供應商報價和會議摘錄裡；如果只挑一份看，很容易把舊日期或未核准的金額寫進回覆。這一節會讓 NotebookLM 讀完指定來源，做出每題附引用的採購問答與待追問清單。

先認識這次會遇到的人與資料：

| 人物或資料 | 角色與用途 |
|---|---|
| 許主任 | 活動負責人；核准活動基準與後續範圍更新 |
| 採購同仁 | 提供報價狀態與可詢價方向 |
| 行銷同仁 | 提出減少方向牌或使用既有展示架的想法 |
| 核准範圍 | 記錄原本的活動安排、採購程序與支出上限 |
| 範圍更新 | 說明哪些欄位被新版取代、哪些條件繼續有效 |
| 供應商報價 | 記錄印刷規格、價格與報價有效期限 |
| 採購會議摘錄 | 區分已決定的事、提案與仍待指派的工作 |

先開啟[第一次建立來源筆記本指南](../assets/notebook-start.html)，下載[入門用星河活動 PDF](../assets/mock-project-v1.pdf)。照指南建立「PDF定位練習」，只加入這份 PDF；這個短練習能先確認帳號、來源上傳和引用功能都能使用。

在「PDF定位練習」中確認只勾選入門 PDF，再貼上：

```
回答星河活動的活動日期。只依目前勾選的來源作答，並在答案後附上能直接支持日期的引用；來源沒有寫的內容就標示「來源未提及」。
```

NotebookLM 回答後，點開日期旁的引用，確認它帶你回到 PDF 第一頁。這一步是在練習「答案可以回到原文」，接下來才換成真正的採購工作包。

## 建立只含四份採購來源的工作筆記本

剛才已確認引用能回到原文，現在把同一套做法用在完整採購情境。開啟[星河成果展素材入口](../assets/workplace-cases/part3-demo/START-HERE.html)，下載核准範圍、範圍更新、供應商報價和採購會議摘錄。

另建一個名為「星河工作包」的筆記本，加入這四份來源。入門 PDF 是另一個教學版本，因此不放進這本筆記本；如果 Markdown 檔無法上傳，就打開檔案，複製全部文字貼進新增來源，並用文件內容命名來源。

開始提問前，在「星河工作包」的來源清單勾選以下四份內容：

- 核准範圍
- 範圍更新
- 供應商報價
- 採購會議摘錄

確認四份來源都能展開原文，這樣 NotebookLM 才能把核准、報價和會議狀態分開回答。

## 讓 NotebookLM 產出附引用的採購問答

四份來源都就緒後，現在讓 NotebookLM 一次整理主管真正需要的答案。留在「星河工作包」，保持四份來源全數勾選，再貼上：

```
整理星河成果展的採購問答，逐題回答：
1. 目前有效的活動日期、人數上限與海報初稿期限是什麼？
2. 場地與印刷的核准支出上限是多少？
3. 供應商報價是多少、有效到哪一天，和核准上限相差多少？
4. 現在能否下單？文件已決定的下一步有哪些？

每一題都附上能直接支持答案的引用。把核准金額、供應商報價、已決定事項和提案分開寫；來源沒有寫或尚未決定的內容，明確標示「來源未提及」或「尚未決定」。
```

你應該會看到 NotebookLM 把新版活動安排、仍有效的支出上限、未接受的報價和暫停下單分開呈現。AI 可能把不同性質的金額混在一起，所以接下來會把核對也交給它先做，再由你抽看少數關鍵引用。

## 請 AI 先查自己的證據，再抽看三處

剛才的問答已經有引用，現在請 NotebookLM 檢查每個結論是否真的受到原文支持。留在「星河工作包」，保持四份來源全數勾選，再貼上：

```
檢查上一份採購問答的每個結論。用表格列出「結論、支持來源、原文支持範圍、是否有超出原文、需要怎麼改」。特別檢查目前活動日期、兩種金額的性質，以及是否能下單。每列附引用；沒有充分依據就改成未知或待確認。
```

看完 AI 的檢查表，只點開最關鍵的三處引用：新版活動日期、核准支出上限、暫停下單。這三處分別決定時程、金額權限與可否執行，最能攔下會影響採購判斷的錯誤。

如果引用沒有落在支持結論的句子，直接要求 NotebookLM 改寫該列並補上正確引用。完成後保留修正版採購問答，下一步要處理文件沒有回答的問題。

## 把來源沒有寫的事變成待追問清單

修正版問答已分清已知與已決，現在把未知事項整理成可以交給主管處理的問題。留在「星河工作包」，仍勾選四份來源，再貼上：

```
整理這四份來源仍未回答、但會影響採購下一步的事項。每項寫成一個可直接詢問的問題，並列出「要問的角色、為什麼要問、目前來源已知到哪裡、收到什麼證據才算確認」。每項附上顯示目前仍未決的引用。不要自行補上負責人、期限、場地設備或核准結果。
```

合格的待追問清單應該讓主管看得出要確認什麼、要找哪個角色，以及收到什麼資料才算有答案。你現在已經有一份附引用的採購問答和待追問清單；下一頁會沿用這四份來源，讓 NotebookLM 比較新舊版本並整理目前有效的條件。

## 自我檢查

### 學員動作分類與比例

| 分類 | 本頁動作 | 次數 |
|---|---|---:|
| AI 產出 | 產出入門回答、採購問答、待追問清單 | 3 |
| AI 協助判斷 | AI 檢查證據；學員抽看三處引用並決定是否修正 | 2 |
| 純人工 | 無 | 0 |
| 工具操作（不計） | 下載來源、建立筆記本、上傳與勾選來源 | 4 |

計入比例的動作共 5 次，其中 5 次屬於 AI 產出或 AI 協助判斷，比例為 100%；每個小節的純人工動作為 0。

### 規格逐條檢查

| 規格 | 是否做到 | 本頁做法 |
|---|---|---|
| 1. 核對交給 AI | 是 | 要 NotebookLM 逐項檢查證據，學員只抽看三處引用 |
| 2. 看工具結果也交給 AI | 是 | 要 NotebookLM 列出超出原文與需要修改之處 |
| 3. 新對話或換工具交代輸入 | 是 | 每次都寫明筆記本名稱與勾選來源 |
| 4. 案例附人物或資料表 | 是 | 案例首次出現即提供人物與資料用途表 |
| 5. PRAC 頁規則 | 不適用 | 本頁不是獨立練習頁 |
| 6. 單人可完成 | 是 | 全部活動可由一位學員與 AI 完成 |
| 7. 提示詞以動詞開頭 | 是 | 使用「回答」「整理」「檢查」開頭 |
| 8. 不用代碼溝通 | 是 | 正文與提示詞均以文件內容稱呼來源 |
| 9. 限制語密度 | 是 | 每個小節最多一句限制語警語 |
| 10. 寫清楚檔案怎麼交給 AI | 是 | 說明 Markdown 無法上傳時複製全文貼入來源 |
| 11. 開場與收尾 | 是 | 開場交代採購情境，收尾接到版本比較 |
