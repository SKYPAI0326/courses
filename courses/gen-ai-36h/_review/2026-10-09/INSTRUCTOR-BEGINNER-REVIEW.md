# gen-ai-36h 講師與零基礎學員可用性審查

審查日期：2026-10-09。範圍：課程總覽、28 個講義／實作頁、課程素材、課程大綱及既有修復紀錄。此次只新增審查文件，未修改講義。

## 結論

**目前可當講師備課素材庫，尚不足以直接作為零基礎學員跟做的正式講義。教學可用性判定：BLOCK。**

教材有值得保留的辦公情境、提示詞模板、分步示範與修復腳本，但主要教學路徑存在中斷；部分示範把未提供的事實當成可採用答案；作業與驗收互相矛盾。熟悉工具的講師可以現場補橋接步驟，零基礎學員卻很難判斷自己漏做了什麼。

**遣詞確實偏繁瑣，也有不夠淺白的地方。** 主要負擔來自同一概念反覆包成故事、口訣、提醒、踩坑、課後行動，再加一段操作契約；英文標籤與製作端欄位混入學員指示；大量「一定」「必備」「幾秒完成」取代適用條件。只縮短句子，仍無法修復這些教學問題。

本報告列出 **6 項 BLOCKER、8 項 MAJOR、1 項 MINOR**。這是人工教學審查結果，與 lint 的機器規則不同。BLOCKER 代表核心操作、交付或正確判斷受阻；MAJOR 代表講師必須補充或修訂才能順利教學；MINOR 代表局部校對問題。

## 七個部分的教學判斷

| 部分 | 值得保留的學習成果 | 實際授課的主要障礙 | 建議 |
|---|---|---|---|

| Part 2 文書 | 用原始資料產出並修訂文件 | 延期信示範捏造進度與承諾；部分「完整」回應只是占位文字 | 先教事實核對，再教語氣與精簡；補完整輸入與結果 |
| Part 3 知識管理 | 根據來源找答案並保留引用 | 「不幻覺」過度保證；自備資料負擔大；Audio 操作與實作重複 | 提供共同來源包，實作改成新問題與引用核對 |

| Part 7 專題 | 展示能被核對的成果與使用方法 | 四類專題卻共用 HTML 部署衝刺；發表頁分享未帶出個人填寫內容 | 依作品類型提供交付路徑，實測保存與分享 |

## 開課前必修：BLOCKER

### B01｜PRAC5 的手動分類無法接上自動化路由

位置：[PRAC5 步驟 2、5–7][prac5]，原檔第 336、344–348 行；另見第 371 行的 System Prompt。

步驟 2 建的是八欄 Sheet；步驟 5 卻要求回填 `category`、`summary`、`next_action`、`review_status`，與課程九欄素材契約不一致。步驟 6 說 JSON Parse 屬於 API 選做，步驟 7 隨即要求「在 JSON Parse 後加 Router」。流程起點監看 Forms 回應，但沒有教如何重新讀取人工補入 Sheet 的分類欄位，也沒有把人工覆核狀態接成發送條件。

**新手會卡在：分類已填好，Make 為什麼拿不到？JSON Parse 到底在哪裡？** 這不是加一句提醒能解決的問題。

建議固定共同主線：課程資料 → 網頁 AI 分類 → 回填九欄表格 → 人工確認並標記已覆核 → Make 讀取該列 → 依分類分流 → 發送到自己的測試目的地／留下紀錄。逐步標明「來源欄位 → 目的欄位」、觸發條件、預期輸出與重跑方式；實測 T01–T04。API 版另成選做分支，主線不出現其模組。這是修復方向，尚未驗證為可用情境。

### B02｜部分核心操作仍使用停用或停止開發的平台

位置：[CH5-2 n8n Desktop 安裝][n8n]第 311–318 行、608–612 行；[CH5-1 LINE Notify][line]第 475–507 行。

n8n 官方在 2023-05-03 宣布停止 Desktop 版本開發；教材仍把下載 Desktop 當入門與練習要求。[官方公告](https://community.n8n.io/t/sunsetting-self-hosted-team-plan-desktop-version/25830)。LINE Notify 已於 2025-03-31 結束服務，教材仍示範取得 Token 與 HTTP 發送。[官方結束服務公告](https://notify-bot.line.me/)。

建議刪除這些必做操作，重新選定並實測課程環境。不能直接把 LINE Notify 換成 Messaging API 名稱就算完成，後者涉及不同帳號、權限與流程。若 n8n 屬選做，學習成果、練習與作業也應一致改為選做。

### B03｜資料政策與「不幻覺」保證會教出錯誤判斷

位置：[CH1-1 敏感資料][privacy]第 529–530 行；[CH1-1 NotebookLM][notebook]第 391–396 行；[CH2-3][multimodal]第 354、414 行。

「付費版預設不訓練」把個人付費訂閱與商務服務混為一談。OpenAI 官方區分個人服務的資料設定與 Business／Enterprise 等商務服務的預設政策，不能只靠是否付費判斷。[資料使用官方說明](https://help.openai.com/en/articles/5722486-how-your-data-is-used-to-improve-model-performance)。教材還把姓名、金額可能出現在別人答案裡寫成確定的情境推論，沒有提供足以支持這種說法的證據。

「不編造、不幻覺、每個答案附來源頁碼」也超出可保證的範圍。Google 對 Audio Overview 明確提醒可能有不準確內容。[Google 官方說明](https://support.google.com/notebooklm/answer/16212820?hl=en)。有來源約束與引用，仍要核對回答是否真的受來源支持。

建議改為：「先確認公司的上傳規範、帳號類型與資料設定。練習使用課程提供的虛構資料。AI 回答後，打開引用，核對人名、日期、金額與結論。」資料提醒放在第一次上傳及對外發布前，其他頁只連回該檢查點。

### B04｜延期信範例把捏造承諾當成精修成果

位置：[CH2-2 對話示範][email]第 273、313–345 行。

已知資訊是客戶案件、供應商缺料與延後五個工作天。AI 卻新增「已完成 60%」「加急運費全額吸收」「後續所有里程碑仍將準時」。講義只修語氣與字數，接著稱讚更有擔當、重點突出，沒有辨識新增事實與未授權承諾。

**這會讓初學者把流暢的文字誤認為可寄出的內容。** CH1-2 與 PRAC1 也有要求補救方案、但未提供可承諾選項的類似問題。

建議把原回應保留為錯誤示範，逐句標出新增事實；補一版不擅自承諾的草稿。若要練兩個補救選項，先提供已核准方案。驗收順序應為「事實與權限 → 讀者看得懂 → 語氣與字數」。

### B05｜報價與儀表板缺少足以產生正確答案的規格

位置：[CH4-2 報價完整 Prompt][quote]第 735–791 行、849–850 行；[CH4-3 月度趨勢][dashboard]第 391–439 行。

報價期間可選 3／6／12 個月，季付顯示卻固定「× 4 期」。期間不同，應分別為 1／2／4 期。原規則先折 15% 再折 3%，總折扣 17.55% 是乘算結果；後文卻把它當問題，提出相加或乘算任選，等於改動業務規則。

儀表板只提供 2025/05–2026/04 十二個月的隨機數據，卻要求 YoY 與去年同期曲線，缺少前一年資料。營收持平、訂單下降也無法單獨證明客戶流失；某月偏低無法單憑圖表確認農曆年效應。

建議提供固定資料與人工算好的核對表。例如月費 30,000、無折扣、含教材設定的 5% 稅額，三個月合計 94,500，季付應為一期 94,500；六個月為兩期、十二個月為四期。YoY 提供前一年基準，否則顯示「缺少去年資料，無法計算」。原因分析改成待查假設，示範資料清楚標示為虛構。

### B06｜可編輯的工具箱／發表頁沒有保存與個人分享交付路徑

位置：[PRAC6 填寫區][toolbox]及第 363–379 行；[PRAC7 填寫區][showcase]第 176–263 行、275–278 行、312–321 行。

兩頁使用 `contenteditable` 讓學員直接填寫，但程式碼沒有將填寫內容保存或匯出。PRAC6 提供列印／PDF 提示，這可保留靜態副本，卻未交代如何持續編輯與月更。PRAC7「複製本頁網址」只複製 `window.location.href`；沒有將個人內容寫入可分享頁面，LinkedIn 連結的 `url` 參數也為空。

**依程式碼，填完不等於已保存作品；複製範本網址也無法把個人編輯交給別人。** 現有 localStorage 用於登入／瀏覽紀錄，不是填寫成果。本次未做瀏覽器重新整理及跨裝置實測。

建議選定清楚的交付形式，例如可保存的個人文件或有匯出與部署流程的 HTML。教材要教保存、再次開啟、修改與分享。驗收必須實際重新整理，並讓另一個瀏覽環境開啟成果，確認內容仍在。

## 局部校對：MINOR

**N01｜數量與標題不一致。** PRAC3 的五個 Notebook／提示詞與實際列項不一致；PRAC2 開場說兩件，實際列三件；CH4-2 UTM 練習第 1111 行說八個渠道，答案第 1126 行為九個。這些容易讓學員以為自己漏讀。逐頁統一標題、實際列項及驗收數量即可，不必改課程結構。

## 遣詞如何改得淺白，又不刪掉必要教學

| 原文／原寫法 | 閱讀問題 | 建議改寫 |
|---|---|---|
| AI 工具地景：選對工具、事半功倍（CH1-1:199） | 地景抽象；後半只有宣傳效果 | 四種 AI 工具怎麼選 |
| 四欄缺一不可；順序不能打亂（CH1-2:291–295） | 把輔助模板變成記憶規則 | 先寫清楚要做的事。需要指定語氣、長度或格式時，再補上這些要求。 |
| 不編造、不幻覺、每個答案附來源頁碼（CH1-1:396） | 簡短但錯誤保證，不能靠精簡保留 | 它能根據上傳資料回答，並提供引用。回答後仍要打開引用核對。 |
| 跨 Part 交接欄位：artifact_id、source_page…（CH6-1:452） | 十個欄位一次湧入，且模板接不住 | 每個工具記下：何時用、要準備什麼、會得到什麼、怎麼檢查，以及失敗時從哪裡重做。 |
| 本節操作契約：Demo／Together／Solo／Check（各章頁末） | 教學管理術語不等於學員下一步 | 先看老師示範，再用同一份資料一起做。接著換一份資料自己試，最後用下方清單檢查結果。 |
| 連結或 NOT_RUN（PRAC6／7） | 狀態碼沒有直接告訴學員能交什麼 | 已測試：貼成果連結。尚未測試：填「尚未測試」，並寫下一步要怎麼測。 |
| 營收持平但訂單數下降＝客戶流失（CH4-3:391） | 從觀察跳到未驗證原因 | 訂單數下降了。先看客戶數、回購與訂單金額，再查原因。 |
| 一看就知道那個月農曆年效應（CH4-3:395） | 讓學員以為看圖即可確定因果 | 這個月低於其他月份。查一下工作天數、活動與客戶資料，再確認原因。 |

上述是審查用示例，沒有直接套用到講義。保留必要的來源、人工檢查與失敗處理，不把它們全部刪成口號。完整範例、欄位對應與核對答案應補足；優先刪減重複的勵志敘事與分類標籤。

## 補充：是否足夠基礎，能否逐步建立實務能力？

**主題排列有由淺入深的方向，但零基礎的起步與章節間能力銜接仍不足。** 若學員已用過 AI、會處理檔案與表格，講師可以利用這些內容帶做；對第一次接觸 AI 的學員，教材仍需要講師大量口頭補充。這是教材內容與依賴關係的判斷，尚未經真人試走驗證。

「零基礎」應先界定：此課至少需要基本瀏覽器、複製貼上與檔案操作能力。若連這些也不熟，應另提供操作預備包。免寫程式仍可能涉及表格欄位、條件判斷、權限、檔案與部署概念，不能省略這些前置教學。

### 目前有打底的地方

- CH2-1 用摘要、分類、改寫、潤稿區分任務，這是很適合入門的實務入口。

- 全課從文書、來源整理、小工具走到流程整合，應用範圍與辦公工作定位一致。

### 尚未形成完整學習階梯的地方

| 能力層次 | 現況 | 要補上的教學橋接 |
|---|---|---|
| 理解 AI 的工作方式 | 第一堂主要比較四個工具的功能、優劣與訂閱；錯誤與上下文觀念散在後續章節 | 先用同一份短資料展示「提供資料 → 提要求 → 生成 → 核對」，說明流暢不代表正確、工具功能與模型並非同一件事 |
| 完成第一次操作 | 同時要求四個帳號登入；第一部分很快進入四欄公式、進階提示及三個專屬助手 | 先在一個主工具完成一個小任務，教新對話、送出、追問、複製與保存；確認成功再介紹其他工具 |
| 判斷答案可否使用 | 有人工檢查提醒，但部分示範沒有真的逐句核對新增事實 | 教「已知／未知／AI 自行新增」標記；先核對事實與引用，再看語氣與格式 |
| 從對話轉為工具 | 有三層架構，但生成結果與人工規格之間缺穩定對照成品與答案 | 先用表格手算一筆，再把同一規則做成工具；用正常與邊界案例核對 |
| 從手動轉為自動 | 名詞有解釋，實際欄位、觸發、覆核與重跑交接仍中斷 | 先人工跑完一筆，記下每一步的輸入與輸出；再用自動化重做相同步驟 |
| 獨立完成與交付 | 範本很多，但部分重複示範；保存分享與最低驗收不一致 | 第二次換資料、減少提示；最後獨立完成、保存並讓他人開啟核對 |

重複一個流程可以幫助熟練，但每次應增加不同要求：第一次照做，第二次換資料，第三次自己選方法並解釋原因。只換情境名稱、仍貼同一組提示詞，無法證明獨立能力。

### 建議的核心能力階梯

| 階段 | 學員這次學會什麼 | 進入下一階段前，應能獨立完成 |
|---|---|---|
| 1 初次使用 | 用一個工具，把需求與原始資料交給 AI | 把五行工作紀錄整理成三點摘要，核對並保存 |
| 2 修訂與核對 | 補缺少資訊、追問、辨識新增事實 | 找出一封草稿裡未提供的日期／承諾，修成可核對版本 |
| 3 根據來源工作 | 上傳共同素材、找引用、區分來源內容與推論 | 回答三個問題，每題指出支持答案的來源；找不到就說明缺資料 |
| 4 可驗證的小工具 | 把確定規則轉為輸入、計算、輸出 | 同一組測試資料，手算與工具結果一致，至少測一個邊界 |
| 5 流程與自動化 | 理解觸發、欄位、條件、人工確認及失敗處理 | 用一筆共同資料完成分類與紀錄，再改成受控的自動流程 |
| 6 整合與交付 | 選擇適合的方式，保存、分享並說明限制 | 另一個人能取得成果、知道怎麼用，學員能說出如何檢查與重做 |

這份階梯可由既有內容重整，不代表需要全面新增章節。四工具比較、Few-shot、專屬助手、n8n 雙平台、外觀美化等，宜放在核心能力完成後再引入，或列為選做。

「整個生成式 AI 實務應用」應依本課定位解讀為辦公工作的主要應用路徑。課程不必擴張到所有圖像、影片、模型訓練或 API 主題；先讓學員理解不同任務如何準備資料、檢查結果與交付，才有機會將方法遷移到新工具。
