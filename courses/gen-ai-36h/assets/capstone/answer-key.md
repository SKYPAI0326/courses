# 教師核對答案｜新人訓練專題

先完成 CH7 與 PRAC7 的摘要、來源表、測試和交接，再使用本答案。答案示範完整推理與修正，不要求逐字相同。

## 核心來源狀態

- **政策：**11/12、20 位上限、手冊和講義 11/09 前完成沿用 POL-01；POL-02 只把地點由 2A 改為 3B、把報名截止由 11/06 改為 11/09。
- **日期碰撞：**11/09 同時出現在報名截止和講義期限，兩者意義不同。遇到更新必須逐欄位判斷，不能全域取代。
- **門市狀態：**`project-status.csv` 共有 4 家 confirmed、2 家 pending；時間為 10/02 09:00。S05、S06 沒有個人回覆。
- **報名人數：**沒有個人名冊或報名數欄。`staff_count` 合計 21，只代表門市員工欄位的加總，不能寫成 21 位報名者。
- **加開名額：**MEET-1002 只有建議，POL-02 仍限定 20 位；未核准。
- **文件用途：**REQ-01 要求內部審核草稿、來源對照、測試與可重做交接；不得宣稱已通知學員。

## 變更範圍測試

若正式核准文件只把「報名截止」改為 11/10：

| 欄位 | 結果 | 原因 |
|---|---|---|
| 報名截止 | 改為 11/10 | 新文件只改此欄 |
| 講義完成期限 | 仍是 11/09 前 | POL-02 沒有取代它 |
| 訓練日／地點 | 11/12／3B | 未被新文件提及 |
| 名額上限 | 20 位 | 加開提案仍未核准 |

需先取得正式文件，再修訂；不能用假設更新當作真的核准。測試 T06 要記錄搜尋到的每個日期字串及判斷理由。

## 常見錯誤修復

| 不可靠句子 | 修復 |
|---|---|
| 「教室 2A」 | 改為 3B，引用 POL-02 |
| 「報名截止 11/06」 | 改為 11/09，引用 POL-02 |
| 「六家都已報名」 | 寫 4/6 家確認、2 家待回；門市確認不是個人報名 |
| 「共有 21 位報名」 | 刪除；員工數不等於名單，總數未知 |
| 「已核准加開 5 人」 | 改為未決提案，現行上限 20 |
| 「講義期限也改為 11/10」 | 若更新只改截止，講義仍 11/09 前 |
| 「同伴測試通過」 | 無真人證據時維持 PENDING；平台未實測時標 NOT_RUN |
