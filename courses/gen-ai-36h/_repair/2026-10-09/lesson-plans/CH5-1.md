# 理解觸發與欄位：先跑最小流程

<!-- learner-content:start -->
## 自動化從一件看得見的動作開始
前面已把人工工作做清楚。現在用Make把「新資料出現」接到「寫入紀錄」。「觸發」是啟動流程的事件；「模組」是一個動作；「映射」是把來源欄位放入目標欄位。第一堂不加AI或寄信，完成物是一筆新列對應一筆紀錄與執行證據。

先開[表格配置與表頭](../assets/part5-sheet-layout.md)、[已覆核示例CSV](../assets/part5-reviewed-queue.csv)、[完整人工重建步驟](../assets/part5-rebuild-guide.html)。需要Google帳號、Make帳號與可授權的教學試算表。沒有連線權限時停在表格演練，不能記自動化已完成。

先開[四課建置狀態與草稿映射](../assets/part5-stage-handoff.html)。本課只完成階段 S1；本節結束應有一筆 ProcessingLog，Drafts 仍可為空。把最後成功的執行 ID 與試算表位置寫入自己的 `Part5-建置紀錄`，下一節從這份狀態接續。

## 示範：一個觸發，一個寫入
建立教學試算表，分頁 Source、ReviewedQueue、ProcessingLog、Drafts。依配置放好表頭後，從已覆核示例 CSV 只取第一筆「小林／詢問方案」，九欄資料各放一格，分別貼入 Source 與 ReviewedQueue 的第 2 列。兩張表都應看到同一筆完整示例，ProcessingLog 與 Drafts 此時只有表頭；先不要貼後三筆。Source 留作原始資料對照，ReviewedQueue 這份已覆核教學示例供流程讀取，中途不空白。

在Make建立Scenario，新增Google Sheets的Watch New Rows，建立連線並選試算表、ReviewedQueue；Table contains headers選Yes，表頭範圍A1:I1，Limit=1。首次起點選All讀既有測試列；之後正式練習改從現在開始，避免把舊資料再跑一次。官方指出[中途空列會阻止後續列處理](https://apps.make.com/google-sheets-modules)，所以不要在表頭下留空列。

第二模組Add a Row選ProcessingLog。source_key先以submitted_at、email、subject合成，category映射分類，route寫「測試」，status寫「已記錄」，draft_status寫「不需要」。點Run once，看觸發輸出的一筆資料與寫入結果。

## 跟著做：映射要看值，不只看線
核對輸入是inquiry、來源時間2026-10-09T09:00、主旨詢問方案；紀錄的category應仍是inquiry。若email跑到subject欄，重新選對應標題欄，不靠手動在結果表改值掩蓋映射錯誤。

沒有輸出先查起點、表名、空列；連線失敗先查帳號與權限，保留來源，不刪列重造。課程主線只寫紀錄及草稿，沒有對客戶寄出的動作。

## 自己試：新列和改舊列不同
先確認前一筆已寫入 ProcessingLog，且 ReviewedQueue 沒有尚未讀取的新列。把 Source 第 2 列 message 中的「請問基礎方案月費」改為「請問基礎方案費用」，不要改 ReviewedQueue。再按 Run once，應沒有新 bundle，ProcessingLog 筆數不增加：這次只改了另一張表的舊列。接著從示例 CSV 取第二筆「小安／交期問題」，完整追加到 ReviewedQueue 第 3 列，再 Run once，應只新增一筆 category=complaint 的紀錄。S1 的 route 仍是「測試」；下一節才改成客服分支。

保存來源列、執行ID或截圖、ProcessingLog結果與問題紀錄。表格演練與實際連線證據分開；下一節才加條件與分類，避免同時出錯卻找不到哪一步。
