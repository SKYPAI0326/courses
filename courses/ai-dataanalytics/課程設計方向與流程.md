## 2. 課程核心與學員起點

### 2.1 核心承諾

學員使用 LLM 網頁服務搭配 Excel，上傳準備好的商務工作簿，確認工作表與資料範圍，再釐清問題、處理基本資料問題、完成可核對的數值分析，生成基本圖表與簡短摘要，並用已知公式比較兩個假設情境。最後能修改提示詞，在新的分析目的或資料條件下完成一次基本轉用。

課程帶來的幫助是降低開始分析與表達成果的門檻，減少反覆查找操作方法及撰寫初稿的工作。資料、計算與結論仍須由使用者核對；不承諾速度提升比例或 AI 自動保證正確。

### 2.2 適合對象與必要能力

適合經常整理 Excel 報表、比較工作數字、向主管說明成果的商務工作者。

學員需具備基本電腦與網頁操作能力，能使用 Excel 編輯資料、輸入簡單公式及篩選，並以文字說明工作需求；不需程式設計或數據分析背景。

製作課前檢查時，至少確認學員能開啟及儲存檔案、切換工作表、修改儲存格、完成簡單加總與篩選，以及登入網頁服務、上傳指定工作簿並貼入提示詞。未通過者提供可直接跟做的補救說明；不能把這些基本操作留到課堂中才首次教學。

完整的數據分析需要從工作問題走到可使用的判斷。本課程教授其中可在六小時內實作的基本流程，其他部分明確標示自學或專業界線。

## 5. 工具分工與操作路徑

### 5.1 通用方法與最低環境

LLM 泛指市面上的網頁端語言模型服務。教學方法維持通用，但讀檔、計算、製圖、預覽與下載是各服務的功能，不能因模型會生成文字就宣稱全部支援。

共同環境為可操作的 Excel、網路及可上傳、讀取課程 `.xlsx` 多工作表檔案的 LLM 網頁帳號。授課服務、模式與方案必須用實際練習檔測試；接受上傳的介面或成功收到附件，都不能證明資料已完整讀取。教材以 Excel 2019 可用的基本功能設計，避免新版專屬公式、外掛及學員自行安裝程式。學員不需要使用 Codex；Codex 是製作與驗收的輔助工具。

完整資料以檔案上傳為主。貼上用於提示詞、需求說明，或已核對的少量樣本與彙總值；不要求學員把整份 Excel 或多張工作表逐段貼入對話。方法以通用 LLM 為基礎，但只有符合上述讀檔條件的網頁服務可作為課堂主要平台。

| 路徑 | 操作方式 | 課堂定位 | 必須驗證 |
|---|---|---|---|
| A 讀檔及圖表工具 | 上傳工作簿，列出工作表並核對指定資料範圍；整理並核對彙總表；以服務工具製圖及保存 | 已實測服務上的主要操作路徑 | 指定帳號能辨識各工作表及完整讀取指定來源表，產出圖表、保存並重新開啟 |
| B 讀檔及 SVG | 沿用對話中已核對的彙總表，或上傳已核對彙總檔，生成靜態 SVG；預覽或另存後開啟 | 課堂示範、課後替代製圖路徑 | 彙總來源與版本、實際預覽、另存方法、中文標籤及圖形比例；少量數值貼上僅為可選方式 |
| C 讀檔及 Excel | 上傳並核對來源資料；LLM 提出公式、步驟與摘要；Excel 執行計算及製圖 | 缺少計算或原生製圖工具時的備援 | 仍須通過讀檔核對；指令可轉成學員能執行的 Excel 步驟 |
| D 預先準備的回應 | 暫時無法使用服務時，以保存的 AI 回應範例繼續 Excel 練習 | 暫時排錯備援 | 可完成資料操作，但不計為已完成當次 LLM 實作 |

LLM 優先製圖的課堂承諾，必須有路徑 A 的實測證據及可用帳號。路徑 C 可支援基本分析，缺少主要製圖功能時要說明受影響項目及補做安排。僅有文字對話功能不符合本課程的最低讀檔環境；路徑 D 可維持練習進度，但不能算成完成 LLM 讀檔或製圖實作。

開課前選定示範服務及支援範圍，依帳號條件測試。其他服務可以嘗試同一方法，但未測分支不能列為已驗證。不要讓全班在同一時段各自排查完全不同的介面。

### 5.2 圖表與 SVG 的設計原則

- 正式圖表來源為單元三已核對的彙總表；選圖、繪圖與美化不得偷偷改變數據。
- 核心先限於長條圖、折線圖等基本圖形；不要求三維、雙軸、互動儀表板或大量圖表。
- 圖表需要期間、單位、類別、數值與來源說明；長條圖通常從零開始，其他尺度選擇須說明理由，避免誤導。
- SVG 先使用靜態圖形與文字，不要求學員寫座標或修改程式。指令要描述希望改什麼，成品仍檢查數值、比例與排版。
- PNG 可能由精確繪圖程式產生，也可能由圖片模型生成；SVG 也可能使用錯誤數值。副檔名不能作為正確性的證據。
- 圖片生成可展示版面或資訊圖的設計用途，但不能跳過數值、標籤與比例核對。
- 修改配色、字體與標籤後，回查數值是否保留；修改分組、期間或指標時，回到計算階段重新核對。
- 圖表可獨立保存，不強制 SVG 嵌入 Excel。各種檔案插入 Word、簡報或報表的方式，以實際軟體版本測試為準。

### 5.3 Excel 多工作表的讀取與核對

第二項依序操作以下步驟，在原有 50 分鐘內試跑；採少量工作表，不新增複雜整併任務。

1. **上傳前看完整工作簿。** 確認上傳權限，檢查所有工作表與隱藏內容是否含敏感資料；只需部分資料時另存可分享的副本。記錄實際檔名與版本。
2. **先辨識，再分析。** 請 LLM 列出可辨識的工作表、用途、欄位與資料範圍，區分原始明細、欄位說明、規則及既有彙總。由學員對照 Excel 工作表清單，指出漏掉或無法讀取的部分。
3. **指定使用範圍。** 明確指定納入的工作表、表頭、資料區與期間，以及排除哪些表、總計列或備註。參考表不當成交易明細，既有彙總不與明細重複加總；篩選及隱藏列是否納入須明示。
4. **核對完整性與數值。** 明確定義有效資料筆數，不把表頭、空白列或總計列算進去；對照 Excel 筆數、首尾識別碼、選定欄位抽查及獨立加總。模型自述筆數或只展示前幾列不能證明完整讀取；這些檢查是基本核對，不能保證任意複雜工作簿都已正確解析。
5. **確認後才清理與計算。** 對未讀到的工作表、範圍或未知欄位停止相依分析，先修復。資料或檔案版本變動後，重新核對受影響範圍，保留來源與檢查紀錄。

公式、儲存的計算值、日期、合併儲存格、隱藏表及外部連結的讀取行為依平台而異，須在平台試跑記錄；不能假定上傳會重新計算 Excel 公式。課堂來源明細優先用清楚的表格與固定值，公式核對仍由 Excel 重算。跨表合併須另定欄位與連結規則；工作表名稱相似不代表可以直接串接或相加。

若完整工作簿讀取失敗，先用已測帳號與格式重試；必要時將指定來源表另存為 `.xlsx` 或各自匯出 CSV，附上工作表對應及範圍，再上傳核對。CSV 一份只對應一張表，不能視為保留整份工作簿的公式、格式與表間關係。課堂應預先提供經核對的拆分備援檔，不把臨時手動拆分大量資料交給初學者。

## 6. 教學內容的設計順序

每單元都從「學員為什麼做、手上有什麼、要留下什麼」開始，再教必要概念及操作。先完成教學內容、素材及完整示範，後做講義排版或 HTML。

1. **定義學員任務與完成物。** 寫出情境、問題、材料取得方式、結果用途、第一個動作、成功訊號及失敗回修位置，沿用專案 Learner Task Contract。
2. **補足必要概念。** 在第一次操作前解釋欄位、資料粒度、分母、比較基準、假設與圖表比例。用案例說明，不能只有名詞清單。
3. **製作一筆完整示範。** 顯示實際輸入、Prompt、處理理由、中間結果、Excel 核對及可打開的完成品。
4. **安排同步練習。** 學員沿用材料，但至少增加一個新的判斷，例如換分組或選擇缺漏處理方式，避免重複播放同一示範。
5. **撤除部分提示。** 第七項用已教方法改變一個主要條件，讓學員自行修改指令、操作與核對，不突然加入新分析方法。
6. **就近提供檢查與修正。** 每個關鍵操作指出「應看到什麼、怎麼查、錯了回哪裡」，保留重跑起點與原始資料。
7. **交接給下一步。** 清理後資料交給統計，統計結果交給製圖，核對後結果交給摘要及試算。不得引用後續才建立的材料。

學員正文需在不閱讀教師筆記的情況下仍可跟做。教師備註可說明時間與觀察重點，但必要答案、素材、示範或修復不能只藏在教師區。

## 7. 資料與檔案設計

### 7.1 主案例規格

主案例沿用銷售資料，貫穿前六項；第七項改變分析目的或一項條件。主要輸入檔為 `.xlsx` 工作簿，建議包含「銷售明細」「欄位說明」「處理規則」三張工作表，讓學員實作辨識工作表及選定來源。統計只使用「銷售明細」，其餘表用來理解與核對，不加入數值加總；課堂不要求跨表合併。

為控制時間，銷售明細先設計約 30–60 筆，涵蓋足夠的月份與類別供比較；工作表名稱、筆數及欄位是製作建議，需以試作調整，不是已完成素材。多月份資料先放在同一明細表，避免同時增加按月分表整併的新方法。

欄位建議為 `record_id`、`sale_date`、`department`、`product`、`quantity`、`unit_price`、`unit_cost`，配繁中欄位字典與單位。每列是一筆銷售明細；明細筆數不能直接當成客戶數或訂單數。

計算規則先固定：營收為數量乘單價；銷售成本為數量乘單位成本；毛利為營收減銷售成本。毛利不等於淨利。占比需指出分母；期間差異需說明比較基準。缺少成本就不能算毛利，缺少時間就不能做期間比較。

資料問題只放入少量、可判斷的缺漏、重複或格式錯誤，每個問題都有固定識別方式及處理理由。不能為了湊練習而要求學員猜測或補造資料。原始版、參考清理版、修改紀錄與標準計算結果必須一致。

### 7.2 必備檔案與用途

以下是後續必須製作的檔案規格，目前不視為已存在。

| 檔案類型與建議名稱 | 設計內容 | 使用時機 | 驗收方式 |
|---|---|---|---|
| `sales-source.xlsx` | 主要上傳檔；含銷售明細、欄位說明、處理規則，固定 record_id、非敏感資料 | 第二項上傳、工作表辨識及清理 | Excel 與測試服務能辨識工作表；指定明細表的範圍、有效筆數、日期及數字核對一致 |

學員完成物為自己的分析工作簿、至少一張可重新開啟的基本圖表、簡短摘要、兩個情境的比較、可重用指令及核對紀錄。圖表不必全部嵌入工作簿；保存位置與格式要明確。

### 7.3 保存與交付規則

- 每份學員材料說明檔名、用途、取得方式、何時使用及無法開啟時的備援；不能只列一個檔名。
- 參考答案與起始材料分開，練習前不要直接提供已填完的答案檔。
- 原始檔保留，處理後另存，修改紀錄可追溯。
- 多工作表檔案是否完整辨識、指定來源表是否完整讀取、公式是否能重算、CSV 是否正確讀取、SVG 是否顯示、圖表是否能匯出，都要實際操作驗證。
- 不要求學員自行製作缺少的核心素材，不把「請自行找一份資料」作為課堂起點。

## 8. 提示詞設計與測試

### 8.1 設計原則

提示詞服務於分析任務，不以角色設定、長篇指令或漂亮輸出代替方法。第一項先提供可用的基本指令，第六項再解釋如何修改；不能讓初學者前段只複製、最後才第一次理解指令。

每份指令都要說明使用情境、必要材料、需填欄位、依賴功能、輸出、核對方式與失敗回修。資料分析指令以已上傳檔案為來源，明列工作表、範圍及排除規則；純文字指令用於需求澄清、方法說明與改寫，小樣本貼上僅為可選測試方式。讀檔與工具執行條件區分清楚：缺少計算功能時，要求公式與 Excel 步驟，不假裝執行過計算。

共用結構可使用下列骨架，正式製作時必須填入實際欄位、規則與輸出範例：

```text
工作目的：{要回答的問題與報告對象}
資料來源：{已上傳檔名與版本、指定工作表、表頭與資料範圍}
排除範圍：{不納入的工作表、總計列、備註或其他範圍}
資料定義：{每列意義、欄位、單位、期間}
分析規則：{分組、公式、分母、比較基準、缺漏處理}
可用功能：{已驗證的讀檔功能，以及可用的計算／圖表工具}
請先確認：{可辨識工作表、來源欄位、有效筆數與缺少的資訊；無法讀取時停止相依分析並說明}
請輸出：{方法、中間表、結果、來源與限制}
限制：不得補造數值；無法執行的步驟須明示並提供替代方式。
驗證：{使用者要以什麼參考值、Excel 公式或檢查表核對}
```

「不得補造」或「請確認」只是指令要求，不能當成防錯保證。必須用實際輸出驗證它有沒有遵守。

### 8.2 指令套件規格

| 指令 | 要解決的問題 | 必須附上的核對內容 |
|---|---|---|
| 需求澄清 | 把工作問題轉成對象、期間、指標及用途 | 缺少成本、日期或分母時，應指出無法完成哪些分析 |
| 讀檔與欄位檢查 | 列出工作表與用途，指定來源表、範圍、有效筆數及欄位，排除參考與重複彙總 | 對照 Excel 工作表清單、筆數、首尾識別碼、抽查值及獨立加總；不以模型自述或上傳成功作證 |
| 清理建議 | 找出資料問題，先提出處理方案 | 對照固定規則及修改紀錄，禁止默默刪除或補值 |
| 計算與彙總 | 產出加總、分組、占比及期間比較 | 公式、分母、中間表與參考值 |
| 計算差異排查 | 協助找出不同結果的原因 | 原始筆數、篩選、公式、單位與四捨五入 |
| 基本圖表 | 依已核對彙總表產出圖表 | 不重新估算數據；核對軸線、比例、標示與保存結果 |
| SVG 替代製圖 | 將少量已核對數值轉成靜態 SVG | 完整檔案或可保存原始碼、預覽與比例檢查 |
| 摘要與工作報告 | 把已驗證數字寫成主管可讀的說明 | 數字來源、不支持的因果、限制及下一步 |
| 情境試算 | 用固定公式比較不同假設 | 基準值、被改變的條件、其餘固定條件與公式 |
| Prompt 改寫 | 將現有指令轉用到新需求 | 修改前後差異、缺件、功能需求與小樣本測試 |
| 回復與重跑 | 解決讀檔、計算、製圖及保存失敗 | 回修位置、重跑起點、哪些成果需重新驗證 |

課後問卷與方案評分的指令另附方法教材，不混入基本數值指令就宣稱已涵蓋新方法。

### 8.3 改寫 Prompt 的固定流程

1. 提供原指令、目前資料定義及新的需求；不把敏感資料作為改寫的必要材料。
2. 請 LLM 列出需修改的欄位、指標、規則、報告對象與輸出格式，指出無法完成的部分。
3. 使用者確認修改清單，再產出新版指令；保留仍適用的定義及限制。
4. 用小樣本執行，對照已知結果；有差異先查資料條件與公式。
5. 通過後再處理完整資料，核對結果，保存指令版本與使用條件。

正式範例至少呈現不同目的的改寫：月份改成產品比較、主管摘要改成部門說明、欄位名稱改變但指標相同，以及資料缺少成本時撤除毛利分析。不得只換公司名稱或語氣就當成不同範例。

### 8.4 指令測試方式

使用固定輸入與獨立參考答案，記錄服務、模型或模式、方案、日期、指令版本、輸出及人工修正。至少測試正常資料、多工作表辨識與來源選擇、缺必要欄位、一種資料問題、一次目的變更與工具功能不足。多工作表測試要確認未漏掉指定來源範圍、未把說明或彙總表重複納入；若教材包含公式、隱藏或篩選資料，另驗其讀取行為及宣稱範圍。

分類或文字摘要允許合理表述差異，數值案例依明確計算規則判定。反覆請同一個 LLM 自查不能替代獨立核對；換另一個模型也不能單獨成為正確性的證據。

## 9. 課後素材與作業

基本作業從銷售、費用或庫存數值範例選一項，用已教方法修改需求與指令，上傳提供的資料檔、核對來源範圍，完成分析、圖表或摘要及核對。作業包需說明檔案內各工作表的用途；不要求逐表貼資料，也不要求上傳公司真實資料。

| 素材包 | 學員回去可以做什麼 | 必備內容 |
|---|---|---|
| 銷售分析 | 月份、產品或部門比較，整理業績摘要 | 樣本、字典、完整示範、Prompt、Excel 核對、參考結果、修正 |
| 費用比較 | 分類支出、比較期間及占比 | 沿用加總與分組；說明分類規則及分母 |
| 庫存整理 | 觀察類別及數量分布，列出待查項目 | 區分快照與期間資料；不延伸承諾需求預測或最佳採購量 |
| SVG 製圖 | 在服務無原生圖表時保存基本圖形 | 已核對彙總表、完整指令、SVG 範例、另存與預覽、排版修復 |
| 問卷與文字回饋 | 依分類規則整理意見 | 新方法說明、完整示範、原文編號、分類規則、人工抽查與例外 |
| SWOT 與加權評分 | 整理方案差異與討論依據 | 方法、準則、權重、評分理由、Excel 檢查及人工確認；不等同完整 AHP |
| 工作報告與需求轉用 | 把驗證結果整理成摘要並調整受眾 | 報告範例、指令改寫前後、數字追溯及檢查表 |

延伸自學須另標示先讀哪份方法說明、完成什麼示範、如何判斷結果。不能只有 Prompt 清單。文字分類與方案評分不設定唯一答案，以原文可追溯、規則一致、理由及人工確認紀錄驗收。

先完成課堂核心及一份完整基本作業包，再擴充其他範例；對外承諾的素材包必須在正式交付前完成。未完成的延伸包清楚標示，不以「回家請 AI 教你」替代。

## 10. 製作流程與階段完成條件

本輪僅產出本設計指引。下表是後續製作順序；每個階段完成的是具體產物，不因文件寫得完整就推定下一階段已通過。角色可由同一執行者依序承擔，不預設需要多代理。

| 階段 | 要做的工作 | 交付物 | 可以進入下一階段的條件 |
|---|---|---|---|
| 1 固定範圍與能力 | 對齊本文件、課名、受眾、時數、課堂／課後界線；同步說明差異 | 正式大綱、能力進展、環境需求與說明同步紀錄 | 沒有範圍矛盾；新內容有時間與成果位置；未知條件已列明 |
| 2 製作主案例與參考答案 | 建多工作表來源檔、工作表對照、字典、清理規則、工作簿、拆分備援、小樣本、獨立計算與參考圖表 | 實際核心素材及參考完成品 | 檔案可開啟、來源範圍可核對，計算一致；正式重算與圖表顯示各自驗證 |
| 3 製作代表性連續單元 | 優先試作第二至第四項：讀檔／清理、計算／核對、製圖／保存 | 正式教案草稿、Prompt、示範、練習、修復 | 產物能連續交接，沒有先用後建；作者自驗有實際結果 |
| 4 平台與時間試跑 | Codex 輔助講師用授課帳號跑多工作表上傳、來源核對、主要製圖路徑及備援；記錄耗時與修正 | 平台測試與時間紀錄 | 宣稱支援的路徑實際跑通，第二項操作符合時間配置；未測服務不列為通過 |
| 5 完成整門課正文 | 補齊其餘單元、獨立練習、答案及基本課後包 | 全部正式教案與必要素材 | 每項目標有教學、練習、成果及核對；六小時安排可解釋 |
| 6 內容審查與回修 | 檢查解釋、示範、難度、重複、前置能力與資料一致性 | 內容問題清單、修正版及版本證據 | 核心內容與素材缺件已修復，不能靠排版補洞 |
| 7 轉製學員講義 | 依授課形式製作講義或 HTML，先代表頁再擴大 | 可閱讀、可操作、可取得素材的學員版本 | 正文、表格、Prompt、答案及連結完整；適用排版檢查通過 |
| 8 真人跟做與轉用 | 符合起點的試學者依教材操作，Codex 協助整理卡點 | 跟做、耗時、提示、錯誤回復與獨立轉用紀錄 | 試學者能完成成果並核對；靠教師臨時補充處修回教材 |
| 9 定版與交付 | 修正試教問題、擴充已承諾課後包、同步招生說明 | 定版教材、素材包、Prompt、教師說明與驗收紀錄 | 所有適用證據通過，承諾與實際交付一致；發布按使用者授權 |

平台試跑可先對代表性素材開始，但內容變更後必須重驗受影響範圍。所有數字、圖表、Prompt 與完成品先在正式正文及素材階段對齊，再交給講義製作。

### 11.2 核心成果的驗收條件

- 上傳檔案版本、工作表清單、指定來源範圍與有效筆數有 Excel 核對紀錄；原始資料、清理後資料及修改理由可追溯，沒有未說明的漏讀、刪除、重複加總或補值。
- 彙總、占比、期間比較及情境試算符合公式、單位與定義。原則上先使用未四捨五入數值計算，再依教材指定顯示位數；允許差異由各案例明確定義。
- 圖表逐項對應核對後表格，期間、單位、比例及刻度合理，保存後可重新開啟。
- 摘要中的數字與比較有來源，不把相關差異寫成因果，不把試算寫成預測。
- 修改 Prompt 後，小樣本測試通過，再核對完整資料；指令版本與使用條件可追溯。
- 真人能在減少提示後完成一項轉用，知道錯誤時從哪一步回修；未通過就修教材或縮小承諾。

### 11.3 必須準備的修復路徑

| 現象 | 優先檢查與回修 | 備援或停止條件 |
|---|---|---|
| 檔案無法上傳 | 確認格式、大小、帳號功能與限制，以已測路徑重試 | 若帳號不支援必要讀檔，切換已測帳號或記錄待補做；暫用備援回應與 Excel，不改為大量貼上 |
| 工作表漏讀或資料範圍不完整 | 對照工作表清單、欄位、範圍及有效筆數，明示來源後重讀；必要時上傳預備的指定表 XLSX／CSV 與對照說明 | 拆分後重新核對；未確認指定資料完整性前停止相依分析，不採用其結論 |
| 數值不同 | 回查筆數、篩選、單位、公式、分母及四捨五入 | 回到已保存清理資料，重算受影響項目 |
| 圖表數字或比例錯誤 | 回到核對後彙總表，固定數據重新製圖 | 使用 Excel 備援；不能只修改圖上的文字掩蓋比例錯誤 |
| SVG 空白、中文或排版異常 | 確認完整原始碼、實際檔案與預覽，再用既定修正指令 | 課堂轉用已測路徑或 Excel，避免變成程式排錯課 |
| 匯出後不能使用 | 檢查副檔名、重新開啟及目標軟體支援 | 改用已測試的靜態圖片格式；保留原始圖表或 SVG |
| 服務限額或暫時不可用 | 確認受影響功能，記錄未完成的 LLM 操作 | 用備援回應繼續 Excel 練習，另安排補做；不填 LLM 操作通過 |
| 工作資料無法確認使用權限 | 回到資料安全檢查 | 不上傳，使用課程樣本；不要求學員自行承擔模糊條件 |

## 12. 防止課程偏離核心

每次新增或修改內容，先回答：

1. 它幫助學員完成哪一項核心成果？
2. 需要的新能力是否已教？需要的材料是否真的存在？
3. 有沒有可核對的完成品及錯誤回修方式？
4. 要花多少實作時間？加入後縮減哪一項內容？
5. 它是課堂必做、課後基本作業還是延伸自學？招生說明是否一致？

若無法回答，先不納入課堂核心。不得透過增加工具、展示更多模型、生成漂亮圖片或堆疊 Prompt，代替必要的分析方法與核對能力。

檢查特別容易偏離的情況：要求學員安裝 Python、直接從掃描圖片精確讀數、大量跨檔案整併、把問卷分類塞入基本作業、把情境試算改成預測、把 SVG 示範改為全班程式修改，以及用圖片生成代替數據圖表。這些變更都需要重新估計時間與前置能力，不能沿用原有可行性結論。
