(01)

場景與任務

阿凱完成了三平台貼文、兩週月曆、互動回應規則與一份數據表，檔案散落在不同資料夾。雯姊想知道下週要發布什麼、誰回應留言、哪些內容能承接到 LINE、數字可以說明什麼，阿凱只能逐一打開檔案口頭解釋。

PRAC3 要把零散文件組成一套可接手的社群經營方案。方案要讓下一位工作者知道：平台各自負責什麼、內容支柱處理什麼、兩週怎麼安排、互動如何處理、數據如何回顧、LINE 何時延伸，以及每個判斷的來源與限制。

(02)

關鍵概念

本單元概念與判斷
CONCEPTS

社群經營方案

社群經營方案是把平台角色、內容架構、發布流程、互動規則、成效觀察與後續行動整合在同一份交付包中。它說明工作如何被執行與修正，不保證平台結果。

• 正例：方案內有策略摘要、平台任務、內容支柱、月曆、回應規則、資料字典、下一輪假設與 LINE 情境。
• 非例：只有一份貼文清單或平台帳號名稱，沒有責任、來源與回顧方式。
• 你的判斷：接手者能否依方案完成一列內容、處理一筆互動並提出下一輪行動？不能時，方案缺少流程或證據。

上游成果與下游交接

PRAC3 要保留 Part 3 各單元的來源關係：

PRAC1 Brief → CH3-1 平台任務 → CH3-2 內容支柱
PRAC2 內容包 → CH3-3 跨平台改編 → CH3-4 月曆
CH3-5 互動風險 → CH3-6 成效紀錄 → CH3-7 LINE 延伸

每一項方案結論都要能追到上游檔案。若缺少資料，標待確認或「待補證據」，不用口頭補出不存在的證據。

策略摘要

策略摘要是用一頁說明受眾、問題、內容主張、平台分工、承接、觀察方式與限制的文件。它讓讀者先掌握方案，再查看細節。

• 正例：寫明 IG 初步理解、FB 完整說明、Threads 問題探索、LINE 同意後回訪，並列出兩週內容與檢查條件。
• 非例：寫「經營四平台、提高曝光、打造品牌」，沒有受眾任務與工作路徑。
• 你的判斷：讀者看完摘要能否說出下週先做什麼與如何知道完成？

整合驗收

整合驗收是用同一組條件檢查策略、內容、流程、互動、資料與承接是否互相支持。檢查內容包含核心訊息一致、素材來源、CTA、責任、資料定義與恢復路徑。

| 驗收面向 | 問題 |
|---|---|
| 受眾與定位 | 所有平台是否服務同一個具體情境？ |
| 內容與支柱 | 每列內容是否能回到一個支柱？ |
| 渠道與承接 | CTA 是否把人帶到合理的下一步？ |
| 互動與風險 | 回應與升級規則是否可執行？ |
| 數據與假設 | 觀察是否有定義、範圍與限制？ |
| LINE 延伸 | 同意、頻率與退出是否清楚？ |
| 可接手性 | 另一人能否找到檔案並執行？ |

示範整合步驟

步驟 1：建立策略摘要。

把受眾、問題、核心訊息、平台角色、兩週節奏、LINE 條件與成效限制寫在一頁。

步驟 2：建立平台與支柱對照。

確認 IG、FB、Threads 與 LINE 各有任務；確認三至四個內容支柱有題目與邊界。

步驟 3：放入內容月曆。

將兩週內容、狀態、素材、CTA、責任、審查與回顧放入月曆，保留待確認項目。

步驟 4：放入互動與風險規則。

將理解問題、錯誤回報、負評、敏感資訊與退出情境放入方案，指定公開／私訊／轉交／停止。

步驟 5：放入成效紀錄。

將資料字典、內容比較、可說明／尚不能說明、下一輪單變因假設放入方案。

步驟 6：放入 LINE 延伸。

只保留已同意情境、內容目的、頻率、退出與回訪理由。沒有真實名單時標為模擬設計。

步驟 7：做一致性檢查。

比較摘要、月曆、內容、CTA、風險與數據假設。若摘要寫「查看服務範圍」，月曆不能改成「保證成交」；若素材是 AI 示意，各檔案都要保持狀態一致。

步驟 8：做接手驗證。

請同學依 README 任選一列內容，找到素材、檢查來源、說出回應路徑與記錄位置。

完成驗證

整合方案要讓另一個人從摘要找到上游產物、讀懂平台任務、處理互動、理解資料限制，並知道下一步。

  • [ ] 策略摘要一頁說清楚受眾、問題、內容、渠道、承接與限制。
  • [ ] PRAC1、PRAC2、CH3-1 至 CH3-7 的成果都有索引與版本。
  • [ ] 兩週月曆可由另一人接手；三平台核心訊息一致。
  • [ ] 互動與風險規則能處理理解、需求、負評與敏感情境。
  • [ ] 數據紀錄有定義、期間、限制與下一輪假設；LINE 有同意、頻率與退出。
  • [ ] 每個待確認或「待補證據」 項目都有查核動作與負責角色。
✓
接手驗證請同學任選一列內容與一個風險情境，找出檔案、來源、回應路徑與紀錄位置。找不到時，修正 README、交付索引或版本欄，不先增加更多檔案。

通過後，Part 4 可沿用共同受眾、內容支柱、平台任務、社群問題與內容證據開始 SEO／追蹤設計。

(06)

商業情境案例

角色：阿凱，27 歲，行銷專員。他把 Part 3 的分散成果整理成雯姊可接手、可執行、可回顧的社群經營方案。檔案很多但沒有摘要與索引時，接手者仍不知道哪一份能用；數據區充滿結論但沒有定義時，也不能直接交付。

請把「可直接使用、待確認、待補證據」三種狀態寫進交付索引。沒有查核路徑的項目先移出主版本。

(08)

動手練習題

完成 社群經營方案-v1/，進行同儕接手、互動角色與資料限制驗收。

  1. 建立 README 與交付索引，列出上游檔案、版本、用途與狀態。
  2. 用一頁摘要連接受眾、問題、核心訊息、渠道、兩週節奏、承接與限制。
  3. 放入內容、月曆、互動／風險、成效與 LINE 延伸成果。
  4. 做一次接手演練，記錄找不到、不能判斷或需要教師確認的地方。
  5. 保存 AI 使用與人工修正紀錄；不使用 AI 也要註明。

變化題：只把一個渠道從核心改為延伸，保留受眾與核心訊息，重新檢查月曆、承接、成效與責任是否一致。

(09)

常見錯誤 3 條

  1. 檔案很多但無法接手。先整理摘要、README、交付索引與版本。
  2. 數據區寫滿結論。分成可說明、尚不能說明與下一輪假設。
  3. LINE 直接使用真實名單。改用模擬同意／退出狀態，保留權限與前測「待補證據」。
(10)

檢核題 2 條

  1. 社群經營方案最重要的整合證據是什麼？
    答案：受眾、內容、平台、互動、數據、承接與檔案可以互相對照並由他人接手。
  2. 資料缺少導流欄位，但月曆已發布內容，方案要如何寫？
    答案：保留可說明的觸及／互動資料，標記導流缺口，提出補追蹤的下一輪設計，不把導流或轉換寫成已完成。
