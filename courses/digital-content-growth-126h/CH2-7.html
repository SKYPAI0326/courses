(01)

破題 / Hook

阿凱已完成剪輯判斷表，知道主版本要保留問題、流程、成果與單一 CTA。他在 Windows 教室打開剪輯工具，卻把素材直接從共用資料夾拖進時間軸，沒有先複製到專案資料夾。隔天他移動了原始檔，專案中的畫面變成離線；輸出後才發現字幕被裁切，音樂蓋過旁白，短版也失去 CTA。

本單元把剪輯判斷表轉成可重做的本機專案。你會先建立資料夾與檔案命名，再匯入素材、建立時間軸、加入字幕與聲音、輸出主版，最後做無聲與接手檢查。每個操作都要留下可回復的檔案與狀態。

你要完成 短影音-v1/：

  • 可重新開啟的剪輯專案檔。
  • 一支 30 秒主版本影片，或課程端指定的主版本長度。
  • 一份 15 秒短版輸出，或清楚保存的短版時間軸設定。
  • 字幕／文字內容、素材來源、音訊來源與輸出檢核紀錄。
(02)

概念 / Concepts

本機剪輯專案

本機剪輯專案是保存時間軸、素材連結、文字、聲音、轉場與輸出設定的工作檔。它通常不等於最後要上傳的影片檔。

  • 用途：保留可修改、可重做、可輸出不同版本的工作狀態。
  • 正例：專案資料夾內有來源素材副本、專案檔、字幕文字、音訊來源與輸出檔，換一台教室電腦時能依說明恢復。
  • 非例：只交一個 MP4，沒有時間軸或來源檔；之後無法修改字幕、替換畫面或輸出短版。
  • 你的判斷：另一位同學能否在沒有口頭補充的情況下開啟專案、找到素材並輸出一次？不能時，專案交付不完整。

本單元以 Windows 本機資料夾保存所有必要檔案，不把完成條件建立在外部上傳平台或學員個人雲端權限上。

素材匯入與檔案路徑

素材匯入是把照片、影片、圖卡、字幕、音訊等檔案加入剪輯專案；檔案路徑是專案找到這些檔案的位置。路徑改變、檔名改變或檔案移除都可能造成離線素材。

  • 正例：先把已確認素材複製到 短影音-v1/media/，再從該資料夾匯入，並在 README 記錄檔案清單。
  • 非例：直接引用桌面、下載資料夾或共用暫存位置的檔案，匯入後再移動原檔。
  • 你的判斷：關閉軟體後重新開啟專案，所有畫面、聲音與字卡仍能找到嗎？不能時，修正資料夾與路徑。

檔案路徑是操作穩定性的條件。先固定資料夾，再開始匯入與編輯。

時間軸（timeline）

時間軸是依時間排列畫面、圖卡、字幕、聲音與其他元素的工作區。它呈現素材何時開始、何時結束、彼此如何銜接。

  • 用途：依 CH2-6 的剪輯判斷落實資訊順序、停留時間與聲音分工。
  • 正例：影像軌放流程畫面，文字軌放字幕，音訊軌放旁白與低音量音樂；每段時間與判斷表一致。
  • 非例：所有素材放在同一軌，層級與聲音關係不清楚；輸出後才發現字幕蓋住證據。
  • 你的判斷：從時間軸可以指出每個時間段的受眾判斷與主要素材嗎？不能時，回到剪輯判斷表整理軌道與命名。

時間軸軌道名稱、素材名稱與時間點都要可讀。不要用軟體預設名稱作為正式交付說明。

字幕與文字圖層

文字圖層是放在影片或圖卡上的可編輯文字；字幕是依時間出現、協助受眾理解畫面或聲音的文字。兩者都要符合訊息層級、可讀性與版本條件。

  • 用途：支持無聲觀看、補充關鍵詞、指出流程或提供 CTA。
  • 正例：字幕在資料畫面出現「先整理現有材料」，位置不遮住資料表，停留時間足以閱讀。
  • 非例：把完整旁白放在畫面底部，字太小、對比不足或超出安全範圍。
  • 你的判斷：在主版本與短版中，字幕都能讀完、看見與畫面對應，且沒有新增未確認的主張嗎？

若工具提供自動字幕，輸出前必須逐句校對專有名詞、數字、標點與時間點；自動結果不直接視為完成品。

音訊軌與混音判斷

音訊軌是時間軸上管理旁白、環境聲、音樂與音效的區域；混音判斷是調整不同聲音的相對音量與出現時間，讓主要語音與畫面訊息清楚。

  • 用途：讓旁白、字幕與畫面互補，並提供無聲版本的替代檢查。
  • 正例：旁白出現時降低背景音樂，音樂來源可追溯，關掉聲音後字幕與畫面仍能完成主旨。
  • 非例：背景音樂蓋住旁白，或使用來源不明的歌曲作為正式輸出。
  • 你的判斷：不戴耳機以一般教室音量播放時，旁白是否清楚？來源與使用條件是否已寫入說明？

本單元以可理解為先，不追求效果數量。音訊失效時，文字與畫面要有最小可用路徑。

輸出與版本檢查

輸出是把本機專案轉成可播放的影片檔；版本檢查是確認輸出檔仍符合主版本／短版本的受眾、訊息、字幕、聲音、CTA 與來源條件。

  • 正例：輸出主版本與短版後，重新播放並檢查開頭、畫面、字幕、音訊、結尾與檔案名稱。
  • 非例：軟體顯示輸出完成就直接交付，沒有重播、無聲檢查、檔案開啟檢查或來源核對。
  • 你的判斷：把輸出檔交給沒有參與製作的人，他能否看懂、知道下一步並分辨示意素材？不能時，回到時間軸或來源說明修正。

輸出檢查要以實際檔案為準。時間軸看起來正確，不代表輸出檔一定保留字幕、聲音、畫面比例與最後一格 CTA。

AI 輔助本機剪輯

AI 可協助產生字幕草稿、整理時間軸建議或提出短版候選；本機剪輯的素材位置、真實性、來源、字幕正確性與輸出驗收仍由操作者負責。

  • 適合使用的時機：把已確認旁白轉成字幕初稿、比較 30 秒與 15 秒的段落刪減方案。
  • 需要人工檢查的內容：人名、品牌名、專有名詞、數字、客戶案例、AI 示意標籤與 CTA 連結。
  • 紀錄要求：保存輸入內容、工具、日期、輸出版本、修改與校對結果；不要把含個資或未授權素材直接貼入外部工具。

AI 產生的字幕與剪輯建議要回到 CH2-6 的剪輯判斷表核對。若工具提出的刪減會移除必要證據，保留原本判斷並記錄不採用理由。

示範操作

步驟 1：建立專案資料夾。

在 Windows 個人課程資料夾建立 短影音-v1/ 與 media/、audio/、text/、project/、export/ 子資料夾。將已確認素材複製進對應位置，保留原始檔名與素材編號。

步驟 2：建立 README。

寫入主要受眾、影像任務、版本、來源檔、工具版本、待確認項目與恢復方式。這份說明讓另一位同學能知道怎麼開啟與檢查。

步驟 3：開啟或建立本機專案。

在已驗證的 OpenShot Windows 版本中建立專案，選擇課程端確認的畫面與輸出設定。若介面顯示不同，依課前操作卡確認，保留版本與日期。

步驟 4：匯入素材並核對。

匯入 media/、audio/ 與 text/ 中的檔案，確認每個素材能預覽、名稱與分鏡編號一致。出現離線、讀取失敗或格式不支援時先停止，不把錯誤拖進時間軸。

Checkpoint 1：任意點選一項素材，能否從軟體中對回來源資料夾、分鏡編號與素材用途？不能時，先修正命名或 README。

步驟 5：依剪輯判斷表建立影像軌。

依 0–4 秒、4–10 秒、10–17 秒、17–23 秒、23–30 秒的順序放入影像與圖卡。每段先使用主素材，再處理過渡與效果。

步驟 6：調整片段長度。

依受眾判斷與字幕閱讀時間修剪開頭、流程與成果畫面。時間軸上每段開始與結束要能對應剪輯判斷表，不以素材原始長度決定保留時間。

步驟 7：建立字幕／文字軌。

依 CH2-6 的字幕版本放入「問題、整理材料、分組主題、交付成果、CTA」等文字。確認位置、大小、對比與停留時間；字幕不要遮住流程或成果證據。

步驟 8：加入聲音。

放入旁白與已確認來源的背景音樂。先確認旁白與畫面同步，再調整音量層級；無法確認來源的音樂不進正式輸出。

步驟 9：處理轉場與效果。

只加入能支持時間關係、閱讀或段落銜接的效果。若轉場讓字幕或證據延後出現，刪除或縮短；不要以效果填滿空白。

步驟 10：建立 15 秒短版。

複製主版本或建立獨立短版專案，依 CH2-6 的短版判斷表保留問題、最必要流程證據、成果與 CTA。檔案名稱與 README 要清楚區分主版與短版。

步驟 11：輸出主版與短版。

依課前驗證的輸出檢核表設定格式與位置，輸出至 export/。檔名含主題、版本、日期或課程規範要求；未確認規格在 README 標記待補。

步驟 12：重播與驗收。

先正常播放，再關閉聲音播放，最後換一台可用的 Windows 教室電腦或由同學開啟檢查。記錄畫面、字幕、聲音、CTA、檔名、來源標示與開啟狀態。

動手 / Hands-on

請使用 CH2-6 的剪輯判斷表與 CH2-5 的視覺資產組，在 Windows 教室完成本機剪輯。若 OpenShot 前測尚未通過，依恢復路徑使用教師預製專案進行接手操作，並把實際缺口記入檢核表。

任務：完成短影音-v1

成果資料夾：短影音-v1/

步驟 1：確認環境與版本。

打開課前檢查表，記錄 Windows 教室編號、OpenShot 版本、輸出路徑與開始時間。若版本或安裝狀態與課前檢查表不一致，先標記待確認。

步驟 2：複製並整理素材。

把已確認素材放入專案資料夾，依 media/、audio/、text/、project/、export/ 分類。禁止從原始共用資料夾直接引用後再移動。

步驟 3：建立 README。

寫入受眾、影像任務、主版／短版、素材來源、AI 示意、工具版本、輸出條件與恢復路徑。

步驟 4：開啟專案並匯入檔案。

依課前驗證路徑建立或開啟專案，逐項預覽素材。遇到離線或格式錯誤時記錄檔名、訊息與修復方式，不先跳過。

Checkpoint 1：關閉並重新開啟專案，確認已匯入素材仍可找到。若發生離線，修正路徑後才進入時間軸。

步驟 5：建立主版本影像軌。

依剪輯判斷表放入開頭、流程、成果與 CTA。每個片段對照素材編號，保持時間軸可讀。

步驟 6：完成片段修剪與順序。

依受眾判斷調整長度、刪除重複或無關畫面，將必要證據留出足夠停留時間。記錄與原始時間軸不同的地方。

步驟 7：加入字幕。

逐段輸入或匯入已校對文字。檢查字型、對比、位置與畫面遮擋；自動字幕結果要逐句核對。

步驟 8：加入聲音與音量調整。

先放旁白，再加入已確認來源的音樂或環境聲。播放檢查旁白、字幕與畫面同步；若教室播放條件不同，記錄需要的修正。

步驟 9：加入必要轉場。

只保留能支持段落銜接的轉場。播放一次，確認轉場不延後主標、遮住 CTA 或造成畫面資訊遺失。

步驟 10：輸出主版本。

使用課前驗證的輸出設定，檔名與位置依 README 規則保存。輸出完成後不要立即關閉專案，先用播放器重新開啟影片。

步驟 11：建立並輸出短版。

依 CH2-6 的 15 秒判斷表建立短版，重新檢查開頭、必要證據、字幕與 CTA。不得只用加速或任意裁切代替內容取捨。

Checkpoint 2：將主版與短版交給同學，不提供口頭說明，請他回答服務處理什麼、留下什麼、下一步在哪裡。記錄答案差異並修正。

步驟 12：完成輸出檢核與備份。

填寫輸出檢核表，保存專案檔、輸出檔、字幕／文字、來源說明與修改紀錄。將狀態標記為可直接使用、待確認或退回修正。

恢復路徑

  • OpenShot 尚未安裝或無法啟動：使用課程端已驗證的預製專案檔完成匯入、字幕、時間軸讀取與輸出檢查；記錄實際工具缺口，不能把預製專案結果寫成個人完整操作。
  • 版本介面不同：依課前操作卡與功能目的尋找匯入、時間軸、字幕／文字、音訊與輸出功能；拍下或記錄差異，讓課程端更新操作卡。
  • 素材離線：關閉專案，依 README 將素材集中到 media/ 或 audio/，重新指定路徑並重新開啟；不要刪除原始專案檔。
  • 影片輸出失敗：先輸出無音訊或降低測試解析度確認問題範圍，再回到課前驗證格式；保留錯誤訊息與最後可開啟的專案檔。
  • 字幕被裁切或被素材遮住：回到文字軌調整位置、大小與停留時間，重做無聲檢查；不要只在 README 寫「字幕有問題」。
  • 音訊來源不明或無法播放：移除音訊，使用字幕與畫面完成主旨；若需要聲音，改用課程提供且已驗證來源的音訊。
  • 短版失去主旨：回到 CH2-6 的 15 秒判斷表，補回核心訊息、必要證據或 CTA，重新安排時間軸。

檢核 / Verification

自我檢查

接手驗證

請同學在同一台或另一台 Windows 教室電腦完成：

  1. 找到 README 與專案檔。
  2. 開啟專案並確認素材沒有離線。
  3. 播放主版，指出前段問題、中段證據與 CTA。
  4. 關掉聲音重播，指出字幕是否足夠。
  5. 開啟短版，說出它保留與刪除的內容。
  6. 找到一項素材來源與一項 AI／示意限制。

任何一項無法完成，回到資料夾、時間軸、字幕、聲音或 README 修正。

成功輸出

完成後應取得 短影音-v1/，可供 PRAC2 與後續社群單元使用。PRAC2 會把短影音、平面素材、來源紀錄與行銷判斷整合成一組可交付的內容資產；若影片只能在製作者電腦上播放，先修復本單元的專案與備份條件。

(06)

常見錯誤 3 條（Common Pitfalls）

  1. 錯誤現象：專案在製作者電腦能開，換到同學電腦後畫面與聲音全部離線。 原因：素材直接引用桌面、下載資料夾或共用暫存位置，沒有把檔案集中到專案資料夾。 解法：建立固定的 media/、audio/ 與 text/，複製已確認素材後重新指定路徑；保存 README 與最後可重開版本。

  2. 錯誤現象：影片輸出完成，但字幕裁切、錯字、旁白被音樂蓋住或 CTA 不見。 原因：只看軟體輸出狀態，沒有重新播放、無聲檢查與接手檢查。 解法：輸出後用播放器正常播放、關聲播放，再請同學開啟；逐項記錄字幕、聲音、CTA 與檔案狀態，修正後重新輸出。

  3. 錯誤現象：短版只是把主版加速或從中間裁切，受眾看不到問題與下一步。 原因：把版本製作當成尺寸或速度調整，沒有依 CH2-6 的短版判斷表重新取捨。 解法：重建短版時間軸，保留核心訊息、最必要證據與 CTA；對被刪除的支援訊息留下理由。

(07)

檢核題 2 條（Quiz）

Q1（概念驗證）：為什麼要同時保存本機剪輯專案與輸出影片？

答案理由：兩者用途不同；專案檔支援修改與重做，輸出檔支援實際播放與驗收，來源與使用條件仍要另外保存。

Q2（應用驗證）：影片在自己電腦能播放，換到教室另一台 Windows 電腦後素材離線。你要依什麼順序處理？

  • 預期答案要點：先保留原專案與錯誤狀態；檢查 README、素材資料夾與檔案名稱；把已確認素材集中到專案 media/／audio/／text/，重新指定路徑並重開專案；重新輸出後做正常、無聲與接手播放檢查。
