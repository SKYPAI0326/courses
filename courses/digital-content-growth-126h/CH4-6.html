破題 / Hook

團隊想知道「下載檢查表」按鈕是否被使用。設計師把按鈕做好，內容人員在頁面上看到下載檔案增加，分析人員卻無法確認數字從哪裡來。問題落在事件規格、標籤設定、觸發時機與驗證證據沒有對齊。

GTM 是把網站行為送到分析工具的一種管理方式。今天先用 LocalWP 練習一條完整鏈路：訪客點擊按鈕、GTM 觸發標籤、事件帶上參數、預覽工具顯示結果。學員要記錄每個環節，並保留未發布到正式環境的權限界線。

概念 / Concepts

Container

Container（容器）是集中管理一組標籤、觸發條件、變數與版本的工作空間。容器要對應正確網站與環境。

  • 用途：保存與管理網站追蹤設定，讓團隊可以預覽、版本化與交接。
  • 正例：測試站使用課堂提供的測試容器，正式站使用經權限核准的正式容器。
  • 非例：把測試容器程式碼貼到不明網站，或在不確認網站身份時直接修改。
  • 你的判斷：這個容器服務哪個網站、哪個環境、由誰負責發布？

Tag

Tag（標籤）是當條件符合時執行的追蹤或整合設定，例如送出 GA4 事件。標籤要與事件名稱、參數及目的對應。

  • 用途：將頁面上的行為送到指定分析工具。
  • 正例：按鈕點擊後送出 file_download，帶上 file_name 與 page_type。
  • 非例：建立名稱含糊的標籤，卻沒有事件規格或驗收方式。
  • 你的判斷：標籤何時觸發、送出什麼資料、資料會去哪裡？

Trigger

Trigger（觸發條件）是決定標籤何時執行的規則，例如所有頁面載入、特定按鈕點擊或特定網址。

  • 用途：把追蹤行為限制在正確時機與頁面。
  • 正例：只有點擊下載按鈕且按鈕文字符合條件時觸發。
  • 非例：使用所有點擊作為條件，將頁面內每個互動都送成下載事件。
  • 你的判斷：這個條件能排除哪些相似但不相關的行為？

Variable

Variable（變數）是供標籤或觸發條件讀取的值，例如點擊文字、頁面網址、元素 ID 或自訂參數。

  • 用途：讓設定能讀取頁面情境，減少每個按鈕都重複建立規則。
  • 正例：讀取 file_name 變數，將不同下載連結送出不同檔名。
  • 非例：把每個頁面的固定文字直接寫死，卻沒有說明後續維護方式。
  • 你的判斷：這個值是固定內容、使用者操作結果，還是頁面環境資訊？

Preview 與 Publish

Preview（預覽）是以測試方式檢查設定是否觸發；Publish（發布）是把版本推向實際使用環境。預覽成功只代表測試條件下觀察到結果。

  • 用途：先在測試環境查找錯誤，再依權限與流程發布。
  • 正例：LocalWP 預覽顯示按鈕點擊與事件參數正確，再由具權限者決定正式發布。
  • 非例：預覽畫面看見一次事件，就直接在正式網站發布。
  • 你的判斷：測試成功、正式發布與資料持續正確，各自需要什麼證據？

Data layer

Data layer（資料層）是網頁與標籤管理工具之間傳遞結構化資訊的方式。課堂使用既有示範欄位，不要求學員修改正式程式。

  • 用途：提供穩定的事件名稱與上下文，讓追蹤設定與視覺介面分離。
  • 正例：按鈕行為推送 event=download_guide 與 file_name。
  • 非例：只靠畫面文字猜測每個元素的用途，卻無法在不同版型保持一致。
  • 你的判斷：這個欄位由誰產生、何時產生、如何被驗證？

操作示範 / Demo

示範情境

  • 網站：課堂提供的 content-lab LocalWP 站點。
  • 行為：點擊「下載內容檢查表」按鈕。
  • 事件：file_download。
  • 參數：file_name、page_type。
  • 產物：GTM事件佈建表-v1.md。

示範前檢查

  1. 啟動正確 LocalWP 站點，確認首頁與服務頁可開啟。
  2. 確認目前使用測試容器與測試資料，不連結學員或客戶的正式資產。
  3. 開啟瀏覽器開發者工具與 GTM 預覽入口。
  4. 準備一份事件規格卡，先寫名稱與參數再進設定畫面。

十二步驟示範

  1. 在事件規格卡寫出行為、事件名稱、參數與目的。
  2. 開啟測試容器，確認目前版本與站點身份。
  3. 建立或檢查事件標籤，指定分析工具與事件名稱。
  4. 新增 file_name 與 page_type 參數。
  5. 建立按鈕點擊觸發條件。
  6. 用按鈕文字、元素 ID 或網址條件縮小觸發範圍。
  7. 儲存草稿並記錄設定名稱。
  8. 啟動 Preview，連線到 LocalWP 頁面。
  9. 點擊指定按鈕，觀察觸發條件與標籤狀態。
  10. 查看送出的事件名稱與參數，與規格卡逐項比對。
  11. 執行一次非指定按鈕點擊，確認標籤不會誤觸發。
  12. 儲存截圖、設定摘要與復原方式，暫不發布正式環境。

項目預期結果證據

AI 輔助點

可將去識別的事件規格與 GTM 設定摘要交給 AI，要求它檢查命名一致性、觸發範圍與缺少的反向測試。學員要用 Preview 實際驗證；AI 不可代替點擊測試或宣稱資料已送進正式 GA4。

動手練習 / Hands-on

任務

在測試容器中佈建一個內容行動事件，完成 GTM事件佈建表-v1.md。可選行為：

  • 下載檢查表。
  • 點擊合作流程按鈕。
  • 播放示範影片。

交付內容需包含事件規格、標籤、觸發條件、變數、Preview 證據、反向測試與正式發布界線。

起始狀態

學員取得 LocalWP 站點、測試容器權限、事件佈建範本與課堂提供的恢復步驟。若無法進入 GTM，改以事件規格與教師預覽截圖完成分析，標註「未完成實機佈建」。

交付規格

```text

GTM事件佈建表-v1.md

├── 行為與商業目的

├── 事件名稱與參數

├── Tag 設定

├── Trigger 設定

├── Variable／Data layer 來源

├── Preview 與反向測試

└── 權限、發布與復原界線

```

最短操作路徑

  1. 選一個內容行動並寫事件規格。
  2. 建立 Tag 與事件參數。
  3. 建立精準 Trigger。
  4. 使用 Preview 連到 LocalWP。
  5. 執行指定行為與反向行為。
  6. 記錄結果與截圖。
  7. 儲存佈建表，標記正式發布界線。

檢查點與修復

檢查點通過證據發現問題時的處理
站點身份Preview 連到指定 LocalWP 網址中止測試，確認站點與容器
事件規格名稱、參數、目的有對應回到事件卡，刪除無明確用途的欄位
正向觸發指定行為觸發一次檢查元素條件與事件順序
反向測試相似行為不觸發縮小 Trigger 條件或補上排除規則
權限邊界明確記錄未發布與復原方式請教師或管理者確認角色，不自行發布

變化題

將事件從「下載檢查表」改成「點擊合作流程」，保留相同容器。重寫事件名稱、參數與觸發條件，說明哪些設定能重用、哪些必須重建。

✓
Checkpoint現在應該看到一份可讀、可重做的中間成果。若沒看到，回到上一個標題的輸入與欄位檢查；通過後才能進入下一階段。平台實測若缺權限，改走本頁 CSV／文字備援。
