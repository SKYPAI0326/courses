情境與範圍 / Scenario

自由工作者要替一個小型服務品牌建立內容入口。前置工作已產生四類資料：關鍵字群組、LocalWP 頁面檢查、GA4 內容假設、GTM 追蹤驗證。品牌方想知道下一輪先改哪個頁面、要追蹤哪個行動，以及目前有哪些資料仍不能下結論。

學員要以一個內容主題為範圍完成決策包。包內文件需能被三種角色讀取：內容人員知道要寫或改什麼，網站人員知道要檢查什麼，分析人員知道要觀察什麼。Search Console 使用教師去識別資料包，學員需清楚註記資料來源與正式環境限制。

概念 / Concepts

決策包

決策包是一組圍繞同一個工作決策的文件與證據，包含情境、目前觀察、建議行動、驗收條件與待確認項目。

  • 用途：讓不同角色可以沿著同一問題協作，不必重新猜測資料背景。
  • 正例：以「優先修正服務頁的下載入口」為決策，附上查詢資料、頁面問題、事件驗證與兩週觀察計畫。
  • 非例：把多份截圖放在資料夾，卻沒有說明它們支持哪項決定。
  • 你的判斷：讀者看完包件後，能否說出下一步、負責人與驗收條件？

證據鏈

證據鏈是從問題、資料來源、觀察、判斷到行動的連續關係。每一段都要能指出來源與限制。

  • 用途：降低 SEO、內容與追蹤各自下結論造成的矛盾。
  • 正例：查詢資料顯示需求，頁面檢查指出入口問題，事件驗證確認下載可測量，最後安排內容修正。
  • 非例：只因某個關鍵字有曝光，就直接主張應增加廣告預算。
  • 你的判斷：這個判斷是由哪份資料支持？中間還缺哪個連結？

Search Console 資料包

Search Console 資料包是教師整理的去識別查詢、曝光、點擊、點閱率或排名資料，用來練習搜尋表現閱讀。它不等於學員擁有正式網站的即時權限。

  • 用途：在無法於課堂直接展示 GSC 權限時，仍能練習查詢與頁面判讀。
  • 正例：用查詢與頁面資料找出曝光有潛力、但頁面目的或標題需要修正的項目。
  • 非例：把教師資料包的數字寫成學員客戶當日的正式報表。
  • 你的判斷：資料包能支持哪個觀察？正式環境還要如何確認？

優先序

優先序是依影響、證據強度、工作量、風險與依賴條件安排處理順序。它要能說明排序理由。

  • 用途：把發現轉成團隊可執行的工作佇列。
  • 正例：先修正錯誤按鈕連結，再補內容段落，最後安排追蹤擴充。
  • 非例：只依個人喜好把視覺微調排在轉換路徑修復前。
  • 你的判斷：這一項若延後，會阻擋哪個後續工作？

證據狀態

證據狀態是對每個觀察標示已驗證、教師資料支持、待正式環境確認、假設或 BLOCK。狀態要與實際資產相符。

  • 用途：讓交接者知道哪些內容能直接採用，哪些需補證據。
  • 正例：LocalWP 頁面可檢查列為本機已驗證；正式收錄列為待正式環境確認。
  • 非例：把尚未登入或尚未測試的資產標為完成。
  • 你的判斷：如果明天由另一位講師接手，他能否依狀態決定下一步？

整合規劃 / Plan

任務範圍

每組選一個主題與一個主要頁面，範圍需能在 3 小時內完成。可選：

  • 自由工作者作品集服務。
  • 社群內容規劃工具包。
  • 小型品牌國際詢問入口。

選題後固定以下邊界：一個主要頁面、兩至三個相關查詢、一個主要內容行動、一個待觀察成果。

整合矩陣

問題資料來源目前觀察行動驗收
受眾在找什麼？關鍵字群組／GSC 資料包查詢與頁面主題的關係調整頁面主題與內容欄位標題與內容能回答查詢
頁面能否完成任務？LocalWP 檢查表title、H1、連結或按鈕問題修正一個優先問題頁面可讀、路徑可用
內容行動能否觀察？GA4 假設／GTM 驗證事件或參數的狀態補測或修正事件規格Preview 與事件紀錄相符
下一輪先做什麼？全部產物證據強度與阻礙排序三項工作有負責人、期限與條件

工作分工

  • 內容角色：查詢、頁面目的、標題與內容欄位。
  • 網站角色：LocalWP 頁面與連結檢查。
  • 分析角色：GA4 假設、GTM 驗證與轉換判讀。
  • 交接角色：證據狀態、檔案命名、版本與待辦清單。

產物實作 / Build

Demo：教師示範整合方式

教師以「社群內容規劃工具包」示範：

  1. 從 GSC 資料包挑出兩個相關查詢。
  2. 回到 CH4-2 的關鍵字群組，確認查詢共用的頁面問題。
  3. 讀 CH4-3 頁面檢查，選出影響行動路徑的問題。
  4. 讀 CH4-5 內容假設，選出一個可在兩週後檢查的結果。
  5. 讀 CH4-7 驗證表，確認事件是否能代表內容行動。
  6. 將以上資料放入整合矩陣，為每一項標記證據狀態。
  7. 排序前三項工作，為每項寫負責人、期限與驗收。
  8. 將檔案整理到決策包資料夾，寫入版本摘要。

示範決策

```text

主題：社群內容規劃工具包

主要頁面：/content-calendar/

主要行動：下載檢查表

觀察：相關查詢有曝光，頁面按鈕指向測試網址；GTM Preview 的下載事件尚未完成手機測試

決策：先修正按鈕路徑並完成桌面／手機驗證，再安排內容欄位調整

狀態：GSC 為教師資料支持；LocalWP 已檢查；正式收錄與 GA4 正式資料待確認

```

AI 輔助點

可將四份去識別產物的摘要交給 AI，請它整理衝突、缺口與可執行任務。學員要逐項回到原始文件核對，尤其是 GSC 資料來源、LocalWP 證據與 GA4／GTM 測試狀態。AI 產生的排序需附上人工作出的理由。

品質檢查 / QA

五項整合檢查

  1. 主題一致：關鍵字、頁面、事件與行動描述同一個受眾問題。
  2. 證據可追：每個重要判斷都能連回檔案、頁面、報表或測試記錄。
  3. 狀態正確：本機、教師資料、正式環境與待補證據清楚分開。
  4. 行動可做：前三項工作有負責人、期限、依賴與驗收。
  5. 交接可讀：未參與過程的讀者能在五分鐘內掌握背景與下一步。

交接回饋 / Handoff

每組用 5 分鐘完成口頭交接，格式如下：

  1. 服務誰、要解決什麼問題。
  2. 目前最重要的觀察與資料來源。
  3. 優先處理的三項工作。
  4. 已通過的驗證與尚待確認的證據。
  5. 若只能再做一件事，會選哪一件，理由是什麼。
