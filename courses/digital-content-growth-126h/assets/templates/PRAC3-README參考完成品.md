# 社群經營方案 README 參考完成品 v1

## 方案摘要

- 受眾：需要把零散服務資料整理成可持續內容的小型團隊。
- 平台分工：IG 讓人看見流程與視覺證據；FB 補充條件與討論；Threads 提出判斷問題；LINE 只承接已明確同意者。
- 兩週行動：先發布流程圖卡，再用短影音與文字串補充理解，最後以 LINE 提供已同意者的檢查表。
- 不能承諾：曝光或營收保證；合成資料不代表真實成果。

## 資料夾索引

| 資料夾 | 用途 | 主要驗收 |
|---|---|---|
| `01-platform/` | 平台角色與選擇 | 每個平台有不同工作 |
| `02-pillars/` | 定位與內容支柱 | 題目能連回受眾問題 |
| `03-adaptation/` | 三平台改編 | 核心訊息沒有漂移 |
| `04-calendar/` | 兩週月曆與流程 | 狀態與責任可接手 |
| `05-risk/` | 互動與風險 | 有停止與轉交條件 |
| `06-measurement/` | 資料字典與假設 | 只做資料支持的判斷 |
| `07-line/` | LINE 延伸 | 同意、頻率與退出清楚 |
| `08-verification/` | 來源與接手紀錄 | 同學可在 3 分鐘找到本週工作 |

## 恢復路徑

來源不明、內容主張漂移、個資出現或退出未生效時，先暫停發布／延伸訊息，回到對應來源與風險表修正，再更新版本與接手紀錄。
