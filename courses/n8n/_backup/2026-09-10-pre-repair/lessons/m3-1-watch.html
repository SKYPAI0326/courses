FILE PROCESSING BASELINE · 3.1

資料夾檔案處理：從可重現的觸發流程開始

先用目前版本可重現的 Manual Trigger + Read/Write Files from Disk 建立檔案處理基線，再把同一條流程延伸成自動監控。

為什麼這很重要 · WHY THIS MATTERS
Make.com 通常從雲端事件開始；本節先處理另一個問題：如何讓 n8n 讀到 Docker 掛載的資料夾，並只把指定格式交給後續節點。先用 Manual Trigger 驗證資料路徑與檔案欄位，因為這條基線能在課堂立即重跑，也能作為日後接上 Local File Trigger 的比較基準。
先釐清路徑 · HOST VS CONTAINER
你會在 Finder／檔案總管建立並放入測試檔；Read/Write Files from Disk 則在 Docker 容器內讀檔。starter kit 已把主機的 shared/ 掛到容器的 /files/shared，所以主機只負責放檔，n8n 節點一律填 /files/shared/待處理PDF/*.pdf。macOS 的 ~/... 與 Windows 的 %USERPROFILE%\... 只用來找到主機資料夾。
STEP BY STEP · 操作步驟
1
建立資料夾並加入可重跑的觸發器
先在主機建立輸入資料夾，再回到 n8n 新建 Workflow。點擊「Add first step」搜尋並加入「Manual Trigger」。本節先用手動觸發，是為了把「檔案是否掛載成功」與「之後是否自動觸發」分開檢查；等讀檔基線通過後，再把同一條路徑改接自動觸發器。
# Finder／檔案總管：建立並放檔案的位置 macOS: ~/n8n-starter-kit/shared/待處理PDF/ Windows: %USERPROFILE%\n8n-starter-kit\shared\待處理PDF\ # 下一個 Read/Write Files from Disk 節點會使用的容器路徑 /files/shared/待處理PDF/*.pdf
預期結果：主機上看得到空的 待處理PDF 資料夾；此時 n8n 還不會讀檔，因為我們先確認觸發器可以手動重跑。若節點日後填入 /Users/... 或 C:\Users\...，容器會找不到該路徑。
2
放入測試檔並手動執行
先下載課程範例檔案包並解壓，從 n8n-sample-pack/batch-inbox/batch-good-01.pdf 取一份 PDF，改名為 report.pdf 後放入主機的 shared/待處理PDF/。回到 n8n 點 Manual Trigger 的「Execute step」。這一步只確認流程能被啟動；檔案是否真的被讀到，會在下一步由 Read/Write Files from Disk 驗證。
快速檢查：右側 Executions 出現一筆成功記錄。若沒有記錄，先確認 Workflow 已儲存，再重新按一次 Execute step。
3
讀取檔案並確認輸出結構
在 Manual Trigger 後新增「Read/Write Files from Disk」，Operation 選「Read File(s) From Disk」，File(s) Selector 填入 /files/shared/待處理PDF/*.pdf，Output Binary Field 填 data。執行後點開這個節點的 Output，確認每個 PDF 成為一個 Item，檔名位於 $binary.data.fileName，內容位於 $binary.data.data。
檔名：{{ $binary.data.fileName }} 內容：{{ $binary.data.data }}（Base64，先不用閱讀）
這一步的意義：只要看得到檔名與 binary 欄位，就代表主機資料夾、Docker 掛載與 n8n 讀檔三件事已接起來；後面才值得加入過濾與 AI。
4
加入 If 節點，保留 PDF
在 Read/Write Files from Disk 後面接一個 If 節點。Value 1 切換到 Expression，填入 {{ $binary.data.fileName.toLowerCase().endsWith('.pdf') }}，Operation 選「Is True」。雖然 selector 已先限制 PDF，這個 If 仍保留作為日後改成多格式輸入時的安全邊界。
// If 節點條件設定 Value 1: {{ $binary.data.fileName.toLowerCase().endsWith('.pdf') }} Operation: Is True
提示：使用 endsWith() 是判斷副檔名最簡潔有效的方式，注意大小寫（PDF 與 pdf 不同）。
5
用兩筆資料確認分流
先把 selector 暫時改成 /files/shared/待處理PDF/*，再放入 document.txt 與 report.pdf，按 Manual Trigger。確認 PDF 走 True、文字檔走 False。測試完成後，把 selector 改回 *.pdf，避免後續 AI 節點收到不支援的格式。
預期結果：Output 顯示 PDF 有一筆 True Item；TXT 只出現在 False 分支。若兩筆都沒有出現，回到 Step 3 檢查 binary 檔名欄位。
完成驗證 · VERIFY
你已完成一條可重跑的檔案處理基線：Manual Trigger 能啟動、Read/Write Files from Disk 能在 /files/shared/待處理PDF/*.pdf 讀到 PDF、If 能依 $binary.data.fileName 分流。這條基線會被 3.2 批次改名沿用；自動監控則列為延伸，不在未驗證前當作本課必要條件。
常見問題 · TROUBLESHOOT
Read/Write Files from Disk 沒有讀到檔案？
先在主機確認檔案位於 starter kit 的 shared/待處理PDF/，再在節點使用容器路徑 /files/shared/待處理PDF/*.pdf。不要把主機的 ~/... 或 %USERPROFILE%\\... 貼進節點。若 Output 仍是 0 items，確認 Docker Desktop 已允許 starter kit 父資料夾，並重新執行 Manual Trigger。
If 節點的 True／False 不符合預期？
確認 Value 1 是 {{ $binary.data.fileName.toLowerCase().endsWith('.pdf') }}，Operation 是 Is True。若顯示 fileName 不存在，回到 Step 3 查看實際 binary 欄位名稱，不要改成猜測的 $json.data.name。
💼 實戰案例
情境｜某設計工作室設『下載資料夾』監控 → 偵測到新 PSD 檔 → 自動備份到客戶專案雲端空間。
做法｜先用 Manual Trigger + Read/Write Files from Disk 驗證資料夾與 binary 欄位；若目前版本的節點清單出現 Local File Trigger，再以同一個容器路徑做小範圍替換測試。
踩雷｜自動監控節點的名稱、事件欄位與 Docker 檔案權限會隨版本與部署方式變動。本課先把可重現基線跑通，不把尚未完成 Mac／Windows 實機測試的即時監控當作必過條件。
