FILE MANAGEMENT · 3.2

PDF 批次改名：AI 辨識內容自動命名

結合 Gemini API，讓 AI 讀取 PDF 內容、提取廠商名稱與金額，依規則產生新檔名並輸出副本；原檔先保留，方便人工抽查與回復。

實際效果 · BEFORE / AFTER
scan_20260315_001.pdf → 2026_合約_廠商A_50萬.pdf
document_final_v3.pdf → 2026_採購單_供應商B_3.2萬.pdf
STEP BY STEP · 操作步驟
📁 先準備可跟做的檔案：請先下載課程範例檔案包，從 n8n-sample-pack/batch-inbox/batch-good-01.pdf 取一份 PDF，放入主機的 n8n-starter-kit/shared/待處理PDF/；n8n 節點使用容器路徑 /files/shared/待處理PDF/*.pdf。macOS 與 Windows 只差主機資料夾的顯示方式，節點設定相同。
本節流程概覽
Manual Trigger
→
Read File(s) From Disk
→
HTTP Request (Gemini)
→
Code (解析)
→
Write File to Disk（副本）
1
Read/Write Files from Disk：讀取 PDF 為二進位資料
承接 3.1 已確認的 Manual Trigger，新增「Read/Write Files from Disk」節點，Operation 選「Read File(s) From Disk」，並把節點重新命名為 Read PDF。在「File(s) Selector」欄位填入目前主線的容器路徑 /files/shared/待處理PDF/*.pdf；副檔名已由 selector 限制，If 分流可留到多格式改造時再加入。執行後，每個 PDF 會成為一個 binary Item，檔名可從 $binary.data.fileName 取得，內容位於 $binary.data.data。
提示：此節點將 PDF 轉換為 Base64，這是上傳至 Gemini API 所需的格式。在 Output 面板確認 binary 欄位已出現。
2
HTTP Request 節點：呼叫 Gemini API 辨識 PDF
新增「HTTP Request」節點，Method 設為 POST，URL 填入 Gemini API 端點（含你的 API Key）。Body 類型選「JSON」，貼入以下結構，讓 Gemini 讀取 PDF 並回傳結構化 JSON。
// URL（替換 YOUR_API_KEY） https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key=YOUR_API_KEY // Body（JSON 格式） { "contents": [{ "parts": [ { "text": "請解析此 PDF，提取以下資訊並以 JSON 格式回傳，不要包含 markdown：{\"vendor\": \"廠商名稱\", \"amount\": \"金額\", \"date\": \"日期YYYYMMDD\", \"type\": \"文件類型\"}" }, { "inlineData": { "mimeType": "application/pdf", "data": "{{ $binary.data.data }}" } } ] }] }
服務界線：在 Google AI Studio 建立 API key，使用量與可用額度依帳號、模型與官方方案而異（請查 官方 Rate limits 頁面）。Gemini 可直接讀取 PDF 圖文內容；批次處理時在 Loop 內加入「Wait」節點（間隔 5 秒）降低 429 風險，但不保證不會遇到限制。
3
Code 節點：解析 Gemini 回傳的 JSON
新增「Code」節點（Language 選 JavaScript），從 HTTP Request 的回傳中提取 AI 辨識結果。Gemini 的回傳結構為 candidates[0].content.parts[0].text，將其解析為 JSON 物件。
// Code 節點內容 const rawText = $input.item.json.candidates?.[0]?.content?.parts?.[0]?.text || ''; const clean = rawText.replace(/^```(?:json)?\s*/i, '').replace(/\s*```$/, '').trim(); let info; try { info = JSON.parse(clean); } catch (error) { throw new Error('Gemini 回傳不是有效 JSON，請查看 HTTP Request Output 後重試'); } const sourceName = $('Read PDF').item.binary?.data?.fileName || 'unknown.pdf'; const originalPath = '/files/shared/待處理PDF/' + sourceName; const dir = '/files/shared/完成'; // 組合新檔名 const newName = `${info.date}_${info.type}_${info.vendor}_${info.amount}.pdf`; const newPath = `${dir}/${newName}`; return [{ json: { originalPath, newPath, newName, ...info } }];
快速檢查：先在 Code 節點 Output 確認 newPath 是 /files/shared/完成/...。若解析失敗，程式會保留紅色錯誤並要求你回看 HTTP Request 的原始回應，不要直接猜欄位名稱；若 date、type、vendor 或 amount 缺漏，先修 Prompt 或人工補值再輸出。
4
Read/Write Files from Disk：以新檔名輸出副本
n8n 2.37.7 的 Code node 會禁止直接載入 fs，因此不在 Code 節點執行重新命名。改用兩個檔案節點：先重新讀取 originalPath，再把同一份 binary 寫到 newPath。這是可回復的安全做法，原 PDF 仍留在原資料夾。
// ① 重新讀取原檔（避免 HTTP Request 丟失 binary） Operation: Read File(s) From Disk File(s) Selector: ={{ $json.originalPath }} Output Binary Field: data // ② 寫出新檔名副本 Operation: Write File to Disk File Name: ={{ $json.newPath }} Input Binary Field: data
提示：先在主機的 starter kit shared/完成/ 建立輸出資料夾，並讓上一個 Code 節點把 newPath 組成 /files/shared/完成/檔名.pdf。這裡是「輸出新檔名副本」，不是刪除或覆寫原檔。
5
用 Loop 節點批次處理多個 PDF
若需要一次處理資料夾內所有已存在的 PDF，在流程開始新增「Read/Write Files from Disk」，Operation 選「Read File(s) From Disk」，File(s) Selector 填 /files/shared/待處理PDF/*.pdf，再連接「Loop Over Items」。讀檔節點會直接產生多個 Items，不需要自行掃描主機資料夾。
// 批次讀檔設定 Operation: Read File(s) From Disk File(s) Selector: /files/shared/待處理PDF/*.pdf Output Binary Field: data → Loop Over Items → 步驟 2–4
提示：目前主線使用「Read File(s) From Disk + Loop」處理資料夾內既有 PDF；若日後要改成自動監控，請先在目標 n8n 版本確認 Local File Trigger 的輸出欄位，再替換觸發器，後面的讀檔、AI 與安全副本規則不變。
完成驗證 · VERIFY
放入一個 PDF 後，執行流程。主機的 shared/完成/ 應出現如 20260315_合約_台積電_500萬.pdf 的新檔名副本，而原始檔仍在 shared/待處理PDF/。若 Gemini 辨識的資訊欄位回傳「未知」，代表 PDF 內容不清晰，可調整 Prompt 加上「若無法辨識請回傳 unknown」。
常見問題 · TROUBLESHOOT
Gemini API 回傳 400 錯誤，或說 inlineData 格式不正確？
確認 HTTP Request 節點的 Body 類型是「JSON」而非「Form Data」。另外檢查 $binary.data.data 是否有值（在 Read/Write Files from Disk 的 Output 面板確認有 binary 欄位）。API Key 是否正確放在 URL 參數中。
Code 節點 JSON.parse 失敗，報錯 SyntaxError？
Gemini 有時會在 JSON 外包 markdown 標記（```json ... ```）。本頁 Step 3 已先清除圍欄並用 try/catch 解析；若仍失敗，先查看 HTTP Request 的原始回應，再修 Prompt 或欄位驗證，不要直接把錯誤字串寫入檔名。
💼 實戰案例
情境｜某律師事務所每月 2,000 份 PDF 卷宗，檔名從『20250408_合約.pdf』改成『2025-04-08_客戶代號_合約.pdf』。
做法｜讀檔名正則拆 → 查客戶資料表取代號 → 組合新名 → Write File to Disk 輸出副本。每月省 8 小時手工時間。
踩雷｜改名前先 Dry run（只輸出預計的新名稱到 CSV，不實際改檔）人工檢查 10% 樣本——檔名改錯無法 undo。
