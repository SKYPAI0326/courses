SCHEDULED REPORT · 3.3

定時彙整日報：排程掃描 × AI 摘要

設定好後，n8n 每天依排程掃描文件資料夾，將文字送到 Gemini API 彙整，再輸出 Markdown 日報。排程不需要人工按鈕，但 AI 摘要仍會使用雲端服務。

這節的核心優勢

Make 必須由外部事件觸發（有人寄信、有人填表），但 n8n 可以從自身的排程主動啟動。Schedule Trigger 讓 n8n 成為真正自主運行的本機代理人——不需要任何雲端訊號，不需要任何人按下按鈕，到時間就跑。

起點與完成物 · START / DELIVERABLE
先在主機建立 shared/每日文件/，放入至少一個 .txt 或 .md 檔，再建立本頁的 6 個節點。你要留下日期命名的 Markdown 日報與一次成功執行記錄。Gemini API 屬於延伸服務；沒有 API key 時，Step 3 提供固定 AI 回覆，後面的格式化與寫檔仍可完整跟做。
MAKE.COM
被動觸發
必須等待雲端事件（Gmail 收信、表單提交）才能啟動，無法自行按時執行本機任務。
N8N（DOCKER 自架）
主動排程
Schedule Trigger 自行定時啟動；檔案讀寫在本機容器，AI 摘要會依設定送往 Gemini API。

1
Schedule Trigger：設定每日定時啟動
新建一個 Workflow，點擊「Add first step」，搜尋並選擇「Schedule Trigger」節點。這個觸發器完全不依賴外部訊號，n8n 自己按照排程執行。
設定欄位建議值說明
Trigger IntervalDays每天觸發一次
Days Between Triggers1間隔 1 天
Trigger at Hour17下午 5 點（可依需求調整）
Trigger at Minute0整點觸發
測試方式：開發時不需要等到真正的觸發時間——點擊節點上的「Execute step」可以立即手動觸發，跳過等待直接測試後續節點是否正確。
Checkpoint 1：Schedule Trigger 的設定畫面顯示每天 17:00，點「Execute step」能讓流程立即產生一筆執行記錄。
2
Read/Write Files from Disk + Code：讀取並合併文字文件
先下載課程範例檔案包，將 n8n-sample-pack/daily-input/ 裡至少一個 .txt 與一個 .md 複製到主機的 n8n-starter-kit/shared/每日文件/。接著新增「Read/Write Files from Disk」，Operation 選「Read File(s) From Disk」，File(s) Selector 填 /files/shared/每日文件/*，Output Binary Field 填 data。這個節點會把每份檔案變成一個 Item；再接 Code 節點，僅用 binary 內容合併 .txt 與 .md，不直接讀取作業系統檔案。
// Code 節點：合併讀檔節點輸入（不使用 fs） const items = $input.all(); const today = new Date().toISOString().slice(0, 10); const files = items .filter(item => /\.(txt|md)$/i.test(item.binary?.data?.fileName || '')) .map(item => { const file = item.binary.data; const name = file.fileName; const content = Buffer.from(file.data, 'base64').toString('utf8'); return '\\n\\n## ' + name + '\\n' + content; }); return [{ json: { combined: files.join(''), today, fileCount: files.length } }];
路徑契約：先在主機的 n8n-starter-kit/shared/每日文件/ 建立資料夾並放入 .txt 或 .md 文件；Read/Write Files from Disk 節點使用容器路徑 /files/shared/每日文件/*。macOS 與 Windows 的節點設定相同，Code node 不需要知道主機作業系統。
Checkpoint 2：第一個 Code Output 的 fileCount 等於資料夾內的 .txt／.md 檔案數，combined 內看得到檔名與文字內容。
3
HTTP Request 節點：呼叫 Gemini API 生成摘要
有可用 API key 時，新增「HTTP Request」節點，呼叫 Gemini API，將合併後的文件內容傳入，請 AI 生成每日摘要。API key 放在 Header Auth credential（名稱 x-goog-api-key），URL 不放秘密。沒有 API key 時，新增 Edit Fields 節點，建立 JSON 類型的 candidates 欄位，貼入固定 AI 回覆，再進入 Step 4。
// URL（有 API key 時，不含秘密） https://generativelanguage.googleapis.com/v1beta/models/gemini-3.6-flash:generateContent // Header Auth credential x-goog-api-key: YOUR_API_KEY // Body（JSON 格式） { "contents": [{ "parts": [{ "text": "你是一位工作摘要助理。以下是今天的工作文件內容，請生成一份每日摘要日報，格式為純 Markdown（不要包含 markdown 圍欄標記）。日報包含：今日重點（3-5 項條列）、待處理事項、備注。\n\n文件內容：\n{{ $json.combined }}" }] }] }
服務界線：Gemini API 的可用額度依模型、帳號與官方方案而異，且可能調整。實際請查 官方 Rate limits 頁面 或 Google AI Studio 內顯示；每天跑一次屬低頻，但仍要以執行記錄確認。
Checkpoint 3：API 路徑或固定回覆路徑的 Output 都能看到 candidates[0].content.parts[0].text，文字內容可讀且沒有空值。
4
Code 節點：格式化為完整 Markdown 日報
新增第二個「Code」節點，從 Gemini 回傳中提取文字，加上日期標題，組合成完整的 Markdown 日報，並生成含日期的檔名。
// Code 節點：格式化 AI 回傳為日報 const raw = $input.item.json.candidates[0].content.parts[0].text; const clean = raw.replace(/```[\w]*\n?|\n?```/g, '').trim(); const today = $('Code').item.json.today; const fileCount = $('Code').item.json.fileCount; const report = `# 每日工作日報｜${today}\n\n` + `> 本日共掃描 ${fileCount} 份文件，由 AI 自動生成摘要。\n\n` + clean; const fileName = `${today.replace(/-/g, '')}_日報.md`; return [{ json: { report, fileName } }];
引用前一個 Code 節點：$('Code').item.json.today 是用節點名稱引用資料。若你的第一個 Code 節點有自訂名稱，將引號內的名稱替換成實際名稱。
Checkpoint 4：第二個 Code Output 有 report、fileName，並在內容開頭顯示今天日期；fileCount 與實際檔案數一致。
5
Read/Write Files from Disk：儲存日報到本機
先新增「Convert to File」節點，把 Markdown 字串轉為二進位（Source Field 選 report，Encoding 選 UTF-8）。再新增「Read/Write Files from Disk」，Operation 選「Write File to Disk」，設定輸出路徑和動態檔名。
// Write File to Disk 設定 File Name: /files/shared/日報/{{ $json.fileName }} Data: data（Convert to File 的輸出）
📁
先建立資料夾：在主機的 starter kit shared/ 裡建立「日報」資料夾（macOS 用 Finder，Windows 用檔案總管）。n8n 不會自動建立不存在的目錄；節點使用 /files/shared/日報/。日後每天的日報都會以日期命名（如 20260415_日報.md）存入此資料夾。
Checkpoint 5：Convert to File Output 出現 data binary，Write File to Disk 執行後，主機的 shared/日報/ 能看到同名 Markdown 檔。
6
啟用 Workflow：讓 n8n 自主運行
完成所有節點後，點擊 n8n 右上角的「Publish」，將 Workflow 狀態切換為 Published（已發布；舊版介面可能顯示 Active）。此後，每天指定時間 n8n 會自動執行，不需要任何人工操作。確認 Docker Desktop 與 n8n 容器都在執行中（Docker Desktop 工具列有鯨魚圖示且狀態為 Running），排程才能正常觸發。
💡
排程要求 n8n 持續運行：Schedule Trigger 的觸發依賴 n8n 容器持續運行。若需要電腦關閉後仍能執行，未來可考慮把 n8n 部署到自己的 VPS（如 Hetzner、DigitalOcean，約 $5/月）或使用系統 Cron service，但對工作坊情境而言，保持 Docker Desktop 開啟已足夠。
完成驗證 · VERIFY
手動點擊「Execute workflow」測試整條流程後：（1）日報資料夾中出現今日日期命名的 .md 文件，（2）打開文件確認包含「今日重點」、「待處理事項」等結構，（3）文件掃描數量與實際資料夾內的 .txt/.md 數量吻合。三點達成即代表成功。將 Workflow 按 Publish 變成 Published 後，無需任何人工操作，每天指定時間自動產出。
常見問題 · TROUBLESHOOT
Read/Write Files from Disk 報錯：ENOENT no such file or directory
資料夾路徑不存在。先在主機的 starter kit shared/每日文件/ 建立資料夾，再確認讀檔節點使用容器路徑 /files/shared/每日文件/*。不要把 Finder／檔案總管的主機路徑貼進節點。
Code 節點回傳 fileCount 為 0，AI 摘要內容空白
讀檔節點沒有找到 .txt 或 .md 文件。確認主機資料夾中至少有一個文字文件，且 File(s) Selector 使用 /files/shared/每日文件/*。Word 文件（.docx）和 PDF 不在本頁的預設掃描範圍。
Schedule Trigger 設定好後沒有在指定時間執行
兩個可能原因：（1）Workflow 尚未按「Publish」變成 Published——確認右上角狀態；（2）Docker Desktop 或 n8n 容器在指定時間已關閉——Schedule Trigger 需要 n8n 持續在背景運行才能觸發。
第二個 Code 節點引用 $('Code').item.json.today 報錯
n8n 用節點名稱引用資料。若你的第一個 Code 節點名稱不是預設的「Code」（例如已改為「讀取文件」），將引用語法改為 $('讀取文件').item.json.today。
💼 實戰案例
情境｜某行銷顧問每天 17:30 排程：從 Google Analytics + Facebook Insights + YouTube 三源抓數據 → Gemini 彙整 → 寄給老闆當日報。
做法｜Schedule Trigger 30 17 * * 1-5 + 3 個平行 HTTP Request 抓源 + Merge + Gemini + Gmail，老闆每天吃飯時 mail 就送到。
踩雷｜日報若失敗沒通知——半週後才發現漏了。規則：Error Trigger 節點 + Slack/Line 通知『今天日報沒送成功』，這是最便宜的監控保險。
