#07 · QUICK TUNNEL RECEIVER · 4 NODES · 進階

把本機 n8n 變成公開 URL：Cloudflare Quick Tunnel 雲地橋接

本機 n8n 對外只能 localhost:5678 — 別的服務（Make scenario / Google Form / 學員自家網站）打不到。Cloudflare Quick Tunnel 可提供一個暫時的 *.trycloudflare.com URL（通常不需 Cloudflare 帳號或自有網域；方案、流量與條款依官方當前說明），把本機服務暫時暴露成公開端點。這個 workflow 是 tunnel 接到後做什麼事的範例 — 收到外部 ping 推 Telegram + 立刻回 pong。

學習成果
能用 starter-kit 的 tunnel-quick.command / .bat 開 Cloudflare Quick Tunnel 取得公開 URL
能設計外部觸發 webhook + 解析請求參數 + 即時回應的 4 節點 pattern
理解 Quick Tunnel 與 Named Tunnel 的差異與適用場景
(01) WORKFLOW 全貌

節點與資料流

Webhook: external-ping → Code: 解析外部請求

↗ Telegram 通知
↘ Respond: pong（responseNode）

4 個可執行節點，類似 #06 的 fan-out pattern，但只有 2 條輸出。Webhook path 設為 external-ping、方法為 GET；搭 Quick Tunnel 後，完整公開 URL 會是 https://xxxx.trycloudflare.com/webhook/external-ping。外部服務以 GET 呼叫這個網址，Code 會整理請求資訊，同時通知 Telegram，再由指定的 Respond 節點回傳 JSON。

🧭
先完成一次可觀察的測試：
  1. 確認 n8n 已在 http://localhost:5678 運作，並從試跑包啟動 tunnel-quick.command（Mac）或 tunnel-quick.bat（Windows）；保留顯示公開 URL 的終端機視窗。
  2. 在 #07 工作流右上按目前版本的 Publish（舊版介面可能顯示 Active），讓 /webhook/ production URL 可接收請求。
  3. 在瀏覽器開啟 你的公開網址/webhook/external-ping?message=hello。這個範例使用 GET，因此網址後面的 message 只是方便觀察 query 資料。

成功訊號：瀏覽器收到 status: "ok" 的 JSON，Telegram 收到「📡 外部 ping 收到」，並在 Executions 分頁看到成功執行及節點結果（編輯器畫布不一定保留綠框）。測試結束後回到工作流取消發布（舊版介面為關閉 Active），並在 tunnel 終端機按 Ctrl+C。

(02) NODE BREAKDOWN

節點逐一拆解

NODE 1 / 4
Webhook: external-ping

Path external-ping、HTTP Method 設為 GET、Response Mode 設為 Using 'Respond to Webhook' Node（匯入設定中的 responseNode）。

請求先交給 Code 節點，再分流到 Telegram 與 Respond。回應節點已被明確指定，無論 Telegram 先完成或後完成，呼叫端都會收到同一份 JSON。

NODE 2 / 4
Code: 解析外部請求

Code 讀取 Webhook 傳入的 headers 與 query，組合一則 Telegram 通知，並把回應資料放在 response 物件，交給下一個 Respond 節點使用：

// 收外部請求 → 組 Telegram 通知文 + Webhook 回應 const headers = $input.first().json.headers || {}; const query = $input.first().json.query || {}; const ip = headers['cf-connecting-ip'] || headers['x-forwarded-for'] || 'unknown'; const ua = headers['user-agent'] || 'unknown'; const ts = new Date().toLocaleString('zh-TW'); const tgMsg = `📡 外部 ping 收到！\n\n⏰ ${ts}\n🌐 IP: ${ip}\n🤖 User-Agent: ${ua.substring(0, 80)}\n📦 Query: ${JSON.stringify(query)}\n\n（你的本機 n8n 正在被外部觸發！）`; return [{ json: { tgMsg, response: { status: 'ok', message: 'pong from your local n8n via cloudflare tunnel', receivedAt: ts, from: ip } } }];
NODE 3 / 4
Telegram 通知

同 #05 / #06，訊息欄位使用 ={{ $json.tgMsg }}。每次有人從外部打你的公開 URL，你的手機就會收到通知，這個分支可作為簡單的 webhook 監控器。

NODE 4 / 4
Respond: pong
respondToWebhook v1.1responseNode

Respond to Webhook 節點負責送出 webhook 回應。Webhook 的 responseNode 模式會等這個節點回應，呼叫端收到 HTTP 200 與下列固定欄位：

{ "status": "ok", "message": "pong from your local n8n via cloudflare tunnel", "received_at": "執行當下時間", "from": "請求來源 IP 或 unknown" }
(03) DESIGN RATIONALE

Quick Tunnel vs Named Tunnel

💭
Quick Tunnel（本課程預設）：
雙擊 tunnel-quick.command / .bat，等待終端機顯示 https://random-words-123.trycloudflare.com 公開 URL。
優點：可快速建立臨時端點，通常不需要 Cloudflare 帳號或自家網域；是否可用仍依官方方案、流量與條款。
限制：關閉 cloudflared 終端機後 URL 立即失效；每次重啟會拿到不同網址，不能指定 hostname，不適合長期服務。
適用：開發測試、課堂 demo、臨時對外。
💭
Named Tunnel（進階）：
需要 Cloudflare 帳號、自家網域與 cloudflared service install 設定，可使用固定 hostname（如 n8n.yourdomain.com）。長期運作仍需自行維護服務、DNS 與存取控制。
適用：生產環境、長期對外服務。
注意：會在系統建 launchd / Windows service，要清乾淨需要 cloudflared service uninstall（連發 #11 學員實測）。
⚠️
Quick Tunnel HTTP/2 vs QUIC 的雷：
Cloudflare Quick Tunnel 預設用 QUIC 協議，部分企業網路（含臺灣某些 ISP / 企業 firewall）會擋 QUIC port 7844。本課程 starter-kit 的 tunnel-quick.command 預設加 --protocol http2 強制走 HTTP/2，避開 QUIC 被擋。如果還連不上代表你的網路完全擋 cloudflared，跳 ngrok 備用方案。
(04) 改造方向

5 種改造方向

  1. Make 觸發 n8n：Make scenario 結束時用 HTTP module 以 GET 呼叫 https://xxx.trycloudflare.com/webhook/external-ping?message=done，把雲端訊號接到本機 n8n。
  2. Google Form → Make → n8n：表單資料進入 Google Sheets 後由 Make 偵測，再以 GET query 呼叫 n8n；若要傳送大量欄位，需另設 POST Webhook 與對應解析規則。
  3. IFTTT / Zapier 接 n8n：把 n8n 公開網址設為 webhook target，服務觸發時以 GET 傳入事件參數，再由 n8n 執行後續工作。
  4. Telegram bot 指令：Telegram webhook 通常使用 POST；要沿用本課程範例，先在 Webhook 節點改用 POST 並調整 Code 的 body 解析，再接續通知分支。
  5. 個人 dashboard：表單以 GET query 呼叫 trycloudflare URL，n8n 回傳固定 JSON，同時把請求內容推送到 Telegram 供你確認。
