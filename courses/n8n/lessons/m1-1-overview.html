(01) · Module 1 · Section 1.1

參與門檻與前置檢查

在課堂開始前先判定這台電腦能不能完成本機實作。你會拿到一個 PASS、CONDITIONAL 或 BLOCK 結果，知道要直接上課、改用備援機，還是先請 IT 解鎖。

學習成果 · OUTCOMES
能依核心硬性門檻判定自己是 PASS、CONDITIONAL 或 BLOCK
能在 Windows 驗證 WSL2、BIOS/UEFI 硬體虛擬化與重開機權限
能回傳一份可供講師提前分流的環境證據，而不是到現場才開始猜
(01)

為什麼是 Docker，不是 n8n Desktop App

情境切入 · HOOK
阿凱這個月做了一檔 PDF 客戶資料抽取的活動，月初才到 12 號，Make 已經跑掉 800 ops，眼看月底還有兩週。他不想立刻升級到更高方案，也不希望客戶 PDF 一開始就上傳到第三方 SaaS。雯姊跟他說：「你可以在自己電腦上自架 n8n，把檔案讀寫與批次處理放在本機；但只要呼叫雲端 AI 或寄信，資料仍會依設定送往外部服務。」阿凱的第一個問題：「不是要會寫 code 才能裝嗎？」

不用。本單元的 10–15 分鐘，目標是讓你看完之後知道自己接下來要走哪條路——不是現在就要動手裝，是先把地圖看清楚。

!
n8n Desktop App 已退役：n8n 官方 GitHub 倉庫 n8n-io/n8n-desktop-app 於 2025-08-15 封存（read-only），不再更新。本課程不使用 Desktop App，改採官方推薦的 Docker Desktop + Docker Compose 方案。啟動仍透過課程提供的一鍵腳本，不需要手打 docker 指令。
(02)

關鍵概念

Docker
基礎設施
把「整包跑得起來的軟體環境」裝箱送到你電腦上的工具，你不用懂裡面的細節。
✓不需要懂容器技術
✓Docker Desktop 開著，n8n 就能跑
Docker Desktop
桌面應用
Docker 在 Mac / Win 上的桌面版本，有圖形介面（左上角看到鯨魚圖示），不用打指令。
✓有 GUI，跟開一般 App 一樣
✓可從官方網站取得安裝程式，Mac 與 Win 均有對應版本
Docker Compose
設定檔
把「要跑哪些容器、用什麼設定」寫成一份 yaml 檔，一個指令把整組服務拉起來。
✓試跑包就是一份寫好的 compose 檔
✓學員雙擊腳本即可啟動，不用手打
n8n Community Edition
自架版本
n8n 的自架版本，授權、方案與使用範圍依官方 Sustainable Use License 說明；跑在你自己電腦上，不採 Cloud 同一套 execution 計算方式，可以讀寫已掛載的本機檔案。
✓執行量改由本機效能、設定與外部 API 額度共同決定
✓可先在本機讀寫客戶 PDF；送往雲端服務前要先確認資料政策

(04)

參與門檻 Gate：先判斷能不能進實作

課前決策 · GO / NO-GO
這一段不是要你背規格，而是把課堂最容易爆炸的問題提前攔下來。Docker 起不來時，原因可能是 OS 太舊、BIOS 沒開虛擬化、WSL2 被公司政策鎖住、沒有重開機權限，或磁碟空間根本不夠。這些問題不能用「到現場再試試看」處理。
結果代表什麼你要怎麼做
PASS核心規格、虛擬化、權限與 Docker smoke test 都通過。可把自己的電腦當作課堂實作機。
CONDITIONAL可以參加概念與觀摩，但自己的電腦還不能穩定跑核心流程。課前安排借用機、遠端備援或只做觀摩；不要在課堂現場才修 BIOS。
BLOCKOS/CPU 不支援、虛擬化被鎖、無法安裝或重開機，或資源低於最低門檻。先由 IT 解鎖、升級或更換電腦；未解除前不承諾能完成實作。

核心門檻（全部要通過）

檢查項最低可參加條件課堂建議驗證證據
作業系統／CPUMac：Docker 官方目前支援的 macOS；Windows：64-bit Win 10 22H2 build 19045 或 Win 11 23H2 build 22631 以上。Mac 至少 macOS 14；Windows x64。Windows ARM 先列備援，不作本課主路徑。「關於這台 Mac」／winver／系統資訊畫面。
記憶體／磁碟總 RAM 8GB；核心流程至少 20GB 可用空間。16GB RAM、30GB 可用空間；要跑 Gemma 4 再額外預留模型空間。系統資訊與儲存空間畫面。
虛擬化／WSL2Windows BIOS/UEFI 硬體虛擬化已啟用、CPU 支援 SLAT、WSL 2.1.5 以上。Docker Desktop 使用 WSL2 backend；Windows Home 只走 Linux containers。工作管理員「虛擬化：已啟用」＋wsl --version、wsl --status。
權限／政策可安裝或由 IT 預先安裝 Docker Desktop，可重開機並接受安全性／防火牆提示。公司電腦先取得 IT 同意；不要把「沒有管理員權限」留到上課才發現。能啟動 Docker Desktop，且沒有被公司 MDM／防毒攔截。
網路／埠可連 HTTPS 443 下載 image 與試跑包；主機 5678 未被占用。課前先下載 ZIP，課堂只做啟動與驗證，降低現場網路風險。Docker Desktop 已登入／可啟動，瀏覽器可開 localhost:5678。

Windows BIOS／UEFI 虛擬化檢查

1
先在 Windows 看結果，不要先猜

開「工作管理員 → 效能 → CPU」，找到「虛擬化」。顯示「已啟用」才算通過；顯示「已停用」或找不到時，先停在這裡。

預期結果：畫面明確寫「虛擬化：已啟用」。若是公司電腦且欄位被鎖定，直接標記 CONDITIONAL／BLOCK，不要在課堂重開機試錯。
2
從 Windows 進 UEFI 設定

「設定 → 系統 → 復原 → 進階啟動 → 立即重新啟動 → 疑難排解 → 進階選項 → UEFI 韌體設定」。不同品牌名稱可能不同，常見選項是 Intel Virtualization Technology / VT-x 或 AMD SVM Mode。

安全停損：如果沒有「UEFI 韌體設定」、選項被密碼鎖住，或你不確定哪個設定是虛擬化，先退出並請 IT／設備管理員處理。
3
啟用後回 Windows 驗證 WSL2

重新開機後，以 PowerShell 執行：

wsl --version wsl --status wsl -l -v

WSL 版本至少 2.1.5；Docker Desktop 安裝後，清單中應能看到 docker-desktop 使用 VERSION 2。

Mac 權限與架構檢查

晶片
Apple 選單 → 關於這台 Mac：看到 Apple M 系列走 Apple Silicon；看到 Intel Core 走 Intel。下載包必須對應，不能只按官網第一個按鈕。
macOS 版本
在終端機執行 sw_vers -productVersion，再對照 Docker 官方目前支援的 macOS 版本。課程建議至少 macOS 14。
安裝權限
第一次啟動可能要求輸入 Mac 密碼、允許系統元件或通過 Gatekeeper。公司管理機若不能輸入密碼，請 IT 先安裝；不要把它算成學員現場步驟。
!
課程不要求 GPU。核心 n8n + PostgreSQL 走 Docker CPU 路徑即可；Gemma 4 + Ollama、Cloudflare Tunnel、Gemini API 與 Telegram 都是延伸能力，不能反過來當成 Docker 入場門檻。

版本依據：Docker Desktop for Mac 官方需求、Docker Desktop for Windows 官方需求。官方條件會隨版本變動，開課前請再核對一次。

本單元完成條件 · VERIFY

把以下 4 項證據交給講師，四項都能回答才算 PASS；有一項不能回答就依 Gate 分到 CONDITIONAL 或 BLOCK：

我的結果是 PASS / CONDITIONAL / BLOCK，原因是 _____
我的 OS／CPU 路徑是 _____，總 RAM _____ GB、可用磁碟 _____ GB
Windows 的虛擬化／WSL2 證據是 _____；Mac 的權限／晶片證據是 _____
Docker Desktop 狀態、docker version 與 docker compose version 結果是 _____

動手練習

用你現在這台電腦，完成上方的「課前回傳清單」6 項，並把截圖或文字結果存成一份課前證據：

OS／CPU
寫下 Mac Intel、Mac Apple Silicon 或 Windows x64，以及 OS 版本；Windows 要附 winver 結果。
資源
記下總 RAM 與可用磁碟的實際數字；低於 8GB RAM 或 20GB 可用空間就標記 BLOCK。
虛擬化／權限
Windows 附工作管理員虛擬化與 wsl --version；Mac 寫下是否能輸入系統密碼並允許 Docker 元件。
Smoke test
T-1 天啟動 Docker Desktop，記下 docker version、docker compose version 與 docker run --rm hello-world 的結果。

把這份證據交給講師；若不能提供完整結果，預設先排 CONDITIONAL，等補齊後才升級為 PASS。

(08)

常見錯誤

看到「裝 Docker」就想跳過，改用 npx n8n
不建議：npx n8n 雖然 30 秒能跑，但資料不持久（重啟易消失）、沒有 PostgreSQL，Module 3 跑大量 PDF 時會很痛苦。Docker Desktop 啟動後跟「開另一個 App」一樣，平時不用不會打擾你。
Mac 用戶跳過「判斷 Intel / Apple Silicon」，直接下官網第一個 .dmg
官網有兩個下載按鈕：裝錯晶片版本啟動後會報錯。現在就到「關於這台 Mac」看「晶片」欄位，自己確認一次。
Win 用戶沒檢查虛擬化，裝完 Docker Desktop 才被擋下
BIOS 設定需重開機：臨時找不到資料會卡很久。Win 用戶現在就開工作管理員 → 效能 → CPU，看「虛擬化」是否「已啟用」。
(09)

自我檢核

Q1：本課程不使用 n8n Desktop App 的原因是？
顯示答案
正確答案：C。n8n 官方 GitHub 倉庫 n8n-io/n8n-desktop-app 於 2025-08-15 封存（read-only），官方不再更新。本課程改採 Docker Desktop + Compose 方案，功能更完整且持續維護。
Q2：阿凱用 MacBook Pro M2，總 RAM 16GB、磁碟剩 25GB，從來沒裝過 Docker。他目前應判定什麼狀態？
顯示答案
正確答案：B。規格與架構已達標，但「從來沒裝過 Docker」代表還沒有 smoke test 證據；先完成 Docker Desktop 啟動、docker version、docker compose version 與 hello-world，再升級為 PASS。
