Module 01
SECTION 1.3

JSON 基礎與 Prompting 技巧

學會理解 JSON 這種通用資料格式，掌握在 n8n 中讀寫數據的語法，並用 Prompting 讓 AI 穩定輸出結構化資料，讓後續節點能自動處理。

⏱預估時間：30 分鐘（精簡版）/ 45 分鐘（完整版）
📋7 個步驟
💡不需寫程式背景
起點 你手上有：固定測試 payload、AI 輸出文字 與 解析後範例；你要留下：一條 Webhook → Set → Code（JSON.parse）的測試 Workflow。整章都先用這些固定資料，完成後再替換成你的真實資料。
1
什麼是 JSON？資料的「名牌標籤」

JSON 是電腦之間傳遞資料的通用格式。想像每件商品都有一張名牌，上面寫著品名、價格、顏色——JSON 就是這種結構化的「名牌」，讓不同的服務（n8n、Make、Google AI Studio）能讀懂彼此傳過來的資料，不會雞同鴨講。

生活類比
一張合約如果只是純文字，電腦不知道哪段是「廠商名稱」、哪段是「金額」。但如果用 JSON 格式，就像幫每個資訊貼上標籤："廠商": "台積電"、"金額": 50000，電腦立刻知道要讀哪個欄位。
💡 節點的結構化欄位通常以 JSON 傳遞；PDF、圖片等檔案會以 binary 欄位一起傳遞。M3 的檔案工作會用到 binary，因此現在先把兩種資料分開看。
2
認識 JSON 物件 {} 與陣列 []

JSON 有兩種基本結構。物件（大括號 {}）用來描述「一筆資料」，裡面是一組組的「欄位名稱 : 值」。陣列（中括號 []）則是「多筆資料的清單」，裡面可以放很多個物件。以下是一個真實的訂單範例：

// 一筆完整的訂單資料（物件 + 陣列） { "客戶姓名": "王小明", "訂單編號": "A20260315-001", "總金額": 3150, "商品列表": [ { "名稱": "無線耳機", "數量": 1, "單價": 2800 }, { "名稱": "充電線", "數量": 1, "單價": 350 } ] }
🗂
n8n 節點輸出視窗中，展開 JSON 結構，看到物件欄位與陣列清單
Checkpoint 1 · 讀懂一筆資料

現在應該能指出「王小明」在 $json.客戶姓名，「無線耳機」在 $json.商品列表[0].名稱。若找不到，回到 Step 2 展開物件與陣列，再進入 Expression。

3
用 Expression 讀取 JSON 欄位

在 n8n 的任何欄位裡，點擊右側齒輪圖示切換到 Expression 模式，就可以用 {{ $json.欄位名稱 }} 的語法讀取資料。若要讀取巢狀欄位（物件裡面的物件），用「.」點下去一層層讀取。

// 以上方的訂單資料為例 {{ $json.客戶姓名 }} → "王小明" {{ $json.訂單編號 }} → "A20260315-001" {{ $json.總金額 }} → 3150
✏️
n8n 節點欄位切換到 Expression 模式，輸入 {{ $json.客戶姓名 }} 後顯示預覽值
🔄 對應 Make 的概念：這就像 Make 中在欄位裡點擊變數、選擇要帶入的資料欄位，只是 n8n 用文字語法表達，更靈活。
4
讀取陣列中的特定項目

陣列的索引從 0 開始，[0] 是第一筆，[1] 是第二筆。讀取陣列裡某個物件的欄位，語法是：先用中括號指定第幾筆，再用點號讀取欄位名稱。

// 讀取商品列表中的第一筆和第二筆 {{ $json.商品列表[0].名稱 }} → "無線耳機" {{ $json.商品列表[0].單價 }} → 2800 {{ $json.商品列表[1].名稱 }} → "充電線" {{ $json.商品列表[1].單價 }} → 350
⚠️ 陣列索引以 0 起算；[0] 是第一筆，[1] 是第二筆。
Checkpoint 2 · Expression 有可見結果

在預覽或 Output 面板看見「王小明」「A20260315-001」「3150」三個值後再繼續。若顯示 undefined，先確認欄位名稱與目前節點的 Item。

5
用 Set 節點組合新的 JSON 物件

當你需要把從不同地方讀到的資料重新組合，可以用 n8n 的 Set 節點。點擊「Add field」，設定欄位名稱，值的欄位切換成 Expression 後填入對應語法，就能組出一個全新的 JSON 物件，傳給後續節點使用。

// 在 Set 節點新增以下三個欄位： 欄位名: 客戶簡報 值（Expression）: {{ $json.客戶姓名 }} 欄位名: 消費總額 值（Expression）: {{ $json.總金額 }} 欄位名: 訂單編號 值（Expression）: {{ $json.訂單編號 }}
🔧
n8n Set 節點介面，Add Field 後設定欄位名稱與 Expression 值
Checkpoint 3 · Set 交出三個欄位

執行 Set 後，Output 應同時看到「客戶簡報：王小明」「消費總額：3150」「訂單編號：A20260315-001」。若欄位是空白，從 Set 的 Expression 預覽回查 Step 3。

6
Prompting 技巧：讓 AI 回傳結構化 JSON

直接問 AI 問題，通常得到的是一段自由格式的文字，n8n 沒辦法自動讀取。解法是在 Prompt 中明確要求 AI 以 JSON 格式回覆，並附上你想要的格式範例——AI 就會照著結構輸出，後續節點才能精準讀取每個欄位。

// Prompt 範本：讓 AI 讀合約並輸出結構化資料 請讀取以下合約文字，並以 JSON 格式回覆， 格式如下，不要包含其他說明文字： { "廠商名稱": "字串", "合約金額": 數字（不含符號）, "簽約日期": "YYYY-MM-DD", "合約類型": "採購單 | 服務合約 | 其他" } 合約文字如下： {{ $json.contract_text }}
🤖
n8n 中連接 Google AI Studio 節點，Prompt 欄位填入上方範本
✅ 關鍵句型：「不要包含其他說明文字」這句很重要——沒有這句，AI 可能會在 JSON 前後加上「以下是回覆：」等文字，導致 Code 的 JSON.parse() 失敗。
Checkpoint 4 · AI 回傳可解析的文字

先把下方 Prompt 送出一次，確認回覆只包含 JSON 物件。若前後出現說明文字，先修 Prompt，再把文字放入 Set 的 ai_text，交給 Code 解析。

7
用 Code 節點解析 AI 回傳的字串

AI 輸出的 JSON 在 n8n 裡通常是一段文字，必須先轉成物件才能讀取欄位。n8n 目前的通用做法是使用 Code 節點呼叫 JSON.parse()。本次先用課程提供的 固定 AI 輸出文字，放進 Set 的 ai_text 欄位，再由 Code 解析，學會後即可換成 AI 節點的文字欄位。

// 在 Set／Edit Fields 新增一個文字欄位 欄位名: ai_text 值: 複製 固定 AI 輸出文字 的整行內容 // 接著新增 Code 節點，Mode 選 Run Once for Each Item const parsed = JSON.parse($json.ai_text); return { json: { ...$json, ...parsed } }; // 解析後，下一個節點就可以直接讀取： {{ $json.廠商名稱 }} → "台積電" {{ $json.合約金額 }} → 50000 {{ $json.簽約日期 }} → "2026-03-15"
🔄
Code 節點以 JSON.parse($json.ai_text) 將文字轉成物件，執行後下一節點可讀取個別欄位值
⚠️ AI 輸出不穩定時：如果 Code 的 JSON.parse 報錯，通常是 AI 在 JSON 外加了說明文字。先回到 Step 6 要求只回覆 JSON；仍有包裹文字時，才在 Code 中先截取大括號範圍，並保留原始 ai_text 供回查。
完成驗證 CHECKPOINT
你應該能做到這些才算完成

在 n8n 中建立一個測試 Workflow，依序完成三段：Webhook 接收 固定 payload，Set 讀取並組合三個欄位，再用 Code 讀取 ai_text 並以 JSON.parse() 解析 固定 AI 輸出文字。通關時應能在 Output 看到「台積電／50000／2026-03-15」，並能說明每個欄位的來源與型別。

// Webhook 測試資料（可從上方下載完整檔案） { "客戶姓名": "王小明", "訂單編號": "A20260315-001", "總金額": 3150, "contract_text": "廠商名稱：台積電；合約金額：50000；簽約日期：2026-03-15；合約類型：服務合約" }

建立與驗收順序：若畫布是空白，先新增 Webhook（POST，Path 可填 json-training），再用連線把 Set 接在 Webhook 後、把 Code 接在 Set 後。點「Listen for Test Event」→ 用固定 payload 送出一次 → 確認 Set Output 有三個欄位 → 在 Set 新增 ai_text 並貼上固定 AI 輸出文字 → 執行 Code → 確認解析後有四個欄位。

Mac 送出測試資料：將 固定 payload 下載到同一資料夾，在終端機先切到該資料夾，再執行 curl -X POST -H "Content-Type: application/json" --data-binary @m1-3-test-payload.json http://localhost:5678/webhook-test/json-training。

Windows PowerShell 送出測試資料：將檔案下載到同一資料夾，在檔案總管的資料夾空白處按右鍵選「在終端機中開啟」，執行 Invoke-RestMethod -Method Post -ContentType "application/json" -InFile .\m1-3-test-payload.json -Uri http://localhost:5678/webhook-test/json-training。

沒看到預期結果時：Webhook 沒資料就回到 Test URL 重新送出；Set 空白就回到 Expression 預覽；Code 報錯就檢查 ai_text 是否為完整單行 JSON，再回到 Step 6 修 Prompt。保留原始輸入，不要用空白值繼續往下接。

常見問題
Expression 顯示 undefined 或空白
通常是欄位名稱拼錯（包含大小寫），或路徑層級有誤。在 n8n Expression 編輯器的左側面板會列出前一節點的實際資料結構，可以直接點擊欄位名稱自動帶入，避免手打錯誤。
Code 節點報錯：Invalid JSON
AI 在 JSON 前後加了說明文字（如「以下是結果：」）。先確認 Set 的 ai_text 仍保留完整原文，再在 Prompt 中加上「只回覆 JSON，不要任何說明文字」。若問題持續，才在 Code 中先截取大括號範圍後再呼叫 JSON.parse()，並把原始文字留下供回查。
AI 回傳的數字欄位變成字串
在 Prompt 中明確標示哪些欄位是數字（number），例如 "合約金額": 數字（不含貨幣符號）。若 AI 仍回傳字串，在 Set 節點中用 {{ parseInt($json.合約金額) }} 強制轉換成數字型別。
💼 實戰案例
情境｜某電商倉管從 Shopee 訂單 webhook 讀出 items 陣列，送到 Google Sheet 每列一品項。
做法｜先在 n8n 畫布右下 Execute Node 跑一次，把真實 JSON 複製出來用 jsonviewer.stack.hu 展開確認結構，再寫 {{ $json.order.items[0].sku }}。
踩雷｜陣列長度 0 時訪問 items[0] 會噴 undefined 造成後面整條壞掉——一律用 optional chaining items?.[0]?.sku ?? '' 兜底。
