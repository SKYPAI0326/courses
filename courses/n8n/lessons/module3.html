MODULE 03

重型文件工廠：批次處理大師

對付成千上萬的 PDF！學會「迴圈（Looping）」思考術。當別人在手動改名時，你已一鍵處理完一整年的存檔。

學習目標 OUTCOMES
用 Manual Trigger 與 Read/Write Files from Disk 建立可重跑的資料夾檔案基線；即時監控列為延伸
實現 PDF 文件的批次自動改名，AI 讀取內容並按規則命名
設定 Schedule Trigger 定時排程，n8n 自主掃描資料夾並以 AI 生成每日摘要日報
Automated Monitoring · 3.1

資料夾檔案處理：先建立可重現的本機基線

這是自架 n8n 相較於 Make 的重要能力差異：Make 通常從雲端訊號開始，而 n8n 可以在容器內讀寫掛載的本機資料夾。本模組先用 Manual Trigger + Read/Write Files from Disk 建立可重跑基線，再討論如何依目前版本接上即時監控，避免把尚未驗證的觸發器當成必做步驟。

透過實作，你將能夠設計出以「本機資料夾」為起點的文件處理流程：先用 Manual Trigger 或 Schedule 讀取測試檔，讓 AI 協助辨識、產生新檔名並輸出副本；若要做到檔案一放入就觸發，再依目標版本另行驗證即時監控節點。

📂
資料夾路徑契約：n8n 只讀取 Docker 掛載的指定共享資料夾，設定來源是 ./shared:/files/shared。主機端可以是 macOS 或 Windows；n8n 節點一律填 /files/shared/...。自動監控節點的名稱與輸出欄位仍須依目前版本介面確認。
01
資料夾檔案處理基線 →
用 Manual Trigger、Read/Write Files from Disk 與 If 篩選 PDF，先建立可重跑的本機檔案流程。
02
監聽策略選擇 →
理解即時監聽與定時掃描的差異，根據任務緊急程度選擇適合的策略。
03
副檔名過濾 →
設定只監控特定副檔名（如 .pdf、.xlsx），避免非目標文件觸發流程。
File Management · 3.2

PDF 批次改名：依規則自動命名

大量 PDF 文件的命名管理常令人頭疼。本節將教你如何利用 n8n 結合 Google AI Studio，從 PDF 內容中提取關鍵資訊，並按照規則實現文件的批次自動改名。

實際案例 EXAMPLE
scan_20260315_001.pdf → 2026_合約_廠商A_50萬.pdf
document_final_v3.pdf → 2026_採購單_供應商B_3.2萬.pdf

無論是根據廠商名稱、合約金額或日期，你都能為文件設定一套智能的命名邏輯，確保所有文件都以統一且具意義的方式命名，易於搜尋與歸檔。

🏷️
AI 辨識 + Prompting：透過 Google AI Studio 讀取 PDF 內容，搭配結構化 Prompt 讓 AI 回傳 JSON 格式的命名資訊，再由 n8n 組合成最終檔名。
01
AI 辨識自動命名實戰 →
Read/Write Files from Disk → Gemini API → Code 解析 → Write File to Disk 輸出副本，五步驟完成 PDF 智慧改名。
02
命名規則設計 →
設計統一命名規則（日期_類型_對象_金額），確保一致性與可搜尋性。
03
Loop 批次重命名 →
利用 n8n 的 Loop 與檔案操作節點，將 AI 提取的資訊組合成新檔名並批次執行。
Scheduled Report · 3.3

定時彙整日報：排程掃描 × AI 摘要

這一段把檔案處理拆成可觀察的步驟：先由 Manual Trigger 或 Schedule 啟動，再讀取掛載資料夾、交給 AI 處理、輸出結果。即時監控是另一種觸發方式，必須先在目標版本與網路環境驗證；不要把它當成本課程唯一的入口。

本節將用 Schedule Trigger 設定每日排程，配合 Code 節點讀取整個資料夾的文件，由 Gemini AI 生成結構化摘要，最終將 Markdown 日報自動存入指定目錄。設定好後，不需要任何人按下按鈕。

⏱
Schedule Trigger 與即時監控：Schedule Trigger 是「到時間就觸發」；即時監控則是「有新檔案才觸發」。本課先用可重跑的 Manual Trigger 驗證檔案契約，之後再依目前版本與作業系統確認自動監控策略。
01
定時 AI 日報實戰 →
Schedule Trigger → Read/Write Files from Disk → Gemini → Write File，建立每日自動日報。
02
Cron 語法指南 →
每日、每週、每月不同排程模式的設定方法，以及 Cron 語法的使用時機。
03
多格式日報擴展 →
擴展掃描範圍至 PDF、Excel 等格式，搭配 AI 辨識生成跨格式彙整日報。

卡關 Checklist ·先從這裡查起

❌ SplitInBatches 迴圈跑不完
→ 最後一個節點的 output 要接回 SplitInBatches 的 input 形成 loop——忘了接就跑第一批就停。
❌ 檔案流程沒有讀到輸入
→ 先在主機的 starter kit shared/ 建立資料夾並確認 Docker Desktop 有權限；Read/Write Files from Disk 與 Code 節點要填容器絕對路徑 /files/shared/資料夾名稱，不要填 Mac 的 /Users/... 或 Windows 的 C:\Users\...。即時監控是延伸，需另依版本驗證。
❌ Gemini API 429 錯誤
→ 超過該模型與帳號當前 RPM/RPD（依 官方 Rate limits 頁面 為準）。加 Wait 5 秒 + Loop Over Items 每批 10 控速，仍需以實際執行記錄確認。
❌ Schedule Trigger 到點不觸發
→ Docker Desktop 或 n8n 容器停止時 Schedule 不會跑；要保持 Docker Desktop 與 n8n 服務開啟。是否設定開機自動啟動，依你的電腦與資安政策決定。
❌ Cron 表達式看不懂
→ 貼到 crontab.guru 會白話翻譯（0 8 * * 1 → At 08:00 on Monday）。
