單元 5-4

內容 SEO：讓 Google 和人都看懂

好的內容 SEO 是雙重任務：讓搜尋引擎能正確理解頁面主題，同時讓真實用戶讀起來流暢、滿足意圖。Title、Meta、H 標籤、語意優化、FAQ Schema——每一個元素都在發送信號。

學習目標 OUTCOMES
能寫出清楚、獨特且符合搜尋意圖的 Title Tag 與 Meta Description，並檢查不同裝置的截斷風險
能正確設計 H1/H2/H3 標題層級，並在內容中自然融入語意相關詞彙
能判斷 FAQ Schema 是否適用，並在頁面確有相同問答時建立有效 JSON-LD
START · 取得共通材料

先分清楚搜尋需求，再確認頁面能說什麼

本節會沿用 M5-2／M5-3 的判讀，但不要求你已經有自己的品牌資料。請先開啟 SEO 關鍵字研究練習表.xlsx，從曝光、CTR、平均排名與你填寫的搜尋意圖理解查詢；再開啟 M5-4 共通練習 brief，確認原始頁面、可使用事實與未知資料。

工作表中的「月費」「試課」或「退費」只是使用者查詢，不代表模擬品牌真的提供這些方案。頁面文案只能引用 brief 已提供的事實；缺少的價格、優惠、資格與效果要標示待確認，不能交給 AI 補齊。

本節完成物：建立一份 onpage-seo-rewrite.md，依序完成頁面 A 與頁面 B。每頁都要留下目標查詢、搜尋意圖、引用的 FACT 編號、Title、Meta、H1、兩個 H2、FAQ 判斷、排除或待補主張，以及兩項採用理由。
ON-PAGE ELEMENTS · 頁面元素

五個標籤，送給 Google 的信號

<title>
清楚、精簡、獨特地描述頁面。沒有固定字數上限，也不必硬把關鍵字塞在最前面；搜尋結果會依裝置寬度截斷，Google 也可能依頁面內容改寫 title link。
meta desc
用一到兩句話提供準確、獨特且與頁面相符的摘要。Google 沒有規定固定長度，會依裝置截斷，也可能改用頁面內容生成 snippet；不要把 150–160 字元當成通過標準。
H1
用一個清楚、最突出的主標題建立頁面主題。H1 可與 Title 相近但不必完全相同；避免多個同等突出的主標讓讀者與搜尋系統無法辨識主題。
H2 / H3
次標題要反映內容層級與讀者問題。自然使用受眾真的會搜尋的詞與相關概念，不追求關鍵字密度，也不使用「LSI Keywords」作為排名公式。
URL
簡短、可讀、能描述內容，單字以連字號分隔。例：/seo-guide/ 而非 /post?id=1234。不要只為塞關鍵字改動穩定 URL；既有 URL 調整還需規劃重新導向。

SEMANTIC SEO · 語意優化

不只關鍵字密度，是語意完整性

內容重點不是達到某個關鍵字密度，而是讓讀者與搜尋系統清楚理解你在回答什麼問題。寫作前先問：「這個受眾要完成任務，還需要哪些子題、證據與限制？」不要為了看起來完整而重複同義詞。

🔍
語意優化實作方法：搜尋目標關鍵字，觀察目前結果頁出現的頁型與讀者問題，再回到自己的頁面判斷哪些子題確實需要補充。搜尋結果或「People Also Ask」只能提供研究線索；沒有頁面事實或讀者需求支持的題目，不必為了看起來完整而全部加入。
📝
使用讀者的語言：可自然帶入同義詞與相關概念，例如談 SEO 時視內容需要使用「搜尋引擎最佳化」「自然搜尋流量」「搜尋結果」，但不需要列滿所有變體。每個詞都要服務讀者理解。
FAQ SCHEMA · 結構化資料

先問是否適用：FAQ Schema 實作

FAQPage JSON-LD 可描述頁面上的真實問答內容，但不保證出現 rich result。Google 目前通常只讓知名、權威的政府與健康網站顯示 FAQ rich results；一般商業網站不應把它當成擴大搜尋版面的策略。只有頁面真的呈現相同問答、且符合政策時才使用。

FAQ Schema 範本（JSON-LD）
<script type="application/ld+json">
{
"@context": "https://schema.org",
"@type": "FAQPage",
"mainEntity": [
{
"@type": "Question",
"name": "沒有瑜伽經驗也能使用入門系列嗎？",
"acceptedAnswer": {
"@type": "Answer",
"text": "可以。入門系列不要求既有瑜伽經驗，內容依序包含呼吸、暖身、基礎體式與收操。"
}
}
]
}
</script>

這段 JSON-LD 只能在頁面 A 確實顯示同一組問題與回答時使用。若可見頁面沒有問答，正確做法是先補上讀者看得到的內容，或暫時不建立 FAQPage，而不是只把答案藏在結構化資料裡。

AI 協作 Prompt｜一次處理一個頁面
我要改寫一個既有頁面的 on-page SEO 元素。 【目標查詢與搜尋意圖】 [貼上工作表中的查詢、數據與人工判讀] 【原始頁面】 [貼上 brief 的原始 Title、Meta、H1、H2 與正文摘要] 【可使用事實】 [貼上本頁可引用的 FACT 編號與內容] 【未知資料】 [貼上 brief 列出的未知項] 請提出一版 Title、Meta、H1、兩個 H2 與一組可公開回答的 FAQ。每一項都要標示引用的 FACT 編號與採用理由。不得新增價格、優惠、資格、測試結果或健康效果；資料不足時寫「待品牌確認」，並另給一版不依賴該資料的可發布文字。 輸出欄位：元素 / 改寫版本 / 事實來源 / 採用理由 / 待補或排除主張
老師示範｜頁面 A 完整改寫

目標查詢與意圖：「線上瑜伽課程」，商業型候選；仍須以實際 SERP 複核頁型。工作表提供 5,470 次曝光、3.3% CTR、平均排名 7.6，這些數據只描述課堂模擬網站的查詢表現。

Title：線上瑜伽課程入門｜在家開始的練習內容｜日常伸展所
Meta：給沒有瑜伽經驗的初學者。了解在家觀看的入門系列如何帶你完成呼吸、暖身、基礎體式與收操。
H1：給初學者的線上瑜伽課程入門
H2：入門系列會練習哪些內容／開始前要準備什麼
FAQ：沒有瑜伽經驗也能使用入門系列嗎？可以。入門系列不要求既有瑜伽經驗，內容依序包含呼吸、暖身、基礎體式與收操。

事實來源：Title 與 H1 使用 FACT-01、FACT-02；Meta、H2 與 FAQ 使用 FACT-02、FACT-03、FACT-05。每一項都能回查 brief，沒有把查詢字串當成方案承諾。

排除與待補：價格、試用、退費、講師資格與健康效果沒有資料，因此不寫進可發布版本。若品牌日後提供證據，再另行更新，不先保留吸引人的空泛句子。

這份示範先證明內容與來源一致；實際上稿後仍要檢查頁面可見文字、結構化資料與搜尋結果，不能把模擬預覽當成最終顯示。
PRACTICE · 獨立頁面驗收

從共同改寫，退去提示後自己交付

D
老師示範：使用共通 brief 的頁面 A。先比較工作表與原始頁面，再逐項完成上方範例；每個主張都標出 FACT 編號，缺少的方案資料直接排除。
T
一起做：仍使用頁面 A。兩人各寫一版 Meta，交換標出每句引用的 FACT，再共同選出能說清楚入門內容、又沒有新增承諾的一版。無法標示來源的句子先刪除，不用較華麗的措辭掩蓋缺口。
S
獨立驗收：改做 brief 的頁面 B，不複製頁面 A 文字。把目標查詢、搜尋意圖、引用事實、Title、Meta、H1、兩個 H2、FAQ 判斷、排除或待補主張與兩項採用理由寫入 onpage-seo-rewrite.md。任何可發布句子若無法回指工作表或 FACT，退回修正。

完成驗證：先從讀者角度重讀 Title 與 Meta 是否說明頁面內容，進入頁面後的 H1 與 H2 是否接得上，FAQ 是否真的出現在可見頁面。再核對目標查詢與搜尋意圖，確認每個可發布主張都能回指 FACT，查詢數據沒有被寫成市場保證，未知資料也沒有被改寫成肯定句。兩次檢查都通過，才交付這份檔案。
