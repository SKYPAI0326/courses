02

先看這裡：這一節你要做什麼

第六模組你在 GA4 報表裡看過很多數字，也和組員選了巷口晨光的三個代表旅程事件。這一節要回答一個你可能還沒想過的問題：那些數字是誰收進來的？

答案是網站上的「追蹤代碼」。顧客按了一個按鈕，要有一段程式知道「他按了」，再把「按了什麼、在哪裡按」送給 GA4。這一整個模組學的工具叫 GTM，就是用來管理這些追蹤代碼的。

但這一節還不會打開 GTM。順序是：

  1. 先用白話把「要收什麼行為、什麼時候收、值從哪裡來、怎麼測」寫成一張表，叫做追蹤規格。
  2. 下一節（7-2）才建立容器、操作預覽模式，拿這張表逐列檢查。
  3. 再下一節（7-3）才建立 GA4 事件代碼，讓資料真的進到 GA4。

為什麼先寫表？因為 GTM 的設定畫面只會問你「要用哪個觸發條件、讀哪個變數」，不會問你「這樣設對不對」。對不對要靠一張事先寫好、可以拿來比對的規格。沒有規格就動手設定，最常見的結果是：事件有進來，但數字不能用，而且沒人說得出哪裡錯。

這一節結束時，你手上會有一張四列、每列八個欄位的表。下面先把會用到的名詞一個一個講清楚，再示範兩列，最後換你寫兩列。

03

第一部分：名詞先講清楚

1. GTM 是什麼

Google 代碼管理工具（Google Tag Manager，簡稱 GTM）：Google 官方說明稱它是一套「代碼管理系統」。白話講，就是網站只要裝一次 GTM 的程式碼，之後要加、改、停用追蹤代碼，都在 GTM 的網頁介面裡做，不必每次請工程師改網站。

你可以把它想成一台裝在網站上的「追蹤代碼配電箱」：電線（追蹤代碼）全部從這個箱子拉出去，要加一條線、關一條線，打開箱子處理就好，不用敲牆。

2. 四元素：每個元素回答一個問題

周小姐，這四個英文詞很容易聽過就忘。記的時候不要背定義，記它回答哪一個問題：

元素 英文 它回答的問題 山徑咖啡的例子
容器 Container 這一整包設定裝在哪個網站？ 裝在預約練習頁的那一個容器，ID 長得像 GTM-XXXXXXX
代碼 Tag 要把什麼資料送到哪裡？ 「送一個叫 line_join 的事件給 GA4」
觸發條件 Trigger 什麼時候送？ 「資料層出現 line_join 這個事件的時候」
變數 Variable 送出去的值從哪裡拿？（也用來判斷條件） 「placement 的值，從資料層裡的 placement 拿」

再把每一個多講兩句：

  • 容器：Google 說明的定義是「安裝在特定網站上的代碼、觸發條件、變數和相關設定的組合」。一個網站通常一個容器。容器 ID 一律以 GTM- 開頭，後面接英文和數字。你在 7-2 會建立自己的容器並拿到這個 ID。
  • 代碼：真正「送資料出去」的那段程式。常見的有：
    • Google 代碼：讓網站和 GA4（或 Google Ads）接上線的基本代碼。7-2 會裝。
    • GA4 事件代碼：送一個特定事件（例如 line_join）給 GA4。7-3 會建。
    • Google Ads 代碼：記錄廣告帶來的轉換。
    • Meta 像素：Facebook／Instagram 廣告用的追蹤代碼。
  • 觸發條件：決定代碼「什麼時候」動作。代碼本身不會自己跑，一定要掛一個觸發條件。
  • 變數：一個「會變的值」的名字。例如「這次點的按鈕上寫什麼字」「這次推送的 placement 是什麼」。變數有兩種用途：放進代碼裡當參數值，或放進觸發條件裡當判斷依據（例如「網頁網址包含 booking 才觸發」）。

3. 四者的關係：一句話版

→
容器裡放著代碼；觸發條件決定代碼什麼時候動作；動作時，代碼用變數取得要送出去的值。

畫成流程：

顧客操作 → 網站發出訊號 → GTM 的觸發條件「聽到了」 → 啟動代碼 → 代碼用變數取值 → 送到 GA4
                       （以上全部發生在網站上裝的那一個容器裡）

4. 任何一個設錯，會發生什麼

這張表在 7-2、7-3 除錯時很有用，現在先讀過，知道「症狀」對應到「哪一格」：

設錯的地方 你會看到的症狀 例子
容器 什麼都沒有，所有事件都不見 網站沒裝容器程式碼，或裝的是別的容器 ID
代碼 觸發了，但 GA4 收到的東西不對，或送到錯的地方 事件名稱打成 Line_join（GA4 事件名稱區分大小寫，會變成另一個事件）
觸發條件 該出現時沒出現，或不該出現時也出現 事件名稱比對寫錯 → 永遠不觸發；條件放太寬 → 按收合也算一次
變數 事件有進來，但參數是空的或值不對 資料層變數名稱寫成 Placement，讀不到值，參數變成 undefined

注意最後一列：事件有進來，不代表追蹤是對的。這就是為什麼規格表裡要寫「讀取的變數」和「參數型別」，之後才能逐項核對。

5. 變數的兩類：內建變數與資料層變數

內建變數：GTM 已經幫你做好、勾選啟用就能用的變數。Google 的內建變數清單把網頁容器的內建變數分成幾類，本課會碰到的有：

類別 常用的內建變數 要搭配的觸發條件
點擊 點擊 ID、點擊 Class（官方中文介面稱「點擊類別」）、點擊文字、點擊網址 點擊觸發條件
表單 表單 ID、表單類別、表單文字 表單提交觸發條件
網頁 網頁網址、網頁路徑、網頁主機名稱、參照網址 任何觸發條件都能用
捲動 捲動深度門檻、捲動深度單位、捲動方向 捲動深度觸發條件

內建變數讀的是網頁上看得到的東西：按鈕的 ID、按鈕上的字、網址。

資料層變數：讀的是網站主動交給 GTM 的資料（下一段講資料層）。例如練習頁按「推送加入 LINE 事件」時，網站會交出 placement: 'booking_practice_bottom'，你在 GTM 建一個資料層變數，名稱填 placement，就能讀到這個值。

兩者怎麼選？一句話：網站有主動交出資料，就用資料層變數；網站沒交，才退而求其次用內建變數去「看」頁面。 原因在第 7 段說明。

6. 資料層（dataLayer）：網站和 GTM 之間的交接箱

這是你第一次看到程式碼。不用會寫，只要看得懂它在說什麼。

資料層是網站和 GTM 之間的一個「交接箱」。網站把「發生了什麼事、相關的值是什麼」放進箱子，GTM 從箱子裡拿。放進去的動作叫 dataLayer.push()，push 就是「推進去」。

練習頁按下「推送加入 LINE 事件」時，網站做的事情是這一行：

dataLayer.push({event: 'line_join', placement: 'booking_practice_bottom', page_type: 'booking_practice'});

逐段拆開讀：

片段 意思
dataLayer.push( 「往交接箱裡放一筆資料」
{ ... } 大括號裡是這一筆資料的內容，一組一組「名稱: 值」，用逗號隔開
event: 'line_join' 名稱叫 event 的那一組最特別：它代表「發生了一個叫 line_join 的事件」。GTM 的自訂事件觸發條件就是看這一格
placement: 'booking_practice_bottom' 附帶的資料：按鈕位置。值有單引號，代表它是文字（字串）
page_type: 'booking_practice' 附帶的資料：頁面類型，也是文字

再看比較表那一筆：

dataLayer.push({event: 'comparison_open', page_type: 'booking_practice', product_count: 3});

product_count: 3 的 3 沒有單引號，代表它是數字，不是文字。這就是規格表要寫「型別」的原因：數字可以加總、比大小，文字不行；同一個參數這次送數字、下次送文字，後面的報表就會亂。

→
用 Excel 來想：一個儲存格裡的 3 和 '3（前面加單引號）看起來一樣，但前者能 SUM、後者不能。資料層也是同樣道理。

兩個要知道的規則（Google 資料層說明）：

  1. 資料層要在容器程式碼之前宣告。 網站的原始碼裡，要先有建立交接箱的這一行，再放 GTM 的容器程式碼：
    window.dataLayer = window.dataLayer || [];
    意思是「如果箱子已經有了就沿用，還沒有就建一個空的」。官方也提醒，GTM 載入後不要再寫 dataLayer = [] 把箱子整個換掉，會把已經放進去的東西清掉。
  2. 名稱區分大小寫。 dataLayer 寫成 datalayer 就不會動；placement 和 Placement 也是兩個不同的名稱。

7. 為什麼優先用資料層事件，而不是直接聽點擊

拿「加入 LINE」舉例，有兩種做法：

  • 做法 A（聽點擊）：觸發條件設「點擊，點擊文字等於『推送加入 LINE 事件』」。
  • 做法 B（聽資料層事件）：觸發條件設「自訂事件，事件名稱等於 line_join」。

做法 A 不需要工程師，但很脆弱：行銷改了按鈕文案（例如改成「加 LINE 拿優惠」），追蹤就無聲無息地斷了；頁面上如果有兩個寫一樣字的按鈕，也分不出是哪一個。做法 B 要網站先推送事件，但事件名稱和參數是雙方約定好的規格，按鈕怎麼改版都不受影響。

練習頁已經替四個互動都推送了資料層事件，所以本單元四列規格的觸發條件都用自訂事件、變數都用資料層變數。內建變數你先知道有哪些就好，碰到「網站沒有推送事件，而工程一時排不進來」的情況才會用到。

8. 代碼：優先用內建範本，自訂 HTML 最後才用

在 GTM 新增代碼時，會先選「代碼類型」。GTM 內建了許多範本（Google 代碼、GA4 事件、Google Ads 轉換追蹤等），也有社群範本庫。

另外有一種類型叫自訂 HTML（Custom HTML），可以貼任何一段程式碼進去。Google 的說明是：要避免效能或惡意軟體問題，最好的方法是使用內建範本；自訂 HTML 是用來部署「GTM 尚未支援」的代碼。

所以你的判斷順序是：

  1. 有內建範本 → 用範本。
  2. 社群範本庫有 → 確認來源可信再用。
  3. 都沒有，才考慮自訂 HTML，而且貼進去之前要問清楚：這段程式碼是誰提供的？它會把資料送到哪裡？會不會拖慢網頁？

自訂 HTML 等於讓一段程式碼在每位訪客的瀏覽器裡執行，貼錯或貼到來路不明的程式，影響的是整個網站。這也是為什麼「發布權限」不能隨便給（第 10 段）。

9. 觸發條件的類型

GTM 建立觸發條件時要先選類型。本課會用到或要認得的：

類型 什麼時候觸發 本課用途
網頁瀏覽 網頁載入時 本單元不用
點擊：所有元素 點擊網頁上任何元素（按鈕、圖片、連結） 網站沒有推送事件時的替代做法
點擊：僅連結 只有點擊 <a> 連結時（課程資料寫作「只限連結」，官方中文說明寫作「僅連結」，同一個東西） 同上，追蹤外連
表單提交 表單送出時 同上
捲動深度 頁面捲到設定的百分比或像素時 練習頁的保養說明區是給這個練習用的，本單元不用
自訂事件 資料層出現指定的 event 名稱時 本單元四列都用這個
初始化 比一般網頁瀏覽更早 需要提早載入、但不是處理同意的代碼；Google 代碼掛「初始化 - 所有網頁」（7-2）
同意初始化 最早，早於所有其他代碼，包括初始化 設定「同意的預設狀態」（模組最後的同意單元）

關於最後兩個：Google 說明指出，同意初始化（官方中文介面稱「同意聲明初始化」）會在所有其他代碼之前觸發，用來設定同意預設值，每個網站容器都內建一個「同意聲明初始化 - 所有網頁」觸發條件；初始化則給需要提早觸發、但不是管理同意的代碼。順序是：同意初始化 → 初始化 → 網頁瀏覽。現在只要記住「同意相關的設定要最早跑」，細節在本模組最後一單元處理。

10. 直接安裝 vs. 用 GTM 管理

不用 GTM 時，每一段追蹤代碼都要由工程師直接寫進網站原始碼。用 GTM 時，網站只裝 GTM 的一段容器程式碼，放在網頁的 <head> 裡，越上面越好。

裝好之後，其他代碼都在 GTM 介面管理。兩種做法比較：

比較項目 直接安裝在網站 用 GTM 管理
新增或修改一個追蹤代碼 每次都要工程師改原始碼、上線 在 GTM 介面設定，發布即生效
上線前測試 要另外架測試環境或直接上線看 預覽模式（Preview）：用 Tag Assistant 連線一個測試分頁，只有你看得到哪些代碼觸發了，一般訪客不受影響
改壞了怎麼辦 找工程師改回來 每次發布都留下版本，可以把舊版本設回最新版再發布
誰能讓修改生效 有網站部署權限的人 有 GTM 發布權限的人；標準版用使用者權限控管，正式的「送審、核准」流程只有付費的 Tag Manager 360 才有
代碼放在哪裡看得到 散在網站各頁原始碼 集中在一個容器

但用了 GTM，不代表完全不需要工程師。 以下仍然要網站或工程協作：

  • 安裝容器程式碼（只需一次）。
  • 新增資料層事件：例如網站原本沒有推送 booking_complete，就要請工程加 dataLayer.push()。GTM 只能聽網站「說出來」的事。
  • 同意管理工具：跳出「是否同意 Cookie」橫幅、記住使用者選擇的那個元件，通常要網站端導入或設定。

這就是本單元要寫規格的另一個理由：規格表就是交給工程的需求單。

04

第二部分：追蹤規格怎麼寫

12. 追蹤規格是什麼

追蹤規格是一張表，每一列描述「一個要追蹤的行為」，回答四件事：

  1. 收什麼行為：使用者做了什麼。
  2. 什麼時候收：哪一個精確的時間點算一次。
  3. 值從哪裡取得：每個參數的值，來自網站推送的哪一格。
  4. 怎麼證明收對了：做哪個操作應該出現、做哪個相近操作不應該出現。

第 4 點的兩種測試要特別說明：

  • 正例：應該出現事件的操作。例如「按『開啟比較表』」。
  • 反例：看起來很像、但不應該出現事件的操作。例如「按『收合比較表』」。

只寫正例不夠。一個「每次點那個按鈕都送事件」的錯誤設定，正例也會過。反例才能抓出「條件放太寬」的錯。

13. 八個欄位，每一格寫什麼

你擔心「網站訊號、觸發條件、變數」三格分不清。先用一個比喻：

→
早餐店櫃台喊「3 號餐好了」。

判斷口訣：網站訊號是網站說了什麼；觸發條件是 GTM 聽到什麼就動作；變數是 GTM 從裡面拿出哪個值。

八個欄位的寫法：

欄位 寫什麼 寫法提醒
1. 使用者操作 使用者在畫面上做了什麼 用畫面上的字描述，例如「按『開啟比較表』」
2. 網站訊號 網站推送的資料層事件名稱、帶哪些值，在什麼時機推送 時機要精確到可以被測試，例如「只在由收合變展開時」
3. 觸發條件 GTM 用哪一種觸發條件、怎麼比對 本單元一律是「自訂事件，事件名稱等於 ○○」
4. 讀取的變數 GTM 要建哪些變數、各讀資料層的哪一格 寫「資料層變數 placement」，名稱逐字照網站訊號
5. GA4 事件名稱與參數（含型別） 最後送進 GA4 的事件名稱，每個參數的型別（文字／數字） 名稱逐字照品牌包第 11 節
6. 應出現的測試 正例：前置狀態 → 操作 → 預期看到什麼 寫到「別人照著做就能判斷過或不過」
7. 不應出現的測試 反例：相近操作 → 預期不新增 至少寫一個最容易混淆的
8. 要向網站或工程確認的事 規格和頁面不一致、或真實網站上線時會出問題的地方 寫成可以回答的問題

14. 網站還沒有現成訊號時：規格就是工程需求單

山徑咖啡練習頁已經推送好四個事件，所以第 2 欄你是「照抄並核對」。但真實工作裡，常常是網站根本沒推送。這時規格表就要多寫清楚六件事，交給工程：

需求項目 意思 以 booking_complete 為例
時機 哪一個瞬間推送 表單通過必填檢查、送出時；不是按鈕被按下時
欄位 要推送哪些名稱 event、form_id、preferred_slot
型別 每個欄位是文字還是數字 三個都是文字
來源 值從哪裡來 form_id 固定寫 trial_booking；preferred_slot 取下拉選單選中項目的 value
個資邊界 哪些東西不能放進來 姓名、Email 不可推送
驗收方式 怎樣算做好 列出正例、反例，在預覽模式逐條測

15. 個資邊界

事件和參數裡不放姓名、Email、電話。Google Analytics 的政策禁止傳送可識別個人的資訊（例如電子郵件地址、手機號碼），官方也點名「使用者輸入內容」，像搜尋框和表單欄位，是常見的無意外洩來源。

實務做法：自由輸入的內容，改成固定分類或非個人資料的值。

  • 不要送「姓名欄填了什麼」，只送「表單送出了」這件事。
  • 不要送「客人留言寫了什麼」，改送事先定好的分類，例如 inquiry_type: 'pickup_time'。
  • 偏好時段用下拉選單的固定值（weekday-afternoon），而不是讓客人自己打字。

練習頁本身也這樣設計：頁面說明寫明不會送出姓名或 Email，所有按鈕只把課堂事件推送到 window.dataLayer。

24. 模組作業：同一套欄位，換成巷口晨光

模組作業「一個點擊的旅程」，你要替第六模組選出的巷口晨光三個代表旅程事件，各寫一列規格，用的就是本單元這八個欄位。

巷口晨光沒有網站，這時規格表的角色會更清楚：它就是第 14 段說的工程需求單。例如「完成隔日早餐預訂」這個事件，你要寫清楚：

  • 時機：預訂成功確認時推送，不是按下按鈕時。
  • 欄位與型別：例如麵包盒品項用固定代碼（文字）、盒數（數字）、取貨時段（固定值，文字）。
  • 個資邊界：取貨人姓名、電話絕對不放進事件。
  • 驗收方式：正例、反例各寫清楚。

（以上只是寫法示範，事件名稱與參數請以你們組在第六模組選定的為準。）

實測時，沒有網站的組改用山徑咖啡練習頁跑一次預覽，展示一個事件從點擊、預覽模式到 GA4 即時報表的路徑。

25. 「練習頁是假的」，那這份規格算什麼

你擔心這只是紙上作業。換個角度看你做了什麼：

  • 你實際操作了一個網站，用事件監看區觀察它推送了什麼。
  • 你拿官方規格和實際行為對照，找到了不一致（例如 booking_start 只聽姓名欄）。
  • 你為每個事件寫了可驗收的測試，包括反例。
  • 你把真實上線會遇到的風險（送出失敗、跳轉前沒送完、重複計算、個資）寫成要向工程確認的問題。

這些正是追蹤工程裡行銷端要負責的工作：定義、驗收、對齊。面試時可以這樣講：

→
「我替一個預約頁寫了四個事件的追蹤規格，包括觸發時機、參數型別、正反例測試。過程中發現『開始填表』事件只監聽姓名欄，和規格寫的『第一個欄位』有落差，使用者若先填 Email 會漏記，我把它列成工程確認事項。」

具體、有發現、有判斷，比「我會用 GTM」有說服力得多。

07

回家複習：照這個順序

  1. 先背四個問題，不背定義：容器＝裝在哪；代碼＝送什麼去哪；觸發條件＝什麼時候送；變數＝值從哪拿。
  2. 再記一個口訣：網站訊號是網站說了什麼；觸發條件是 GTM 聽到什麼就動作；變數是 GTM 拿出哪個值。
  3. 重開練習頁，不看講義，把四個互動各做一次正例、一次反例，看監看區序號有沒有跳。
  4. 拿出你的四列規格，跑一次第 21 段的自我檢查。
  5. 開始寫巷口晨光的三列，八個欄位照抄表頭。
