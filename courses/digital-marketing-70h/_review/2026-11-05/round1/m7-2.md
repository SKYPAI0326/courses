# 安裝 Google 代碼並用預覽模式驗證
把自己的 GTM 容器接上 GA4，再用練習頁留下網站、GTM、GA4 三層驗證紀錄。
學習目標：能在 GTM 建立網頁容器與 Google 代碼，連到自己的 GA4 評估 ID｜能用 Tag Assistant 預覽練習頁，核對容器、資料層事件與參數，並做應出現與不應出現的測試｜能依「網站推送、GTM 看到、GA4 收到」三層證據排查看不到事件的原因
本節完成物：預覽模式驗證紀錄

## 預覽模式要證明三層訊號確實接通

這一節要把自己的 GTM 網頁容器載入[山徑咖啡預約練習頁](assets/practice/booking-practice.html)，確認網站推送、GTM 看見、GA4 收到三層證據。完成物記錄網址、操作、事件、參數、三層結果與反例，讓別人能重跑。

資料層（dataLayer）是網站把事件與參數交給 GTM 的 JavaScript 資料佇列；練習頁使用 `window.dataLayer`。Tag Assistant 預覽模式是 GTM 的除錯工具，顯示容器收到的事件、變數與代碼觸發結果。GA4 DebugView 顯示開啟除錯模式裝置的事件，位置是「管理 → 資料顯示 → DebugView」；即時報表查看最近活動。

右下角「最近事件」證明網站已推送資料層事件；Tag Assistant 證明 GTM 看見事件及參數；DebugView 或即時報表證明 GA4 收到事件。一層通過不代表另外兩層通過。[Monitor events in DebugView](https://support.google.com/analytics/answer/7201382)（2026-11 查證）。

## 建立容器與 Google 代碼

先把自己的 GTM、GA4 與練習頁連在一起。完成時應有 `GTM-` 容器 ID、`G-` Google 代碼 ID，以及使用 Initialization - All Pages 觸發的 Google 代碼。

1. 到 [Google Tag Manager](https://tagmanager.google.com/) 建立帳戶，容器平台選「網頁」，複製 `GTM-` ID。[Get started with Tag Manager](https://support.google.com/tagmanager/answer/12974036)（2026-11 查證）。
2. 到 GA4「管理 → 資料收集和修改 → 資料串流 → 網頁串流」，複製自己的 `G-` ID；示範帳戶不能接收練習資料。
3. 在 GTM 按「代碼 → 新增 → 代碼設定 → Google 代碼」，貼上 `G-` ID。舊的 GA4 設定代碼已由 Google 代碼取代。[GA4 Configuration tag 改為 Google 代碼](https://support.google.com/tagmanager/answer/13543899)（2026-11 查證）。
4. 觸發條件選 Initialization - All Pages，命名後儲存；同意設定仍要更早處理。
5. 練習頁線上網址後加 `?gtm=GTM-自己的ID`。頁面上方應顯示該 ID；範例 `GTM-XXXXXXX` 會被擋下。

自有網站要把第一段容器程式碼放在 `<head>` 越前面越好，第二段放在 `<body>` 開頭；有外掛或設定欄位時依平台說明。[Install the Google Tag Manager container snippet](https://support.google.com/tagmanager/answer/2574370)（2026-11 查證）。本頁只用練習頁的 `?gtm=` 參數。

## 接受同意後連上 Tag Assistant 與 GA4

接著驗證容器連線、Google 代碼觸發與 GA4 的 `page_view` 收件，對象是練習頁、Tag Assistant 與自己的 GA4 資源。

1. 在 GTM 右上按「預覽」，貼上完整練習頁網址並按 Connect；成功時 Tag Assistant 顯示 Connected。
2. 練習頁四項同意預設為「拒絕」。先在左下橫幅按「接受全部」；分析儲存被拒絕時，GA4 資料可能看不到或不完整。[Consent settings in Tag Manager](https://support.google.com/tagmanager/answer/10718549)（2026-11 查證）。
3. 在 Tag Assistant 確認 Google 代碼只觸發一次，代碼 ID 等於自己的 `G-` ID。
4. 到 GA4 DebugView 或「報表 → 即時」核對 `page_view`；DebugView 只顯示開啟除錯模式的裝置事件。

加強型評估可自動收集 `page_view`、`scroll`、外連 `click`、站內搜尋、影片、`file_download`、`form_start`、`form_submit`。自訂事件要避免重複；`form_submit` 不適用所有表單，重要表單仍用自訂事件驗證。

## 山徑咖啡示範：三個資料層事件的正反例

練習頁有四個自訂互動：三個預約事件供示範，`line_join` 留給練習。示範確認網站與 GTM 的事件、參數及反例；GA4 先用 `page_view` 驗證收件，自訂事件待下一節建代碼後再驗證。

| 材料 | 用途 |
|---|---|
| 預約練習頁 | 產生四個可觀察互動 |
| 品牌包量測規格 | 核對事件名稱、時機與參數 |
| Tag Assistant、DebugView | 分別核對 GTM 看見與 GA4 收到 |

每列記錄：操作、預期事件與參數、頁面事件、Tag Assistant、GA4、反例、證據備註。

1. **開啟比較表**：展開時應出現一次 `comparison_open`，參數 `page_type=booking_practice`、`product_count=3`；收合時不應新增。
2. **開始預約**：姓名欄首次取得焦點應出現一次 `booking_start`，參數 `form_id=trial_booking`、`page_type=booking_practice`；同輪切換其他欄位不應再出現。
3. **完成預約**：填妥姓名、Email、時段並送出，應出現 `booking_complete`，參數 `form_id=trial_booking`、所選 `preferred_slot`；缺任一必填欄位時不應出現。

GA4 欄中，`page_view` 寫實際收件結果；三個自訂事件寫「待下一節建立事件代碼」，以免把 GTM 看見誤當 GA4 收到。

## 看不到事件時依網站、GTM、GA4 三層排查

排查要找出訊號在哪一層中斷，再到對應位置修正。

- **網站推送**：看右下角最近事件；沒有就查操作與必填欄位，有事件但參數錯就查頁面推送。
- **GTM 看到**：網站有事件而 Tag Assistant 沒有，就查容器 ID、Connected 狀態與分頁；事件有而代碼未觸發，就查代碼或觸發條件。
- **GA4 收到**：代碼已觸發而 `page_view` 不見，就查 `G-` ID、預覽連線、同意與資料篩選。

兩個 `page_view` 常表示 Google 代碼同時由 GTM 與網站原生程式碼安裝。即時報表與 DebugView 幾乎即時；一般資源的當日資料約需 2～6 小時、每日資料約 12 小時。[Data freshness](https://support.google.com/analytics/answer/11198161)（2026-11 查證）。

## 用 line_join 完成可重跑的驗證紀錄

練習改測 `line_join`，欄位與示範相同。先重新整理、確認容器 ID、連上預覽並按「接受全部」。

1. 正例：按「推送加入 LINE 事件」，預期頁面與 Tag Assistant 各出現 `line_join`，參數 `placement=booking_practice_bottom`、`page_type=booking_practice`。
2. 反例：只捲動到 LINE 區塊但不按按鈕，預期不出現 `line_join`。這能證明觸發時機是點擊，不是看見區塊。
3. GA4 欄：本頁先記 `page_view` 的實際收件；`line_join` 寫「待下一節建立自訂事件代碼」，不能把資料層事件當成 GA4 已收到。
4. 重新整理後重做正例，確認事件與參數一致，備註測試時間、容器 ID 後四碼、截圖編號。

完成後再看參考方向：合格紀錄同時保留「點擊時出現」與「只捲動時不出現」，網站與 Tag Assistant 分欄，GA4 未建事件代碼也如實標示。下一節再補第三層證據。
