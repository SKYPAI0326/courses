### m2a-1｜大型語言模型怎麼運作、為什麼會說錯
- 型態：概念型。理由：學員要能說明 LLM 是「預測下一個 token」的系統、幻覺為什麼會發生，並用這個原理判斷 AI 輸出哪裡要查證。
- 學習目標草案：
  1. 能說明 LLM 以「預測下一個 token」產生文字，和資料庫、搜尋引擎有什麼不同
  2. 能說明幻覺的成因，並辨認捏造、假引用、混淆、過時等常見類型
  3. 能判斷一段 AI 輸出中哪些句子需要回到來源查證，並用提供上下文的方式降低補造
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | LLM（Large Language Model）術語 | 標題就寫 LLM 全名，全頁用 LLM 稱呼 | 弱化（只寫「大型語言模型」，LLM 0 次） |
  | 核心機制：預測下一個最可能的 token | LLM 只做一件事：依統計關係預測下一個 token | 保留 |
  | 不是資料庫、不是搜尋引擎 | 以為 ChatGPT 去「查」答案是誤用的根源 | 保留 |
  | 手機鍵盤預測下一字的類比 | 輸入「今天天氣」鍵盤預測下一字，LLM 規模大幾億倍 | 遺失 |
  | 「統計上最合理」不等於「事實正確」 | 兩件事有時一致、有時不同 | 保留（改寫成流暢度與可信度分開驗收） |
  | Token 定義 | 約英文一個詞或半個詞、中文一到兩個字 | 弱化（有定義，沒有中文大約多長） |
  | Context Window（上下文視窗） | 一次能看到的 token 上限，超過會忘記前面的對話 | 遺失（只說模型看到的是一段上下文，沒有「上限」與「遺忘」） |
  | Temperature（溫度） | 溫度低輸出保守一致，溫度高較有創意但不穩定 | 遺失（是否保留見備註） |
  | 幻覺（Hallucination）術語與定義 | 用極自信語氣描述不存在的事實 | 遺失（改稱「補造」，幻覺 0 次） |
  | AI 不知道自己在說錯 | 沒有說謊意圖，只是預測出的序列恰好是錯的 | 弱化（只剩「會自信地補出不存在的細節」） |

  | 假論文實測（HBR、虛構作者與百分比） | 貼一段指令，示範格式完整但來源不存在 | 遺失 |
  | 黃金守則：越權威越要驗證，「90% 正確」最危險 | 關鍵細節錯但其他都對時最容易放鬆警戒 | 弱化（只剩卡關「把語氣肯定當成有把握」） |
  | 把 AI 當草稿機，不當事實庫 | AI 負責形式，人負責事實 | 保留 |
  | 提供上下文減少補造 | 給越多正確背景，AI 越少需要自己編 | 保留（示範的兩種輸入） |
  | 對外數字、引用一律查證 | 會對外發布的事實必須查原始來源 | 保留 |
  | 知識截止日期 | 訓練資料有截止日，之後的事模型不知道 | 遺失 |
  | 要求 AI 標出不確定 | 在指令中要求「不確定就明說」 | 遺失（m2a-3 現稿只有「模型表達不確定只能當線索」） |
  | 省時要把提示、修訂、查證與重做時間一起算 | 本單元核心洞察 | 遺失 |

### m2a-2｜2026 年的 AI 工具：聊天、深度研究、代理、生圖、生影片
- 型態：方法型（次：概念型）。理由：學員要能用一套評估框架為自己的任務選工具；工具類別是框架的前置概念。
- 學習目標草案：
  1. 能說明生成式 AI 工具的主要類別或產品形態，以及各自適合的任務
  2. 能用評估問題（任務需求、真實任務下的輸出品質、整合性、成本與風險）判斷新工具值不值得引入
  3. 能完成一份個人工具選用表（AI 工具組合），寫出每個工具的分工與不選的理由

  | 工具名稱、方案、價格會變，以官方頁面為準 | 本頁名稱只當候選例子，採用前查官方 | 保留 |

### m2a-3｜AI 的邊界：資料安全、版權與 AI 內容標示
- 型態：概念型（次：方法型）。理由：學員要能說明資料安全、版權、偏見與平台標示的原則，並用來判斷某個情境能不能把資料交給 AI、輸出能不能發布；次要帶走一份可套用的驗證問題或守則。
- 學習目標草案：
  1. 能判斷哪些資料不應輸入消費者版 AI 工具，並說明替代處理方式（去識別、企業方案、核准環境）
  2. 能說明 AI 生成內容的版權現況與偏見風險，判斷素材能不能使用
  3. 能用驗證問題檢查 AI 輸出，並依平台規則決定是否標示 AI 內容
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | AI 的自信程度與準確程度無關 | 語氣有把握不等於內容正確，越精確的數字越要查 | 弱化（本頁只剩「語氣保留也不等於已驗證」，m2a-1 有卡關一條） |
  | 幻覺四形式（捏造引用、事實錯誤、過時資訊、混淆細節） | 表格列出形式與行銷場景風險 | 遺失（本頁沒有；m2a-1 剩三類，沒有捏造引用） |
  | 高風險內容（數字、引用、法規、競品事實）回原始來源驗證 | AI 是起草者，不是權威來源 | 弱化（只剩「文字要逐句核對來源」） |
  | 消費者版工具的輸入可能被用於訓練或人工審閱 | 輸入一旦上傳就不完全在你的控制下 | 遺失（現稿只問「會保存多久、誰能存取」，消費者版 0 次） |
  | 可以輸入／不應輸入清單 | 兩欄各五、六項具體例子 | 保留（改成資料四分類加練習守則） |
  | 企業版與消費者版的差異、本機模型選項 | 企業方案通常承諾不用輸入訓練模型 | 弱化（只剩「內部資料要看公司核准的工具、方案與保存設定」） |
  | 純 AI 生成、沒有人類創作介入的作品難獲著作權保護 | 競爭對手也能合法使用相同輸出 | 遺失 |
  | 人類創作介入越多，越接近受保護作品 | AI 輔助創作比全自動生成地位穩固 | 遺失 |
  | 訓練資料的版權爭議 | 以訴訟為例說明仍在演變 | 遺失（案件狀態見 E） |
  | 平台與客戶對 AI 內容的政策不同 | 選舉廣告揭露、部分客戶要求非 AI 內容 | 弱化（改成 YouTube／TikTok／Meta 標示規則，客戶政策不見） |
  | 偏見與代表性：來自訓練資料、常見例子、四項應對策略 | 生圖族裔、領導者代詞、年齡、西方框架 | 弱化（剩一句「涉及族群、職業、年齡與外貌時……刻板印象」） |
  | 三問驗證框架（有沒有高風險資訊、像不像我們的品牌聲音、我理解這個建議的邏輯嗎） | 每次使用 AI 輸出前問自己 | 遺失 |
  | 六個安全使用習慣 | 數字必驗證、敏感資料不輸入、AI 起草人潤稿、注意知識截止日、審查偏見、保留決策脈絡 | 弱化（剩驗證、敏感資料、偏見；截止日、人潤稿、保留決策脈絡不見） |
