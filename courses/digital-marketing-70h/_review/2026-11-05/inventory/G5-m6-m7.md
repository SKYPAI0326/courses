### m6-1｜GA4 怎麼組成：帳戶、資源、資料串流與示範帳戶
- 型態：概念型（次：操作型）。理由：學員要能說明 GA4 三層架構與各功能區的用途，並在示範帳戶找到對應報表。
- 學習目標草案：
  1. 能說明帳戶、資源、資料串流三層各自管什麼，並判斷看錯數字時該先檢查哪一層。
  2. 能操作 GA4 示範帳戶，找到首頁、報表、探索、廣告、管理五區，說出各區能回答的問題。
  3. 能說明 GA4 建置後的基礎設定（資料保留、內部流量、關鍵事件、Search Console 連結、追蹤驗證）各自防止什麼問題。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 三層架構：帳戶（Account）／資源（Property）／資料串流（Data Stream） | 三張卡片分別定義範疇與一對多關係 | 保留 |
  | 帳戶層管權限、Google Ads 連結、帳單 | 帳戶卡片列出三項職責 | 弱化（只剩「管理成員與存取權」） |
  | 一個資源可有多個串流（Web＋iOS＋Android） | 資源與串流卡片說明 | 保留 |
  | 在資料串流取得追蹤代碼（G-XXXXXXXX） | 串流卡片說明代碼來源 | 保留（稱「評估 ID」，只辨識用途） |
  | 左側五大功能區：首頁、報告、探索、廣告、管理 | 五張卡片各寫用途 | 弱化（剩四個，「廣告」區遺失） |
  | 預建報告類別：流量獲取、參與度、營利、留存、客層 | 「報告」卡片列出 | 弱化（導覽表只列流量獲取、網頁與畫面、事件、探索） |
  | 資料保留期預設 2 個月，改為 14 個月 | 基礎設定第 1 項，附路徑 | 遺失（m6-4 只說「資料保留設定只影響探索」） |
  | 排除內部流量 | 基礎設定第 2 項，附路徑 | 遺失 |
  | 關鍵事件（key event）與 Google Ads 轉換是兩個名詞 | 基礎設定第 3 項 | 保留 |
  | 連結 Google Search Console | 基礎設定第 4 項，附路徑 | 遺失 |
  | 追蹤驗證：Tag Assistant 檢查連線、DebugView／即時報表看事件 | 基礎設定第 5 項 | 遺失（本頁未提，m7-2 才有） |
  | 即時報表／DebugView 當下可驗證，標準報表可能需 24–48 小時處理 | AI 區段說明兩種等待門檻不同 | 遺失 |
  | 建議用 GTM 安裝 GA4（不改網站程式碼即可調整） | 提示框 | 弱化（只說「事件安裝留到追蹤工程模組」） |

- 現稿問題：
  - A 案例先上（輕微）：概念段就用案例當例子，「同一個山徑咖啡資源若同時接官網與 App，可以有不同串流」。
  - B 沒引入就使用：「關鍵事件」在第一節就用（「還需要期間、成本、關鍵事件與資料品質」），到第五節才定義；「工作階段」用了沒定義（「報表顯示某個來源有 100 個工作階段」），定義在 m6-3。

- 備註：
  - 改寫前的練習用「互評者隨機抽兩項」驗收，和不設計學員互評的原則衝突，不列入保留。
  - m7-2 現稿要求每組自建 GA4 資源，因此改寫前的「基礎設定五件事」又有地方可操作。要放回 m6-1（概念＋路徑），還是放到 m7-2 建資源後實作，需要負責人決定。

### m6-2｜流量從哪裡來：來源、媒介與 UTM
- 型態：概念型（次：方法型）。理由：學員要能說明來源、媒介、管道群組，讀懂各管道的常見誤讀，並用一套命名規則建立可驗證的 UTM。
- 學習目標草案：
  1. 能說明來源、媒介、預設管道群組的差別，並判斷自然搜尋、直接、推薦、付費搜尋、自然社群、Email 各自的常見誤讀。
  2. 能依團隊字典建立 UTM 連結，並用測試連結和 GA4 報表確認參數有進來。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 六種流量來源定義（Organic Search／Direct／Referral／Paid Search／Organic Social／Email） | 三欄表：來源、定義、常見誤讀 | 弱化（只有來源／媒介的一般說明，沒有逐一定義各管道） |
  | Direct 代表 GA4 沒取得清楚來源，不能證明品牌知名度提升 | 表格中的誤讀說明 | 保留 |
  | Organic Search 下降可能是 SEO 問題或 AI Overview 截流，要和 GSC 比對 | 表格中的誤讀說明 | 遺失 |
  | Referral 要看是哪個網站、排除內部子網域 | 表格中的誤讀說明 | 遺失 |
  | Paid Search 要連結 Google Ads、確認自動標記（auto-tagging）；已有自動標記時不重複加 UTM | 表格與 UTM 定義段 | 遺失 |
  | 社群 App 內瀏覽器或轉址會讓來源遺失 | 表格中的誤讀說明 | 遺失 |
  | Email 沒有 UTM 可能落入 Direct | 表格中的誤讀說明 | 弱化（併入 Direct 一句「未標記連結」） |
  | UTM（Urchin Tracking Module）定義 | 「行銷活動的身分證」 | 弱化（定義保留，原文全名遺失） |
  | 參數 utm_source／medium／campaign／content（＋term） | 範例網址逐欄拆解 | 保留（utm_term 遺失） |
  | 命名規範：小寫、統一字典、推薦／避免對照 | 推薦格式 vs 避免格式表 | 保留 |
  | Campaign URL Builder | 建立與驗證提示 | 遺失 |
  | 測試連結確認參數抵達、GA4 看到預期 source／medium／campaign | 建立與驗證提示 | 保留 |
  | UTM 治理紀錄（申請人、目的頁、啟用日期、驗證結果） | 參考輸出「治理紀錄」 | 保留 |

- 現稿問題：
  - A 案例先上（輕微）：UTM 概念段直接用品牌包的規則當規範，「山徑咖啡規則使用小寫英文字母、數字與連字號……例如比較內容活動在 Instagram 與 Threads 都用 `compare-before-upgrade`」，示範段又重講一次。
  - B 沒引入就使用：示範計算「參與率」與「互動工作階段」（「參與率是 840 ÷ 1,350，約 62.2%」），兩者到下一頁 m6-3 才定義。
  - C 練習等於示範：渠道計算的練習資料（練習包 1A）和示範用的品牌包 MEASURE-03 是同一張表，示範已算完其中兩列：「先用試算表或計算機完成六個渠道的參與率……」。UTM 練習要學員「抄下品牌包的六個 UTM 範例」，示範用的 Instagram 那列就在其中；參考寫法的 Email 那列（`email-list`、`email`、`booking-reminder`、`cta-01`）也是品牌包原文。
  - D 判準不一致：無。
  - E 疑似錯誤或過時：「GA4 在 2026-05-13 新增這個預設管道群組；ChatGPT 導出的連結會帶 `utm_source=chatgpt.com`」，日期與參數值需確認；品牌包寫「2026-05」，兩處精度不同。
- 備註：
  - 練習包開頭寫「所有數字與品牌包 `MEASURE-03`、第 9 節課堂模擬基線一致」，M6 的 C 問題來自練習包的設計，不只是頁面寫法（m6-4、m6-5 同）。要另做一份練習用數據，還是改用示範帳戶，需要負責人決定。
  - 參與率要在 m6-2 先定義，還是把示範的參與率計算移到 m6-3 之後，要和 m6-3 一起決定。

### m6-3｜誰來了、做了什麼：使用者與行為報表
- 型態：概念型（次：操作型）。理由：學員要能說明使用者、工作階段、事件與參與度指標的意義，並在報表中寫出不越界的行為觀察。
- 學習目標草案：
  1. 能說明使用者、工作階段、事件次數三種單位，以及參與率、跳出率、平均參與時間、捲動事件的定義與限制。
  2. 能判斷一句報表觀察有沒有把次數寫成人數、把觀察寫成原因。
  3. 能操作示範帳戶的網頁與畫面、事件報表，寫出含期間、對象、數字、待確認問題的觀察句。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 參與率定義與有效工作階段三條件（超過 10 秒、發生關鍵事件、2 次以上頁面瀏覽） | 參與率卡片 | 弱化（定義保留，三條件遺失） |
  | 跳出率是參與率的反面 | 段首說明 | 保留 |
  | 沒有通用健康門檻，與同頁面／來源／裝置／期間的自身基線比較 | 參與率卡片 | 遺失 |
  | 平均參與時間：網頁保持焦點或 App 在前景的時間，不等於讀懂 | 卡片定義＋用法 | 遺失（練習要學員記錄，但頁面沒有定義） |
  | 捲動深度：加強型評估在 90% 送 `scroll`，不能證明讀完 | 卡片定義 | 保留 |
  | 事件計數；GA4 以事件為核心 | 卡片定義 | 保留（併入三種單位） |
  | 使用者路徑：最常見進站頁、主要轉換路徑、最大離開點、不同來源路徑差異 | 四個分析角度 | 弱化（路徑探索移到 m6-4，進站頁與離開點的分析角度遺失） |
  | 留存報告：比較 cohort 回訪；回訪不等於滿意，需搭配訂單、毛利等價值 | 留存讀圖示意（標明模擬值） | 遺失 |
  | 受眾分群：條件要可觀察、可合法使用、對決策有意義 | AI 區段的分群心法 | 遺失 |

- 現稿問題：
  - A 案例先上：無。
  - B 沒引入就使用：「報表也可能含同意模式的行為建模」，同意模式到 m7-4 才教；練習要求記錄「平均參與時間」，頁面沒有定義；「加強型評估的 `scroll`」中的「加強型評估」沒說是什麼。
  - C 練習等於示範：無（示範用品牌包，練習用示範帳戶）。
  - D 判準不一致：練習的觀察句要「期間＋對象＋兩個可核對數字＋尚待確認的問題」，示範只有一個數字（「近 30 天／商品頁／2,400 次瀏覽／需要再與比較表開啟和預約事件對照」）；練習完成物是四欄（報表與期間／維度與指標／觀察句／下一個驗證問題），示範沒有照這四欄做。
  - E 疑似錯誤或過時：「GA4 內建的 Ask Advisor 也能用 Gemini 問資源資料，但目前只限介面語言為英文的資源」，功能名稱與語言限制需確認；行為建模門檻只寫「每天至少有 1,000 筆拒絕分析儲存的事件，並持續至少 7 天」，看起來少了同意使用者數的另一條門檻，需確認。
- 備註：
  - 改寫前的留存與受眾分群內容，m8-4 Meta 再行銷可能會用到。要放回本頁還是移到廣告模組，需要負責人決定。
  - 「同意模式行為建模」放在 m7-4 之前講，要刪掉還是改成預告，需要決定。

### m6-4｜探索報表：漏斗、路徑與區隔
- 型態：方法型（次：操作型）。理由：學員要能依問題選擇探索技法，並用漏斗步驟算出最大流失段。
- 學習目標草案：
  1. 能說明漏斗、路徑、區隔重疊、任意形式、使用者生命週期各自回答什麼問題，並依問題選一種。
  2. 能完成一個漏斗：定義步驟與開放／封閉，計算逐步流失與整體完成率，並把觀察和原因假設分開。
  3. 能操作示範帳戶建立漏斗探索並保存設定摘要。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 漏斗探索（Funnel Exploration）：回答哪一步流失最嚴重 | 第 01 型卡片 | 保留 |
  | 開放式 vs 封閉式漏斗 | 漏斗設定方式 | 保留 |
  | 漏斗加細分比較不同受眾 | 漏斗設定方式 | 保留（裝置區隔） |
  | 路徑探索（Path Exploration）：起點、向前／向後追蹤 | 第 02 型卡片 | 保留 |
  | 區隔重疊（Segment Overlap）：最多 3 個區隔、Venn 圖、可下鑽 | 第 03 型卡片 | 弱化（只剩一般「區隔」，區隔重疊技法遺失） |
  | 任意形式（Free Form）：自訂維度×指標交叉表、可切圖表 | 第 04 型卡片 | 遺失 |
  | 使用者生命週期（User Lifetime）：比較不同獲取來源的長期價值 | 第 05 型卡片 | 遺失 |
  | 漏斗只指出哪裡流失，原因要用裝置細分、流程實走等查證 | 新手入門提示 | 保留 |
  | 整體完成率、逐步流失回答不同問題 | 參考輸出 | 保留 |
  | 單一變因測試、主要指標、停止條件 | 練習驗收 | 保留 |
  | Mobile／Desktop 比較 | 一起做 | 保留 |

- 現稿問題：
  - A 案例先上：無。
  - B 沒引入就使用：「資料保留設定只影響探索與漏斗報表」，資料保留是什麼、預設多久、在哪裡改，全課現稿都沒教過（改寫前在 m6-1）。
  - C 練習等於示範：示範算完 2,400 → 120 → 54，練習要學員用同一組數字再算一次，參考寫法就是示範結果：「再回到山徑咖啡模擬資料……120 的上一層是 2,400，54 的上一層是 120」「合格結果會寫『近 30 天；商品頁瀏覽 2,400 → 預約開始 120 → 預約完成 54；最大流失在第一段』」。示範帳戶那段的資料不同，不在此列。
  - D 判準不一致：頁面教「常見卡關是把不同事件口徑硬串成漏斗」，示範卻把「商品頁瀏覽 2,400」（三款商品頁的瀏覽次數）和「預約開始 120」（事件次數）串成同一個漏斗。
  - E 疑似錯誤或過時：「漏斗探索回答一連串指定步驟有多少次到達」「本例以事件與瀏覽次數計算」，GA4 漏斗探索看起來是以使用者數計算，不是次數，需確認。改寫前把 User Lifetime 譯成「使用者需求」，中文名有誤。
- 備註：m6-4 的示範結果（2,400 → 120 → 54）在 m6-5 又當成示範與練習的起點，兩頁重複用同一組數字。

### m6-5｜從數據到決策：A3 與假設
- 型態：整合型（次：方法型）。理由：學員要能把前幾頁的流量、行為、漏斗發現組成一頁 A3 決策，並寫出可推翻的單一變因假設。
- 學習目標草案：
  1. 能說明 A3 報告的出處與五段結構（現況、目標、根因、對策、驗證）。
  2. 能用「觀察→問題→假設→測試→驗證」寫出含主要指標、護欄指標、停止條件的假設。
  3. 能完成一頁 A3 決策草案，並在小組中選出代表旅程的三個指標。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | A3 報告源自豐田生產系統，一張紙呈現問題全貌 | 段首定義 | 弱化（一頁式保留，出處遺失） |
  | A3 五段：現況、目標、根因、對策、驗證 | 五格框架，各附例句 | 弱化（改成背景問題／證據／原因假設／行動／驗證，「目標」段沒了） |
  | 觀察與原因分開 | 根因段例句 | 保留 |
