### m5-1｜搜尋生態：一般結果、AI 摘要、AI 模式與廣告
- 型態：概念型（次：操作型）。理由：學員要能說明搜尋結果頁有哪些版位與入口、成效要分三層看，再實際搜尋並記錄觀察。
- 學習目標草案：
  1. 能說明搜尋結果頁（SERP）上的主要版位：一般結果、AI 摘要（AI Overview）、AI 模式（AI Mode）、地圖、購物、廣告，以及 Google 以外的 AI 搜尋與社群搜尋入口。
  2. 能判斷一次搜尋的成效要拆成可見度、點擊、轉換三層，並說明為什麼看到 AI 摘要不能直接推論點擊會下降多少。
  3. 能操作實際搜尋，記錄日期、裝置、地區、是否登入與版位觀察。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態：保留／弱化／遺失 |
  |---|---|---|
  | 用自己的資料判斷各入口扮演發現、比較或行動的角色 | 有 Search Console、GA4、訪談時用資料判斷入口角色，不套產業通則 | 弱化（只剩「第一步是記錄畫面，而不是先猜哪個入口最好」） |
  | AI 搜尋入口（Perplexity／ChatGPT Search） | 多輪探索；引用是可見度訊號，不等於信任、點擊或轉換；要核對品牌被怎麼描述、引用哪一頁 | 遺失 |
  | 社群搜尋（TikTok／Instagram） | 部分受眾在社群平台搜尋，要看平台內搜尋與導站，不套用 Google 排名邏輯 | 遺失 |
  | 地圖搜尋與 Google 商家檔案 | 商家檔案維護地址、營業時間、類別、聯絡資訊，名稱／地址／電話要完整一致 | 遺失（只剩示範表「有地圖結果」） |
  | 在地排序三因素：關聯性、距離、知名度 | 引 Google 說明；評論與評分可能有幫助但不是唯一因素 | 遺失 |
  | Google AI 功能不需特殊 AI schema 或 AI 文字檔 | 仍沿用可爬取、可索引、有用可信的內容基礎 | 保留 |
  | 可見度、點擊、轉換三件事分開量測 | 不套用固定點擊跌幅，同時看 AI 可見度、網站點擊與進站後成果 | 保留 |
  | 搜尋結果頁（SERP）版位類型：AI 功能、廣告（SEA）、有機結果（SEO）、精選摘要（Featured Snippet） | 四張版位卡說明各自如何取得與量測，順序依查詢、地區、裝置變動 | 弱化（AI 摘要、AI 模式、廣告保留；SERP、SEO／SEA 對照、精選摘要與原文術語遺失） |
  | 結構化資料只標示頁面真實可見內容，不保證版位 | 精選摘要段與知識型品牌策略中說明 | 遺失 |
  | 品牌類型 × 可先驗證的入口（電商、在地服務、知識教育、生活風格、B2B） | 一張表當作「開始查證的假設，不是產業通則」 | 遺失 |
  | 搜尋投資原則：先做可爬取、內容品質、量測與落地頁，再用付費搜尋加速；AI 搜尋可見度是成效面向，不是獨立媒體渠道 | 頁尾原則與 AI 方案 prompt 的分類（內容與技術 SEO／付費搜尋／量測／實驗） | 弱化（只剩「不是另造一套『AI SEO』捷徑」） |
  | 廣告與自然結果是不同取得方式 | 廣告版位卡說明位置動態、是否投入看查詢、競價、毛利與轉換 | 保留（出價與預算移到廣告模組） |

- 現稿問題：
  - A 案例先上：第一節在任何入口或版位教之前就進品牌包與人物。原句：「第一次使用[山徑咖啡品牌包](assets/datasets/simulated-brand-pack.md)的搜尋資料，先分清楚三類資料」；「阿傑可能搜尋「手沖壺怎麼選」，麗芬可能搜尋「手沖壺推薦」」。（diagnosis 2.1 也列 m5-1 為「沒有任何一個小節是純概念」）
  - B 沒引入就使用：
    - Search Console 與四項指標在第一節的表格就出現，本頁沒說明是什麼（m5-3 才教）。原句：「| Search Console 近 28 天查詢 | 觀察網站已有曝光、點擊、點閱率與平均排名 |」
    - 小節標題「看懂四種入口與三種結果」沒有說四種入口是哪四種；正文只寫一般結果、AI 摘要、AI 模式，第一節又列「一般結果、AI 摘要、AI 模式、地圖、購物與廣告」。
  - C 練習等於示範：練習的五個查詢和示範完全相同，「選一列對照品牌包」也已在示範表最後一欄寫好。原句：「先用手機依序搜尋五個查詢」「接著選一列，對照品牌包判斷現有頁面能說什麼、缺什麼」。（實際搜尋畫面會不同，可降低但不能消除照抄）
  - D 判準不一致：第三節要求每列填 8 欄（「查詢、推測任務、AI 摘要、前三個一般結果類型、地圖、購物、山徑咖啡可承接的現有頁面、仍缺的內容」），示範表只有 4 欄（查詢｜模擬畫面重點｜顧客可能要完成的事｜山徑咖啡現況），練習又改成記錄「日期、裝置、地區、是否登入，以及畫面出現的一般結果、AI 摘要、AI 模式入口、地圖、購物與廣告」。三處欄位不同。
  - E 疑似錯誤或過時：
    - 【現稿】「Search Console 的生成式 AI 成效報表自 2026-08-31 起全球可用，提供曝光而沒有點擊」：日期與欄位待查證。
    - 【現稿】「Google 官方說明列出支援台灣及繁體中文」（AI 摘要）、「台灣上線日期目前來自媒體報導」（AI 模式）：時效性說法，待查證。
    - 【改寫前】「AI 功能中的曝光與傳統搜尋共同納入 Search Console 量測」：和現稿的「獨立生成式 AI 報表」說法衝突，兩者擇一，待查證。
- 備註：
  - m5-1 與 m5-2 的示範、練習都用同一組五個代表查詢（品牌包 SEARCH-02），兩頁的 C 是同一個來源；品牌包 SEARCH-01 有 30 個查詢，可另配練習資料，但 SEARCH-02 只提供這五個查詢的畫面觀察。
  - 要負責人決定：社群搜尋是否在 M5 教（可能和社群模組重疊）；在地搜尋／Google 商家檔案是否在 M5 教（目前全模組沒有任何一頁教）；Google 以外的 AI 搜尋（Perplexity、ChatGPT Search）是否保留；改寫前的「品牌類型 × 入口」表與搜尋投資配比是否保留在本頁（預算部分可能屬廣告模組）。
  - E-E-A-T 在改寫前的 m5-1 與 m5-6 都出現，要決定只在 m5-6 教，或在 m5-1 先提一句。

### m5-2｜搜尋意圖：顧客搜尋時想完成什麼
- 型態：概念型（次：方法型）。理由：學員要能說明四種搜尋意圖與修飾詞線索，並用搜尋結果頁核對，判斷一個查詢該配什麼頁面。
- 學習目標草案：
  1. 能說明資訊型、導航型、商業型、交易型四種搜尋意圖的定義、例子與適合的頁型。
  2. 能判斷查詢中的修飾詞透露的意圖線索，並用同地區、同語言的搜尋結果頁（SERP）核對、修正假設。
  3. 能完成一份查詢意圖分類表，標出主要／次要意圖與證據。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態：保留／弱化／遺失 |
  |---|---|---|
  | 四種意圖：資訊型（Informational）、導航型（Navigational）、商業型（Commercial）、交易型（Transactional） | 四張卡各附「我想知道／我要去某個地方／我在比較選項／我要採取行動」與跨產業例子（什麼是 SEO、GA4 登入、Shopify vs 91APP、預約健身教練台北） | 弱化（中文名與定義保留；英文原文、心智句、非案例的日常例子遺失） |
  | 四分類是工作框架，不是 Google 唯一官方分類；同一查詢可能有多種合理解讀 | 引 Google 搜尋品質評估指南（Search Quality Evaluator Guidelines） | 弱化（說法保留，出處遺失） |
  | 先提出意圖假設，再用相同地區、語言、裝置的 SERP 核對 | 每卡都寫「先查 SERP 再決定頁型」 | 保留（現稿「判讀時用三步」） |
  | 各意圖適合頁型：資訊→教學文、影片、FAQ；導航→官方頁、商家檔案；商業→比較文、評測、選購指南，需第一手經驗與利益揭露；交易→產品頁、服務頁、Landing Page，需清楚 CTA 與信任信號 | 每卡列「最適合」頁型與內容要求 | 弱化（頁面任務保留；Landing Page、CTA、信任信號、利益揭露遺失） |
  | 導航型：非自有品牌的導航詞機會有限；品牌詞廣告要看增量轉換 | 導航卡說明 | 遺失 |
  | 意圖地圖：同一主題在四種意圖各有關鍵字、起始頁型、查詢者下一步、先驗證什麼 | 以「數位行銷課程」示範四種切角 | 弱化（改成五個查詢的分類表，沒有「同一主題四切角」的概念） |
  | 修飾詞心理學六組：推薦／最好、怎麼／如何、價格／費用、vs／比較、評價／心得（社交證明）、台北／附近／在地 | 「主關鍵字＋修飾詞＝更精準的意圖信號」，每組說明心理與適合格式 | 弱化（縮成一段；「評價／心得」社交證明型遺失；「轉換潛力」說法遺失） |
  | 意圖不確定標「待查 SERP」，混合意圖保留混合分類 | AI 分類 prompt 與合格輸出說明 | 保留（現稿改寫成「主要／次要」） |
  | 優先級判準：與本月目標直接相關、SERP 頁型相符、有能力做出完整頁面 | AI 分類 prompt 的三級星號判準 | 遺失（本頁沒有；m5-3 部分涵蓋） |
  | 術語 SERP（搜尋結果頁） | 全頁通用 | 遺失（現稿一律寫「搜尋結果頁／搜尋畫面」，沒有原文） |

- 現稿問題：
  - A 案例先上：概念段（第二節）的例子全部取自案例查詢，沒有日常例子。原句：「資訊型意圖想理解概念或解決問題，例如「手沖壺怎麼選」」「導航型意圖想前往特定品牌、網站或地點，例如「山徑咖啡」」。概念有在示範前教，程度比其他頁輕。
  - B 沒引入就使用：無。
  - C 練習等於示範：示範表已填完五個代表查詢的意圖、旅程位置、頁面任務與缺口，練習要學員再填同五列。原句：「接著把五個代表查詢全部填完，並為每列寫一句「因為……所以頁面要……」」。
  - D 判準不一致：練習要求每列寫「主要意圖、次要意圖、旅程位置、搜尋畫面證據、適合頁面與品牌可用事實」，示範表只有「主要意圖｜旅程位置｜適合頁面任務｜品牌目前缺口」，沒有次要意圖、搜尋畫面證據，也沒有示範「因為……所以……」句。判讀三步的第二步要看搜尋結果，但示範「「手沖壺推薦」偏商業型，顧客正在比較候選」沒有引用畫面（品牌包 SEARCH-02 這個查詢有購物結果）。
  - E 疑似錯誤或過時：無。
- 備註：
  - 示範與練習資料和 m5-1 共用五個代表查詢（見 m5-1 備註）。
  - 第一節引用「市場洞察時畫過的顧客旅程」的四階段，依賴前面模組；要確認該模組確實教過這四階段名稱。
  - 改寫前的修飾詞心理學是獨立一節；要負責人決定是否恢復成獨立小節或併入意圖定義。

### m5-3｜關鍵字研究：Search Console 與關鍵字地圖
- 型態：方法型（次：操作型）。理由：學員要能照一套步驟（取數據 → 篩選 → 判意圖 → 分群 → 排優先序）把查詢資料變成關鍵字地圖，有權限者在 Search Console 實際匯出。
- 學習目標草案：
  1. 能說明 Search Console 的曝光、點擊、點閱率（CTR）、平均排名代表什麼與限制，並分辨它和外部工具的搜尋量、關鍵字難度（KD）不同。
  2. 能判斷哪些查詢值得優先處理，理由要同時引用網站表現、搜尋意圖、品牌事實與頁面承接。
  3. 能完成一張主題叢集（支柱頁＋子頁）關鍵字地圖，以及產能限制下的內容組合與排除理由。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態：保留／弱化／遺失 |
  |---|---|---|
  | Search Console 成效報表四指標：曝光、點擊、CTR、平均排名 | 說明四指標是自家網站表現 | 保留（CTR 原文遺失，只寫「點閱率」） |
  | 平均排名的定義：多次曝光所對應最高位置的平均值 | 引 Google 官方指標說明 | 弱化（「多次曝光位置的平均表現」，少了「最高位置」） |
  | Search Console 是自家網站表現，不含整個市場的月搜尋量 | GSC 流程開頭說明 | 保留 |
  | GSC 操作路徑：成效 → 搜尋結果，期間 3 個月；點查詢看 Pages 分頁，確認對應網址並匯出 | 四步驟操作卡 | 遺失（現稿只寫「從 Search Console 匯出同一期間的查詢資料」） |
  | 平均排名 5–20 的練習篩選（不是通用成功公式） | 第 2 步 | 遺失 |
  | 依曝光排序；高曝光、低 CTR 是檢查候選，不能直接宣告原因 | 第 3 步 | 保留 |
  | 搜尋量與 KD（關鍵字難度）是外部工具估計值；沒有核准來源寫「待補」 | 證據欄位表與 prompt 限制 | 弱化（現稿寫「市場搜尋量或競爭程度」「第三方難度分數」，KD 術語與「待補」作法遺失） |
  | 證據四面向：網站現有機會、搜尋意圖、品牌與內容承接、外部估計（選配） | 一張「判斷面向／使用欄位／要回答的問題／缺資料時怎麼做」表 | 保留（外部估計一欄弱化） |
  | 缺品牌證據時降低優先序；交易意圖不會自動勝過資訊需求 | 證據表與聚類步驟 3 | 遺失（現稿示範反而以「缺口」作為優先理由，見 D） |
  | 不用固定機會分數；備註寫採用理由、缺少來源、下一個查證動作 | 證據表下方提示 | 保留 |
  | 主題叢集（Topic Cluster）：支柱頁（Pillar Page）整理廣主題，子頁回答具體需求，以內部連結串起 | 定義＋「數位行銷課程」叢集圖 | 弱化（現稿用「主題群集」「支柱頁或子頁」，未定義；英文原文與內部連結遺失） |
  | 產能限制下的內容組合，逐頁寫採用與排除理由 | 6 點產能的小組拍賣 | 保留（改為單人取捨三頁） |

- 現稿問題：
  - A 案例先上：四項指標還沒教就先介紹山徑咖啡 30 筆資料；指標定義段（第二節）內就直接用案例數字判讀。原句：「它含 30 筆山徑咖啡近 28 天課堂模擬查詢」「山徑咖啡的「手沖壺怎麼選」有 3,300 次曝光、79 次點擊、2.4% 點閱率、平均排名 10.6」。
  - B 沒引入就使用：
    - 「主題群集」在第一節就要學員填，第三節「關鍵字地圖」只有否定式定義。原句：「淺黃色欄位用來填搜尋意圖、主題群集、內容優先序與備註」「關鍵字地圖不是把相似字塞在同一頁，而是……」。
    - 「支柱頁」「子頁」沒有定義就要學員指定。原句：「每群要寫主要意圖、代表查詢、旅程位置、支柱頁或子頁」。
  - C 練習等於示範：練習指定的三列都已在示範出現（「手沖壺怎麼選」有完整數字分析，另兩個在示範群集表的代表查詢欄），取捨題的支柱頁也已由示範選定。原句：「先在試算表選「手沖壺怎麼選」「不鏽鋼 vs 銅 手沖壺」「手沖壺 試握」三列」「選一個支柱頁和兩個子頁」。
  - D 判準不一致：第二節的優先判準是「品牌是否有可用事實」，示範卻把缺事實當優先理由。原句：「優先處理新手升級選擇群，理由不是它的單一數字最大，而是高曝光查詢集中、與核心訊息相符，且現有三款商品頁有明確比較缺口」；同節前文又說「它值得檢查指南內容，但品牌需要補足比較方法」。
  - E 疑似錯誤或過時：無。
- 備註：
  - 示範把「手沖壺推薦」（m5-2 判為商業型）和「手沖壺怎麼選」（m5-2 判為資訊型）放在同一群，主要任務寫「建立選擇方法」；跨頁說法要對齊。
  - 本頁結尾說「下一頁會用這張地圖選定的新手升級分類頁與溪線 700 商品頁」，m5-4 實際只做溪線 700（見 m5-4 備註）。
  - 要負責人決定：是否恢復「平均排名 5–20」的練習篩選；Search Console 實際操作（有權限者）要教到多細。

### m5-4｜內容 SEO：標題、描述、標題階層與有用內容
- 型態：方法型（次：概念型）。理由：學員要能依搜尋意圖與頁面事實，照步驟改寫一頁的 Title、Meta、H1／H2 與正文，並先懂每個元素的作用。
- 學習目標草案：
  1. 能說明 Title、Meta 描述、H1／H2／H3、URL 各自的作用與常見誤區（固定字數、關鍵字密度）。
  2. 能完成一頁頁面元素（on-page）改寫，每個可發布主張都回指頁面事實，缺資料的主張排除。
  3. 能判斷結構化資料（例：FAQPage）何時適用，只標示頁面上看得到的內容。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態：保留／弱化／遺失 |
  |---|---|---|
  | On-page SEO（頁面元素優化）術語 | 頁面元素段與 prompt 使用 | 遺失（現稿頁題「內容 SEO」，正文沒有說明） |
  | Title：清楚、精簡、獨特；沒有固定字數；依裝置截斷；Google 可能改寫 title link | 元素卡 | 弱化（「獨特」、截斷、Google 改寫遺失） |
  | Meta 描述：一兩句準確、獨特的摘要；不以 150–160 字元為標準；Google 可能改用頁面內容生成摘要 | 元素卡 | 保留 |
  | H1：一個最突出的主標題，可和 Title 相近但不必相同 | 元素卡 | 保留 |
  | H2／H3：反映內容層級與讀者問題；不追關鍵字密度，不把「LSI Keywords」當排名公式 | 元素卡 | 弱化（H3、「關鍵字密度」「LSI」遺失） |
  | URL：簡短、可讀、連字號分隔；改既有 URL 要規劃重新導向 | 元素卡 | 遺失 |
  | 低效 Title 對照優化 Title 的例子 | 三組前後對照 | 遺失 |

  | 使用讀者的語言，自然帶入同義詞與相關概念 | 語意優化段 | 弱化 |
  | 結構化資料（JSON-LD、FAQPage）：只在頁面可見同一組問答時使用，不保證複合式結果 | 範本＋使用條件 | 遺失（只剩一句 FAQ 複合式結果停用） |
  | 每個主張標出 FACT 編號；缺資料寫「待品牌確認」並排除 | prompt 與示範 | 保留 |
  | 示範頁（頁面 A）與獨立練習頁（頁面 B）分開，練習不複製示範文字 | D／T／S 三階段 | 遺失 |
  | 完成驗證：Title／Meta 的承諾進站後能被 H1／H2 兌現 | 完成驗證段 | 保留 |

- 現稿問題：
  - A 案例先上：五個元件還沒教，第一節就選定溪線 700、列出商品事實與頁面任務。原句：「這一頁選溪線 700 商品頁，練習讓搜尋結果和頁面更清楚」「其中溪線 700 的已知事實是：不鏽鋼、700 ml、NT$2,380……」。
  - B 沒引入就使用：
    - 五個元件在第一節就使用，第二節才定義。原句：「接下來的 Title、Meta、H1、H2 和正文都要服務這一題。」
    - 頁題「內容 SEO」沒有定義，也沒說和技術 SEO（m5-5）、站外（m5-6）怎麼分工。
  - C 練習等於示範：示範已完整改寫溪線 700 的 Title、Meta、H1、兩個 H2 與兩段正文，練習要學員用同一頁做同一組元件。原句：「使用同一份練習資料，先自行改寫溪線 700 的 Title、Meta、H1、兩個 H2 與兩段正文。」
  - D 判準不一致：練習提醒「若每個元件都重複完整產品名，保留必要辨識詞，其餘空間用來說明頁面任務」，但示範的 Title、Meta、H1 三處都寫了「溪線 700」產品名（「溪線 700 不鏽鋼手沖壺｜……」「查看溪線 700 的……」「溪線 700 不鏽鋼手沖壺」），學員無法從示範判斷什麼算「必要辨識詞」。
  - E 疑似錯誤或過時：

    - 【改寫前】「Google 目前通常只讓知名、權威的政府與健康網站顯示 FAQ rich results」：2023 年的規則；若現稿說法正確即已過時。
- 備註：
  - 與練習資料衝突：`onpage-seo-practice-brief.md` 寫「頁面 A 是新手升級分類頁，用於老師示範；頁面 B 是溪線 700 商品頁，由學員個別完成」，現稿把頁面 B 當示範又當練習，頁面 A 只在練習段一句帶過（「再選新手升級分類頁做第二次練習，但本頁完成物只交一頁商品頁」，意思不清）。改回 brief 的 A 示範／B 練習即可解 C。
  - 跨頁不一致：本頁第一節說「上一頁的關鍵字地圖把「手沖壺 控流」「手沖壺 壺嘴 差別」「手沖壺 出水 影片」放進規格與使用比較需求」，m5-3 示範群集表的「材質與規格比較」代表查詢是「不鏽鋼 vs 銅、容量選擇、壺嘴差別」，沒有控流與出水影片。m5-3 把新手升級群排第一優先，本頁卻選溪線 700。

### m5-5｜技術 SEO：網頁體驗、索引與轉址
- 型態：方法型（次：概念型）。理由：學員要能用一套健檢項目找出技術問題，寫成工程師能重現、驗收的工單，並懂 Core Web Vitals、canonical、轉址等術語在說什麼。
- 學習目標草案：
  1. 能說明 Core Web Vitals 三項指標（LCP、INP、CLS）的意義與良好門檻，以及欄位資料和實驗室資料的差別。
  2. 能說明 HTTPS、robots.txt、XML Sitemap、canonical、301／302／404 各自處理什麼問題。
  3. 能用 Search Console 網址審查、網頁索引報表與 PageSpeed Insights 完成一張技術健檢，並把一項寫成分開「已知證據」與「影響假設」的工單。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態：保留／弱化／遺失 |
  |---|---|---|
  | Core Web Vitals（核心網頁指標）衡量真實使用者的載入、互動、視覺穩定 | 開頭定義 | 弱化（「網頁體驗」一項帶過，原文術語未給） |
  | LCP（最大內容繪製）良好 ≤ 2.5 秒；影響因素：圖片大小、伺服器回應、阻擋渲染的 JS | 指標卡 | 遺失（縮寫只出現在示範表） |
  | INP（互動到下一次繪製）良好 ≤ 200 毫秒，取代 FID；影響因素：JS 執行、主執行緒阻塞 | 指標卡 | 保留（影響因素遺失） |
  | CLS（累積版面位移）良好 ≤ 0.1；影響因素：未設尺寸圖片、動態插入廣告、字體載入 | 指標卡 | 遺失（只剩「畫面不會因元素載入突然位移」） |

  | 行動版內容索引（Google 以行動版內容建立索引）；Mobile-Friendly Test 已下線 | 六項清單 | 弱化（「行動版與內容一致」） |

  | robots.txt：控制爬取；常見錯誤 `Disallow: /` | 六項清單 | 遺失（「有沒有被登入、權限或規則擋住」） |
  | 內部連結結構與孤立頁；不套固定三次點擊門檻 | 六項清單 | 遺失 |
  | 圖片優化：srcset／sizes、WebP／AVIF、有意義的圖寫 alt、裝飾圖空 alt | 六項清單 | 弱化（「圖片有合適替代文字」） |
  | 301 永久、302 暫時（Google 通常仍以來源為 canonical）、避免 redirect chain | 狀態碼卡 | 保留（302 與 redirect chain 細節遺失） |

  | 行銷人的角色：診斷、翻譯、驗收；修改交給工程或 IT | 提示框與頁尾 | 保留 |
  | 工單格式：標題／已知證據／影響假設／重現步驟／期望結果／驗收標準，證據與假設分開 | AI prompt 與參考工單 | 保留（欄位改為重現條件、已知證據、待查原因、負責角色、驗證方式） |

- 現稿問題：
  - A 案例先上：開頭第一句就接上一頁的案例頁，第二段要零權限者用品牌包；第一、二節主體仍是概念，程度輕。原句：「上一頁完成溪線 700 商品頁文字，但內容寫好不代表搜尋系統一定能抓取……」「沒有權限者使用品牌包的頁面摘要」。
  - B 沒引入就使用：

    - 三個工具與 sitemap 第一次出現沒說是什麼、看什麼。原句：「有權限者可用 Search Console 的網址審查與網頁索引報表，再搭配 PageSpeed Insights」「內部連結與 sitemap 也使用同一網址」。
  - C 練習等於示範：零權限的學員「用上方山徑咖啡資料完成已知與未知」，就是示範表本身；交接範例也直接寫示範表「行動版任務」那一列。原句：「沒有網站權限時，用上方山徑咖啡資料完成已知與未知」「在行動版商品頁，以一般手機寬度進入後需滑動三個畫面才看到試握入口」。

  - E 疑似錯誤或過時：無。
- 備註：
  - 示範的已知問題「稜峰 600 沒有 Meta 描述」屬稜峰 600 頁，練習要學員選「上一頁改寫的商品頁」（溪線 700），兩者對象不同。

### m5-6｜站外信任：反向連結、E-E-A-T 與聲譽
- 型態：概念型（次：方法型；頁尾模組作業為整合型）。理由：學員要能說明 E-E-A-T 與反向連結品質，判斷哪些站外做法合理、哪些違反政策，再列出外部信任來源並寫接觸稿。
- 學習目標草案：
  1. 能說明 E-E-A-T 四個面向（出自 Google 搜尋品質評估指南）與各自可呈現的訊號，以及它不是可計算的單一排名分數。
  2. 能判斷反向連結的品質（主題相關、編輯理由、取得方式），辨識購買連結、連結農場、過度交換連結等違反垃圾內容政策的做法。
  3. 能完成一份外部信任來源清單與一封不要求回連的接觸稿。
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態：保留／弱化／遺失 |
  |---|---|---|
  | E-E-A-T 四維度：Experience（經驗）、Expertise（專業）、Authoritativeness（權威）、Trustworthiness（可信），出自 Google 搜尋品質評估指南 | 四張字母卡 | 弱化（四個中文詞保留；英文全稱與出處遺失） |
  | 各維度可呈現的訊號：親測日期與情境、真實照片；具名作者與資歷、引用可信來源；他站引用與媒體報導；HTTPS、聯絡資訊、關於頁、隱私政策 | 每卡四項 | 弱化（現稿只舉山徑咖啡可做的幾項，未對應到四個維度） |
  | YMYL（Your Money or Your Life）內容要求最嚴 | 開頭說明 | 遺失 |
  | 反向連結品質勝過數量；一個相關行業媒體連結勝過大量低品質目錄 | 連結建立開頭 | 保留 |
  | 先做值得被連結的內容（資源型內容：統計整理、工具清單） | 策略卡 | 保留 |
  | 連結建立策略：客座文章、媒體露出、合作夥伴、監控品牌的「未連結提及」 | 五張策略卡 | 遺失（現稿改成四種來源類型；只保留合作夥伴，客座文章、媒體露出、未連結提及遺失） |
  | 避免購買連結、連結農場、交換連結計畫 | 警示框 | 保留（現稿改引 Google 垃圾內容政策） |
  | 社群讚數與分享不是直接排名因素；社群擴散 → 曝光 → 自然連結 | Social × SEO 段 | 遺失 |
  | 接觸信寫法：指出對方的相關文章、說明能提供的價值、讓對方決定 | Outreach Email 範本 | 保留 |
  | 驗收候選網站：真實存在、主題相關、聯絡方式與投稿規則有效；DR 與回信率沒有來源只能標待查 | 參考規劃後的驗收說明 | 保留 |
  | DA／DR（第三方網域評分）術語 | 客座文章卡 | 弱化（現稿說「不使用第三方網域分數」，但沒說它是什麼、限制在哪） |
  | 黑帽 PBN（私人部落格網路） | 避雷區 | 遺失 |

- 現稿問題：
  - A 案例先上：E-E-A-T 只給一句定義，同段就進山徑咖啡；第二節「先做值得被引用的內容」整節都是案例，概念段沒有日常例子。原句：「山徑咖啡要建立信任，可以呈現同一條件的器具比較過程、具名內容負責人……」「山徑咖啡目前最有潛力的資產不是泛泛的「手沖壺推薦」……」。
  - B 沒引入就使用：
    - E-E-A-T 沒說出處，四個面向各自是什麼也沒定義。原句：「E-E-A-T 可用經驗、專業、權威與可信四個面向檢查內容……」。
