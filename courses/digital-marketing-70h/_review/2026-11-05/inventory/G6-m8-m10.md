### m8-1｜該不該投、投哪種：付費流量與預算
- 型態：方法型（次：概念型）。理由：學員要能用一套判斷步驟決定投不投、投哪種、預算上限多少，同時要認得付費與自然流量的分工和廣告指標。
- 學習目標草案：
  - 能說明付費流量與自然流量各自的特性與互補關係
  - 能說明 CTR、CPC、CPL、CVR、ROAS 的公式，並判斷單看其中一個數字為什麼會誤判
  - 能完成一張投放決策（投不投、活動類型、預算上限、停止條件）
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 付費 vs 自然流量互補 | 兩欄對照：付費停投就停、可測試、適合新品／活動／競品字；自然流量累積慢、可持續、適合品牌資產與長尾 | 遺失（只剩「廣告是加速器」一句） |
  | 策略判斷依據 | 先看旅程缺口、時效、可用素材、量測與單位經濟，品牌階段不能單獨決定渠道 | 弱化（改成投放前四題，單位經濟只在示範裡提到缺毛利） |
  | 廣告漏斗：Google Ads 與 Meta Ads 在認知／考慮／轉換／留存的常見角色 | 一張四階段 × 兩平台的任務地圖，註明要依帳號數據調整 | 遺失（改成只講 Google 的搜尋／PMax／Demand Gen，Meta 不出現） |
  | 依品牌階段配置預算 | 新創／成長／成熟／促銷四期，各寫配置原則與配置前要有的證據 | 遺失 |
  | 廣告 KPI 定義：CTR、CPC、CPL、CVR、ROAS、Impression Share | 每項寫公式與判讀限制（如低 CPC 可能是低品質流量、ROAS 要回到毛利） | 遺失（全課都沒有，見檔頭） |
  | 測試預算＋唯一變因＋停止條件 | 第一輪只改一個變因，並寫預算上限與停止條件 | 保留 |
  | 缺資料時不給精確比例 | 缺毛利、CPA、事件驗證時，列 50/30/10/10 是假精準 | 保留（「不自行拆出百分比」） |

- 現稿問題：
  - A 案例先上：第一個 `##` 第二段就是「第一次使用山徑咖啡資料時，先打開[山徑咖啡品牌包]……用下表辨認資料與用途。」付費 vs 自然、KPI 都還沒教。
  - B 沒引入就使用：「接著把活動類型當成任務選擇，不把它們排成誰比較高級。」沒說「活動類型」是 Google Ads 的什麼、為什麼只比 Google。另「Performance Max……不能再簡化成完全無法觀察的黑盒子」是在反駁一個頁面沒介紹過的說法。
  - C 練習等於示範：「先用山徑咖啡練一次，做出下列內容」，對照答案「山徑咖啡的合理起點是搜尋活動草稿……」就是示範第三節的結論。
  - D 判準不一致：練習第 3 步要求寫出「第一輪核准額度」，示範只寫「先由負責人核准一筆可承受的第一輪測試額度」，沒有示範這個額度怎麼定，品牌包也沒有能算出額度的資料。
  - E 疑似錯誤或過時：現稿無。改寫前頁面把 CPL 寫成「每次獲客成本」，CPL 是每筆名單（lead）成本，「獲客」比較接近 CPA／CAC；恢復時要改譯名。
- 備註：KPI 定義要放在 m8-1 還是另開一節，請負責人決定（M6 GA4、M7 追蹤現稿也沒有教 CTR／CVR）。Google vs Meta 的分工表在現稿沒有落點，m8-4 也只講 Meta 本身，兩平台怎麼分工全模組沒有一處交代。

### m8-2｜廣告文案心理學：AIDA、PAS、BAB 與單一變因測試
- 型態：方法型。理由：學員要能用三種文案公式寫出候選，並設計只改一個變因的測試。
- 學習目標草案：
  - 能說明 AIDA、PAS、BAB 各自的順序與適用情境
  - 能把社群 Hook 改寫成付費廣告候選，並標出漏斗階段、版位與主要指標
  - 能完成兩版只差一個變因的文案與測試假設
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | AIDA（Attention・Interest・Desire・Action） | 四步定義加適用情境 | 保留（英文全名沒有寫出） |
  | PAS（Problem・Agitate・Solution） | 三步定義，不為加強語氣補寫恐懼 | 保留 |
  | BAB（Before・After・Bridge） | 三步定義，希望狀態不能寫成保證 | 保留 |
  | 公式只是排列順序，不能預測成效 | 公式名稱本身不能預測成效，要用測試比較 | 保留 |
  | 五種 Hook（問句、數字、差異、清單、認同）從 M4 自然內容改成付費測試 | 每種附山徑咖啡例句與來源限制 | 遺失 |
  | 每版標漏斗階段、版位、主要 KPI、唯一變因 | 少一項就還不是可測試的廣告 | 弱化（只剩不變項、假設、主要指標，漏斗階段與版位不見了） |
  | 廣告視覺原則（標題文字、主視覺、色彩、比例、文字覆蓋率、安全區） | 一張原則／常見錯誤表，註明沒有通用的 20% 文字合格線 | 遺失 |
  | 單一變因 A/B | 受眾、優惠、版位、量測都一致，只改一個變因 | 保留 |

- 現稿問題：
  - A 案例先上：第一個 `##` 第二段：「第一次使用本頁資料時，先打開[山徑咖啡品牌包]。」接著是品牌包資料表，三種公式排在這之後。
  - B 沒引入就使用：練習第 4 步「寫一句測試假設、主要指標、護欄指標與停止條件」，「護欄指標」在本頁第一次出現就直接要求填寫，前面沒有定義。
  - C 練習等於示範：「先用山徑咖啡做出下列內容」，對照答案是「示範保留同一內文、圖片與 CTA，只比較『規格難比較』和『先試再選』兩個主標題切角」，與示範完全相同。
  - D 判準不一致：練習第 1 步要「選 AIDA、PAS 或 BAB 寫一版完整文案，標出每一段的功能」，示範的 A／B 兩版只有主標題加一句內文，沒有用任何公式，也沒有標段落功能；示範沒有做到練習要求的那一步。
  - E 疑似錯誤或過時：無。
- 備註：五種 Hook 依賴 M4（m4-1 現稿是否還有 Hook 分類，要跨頁確認）。

### m8-3｜Google 搜尋廣告：帳戶結構、品質分數與 AI Max
- 型態：操作型（次：概念型）。理由：學員要能在 Google Ads 建立一個結構正確的搜尋活動草稿，也要懂帳戶結構、比對類型與品質分數。
- 學習目標草案：
  - 能說明 Google Ads 四層帳戶結構與每層的設定
  - 能判斷廣泛、詞組、完全比對的差異，並為關鍵字選比對類型
  - 能在 Google Ads 建立含兩個意圖廣告群組的搜尋活動草稿
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 四層帳戶結構（帳戶／廣告活動／廣告群組／廣告） | 每層各自設定什麼（付款時區、目標預算地區、關鍵字主題、RSA） | 弱化（只有「活動層級」與「廣告群組」的欄位，沒有四層定義） |
  | 廣告群組依共同搜尋意圖與落地頁分組 | 不把「一字一群組」當普遍答案 | 保留 |
  | RSA（回應式搜尋廣告）最多 15 標題、4 說明 | 每項要不同、正確、能對應落地頁 | 遺失（只剩名稱） |
  | 三種比對類型與語法（數位行銷課程／"…"／[…]） | 表列語法範例與觸發條件 | 弱化（各一句，沒有語法） |
  | 排除關鍵字＋搜尋字詞報表 | 定期查報表，把不相關詞加入排除 | 保留 |
  | Ad Rank 的組成 | 出價、即時品質、門檻、競爭、搜尋情境、素材預期影響 | 遺失 |
  | 品質分數 1～10 與三組成（預期點閱率、廣告關聯性、落地頁體驗） | 每個組成各有說明 | 弱化（只列名稱，沒有逐項說明） |
  | 出價策略四種（手動 CPC、tCPA、tROAS、最大化點擊） | 各寫適用情境與注意事項，不套固定 30／50 次門檻 | 弱化（只剩 tCPA、tROAS） |
  | AI Max for Search 組成與啟用前檢查 | 搜尋字詞比對、文字自訂、最終網址擴展；先確認轉換與品牌控制 | 保留 |
  | Pin 與顯示路徑的使用時機 | Pin 只在法規、必要品牌訊息或實驗需要時用 | 遺失 |

- 現稿問題：
  - A 案例先上：第一個 `##` 第二段「第一次使用資料時，打開[山徑咖啡品牌包]」加資料表，帳戶結構與比對類型排在之後。
  - B 沒引入就使用：「帳戶結構不是整理資料夾，而是讓每一組搜尋意圖看到相符的廣告」——四層結構沒有定義就說它不是什麼。「將上一頁的文案放入回應式搜尋廣告」——RSA 沒有介紹。「動態搜尋廣告預計 2027 年 2 月起自動升級」——動態搜尋廣告第一次出現就講升級。
  - C 練習等於示範：「先完成自己的版本，再對照：示範用『比較』與『門市試握』兩個意圖群組……」，練習與示範是同一個活動、同一組關鍵字。
  - D 判準不一致：完成清單要求「每個關鍵字有比對類型」，示範只列關鍵字，沒有指定任何比對類型（品牌包 AD-02 的比對類型欄是「學員填寫」，示範也沒填）。示範說要填「出價方向」，但沒有寫選了哪一種。
  - E 疑似錯誤或過時：無。
- 備註：AI Max「2026 年 4 月起脫離 Beta」「動態搜尋廣告 2027 年 2 月自動升級」都是有日期的平台公告，開課前要重查。

### m8-4｜Meta 廣告：高效速成+、受眾與再行銷
- 型態：方法型（次：操作型）。理由：學員要能定義受眾的進入與排除條件、設計一次只問一個問題的測試，再到廣告管理員設定出來。
- 學習目標草案：
  - 能用冷／暖／熱規劃受眾，寫出每群的資料來源、進入與排除條件
  - 能設計再行銷的進入事件、視窗與退出條件
  - 能設計只改一個變因的 Meta 廣告測試，並在廣告管理員建立草稿
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 冷／暖／熱是規劃標籤，不是平台架構 | 每層寫資料來源、進入、排除與素材 | 保留 |
  | Meta Pixel／Conversions API 事件來源 | 熱受眾要先確認事件真的收到 | 遺失 |
  | 同意與合法使用依據 | 網站受眾、顧客名單上傳都要先確認 | 保留（「不具追蹤同意資格者要排除」） |
  | 再行銷四情境（網站訪客視窗、瀏覽未購、加購未結帳、現有顧客） | 每種寫進入事件、排除條件與可用訊息 | 弱化（只剩「開啟比較表或開始預約但未完成」一種） |
  | 頻率控制 | 再行銷要控制頻率、排除已完成者 | 遺失（只保留排除） |
  | A/B 測試五個維度（素材、受眾、文案、落地頁、期間） | 每個維度寫要固定什麼、只比什麼 | 弱化（只示範受眾測試） |
  | 測試期間與樣本量要預先估算 | 不以固定 7 天或 50 次轉換宣稱統計成立 | 遺失 |
  | Advantage+ 自動化不用帳戶新舊判斷 | 先鎖目標與排除，再用 A/B 比較自動化與控制組 | 保留 |
  | 不以 CTR 單獨決勝 | 看合格轉換的數量與成本 | 保留 |

- 現稿問題：
  - A 案例先上：第一個 `##` 第二段「第一次使用資料時，打開[山徑咖啡品牌包]」加資料表，之後才定義冷暖熱。
  - B 沒引入就使用：「高效速成+（Advantage+）已整併為銷售、應用程式與潛在顧客活動。官方開發者文件以三個槓桿判定：受眾、活動層級預算與版位……」——活動目標、「槓桿」、「活動層級預算」都沒介紹就拿來判定。
  - C 練習等於示範：無。模組作業用各組主題產品。（「在廣告管理員完成設定表」一節沒寫用哪份資料，見備註。）
  - D 判準不一致：頁面說要受眾、活動層級預算與版位三項都自動化才屬於高效速成+；示範的實驗組卻是「使用高效速成+受眾或較廣泛設定」，同時兩組「固定同一素材、文案、版位策略、預算限制」，照頁面自己的定義，這不是高效速成+。
  - E 疑似錯誤或過時：「高效速成+」是否為 Meta 台灣介面的正式譯名，看起來有疑問（改寫前頁面一律寫 Advantage+），需要對照介面確認。
- 備註：「在廣告管理員完成設定表」一節沒說學員要用山徑咖啡還是自己的產品；接在山徑咖啡示範後面，學員應該會照抄示範。模組作業的小組形式依使用者指定沿用。

### m9-1｜第一方數據：自己的名單與同意
- 型態：概念型（次：方法型）。理由：學員要能說明第一、二、三方資料的控制與同意差異，並用它盤點名單來源。
- 學習目標草案：
  - 能說明第一方、第二方、第三方資料的差異，以及瀏覽器政策變化對量測的影響
  - 能比較 Email 名單與社群受眾在控制、可攜、同意與維護成本上的差異
  - 能完成一份名單來源盤點，分清楚資料存在與使用授權
- 保留清單：

  | 項目 | 改寫前怎麼教（一句） | 現稿狀態 |
  |---|---|---|
  | 第一／二／三方數據的定義與控制差異 | 三張卡各寫來源與控制程度，第一方也要遵守告知與同意 | 保留 |
  | Chrome 第三方 Cookie 政策更新 | 2025 年維持使用者選擇，不能再用「即將全面停用」當理由 | 保留（另補 Privacy Sandbox 退場） |
  | Mail Privacy Protection 讓開信率失真 | 第一方資料重要的理由之一 | 保留（移到 m9-2） |
  | Email 名單 vs 社群受眾（可攜、意圖訊號、直接渠道成本、可量化的個人化） | 四點說明，並註明名單不保證送達或轉換 | 遺失 |
  | 名單建立五入口（網站表單、Lead Magnet、社群、廣告／Lead Ads、活動） | 表列方法與優缺點 | 遺失 |
  | Email 工具篩選（Mailchimp、Brevo、Kit、Klaviyo） | 依需求篩選，方案以開課日官方資料為準 | 遺失 |
  | 最少必要欄位、來源標籤、保留／刪除 | 只蒐集交付與後續溝通必要的欄位 | 保留 |
  | 名單規模不是唯一目標 | 能證明來源、同意、互動才是可維護資產 | 保留 |

- 現稿問題：
  - A 案例先上：第一個 `##` 第二段「第一次使用資料時，打開[山徑咖啡品牌包]」，接著是 1,180／420／650 的名單表，第一方數據的定義排在第二節。
