單元 7-3

自訂事件：按鈕、表單與捲動

把預覽中看見的網站訊號送進 GA4，留下設定、正反例與收件證據。

學習目標
能判斷按鈕、表單、捲動、外部連結的追蹤該用資料層事件、穩定的元素屬性，還是沿用加強型評估
能先對照 GA4 建議事件與命名規則，再替自訂事件命名
能在 GTM 建立資料層變數、自訂事件觸發條件與 GA4 事件代碼，用正反例驗證，並在 GA4 確認收到、標記關鍵事件與註冊參數
本節完成物
GA4 事件代碼設定與收件紀錄（三個預約事件示範、`line_join` 練習）
01

先判斷現有事件是否已經回答量測問題

山徑咖啡練習頁已推送四個資料層事件，但 GA4 還沒收到。本節要接上變數、觸發條件與事件代碼，再把預覽及 DebugView 結果補回紀錄。

自訂事件是為特定業務行為自行命名與設定的事件。建立前先查加強型評估已收的 page_view、約 90% 的 scroll、外連 click（含 link_url、link_domain）、file_download、form_start、form_submit。加強型評估事件（2026-11 查證）。現有事件已能回答問題就沿用，避免重複送出。

完成時要有正反例、DebugView、關鍵事件與自訂維度證據。

02

互動訊號與事件名稱都要先選對

設定前先找最接近業務結果的訊號，因為點到元素、嘗試送表單與真正成功意義不同：

  • 按鈕：優先用成功時推送的資料層事件；其次用穩定的點擊 ID 或 Class 搭配「點擊－所有元素」，不單靠易變的文字。
  • 表單：「表單提交」中的「等待代碼」讓代碼先執行，「檢查驗證」只處理通過瀏覽器驗證的提交，也可用表單 ID 限定。表單提交觸發條件（2026-11 查證）。AJAX 或客製表單由成功回呼推送資料層事件；成功後必定進入唯一感謝頁時才用網址，並測重新整理是否重複。
  • 捲動：可用垂直百分比或像素；每個門檻每頁觸發一次，載入時已可見便會觸發。「捲動深度門檻」可作為 scroll_depth_threshold 的值。捲動深度觸發條件（2026-11 查證）。門檻要對應問題且避開既有約 90% scroll。
  • 外部連結：先查加強型評估的 click，現有參數不足時才補設定。

命名先查 GA4 建議事件（recommended events），如 generate_lead、purchase、begin_checkout；有對應就沿用名稱與規定參數。GA4 建議事件（2026-11 查證）。自訂名稱以字母開頭，只用英文字母、數字、底線並避開保留名稱；大小寫視為不同。事件命名規則（2026-11 查證）。Booking Complete 應寫成 booking_complete；既有 form_submit 能表達時先確認新增是否必要。案例沿用品牌包名稱，自己的產品先查建議事件。

03

用 comparison_open 完整建立一組事件設定

第一組示範走完九步，後兩個事件只補差異。打開山徑咖啡預約練習頁、山徑咖啡品牌包第 11 節與預覽紀錄；畫面以實際為準。

  1. 重設：重新整理，確認 GTM- 容器 ID；按 GTM「預覽」連上 Tag Assistant，再按「接受全部」。每次重新整理都會回到同意預設拒絕。
  2. 變數：到「變數 → 使用者定義的變數 → 新增 → 資料層變數」，建立 page_type、product_count；名稱逐字等於鍵值。
  3. 觸發：到「觸發條件 → 新增 → 自訂事件」，填 comparison_open，不勾規則運算式（regex）。.* 會納入系統事件；2026-10-08 起 config 指令也會成為 gtag.config，萬用條件可能誤觸發。Google 代碼事件變更（2026-11 查證）。
  4. 代碼：到「代碼 → 新增 → Google Analytics：GA4 事件」，選 Google 代碼或填 G- 評估 ID；事件名稱填 comparison_open，參數逐列選兩個資料層變數。
  5. 預覽：展開比較表應觸發一次；記下監看序號後收合，序號與觸發次數都不增加。
  6. 收件：到 GA4「管理 → 資料顯示 → DebugView」確認事件與參數，再看即時報表。沒收到就記「待排查」。
  7. 關鍵事件：comparison_open 不標記；做到 booking_complete 時，在「管理 → 資料顯示 → 事件」按星號。需編輯者權限，事件要先出現在清單，標準報表最多 24 小時反映。標記關鍵事件（2026-11 查證）。
  8. 自訂維度：做到 booking_complete 時，進「管理 → 資料顯示 → 自訂定義 → 自訂維度 → 建立」，範圍選「事件」，參數填 preferred_slot。自訂維度（custom dimension）讓參數成為報表維度；約 24～48 小時可用，一般資源上限 50 個。建立自訂維度、配額（2026-11 查證）。
  9. 保留草案：正例、反例與同意情境通過後，才由有發布權限的人發布。

booking_start 改讀 form_id、page_type；測姓名欄首次焦點，並反測先點 Email、同次切換欄位。booking_complete 改讀 form_id、preferred_slot；測完整送出與缺欄位送出，收件後標關鍵事件並註冊 preferred_slot。三列 GA4 欄都改填實際 DebugView 結果。

04

用三層證據驗收，並用長內容測捲動門檻

驗收要同時證明網站推送、GTM 觸發與 GA4 收件。每列記事件、觸發條件、資料層變數、事件代碼、正反例、DebugView、關鍵事件、自訂維度、測試時間、容器 ID 後四碼與截圖。通過標準是「正例一次＋反例未觸發＋DebugView 事件與參數正確」。

變數空白先查鍵值；複製後事件錯誤查名稱與大小寫；其他事件也觸發查 regex；DebugView 空白查「接受全部」、Connected、G- ID 與內部流量。參數未註冊仍可能在 DebugView 出現，只是尚非報表維度。

捲動測試用練習頁的長內容區。建立垂直 25% 觸發條件，套到講師指定、只留在工作區的測試代碼，啟用「捲動深度門檻」變數。頁首約可見全頁 23%，此時不觸發；捲過 25% 應觸發一次，繼續捲動不重複。若載入即觸發，記錄視窗環境並提高門檻。長內容本身不推送事件，可分辨資料層與捲動觸發。

05

用 line_join 獨立完成設定與收件紀錄

個人練習把流程用在 line_join，從規格追到 GA4 收件。先重新整理、確認容器 ID、連上預覽並按「接受全部」：

  1. 建立 placement、page_type 資料層變數，自訂事件觸發條件與 GA4 事件代碼。
  2. 做正例與反例，在 Tag Assistant 核對觸發次數，並到 DebugView 確認事件與參數。
  3. 到 GA4 事件管理把 line_join 標為關鍵事件，再把 placement 註冊成事件範圍自訂維度。
  4. 依示範欄位補完紀錄；事件尚未出現在管理清單時，記下複核時間與證據層級。
做完再展開：參考方向

正例證明按鈕互動只觸發一次，反例證明只到達該區塊不觸發；網站、Tag Assistant、DebugView 分欄記錄，另記關鍵事件與自訂維度狀態。

06

用 AI 加速：只找規格與紀錄不一致

學員先完成設定、預覽與收件判讀，再讓 AI 對照紀錄。結果由學員先讀，AI 只回答「我漏看了什麼」。

提示詞
對照這份追蹤規格與驗證紀錄，列出最多三個不一致處。 逐項核對事件名稱、觸發條件、變數來源、參數、正例、反例、觸發次數、DebugView 收件、關鍵事件與自訂維度；只引用提供內容，缺資料就指出要補的證據。 最後只回答：我漏看了什麼。 [貼上 line_join 追蹤規格與驗證紀錄全文]
07

延伸設定：排除內部流量並連結 Search Console

收件穩定後再處理基礎設定。排除內部流量可避免辦公室與測試操作灌高數字：到「管理 → 資料串流 → 網頁串流 → 設定代碼 → 定義內部流量」建規則，再到「資料收集和修改 → 資料篩選器」先測試；設為有效後會永久影響後續資料。排除內部流量（2026-11 查證）。

Search Console 連結會加入自然搜尋查詢與到達頁面資料。到「管理 → 產品連結 → Search Console 連結」選資源與網頁串流；操作者須有 GA4 編輯者權限，也是 Search Console 已驗證擁有者。連結 Search Console（2026-11 查證）。缺權限就記負責人與待處理項目。
