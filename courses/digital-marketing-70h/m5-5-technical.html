技術 SEO：網頁體驗、索引與轉址

用證據分清楚搜尋存取、頁面體驗與內容問題，再交成可驗收的工單。

學習目標
能說明核心網頁指標（Core Web Vitals）LCP、INP、CLS 的意義與良好門檻，以及欄位資料和實驗室資料的差別
能說明 HTTPS、robots.txt、XML Sitemap、canonical、301／302／404 各自處理什麼問題
能用免權限工具與（有權限時）Search Console 完成一張六項技術健檢，並把一項問題寫成分開「已知證據」與「影響假設」的交接工單
本節完成物
一張六項技術健檢清單與一張交接工單
01

技術 SEO 先確認頁面能被找到與使用

技術 SEO 要確認搜尋引擎能否抓取、索引及選對頁面，讀者在手機上能否完成任務。Google 搜尋分成檢索（crawling）、建立索引（indexing）與提供結果（serving）；檢索是下載頁面，索引是分析並儲存內容，最後才依查詢呈現。Google 不保證每頁都會進入各階段，也不接受付費提高自然排名。Google 搜尋運作方式（2026-11 查證）。

行銷人負責診斷、翻譯與驗收：把工具畫面轉成證據，指出受影響的任務，再交給網站管理者或工程師修改。成果是六項健檢與一張可重現工單。

02

六項健檢各自處理不同技術風險

第一項是存取與安全。HTTPS 表示瀏覽器與網站之間使用加密連線，需確認憑證有效且 HTTP 會轉到 HTTPS。robots.txt 管理搜尋爬蟲可檢索的路徑；它不是排除索引的方法，若要阻止索引要用 noindex。常見事故是規則誤擋重要頁。Google robots.txt 說明（2026-11 查證）。

第二項是索引。有權限時，網址審查（URL Inspection）可看索引狀態、上次檢索、即時測試及兩種 canonical；網頁索引報表則列已索引、未索引數量與原因。是否有問題要回到頁面用途判斷。網址審查說明與網頁索引報表（2026-11 查證）。

第三項是代表網址。canonical 是重複或相似頁面的偏好版本；訊號強度依序為轉址、rel="canonical"、XML Sitemap。Sitemap 幫助發現網址，但不保證檢索或索引；重要頁至少要有一個站內連結。canonical 指南與Sitemap 指南（2026-11 查證）。

第四項是轉址與錯誤頁。301／308 是永久搬移，目的地會成為代表網址；302／307 是暫時搬移，原網址可能保留。沒有替代頁時回傳 404 或 410，有對應新頁才用 301。軟 404（soft 404）是畫面說找不到，伺服器卻回 200。轉址指南與錯誤排查（2026-11 查證）。

第五項是行動版。行動版內容索引（mobile-first indexing）表示 Google 依行動版內容建立索引與排名，手機與桌機要有相同主要內容。Google 行動版指南（2026-11 查證）。已下線的相容性測試改以實際手機、Lighthouse 與網址審查取代。

第六項是網頁體驗與圖片。檢查載入、互動、版面穩定及主要內容。有資訊的圖片用替代文字（alt）描述用途；srcset 搭配 src，可用 WebP 或 AVIF。Google 圖片指南（2026-11 查證）。Meta 缺漏轉交內容負責人。

03

三項核心網頁指標要分清資料來源

核心網頁指標（Core Web Vitals）用三項資料描述體驗。LCP（Largest Contentful Paint，最大內容繪製）看載入，良好是 2.5 秒內；常見原因有慢伺服器、大圖與阻擋繪製的資源。INP（Interaction to Next Paint，互動到下一次繪製）看互動回應，良好是 200 毫秒內；它在 2024-03-12 取代 FID，主執行緒長工作常造成延遲。CLS（Cumulative Layout Shift，累積版面配置位移）看視覺穩定，良好是 0.1 以下；媒體未設尺寸、上方插入內容與字型都可能造成位移。判定看第 75 百分位，行動版與桌機版分開。web.dev 指標說明與INP 更新（2026-11 查證）。

PageSpeed Insights 的欄位資料來自前 28 天真實使用者；網址樣本不足時改顯示整個來源，再不足便沒有資料。實驗室資料是一次模擬，兩者可能不同。Search Console 依網址群組看趨勢；Lighthouse 或 DevTools 用來重現與除錯。PageSpeed Insights 說明（2026-11 查證）。Google 沒有單一網頁體驗分數，達標也不保證排名。網頁體驗指南（2026-11 查證）。

健檢方法是：選頁面與使用者任務；逐項記錄證據並判為正常、問題或未知；先處理會阻止存取或索引、再處理阻礙核心任務的項目；挑一項寫工單；最後訂出修正後驗證方式。工單欄位是標題、已知證據、影響假設、重現步驟、期望結果、驗收標準，證據與推論要分開。

04

山徑咖啡兩頁技術健檢示範

示範使用SEO 技術健檢與站外信任練習資料中的分類頁與溪線 700 商品頁。每列都填相同八欄：健檢項目、方法與工具、已知證據、判斷、未知時索取資料、影響的使用者任務、建議處理者、驗證方式。

  1. 存取與安全：用網址列與 robots.txt；兩頁皆為 HTTPS，但規則寫 Disallow: /products/riverline-700；判為商品頁檢索問題；向網站管理者確認封鎖目的；影響搜尋者找到商品頁；由網站管理者處理；修改後重讀檔案並做即時測試。
  2. 索引：用網址審查與索引報表；分類頁已索引，商品頁未索引，且報表有 3 個 canonical 不一致網址；商品頁判為問題，具體原因仍待查；向網站管理者索取即時測試；影響商品頁出現在搜尋結果；修正後重新送出檢索並追蹤狀態。
  3. 代表網址：看兩種 canonical；商品頁宣告自己，Google 卻選分類頁；判為問題；Sitemap 與內部連結狀態未知；向工程師索取設定；影響單一商品版本的辨認；部署後核對原始碼、內部連結與網址審查。
  4. 轉址與錯誤頁：用狀態碼；舊分類網址永久搬移卻回 302，舊商品回 301 到首頁；兩列皆需確認用途；向內容負責人確認是否有對應替代頁；影響舊連結抵達正確內容；由工程師處理；以相同舊網址重測目的地與狀態碼。
  5. 行動版：用手機操作；商品頁平均滑動三個畫面才看見預約入口；判為核心任務受阻；向內容與網站負責人確認版面限制；影響預約試握；調整後以同裝置重跑。
  6. 網頁體驗與圖片：用 PageSpeed Insights；分類頁來源層級 LCP 2.3 秒，但實驗室 LCP 3.8 秒且最大元素是首屏合照；商品頁欄位資料達良好門檻，實驗室 CLS 0.18；判為需重現，圖片 alt 與尺寸設定未知；向工程師索取頁面設定；影響看見主要內容；以相同網址、裝置與工具重測並檢查畫面。

分類頁缺 Meta 描述另轉交內容負責人。示範工單如下：標題「商品頁遭 robots.txt 封鎖檢索」；已知證據為 2026-11-05 行動版紀錄及檔案中的封鎖路徑；影響假設為搜尋程式可能無法重新抓取商品內容；重現步驟是開啟檔案並對照商品路徑；期望結果是重要商品頁可被檢索；驗收標準是規則移除後，以即時測試確認允許檢索。工單不估排名損失或工時。

05

實跑一個公開頁面的六項健檢

練習自選一個不需登入的公開頁面，建議使用小組主題產品官網的一頁。課堂紀錄只寫網站類型與頁面類型，不寫真實網站名稱；實跑工具時仍以實際網址測試。完成與示範相同的八欄，並從問題列挑一項寫同樣六欄的工單。

實作順序：跑 PageSpeed Insights 行動版；開啟「網域/robots.txt」；檢視原始碼找 canonical；看網址列是否為 HTTPS；用手機核對主要內容與行動呼籲；最後處理索引欄。有權限者加做網址審查；無權限者寫「未知，需網站管理者用網址審查提供」。講師先確認工具當天可用。

先完成判斷與工單，再展開參考段落。

做完再展開：參考方向

欄位資料與實驗室資料不一致時，分開記錄，不把單次模擬直接當成真實使用者現況。無權限的索引狀態標未知，並寫清楚要向網站管理者索取網址審查的哪個欄位。優先序先看存取與索引，再看是否阻礙頁面的核心任務。

完成後保留測試日期、裝置與工具，下一節會把可存取的頁面接到外部信任判斷。

06

用 AI 加速：檢查工單中的推論

完成健檢表與工單後，把表格及 PageSpeed Insights 畫面文字貼入新對話；數值由你回報表確認。

提示詞
改寫這張技術工單，讓已知證據、影響假設、重現步驟、期望結果與驗收標準彼此分開。 列出最多 3 處沒有證據支持的影響推論，不估排名、流量、工時或投資報酬。 [貼上六項健檢表、工單與 PageSpeed Insights 畫面文字]
