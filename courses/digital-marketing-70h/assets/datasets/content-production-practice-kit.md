# M2C 內容產製共同練習包

> 版本：2026-10-24-v1
> 用途：提供 M2C-2 視覺 Prompt 與 M2C-3 字幕／內容再利用的共同輸入。
> 資料聲明：品牌、人物、活動與逐字稿都是課堂模擬資料。離線完成只代表規格或校對通過，不代表已在任何 AI 工具生成、轉錄或發布。

## Part 1｜視覺任務 brief

山徑咖啡要為 Instagram 製作一張 4:5 的「門市試握手沖壺」概念圖。目標受眾是已經使用入門壺、想升級但擔心重量與控流不適合的人。圖片的任務是讓受眾理解可以先到門市試握，不負責直接成交。

### 必須保留的品牌條件

| 欄位 | 課堂資料 |
|---|---|
| 主體 | 一雙手拿著黃銅色細口壺，旁邊有米白陶瓷濾杯 |
| 場景 | 風化橡木吧台、左側清晨自然光 |
| 色彩 | 陶土紅、深棕、奶油色；低飽和暖色調 |
| 氛圍 | 安靜、耐心、可親近，不做奢華精品感 |
| 構圖 | 4:5 直式；右上保留約三分之一留白，供後製文字使用 |
| 排除 | 不在生成圖中放 logo、價格、活動日期或可辨識真人臉孔；不得出現受保護角色或其他品牌商標 |
| 後製文字 | 「先試握，再決定下一把壺。」文字只在設計工具中人工排版，不要求生成模型繪製 |

### M2C-2 正式產物

建立 `visual-prompt-card.md`，內容要包含：

```markdown
# Visual Prompt Card
- 版本／日期：
- 任務與版位：
- 使用的課堂 brief：Part 1
- 主體／場景：
- 色彩／光線／材質／氛圍：
- 構圖與留白：
- 排除元素：
- 完整 prompt：
- 工具、版本與執行日期：未執行／實際紀錄
- 候選 A／B 比較：構圖、品牌一致性、文字風險、權利與來源
- 採用／退回理由：
- 狀態：PROMPT REVIEW PASS／GENERATED ASSET REVIEWED
```

沒有生圖工具時，完成 brief 轉譯、prompt、來源紀錄與頁面 A／B 示例的比較，狀態只能寫 `PROMPT REVIEW PASS`。真的執行工具時，至少保留兩張候選的編號或連結，逐項完成權利、人物、文字與品牌審查後，才可寫 `GENERATED ASSET REVIEWED`；這個狀態仍不等於已核准發布。

## Part 2｜短影音來源與字幕校對

### 2A. 30 秒來源口白

```text
挑手沖壺，不要只看材質。先想想你現在最常卡在哪裡：是水流忽大忽小，還是壺拿久了手腕容易痠？山徑咖啡門市有三款手沖壺，可以預約二十分鐘試握和注水。先比較重量與控流，再決定哪一把適合你的沖煮習慣。想試試看，請到門市體驗頁預約。
```

### 2B. 帶錯字幕草稿

這是課堂刻意製作的錯誤版本，不是 CapCut 或 Whisper 的真實輸出。請對照 2A 修正用字、斷句與時間軸；不得自行加入來源口白沒有的價格或優惠。

```srt
1
00:00:00,000 --> 00:00:03,200
挑手沖湖，不要只看才質

2
00:00:03,200 --> 00:00:08,000
先想想你現在最常卡在哪裡 是水流忽大忽小

3
00:00:08,000 --> 00:00:12,500
還是壺拿久了 手晚容易酸

4
00:00:12,500 --> 00:00:18,500
山徑咖啡門市有三款手沖湖 可以免費體驗一小時

5
00:00:18,500 --> 00:00:24,000
先比較重量與控流 再決定哪一把最貴

6
00:00:24,000 --> 00:00:30,000
想試試看 請到門市體驗頁預約
```

必須修正的事實錯誤包含「手沖湖／才質／手晚／酸」等辨識錯字，以及來源沒有支持的「免費體驗一小時」與「哪一把最貴」。正確服務是預約 20 分鐘試握與注水；判斷原則是適合沖煮習慣，不是價格最高。

### 2C. 內容再利用逐字稿

```text
我們整理了最近在門市最常被問的三個問題。第一，壺嘴越細不一定越適合新手；如果握法還不穩，太敏感的水流反而更難控制。第二，重量要連同裝水後一起試，空壺拿起來輕，不代表沖煮一分鐘後手腕仍然舒服。第三，比較影片要使用同一個人、同一個水量與相近的注水節奏，否則看不出器具差異。山徑咖啡目前有三款手沖壺，價格區間是新台幣一千六百八十元到三千二百八十元。門市提供預約二十分鐘試握與注水體驗。這份課堂案例沒有提供哪一款銷量最高、轉換率提升多少，也沒有證明試握一定會帶來購買；這些都必須保留為待驗證。
```

### M2C-3 正式產物

建立 `video-repurpose-pack.md`。文件要保存原始來源、六鏡腳本、修正後的 SRT、至少一則社群貼文與一封 Email 摘要，並在每項衍生內容旁標出它引用的逐字稿句子。若 AI 加入逐字稿沒有的成效、人物或承諾，刪除或標成「待驗證」，不能用順口當作正確。

沒有字幕工具時，使用 2B 完成校對，狀態寫 `TRANSCRIPT REVIEW PASS`。有工具時，可以自行錄製 2A、實際轉錄並保存工具名稱、日期、原始輸出與人工修訂；只有這條路徑能寫 `TOOL RUN VERIFIED`。兩種路徑都必須保留錯字與事實修正紀錄。

## Part 3｜互評標準

互評者先讀來源，再讀產物；只看版面漂亮不能判定通過。

1. 每一項品牌或活動事實都能回指本練習包，沒有補造折扣、成效或使用者證言。
2. 視覺產物能分辨 prompt 規格、已生成候選與已核准發布三種狀態。
3. 字幕產物保留原始草稿與修訂理由，沒有把課堂錯誤 SRT 寫成真實工具輸出。
4. 衍生內容依渠道重新安排篇幅與 CTA，但事實層與來源逐字稿一致。
5. 狀態名稱與實際證據相符；任一項不符就退回修訂。
