## 教學流程（Teaching Flow）

### 看 / Observation（5 min）

<!--

接著對比「一次性生圖」vs「三段閉環」的差別——很多人以為 AI 生圖就是「下 prompt → 拿圖 → 結束」，

-->

#### 開場情境（90 秒，純口述）

上一堂我們學了「參考 → 解構 → 再造」的思維閉環。現在把它套到 AI 生圖的工作流上：

- **參考**：使用課程 READY reference 或可證明權利的自有素材；公開網站只做觀察與筆記，不下載、截圖或重新上傳
- **解構 + 再造**：你猜該怎麼用 AI 做？

最常見的錯誤答案：「下 prompt 給 AI、AI 吐一張圖、我就用這張。」

這是**一次性生圖思維**——跟 CH1-1 的「模仿 → 複製」一模一樣，只是把「複印」的動作交給 AI。結果就是：每次都從零開始、每次品質靠運氣、每次拿到的圖都無法跟上次連動。

本課要教你的是**三段閉環工作流**——讓每次產出都累積可重用的「結構資產」，下次做圖從資產開始，不是從零開始。

---

#### 三段工作流總圖（3 min，口述 + 紙本示意）

老師在白板 / 投影片畫以下流程圖，學員跟畫在筆記本上：

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│   [起]            [承]             [轉 / 合]              │
│                                                          │
│   brief ─→ L4 ─→  L2 線稿  ─→  新 brief → 新 L4         │
│            完稿    (骨架)        新變體    新系列          │
│                                                          │
│   M2 生圖      M3 線稿反推     M4 線稿反控 + M5 整合      │
│   2h           2h              2.5h + 0.5h                │
│                                                          │
└──────────────────────────────────────────────────────────┘

每一段的產出 = 下一段的素材
每次跑完 = 累積一個可重用的骨架 + 品牌 DNA
```

**重點提問**（給學員 30 秒思考）：

- 為什麼中間要多一個「L2 線稿」環節？直接從完稿 A 到完稿 B 不行嗎？
- 不行。因為完稿包含太多表象（色彩、字體、紋理），直接從完稿 A 做完稿 B，AI 會連表象一起複製過去——做出來的就是「把 A 改成 B」的山寨貨，不是屬於 B 的作品。
- **L2 線稿是「脫掉表象、只留結構」的中轉站**。透過線稿，結構可以乾淨地傳承到下一段，表象則完全替換。

### 學 / Learn（18 min）

#### 三段工作流逐段解說（10 min）

---

**第一段｜起：商業廣告生圖（對應 M2，約 2h）**

從 **brief** 到 **L4 完稿**。

- **輸入**：業種 / 商品 / 客群 / 訴求 / 必要元素 / 風格 preset（brief 六件套，CH2-2 會詳教）
- **工具**：Gemini 或 ChatGPT 生圖
- **產出**：1 張 1:1（或其他比例）的商業橫幅 L4 完稿（日系為教學基準、其他風格 preset 為演練延伸）
- **人的角色**｜**需求判定者**——把模糊想法結構化成 brief 六件套、選骨架、選風格 preset

**本段要學會**：
- 5 種跨風格通用的版面骨架（CH2-1）
- brief 六件套怎麼組合成可丟 AI 的 prompt（CH2-2）
- 多主題 + 多風格 preset 演練（PRAC2）

**這段產出的價值**：一張完稿 + 一個「我跑過這個骨架」的經驗。但**完稿本身不是終點**——它是下一段的素材。

---

**第二段｜承：圖轉線稿（對應 M3，約 2h）**

從 **L4 完稿** 到 **L2 視覺化線稿**。

- **輸入**：上一段的 L4 完稿（或任何現成商業廣告）
- **工具**：同對話裡延續 Gemini 或 ChatGPT（關鍵：**同對話**）
- **產出**：1 張灰階線稿（保留物件輪廓、去掉色彩紋理、文字換佔位符）
- **人的角色**｜**骨架驗收者**——用驗收提問 B 檢查 AI 反推的 L2 是否可繼承（輪廓清晰、色彩移除、佔位符正確、形狀一致、位置不變、風格像 wireframe）

**本段要學會**：
- L2 視覺化線稿反推（CH3-1）
- 從線稿讀出結構語言（CH3-2）
- 線稿反推演練（PRAC3）

**這段產出的價值**：**結構骨架**——一張可重複使用的、跨業種的、跨配色的、跨風格的「版面藍圖」。

---

**第三段｜轉 / 合：線稿反控圖片（對應 M4 + M5，約 3h）**

從 **L2 線稿** 反控，產出 **新的 L4 變體 / 系列**。

有三種應用方式：

1. **同線稿 × 跨產業套用**（CH4-1）——線稿是「空房間」、新業種是「新住戶」
2. **同線稿 × 多變體**（CH4-2）——AB 版面探索，挑最適合的
3. **同線稿 × 品牌 DNA**（CH4-3）——繼承式設計，產出視覺一致的系列

最後整合實戰（CH5-1）：一次跑完 brief → 完稿 A → 線稿 → 完稿 B → 完稿 C，產出「一個品牌 3 張系列」。

- **人的角色**｜**系列把關者**——建立 brand-dna.md、用驗收提問 C 檢查 AI 產出的 3 張系列是否都守在品牌 DNA 內（色票、字族、禁用、骨架、語氣）

**這段產出的價值**：**規模化與一致性**——你得到的是可複製、可傳承、可建立品牌系列的能力，不只是一張作品。

---

#### 為什麼要分三段？（3 min）

**一次性生圖的問題**：
- 每次都從零開始，結構沒累積
- 修一張只能重跑，不能局部調整
- 跨系列（春夏秋冬 4 張）沒辦法保持風格一致
- 模型升級後，舊 prompt 可能跑不出來

**三段閉環的好處**：
- 結構（L2 線稿）可以保存，重複使用
- 新主題只要換 brief、不用重新發明版面
- 品牌 DNA + 骨架 = 系列化資產
- 模型升級不影響骨架（骨架是結構知識、不綁定模型）

**核心觀念**：你不是在學「用 AI 畫圖」，是在用 AI 當**執行團隊**去實踐 PM 的三位一體協作（CH1-1 已建立：需求判定 / 骨架驗收 / 系列把關）。AI 負責生成，你負責**下需求、驗收、把關**。

---

#### 平台地圖（5 min）

**本課不指定固定方案或模型**。先打開 `courses/gen-image/assets/downloads/platform-check-card.md`，用你今天登入的帳號完成能力查核。

| 能力需求 | 當場證據 | 不通過時的 fallback |
|---|---|---|
| 產生或編修圖片 | 用課程 READY reference 跑一個最小測試 | 切換另一個已驗證平台，或用預製候選 |
| 上傳 reference | 帳號實際看到上傳入口且測試成功 | 改做離線 reference 分工與 L2 判讀 |
| 局部修改 | 指定一區，前後對照選區外是否不變 | 回到原圖，用設計軟體後製 |
| 比例與裁切 | 實測 1:1、4:5 或 16:9 至少一種 | 先產安全構圖，再人工裁切 |
| 資料控制 | 找到官方資料使用、保留與刪除說明 | 不上傳客戶或可辨識人物素材 |

**平台決策看四件事**：任務功能、資料風險、預算與 fallback。方案名稱、模型、額度、價格與等待時間都可能因日期、地區、帳號而不同，只在檢查卡記錄當日證據。

**Canva／Firefly 是工具選項，不是權利保證**：換平台、重製或使用內建素材，都不能替你證明輸入權利、人物同意、個別素材授權、相似性與揭露已通過。正式交付仍要走商用五關。

> **預期差異**：你和同學可能看到不同方案與功能。記錄「查核日期、地區、帳號類型、官方連結與實測結果」，不要把一次測試寫成永久規則。

### 做 / Hands-on（7 min）

#### 活動｜選定路線 + 繪工作流圖

**階段 1｜繪工作流圖（3 min）**

學員拿出筆記本或手機備忘錄，畫出或寫出三段工作流：

- 三個方框：起 / 承 / 轉-合
- 每個方框內寫：輸入 / 工具 / 產出
- 方框之間用箭頭連接

**預期成果**：1 張工作流圖（手繪或文字條列皆可），能在 30 秒內解釋給別人聽。

---

**階段 2｜填平台檢查卡 + 選主路徑（3 min）**

學員打開平台檢查卡，至少查一個主平台與一個 fallback：

- 實測能否產圖／上傳課程 READY reference／做局部修改
- 查官方方案、資料控制與商用條款頁
- 記錄日期、地區、帳號類型與實際錯誤訊息

查完後回答：

- 我今天的**主路徑與 fallback**是什麼？
- 哪些素材不能上傳？平台失敗時如何繼續完成學習任務？
- 我的決策理由是什麼？（功能 / 資料風險 / 預算 / 工作頻率）

**預期成果**：1 份平台檢查卡 + 主路徑／fallback + 50 字內的決策理由。

---

**階段 3｜分享（1 min）**

2-3 人一組，快速分享各自的路線選擇。

- 注意：**沒有「正確答案」**，每個人的預算、頻率、品質需求不同
- 重點是你**能說出理由**，不是你選哪條

---

#### 完成標準（self-check）

- [ ] 工作流圖含三段（起 / 承 / 轉-合）+ 箭頭方向正確
- [ ] 每段寫出輸入、工具、產出 3 個欄位
- [ ] 能用 30 秒口述說出三段的意義與產出
- [ ] 選定主路徑與 fallback，知道雙平台都不可用時的離線任務
- [ ] 決策理由至少含功能、資料風險、預算與使用頻率中的兩項

## 商業情境案例（Case）

**角色**：主線 A 老闆（弄一下咖啡工作室單店老闆）

**公司**：弄一下咖啡工作室

**任務**：老闆上完 CH1-1 後，知道「參考 → 解構 → 再造」的閉環。現在他想知道：這個閉環在 AI 工具上**實際怎麼跑**？要用什麼工具？要花多少錢？

**本單元要他學會**：

- 把抽象的「參考 → 解構 → 再造」對應到具體的「起 → 承 → 轉-合」三段工作流
- 認識主打工具（Gemini / ChatGPT / Canva / Firefly）各自的定位
- 依功能、資料風險、預算與工作頻率選定主路徑與 fallback

**情境擴展**：同一平台選擇必須隨資料風險改變。公開假想商品可測試生成；客戶未公開包裝或人物素材，若資料控制與同意不明就不上傳，改用課程 reference。

**本單元的 POV**：

主要走第二人稱「你」，讓學員把自己代入「一個要做平台選擇的工作者」。情境擴展部分用第三人稱介紹 3 種不同使用者畫像，供學員對照自己屬於哪類。

## 動手練習題（Hands-on Exercise）

**題目**：

請在 7 分鐘內完成以下 3 件事：

1. **繪工作流圖**：畫出或寫出三段工作流（起 / 承 / 轉-合），每段標註輸入 / 工具 / 產出
2. **填檢查卡**：查一個主平台與一個 fallback 的官方方案、資料控制、條款與實際功能
3. **選路線**：寫下主路徑、fallback 與 50 字決策理由

**預期成果**：

- 1 張工作流圖（手繪 / 文字條列皆可）
- 1 份平台檢查卡與主路徑／fallback
- 1 段 50 字內的決策理由（含功能／資料風險／預算／頻率至少兩項）

**完成標準**（self-check）：

- [ ] 工作流圖三段齊全、箭頭方向正確
- [ ] 每段寫出輸入 / 工具 / 產出
- [ ] 能用 30 秒口述說明三段各自產出什麼
- [ ] 主路徑與 fallback 明確，知道平台都不可用時的離線任務
- [ ] 決策理由提到至少 2 項具體考慮，且列出不能上傳的素材

**預期差異提醒**：你選的路線跟隔壁同學**不會一樣**——這是正常的。預算、頻率、品質需求每個人都不同，沒有「標準答案」。唯一要避免的是「盲選」——請基於自己的真實情境做決策。

## 常見錯誤 3 條（Common Pitfalls）

### 錯誤 1｜一上來就用付費版（消費者思維、非 PM 思維）

**錯誤現象**：

學員上完本單元後立刻升級多個方案，卻沒有先測試自己帳號是否真的支援 reference、局部修改與資料控制。付費後仍在同一個環節卡住，還沒有可用 fallback。

**原因**：

這是典型的**消費者思維**（「想買最好的工具」），不是 **PM 思維**（「選合適的工具解決當前問題」）。

- 消費者思維：工具越貴越好、功能越多越好
- PM 思維：先列任務能力與資料限制，再用自己的帳號做最小測試

付費與品質、穩定度或功能不是永久的一對一關係；必須依查核日期、地區、方案與實測判斷。

**解法**：

用 **PM 需求判定思維** 做平台決策：先填檢查卡，確認主平台完成核心能力；另一條路徑只需能接手失敗任務。平台都不可用時，以 READY reference、預製候選與離線 QA 繼續。

**原則**：**工具升級應該被「具體需求」推動，不是被「想用好的」推動**——這是 PM 與消費者的根本區別。

---

### 錯誤 2｜只看平台名、不做最小測試

**錯誤現象**：

學員依網路推薦選平台，沒有用課程 READY reference 測試上傳、局部修改與比例。進入第二段才發現帳號、地區或方案缺少需要的功能。

**原因**：

產品名稱不能證明目前帳號可用的功能；方案與介面會變，只有官方頁面與當場實測能作證。

**解法**：

- 若你已經是 MJ 重度使用者，**第一段生圖可以用 MJ**（產出 L4 完稿）
- 開課前用同一張 READY reference 測試主平台與 fallback
- 寫下成功條件、錯誤訊息與不能上傳的資料
- 不強求單一工具走完三段；工具是手段，工作流閉環才是目的

---

### 錯誤 3｜不做平台分工（全部塞給一個工具）

**錯誤現象**：

學員把生圖、reference、局部修改、正式文字與最終交付全塞給同一平台。遇到功能限制時，只能反覆重跑，正式文字也沒有後製與校稿。

**原因**：

平台能力會變；生成、局部修改、文字後製與權利檢查本來就有不同責任，不能用單一工具取代完整流程。

**解法**：

**基本分工建議**（**任務導向、不指定品牌**）：

- **第一段生圖**：簡單 brief 用兩家任一、複雜 brief（多必要元素 / 多比例切換）用 prompt 遵循度當下表現較好的那家
- **第二段 L4 → L2**：哪家**同對話延續編輯**最穩、就用哪家
- **第三段品牌繼承**：哪家**identity 一致性**當前表現好、就用哪家
- **最後交付**：設計工具完成正式文字、尺寸與對比；release gate 檢查權利、揭露與 provenance

**心法**：**「能力導向、不偏好品牌、卡關就換另一家」**——當前表現好的那家、不論是 Gemini 還 ChatGPT、就是你的「主力」。三個月後可能換。

**測試方法**：開課日用同一份 brief 與 READY reference 各跑一個最小任務，保存結果與日期；這比沿用舊排名可靠。

## 檢核題 2 條（Quiz）

### Q1（概念驗證｜簡答）

請**用自己的話**寫或畫出「生圖 → 轉線稿 → 線稿反控」三段工作流，並說明：**為什麼要多中間「線稿」這段？一步到位從完稿 A 直接做完稿 B 不行嗎？**

**預期答案要點**（至少命中 3 點算通過）：

1. 三段工作流圖：起（brief → L4 完稿）→ 承（L4 → L2 線稿）→ 轉-合（L2 + 新 brief → 新 L4）
2. 中間要有線稿是因為**完稿包含太多表象**（色彩、字體、紋理），直接從完稿做完稿會把表象複製過去
3. **線稿脫掉表象、只留結構**，讓結構可以乾淨傳承到下一段
4. 線稿是**可重複使用的資產**（同一張線稿可套多個新業種 / 多個變體 / 多個品牌主題）
5. 一步到位等於「模仿 → 複製」，三段閉環等於「參考 → 解構 → 再造」（加分項：扣回 CH1-1 閉環思維）
6. 線稿讓**結構知識可保存、可累積、經驗會複利**（加分項）

**不及格的答案**：
- 只畫三個方框沒寫理由
- 「因為老師說要這樣」
- 「這樣比較好看」（錯誤：線稿跟好不好看無關，是關於結構傳承）

### Q2（應用驗證｜PM 決策情境題）

**情境**：

你作為老闆的 PM（或顧問），主線 A 老闆想報名本課但有以下限制：

- 預算有限（月可支配約 NT$1,500 用於工具訂閱）
- 時間有限（每週只有週日晚上 2 小時可以練習）
- 品質要求中等（不是專業設計交付，只是 IG 自用）
- 目前已有 Canva Free 帳號、Gmail / Google 帳號
- 未公開商品包裝與客戶照片不可上傳到資料控制不明的平台

請用平台檢查卡替老闆做配置。具體說明：

1. 主平台需要通過哪些能力測試？
2. 哪些素材不能上傳？
3. 主平台失敗時的 fallback 與完全離線任務是什麼？
4. 是否需要付費，依什麼當日證據決定？

**預期答案要點**：

- 先用課程 READY reference 實測產圖、reference、局部修改與比例；留下日期與錯誤訊息。
- 客戶未公開包裝、可辨識人物與權利不明素材不上傳；改用課程 reference 或去識別資料。
- 主平台失敗時切換另一個已驗證入口；都不可用時完成 brief、reference 分工、L2 骨架與人工 QA。
- 只有當現有方案缺少必需能力，且官方方案頁與實測能證明升級可解決，才考慮付費。
- 正式文字在 Canva 或其他設計工具後製並逐字校稿；工具方案不替代 release gate。

**加分答案**：

- 把官方條款、資料控制與方案頁連結記進平台檢查卡。
- 說明同學看到不同功能可能來自地區、帳號與逐步推出，不把一次測試寫成永久規則。

**不及格的答案**：

- 只寫「選最貴的」或「選免費的」，沒有能力與資料證據。
- 沒有 fallback，平台失敗就整堂停擺。
- 把可辨識人物或客戶未公開素材直接上傳。
