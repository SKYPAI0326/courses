# 開課日平台檢查卡

易變資訊只放這張卡，不把固定價格、額度、等待秒數寫進核心課程。每次開課與正式交付前重新查官方頁面。

## 2026-10-16 能力基準

目前主流工作流已從「一次文字生一張圖」移到以下能力。開課時逐項實測，不因平台宣傳文字直接判定通過：

- 同一對話內多輪修改，並能把一張或多張圖片分配成構圖、商品、質感或色彩 reference。
- 用遮罩、選區或明確區域做局部修改；前後對照選區外是否被意外改動。
- 產出同時交付 prompt、reference ID、人工修改、模型／工具與日期等 provenance。
- 以 Content Credentials／SynthID 等來源訊號輔助查核；沒有訊號不代表「真人拍攝」，有訊號也不代表內容真實或權利完整。
- AI 只列待查線索；文字、商標、人物、商品細節、無障礙、偏見與商用風險仍由人檢查並留證據。

## 查核順序

1. 先確認登入帳號、地區與實際方案，不沿用別人的截圖。
2. 用一張課程 READY reference 測試是否可上傳、是否能限定局部修改。
3. 記錄實際錯誤訊息與等待情況；不要把一次測試推論成固定秒數或永久額度。
4. 查官方服務條款、產品條款、隱私／資料控制與素材個別授權。
5. 任一平台不可用，切換另一已驗證平台；兩者都不可用時改做 reference 分工、L2 骨架、prompt 與人工 QA。

## 功能性通過條件

- 至少一條路徑可產生或編修圖片。
- 至少一條不需上傳客戶素材的離線路徑可完成學習目標。
- 學員知道輸入資料不該上傳的停止條件。
- 教師已準備預製候選圖，平台中斷不會讓整堂課停擺。

## 不可寫成結論的句子

- 「每天固定可生成＿＿張。」
- 「一定會在＿＿秒完成。」
- 「使用某平台就保證可商用／無侵權。」
- 「訂閱某方案就一定包含某模型與功能。」

把它們改寫成「於查核日期、此帳號、此地區實測／官方頁面顯示」，並附來源。
