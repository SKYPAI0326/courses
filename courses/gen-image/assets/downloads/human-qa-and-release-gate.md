# 人工 QA 與交付 Release Gate

AI 可以整理待查項目，不能替人證明自己產出的圖已正確、合法或可交付。每個候選版本都要留下三層證據。

## 第一層｜AI 只列待查線索

要求模型回答：

- 哪些地方可能沒有遵守 brief？
- 哪些文字、比例、手部、商品結構或 reference fidelity 需要人工放大？
- 哪些判斷需要取色器、OCR、尺寸或來源紀錄，模型無法直接證明？

把答案放進紀錄，但不要勾「通過」。

## 第二層｜人工目視必要項

| 必要項 | 人工要看什麼 | 失敗回哪裡 |
| --- | --- | --- |
| 任務對齊 | 用途、受眾、主體與比例是否符合 brief | Brief／用途版型 |
| 視覺層級 | 3 秒內能否指出 P1、P2、P3 | L2 骨架／構圖 |
| 主體完整 | 商品、角色、手部、邊緣與材質是否異常 | 主體 prompt／reference |
| Reference fidelity | 不可變項是否保留、禁止元素是否未帶入 | Reference 分工 |
| 局部修改 | 選區外是否完全不變 | 局部修改或後製 |
| 系列一致 | 光向、色彩、材質、主體比例是否一致 | Brand DNA |
| 文字風險 | 正式文字是否已移到後製並逐字校稿 | 後製 |

任一必要項失敗，候選圖不得進下一關。

## 第三層｜可觀測工具證據

- 尺寸與比例：檔案像素、裁切預覽。
- 色彩：取色器記錄 RGB／HEX 與容差。
- 文字：OCR 只用來找疑似錯字，最後逐字人工校稿。
- 安全區：疊上實際文案框與平台 UI 範圍。
- 對比：正式文字後製後檢查色彩對比。
- 差異：局部修改前後疊圖，檢查選區外變動。
- 第三人盲評：不看 prompt，說出先看到什麼、以為要做什麼。

## 商用五關

只有五關都能回答並提供證據，才可標記「可進交付審查」。這不是法律保證。

### 1. 輸入權利與人物同意

- Reference、logo、照片、客戶檔案是自有、獲授權或課程 READY 素材嗎？
- 可辨識人物是否同意此用途與 AI 處理？
- 未成年人、公共人物、冒充或深偽情境：停止，交由更高層審查。

### 2. 平台條款與帳號方案

- 開課日或交付日查過目前方案的輸入、輸出與商用條款嗎？
- 客戶資料是否允許上傳？是否知道資料控制、保留與刪除方式？

### 3. 個別素材授權

- 字型、stock、模板、icon、音訊與 plug-in 是否各自允許該用途？
- 不能把「平台可商用」推論成所有輸入素材都可商用。

### 4. 相似性、商標與 Trade Dress

- 是否出現近似 logo、角色、包裝配置、知名產品輪廓或特定品牌識別？
- 使用風格屬性描述，不靠品牌名稱複製外觀。

### 5. 揭露與證據留存

- 保存模型／版本、日期、prompt、reference、授權、人工修改與審核者。
- 檢查 C2PA／Content Credentials／SynthID 等訊號；有或沒有都如實記錄。
- 依客戶、平台或法規要求放置 AI 使用揭露；畫面文字與 metadata 分開處理。

## Accessibility Gate

- [ ] 每張交付圖有描述目的的 alt，不只寫「圖片」。
- [ ] 圖內資訊另附完整純文字版本。
- [ ] 正式文案已逐字校稿，價格、日期與法規文字未交給模型決定。
- [ ] 文字與背景對比已檢查；不能只靠顏色傳達狀態。
- [ ] 圖片載入失敗時，純文字仍能完成核心任務。

## Bias Gate

- [ ] 人物屬性與 brief 直接相關，且取得適當同意。
- [ ] 不用年齡、性別、族群、身體或職業刻板印象當風格捷徑。
- [ ] 對敏感人物任務做成對 prompt 測試：只改一項屬性，比較角色、場景、權力與表情差異。
- [ ] 由人複核，不以模型聲稱「沒有偏誤」作結論。

## Release 紀錄

```text
候選檔名／版本：
Brief 與用途：
AI 待查線索：
人工必要項：PASS／FAIL（附現象）
工具證據：
五關：1___ 2___ 3___ 4___ 5___
Accessibility：PASS／FAIL
Bias：PASS／FAIL／N/A（說明）
決定：REVISE／STOP／READY_FOR_DELIVERY_REVIEW
審核者與日期：
```

`READY_FOR_DELIVERY_REVIEW` 仍不是「保證無侵權」或最終法律核准。
