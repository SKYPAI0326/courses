# 教學證據鏈參考

共通判準引用 `$BASE/_規範/course-content-substance.md`。本檔的模組、分流、欄位與 canonical 表格是資料工作流專項；僅在本課真正含此類任務時使用。

## 最小審查表

| 檢查 | 通過條件 | 不通過時 |
|---|---|---|
| Learning objective | 能在示範、操作、驗證各找到對應內容 | BLOCK；回到教案補齊，不用文案掩蓋 |
| Worked example | 有原始輸入、操作、中間結果、判斷理由、**完整 canonical 產物** | BLOCK；學員不得第一次在 Solo 才遇到欄位或產物版本 |
| Branch / failure | 有觸發條件、資料狀態、去向／負責人、**終態或回到哪個模組** | MAJOR；只寫「人工確認」「停止或退回」不算完整 |
| Artifact identity | Hero、步驟、練習、驗證使用同一名稱、版本與數量 | MAJOR；建立 canonical artifact line |
| Source transfer | 清楚區分不變的模組、變動的欄位與角色語義 | MAJOR；禁止把 sender、customer、owner 混用 |

## Worked example 的判準

若學員被要求補一欄，示範至少要出現一筆正確答案；若該欄是 learning objective 的核心，示範必須呈現完整答案，而非只給句型。

正式產物若規格有 N 欄，示範表就必須同時展示所有欄位與至少一份完整 canonical 完成品；完成品的列數依任務需要，不以固定數字湊版面。只在步驟中列出欄位名稱、再要求學員自行補齊，不算 worked example。來源替換若產生 `v2`，示範必須交代每個來源欄位的去向、被移除的 v1 欄位、固定設定值的來源，以及下游模組的新輸入契約。

## 分流的判準

```text
needs_review=true
→ 人工確認佇列（狀態：待人工確認）
→ 內部負責人檢查
→ 核准：回到寄信模組；退回修改：回到 AI 處理模組；拒絕：狀態標記已停止

needs_review=false
→ 文件 → 寄信 → message ID（狀態：已完成）
```

如果本節沒有建立人工模組，請明確寫「未實作的流程出口」，但仍要寫出負責人、核准／退回／拒絕的下一狀態；不要用「停止或退回」這類未指定責任人的二選一描述。

## 失敗反應的判準

「失敗影響」不能只描述下游會壞掉。每個核心模組都要能回答：誰先處理、要記錄什麼、下游是否停止、修正後重試哪個模組，或以何種狀態結束。若 learning objective 寫「每個模組」，示範與驗證都必須逐列覆蓋，而不是只驗收至少一個案例。
