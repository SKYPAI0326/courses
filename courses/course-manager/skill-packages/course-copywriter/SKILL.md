# 課程文案設計

## 定位

這個 skill 用於「內容已經存在，但讀起來不像一門課」的二次編輯。目標不是把文字寫得華麗，而是讓學員能一路理解：現在為什麼學、剛才學到什麼、接下來要做什麼。

在新課 G3 流程中，本 skill 是診斷編輯：核對連貫性、學員可讀性與內部標籤是否移除，將來源 SHA-256 與結論寫入 lesson record 的 `editorial_evidence`。它不能成為第二位內容作者，也不能用順暢文案補造缺少的事實、示範、素材、步驟、答案或修復路徑；遇到這些缺口直接退回 course-designer。

它支援兩種輸入：

- 教案 Markdown：整理教學流程、案例敘事與段落承接。
- 學員 HTML：只修正文案與閱讀節奏，不改版型、操作行為、連結或設計系統。

不負責重新設計課程大綱、發明新案例、改寫操作步驟，或把教師備註直接搬進學員頁。

所有零基礎講義的潤稿都必須以 `$BASE/_規範/learner-action-contract.md` 為學員路徑事實來源，並套用 `$SKILLS_ROOT/course-handout-designer/references/beginner-continuity-gate.md` 做 30 秒入口與轉段測試；未設定 `SKILLS_ROOT` 時停止。本 skill 只重排既有事實的進入順序與閱讀節奏；不能另造故事、補寫技術事實，或只把片段改得通順。

## 何時使用

遇到下列任一症狀就啟用：

- 標題、表格、提示和步驟各自成立，但前後沒有理由。
- 段落常以工具名稱、欄位名稱或「學員操作：」突然開始。
- 示範結束後直接跳到跟做，學員不知道示範和自己的任務如何對應。
- 同一案例的資料來源、角色、輸出名稱在不同段落變動，卻沒有解釋。
- 講義提到「課程資產／附件／範例檔」但學員在第一次使用前找不到連結、路徑、格式或用途。
- 內容看似完整，朗讀或從頭閱讀時仍像零散筆記。

若問題是缺少學習成果、操作步驟、素材或評量，先回到 `course-designer`；若問題是 HTML 結構或模板合規，使用 `build-course-page` 或 `course-reviewer`。

## Pipeline Risk Gate

正式正文或 HTML 出現下列任一可觀察條件就必須執行本 skill，不能只以 lint 或區塊齊全放行：

- 第一個主要區段直接開始操作，沒有起始狀況、任務及保留／改變。
- 連續兩個主要區段之間，沒有引用上一段具體結果並說明下一段目的。
- 連續多組固定步驟欄位，中間沒有自然說明段落。
- Demo 結束後直接進入 Together／Solo，沒有說明沿用條件與重新判斷項。
- 結尾只有完成檢核，沒有成功意義、交付對象或日後使用。

先判定缺口類型：

| 缺口 | 處理 |
|---|---|
| 事實完整但敘事斷裂 | 使用本 skill 重寫承接與閱讀節奏 |
| 缺素材、權限、完整示範、操作事實或驗收標準 | `BLOCK`，退回 `course-designer`／素材製作；本 skill 不補寫 |
| 資產存在但學員找不到、無法開啟或不知道何時使用 | `BLOCK`，退回 `build-course-page`／素材製作；本 skill 不以文案假裝補齊連結 |
| HTML 組件遺失 teaching atom | `BLOCK`，退回 `build-course-page` |

Gate 輸出必須是 `PASS`、`MAJOR` 或 `BLOCK`，並列出觸發條件與對應位置。機械腳本只負責篩選風險，不能取代 cold follow-along。

## 不可破壞的教學事實

編輯前先建立保留清單。下列內容不可因潤飾而改變：

- 學習成果、案例任務、資料值、欄位名、公式、Prompt、JSON、模組名。
- 操作順序、檢查點、預期結果、錯誤處理與安全限制。
- 教案已明確指定的工具、版本、免費／付費界線與學員前置條件。

若原文互相矛盾，標記矛盾並回報，不要用文案猜一個答案。若缺少必要事實，使用 `[需補資料：...]` 暫標，不能自行補寫。

## 契約導出的編輯鏡頭

把核心契約的事實重新讀成以下學習路徑；這是編輯鏡頭，不是另一份內容契約，不一定要使用這些標題：

```text
情境與任務
  → 為什麼這件事值得學
  → 必要概念與判斷原則
  → 完整示範（輸入 → 操作 → 中間結果 → 理由 → 完成品）
  → 跟著做（逐步模仿示範）
  → 自己做（在需要時改變一個或多個條件，重新判斷並遷移）
  → 驗證與修正
  → 帶走的通用方法
```

段落關係不明時，補足能回答「為什麼現在進入下一步」的橋接句。橋接句必須指向前一段的具體結果，例如「剛才已確認 `needs_review` 會阻擋寄信，現在把這個判斷寫進你的地圖」，不能只寫「接下來我們繼續操作」。

## 教學證據鏈

共通充分性及有效重練依 `$BASE/_規範/course-content-substance.md`。下列資料表、模組、分流及欄位規則僅用於實際含此類任務的課程，不套用於概念、語言或推導課。

敘事順暢不等於可以學習。每一個學習成果都必須形成可追蹤的證據鏈：

```text
學習成果 → 完整示範 → 學員操作 → 預期產物 → 驗證證據
```

編輯前建立這張矩陣；任何一格空白都要補內容或標記為 `BLOCK`，不能用橋接句掩蓋：

| 學習成果 | 示範證據 | 學員操作 | 驗證方式 |
|---|---|---|---|
| 判斷失敗影響 | 示範每個模組的失敗與下游影響 | 學員逐列補寫 | 驗證至少一個失敗點、影響與處理出口 |

硬性規則：

1. 學員要自行填寫的欄位，完整示範必須先展示至少一個正確答案；若是核心學習成果，必須展示完整答案。
2. 每個 `true / false`、通過／不通過或分流條件，都要寫出資料去向、負責人或終止狀態；只寫「人工確認」不算完成。
3. 「模組角色」與「資料映射」分開定義；一個是模組的責任，一個是模組之間的欄位關係。
4. 完成物只保留一個正式規格。若有版本，明確列出版本名稱、每版必備欄位與附帶說明，並同步到 Hero、操作與驗證。
5. 最終驗證逐項扣回 learning objective；沒有證據的「我已經了解」不算驗收。
6. 若正式產物是七欄表格，完整示範必須真的展示七欄與完整五列完成品；不能只在操作步驟列出欄位名稱。
7. 來源替換版本必須閉合欄位契約：每個新來源欄位要有去向，被移除的舊欄位要明確標記，固定設定值要說明來源，下游輸入要重新列出。
8. 分流必須有明確終態：核准回到哪個模組、退回由誰修改、拒絕如何標記、成功如何結束；禁止「停止或退回」而不指定責任與回路。
9. 若 learning objective 寫「每個模組」的失敗影響，示範表與驗證都要逐列覆蓋負責人、下游影響與停止／記錄／重試方式。

### 失敗影響與分流的最小完整度

若單元涉及失敗、審核、Filter、Router 或人工接手，至少說明：

```text
觸發條件 → 資料狀態 → 去向／負責人 → 下一步或停止狀態
```

若本節刻意不實作某個分支，必須寫成「未實作的流程出口」，不能讓學員以為分支已經存在。

## 編輯流程

### 1. 先診斷，不直接潤飾

讀取官方大綱、style guide、教案與 HTML（若存在）。先列出：

| 區塊 | 已有的教學功能 | 讀者斷點 | 需要補的承接 |
|---|---|---|---|
| 示範 → 跟做 | 示範完成品 | 不知道要模仿哪個決定 | 指出示範中的固定欄位與本次要重做的欄位 |

至少辨識情境、概念、示範、操作、驗證、遷移六種功能。若某功能不存在，回報「缺內容」，不要用空泛文案掩蓋。

另外依 `beginner-continuity-gate.md` 執行 30 秒入口與轉段測試，不另建立一份入口 checklist。若第一句教學是負面邊界（例如「你不需要先建立……」）、時間標籤或工具箭頭，先重寫段落功能，不要直接潤色該句；若核心契約事實缺失，回交 `course-designer`，本 skill 不補寫。

### 2. 建立一致的名詞與案例線

先做一張名詞表：角色、資料來源、關鍵欄位、完成物、判斷條件。整頁沿用同一名稱；必須換來源時，明確寫出：

- 哪些模組與判斷保持不變。
- 哪些輸入欄位改變。
- 哪些映射或輸出需要重新檢查。

名詞表再加兩欄：**第一次出現位置**與**白話定義／本案例用途**。凡學員在操作前看到但無法用日常語言解釋的詞，標記為 `MAJOR`；若該詞決定第一步是否能執行，標記為 `BLOCK`。

### 3. 由大到小重寫

依序處理：

1. 單元開頭：把受眾、工作情境、任務與完成物接在一起。
2. 區段之間：補上結果與下一步目的的因果句。
3. 區段內部：把概念、例子、操作、檢查放成可讀順序。
4. 句子層級：將片語、孤立標籤與機械式提示改成完整句，但保留操作欄位。

不要先逐句換同義詞。若大結構仍跳躍，句子越漂亮只會讓問題更難察覺。

### 4. 保留操作原貌，增加理解支架

操作段落可以保留固定欄位，但欄位前要有上下文：

```text
先把示範中的三個輸入欄位放進同一張表，因為下一步要檢查它們是否完整傳給 AI。

學員操作：...
預期結果：...
快速檢查：...
卡住時：...
```

不要把「學員操作／預期結果／快速檢查／卡住時」連續堆成沒有解釋的表單。每一組操作後，說明這一步完成了哪個判斷，以及它如何影響下一步。

### 5. 做兩次閱讀驗收

先以教師視角比對事實，再以零基礎學員視角從頭讀一次。第二次閱讀時，每個主要區段都要能回答：

- 我現在處理什麼問題？
- 我剛才看見的結果，和現在的操作有什麼關係？
- 做完這一步，我如何知道可以繼續？

### 6. 做教學證據審查

完成文案後，逐項比對學習成果、完成物與驗證。優先查四個高風險點：

- 示範是否包含學員被要求自行判斷的欄位與答案。
- 分流是否有完整的 true／false 去向與人工出口。
- 替換資料來源時，寄件者、客戶、內部負責人等角色是否沒有混用。
- Hero、步驟、Solo、驗證是否使用同一份產物規格。

## 文案規則

- 先說目的，再說操作；先給可理解的情境，再引入工具名。
- 段落需能讓學員理解目的與承接；上下文已清楚時可直接接表格，不按標題數補固定引言。
- 依 llm-prose-risk-gate.md 核對實際資料、理由與前提；加入「所以」不能修補不相干的因果。
- 同一頁只維持一條主要案例線；換案例時說明換案例的教學目的。
- 將「工具 → 工具」改寫成「某資料以某欄位進入某模組，產生某結果後，才交給下一模組」。
- 每一段操作前先回答「我們剛才看到什麼，所以現在要做什麼」；不得讓 `Demo / Together / Solo / Check / Stage` 或英文縮寫承擔因果與名詞解釋。
- 符號、箭頭、JSON 路徑或欄位映射必須在一筆具體資料被口頭追過後才出現；先講資料變化，再教符號如何記錄它。
- 將結論落在學員可觀察的結果，不寫「很重要」「快速掌握」等沒有證據的評語。
- 以語意完整為準：核對動作由誰執行、處理哪個資料或物件、必要條件與結果是否清楚；上下文已明確時可省略主詞、受詞或副詞，不為每句湊齊文法欄位。只有「設定」「完成」「確認」等片語在指涉不明或缺少判準時才需補寫。
- 保持繁體中文、對學員用「你」，避免教師口吻、行銷口號與過度抽象的名詞。
- HTML 編輯只動文字節點；不得移除互動、改動 class、改變連結目標或偷偷新增操作。

## 硬性檢查

完成前必須確認：

1. 沒有連續多個只含標籤或清單的段落而沒有解釋句。
2. 各主要區段的目的與前後關係清楚，所需解釋未被表格或標籤取代。
3. 第一個學員動作前已交代情境、手上材料、完成物、第一個關鍵術語的白話定義與示範結果。
4. 示範有完整輸入、中間結果、判斷理由與完成品；跟做明確指出要模仿什麼。
5. 獨立練習依內容實質契約驗收支援減少；主張遷移時要有可辨識的新條件。依 learning objective 改變一個或多個真正需要整合的條件（素材、對象、限制、資料形狀或決策），並寫清楚學員要重新判斷什麼、哪些條件沿用、以及通過標準；若沒有新增認知工作就合併，不要換案例名稱重跑。
6. 所有關鍵名詞、欄位與資料值前後一致；矛盾已標記。
7. 每個檢查點都說明「現在應該看到什麼」及「沒看到時回到哪裡」。
8. 從第一段連續讀到最後一段，不依賴教師口頭補充才能理解任務。
9. 每個 learning objective 都能在示範、操作與驗證中找到對應證據。
10. 失敗影響與分流出口已被示範，不是首次出現在學員自行填寫的步驟。
11. 產物名稱、版本、欄位與交付數量前後一致。
12. canonical 示範表的欄位數與學員產物規格一致，且每一列都包含可追溯的映射與失敗反應。
13. 來源替換後的新欄位契約閉合，沒有要求學員使用未提供的欄位或條件。
14. 每條分流路徑都落在已完成、已停止、待修改或待人工確認等明確狀態。

可執行機械檢查：

```bash
python3 "$SKILLS_ROOT/course-copywriter/scripts/audit_copy_continuity.py" <markdown-or-html-file>
## 下列為資料工作流的參數示例，依本課真實欄位替換，不原樣套用
python3 "$SKILLS_ROOT/course-copywriter/scripts/audit_teaching_evidence.py" <file> --field "失敗影響" --artifact "v1-sheets" --artifact "v2-gmail" --branch "needs_review" --canonical-field "順序" --canonical-field "模組" --canonical-field "角色" --canonical-field "輸入" --canonical-field "輸出" --canonical-field "映射備註" --canonical-field "失敗影響" --failure-response 5 --terminal "已完成" --terminal "已停止" --terminal "回到 Gemini" --contract-note "不再使用"
```

連貫腳本只負責找出高風險斷點，不宣稱能判定文學品質；教學證據腳本負責檢查「成果—示範—驗證」是否有缺口。掃描列出的 BLOCK／MAJOR 是待語意確認的候選，先閱讀原文分類；真實缺漏才退回，不能因無特定標籤、卡片或連接詞誤擋完整正文。

## 交付格式

交付修改後檔案時，同時附一份簡短的文案修訂報告：

```text
敘事主線：情境 → 概念 → 示範 → 跟做 → 驗證 → 遷移
保留事實：列出未改動的案例、欄位、步驟與輸出
主要修訂：列出 3–7 個真正補上的銜接或重排
未解斷點：缺資料、原文矛盾或需使用者決策的地方
驗收結果：機械檢查 + 人工從頭閱讀結論
教學證據：逐項列出 objective、worked example、learner artifact、verification 的對應位置
```

若只做局部潤飾，明確指出未檢查的區段，不得宣稱整頁已連貫。

## 常見失敗

| 失敗寫法 | 為什麼不行 | 修正方向 |
|---|---|---|
| 每個段落各自寫得通順 | 段落之間仍沒有學習因果 | 先補上一段的結果與下一段的目的 |
| 把所有標題改成完整句 | 只有表面語氣變化，教學功能未補 | 先確認該段要解決的學員問題 |
| 用「接下來」「最後」串全文 | 只有時間順序，沒有理由 | 說明資料、判斷或成果如何推動下一步 |
| 為了流暢自行補一個欄位或步驟 | 破壞操作事實 | 標記需補資料，回到教案確認 |
