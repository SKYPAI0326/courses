# 教學品質審查與實測方法

本檔定義測試方法。任務與正式狀態見 `$BASE/_規範/learner-action-contract.md`；充分性與去重見 `$BASE/_規範/course-content-substance.md`。審查結論要引用實際正式正文或頁面，作者摘要、標題存在與自填 covered 都不足。

## 審查順序

1. 正文審查：遮住內部設計與教師備註，依目標核對解釋、完整示範、練習、答案與必要修復；核對知識正確性、前提先教及操作狀態順序。
2. 語意審查：依 llm-prose-risk-gate.md 檢查指涉、句意與因果。特別讀「所以」前後的資料和理由，不把連接詞當連貫證據。
3. 能力與重複：讀相鄰單元及活動的實際內容，核對新增認知工作、支援遞減與回饋；同素材可以是有效重練。
4. HTML 保真：逐項比對核心表格、推理、原始輸入、中間結果、完成例子與答案；核對素材首次使用前可取得。HTML 出現同名標題仍可能遺失內容。
5. 缺漏回到責任層修復，重驗受影響部分。局部審查 PASS 不是課程已授課驗證。

## 分層實測

| 層次 | 實際執行 | 可支持的結論 |
|---|---|---|
| 技術／素材 | lint、可讀連結、實檔、版本與必要程式執行 | 所測確定性條件成立 |
| 入口 | 只給學員頁與列出材料；記錄能否找出目的、材料、第一個動作與預期結果 | 找得到起點；30 秒是診斷時間範例，不是普遍硬門檻 |
| 完整跟做 | 從起點走到承諾成果，實際檢查並在適用時處理合理錯誤 | 所測路徑能完成；入口答案不能替代 |
| 理解／遷移 | 解釋關鍵理由、診斷錯誤、在新條件下選擇或調整方法 | 所測能力能運用，不能只憑完成成品推定 |
| 連續課 | 代表性三課或不足三課時全數，記錄能力沿用、新判斷及整合 | 所測序列銜接成立；真有產物鏈再核對檔案 |
| 平台 | 實際帳號、方案、版本與指定路徑 | 只驗證已跑的平台條件；非工具課記不適用及原因 |

## 記錄格式

沿用 `_validation/evidence.json` 與 `_review/` 審查紀錄，欄位格式見 `course-validator/references/evidence-format.md`。每項記錄含受測教材與素材版本（SHA-256）、方法、執行者類型、實際動作、卡點、提示、自我修正、結果與完成證據。保留失敗，不只記最後成功。

作者自驗標 `author-self-check`；另開無作者推理上下文的 AI 模擬才標 `independent-ai`；真人標 `human`。不得互相冒充。採样要事先說明課型／風險範圍；單一頁成功不能替未測分支或整門課放行。

## 局部審查結論

- PASS：本次範圍的必要證據充分，沒有未解核心或必要內容問題。
- MAJOR：必要解釋、回饋或理解支援不足，需修正後重審。
- BLOCKER：無法開始／完成、核心材料或教學缺失、知識錯誤、依賴順序不可能、轉製遺失核心內容。
- PENDING：尚未執行，或需要指定受測者／平台。不得寫成已失敗或已通過。

審查引用與 hash 能確認證據歸屬，不能自動判斷語意或證實真人身分；執行者仍須如實記錄。
