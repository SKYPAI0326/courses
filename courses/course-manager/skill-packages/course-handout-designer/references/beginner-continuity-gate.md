# Beginner Continuity Gate

這份檔案是零基礎入口與轉段的驗證方法，不是另一份契約。學員路徑欄位與放行語義唯一以 `$BASE/_規範/learner-action-contract.md` 為準；本 Gate 只回答「頁面是否真的把契約呈現出來」。

## 入口測試

30 秒是快速診斷參考；記錄實際時間與提示，不把時間上限當普遍內容退件標準。完整跟做方法見 quality-gate.md。

遮住教師筆記、Blueprint、作者狀態與角色標籤，只看學員首先看到的內容。開始操作前，學員必須能回答：

1. 我在處理哪個情境或學科問題？
2. 這個問題為什麼值得處理？
3. 我手上的第一份材料是什麼，怎麼取得？
4. 我要留下什麼成果，名稱、位置或格式是什麼？
5. 這個成果如何驗收與再次使用？
6. 我第一步要做什麼，做完應看到什麼？沒看到要回哪裡？

這六題是核心契約的快速抽查，不是新增的內容欄位。任何一題需要猜測或講師補充，判定 `BLOCK`，回到契約或上游素材／環境修正；不要用更多步驟、英文標籤或裝飾性開場掩蓋斷點。

## 入口順序

頁面應依課型調整篇幅，但第一個學員動作前必須形成這條因果鏈：

```text
學習問題與用途
→ 起始材料
→ 完成物預覽與用途
→ 本次需要的概念與判斷
→ 一筆完整示範（輸入／處理／中間結果／完成品）
→ 第一個動作與可觀察結果
```

主要階段之間要能填入：

> 剛才完成或看見的具體結果是＿＿，所以現在要＿＿，目的是＿＿。

「接下來」「先不要」「你不需要先……」不能單獨承擔轉段理由。確實要交代邊界時，先說明目前問題、手上材料與本節目標，再說明此刻暫不處理什麼。

## 首次使用檢查

凡學員稍後要讀、填或判斷的工具物件、檔案格式、欄位、資料結構、錯誤狀態或課堂標籤，第一次出現時都要同時說明：

```text
名詞 = 白話意思 + 在本案例中的位置 + 現在為什麼需要它
```

先用一筆具體資料說明關係，再使用箭頭、表格、JSON 路徑或縮寫。`Demo`、`Together`、`Solo`、`Check`、`Checkpoint`、`Stage` 只能作為導航；刪除標籤後，正文仍須說明學員為何做、做什麼與如何判斷。

## 冷讀記錄

冷讀只提供 learner-facing handout 與契約列出的材料，不提供 Blueprint 或講師口頭解釋。記錄：

- 使用的頁面、材料與起始時間；
- 上述六題的原話或摘要；
- 到第一個 checkpoint 的時間；
- 是否猜測、停住或需要提示；
- 若失敗，對應的契約欄位與回修角色。

入口測試通過不代表平台或整門課已放行；仍依核心契約的 `MACHINE_CHECKED`、`LEARNER_READ`、`PLATFORM_VERIFIED`、`HUMAN_READY` 分開記錄。
