# course-manager 專案入口

## 文案迭代

使用者以「文案迭代」啟動時，先讀[文案使用入口](docs/course-copy-quickstart.md)、[專用規範](docs/course-copy-profile-v0.6.md)、[共用控制器說明](docs/course-loop-runtime.md)及[開發紀錄](operations/course-content-scoring/開發進度追蹤.md)目前狀態。套用course-copywriter的事實保留邊界；只處理原稿已有內容的語氣、指涉、承接與完整敘事，不另造案例或操作。

對象定位沿用上層[courses共用入口](../AGENTS.md)：先依指定路徑或目前課程定位，只有範圍／用途仍不明時才詢問，不要求版本或切換目錄。指定後先找既有run，無既有工作才用`scripts/course_copy_loop.py`準備單章隔離設定或整課清單，後續用`scripts/course_loop.py`接續。沿用Sol評估／新上下文覆核、Luna改寫／比較、人工H3，每章最多兩版，單章預設八次low呼叫；整課明列共用總額，不自行按章數放大。不另派平行代理，未授權不覆蓋正式講義或擴大修復。缺事實、素材或需改技術內容時依專用規範停止回交，不以潤稿掩蓋；完成後更新同一份開發紀錄。

文案迭代以單章執行但須完成使用者指定範圍；整課先依實際目錄列齊章節，逐章記錄候選、確認、套用及阻塞狀態，不能將部分通過說成整課完成。新run使用v0.6的白話重述、指涉、理由位置與閱讀負擔檢查；舊run不重綁或重置用量。已有正式套用／發布授權時直接接續，發布須核對實際來源分支、部署及逐頁公開內容，不能用工作分支push代替。

## 文案迭代改

使用者以「文案迭代改」啟動時，依共用入口先找既有run並讀取同一份v0.6規範及目前開發紀錄。只有新run用`scripts/course_copy_loop.py --agy-writer`選擇agy；只派送`rewrite`階段到固定的`gemini-3.8-flash-low`。評估、compare與review仍分別使用原本的Sol、Luna與Sol，不產生第二位作者稿；H3由使用者確認。

沿用相同的來源雜湊、單章兩版及八次low上限、事實保留與隔離輸出。舊run不可切換provider或重置用量。agy若使用工具／子代理或無法證明模型與結構化輸出，控制器拒收；預檢失敗不計模型呼叫。未授權不覆蓋正式講義或發布；完成後更新同一份開發進度追蹤。

## 課程迭代

使用者以「課程迭代」啟動工作時，先讀取[開始使用教學](docs/course-loop-quickstart.md)、[操作規範](docs/course-loop-runtime.md)與[開發進度追蹤](operations/course-content-scoring/開發進度追蹤.md)的目前狀態，再依指定課程與章節辨認既有run及必要來源。不可依聊天記憶重建流程，也不可重建run重置候選用量。

主對話負責確認範圍、執行控制器、處理例外與登記人工回饋，建議使用GPT-6.1 Sol；入口不能切換使用者已選的對話模型。流程內模型由設定檔派送：預設gpt-6.1-sol評估與新上下文覆核、gpt-6-luna改寫與作者比較，H3由使用者確認。先核對既有run設定；新run沿用現行範本與本次授權，不自動替換模型或提高資源上限。實際執行使用`scripts/course_loop.py`，不另行派遣代理取代既有控制器。

只有啟動詞、尚未指定對象時，完成上述載入後簡述目前可用流程，詢問本次課程與章節；不呼叫模型、不啟動佇列。已有明確對象與授權則直接依規範接續，不重問已確認事項。預設隔離候選、兩版上限，不覆蓋正式講義、不擴大整課修復；既有待補證與使用者限制依紀錄保留。完成工作後同步更新同一份開發進度追蹤。

## 接續課程 skill 改善

使用者說「接續課程 skill 改善」時，先讀取本目錄下的 [課程設計 skill 修正紀錄](operations/skill-improvement-2026-10-26/課程設計skill修正紀錄.md)，再依當次指定的問題與範圍接續工作。先辨認已套用修正、人工回饋及尚未驗證的結論，並讀取本次涉及的現行 skill；不可只憑歷史紀錄覆寫現行檔案。

若只有啟動詞，先簡述目前狀態與待續項目，詢問本次要處理的問題，不自行啟動所有待辦。完成實質修正後，將原因、變更位置、實際結果與限制追加至同一份修正紀錄。沿用既有規範，不另建檢查表，也不把參考課程固化為通用章節模板。
