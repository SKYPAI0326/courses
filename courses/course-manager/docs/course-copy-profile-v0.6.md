# 文案迭代：專用執行規範 v0.6

承接v0.5的事實保留、候選、H3、整課範圍與發布界線；舊run不重綁。本版將四項讀者檢查接入改寫提示、比較／覆核的JSON schema、runtime保存與控制器接收，不增加模型輪次、模型等級或候選額度。

## 實際改稿與覆核

1. 用讀者的話重述。`plain_restatement`不沿用抽象製作術語，說明主要段落的意思與理由；`support_quotes`逐字引用當前正文的依據。不得從其他來源替候選補背景。必須靠猜測才能說通的內容，記入`added_background`；沒有就留空。
2. 先解決理解障礙。`referents`判斷人、材料、行為與條件能否辨認，說明實際指涉。先看全文已有交代，不對熟悉名詞強加定義；換口語同義詞不能代替補清楚關係。
3. 理由放在需要的位置。`reason_placement`判斷讀者執行或判斷前，是否已讀到所需理由。不是每個簡單操作都補一段原因；術語與概括口號不能代替解釋。
4. 檢查連讀負擔。`reading_load`說明同時出現的日期、代碼、條件與例外是否迫使讀者自行拆解。依理解順序拆段或保留操作清單，不以口語、短字數或少條列當標準。

后三項各交`verdict: supported|gap`及具體`explanation`。欄位只出現在編輯報告，不能搬進學員講義。評估、作者改稿、作者比較與新上下文覆核都使用同樣四個閱讀方向；比較／覆核每個關鍵引文須交實際檢查結果。

任何補入背景或上述gap，都須反映為`remaining_gap`與仍open的B問題，整篇不能supported或B L3。缺欄位、空重述、無正文依據、判斷不一致均拒收。支持引文存在不代表重述一定忠實；語意仍由實際覆核判斷，不能用程式測試冒充讀者理解。

優先引用承載判斷、操作與交付的完整段落；先連讀全文，不逐標題湊欄位，也不以一句轉場替正文背書。作者直接修原有主要段落，不能只增加前言。原有數字、提示詞、案例、操作、條件及連結保留；必要事實確實缺少才依原P／Q界線回交。supported僅是模型閱讀結論，仍需使用者H3。

## 引文位置與問題紀錄的控制器分工

新run另採`citation_contract: locations-v1`，仍是v0.6，不需使用者指定。比較／覆核收到具ID與字元長度的reading_blocks，回傳quote_ref與support_refs，由程式從同版正文擷取原文，再交原閱讀檢查；不再要求模型手抄引號與標點。引用位置越界、段落不存在或來源SHA改變都拒收。舊run與已派送任務不重綁，保留原引文格式。

此契約下，既有P／Q只回報id與open更新，不必重抄身分；未列出便保留原狀態，不代表關閉。新問題才提供完整定義。控制器保存原描述、core／required與已關閉歷史，拒絕變更身分，清除評級中的closed引用；未知ID及仍open問題卻不列入評級也拒收。不依引用清理提高任何等級。

格式更正只接受局部引文位置patch，不再要求模型複製全份JSON；原閱讀結論與內容缺口仍保留。詳見[報告更正操作](course-loop-runtime.md#已回交比較報告的格式更正)。評估須依本章既有用途與案例判斷，不能因清單列到一類工作，就強迫逐類新增完整示範；涉及新素材、案例或教學目標應回交，不直接當本章文案未通過。範圍判斷仍需語意覆核，程式不宣稱能自動判定教學充分性。

## 本版試跑

使用同一課程被否決版本與修正版的完整PRAC2正文，轉成保留段落、清單及表格的Markdown；以中性檔名分開送入新上下文，不提供版本標籤、人工好壞結論或另一份文本。各一次現行Sol、low覆核，沿用實際prompt／schema／執行器及接收檢查。保存來源、轉換、任務、原始回交、用量及結果。試跑預期先登記，失敗不靠改標籤或重抽答案掩蓋。這只是同課一對樣本的辨識證據，不代表全課或所有領域均已驗證。
