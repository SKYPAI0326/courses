# course-pdf 技能設計與整合分析

日期：2026-10-11。狀態：設計提案；未安裝技能、未實作轉製引擎、未產製 PDF。

## 1. 建議與需求邊界

新增 `course-pdf`，負責依既有網頁講義轉製、驗收、登錄與同步 PDF。沿用通用 PDF 檢視能力、課程 HTML 內容保護契約及 course-manager 的操作紀錄方式。轉製引擎與登錄資料放在課程專案內，技能負責選擇模式及執行流程。

使用者已明確要求：

- 教學內容依據現有網頁版講義；不能憑空生成內容。
- 系統涵蓋 PDF 設計、製作、管理，以及來源更新後的同步修正。
- 講義成品集中；教材素材、備份、驗收檔保留原位。
- 目前先設計技能，不產製 PDF。

設計假設：正式網頁 HTML 是轉製內容來源；教案 Markdown、大綱與課程目錄可協助確認單元身分及順序，但不能用來補寫網頁缺失內容。PDF 完整保留指定講義的教學內容。單頁、模組合冊或全課合冊由明確的來源清單決定，第一版不自動為每課產出所有組合。

## 2. 現有基礎與六個核心缺口

本次盤點範圍為目前可用技能、專案規範、相關產製腳本及既有搬移紀錄；沒有查到完整涵蓋本需求的專用 HTML 講義轉 PDF 技能。以下是能力缺口分析，不以缺乏權重依據的百分比估算完成度。

| 需求 | 已有能力 | 差異與補強 |
| --- | --- | --- |
| PDF 設計與基本檢視 | `pdf:pdf` 有渲染、文字擷取及視覺檢查；`kami` 有紙本排版體系；既有腳本有列印 CSS | 可重用工具；另定課程列印設定，避免套用會改寫或壓縮教材的文件製作流程 |
| ① 完整內容忠實轉製 | `course-html-contract` 保護網頁文字與結構；`build-course-page` 保護重要示範資訊 | 尚無 HTML → PDF 的內容保留契約、互動轉換規則與完整核對 |
| ② PDF 與來源逐一對應 | 已有 PDF 檔名、分類與搬移清單 | 尚無每份 PDF 的正式 HTML 清單、順序、區塊定位、來源版本及建置配方 |
| ③ 完整依賴版本追蹤 | `course-validator` 已使用來源／素材 hash 驗證 HTML 證據 | 尚無 PDF 的 HTML、CSS、圖片、字型、JS、列印設定及引擎版本依賴圖 |
| ④ 更新偵測與同步重建 | 網頁產製和運維技能有更新後的操作步驟 | 尚無 PDF 過期判定、受影響成品清單、增量重建及自動觸發 |
| ⑤ 成品登錄與可回復更新 | 已有集中講義庫、course-manager 搬移紀錄及 rollback | 尚無 PDF 來源狀態、現行／歷史版本及建置後發布交易；資料夾搬移工具不能直接代替 |
| ⑥ PDF 專用交付驗收 | 通用 PDF 視覺檢查、課程 HTML 驗收、相對連結檢查 | 尚無把內容忠實、缺字／裁切、圖片表格、合冊順序、PDF 連結與建置版本綁定的交付 Gate |

### 現有技能的整合邊界

| 技能 | 整合方式 | 不直接沿用的部分 |
| --- | --- | --- |
| `pdf:pdf` | PDF 結構、文字擷取、頁面渲染與視覺驗收 | 通用從內容另寫 ReportLab 文件的預設路徑、與來源字元衝突的文字替換要求 |
| `kami` | 參考閱讀層級、間距、字型與紙本品質；依課程需求選用設計細節 | 自動改寫、提煉、新增圖表或換用全新文件敘事；不整套接管轉製 |
| `course-html-contract` | 採用 layout-only 的文字保護原則及 DOM/parser 邊界 | 不為 PDF 改動正式網頁；其網頁 wrapper/RWD 檢查不能當 PDF 驗收 |
| `build-course-page` | HTML 更新完成後通知 PDF 流程重新檢查來源版本 | 教案轉 HTML 的背景壓縮規則不能延伸到 HTML 轉 PDF |
| `course-validator` | 參照 hash 綁定證據的格式，報告分別呈現 HTML 及 PDF 結果 | PDF PASS 不提升課程教學驗收狀態；HTML PASS 也不代表 PDF 可交付 |
| `course-ops` | 網頁下載位置及發布前 PDF 狀態檢查 | 目前相對 href 檢查不足以驗證 PDF 內部連結、外部網址與合冊錨點 |
| `course-run` | 有要求交付 PDF 的課程，在 HTML 驗收後接上 PDF 階段 | 不把 PDF 強制加入所有課程或取代原有教學 Gate |
| `skill-creator` | 後續建立精簡技能入口、必要參考及技能格式驗證 | 格式驗證通過不等於轉製流程已可用 |

## 3. 方案選擇

| 方案 | 優點 | 代價 |
| --- | --- | --- |
| 擴充通用 `pdf` 技能 | 入口少 | 課程專案規則會混入通用文件工具，仍需另建來源追蹤引擎 |
| 每課各自包裝 PDF 工具 | 可以保留特殊版面 | 來源、更新及驗收規則繼續分散，難以維護一致性 |
| 新增 `course-pdf`，搭配專案內共用引擎 | 規則集中；底層工具可沿用；能連結現有管理流程 | 需要新增 PDF 配方、登錄、同步和驗收實作 |

推薦第三方案。先做本地命令式流程，建立可重現的來源與驗收紀錄，再接自動觸發。

## 4. 技能與程式的責任分工

`course-pdf` 技能負責判斷任務範圍、確認來源及排版設定、執行流程、處理阻擋與回報證據。專案內的共用引擎負責解析 DOM、計算依賴指紋、渲染、驗收資料、更新索引及回復。

建議沿用專案已有的 Playwright／Chromium 路徑作為首個渲染實作，搭配 pypdf／Poppler 檢視工具。這是基於既有工具的整合選擇；複雜分頁、合冊錨點及互動內容仍需用實際講義試作確認。

建議資料位置，以下均為待實作的介面設計：

```text
courses/output/pdf/<slug>/<穩定檔名>.pdf           現行講義，沿用既有集中位置
courses/course-manager/registry/pdf/catalog.json  講義登錄與最後檢查狀態
courses/course-manager/registry/pdf/recipes/      每份講義來源清單、順序與排版設定
courses/course-manager/pdf-profiles/              共用列印 CSS 與設定
courses/course-manager/operations/pdf-build/      每次建置 manifest、驗收與回復紀錄
courses/course-manager/scripts/pdf_pipeline.py   共用引擎的建議入口
```

配方、設定與稽核格式應可版本管理；PDF 成品依現有發布政策處理。目前只有四份既有下載 PDF 開放 Git 追蹤，不能因新增技能就全面放行所有成品。歷史成品的保存位置與容量上限，在實作前明列；不把備份混入現行講義清單。

建議模式：`inventory`、`register-existing`、`plan`、`build`、`status`、`sync`、`verify`、`rollback`。`inventory`、`plan`、`status` 預設唯讀；需要寫報告時顯式選擇。這些名稱是擬議介面，目前不能當作已存在的命令執行。

## 5. 內容忠實契約與列印設計

- 確認 learner-facing HTML 與完整教學內容範圍；`.lesson-body`、`main` 等 selector 要實際核對，不假定所有課程相同。1159 個 HTML 候選檔不能直接視為 1159 份講義。
- 完整保留正文、提示、示範、Prompt、公式、程式碼、練習、答案、表格與圖片；不摘要、不潤飾、不自行補範例、不套用新的術語。
- 僅在暫存副本套列印樣式與已登錄的 UI 轉換；正式 HTML、JS、圖片及素材保持原始內容。
- details／頁籤內既有教材需展開並保留順序；可將原本頁籤標題映射為紙本小標。不能把未知 hidden 區塊全部顯示，也不能把所有 button／btn-* 連結全部移除。
- 影片、互動、動態載入內容僅使用原有可證明的文字、結果、圖片或連結。無法忠實轉製的必要內容標記 BLOCKED，交回來源責任人；轉製技能不撰寫替代教材。
- 密碼關卡、導覽與複製按鈕只有在確認為 UI 時可從暫存副本排除；本地轉製不改正式網頁的存取規則。
- 封面、目錄、頁碼、來源網址與版本時間可機械產生；課程名稱、章節名、作者、版權等資訊需來自來源或已確認登錄，不能自行宣稱。
- 原文特殊符號、數字及程式碼保留；href 保留來源目標，必要的網址重映射需留紀錄。長碼換行只改視覺，不改字元；寬表格可改分頁或橫式，不能縮小到不可讀或刪欄。

第一版建議 A4 直式、白底、繁體中文字型、清楚標題層級，正文先以 11–12pt 試作；大小依實際頁面驗收調整。沿用課程識別色，避免重新創作圖像。`screen`／`print` 可有不同背景、對比與頁距，但教學內容相同。合冊順序以已確認的來源清單為準，不以檔名字典排序推論課程順序。

轉換前後保存文字、區塊、圖片、表格、程式碼與連結清單，以及每個排除／轉換節點的來源定位和理由。DOM 比對、PDF 文字擷取及視覺檢查共同提供證據；單一字數或 hash 不足以證明 PDF 的內容與畫面完整。

## 6. 登錄資料、狀態與更新聯動

每份成品至少記錄：`artifact_id`、課程、變體、穩定輸出路徑、來源頁清單與順序、各頁內容 selector、來源定位、UI 排除／轉換規則、排版設定、依賴檔及 hash、引擎版本、建置時間、PDF hash／頁數、驗收紀錄位置。

建置 manifest 為每次執行的紀錄；catalog 為目前查詢用索引。來源檔案的實際 bytes/hash 才是版本依據，Git commit 僅作補充，不能用 commit 代表未提交的網頁內容。

| 狀態 | 意義 |
| --- | --- |
| `UNVERIFIED` | 已登錄既有 PDF，尚無有效來源與建置證據；不宣稱與現在網頁同步 |
| `CURRENT` | 有有效建置與驗收紀錄，且本次檢查的來源、依賴和設定指紋一致 |
| `STALE` | 曾有有效紀錄，但來源、依賴或設定已改變 |
| `BLOCKED` | 來源缺失、單元對應不明或必要互動內容無法忠實轉換 |
| `FAILED` | 本次渲染或驗收失敗；保留前次成品，記錄失敗原因 |

來源狀態與建置結果分開保存：重建失敗的舊 PDF 仍可能是 STALE；介面不能只顯示「有檔案」或用 FAILED 掩蓋其版本落差。CURRENT 顯示最後檢查時間，沒有持續觸發時只能表示該次檢查有效。

更新判定採完整依賴指紋：HTML、遞迴引用的 CSS／圖片／字型／JS／資料、來源清單及順序、轉換規則、列印 profile、引擎和渲染環境版本。JS 運算或動態載入的依賴需有明確清單；無法盤點就不能宣稱完整追蹤。外部資源需記錄取得內容及版本／hash，不能只記 URL。

來源頁連回自己產出的 PDF 時，該 PDF 是輸出連結，不列為來源 bytes 依賴，避免每次建置都造成自我過期；連結路徑仍要驗收。作為教材輸入的素材 PDF 則列入依賴。

聯動流程：

```text
HTML／資產／設定變更
  → 重算依賴指紋
  → 找出受影響的單頁、模組與合冊
  → 標記 STALE 並提出重建清單
  → 暫存來源快照、渲染、核對內容與視覺
  → 再確認來源指紋未於建置期間變動
  → 提升新版本、更新登錄及取用索引
```

先提供手動 `status`／`sync`。後續在網頁 builder／修復流程完成時呼叫檢查，並於交付前補做檢查，以涵蓋人工編輯；有持續同步需求再配置 watcher 或排程。Skill 本身不會持續監看。自動模式需沿用使用者已授權的課程、成品與觸發範圍，發現新增／刪除／改名的單元先列配方差異，不擅自改合冊內容清單。

## 7. 產製、驗收與安全提升

建置按 artifact 或課程設定鎖定，從固定快照渲染；確認圖片及字型載入完成，避免在空白或半載入狀態列印。失敗不覆寫現行成品，也不刷新其同步時間。

驗收需覆蓋：

1. 來源清單完整，順序正確，教學區塊、表格、Prompt、程式碼、圖片和素材連結沒有未說明遺失。
2. PDF 可開啟、有合理頁數；中文字元、公式及可搜尋／複製文字可用。對擷取差異只允許已定義的排版正規化，不能用刪除標點或改字掩蓋差異。
3. 全部頁面有渲染檢查證據；檢查缺字、重疊、裁切、空白頁、表格及程式碼跨頁。需要放大確認的問題頁必須逐頁檢視，未檢視項目如實記待驗。
4. PDF 內網址、下載檔及合冊錨點在新位置可用；相對網址需依來源 base URL 映射，轉換表留下證據。合冊需重映射本地錨點及跨頁連結，不能只合併 PDF bytes。
5. 建置前後來源指紋一致；成品 hash 與驗收 hash 相同；正式來源沒有被轉製程序修改。

通過後才用每檔原子替換及操作 manifest 提升新成品；多份成品與索引的更新視為可回復交易，不能宣稱跨檔案原子性。未完成整批提升前，不把該批標為 CURRENT。紀錄前版 hash、備份及後版 hash；回復前確認沒有後續修改，避免覆寫新工作。

網頁下載入口沿用已存在的穩定檔名。需要新增入口或改 href 時另列明確更新範圍；建置流程不擅自發布、commit、push 或修改整體 Git 忽略政策。

## 8. 既有 36 份 PDF 的接軌

搬移驗收已確認 36 份成品集中於 8 個課程／指南資料夾，全庫 158 份 PDF bytes 未改變。這份搬移證據不能當作轉製來源一致性的證據。

第一步只登錄成品及候選來源，全部先維持 UNVERIFIED；有有效舊 manifest 才進一步核對。對 Markdown 製作的素材文件、節錄／編輯版、速查表及 PDF-only 指南分別記錄來源類型，不為了統一規格假裝都有正式 HTML。

沒有 HTML 的指南保留原檔並標明不能自動重建；不逆向憑空生成網頁。已登錄的精簡版不能被完整版本悄悄取代。`simple-ai` 既有手冊內兩個舊下載網址留在問題清單，後續有授權重建時核對實際來源再修正。

# 課程講義 PDF 轉製

## 入口

從目前工作區定位課程網頁專案與 course-manager，讀適用 AGENTS.md。
確認使用者要盤點、設計、登錄、產製、同步、驗收或回復；沿用本次已授權範圍。
只要求分析或設計時，不執行產製。

檢查專案的 PDF 引擎、配方與規格是否已實作。缺少引擎就回報尚未可執行，
不虛構命令或把舊編輯型產製腳本當作忠實轉製器。

## 內容與版面邊界

正式 HTML 是教學內容來源。核對頁面身分、完整內容範圍及來源順序；
