# 課程生產工具與人機分工矩陣 v0.1

更新日期：2026-10-18
狀態：候選架構，尚未完成工具實測與現有系統差距盤點
上游規格：[課程生產能力規格 v0.1](course-production-capability-spec-v0.1.md)

## 1. 文件目的

本文件把 40 項課程生產能力分配給四種工作來源：人類、AI、規則型自動化與外部驗證。目的不是減少人工，而是讓判斷責任、加速方式與驗收證據清楚分開。

本版只提出工具類型與候選產品，不宣稱任何候選已被選定或已適用現有流程。

## 2. 分工代碼

| 代碼 | 名稱 | 定義 |
|---|---|---|
| H | 人類主責 | 對目標、取捨、風險與發布決定負責 |
| A | AI 協作 | 搜尋、整理、比較、草擬、轉換或生成候選；結果必須可覆核 |
| M | 機械自動化 | 依明確規則重複執行、檢查、比對或產生報告 |
| E | 外部驗證 | 領域專家、代表性學員、講師或其他獨立審查者 |

矩陣中的「主責」代表最終決定權；其他代碼代表可以參與，但不能取代主責。

## 3. 不可委派原則

以下工作必須保留明確的人類責任：

1. 決定課程要解決什麼問題、服務誰，以及哪些內容不做。
2. 接受法律、倫理、隱私、偏誤、安全與商業風險。
3. 判斷衝突證據與高影響資訊是否足以進入課程。
4. 確認學員成果標準符合真實需求。
5. 核准公開發布、重大更新與內容退役。

AI 可以提供候選、反例與差異，但不能成為自己輸出的唯一驗證者。NIST 的生成式 AI 風險資料將測試、評估、驗證與確認視為持續治理活動；UNESCO 也主張教育中的生成式 AI 採以人為本的方法，不能把人類責任交給模型。

規則型自動化適合回答「是否符合已寫下的規則」，不能單獨回答：

- 內容是否真實且適用。
- 解釋是否讓目標學員理解。
- 練習是否真的形成能力。
- 畫面是否在真實情境中好用。
- 這門課是否值得發布。

## 5. 工具組合候選

### 5.1 研究與來源層

| 工作 | 候選工具類型／產品 | 適合用途 | 不可取代的工作 |
|---|---|---|---|
| 網路與文件搜尋 | 瀏覽器搜尋、網站內搜尋、專業資料庫 | 發現第一手來源與替代觀點 | 判斷搜尋結果是否足夠與適用 |
| 來源保存 | Zotero | metadata、PDF、網頁快照、標籤、集合與引用 | 來源品質、主張真偽與課程取捨 |
| 來源內綜整 | NotebookLM 類 source-grounded 工具 | 對限定來源提問、整理主題與候選摘要 | 回到原文查核、跨來源風險判斷 |
| 結構化證據表 | CSV、試算表、SQLite 或 JSON | 主張—來源—日期—版本—用途追蹤 | 決定哪些欄位與狀態具有意義 |

Zotero 官方文件確認其可蒐集、組織、引用及分享研究來源，並保存網頁快照與 metadata；因此適合作為「原始來源層」候選，而非最終課程知識判斷器。

| 工作 | 候選工具類型／產品 | 適合用途 | 主要限制 |

| 工作 | 候選工具 | 適合用途 | 必要人工補充 |
|---|---|---|---|
| 版本管理 | Git | 差異、歷史快照、分支與回復依據 | scoped staging、審查、發布決定 |

Playwright 官方文件支援跨瀏覽器執行、headed／UI debug、trace 與全頁截圖；Lighthouse 可產生效能、可近用性、最佳實務及 SEO 報告。axe-core 官方說明也明確指出自動化只能找到部分 WCAG 問題，仍需要人工審查。

## 6. 建議的人機工作模式

### 模式 1：AI 先產生，人類核准

適用：提案選項、大綱候選、文案初稿、案例變化、錯誤假設、測試清單。

必要控制：

- AI 輸入必須附目標、來源、限制與輸出 schema。
- 輸出標示事實、推論、候選與未知。
- 人類核准後才進入下游。

### 模式 2：自動化先篩查，人類處理例外

適用：缺欄位、斷鏈、版本、術語、HTML、資產、效能與部分可近用性。

必要控制：

- 檢查可重跑並保存版本化結果。
- 規則與例外有 owner。
- 自動通過不能取代人工抽查與真實流程測試。

### 模式 3：人類先決策，AI 執行受限轉換

適用：已核准內容轉 HTML、格式轉換、元件套用、大量一致性修改。

必要控制：

- 先保存來源快照。
- 只允許指定轉換，不擴張內容。
- 轉換後執行內容與結構 diff。

### 模式 4：獨立人類驗證

適用：高影響內容查核、領域審查、視覺人工檢查、冷啟動學員試走與發布核准。

必要控制：

- 驗證者不能只看作者摘要。
- 使用正式候選、真實素材與目標環境。
- 問題記錄到具體頁面、任務、症狀和重現步驟。

## 7. 最小可行工具棧假設

這是待實測假設，不是採購建議：

```text
來源發現：瀏覽器／專業搜尋
來源保存：Zotero
證據與課程矩陣：Markdown + CSV／JSON
協作與核准：可追蹤修訂的文件或 issue 系統
AI 協作：可保存提示、來源、輸出與差異的 LLM／agent
視覺原型：Figma 類設計系統工具
網頁製作：文字編輯器／coding agent + 可重用元件
版本控制：Git
自動驗證：link／HTML／內容 diff + Playwright + Lighthouse + axe-core
人工驗證：SME review + 視覺檢查 + 冷啟動學員試走
發布維運：CI／manifest／備份／rollback／更新提醒
```

此工具棧成立的前提是資料能以開放或可匯出的格式流動，來源與核准紀錄不被鎖在單一聊天或單一 SaaS 中。

## 8. 工具實測設計

下一步不應直接導入全部工具，而應使用同一個小型課程任務做比較。

### 8.1 測試任務

選擇一個同時包含：

- 3 至 5 份外部來源。
- 一個需要交叉查核的主張。
- 一段概念解說。
- 一個完整示範。
- 一個引導練習和獨立任務。
- 一張圖或表。
- 一頁響應式 HTML。
- 一次自動 QA 與人工試走。

### 8.2 測量指標

| 面向 | 指標 |
|---|---|
| 正確 | 無來源主張、查核錯誤、版本錯誤、轉換缺漏 |
| 快速 | 實際工時、等待時間、重工次數、交接次數 |
| 好用 | 製作者找資料時間、學員完成率、阻擋數、回查時間 |
| 可追溯 | 能回到來源與核准紀錄的關鍵項目比例 |
| 可重現 | 第三人能否依相同輸入重跑並得到可比結果 |
| 可維護 | 單一來源變更時需要人工查找與修改的範圍 |

### 8.3 通過條件

- 工具節省時間時，不能降低來源追蹤或驗收品質。
- AI 輸出被接受前必須留下人類核准者與證據。
- 自動化報告必須能重跑、比較並定位到具體問題。
- 若工具輸出無法匯出、無法 diff 或無法回復，不能成為唯一資料來源。
