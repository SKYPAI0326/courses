# 文案迭代：專用執行規範 v0.4

本規範是課程迭代的文案專用設定，供評估、作者及覆核角色共同使用。沿用v0.7、v0.10及文案v0.3，不建立第二套評分或狀態控制器。處理既有講義的語氣、指涉、段落承接、完整敘事及冗餘；不是全課內容審查或技術認證。

本版把改寫及覆核的對象放回正文。已解決個別轉場、指涉或結尾問題，不等於整篇已從工作交辦變成學員能讀懂的文章。

## 範圍與分工

評估者先讀原稿、用途及必要來源，指出具體原文斷點，交接應修段落、修法、保留優點與核對方式。作者依交接產出可連續閱讀的完整Markdown候選，不交零碎替換句，不改正式HTML。作者比較後必須通過必要檢查及新上下文覆核；使用者負責H3閱讀確認。

允許依已有事實重排說明、補足指涉與關係、刪除無新增資訊的重述，保留有用的步驟清單。禁止另造情境、數據、技術原因、示範答案或操作，禁止變更學習目標、案例、數值、公式、提示詞、程式碼、操作順序、檢查點、預期結果、連結目的地與錯誤處理。缺少事實不能用自然語氣補成已知；不能靠刪掉難解內容來提高可讀性。

## 評估與交接

B依文案v0.3六項要求核對原稿，但先判主要正文如何用案例與理由推進理解；不能為六項各找一句話就判全文通過。交接指出真正承載教學的連續段落、讀者缺少的理解與可用的既有事實，同時保留原稿已有的優點。資料齊全、步驟完整或篇幅變長，都不代表閱讀脈絡成立。依章節用途判斷，不強加完整操作課結構。

評估與新上下文覆核須從頭連讀正文，不以六項各找到一句話或既有P已關閉代替整篇判斷。對每個主要區段，引用相鄰原文，說明讀者讀到這裡已理解什麼、下一段要求理解或操作什麼，以及正文如何交代兩者關係；特別檢查大段任務、限制、代碼與核對要求之間，是否只有指令或概括承接句。若移開標題與任務編號後，主要正文仍只是在交辦下一步，須記錄未解的B問題及其對學員理解的影響，不能判B L3。操作清單可保留，但不能替代讀者在操作前需要的背景、材料意義、判斷理由及範例解讀。不得要求每段都加敘事句，也不得為通過檢查而補無來源的故事或操作。

作者比較與新上下文覆核先只讀候選正文，找出主要承載教學的連續段落，尤其是要求學員操作、判斷與交付的段落。逐字引用這些完整段落，說明讀者在操作前能否從正文理解材料、理由、例子或判準；不能挑後面一個解釋句替前面的交辦段落背書。若主要段落仍靠「先做、再做、必須、不能、交付」推進，即使後面附有摘要或個別轉場，也須記未解B問題，不能給B L3。先完成這項候選本身的閱讀判斷，再看原稿、來源、舊P/Q與檢查結果。報告保留原文引文與判斷即可，不再填逐標題`reading_audit`；人工連續閱讀仍決定H3。

A核對文案涉及的事實與一致性；C核對本章用途及既有教學價值是否保留。三原則仍按v0.7判級，必須明示本次只屬文案範圍，不宣稱工具最新或實際可操作。必要未知記Q，不因本次沒做平台實測就虛構缺失；若未知直接影響要寫的解釋，列必要Q並停待補證。

操作指令與起始狀態核對：遇到取消、改成、保留、還原等變更指令，評估與覆核都須核對前文起始狀態、實際需改動的項目與目標狀態。結果正確，不代表變更敘述正確；發現不一致時，列出兩處原文及讀者影響。不得僅因主線成立而忽略局部條件表達問題，也不要求每份教材必須找出問題。

若發現已確認的素材缺失、技術矛盾、錯誤數值、操作缺漏或需要改教學設計，記P、提供原文及回交原因，**next_fix必須為null**，由現有控制器停H2交人工決策；即使同時存在可潤稿處，也不能將完整技術修復偷偷納入本模式。必要Q依既有規則停待補證。不得把已知缺失改標未知以規避處理。這些分類依模型與覆核辨認，程式本身不保證理解所有語意。

交接報告固定說清楚：讀者在哪裡斷線、原文位置、可以依哪些現有事實改善、哪些內容必須保留、哪些問題超出文案範圍。沒有必要文案缺口就不強製造候選。

## 候選、比較與停止

候選保留完整正文、提示詞及案例；只改與已確認缺口相關的文字。HTML來源只輸出Markdown閱讀候選，不重製網頁互動；正式套回HTML需另行授權並遵循course-html-contract。

作者交候選時，要讓學員能連續讀出問題如何出現、材料為何在此使用、示範中的具體判斷如何支持下一步，以及結尾得到什麼理解。須直接重寫原稿中承載主要教學的交辦段落：用已有案例事實說清楚判斷如何得出，再讓學員照既有操作去做；完整保留必要指令、順序、限制與交付物。只在任務清單前後增加轉場句、術語解釋或摘要，卻讓主要段落繼續堆疊指令，不算完成。若原稿與必要來源沒有足以說明判斷的事實或示範，依前述P／Q邊界停下回交，不虛構內容。

前後比較及覆核逐項呈現原句、候選句、理解關係是否改善，另核對事實、操作及有用解釋是否退步。機械保留檢查只會發現指定文字消失，不能發現所有新錯誤；覆核須看全文、數值、順序、連結目標及新增的無據解釋。引用本機檔可改為同一目的地的絕對路徑，但不能換指向。

既有P／Q的ID、描述與核心／必要性由控制器保留。作者或覆核若以同義文字重述已登記描述，原始回交與報告仍保存，控制器在接收時沿用原描述並另記正規化；不得因此更改問題身分、open狀態或判級。缺少既有ID或變更核心／必要性仍拒收。

最多兩版、八次模型呼叫，low；不是每次必須產出兩版。第一版達到本次標準便停止等待H3；若需要第二版，僅處理可分離的未解文案問題。兩版用完仍有問題、相同失敗再次出現、必要事實缺失或改動範圍需擴大時，沿用既有停止規則，不自動換模型、加額度或重開run。

報告中的PASS／MAJOR／BLOCK是文案編輯結論，不能代替控制器狀態：PASS仍須檢查與覆核且候選須H3；MAJOR須有具體文案P與修法；BLOCK須記清已知P或必要Q，交人工處理，不以文案掩蓋。

使用者對指定候選的實際連續閱讀回饋若指出主要正文仍像待辦清單，應記錄回饋、候選版本與具體區段，將其視為本次閱讀判斷未通過的證據；既有AI的B L3或局部P已解不能推翻該回饋。不得代填H3、改寫舊模型報告或重置既有run的用量；依當前停止狀態與剩餘額度決定能否續作。
