# 文案迭代：專用執行規範 v0.5

沿用[v0.4](course-copy-profile-v0.4.md)的事實保留、完整候選、角色分工與停止規則；以下規定優先。新run使用copy-v0.5，舊run及其規範雜湊、候選用量不重綁。仍使用原模型、low、兩版與八次呼叫上限，不增加角色或審核輪次。

## 最基本的成果：學員讀得懂

文案迭代首先修正學員無法理解的文字。資訊齊全、句子變長、局部問題關閉、結構檢查通過，都不能取代閱讀判斷。評估者須依指定學員背景連讀全文，不能借用自己已知的案例背景替正文補意思。

先查讀者在哪裡失去理解，再選擇適合的改寫：誰遇到什麼情況、正在看什麼材料、材料說明什麼，以及為何要採取下一步。不是每段都套同一組欄位。現有來源已能解釋時，直接把關係寫清楚；只有確實缺必要事實才回交，不能把普通文案問題一律當技術缺口。

內部製作要求要翻成學員需要理解的事。例如「撤除逐列提示的整合練習，舊包驗證來源重查」沒有交代學員現在拿到什麼，可以依既有事實改成「這次仍用前面讀過的資料，但不再逐項提示你去哪裡找。請自己回到原文，確認哪些消息仍然有效，再整理摘要。」這是改寫原有要求，不新增案例或操作。

必要代碼、術語與檔名保留，在首次影響理解時交代用途。條列適合呈現步驟或並列條件就保留；不能把五項指令併成長段落，便宣稱已成為敘事。只補引言、轉場或摘要，而主要段落仍不知所云，也不能通過。

## 將閱讀判斷接入控制器

作者比較及新上下文覆核都須交`reading_decision`：

- `verdict`：supported或gap；`explanation`說明整篇能否讓指定學員理解。
- `passages`：選擇真正承載操作、判斷或交付的完整段落，逐字引用`quote`，以`reader_understanding`說明讀者僅依正文能理解什麼。
- 仍有缺口就在`remaining_gap`寫明缺少的關係，`problem_id`指向本次仍open、列入B的問題；無缺口留空，ID為null。

先完成候選閱讀，再比對原稿與來源；不逐標題湊引文、不挑一句轉場替整段背書。評估整篇，引用關鍵證據，而非把報告做成另一份章節清單。supported代表AI閱讀判斷，仍停H3，不代表真人認可。

控制器會拒絕缺少閱讀依據、捏造引文、缺口沒有open B問題，或一面承認閱讀缺口一面給B L3的回交。程式只能核對證據存在及前後一致，不能自動證明「講人話」；不能把這些檢查包裝成品質保證。使用者否定候選時，保存版本與原話，不能用AI評分反駁，也不重開run重置用量。

## 完成範圍與交付狀態

單章是執行單位，不是縮小使用者要求的理由。使用者指定整課時，開始即從實際課程首頁／目錄列出全部授權章節，沿用同一份逐章紀錄，依序接續既有run。列明未開始、候選待確認、已接受、已套用及阻塞原因；沒有套用的章節不得算已修正。按原本授權及資源限制執行，不自行擴大模型總呼叫額度。

回報清楚區分：候選完成、正式講義已套用、已提交／推送、公開網站已更新。若已授權正式套用或發布，完成必要檢查後直接接續，不重問既有授權。只有工作分支push不能稱上線；須確認網站實際來源分支及部署結果，並逐頁比對公開內容與本次版本。未完成頁面須列出，不能以部分通過或網站HTTP 200替代整課完成。

套回HTML前保留原操作元件，包含執行JS前看似空白的動態表單容器。套用程式拒絕遺失原元件；瀏覽器仍須核對實際操作，不能只查script存在或頁面無溢出。
