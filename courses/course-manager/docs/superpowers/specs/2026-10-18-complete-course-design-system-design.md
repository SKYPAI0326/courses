# 完整課程設計系統設計

**日期**：2026-10-18
**狀態**：完整設計已核准，下一步為實作計畫
**範圍**：從新課提案、研究、規劃、內容與素材製作、網頁成品、獨立試學，到授權發布及維護
**取代關係**：本文件取代〈課程設計 Skill 母群系統設計〉的最終系統決策；舊文件保留為 G0–G2 基礎階段的歷史紀錄

## 1. 設計目標

這套系統要穩定產出一份學員可以獨立閱讀、跟做、練習、排除問題並完成學習成果的網頁課程。系統同時追求：

- **正確**：重要事實、工具版本、操作結果、限制及風險都有來源或實測證據。
- **快速**：以單一契約、自動調度、代表單元試製及明確責任邊界降低返工。
- **好用**：學員知道為何要做、從哪裡開始、完成後應看到什麼，以及失敗時如何恢復。

速度不能取代正確性與可學習性。文件齊全、文字流暢、HTML 能開啟或 lint 通過，都不能單獨證明課程完成。

## 2. 核心原則

1. 先確認學員、情境、成果與限制，再開始研究與製作。
2. 從真實工作與可驗證成果倒推課程，不從舊模板或既有課程複製規格。
3. 通用流程與品質標準固定；教學方法、素材與視覺依主題自動適配。
4. 課程正文是給人閱讀與操作的成品，不是 schema、待辦事項或名詞清單。
5. 問題回到負責的上游階段修正，不在末端反覆補文字或 CSS。
6. 先完成風險最高的代表單元，通過後才製作全課。
7. 發布前由未參與製作的 AI 以學員身分完成實際任務。
8. 內部產製可依證據自動前進；涉及重要判斷或外部狀態變更才詢問使用者。
9. 所有狀態、證據與變更影響都可追溯，不能由敘事掩蓋缺口。

## 3. 明確反目標

系統不得產生下列結果：

- 只有章名、名詞、提醒與待辦事項，沒有可連續閱讀的教學。
- 直接把內部編號、縮寫或編碼式檔名暴露給學員。
- 給出操作要求，卻沒有起始狀態、目的、預期結果與檢查方式。
- 用固定字數、卡片數、段落數或模板欄位假裝品質已受控。
- 缺少素材、權限、示範或實測時，以文字描述假裝已完成。
- 同一工作流只更換案例名稱後重複成多個單元。
- 為了視覺簡潔，刪除理解與操作所需的內容。
- 由作者自己的檢查冒充陌生學員試學或真人驗證。
- 未經授權即上線、公開網址、設定密碼、修改入口或覆寫既有發布內容。

## 4. 系統邊界

### 4.1 新課主流程

```text
需求問答
→ 外部研究與工具實測
→ 課程藍圖
→ 完整內容與素材
→ 代表單元網頁試製與獨立試學
→ 全課製作與完整試學
→ 待發布版本
→ 使用者授權後發布
→ 定期唯讀維護檢查
```

### 4.2 既有課程支線

`course-repair` 保持獨立入口，執行 scan → plan → backup → fix → verify。它可以共用研究、內容、網頁與驗證能力，但不能把舊課直接塞入新課模板。

若診斷發現學員、成果、時數或全課架構本身需要重新定義，修復流程停止，改由新課主流程建立新契約。

### 4.3 外部操作邊界

以下行為即使所有 Gate 都通過，也必須取得使用者最後授權：

- 正式上線或公開新網址。
- 設定、變更或注入密碼與存取規則。
- 修改統一入口、課程清單、正式索引或 sitemap。
- 覆寫已發布內容或觸發正式部署。
- 使用付費服務、帳號權限或其他會產生外部影響的操作。

系統可以在授權前建立完整待發布版本、執行唯讀檢查並產出操作提案。

## 5. 母系統與能力分工

`course-run` 是唯一母入口，負責問答、契約、調度、Gate 狀態、證據索引、失效傳播與使用者決策。專業工作交給以下能力：

| 系統 | 主要階段 | 責任 |
|---|---|---|
| `course-run` | 全流程 | 建立契約、判斷是否詢問、調度與治理 |
| `course-researcher` | G1 | 外部研究、來源查核、真實工作分析與工具實測 |
| `course-pm` | G2 | 成果倒推、課程架構、進程、時數、素材與試製選擇 |
| `course-designer` | G3 | 完整教學正文、示範、練習、檢查與修復 |
| `build-course-page` | G4–G5 | 課程專屬視覺系統、網頁與素材整合 |
| `course-validator` | G4–G6 | 結構、保真、執行、獨立試學及發布證據驗證 |
| `course-ops` | G6 | 連結、入口、密碼、索引、部署、版本與回復 |
| `course-refresh` | 上線後 | 唯讀時效、連結、介面與教材可用性檢查 |
| `course-repair` | 獨立支線 | 既有課程診斷、可回復修正與重驗 |

能力不必各自變成新 Skill。只有具有獨立輸入輸出、專門工具及清楚驗收責任時才拆分。

## 6. 自動調度與詢問政策

### 6.1 可自行決定

只要輸入完整、證據足夠且沒有外部風險，母系統可以自行：

- 選擇研究問題、可靠來源與實測方式。
- 選擇課程結構、代表單元、教學方法與練習形式。
- 決定內容所需的圖、表、截圖、範例檔及練習素材。
- 根據主題與學習任務設計課程專屬版型。
- 在 Gate 通過後調度下一階段。
- 對失敗結果定位責任層並退回重做。

### 6.2 必須詢問使用者

以下情況必須停止並詢問：

- 缺少會改變設計的學員、情境、成果或限制資訊。
- 存在數個會實質改變結果的重要取捨，且無證據可自行判斷。
- 必要素材、帳號、權限、環境或真實資料無法取得。
- 涉及付費、著作權不明、敏感資料或高風險決定。
- 即將執行第 4.3 節所列的外部狀態變更。

母系統一次只提出一份具體決策摘要，包含缺口、影響、單一建議主方案、理由與確認後的續行點。已知資訊不重問，也不為了形式強迫使用者挑選多個方案。

## 7. 課程契約與狀態模型

### 7.1 單一狀態來源

每門課只有一份機器可驗證的課程契約，長篇正文與報告保存在適合的檔案中，由契約記錄相對路徑、SHA-256、版本及產生時間。

契約至少包含：

```text
identity
governance
gates
G0_requirements
G1_research
adaptation
G2_architecture
G3_lesson_design
G4_pilot
G5_production
G6_release_maintenance
evidence_index
changes
external_actions
maintenance
```

### 7.2 Gate 狀態

| 狀態 | 語義 |
|---|---|
| `NOT_STARTED` | 尚未開始，不能交給下游 |
| `IN_PROGRESS` | 正在產製或修正 |
| `PASS` | 交付物、必要證據及驗證全部通過，可自動進入下游 |
| `FAIL` | 已完成檢查但不符合通過條件，必須修正並重驗 |
| `BLOCKED` | 缺必要資訊、素材、權限、環境、證據或決策 |
| `STALE` | 上游實質變更使現有成果或證據失效 |

Gate 是否通過與外部操作是否獲准是兩件事。發布相關動作使用 `PUBLISH_APPROVAL_REQUIRED` 及獨立的授權紀錄，不能用人工簽核阻擋每一個內部 Gate。

### 7.3 Gate 證據

每個 Gate 至少記錄：

- owner、輸入與相依 revision。
- 交付物與 evidence IDs。
- 驗證方式、結果、執行者與時間。
- 未解風險、非阻擋未知及 blocking issues。
- 影響的下游 Gate。
- 自動通過或人工決策的理由。

### 7.4 變更傳播

實質變更必須建立 change record，找出最早受影響的 Gate，將其設為 `IN_PROGRESS`，並把受影響的下游 Gate 設為 `STALE`。舊成果與證據保留供追溯，不能直接覆寫歷史。

錯字與不改變語義的排版修正只執行對應技術回歸，不觸發整條流程重做。

### 7.5 既有基礎遷移

目前 G0–G2 基礎採 `DRAFT`、`REVIEW`、`APPROVED`、`BLOCKED`、`STALE`。實作新版時以遷移器保留資料與歷史：

- 有完整證據的 `APPROVED` 轉為 `PASS`。
- `REVIEW` 轉為 `IN_PROGRESS` 並重新執行該 Gate validator。
- 尚未產製的 `DRAFT` 轉為 `NOT_STARTED`；已有內容者轉為 `IN_PROGRESS`。
- `BLOCKED` 與 `STALE` 保留語義。
- 原核准人與時間保留為歷史，不再作為內部自動前進條件。

## 8. 七個 Gate

### G0：需求契約

母系統透過適應式問答確認：

- 目標學員與現有能力。
- 使用情境與要解決的問題。
- 最終可觀察成果及實際使用方式。
- 時數、裝置、工具、權限、交付與其他限制。
- 成功證據、已知事實、假設與未知。

**通過條件**：能清楚回答「誰在什麼情境下，最後能獨立完成什麼，以及如何知道完成了」。仍有會改變課程方向的重要未知時必須 `BLOCKED`。

### G1：外部研究與工具實測

輸出包含：

- 研究問題及其對應的設計決策。
- 來源、擷取日期、適用版本、上下文、信心水準與衝突。
- 真實任務、交付物、常見錯誤、環境與限制。
- 關鍵工具的實際輸入、操作、輸出、失敗及恢復紀錄。
- 對架構、練習、素材、風險與維護週期的具體影響。

**通過條件**：核心主張有可靠來源，關鍵路徑已實測，高變動內容有版本與複查條件。需要登入或權限卻無法實測時不得用二手文章代替。

### G2：課程藍圖

從最終成果倒推：

- 能力、先備、練習及評量證據。
- 單元順序、依賴、時數及不同學習成果。
- Demo、Together、Solo 的安排。
- 素材、環境、風險與備援。
- 主題適配設定及代表單元選擇。

**通過條件**：每個單元都有必要且不同的能力進展；前一階段確實提供下一階段需要的能力與材料；整體可在限制內完成。

### G3：完整內容與素材

每個單元必須具備：

- 情境、用途、起始狀態與完成物。
- 必要概念、判斷方式及完整示範。
- 引導練習、獨立運用及可觀察檢查點。
- 預期結果、驗收方式、常見錯誤與恢復路徑。
- 可連續閱讀的正式正文。
- 已完成或可驗證取得的教材素材。

**通過條件**：學員不依賴作者口頭補充即可理解；沒有佔位內容、內部待辦、名詞堆疊或缺乏前因後果的指令；核心素材可實際開啟或操作。

### G4：代表單元試製

系統選擇綜合風險最高的單元，完成真正的 learner-facing 網頁、視覺系統、素材與操作環境。風險包含工具不確定性、內容複雜度、素材依賴、版面難度、後續單元依賴及失敗成本。

驗證包含：

- 內容保真、導覽、素材取得與真實操作。
- 手機、平板及桌機的核心學習路徑。
- 鍵盤操作、焦點、對比、語意順序及其他適用的無障礙要求。
- 未參與製作的 AI 完成代表單元。

**通過條件**：試學者能從入口完成任務、產生成果、判斷正確與依教材修復合理錯誤。G4 未通過前禁止批量製作。

### G5：全課製作與整合

- 依已驗證的視覺與互動原則擴展全課，但保留各單元需要的差異。
- 檢查術語、素材、案例、進程、跨單元依賴與最終成果的一致性。
- 執行全課內容保真、技術、連結、資產、渲染與無障礙檢查。
- 由未參與製作的 AI 從正式入口完成整門課與最終成果。

**通過條件**：完整路徑可連續完成；沒有換標籤重複、失效素材或作者專屬知識；最終成果符合 G0 定義的驗收方式。

### G6：待發布、發布與維護基準

- 彙整教學與技術證據。
- 檢查連結、SEO、效能、存取、密碼、入口、索引、sitemap、部署與回復資訊。
- 建立版本、查核日期、維護觸發條件及退役方式。
- 產出明確的外部操作提案。

**通過條件**：待發布成品及回復方案完整，且發布後能追蹤來源、工具、頁面與素材版本。G6 `PASS` 只代表可發布；實際發布仍須使用者授權。

## 9. 通用核心與主題適配

### 9.1 所有課程共同標準

- 真實、可驗證的學習成果。
- 概念、完整示範、同步操作、獨立練習與驗收形成連續路徑。
- 重要內容具有來源或實測證據。
- 自然、連貫且足以支持理解的正文。
- 可取得的素材、清楚導覽、響應式及基本無障礙。
- 發布前的獨立 AI 完整試學。

### 9.2 自動適配輸出

G1–G2 依實際條件產生 `adaptation`，至少記錄：

- 真實問題、任務與交付成果。
- 學員差距與需要的支援量。
- 任務偏向概念、判斷、操作、創作或綜合活動。
- 工具變動速度、輸出不確定性與錯誤成本。
- 帳號、裝置、資料、素材、權限與備援。
- 最適合的示範媒介、練習形式及成果驗證。
- 需要複查的內容與觸發條件。

主題名稱只是 metadata，不能作為套用固定模板的開關。混合型課程逐單元判斷。

### 9.3 常見主題的設計含義

- 軟體操作：介面版本、起始檔、操作結果、錯誤復原與裝置差異。
- 生成式 AI：模型與日期、輸入條件、輸出變異、判讀方式、失敗案例與人工驗證。
- 數位行銷：真實商業情境、客群、平台規則、資料判讀、法規與成效證據。
- 溝通與軟技能：情境演練、決策理由、觀察指標、回饋標準與跨情境遷移。

## 10. 可學習內容契約

每個單元都要讓學員完成以下歷程，但不強迫使用固定標題或機械模板：

1. 理解目前情境、已有材料及要解決的問題。
2. 學會完成任務所需的概念與判斷方式。
3. 看見包含輸入、行動、理由、結果與驗證的完整示範。
4. 跟著完成一次，途中有可觀察的短檢查點。
5. 獨立完成不同但可遷移的任務。
6. 根據明確標準驗證成果。
7. 找出常見失敗原因並恢復。
8. 把成果銜接下一單元或真實工作。

文案以功能驗收：

- 操作指令交代目的、起始狀態、動作及預期結果。
- 專有名詞首次出現時，以目標學員能理解的方式說明。
- 範例完整走到成品，不只展示片段或理想答案。
- 表格、清單、提示框只在比連續段落更適合時使用。
- 移除大部分標題後，正文仍應基本連貫。
- 驗收規格留在系統層；學員頁面呈現自然教學與操作引導。

沒有具體的正確性、理解或可執行性問題時，不為了「更精簡」或「更像模板」改寫正常正文。新證據沒有增加時停止反覆潤飾。

## 11. 視覺系統與教材資產

### 11.1 每門課可重新設計整體版型

`build-course-page` 根據主題、學員、內容密度、任務類型、操作比例與主要裝置建立課程專屬視覺系統，不複製舊課版型作為預設答案。

共同底線包括：

- 學員能辨識位置、進度、操作區、範例、練習及驗證。
- 長文、表格、程式碼、提示詞、截圖與下載素材有適合的呈現。
- 手機、平板及桌機都能完成核心學習。
- 色彩、字級、焦點、鍵盤操作與內容順序符合適用的無障礙要求。
- 裝飾不干擾操作，視覺層級反映內容關係。
- HTML 忠實保留已核准內容，不能為了版面刪除必要教學。

### 11.2 資產管線

流程圖、示意圖、介面截圖、範例檔、練習資料與參考成品原則上由系統自行取得或製作。資產清單記錄：

- 教學目的、使用位置及對應單元。
- 來源、授權或自行製作狀態。
- 適用工具、版本與日期。
- 學員取得方式及描述性顯示名稱。
- 對應示範、練習與預期結果。
- 實際開啟、下載或操作結果。

涉及付費、登入權限、著作權不明或無法實際操作時必須詢問，不得以空白佔位或敘述替代成品。

## 12. 獨立 AI 試學

### 12.1 獨立性

試學 AI 不得參與該課程的研究、規劃、撰寫、網頁製作或作者自驗。它只能取得學員實際能看到的入口、頁面、素材、工具與內建說明，不得讀取：

- 課程契約與內部規格。
- 作者筆記、製作紀錄或隱藏提示。
- 標準答案與 validator 的內部判定資料。
- 先前製作者的對話上下文。

### 12.2 試學紀錄

每次試學保存：

- 入口與環境、裝置、工具及版本。
- 每一步實際行動與判斷。
- 使用過的學員可見提示及次數。
- 疑問、阻礙與恢復過程。
- 實際產出的檔案或成果。
- 依課程標準得到的驗證結果。

### 12.3 直接失敗條件

- 必要素材、權限或起始狀態不存在。
- 必須猜作者意圖才能繼續。
- 教材與實際工具或結果不一致。
- 能照著點擊，卻不知道理由或判斷方法。
- 產生成品後沒有方法確認是否正確。
- 必須取得學員頁面以外的資訊。
- 核心任務只能由試學者自行發明替代流程。

### 12.4 證據成熟度

| 等級 | 意義 |
|---|---|
| `STATIC_VALIDATED` | schema、結構及確定性規則通過 |
| `EXECUTION_VALIDATED` | 關鍵工具、素材與操作實際執行通過 |
| `INDEPENDENT_AI_VERIFIED` | 未參與製作的 AI 完成指定或完整學習路徑 |
| `HUMAN_VERIFIED` | 真實目標學員完成測試 |

各層不能互相冒充。沒有真人測試時，系統最多宣告 `INDEPENDENT_AI_VERIFIED`。

## 13. 失敗回流

| 問題來源 | 回流位置 |
|---|---|
| 資料錯誤、過時、來源不適用或工具不符 | G1 |
| 成果、順序、難度、時數或依賴不合理 | G2 |
| 解釋、示範、練習、檢查或修復不足 | G3 |
| 導覽、版面、互動、響應式或素材取得失敗 | G4／G5 |
| 入口、權限、連結、索引或部署問題 | G6 |

修正上游後，所有受影響的下游證據設為 `STALE` 並重新驗證。下游不得自行補寫尚未獲得的事實、素材或教學理由。

## 14. 現有 Skill 整併

### 14.1 核心保留

- `course-run`：重構為條件式自動調度的母系統。
- `course-researcher`：保留 G1 專業責任。
- `course-pm`：專責 G2，不重做需求訪談。
- `course-designer`：專責 G3 完整正文與教學資產需求。
- `build-course-page`：負責 G4–G5 課程專屬視覺與網頁成品。
- `course-validator`：整合內容、保真、執行與獨立試學驗證。
- `course-ops`：整合 G6 發布與外部操作。
- `course-refresh`：只做唯讀維護掃描。
- `course-repair`：保留獨立修復入口。

### 14.2 合併與相容層

- `course-copywriter` 的通用文案能力納入 `course-designer` 與 `course-validator`；舊入口只保留診斷式編輯相容性。
- `course-reviewer` 的 content／fidelity 能力併入 `course-validator`；舊入口暫作相容層。
- `course-register` 的入口、密碼與登錄能力併入 `course-ops`；舊入口暫作相容層。
- `course-html-contract` 作為網頁製作、驗證與修復的共用技術契約。
- `course-handout-designer` 作為教學方法與內容結構資源，不作第二作者。
- `course-typography-fixer` 與 `course-pdf` 保持選用，不進入核心必經鏈。

不另建版型 Skill；視覺方向由 `build-course-page` 依契約與 adaptation 決定。

## 15. 發布與維護

### 15.1 發布

`course-ops` 先產生唯讀提案，列出即將修改的檔案、入口、密碼、索引、部署目標、回復方式及驗證命令。只有與使用者核准內容完全相符時才執行。

發布後保存：

- 發布 revision、時間與操作者。
- 實際網址、存取方式與驗證結果。
- 變更 manifest、備份與回復方法。
- 對應的 G6 證據與授權紀錄。

### 15.2 維護

上線後定期執行唯讀檢查：

- 來源與事實的新鮮度。
- 外部連結、下載與嵌入內容。
- 軟體、模型、介面、方案與平台規則。
- 素材能否取得及操作。
- 頁面技術狀態與學習入口。

報告標示影響範圍、嚴重程度、最早應回流的 Gate 及單一建議修訂方式。未經授權不得修改或重新發布。

## 16. 實作與驗證策略

實作順序由下一份 implementation plan 細化，設計層固定以下原則：

1. 為目前 G0–G2 行為建立與保留基準測試。
2. 先遷移契約與狀態模型，再改母系統調度。
3. 逐一接上 G3、G4、G5、G6；一次只改一個責任邊界。
4. 每個 Skill 先寫會失敗的行為測試，再進行最小實作及回歸。
5. 舊名稱先作相容入口；全流程證明完成前不刪除。
6. 安裝正式 Skills 前比對套件內容、執行 validator 並保留可回復備份。
7. 不在目前 main 工作區的無關變更上改檔或使用廣泛 staging。

必要測試至少包含：

- 證據完整時 Gate 自動 `PASS` 並調度下一階段。
- 缺必要資訊、素材、權限或實測時正確 `BLOCKED`。
- 外部操作在沒有明確授權時無法執行。
- 上游實質變更會使正確的下游範圍 `STALE`。
- 正常正文不會被改成片語、名詞或待辦清單。
- HTML 沒有遺失完整示範、表格、提示詞、公式、素材或驗收說明。
- 代表單元未通過時無法開始全課批量製作。
- 製作 AI 不能簽發獨立試學通過證據。
- `course-repair` 仍能依獨立流程操作。

## 17. 系統完成定義

只有同時具備下列證據，才能宣告完整課程設計系統完成：

- 母系統能從適應式問答建立有效 G0 並自動調度 G1–G6。
- 課程契約可驗證、追溯、傳播失效並區分 Gate 與外部授權。
- 現有 Skill 已依責任整併，沒有平行狀態或重複核心流程。
- 一門全新代表性課程從 G0 走到 G6 待發布狀態。
- 該課有完整 learner-facing 網頁、素材、最終成果及 `INDEPENDENT_AI_VERIFIED` 證據。
- 發布操作能在未授權時停止，授權後可執行並回復。
- 一門既有課程通過 `course-repair` 相容性驗證。
- 定期唯讀維護能發現老化並提出回流 Gate，不自行改檔。

## 19. 已核准決策摘要

- 系統目標是完整 learner-facing 網頁課程，學員可以獨立完成學習。
- 新課主流程與既有課修復分離。
- 母系統自動調度，只有資訊不足、重要判斷、付費／權限／著作權及外部變更時詢問。
- Gate 依證據自動通過，不逐關等待人工核准。
- 每門課可重新設計整體版型，由系統依主題自行決定。
- 教材資產原則上由系統自行取得或製作並實際驗證。
- G4 與 G5 都必須由未參與製作的 AI 以學員身分操作。
- 正式發布及其他外部狀態變更一律需要最後授權。
- 上線後執行定期唯讀維護檢查，修訂與重新發布仍需授權。
