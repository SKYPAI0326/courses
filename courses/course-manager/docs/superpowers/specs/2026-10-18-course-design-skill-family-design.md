# 課程設計 Skill 母群系統設計

**日期**：2026-10-18  
**狀態**：設計決策已逐項核准，待撰寫實作計畫  
**範圍**：從零建立新課程的主流程，以及既有課程修復支線的銜接  

## 1. 目的

建立一套能持續產出正確、好用且製作效率可控的課程設計系統。系統必須先理解學員與現實工作，再形成課程架構、完整教學內容及成品；不能以格式齊全、文字流暢或機器檢查通過代替真實可學、可做與可驗證。

本設計不直接改善任何一門既有課程，也不照抄目前的課程規格。既有 Skill 只在新架構確立後進行能力對照、保留、合併或改造。

## 2. 頂層成效

### 2.1 正確

- 重要事實、工具版本、操作結果、限制與風險有可追溯證據。
- 課程承諾的成果、教學活動及驗收方式互相對應。
- 工具或生成式 AI 課程須實際操作代表性任務，不能只整理網路資料。
- 未查明的重要資訊明示為未知或阻擋，不由流暢文案補寫。

### 2.2 好用

- 學員知道自己正在處理什麼情境、手上有什麼、要留下什麼成果。
- 學員看得懂概念、示範與步驟之間的關係。
- 學員能開始、完成、判斷結果，並在失敗時回到明確位置修復。
- 課程正文保留自然段落、完整推理與教學節奏，不被規格欄位或待辦清單取代。
- learner-facing 網頁須具備可讀性、響應式呈現及適用的無障礙驗證。

### 2.3 快速產出

- 以單一課程契約、明確責任邊界與結構化交接降低返工。
- 全課批量製作前先完成一個代表單元，驗證最危險的假設。
- 確定性要求交由 schema、腳本與 validator；需要判斷的品質保留證據與核准責任。
- 速度不得覆蓋正確性或學員可用性。

## 3. 系統邊界

### 3.1 主流程

主流程只處理從零開始的新課程：

```text
需求問答
→ 現實研究與實測
→ 課程藍圖
→ 單元與內容設計
→ 代表單元試作
→ 全課製作
→ 發行與維護
```

### 3.2 修復支線

既有課程由 `course-repair` 作為獨立入口。它共用研究、內容、製作及驗證能力，但不把舊課直接套入新課模板。若診斷顯示需要重新定義受眾、成果或全課架構，修復流程停止，另開新課設計流程。

### 3.3 不在本系統內

- 為了增加 Skill 數量而拆角色。
- 以固定字數、卡片數、段落數或選項數評定品質。
- 在成品末端以文案或 CSS 掩蓋上游設計缺口。
- 未經核准的公開發布、付費服務、帳號操作或外部訊息。

## 4. 核心架構

### 4.1 母 Skill

沿用 `course-run` 作為唯一公開入口並重構其內部行為。它負責：

- 適應式需求問答。
- 建立與維護課程契約。
- 判定目前 Gate、相依性與阻擋。
- 派送子能力並接收結構化結果。
- 呈現成果、證據、風險及待決事項。
- 僅在使用者明確核准後，把 Gate 標記為 `APPROVED`。
- 上游變更時使受影響下游 Gate 失效並安排重驗。

母 Skill 不代替專業子能力，也不自行把缺少的證據推定為完成。

### 4.2 子能力

| 能力 | 主要責任 |
|---|---|
| 研究與實測 | 外部資料、真實工作、版本、工具操作、錯誤情境與設計含義 |
| 課程架構 | 能力拆解、成果證明、評量方式、單元順序與時數可行性 |
| 教學內容撰寫 | 概念、案例、完整示範、練習、修復及可獨立閱讀的正文 |
| 課程成品製作 | 代表單元、HTML、視覺、素材及完整課程轉製 |
| 獨立驗證 | 內容、保真、入口、跟做、理解、遷移、平台與技術證據 |
| 發行與維護 | 註冊、部署就緒、索引、版本、老化與更新觸發 |
| 既有課程修復 | 唯讀診斷、可回復修正及受影響範圍重驗 |

能力不必一對一變成 Skill。只有具備獨立輸入輸出、專門工具與獨立驗收責任時才拆分。

## 5. 課程契約：唯一狀態來源

### 5.1 儲存方式

建議實作位置：

- Schema：`courses/course-manager/contracts/course-contract.schema.json`
- 每門課實例：`_design/{slug}/course-contract.json`
- 人類可讀 Gate 摘要：由契約產生，不作為第二狀態來源。
- 詳細研究、審查與測試紀錄保留為獨立檔案，由契約記錄相對路徑與 SHA-256。

使用 JSON 是為了能以標準工具做 schema、狀態與相依性驗證；長篇正文、研究報告與測試紀錄仍使用 Markdown 或適合的成品格式。

### 5.2 核心區段

```text
identity
governance
gates
G0_requirements
G1_research
adaptation
G2_architecture
G3_lesson_design
G4_pilot
G5_production
G6_release_maintenance
changes
evidence_index
```

每個 Gate 至少記錄：

- `status`
- `owner`
- `inputs`
- `deliverables`
- `evidence`
- `risks`
- `open_questions`
- `approved_by`
- `approved_at`
- `source_revision`
- `affected_downstream`

### 5.3 Gate 狀態

| 狀態 | 語義 |
|---|---|
| `DRAFT` | 正在產製，不能交給下游作為核准輸入 |
| `REVIEW` | 交付物與證據已備妥，等待使用者核准 |
| `APPROVED` | 已核准並凍結，下游可以依賴 |
| `BLOCKED` | 缺必要資訊、素材、權限、實測、證據或決策 |
| `STALE` | 上游變更使既有成果暫時失效，必須重新驗證 |

Gate 狀態與驗證證據狀態是兩個層次。現有的 `MACHINE_CHECKED`、`LEARNER_READ`、`PLATFORM_VERIFIED`、`HUMAN_READY` 可保留為證據或發行成熟度，不能與 Gate lifecycle 混用。

### 5.4 變更控制

Gate 核准後立即凍結。若學員、成果、時數、工具環境、評量或其他實質條件改變：

1. 建立 change record，記錄原因及修改者。
2. 找出最早受影響的 Gate。
3. 將受影響下游標為 `STALE`。
4. 保留舊成果與證據，不直接覆蓋歷史。
5. 從最早受影響 Gate 重新產製與核准。

未改變語義的錯字或純排版修正，不觸發整條流程回退，但仍需執行相應技術回歸檢查。

## 6. 七個固定 Gate

### G0：需求契約

母 Skill 透過適應式問答確認：

- 學員與現有能力。
- 使用情境與要解決的問題。
- 可觀察成果與使用方式。
- 時數、交付、工具、權限及其他限制。
- 已知事實、假設、未知與阻擋。

只問會改變設計的問題；已知資訊不重問。重要條件未明時可以保存草稿，但不能核准 G0。

### G1：現實研究

輸出必須包含：

- 研究問題與決策用途。
- claim、source、retrieved_at、version、context、confidence 的證據矩陣。
- 官方資料、實務案例及使用者問題的整合分析。
- 真實任務、交付物、常見錯誤與環境限制。
- 相互衝突的證據、未知及不可下的結論。
- 對課程架構、練習、素材、風險及維護週期的具體影響。
- 高變動資訊的複查日期與責任人。

工具、軟體與生成式 AI 課程還要實際使用目標工具完成代表性任務，記錄帳號、方案、版本、輸入、輸出、卡點及限制。無法取得必要環境時標記 `BLOCKED`，不能靠網路文章替代。

### G2：課程藍圖

提交一個有充分理由的主方案，內容包含：

- 最終成果與驗收方式。
- 所需能力、先備與能力進展。
- 教學活動、練習與評量的對齊。
- 單元順序、依賴與時數可行性。
- 適配設定如何改變教學方法。
- 所需素材、環境及風險。

不為了呈現選擇而強制產生多套方案。證據不足時列出缺口並阻擋。

### G3：單元與內容設計

每個單元須提供：

- 學習問題、用途、材料與完成物。
- 必要概念、判斷原則及完整範例。
- 示範、引導練習、獨立運用與回饋。
- 預期結果、檢查方式及錯誤修復。
- 學員能連續閱讀的正式正文。
- 需要製作的素材、畫面及環境。

正文品質屬於作者責任，不留給排版或末端 copywriter 發明。

### G4：代表單元試作

先製作一個能代表主要風險的完整單元，包括正文、素材、成品介面與真實環境。驗證：

- 內容正確與來源適用。
- 學員入口及第一次操作可理解。
- 能完成承諾成果並判斷是否成功。
- 合理錯誤可依教材修復。
- HTML 或其他載體保留完整教學資訊。
- 實際畫面、響應式與適用的無障礙條件。

G4 未核准前禁止批量製作全課。

### G5：全課製作與整合

- 依已驗證模式擴展，不複製相同工作流換標題。
- 每單元仍需有新的能力、判斷或遷移價值。
- 檢查全課敘事、術語、案例、能力與依賴的一致性。
- 執行內容保真、技術、連結、資產、渲染與無障礙檢查。
- 任何批次生成錯誤回到責任層修正，不在末端逐頁堆補丁。

### G6：發行與維護

- 合併教學證據與技術發行狀態。
- 完成註冊、入口、權限、索引、sitemap、部署就緒及回復資訊。
- 記錄來源、工具及頁面的版本與複查條件。
- 建立學員回饋、問題分類、修正責任及內容退役方式。
- 缺真人或指定平台證據時，只能回報對應成熟度，不能稱為完全可授課。

## 7. 差異化設計

不以固定的 AI、軟體、行銷或概念課模板決定課程。G1 結束時，依下列條件生成 `adaptation`：

| 條件 | 影響 |
|---|---|
| 學員差距 | 解釋密度、先備補救、練習支援量 |
| 任務性質 | 概念、判斷、操作、創作或綜合活動的比例 |
| 工具依賴 | 帳號、權限、方案、裝置、資料與備援要求 |
| 變動速度 | 來源新鮮度、介面證據、複查週期 |
| 失敗風險 | 安全邊界、人工審核、錯誤演練與停止條件 |
| 成果證明 | 成品、操作、決策理由、表現或真實成效的驗收方式 |

現有四種 `course_type` 可以暫時保留為相容性 metadata 或證據提示，不能再作為主流程的固定模板開關。

## 8. 教學溝通品質

教學文案是 G2 至 G5 的共同品質，不是最後美化。

### 8.1 作者責任

- 說清楚情境、目的、動作與結果。
- 讓概念、示範、操作及驗收形成連續因果。
- 提供必要理由、中間結果、判斷標準與修復方式。
- 使用自然段落承擔解釋；清單、表格和卡片只在適合的資訊型態使用。
- 保留學員理解與獨立操作需要的細節。

### 8.2 編輯邊界

- 沒有具體學員問題、正確性問題或可執行性問題，不改可見文字。
- 「更精簡、更一致、更像模板」不能單獨構成改寫理由。
- 每次內容修改記錄原問題與預期改善的學員結果。
- 新證據沒有增加時，停止重複改寫。
- Copywriter 只處理已有事實但敘事斷裂的內容；缺事實、素材、示範或評量時退回上游。

### 8.3 驗收方式

以代表頁審讀、完整冷讀與學員跟做結果判定，不使用字數、卡片數、固定句型或連接詞數量作為品質代理。

## 9. 驗證與證據

### 9.1 可自動驗證

- Schema 與必填欄位。
- Gate 狀態轉換及相依性。
- 路徑、hash、版本、連結、資產與檔案存在。
- HTML 結構、lint、響應式斷點的確定性條件。
- 已核准內容與轉製成品的可比對項目。

### 9.2 必須保留判斷

- 學習成果是否有實質價值。
- 教學、練習與評量是否對齊。
- 文案是否自然、連貫且足以支持理解。
- 學員是否真的能完成、修復及遷移。
- 案例是否真實、風險是否可接受。

### 9.3 證據層次

沿用並明確區分：作者自驗、獨立 AI 審查、工具執行、平台實測及真人驗證。任何一層都不能冒充另一層；失敗與提示次數也要保留。

## 10. 本機 Skill 整併

### 10.1 核心保留

| 現有項目 | 新系統責任 |
|---|---|
| `course-designer` | G3 教學內容作者 |
| `build-course-page` | G4、G5 HTML 成品製作 |
| `course-validator` | G4 至 G6 的內容、保真、跟做、平台與技術驗證 |
| `course-repair` | 既有課程獨立修復入口 |
| `course-pdf` | 已核准 HTML 的 PDF 輸出適配器 |
| `course-html-contract` | HTML 共用技術契約與 validator |

### 10.2 重構或合併

| 現有項目 | 處理 |
|---|---|
| `course-run` | 重構為母 Skill，採 G0–G6 與課程契約 |
| `course-pm` | 移除重複需求訪談，專責 G2 架構；保留現有名稱以避免新增平行能力 |
| `course-handout-designer` | 保留為共用教學契約與方法庫，不作第二作者 |
| `course-reviewer` | 能力併入 `course-validator` 的 content、fidelity review；舊入口暫作相容層 |
| `course-copywriter` | 移出新課必經流程，作診斷式編輯與修復專項；通用原則上移共用契約 |
| `course-register` | 能力併入 `course-ops register`；舊入口暫作相容層 |
| `course-refresh` | 僅保留唯讀老化掃描；metadata 寫入移交 `course-ops` |

### 10.3 選用專項

`course-typography-fixer`、`coldtone-html`、一般 Web/UI 設計 Skill 只在具體成品或修復需求成立時調用，不進入核心鏈。

### 10.4 唯一新增的專業 Skill

新增 `course-researcher`，專責 G1 外部研究、來源治理、實務任務與工具實測。其輸入是核准的 G0；輸出是可由 G2 直接使用的研究包與適配設定。

## 11. 防止規則補丁化

新增問題先判定唯一責任層：

```text
流程 → 母 Skill
狀態與欄位 → 課程契約／schema
教學原則 → 共用教學契約
主題差異 → adaptation
HTML 結構 → course-html-contract
確定性驗證 → validator／script
既有課特例 → repair record
```

跨課反覆出現且具有共同因果的問題才升為共用規則。單一案例先保留在課程紀錄。新增規則時必須檢查能否合併或刪除舊規則，不能只追加文字。

## 12. 遷移與實作順序

1. 建立 course contract schema、狀態機、影響傳播規則與 validator。
2. 重構 `course-run`，先支援 G0、Gate 停止點及現有 Skill 調度。
3. 建立 `course-researcher` 與 G1 研究輸出格式。
4. 調整 `course-pm` 只承擔 G2，接收 G0、G1 與 adaptation。
5. 建立共用教學溝通契約，讓 `course-designer` 直接產生良好正文。
6. 將 content／fidelity review 併入 `course-validator`，保留舊入口相容層。
7. 整併 register、ops 與 refresh 的寫入責任。
8. 更新 `course-repair`，讓診斷結果回到新責任層。
9. 用一門新課完成 G0–G6 代表性試跑。
10. 通過試跑前不刪除舊 Skill；通過後才移除相容層與重複規則。

每一階段需有獨立測試與回復方式。不得一次改寫所有 Skill 後才驗證。

## 13. 第一輪實作驗收

第一輪不要求完成整套新課，而要求證明架構可工作：

- 母 Skill 能以問答建立一份有效 G0。
- 未核准 G0 時，G1 無法開始。
- G1 能記錄來源、版本、實測與設計含義。
- 上游實質修改會把下游 Gate 標為 `STALE`。
- 子 Skill 無法自行將 Gate 標為 `APPROVED`。
- 缺素材、權限或核心實測時能正確 `BLOCKED`。
- 一個代表單元能由核准正文轉成 HTML，通過保真與冷讀檢查。
- 正常可讀正文不會因格式統一而被改成片語或待辦清單。

## 15. 完成定義

本系統完成時應具備：

- 一個可實際運行的母入口。
- 一份可驗證、可追溯、可做變更影響分析的課程契約。
- 一個新的研究與實測 Skill。
- 經整併而非重複建立的現有 Skill 群。
- 一門從 G0 到 G6 完成的代表性新課證據。
- 一次既有課程修復支線的相容性驗證。
- 明確證明課程正確、學員可用，以及流程返工量受到控制。
