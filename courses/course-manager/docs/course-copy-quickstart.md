# 文案迭代：講義文案快速處理

這是課程迭代的文案專用入口。適用於資料已有、但語氣不合適、段落跳躍、像待辦清單、術語突然出現或解釋重複的講義。它以較小範圍處理，不省略比較、覆核或人工閱讀確認。

## 在對話中使用

在`courses/`下任一課程目錄直接輸入「文案迭代」，即可透過[共用入口](../../AGENTS.md)使用v0.6，不必切到course-manager或指定版本。需要明確描述時可輸入：

> 文案迭代：［課程／章節或檔案］。學員是［背景］，這頁用來［用途］。我讀到［位置］覺得［問題］。請保留案例、操作與提示詞，只調整文案，交完整候選給我比較。

不一定要先指出全部問題；原稿與用途足夠時可由評估角色定位。只輸入「文案迭代」時，先依目前課程與既有資料定位，只有章節範圍或用途仍不明時才詢問；不自動把啟動詞當整課改寫授權。若同章已有run，先接續或辨認差異，不自動升級舊版或重開以繞過額度。

## 快速反應分工

| 角色 | 責任 |
| --- | --- |
| 主對話，建議Sol | 固定本次範圍與材料，執行控制器，處理超出文案的問題，登記人工回饋 |
| Sol評估 | 找閱讀斷點，提供原文證據、修正交接及保留內容 |
| Luna編輯與自查 | 依交接改成完整候選，比對前後文案與事實 |
| Sol新上下文覆核 | 查漏、核對保留內容與新增退步；不能沿用作者評分答案 |
| 你 | 連續閱讀候選並決定是否接受H3 |

這些角色由現有控制器依序派送，不是常駐或平行代理團隊。單章是執行單位；指定整課時，先從實際目錄列齊授權章節，再依序接續既有run，不能只交通過的幾章。沒有指定對象時不派模型。每個單章run採low、最多八次模型呼叫及兩版候選，通常一版四次；整課不得因此自動擴大原先核准的總呼叫額度。細則見[文案專用規範v0.6](course-copy-profile-v0.6.md)。新run預設v0.6；舊run保留原規範與雜湊，不重綁、不重置用量。

v0.6把四項讀者檢查接入實作：用日常說法重述意思並引用正文依據、找出人物與材料等理解障礙、判斷理由是否出現在需要處，以及連讀時條件與代碼是否過度集中。改寫依這四點修主要段落；比較與覆核在`reading_decision`交實際結果。重述若補入背景，或任一項有缺口，須對應open B問題，不能同時判supported／B L3。控制器檢查欄位、正文引文與結論一致性；語意仍須實際閱讀，不能用程式檢查取代H3。

新run會自動使用段落位置引用：模型選段落ID與範圍，程式擷取原文；既有問題只回報狀態更新，身分與歷史由控制器保存。格式出錯時以局部位置patch更正，不重交整份報告，也不改高評級。舊run與已派送任務保留原契約及已用額度；不因功能補強自動續跑。

## 不需要手填JSON的準備入口

在course-manager目錄執行，替換以下原稿、用途與輸出路徑：

```bash
python3 scripts/course_copy_loop.py \
  --source '/原稿完整路徑/CH1.html' \
  --unit CH1 --title '章節名稱' \
  --purpose '給初學者理解這份既有案例的判斷理由' \
  --run '/隔離輸出完整路徑/run'
```

可重複加 `--material '/必要來源路徑'`，提供教案、前後章或已確認事實；可加 `--keep '必須原樣保留的文字'`。零基礎教材如有學員路徑契約，應一併提供；缺少支持新增說明的事實時先補證，不用文案猜答案。

準備入口會產生本run的spec、來源快照與章節設定；不呼叫模型、不啟動修復。HTML的pre區塊及Markdown圍欄程式區塊自動加入逐字保留檢查；其他表格、行內數值、操作順序、連結目的地仍須評估與覆核逐項核對，不能把此檢查當完整語意保證。

確認run設定後，後續全數沿用既有入口：

```bash
python3 scripts/course_loop.py start --run '/隔離輸出完整路徑/run' --actor '你的名字' --note '僅本章文案，兩版上限，不覆蓋正式講義'
python3 scripts/course_loop.py work --run '/隔離輸出完整路徑/run' --max-tasks 8
python3 scripts/course_loop.py report --run '/隔離輸出完整路徑/run'
```

交付原稿快照、完整Markdown候選、原文依據、交接、前後比較與覆核。原稿HTML不變，候選尚未套回正式版型。人工確認、恢復及結案命令見[統一操作說明](course-loop-runtime.md)。

## 整課使用同一份清單與佇列

先核對實際課程首頁及既有run。已有run的章節接續原run，不把下列新建入口拿來重置候選或用量。尚未開始的授權章節，可在JSON清單列出：

```json
{
  "id": "copy-my-course",
  "max_model_calls": 8,
  "units": [
    {"id": "CH1", "title": "第一章", "purpose": "讓初學者理解既有案例", "source": "CH1.html"},
    {"id": "CH2", "title": "第二章", "purpose": "理解前章成果如何接續使用", "source": "CH2.html"}
  ]
}
```

路徑相對清單位置解析；每章可另列`materials`與`keep`。`max_model_calls`是整份清單已核准的總額，不是每章八次，也不保證足夠完成全部章節。沒有總額就拒絕準備，不自行乘上章節數。主對話須把清單與實際授權範圍核對，程式不能知道你是否漏列章節。

```bash
python3 scripts/course_copy_loop.py --course-manifest '/完整路徑/course.json' --run '/隔離輸出/run'
```

此命令只準備全部來源及現有控制器設定，不啟動模型；後續start／work／status／report仍用同一run。每章各自保留兩版上限、H3與停止狀態，報告列出全部章節；不另建第二套批次控制器。正式套用與公開更新另依已取得的授權完成。

## 什麼時候停

完整正文的閱讀問題改善且保留內容未退步，即停H3讓你閱讀，不為用滿兩版而再改。若沒有必要缺口，檢查與覆核後可不產生候選。你的連續閱讀回饋若否定候選，須記錄為本稿未通過的證據；AI的B L3與局部問題已解不能取代這項判斷。

發現缺素材、技術矛盾、錯誤數據或需要改操作時，提供原文與回交理由，停下交人工決策；必要資料不明則待補證。這時不自動改成整課修復、不自創正確答案。可由你另行指定「課程迭代」處理原問題，既有問題與用量紀錄仍保留。

本模組候選完成不代表技術最新、平台實測、正式套用或公開更新。正式覆蓋與發布須有授權；已有授權就直接接續必要工作，不重問。整課逐章列明候選、確認、套用及阻塞，未完成者不能算修正。發布要確認實際來源分支、部署與各頁公開內容，工作分支push不算上線。各章試作與人工回饋以[開發紀錄](../operations/course-content-scoring/開發進度追蹤.md)為準。
