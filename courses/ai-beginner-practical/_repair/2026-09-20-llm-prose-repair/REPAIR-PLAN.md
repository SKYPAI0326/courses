# AI 入門即戰力 LLM 慣用文案修整計畫

## 範圍

- 目標：`CH1-1.html`、`CH2-1.html`、`CH3-1.html`、`CH4-1.html`
- 只修改學員看得到的文字節點。
- 不修改 HTML 結構、class、錨點、連結、工作台、提示詞、欄位、操作順序或驗收資料。

## 問題分類

- `CONTRAST`：把「不是／不只……而是……」改成直接描述行動、目的與可觀察結果。
- `BOUNDARY`：必要限制拆成獨立句，清楚說明使用界線。
- `EXAMPLE`：學員必須辨認的錯例或引用保留，明確標成錯例／判斷內容。
- `EVIDENCE_GAP`：抽象詞改成欄位、產物、數量、行動或驗收條件。

## 保留清單

- 四單元案例角色、資料值、NotebookLM 固定平台與平台中立的 LLM 觀念。
- 五欄框架、工作台欄位、提示詞原文、操作順序、checkpoint、回復位置與匯出檔名。
- 必要的不確定性與限制，例如「待確認」、來源未提及、不得自行增加承諾。

## 改寫原則

1. 先說學員要做的動作，再說目的與完成後應看到的結果。
2. 需要保留限制時，使用「LLM 不會自動知道……」「本欄要留下……」等直接句，不用公式化反轉。
3. 不為了消除字詞而刪除真實風險、錯例或判斷條件。
4. 同一段若已具體，僅移除多餘對比，不補新的教學事實。

## 驗證

- 逐頁重跑 LLM prose risk 掃描與人工分類。
- 重跑 copy continuity、cold-follow、語意去重、工作台與課程契約檢核。
- 以 HTML parser 與 `git diff --check` 確認結構與格式未受影響。
- 產出修訂報告，列出仍保留的必要否定句及其功能。
