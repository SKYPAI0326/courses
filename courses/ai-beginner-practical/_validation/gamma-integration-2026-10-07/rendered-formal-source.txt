<h1>把完整企劃做成十頁 Gamma 提案簡報</h1>
<p>你要向主管提出一項工作改善，手上已有完整企劃。這次把企劃整理為十頁簡報：開頭讓主管知道請求，中間說明問題、方法、時程與資源，最後回到核准事項。每個重要數字與條件都能回查原文，主管才能評估是否開始試行。</p>
<p>完成後，你會留下自己的十頁大綱、可編輯的 Gamma 簡報與十頁 PDF。你可以用它說明提案；日後換成自己的工作企劃，再依相同方法處理。這次每人選題、操作與保存，不需要共同企劃或同學成果。</p>
<p>先開啟 <a href="assets/workplace/gamma/examples/README.md">兩份實跑成果</a>，選一份 PDF 看封面與最後核准頁。這就是本次要做的完成物；其中也保留實際大綱初稿，稍後可以比較修改。成品供參考，不要求複製它的版型或措辭。</p>
<h2>先取得一份完整企劃</h2>
<p>從下表選一份並開啟。Markdown（<code>.md</code>）是可讀的文字檔；即使沒有排版，也能複製全文到你的對話工具。先讀第一段與 P01，確認讀者和希望對方核准的事項。</p>

<p>兩份課程企劃都明示教學模擬、尚未執行。企劃中的窗口是模擬單位角色，並非要找同學分工。若連結無法複製全文，下載後以文字編輯器開啟；沒有自己的企劃不會阻擋這次操作。</p>
<p>開始前，確認你的 LLM 可輸入文字，Gamma 可登入並建立內容，電腦有可保存檔案的位置。建立自己的資料夾，例如 <code>我的提案</code>，稍後依序保存 <code>企劃.md</code>、<code>10頁大綱.md</code>、<code>Gamma貼入文字.txt</code> 與 <code>提案.pdf</code>。檔名可自行調整，保留版本與用途即可。</p>
<p>你能否說出「我希望誰核准什麼」？A 的答案是部門主管核准四週報表試行、兩位窗口與第四週檢討；B 的答案是單位主管核准四週文件交接試行、兩位窗口、暫定投入與第四週檢討。自己的來源若沒有說明請求，先補這項，再產生大綱。</p>
<h2>先辨認主管要決定的事</h2>
<p>企劃保存完整背景；簡報讓讀者在有限頁面內看出決策所需資訊。先寫出「請主管核准……」，再決定哪些內容支援這個請求。十頁是本次的呈現限制，包含封面與最後核准事項，不能用額外謝謝頁擠掉結論。</p>
<p>原文中的狀態會影響讀者判斷。例如 B 的「預計建立六題問答」代表核准後才製作；寫成「已完成六題問答」會讓主管誤判試行進度。A 的三筆費用「待確認」需要回查，寫成「發現損失9,601元」會把待查資料變成已確認結論。</p>
<p>保留事實、保留狀態，再精簡措辭。版面可以改，四週、角色、核准事項、金額單位與未量測成效等條件需維持來源原意。</p>
<h2>看一份企劃如何縮成十頁</h2>
<p>示範使用 A 的完整企劃。開啟 <a href="assets/workplace/gamma/case-a/outline-reference.md">A來源對照</a> 與 <a href="assets/workplace/gamma/case-a/gamma-text.txt">十頁參考文字</a>，先看第1、4、5與10頁；其餘頁面依同一邏輯組織。</p>
<p>第1頁使用 P01／P10 的請求，讓主管知道要核准四週與兩位窗口。第4頁使用 P04 的營收基準，第5頁使用 P03／P04 的費用與規則。第10頁回到核准與檢討，讓主管可以採取下一步。</p>
<p>以第4頁為例，來源 P04 提供三個月份營收，金額單位為萬元。依照期間排列可看出月份差異；來源沒有下滑原因與成本，所以這頁不能加入原因或毛利。</p>

<p>第4頁參考完成文字：</p>
<blockquote>
<p>課程模擬資料共50筆，涵蓋2026年2至4月，金額單位為萬元。2月2,991.0；3月3,434.2；4月1,280.4；合計7,705.6萬元。月份與產品比較需回查同一來源；資料沒有成本與原因調查，不能據此計算毛利或宣稱下滑原因。</p>
</blockquote>
<p>你可以用三列月份表呈現，也可以使用正確數值的圖表。用文字表格已能達成本次驗收；Gamma 畫出看似合理的曲線，仍需檢查其實際數字。</p>
<p>第5頁應保留費用總額3,138,430元、兩項規則、E0010／E0130／E0188與待確認合計9,601元。三筆中有一組重複對，不能說成三組重複。完整十頁、組織理由與來源都已提供在上方參考檔，不需要自行猜出其他頁面。</p>
<p>如果你選 B，開啟 <a href="assets/workplace/gamma/case-b/outline-reference.md">B來源對照</a> 與 <a href="assets/workplace/gamma/case-b/gamma-text.txt">B十頁參考文字</a>。B 第4頁說明核准後如何取得來源，第6頁說明預計問答與交接成果；它沒有銷售資料，不使用 A 的第4／5頁數字。</p>
<h2>用 LLM 產生自己的十頁大綱</h2>
<p>開啟 <a href="assets/workplace/gamma/prompts/outline.txt">outline.txt</a>，複製整份提示詞，接上你選定企劃的全文，一次送到正在使用的 LLM。提示詞中的「來源對應」是回到企劃 P01–P10 的定位，供你核對，稍後不放進正式簡報。</p>
<p>等待回答後，保存為自己的 <code>10頁大綱.md</code>。應看到第1至10頁，每頁有標題、主旨、要點、版面建議與來源。大綱後的核對清單保留在這個檔案中，沒有第11頁。</p>
<p>逐頁看它引用的 P 段落。遇到金額、期間、角色與成效句，回原文確認。A 用本章第4／5頁基準檢查；B 檢查六題、四週、兩位窗口、暫定每人每週三十分鐘，都是提案設定，沒有被寫成已完成。模型可能把兩組資料合在同頁，頁碼不必照參考答案；來源事實、十頁限制與核准事項需一致。</p>
<p>A 的試跑曾保留編號與9,601元，卻漏寫兩項篩選規則。編號正確不代表資訊完整：回 P03 查到「同申請人、同日、同項目、同金額的重複紀錄，以及金額小於10元的紀錄」，要求補回費用頁，並保留待確認狀態。自己使用其他規則時，以自己的企劃核對。</p>
<p>若 LLM 認為缺資料，先看缺件是否已在企劃寫為核准後確認。B 的真實文件與開始日期尚待確認，但企劃已提供取得方法，不必現場捏造。你可以回覆：</p>
<pre><code class="language-text">企劃已將這項資訊列為核准後確認，請保留其狀態，使用已提供的取得方法完成提案大綱。
若仍有阻擋提案的重要缺件，指出缺少哪一段，不要自行補造。
</code></pre>
<p>若多出來源頁或謝謝頁，請回覆「把來源與核對清單留在大綱檔，正式頁面維持十頁，封面與最後核准事項都計入」，核對修改後結果。保留前一版，不需要重新建立整份企劃。</p>
<h2>整理 Gamma 要用的十段文字</h2>
<p>剛才的大綱包含內容與製作說明。Gamma 若把來源表、講稿或核對清單當成投影片，會增加頁面或讓畫面太密。因此，使用 <a href="assets/workplace/gamma/prompts/gamma-text.txt">gamma-text.txt提示詞</a>，接上已核對大綱，送出第二次轉換。</p>
<p>保存結果為自己的 <code>Gamma貼入文字.txt</code>。應有十個「第X頁」區塊，中間共九行 <code>---</code>；這個記號協助分段，最終仍以 Gamma 實際卡片數為準。文字只保留頁面標題與要點，來源對照留在原大綱。</p>
<p>快速確認第1頁的模擬標示與第10頁的核准請求仍在，再檢查幾項重要數字。如果轉換修改事實，回前一份大綱修正。A／B 的貼入參考可用於比對與恢復，但先保存你自己的版本，才能知道哪一個階段改錯。</p>
<p>實際試跑的大綱曾出現每頁五個要點。第二次轉換將同一主旨的文字整併為二至四個要點；整併後仍需逐項查來源，不能為了要點數刪掉條件。如果文字仍太密，先保留已核對版本，在 Gamma 改用分行或表格，再檢查匯出結果。</p>
<h2>在 Gamma 確認大綱，再生成</h2>
<p>開啟 <a href="https://gamma.app/">Gamma</a>。本章使用「卡片」稱呼 Gamma 中的一張內容頁；設定為簡報並匯出時，本次要檢查十張卡片與十頁 PDF。</p>
<h3>首頁顯示訊息輸入框時</h3>
<p>在訊息輸入框貼入 <a href="assets/workplace/gamma/prompts/gamma-generate.txt">gamma-generate.txt</a>，接上你自己的十段文字並送出。指令要求先看十張卡片的大綱，再生成；若 Agent 仍改寫內容，直接在對話中要求保留原文字與條件。</p>
<p>看到生成前大綱時，數到十張，確認封面、模擬狀態、期間、人力、資源與最後核准事項。核對完成才按生成。若出現版面選擇，選簡潔、字易讀的版型；不需新增圖片才能完成任務。</p>
<h3>介面提供「使用經典生成器」時</h3>
<p>選擇貼上文字，貼入自己的十段內容；若接著進入 Agent，使用上方訊息方式。若仍在傳統生成器的大綱頁，指定簡報、十張卡片與繁體中文，文字處理選 Preserve／保留，不要求模型再擴寫內容。檢查十張後才生成。</p>
<p>這兩條是依介面辨識的替代路徑，不要求都做。官方說明可在 <a href="https://help.gamma.app/en/articles/11047840-how-can-i-import-slides-or-content-into-gamma">匯入與貼入內容</a> 查閱；按鈕不同時先找訊息輸入或貼上內容入口。只把已確認的文字交給 Gamma，不需上傳 Excel。</p>
<p>如果帳號無法生成或額度不足，保存大綱與貼入文字，標記「Gamma待補」。本次不要求付費升級；完成文字路徑仍有成果，但不能把未生成簡報列為已完成。</p>
<h2>修一項問題，開啟 PDF</h2>
<p>生成完成後，先檢查文字，再看版面。確認十張卡片，第10張仍是核准事項。若數值或狀態被改，直接回來源修正卡片；若內容太密，調整段落、表格或文字大小，保留會影響核准的條件。</p>
<p>至少修一項具體問題並記下理由。可用的例子包括：把一段時程改為四列時間表，讓主管看出各週交付；刪除 Gamma 擅加的效率比例；把第5頁「損失」改回「待確認」，保留原金額。只換主題色未必改善讀者判斷，請說明這個修改如何幫助閱讀。</p>
<p>B 的實際試跑將第8張三個角色放在同一段，閱讀時不易比較。可在 Agent 訊息框送出：</p>
<pre><code class="language-text">只調整第8張卡片的版面：主管、文件窗口、使用者窗口各自分行呈現，讓責任容易比較。
保留原有所有文字、兩位窗口各每週30分鐘、零新增採購與工時另記等條件，不改其他卡片。
完成後維持恰好10張，不發布或更動分享權限。
</code></pre>
<p>修訂後回第8張，確認三個角色分行、條件仍在，並檢查沒有改到其他頁。自己的頁碼不同時，先改指令中的頁碼與角色，不照貼另一個案例的內容。</p>
<p>用簡報播放視圖從第1張看到第10張，確認表格、段落及標題可讀。開啟右上分享選單中的匯出，或右上更多選單中的匯出，選 PDF 與全部卡片。匯出選單中的「全部卡片」很重要，否則可能只下載目前一張。詳見 <a href="https://help.gamma.app/en/articles/8022861-what-s-the-easiest-way-to-export-my-gamma">Gamma官方匯出說明</a>。</p>
<p>保存 <code>提案.pdf</code> 後重新開啟：應有十頁，檢查每頁是否截字、漏字、圖表數值不同或字太小。若只有一頁，回匯出選單改為全部卡片；若文字太密，回原卡片修版面，再匯出重開。不要只檢查編輯畫面。</p>
<p>A 的實際匯出曾將第7頁第四週擠成最右側的窄直欄，雖然 Gamma 回報版面檢查通過，PDF 仍不可讀。這時保留失敗版，回 Gamma 要求「只重做第7張，移除表格，改成四個由上而下的文字段落，完整保留四週工作、交付與核准後排定的條件，其他頁不變」。重新匯出全部卡片後，再看第7頁及總頁數，確認四週都能閱讀。</p>
<h2>完成你自己的提案</h2>
<p>對照 <a href="assets/workplace/gamma/checks/quick-check.md">quick-check.md</a>，在現有成果上檢查，不另抄十頁內容。保留大綱、貼入文字、Gamma位置與PDF，並用其中的短交接欄寫出讀者、來源、修改理由與待確認事項。</p>
<p>你若使用完整模擬案例，成功代表能保留來源與狀態完成轉換；要遷移到工作，下一次再替換讀者、核准事項、限制或來源。改變真的會影響頁面重點的條件，例如由主管核准試行改成窗口接手執行，應相應調整請求、方法與下一步，不能只改單位名稱。</p>
<p>這次保存的來源對照讓你在主管追問或企劃更新時，知道哪些頁需要修改。原企劃與大綱持續保存，PDF用來閱讀，Gamma用來編輯；三者各有用途。</p>
