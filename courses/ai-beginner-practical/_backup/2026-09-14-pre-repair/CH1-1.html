(01 / 04) 認識 LLM

第一次與 LLM 對話：把日常問題說清楚

3 小時｜用五欄提示詞框架完成五個日常對話、一次修改，留下可重做的 LLM 實務紀錄。

學習成果
能分辨「找外部資料」與「請 LLM 處理任務」的差異。
能用情境、任務、資料、條件、格式五欄寫出可執行的提示詞。
能完成五個日常問題，並保留每題的原始輸入與回答。
能用一個修改指令改善回答，說出前後版本的差異。
(01) 先知道要留下什麼

你今天不是試玩，而是完成一份實務紀錄

為什麼這很重要
只看一次回答，很難知道下次該怎麼重做。這一單元把每次提問、回答與修改都放在同一份紀錄表裡，讓你看得出條件怎麼影響結果，也讓下一單元可以直接沿用同一套提問方法。

阿凱第一次使用 LLM 時，常常只輸入「幫我想一下」或「這是什麼」，得到的回答有時太長、有時不符合情境。你今天要留下的是一份可以重做的實務紀錄：五個日常問題、每題的回答、一次修改，以及自己判斷回答是否可用的理由。

開啟 第 1 單元實務紀錄表。它是可複製的 Markdown 文字檔，作用是保存原始問題、回答與修改結果。如果對話工具暫時無法使用，改開啟 離線備援結果，先完成晚餐與通知整理的觀察。

你手上的材料這次會留下什麼完成後如何使用
實務紀錄表與一個可輸入文字的 LLM 對話畫面五個原始問題、五個回答、一次修改第 2 單元沿用五欄提示詞框架寫日常文書
(02) 關鍵概念

同一句話，可以是搜尋任務，也可以是對話任務

LLM 是能用文字對話協助產生、整理或改寫內容的語言模型。它會依照你提供的文字與條件產生回答；回答是否適合使用，要回到你的任務與條件判斷。

搜尋問題
找外部資料
目標是找到網頁、時間、價格或其他外部資訊。
✓例：查京都目前的營業時間
✓要注意資料日期與來源
對話任務
處理你的要求
目標是讓 LLM 依照條件產生初稿、清單或解釋。
✓例：依預算提出晚餐選項
✓要交代讀者、格式與限制

提示詞是你交給 LLM 的任務說明。這堂課使用五欄框架，先把「事情在哪裡發生、要做什麼、要參考什麼、不能違反什麼、答案要長什麼樣」寫出來。

欄位白話意思晚餐例子
情境事情發生在哪裡今天下班後要安排晚餐
任務要 LLM 幫你做什麼提出三個晚餐選項
資料LLM 必須知道的條件兩人、不吃牛、預算 600 元
條件不能違反的限制30 分鐘內完成
格式答案要長什麼樣表格，列出菜色、時間、預算
(03) 完整示範

從「幫我想晚餐」變成可用初稿

阿凱想安排晚餐。先看模糊輸入，再看補齊條件後的輸入，最後觀察回答是否真的回應了每個條件。

1
模糊輸入
只有「幫我想晚餐」時，LLM 不知道幾個人吃、預算多少、有哪些不能吃的食材，也不知道你要清單、食譜或餐廳建議。
2
補上五欄條件
我今天下班後想安排晚餐。請依照以下條件提出三個選項：兩人、預算 600 元、不吃牛、希望 30 分鐘內完成。請用表格列出菜色、預估時間與預算，最後告訴我還缺哪一個條件。
3
讀回答，不只看文字順不順
選項菜色預估時間預算
A番茄雞肉義大利麵＋沙拉25 分鐘420 元
B豆腐蔬菜鍋＋白飯30 分鐘480 元
C蝦仁蛋炒飯＋燙青菜20 分鐘360 元

逐一對照：有三個選項嗎？有回應兩人、不吃牛、600 元與 30 分鐘嗎？還可能缺少「家裡現有食材」或「是否需要外帶」等條件。

i
示範的判斷點　提示詞讓 LLM 先產生規劃初稿；它沒有自動知道你的所在位置、當日價格或店家營業狀態。任務的完成不只看答案好不好看，也要看它是否回應了你交代的條件。

同樣的方式可以用在「四天三夜京都自由行」：先交代預算、偏好、每天可接受的景點數與輸出格式。行程表是初稿；交通班次、票價與營業時間要另查最新資料。

(04) 同步演練

完成五個基本對話，再修改其中一個結果

現在使用同一份紀錄表。每題都先保留原始提示詞與第一版回答，再寫觀察。這樣你能看見「問法 → 回答 → 修改」的完整關係。

1
建立紀錄位置｜U1-START
學員操作：開啟 實務紀錄表，填姓名與日期；同時開啟一個可輸入文字的 LLM 對話畫面。
預期結果：你看得到紀錄表與對話畫面。
快速檢查：能指出回答要貼到哪裡，以及本單元最後要留下什麼。
卡住時：找不到檔案 → 回到 U1-START → 重新開啟資產連結 → 從步驟 1 重做；若編輯器不能保存，先複製到自己的文字筆記，安全停止在姓名與日期已記錄。
2
提問自我介紹｜U1-ASK
學員操作：複製工作表第 1 題完整提示詞並送出，把回答貼回紀錄表。
預期結果：回答提到 LLM 能協助的三類事情，以及需要人自行確認的內容。
快速檢查：回答是否真的在介紹它能做什麼。
卡住時：回答偏題 → 回到 U1-ASK → 追加「請只回答自我介紹」→ 從步驟 2 重跑，保留第一版。
3
詢問明天台北的天氣｜U1-ASK
學員操作：送出工作表第 2 題，保留回答中的日期、時間與資料依據；若回答無法取得即時資料，也記下來。
預期結果：得到天氣回答，或得到需要改用即時資料來源的說明。
快速檢查：能指出回答是否說明資料時間與依據。
卡住時：只有晴雨結論 → 回到 U1-ASK → 追加「請先說明資料時間與來源」→ 從步驟 3 重跑。
✓
Checkpoint U1-CHECK-1　現在應該看到：前 3 題已有回答，晚餐題至少有一份表格。若沒看到：檢查是否貼上完整提示詞，而不是只貼題目標題；回到對應步驟修正。通過後才能繼續，因為後兩題會改變任務類型。
4
提出晚餐選項｜U1-ASK
學員操作：送出工作表第 3 題，確認回答有三個選項、時間與預算，在紀錄表寫下最符合自己的選項。
預期結果：回答回應兩人、不吃牛、600 元與 30 分鐘四個條件。
快速檢查：逐一標記四個條件在回答中的位置。
卡住時：忽略某個條件 → 回到 U1-ASK → 只補上被忽略的條件 → 從步驟 4 重跑，保留原回答作比較。
5
用自己的話解釋 ETF｜U1-ASK
學員操作：送出工作表第 4 題，用自己的話寫一句 ETF 是什麼，並保留三個待查問題。
預期結果：回答先有一句話定義，再有生活化例子，最後列出待查問題；不直接替你做投資推薦。
快速檢查：重述包含「一籃子資產」與「可以在市場交易」兩個核心意思。
卡住時：回答太專業 → 回到 U1-ASK → 追加「請改用國中生聽得懂的方式，不增加新的金融術語」→ 從步驟 5 重跑，保留原版。
6
整理一段通知｜U1-ASK
學員操作：送出工作表第 5 題，比較整理前後是否保留週三、晚上 7 點、下午 6 點前移車與雨天順延四個資訊。
預期結果：得到三個條列重點，沒有加入原文沒有的規定。
快速檢查：在回答中標記日期、時間、住戶行動與雨天備案。
卡住時：刪掉重要時間 → 回到 U1-ASK → 追加「日期、所有時間、住戶行動與雨天備案都必須保留」→ 從步驟 6 重跑，留下前後差異。
✓
Checkpoint U1-CHECK-2　現在應該看到：五個問題都有回答，第 5 題保留四個指定資訊。若沒看到：開啟 離線備援結果，先比對晚餐或通知整理的預期樣子，再回到對應步驟修正。
7
只改一個條件｜U1-REVISE
學員操作：從五個回答選一個，輸入「太長了，請縮短成 80 字」或「請改成表格，只保留我需要做的事」，把第二版接在第一版下面。
預期結果：第二版只針對長度、語氣或格式其中一項改變。
快速檢查：能說出這次改了哪個條件、哪項內容被保留。
卡住時：第二版同時改了很多事 → 回到 U1-REVISE → 只留一個修改指令 → 從步驟 7 重跑，保留兩個版本。
8
保存實務紀錄｜U1-SAVE
學員操作：逐項勾選工作表最後的完成條件，將填寫版保存成 `unit1-practice-sheet-complete.md` 或貼到自己的文字筆記。
預期結果：文件包含五題原始問題與回答、一次修改、需要再查資料的地方，以及完成檢查。
快速檢查：沒有參加這堂課的人也能看出你問了什麼、得到什麼、哪一題需要再確認。
卡住時：缺少原始提示詞 → 回到 U1-SAVE → 重新開啟工作表複製該題 → 從步驟 8 重做；不要刪除現有回答。
(05) 完成驗證

用三個檢查確認紀錄真的可重做

完成物不是「看過五個回答」，而是別人拿到紀錄也能看懂你怎麼問、回答是否符合條件、下一輪要怎麼改。

輸入與回答
打開填寫版紀錄表，確認五題的原始提示詞與回答都在同一份文件中。
條件對照
隨機挑一題，標記情境、任務、條件與格式；缺哪一種就補回提示詞。
版本比較
讀第一版與第二版，說出修改指令改變的是長度、語氣或格式。
✓
通過標準　五題皆有回答、至少一題有前後版本、至少一題記錄了需要再查資料的地方，而且你能說明第 2 單元會沿用五欄提示詞框架。

(07) 常見錯誤

回答不合用時，回到對應階段修

PITFALL 01
輸入只有「幫我處理一下」，回答看似完整但和需求不相干。
原因：沒有交代任務、條件與輸出格式。
修復：回到 U1-ASK，補填五欄中的任三欄，先重跑一個小任務。
PITFALL 02
第二輪同時要求縮短、改語氣、改格式，結果無法判斷變化原因。
原因：一次改了多個主要條件。
修復：回到 U1-REVISE，每輪只保留一個修改指令。
PITFALL 03
只保存最後回答，無法說明原本問了什麼。
原因：沒有把原始提示詞與第一版回答一起保存。
修復：回到 U1-SAVE，依序保存原始輸入、第一版與第二版。
