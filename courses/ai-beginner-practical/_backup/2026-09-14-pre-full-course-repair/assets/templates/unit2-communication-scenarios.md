# 日常溝通情境素材包

這份素材包可以獨立使用，不需要開啟課程 HTML。你可以把任一段提示詞複製到自己能使用的文字型 LLM，再把輸出貼回自己的筆記。提示詞中的 `[方括號]` 是要替換的欄位；沒有資料的地方保留 `[待補]`，不要讓模型自行猜日期、金額、承諾或經歷。

## 使用方式

1. 先選一個情境，不要一次跑完全部卡片。
2. 把背景、任務、限制、輸出格式四段中的方括號換成自己的資料。
3. 保存「原始提示詞 → 第一版 → 一次迭代指令 → 修正版」，不要只留下最後一句。
4. 用最後的成果檢核表檢查讀者、目的、語氣、長度、事實與待補欄位。

## 四段式提示詞骨架

```text
【背景】
[事情發生在哪裡？我是誰？收件者是誰？已知資料有哪些？]

【任務】
請幫我[寫／改寫／縮短／整理]一份給[讀者]看的[Email／訊息／自我介紹]，目的是[希望讀者理解或採取的行動]。

【限制】
- 使用繁體中文，語氣[正式清楚／親切口語／專業有禮／其他具體描述]。
- 長度[字數／句數]。
- 只能使用我提供的事實；沒有提供的日期、金額、期限、承諾或經歷標為[待補]，不要自行補寫。
- 必須保留：[一定不能刪掉的資訊]。

【輸出格式】
[主旨／正文／署名；或 2–4 句訊息；或指定的多個版本]。直接給可編輯成品，不先解釋寫法。
```

「背景」也包含 CH1-1 五欄框架中的資料；「限制」可以放條件；「輸出格式」決定答案長相。四段不是固定術語，而是讓你檢查「模型知道事情、知道要做什麼、知道不能做什麼、知道成品要長什麼樣」的工作順序。

# A. 10 個 Email 情境提示詞

每張卡都可以直接複製。先用一張卡完成一封信，再依迭代速查表調整一次。

## Email 01｜請假

```text
【背景】
我是[職稱／身分]，需要向[主管姓名／稱呼]請假。[請假原因可寫成願意透露的簡短說法]，請假日期為[日期]，共[天數／時數]。目前負責的工作是[工作名稱]，交接給[代理人]；緊急事項請透過[聯絡方式]通知我。

【任務】
請寫一封請假 Email 給[收件者]，說明請假時間、工作交接與必要的聯絡方式。

【限制】
- 語氣誠懇、清楚、尊重，避免過度描述私人原因。
- [字數，例如 120 字]內。
- 只能使用上述資料；沒有提供的日期、代理安排或核准結果標為[待補]，不要自行補寫。

【輸出格式】
依序輸出：主旨、正文、署名[姓名／職稱]。直接給可編輯草稿。
```

## Email 02｜報告延期

```text
【背景】
我是[姓名／職稱]，原定在[原期限]交付[報告名稱]給[收件者]。目前已完成[已完成部分]，因為[已知原因]，預計需要延後到[新期限／若尚未確認則寫待補]。

【任務】
請寫一封 Email，向[收件者]清楚說明報告延期、目前進度與下一步安排。

【限制】
- 語氣負責、直接、不使用「萬分抱歉」「敬請見諒」等空泛套話。
- [字數]字內；只陳述已知事實，不把[進行中／待確認]寫成已完成。
- 沒有確認的新期限、補償或保證標為[待補]，不要自行承諾。

【輸出格式】
輸出主旨、正文、署名；正文最後列出需要對方確認的事項[事項]。
```

## Email 03｜感謝信

```text
【背景】
我是[姓名／身分]，想感謝[收件者姓名／稱呼]在[事件／期間]提供[具體協助]，這項協助讓我[具體結果或幫助]。我們的關係是[同事／客戶／老師／合作夥伴／其他]。

【任務】
請寫一封感謝 Email，讓對方知道我感謝的具體原因與後續想保持的聯繫。

【限制】
- 語氣真誠、溫暖、不要像制式賀詞。
- [字數]字內，不新增我沒有提供的合作成果或承諾。
- 若後續行動尚未確定，寫成[待補]，不要替我安排日期。

【輸出格式】
輸出主旨、三段內正文與自然的署名[姓名]。
```

## Email 04｜會議邀約

```text
【背景】
我是[姓名／職稱]，想邀請[對象／團隊]討論[會議主題]。已知時間為[日期與時段／尚未確定]，地點或連結為[地點／連結／待補]，預計需要[分鐘]分鐘，與會者需要事前準備[資料／問題]。

【任務】
請寫一封會議邀約 Email，讓收件者知道為什麼開會、何時何地開會，以及會前要準備什麼。

【限制】
- 語氣清楚、禮貌、結論先講。
- 未確認的時間、地點、連結與回覆期限一律標[待補]。
- 不自行增加議程或與會者；[字數]字內。

【輸出格式】
主旨；正文用條列列出主題、時間、地點／連結、預計時長、事前準備與回覆方式；最後加署名。
```

## Email 05｜客戶回覆

```text
【背景】
我是[公司／職稱]的[姓名]，收到客戶[客戶姓名／公司]詢問[問題／方案／案件]。已確認的資訊是：[事實 1]、[事實 2]；尚未確認的是：[待確認問題]。我們的關係是[新客戶／合作中／長期客戶]。

【任務】
請寫一封回覆給[客戶]的 Email，先回答已知問題，再詢問缺少的資訊，讓雙方知道下一步。

【限制】
- 語氣專業、有禮、讓人放心，但不要過度承諾。
- [字數]字內，只能使用已確認事實；未知的日期、價格、折扣、交期或政策標為[待補]。
- 必須保留這些內容：[必須保留的數字／條件／問題]。

【輸出格式】
輸出主旨、正文、下一步、署名；不要先解釋寫作方法。
```

## Email 06｜追蹤未回覆

```text
【背景】
我在[日期]寄出一封關於[主題／文件／報價]的 Email 給[收件者]，目前尚未收到回覆。原信希望對方確認[要確認的事項]；我希望在不造成壓力的情況下知道對方是否看過。

【任務】
請寫一封禮貌的跟進 Email，提醒原本的事項並請對方回覆[具體問題]。

【限制】
- 語氣客氣、簡短、不使用威脅或自行設定的最後期限。
- [字數]字內；若我沒有提供期限、後果或替代方案，不要自行添加。
- 保留原本主題與必要附件／連結：[資訊或待補]。

【輸出格式】
輸出主旨、正文、署名；直接給成品。
```

## Email 07｜交接通知

```text
【背景】
我是[姓名／職稱]，將在[期間]無法處理[工作／專案]。目前狀態是[進度]，已交接給[代理人／若尚未安排則待補]；對方可以透過[聯絡方式]處理[緊急事項]。

【任務】
請寫一封交接通知 Email 給[收件者群體]，說明期間、目前狀態、代理安排與必要行動。

【限制】
- 語氣清楚、可靠、不要添加沒有提供的進度或承諾。
- [字數]字內；未知的代理人、日期或聯絡方式標[待補]。
- 必須讓讀者知道需要做的事：[回覆／提供資料／等待通知]。

【輸出格式】
主旨、正文；正文以條列列出期間、狀態、代理與緊急處理方式；最後署名。
```

## Email 08｜詢問資訊

```text
【背景】
我是[姓名／身分]，正在處理[任務／申請／採購]，目前已完成[已完成事項]，但缺少[資料 1、資料 2]。我要詢問[收件者]，因為沒有這些資料就無法完成[下一步]。

【任務】
請寫一封資訊詢問 Email，清楚列出需要對方提供的項目與用途。

【限制】
- 語氣有禮、直接、不要讓對方猜我要什麼。
- [字數]字內；沒有提供回覆期限就不要自行加期限。
- 保留資料項目的原名稱，不把[待確認內容]改成確定資訊。

【輸出格式】
輸出主旨、簡短背景、待提供資料條列、下一步與署名。
```

## Email 09｜提供修改回饋

```text
【背景】
我是[姓名／角色]，收到[對方]提供的[文件／設計／草稿]。整體可以保留的部分是[保留內容]；需要修改的部分是[修改項目]，原因是[具體原因]。希望在[日期／待補]前看到[修正版／確認結果]。

【任務】
請寫一封清楚而有合作感的修改回饋 Email，讓對方知道保留什麼、修改什麼與下一步。

【限制】
- 語氣直接但尊重，不使用模糊的「再好一點」「自然一點」。
- [字數]字內；只使用我列出的回饋，不新增評價或期限。
- 若回饋優先順序未提供，請標[待補]，不要自行排序。

【輸出格式】
主旨、開場肯定、修改事項條列、下一步、署名。
```

## Email 10｜活動提醒

```text
【背景】
我是[主辦方／姓名]，要提醒[對象]參加[活動名稱]。已知活動日期與時間為[日期時間]，地點／連結為[地點／連結／待補]，參加前需要準備[物品／資料]，聯絡窗口是[姓名／方式／待補]。

【任務】
請寫一封活動提醒 Email，讓收件者能快速找到時間、地點、準備事項與需要回覆的內容。

【限制】
- 語氣親切、清楚、不要製造未提供的優惠或名額壓力。
- [字數]字內；缺少的連結、期限或聯絡方式標[待補]。
- 必須保留：[活動時間／地點／準備事項]。

【輸出格式】
主旨；正文用條列呈現活動資訊與行動提醒；最後署名。
```

# B. 10 個訊息情境提示詞

訊息通常比 Email 短，但仍要交代背景、任務、限制與格式。把「收件者關係」與「對方下一步」寫出來，模型才不會把訊息寫成無人稱的公告。

## 訊息 01｜婉拒邀約

```text
【背景】
[對方姓名／關係]邀請我參加[活動／合作／聚會]，時間是[時間]。我這次無法參加，原因可簡短說成[原因／不想透露則寫不便]；我願意[提出替代時間／保持聯繫／不提出替代方案]。

【任務】
請幫我寫一則訊息，禮貌婉拒[對方]的邀約，同時清楚表達[替代安排／感謝]。

【限制】
- 語氣[親切／尊重／直接]，不要讓對方以為我只是暫時猶豫。
- 2–4 句，不新增我沒有同意的替代時間或承諾。

【輸出格式】
只輸出可直接傳送的訊息，不要加標題或解釋。
```

## 訊息 02｜催促回覆

```text
【背景】
我在[日期／時間]請[對方姓名／關係]確認[事項]，目前還沒有收到回覆。這個回覆會影響[下一步／排程]，但我不想讓訊息像在責備對方。

【任務】
請幫我寫一則提醒訊息，請對方回覆[具體問題]。

【限制】
- 語氣客氣但明確，2–3 句；不要自行設定期限或威脅後果。
- 只提及已提供的事項；缺少期限標[待補]。

【輸出格式】
只給可直接傳送的訊息，最後保留一個清楚的回覆問題。
```

## 訊息 03｜道歉

```text
【背景】
我在[事件]中造成[對方姓名／關係]不便，已知事實是[具體事實]。我能做的補救是[補救行動／尚未確認則待補]，我希望對方知道我會[下一步]。

【任務】
請幫我寫一則真誠道歉訊息，承認造成的影響並說明下一步。

【限制】
- 2–4 句，語氣誠懇但不卑微；不替我承諾未確認的賠償或期限。
- 只能根據已知事實，缺少的補救內容標[待補]。

【輸出格式】
只輸出訊息成品，不先分析。
```

## 訊息 04｜報平安

```text
【背景】
我目前在[地點／行程]，原本預計在[時間]抵達／回家；現在的狀況是[目前狀態]。收件者是[家人／朋友／同事]，他可能因為[原因]擔心我。

【任務】
請幫我寫一則簡短報平安訊息，告知目前狀況與下一次聯絡時間。

【限制】
- 語氣自然、讓人放心，2–3 句；沒有提供的抵達時間標[待補]。
- 不誇大目前狀況，也不新增我沒有說過的行程。

【輸出格式】
只輸出可以直接傳送的訊息。
```

## 訊息 05｜解釋誤會

```text
【背景】
[對方]以為我[對方的理解]，但實際情況是[事實]。誤會可能來自[漏回訊息／說法不清／時間差]；我希望對方知道[真正意思／下一步]。

【任務】
請幫我寫一則訊息，先承認說法可能不清楚，再用簡單方式解釋事實與下一步。

【限制】
- 語氣平和、不反駁、不把責任推給對方；3–5 句。
- 不能新增對話中沒有的承諾或原因。

【輸出格式】
只給可直接傳送的訊息，順序是：承接感受、澄清事實、下一步。
```

## 訊息 06｜請同事幫忙

```text
【背景】
我是[姓名／職稱]，需要請[同事姓名]協助[具體工作]。目前我已完成[已完成事項]，希望對方幫我處理[需要協助的部分]，最好在[時間／待補]前完成。

【任務】
請幫我寫一則清楚、有禮的請求訊息，讓對方知道要幫什麼與何時回覆。

【限制】
- 2–4 句、像同事間的日常訊息；未確認的期限標[待補]。
- 不把請求寫成對方已答應的事，也不新增工作內容。

【輸出格式】
只輸出訊息成品，最後留一個可以回答「可以／不行」的問題。
```

## 訊息 07｜改約

```text
【背景】
我和[對方]原定在[原日期時間]進行[會面／通話／活動]，但因[已知原因]需要改期。我可以配合的時段是[選項 1]、[選項 2]；若對方都不方便，再請他提供可行時間。

【任務】
請幫我寫一則改約訊息，說明變更並提出可選時段。

【限制】
- 語氣禮貌、直接，3–4 句；只能使用我提供的時段。
- 不要自行判定對方一定能配合，也不要新增地點或連結。

【輸出格式】
只輸出可直接傳送的訊息。
```

## 訊息 08｜表達感謝

```text
【背景】
[對方]剛剛在[事件／任務]中幫了我[具體協助]，讓我能[結果]。我們的關係是[朋友／同事／合作夥伴／其他]。

【任務】
請幫我寫一則自然的感謝訊息，說出具體感謝原因。

【限制】
- 1–3 句，避免制式或過度誇張的稱讚。
- 不新增對方沒有做過的事，也不安排未確認的回報。

【輸出格式】
只輸出可直接傳送的訊息，可在最後加入[下次請對方喝咖啡／保持聯絡／其他]。
```

## 訊息 09｜邀請聊天或見面

```text
【背景】
我想邀請[對方姓名／關係]在[日期／時段／待補]聊聊[主題]。我們上次談到[共同背景]；我希望這次談完能[目標]。

【任務】
請幫我寫一則自然邀請訊息，說明想聊的主題並詢問對方是否方便。

【限制】
- 語氣[輕鬆／禮貌／專業]，2–4 句；沒有確認的地點、時間不要自行補寫。
- 不把邀請寫成對方已經答應。

【輸出格式】
只輸出可直接傳送的訊息，結尾用一個明確問題。
```

## 訊息 10｜提醒截止前行動

```text
【背景】
我要提醒[對方／群組]在[日期時間／待補]前完成[行動]。這件事的原因是[原因]；完成後請回覆[回覆內容]。目前已知的協助方式是[方式／待補]。

【任務】
請幫我寫一則行動提醒訊息，讓讀者快速知道期限、要做什麼與完成後如何回覆。

【限制】
- 語氣清楚、友善、2–4 句；未提供的期限或後果標[待補]。
- 不製造焦慮，不增加我沒有提供的規定。

【輸出格式】
只輸出可直接傳送的訊息，先講行動，再講原因與回覆方式。
```

# C. 自我介紹資料表與三版提示詞

## 先填一次的個人資料表

三個版本必須使用同一份資料。表格可以填真實或練習用資料；只填你願意拿來練習的內容。

| 欄位 | 我的資料 | 填寫提醒 |
|---|---|---|
| 我希望別人怎麼稱呼我 | `[稱呼]` | 可用名字或暱稱 |
| 目前身分／正在做的事 | `[工作、學習或生活身分]` | 用一句話即可 |
| 最近投入的事情 | `[正在做的專案、學習或興趣]` | 寫具體活動，不必誇張 |
| 我感興趣的主題 | `[主題 1、主題 2]` | 選願意和別人聊的內容 |
| 一個可分享的小經驗 | `[事件與我做了什麼]` | 只填自己確定的事實 |
| 我希望認識／貢獻什麼 | `[想認識的人或能提供的協助]` | 依用途可留空 |
| 不想在這次介紹中提到的內容 | `[不要出現的內容]` | 讓模型知道要避開什麼 |

### 填寫示範：阿凱的同一份資料

| 欄位 | 範例值 |
|---|---|
| 我希望別人怎麼稱呼我 | 阿凱 |
| 目前身分／正在做的事 | 在弄一下行銷工作室負責一般文書與生活安排 |
| 最近投入的事情 | 練習把日常文字整理成可直接使用的初稿 |
| 我感興趣的主題 | 小店行銷、散步、把複雜事情說清楚 |
| 一個可分享的小經驗 | 最近替工作室整理客戶回覆模板，並比較不同讀者的語氣 |
| 我希望認識／貢獻什麼 | 想認識也在學習數位工具的人，分享文字整理方法 |
| 不想在這次介紹中提到的內容 | 未提供的工作成果、年資或收入 |

## 自我介紹 01｜社交場合

```text
【背景】
以下是我的個人資料，請只使用這份資料：
[貼上同一份個人資料表]
場合是[聚會／課程／活動]，對象是[第一次見面的人／同領域的人]。

【任務】
請寫一版適合社交場合的自我介紹，讓對方快速知道我目前在做什麼，也留下一個容易接話的主題。

【限制】
- 使用繁體中文，語氣自然、親切、不像履歷。
- 80–120 字，保留資料中的稱呼、目前身分與一個興趣或經驗。
- 只能使用資料表內容，不新增職稱、成就、年資或個人故事。

【輸出格式】
直接輸出一段可口頭說出的自我介紹，最後加一個自然的開放式問題。
```

## 自我介紹 02｜線上交友

```text
【背景】
以下是我的個人資料，請只使用這份資料：
[貼上完全相同的個人資料表]
使用場合是[交友平台／興趣社群]，讀者是可能想先了解我的陌生人。

【任務】
請寫一版線上交友用的自我介紹，讓人知道我平常在意什麼，以及可以從哪個主題開始聊天。

【限制】
- 使用繁體中文，語氣真誠、輕鬆、有界線，不過度包裝自己。
- 80–120 字；保留同一份資料中的事實，不新增生活經歷、興趣或期待。
- 避免空泛形容詞，例如「很優秀」「超級有趣」；改用資料中的具體活動。

【輸出格式】
直接輸出一段可放在個人頁面的文字，不加標題、不解釋修改理由。
```

## 自我介紹 03｜求職面試

```text
【背景】
以下是我的個人資料，請只使用這份資料：
[貼上完全相同的個人資料表]
面試職位是[職位名稱]，面試官想了解我的背景、相關能力與想投入的方向。

【任務】
請寫一版求職面試的自我介紹，讓我在[60–90 秒／字數]內說明背景、相關經驗、能帶來的貢獻與求職動機。

【限制】
- 使用繁體中文，語氣專業、清楚、有自信但不誇大。
- 120–180 字；只能使用資料表中的身分、經驗與興趣，不新增職責、數字、成果或年資。
- 若資料不足以支撐某項能力，標為[待補]或改成「正在學習」，不要替我補成就。

【輸出格式】
依序輸出：背景一句、相關經驗一句、能提供的貢獻一句、求職動機一句；直接給可練習朗讀的版本。
```

### 三版共同檢查

把三版並排後，先圈出共同事實，再看不同場合的調整：

- 社交版：開場較像當面說話，留一個可接話的興趣。
- 線上交友版：讓讀者感覺能理解你，也保留自然界線。
- 求職版：把資料中的經驗與貢獻放前面，避免新增履歷內容。

# D. 迭代指令速查表

每次只選一列使用。指令後面加上「保留＿＿」會更容易控制結果。

| 想要的變化 | 可直接複製的迭代指令 | 這輪要保留 |
|---|---|---|
| 降低正式度 | `太正式了，保留原本的事實與下一步，改成像和熟悉的對象說話。` | 事實、目的、行動 |
| 縮短 | `再短一點，保留[日期／價格／原因／行動]，控制在[句數／字數]內。` | 指定資訊 |
| 改輕鬆 | `換成輕鬆口吻，像平常傳訊息給[同事／朋友]，但不要改變原本意思。` | 原本意思與關係 |
| 更直接 | `開頭直接講重點，刪掉寒暄與空泛套話；其餘事實保留。` | 必要事實 |
| 更有禮 | `保留拒絕／提醒的結論，改成直接但有禮，不要讓對方誤以為我已答應。` | 真實立場 |
| 只改一段 | `只改第[一／二／三]段，其他段落與資訊保留。` | 未指定段落 |
| 改成訊息 | `把這段改成 2–4 句可直接傳送的訊息，保留[必要資訊]，不要加主旨。` | 行動與必要資訊 |
| 改成口頭介紹 | `把這段改成可以自然說出口的自我介紹，保留[身分／興趣／經驗]。` | 指定資料 |
| 不要新增內容 | `只使用原文與背景中的事實；找不到依據的內容標[待補]，不要自行補寫。` | 事實邊界 |
| 需要兩種選擇 | `請在保留相同事實下給兩版：A[較正式]、B[較親切]，各自適合什麼對象用一句話說明。` | 事實與任務 |

## 迭代後的三句檢查

```text
我這輪只改了：[正式度／長度／口吻／某一段／格式]
我刻意保留了：[日期、金額、行動、經歷等]
修正版仍適合：[讀者與使用場合]
```

# E. 成果檢核表

## 所有文字都要檢查

- [ ] 我能說出這份文字寫給誰。
- [ ] 我能說出它要完成的動作或讓讀者採取的下一步。
- [ ] 背景包含必要的已知資料；沒有把猜測當成事實。
- [ ] 限制有寫語氣、長度與不能新增的內容。
- [ ] 輸出格式符合用途，而不是只得到一大段文字。
- [ ] 未提供的日期、金額、期限、承諾或經歷沒有被模型自行補成確定值。
- [ ] 我保存了原始提示詞、第一版、迭代指令與修正版。
- [ ] 我能用一句話說明這輪只改了哪一個主要變因。

## Email 專用

- [ ] 有合適的主旨、稱呼、正文與署名。
- [ ] 收件者能看懂背景、重點與下一步，不需要回頭猜。
- [ ] 請假有日期與交接；延期有目前狀態與新期限／待補；感謝信有具體原因；會議邀約有時間地點與準備；客戶回覆有已知答案與待確認問題。
- [ ] 任何未核定的折扣、補償、交期或承諾都沒有被寫成已確定。

## 訊息專用

- [ ] 句數適合訊息，不是把 Email 原封不動縮短。
- [ ] 關係與語氣符合對象；婉拒是清楚拒絕，催促是明確詢問，道歉有下一步，報平安有目前狀態，誤會說明有事實與澄清。
- [ ] 收件者讀完知道需要回覆或採取什麼行動。

## 三版自我介紹專用

- [ ] 三版都使用同一份個人資料表。
- [ ] 社交版有容易接話的主題。
- [ ] 線上交友版自然、具體，不過度包裝。
- [ ] 求職版有背景、相關經驗、可提供的貢獻與動機。
- [ ] 沒有任何一版新增資料表中沒有的成就、年資、數字或經歷。
- [ ] 我能說出三版因讀者、場合與目的而改變的地方。
