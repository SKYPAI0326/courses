## 教學流程（Teaching Flow）

### 破題 / Hook

阿凱第一次使用 LLM 時，常常只輸入「幫我想一下」或「這是什麼」，得到的回答有時太長、有時不符合他的情境。他今天要留下的不是一段漂亮示範，而是一份可以重做的實務紀錄：五個日常問題、每題的回答、一次修改，以及自己判斷回答是否可用的理由。

學員手上有兩份材料：`assets/worksheets/unit1-practice-sheet.md` 是可填寫的紀錄表，`assets/fallback/unit1-dialogue-simulator.md` 是 LLM 暫時無法使用時的離線備援。課程結束時，填寫版紀錄表就是完成物；第 2 單元會沿用其中的五欄提示詞框架。

### 概念 / Concepts

- **LLM** — 能用文字對話協助產生、整理或改寫內容的語言模型；它會依照你提供的文字與條件產生回答，不等於自動替你做最後判斷。
- **搜尋問題** — 目標是找到外部資料或網頁；例如查詢明天的天氣時，重點是時間與資料來源。
- **對話任務** — 目標是把一件事交代給 LLM 處理；例如依照人數、預算與飲食限制提出晚餐選項。
- **提示詞** — 你交給 LLM 的任務說明；越清楚交代情境、任務、資料、條件與格式，越容易得到可使用的初稿。
- **修改指令** — 對第一版回答追加的調整要求，例如「縮短成 80 字」或「改成表格」。

#### 五欄提示詞框架

| 欄位 | 白話意思 | 例子：晚餐建議 |
|---|---|---|
| 情境 | 事情發生在哪裡 | 今天下班後要安排晚餐 |
| 任務 | 要 LLM 幫你做什麼 | 提出三個晚餐選項 |
| 資料 | LLM 必須知道的條件 | 兩人、不吃牛、預算 600 元 |
| 條件 | 不能違反的限制 | 30 分鐘內完成 |
| 格式 | 答案要長什麼樣 | 表格，列出菜色、時間、預算 |

### 操作示範 / Demo

#### 先看同一個需求的兩種寫法

阿凱想知道「去日本旅遊要怎麼安排」。這句話可以作為搜尋關鍵字，也可以交給 LLM 做規劃；兩者任務不同。

**搜尋方向**：輸入「京都四天三夜寺廟美食交通」，目標是找到外部網頁、價格與別人的行程。

**LLM 方向**：

```text
我想安排四天三夜的京都自由行。請先提出一份初稿，條件是：預算 4 萬元、喜歡寺廟與美食、每天不要排超過三個主要景點。請用表格列出日期、區域、主要行程與需要再確認的資訊。不要假設目前的票價或營業時間一定正確。
```

這個提示詞把「想去日本」改成了可執行任務：有情境、有任務、有資料、有條件，也指定了格式。輸出仍只是規劃初稿；票價、營業時間與交通班次要另外查最新資料。

#### 完整示範：從模糊問題改成可用初稿

**原始輸入**：

```text
幫我想晚餐。
```

**問題**：LLM 不知道幾個人吃、預算多少、有哪些不能吃的食材，也不知道你要一份清單、食譜或餐廳建議。

**改寫後輸入**：

```text
我今天下班後想安排晚餐。請依照以下條件提出三個選項：兩人、預算 600 元、不吃牛、希望 30 分鐘內完成。請用表格列出菜色、預估時間與預算，最後告訴我還缺哪一個條件。
```

**示範輸出**：

| 選項 | 菜色 | 預估時間 | 預算 |
|---|---|---:|---:|
| A | 番茄雞肉義大利麵＋沙拉 | 25 分鐘 | 420 元 |
| B | 豆腐蔬菜鍋＋白飯 | 30 分鐘 | 480 元 |
| C | 蝦仁蛋炒飯＋燙青菜 | 20 分鐘 | 360 元 |

仍缺的條件可能是「家裡現有的食材」或「是否需要外帶」。這表示提示詞已經足夠產生初稿，但還可以用一個修改指令繼續縮小範圍。

### 動手 / Hands-on

#### 起始狀態與最短可跑路徑

你已經能開啟一個可輸入文字的 LLM 對話畫面，並下載或開啟 [第 1 單元實務紀錄表](assets/worksheets/unit1-practice-sheet.md)。如果暫時無法使用 LLM，先開啟 [離線備援結果](assets/fallback/unit1-dialogue-simulator.md)，完成第 3 與第 5 題的觀察，再回到本頁繼續記錄。

你要留下的完成物是填寫版 `unit1-practice-sheet.md`：其中有五個問題、五個回答、一次修改，以及四個完成檢查。每完成三個問題就停下來核對一次，不要等到最後才發現沒有保存回答。

#### 同步演練步驟

**階段 U1-START｜建立紀錄位置**

1. **Together · 開啟紀錄表並寫下自己的姓名與日期**

   - **學員操作**：開啟 `unit1-practice-sheet.md`，先填姓名與日期；在自己使用的 LLM 對話畫面開一個新的對話。
   - **講師提示**：紀錄表是本單元的完成物，不要只在對話畫面瀏覽回答。
   - **預期結果**：你同時看得到紀錄表與可輸入文字的對話畫面。
   - **快速檢查**：能指出「回答要貼到哪裡」以及「本單元最後要留下什麼」。
   - **卡住時**：找不到紀錄表 → 回到 `U1-START` → 重新開啟資產連結 → 從步驟 1 重做；若編輯器無法儲存，改用複製內容的文字檔保存，安全停止在「姓名與日期已記錄」。

   這一步建立了保存位置；接下來每一題都會把原始問題、回答與觀察寫回同一份紀錄表。

**階段 U1-ASK｜完成五個基本對話**

2. **Together · 送出自我介紹問題並觀察回答**

   - **學員操作**：複製紀錄表第 1 題的完整提示詞，貼到 LLM，送出後把回答貼回「我觀察到的回答」。
   - **預期結果**：回答至少提到 LLM 能協助的三類事情，以及需要人自行確認的內容。
   - **快速檢查**：回答是否真的在介紹它能做什麼，而不是直接替你完成另一個任務。
   - **卡住時**：回答偏離問題 → 回到 `U1-ASK` → 在原提示詞最後加上「請只回答自我介紹」→ 從步驟 2 重跑，不刪除第一版。

3. **Together · 詢問明天台北的天氣**

   - **學員操作**：送出紀錄表第 2 題，保留回答中的日期、時間與資料依據；若 LLM 說無法取得即時資料，也把這個結果記下來。
   - **預期結果**：你會得到天氣回答，或得到需要改用即時資料來源的說明。
   - **快速檢查**：能指出回答是否說明「根據哪個時間」以及是否需要另外查證。
   - **卡住時**：回答只有晴雨結論、沒有時間 → 回到 `U1-ASK` → 追加「請先說明資料時間與來源」→ 從步驟 3 重跑；不要把缺少時間的回答當成完成品。

4. **Together · 請 LLM 提出晚餐選項**

   - **學員操作**：送出紀錄表第 3 題，確認回答有表格、三個選項、時間與預算；在紀錄表寫下最符合自己的選項。
   - **預期結果**：回答會依兩人、不吃牛、600 元與 30 分鐘四個條件提出選項，並指出仍可能缺少的條件。
   - **快速檢查**：逐一圈出輸出中對應四個條件的位置。
   - **卡住時**：回答忽略某個條件 → 回到 `U1-ASK` → 只補上被忽略的條件 → 從步驟 4 重跑；保留原回答作為比較。

**Checkpoint U1-CHECK-1**

現在應該看到：紀錄表已經有前 3 題的回答，晚餐題至少有一份表格。若沒看到：檢查是否真的把「完整提示詞」貼上，而不是只貼題目標題；回到步驟 2、3 或 4 對應位置修正。通過後才能繼續，因為後兩題會要求你分辨解釋與整理兩種不同任務。

5. **Solo · 用自己的話請 LLM 解釋 ETF**

   - **學員操作**：送出紀錄表第 4 題；讀完後用自己的話寫一句 ETF 是什麼，並保留 LLM 列出的三個待查問題。
   - **預期結果**：回答先有一句話定義，再有生活化例子，最後列出需要再查資料的問題；不直接替你做投資推薦。
   - **快速檢查**：你的重述是否包含「一籃子資產、可以在市場交易」兩個核心意思，且沒有把範例當成購買建議。
   - **卡住時**：回答太專業 → 回到 `U1-ASK` → 追加「請改用國中生聽得懂的方式，不增加新的金融術語」→ 從步驟 5 重跑；保留原版，避免只看修改版。

6. **Solo · 把一段通知整理成三個重點**

   - **學員操作**：送出紀錄表第 5 題；比較整理前後是否保留週三、晚上 7 點、下午 6 點前移車與雨天順延四個資訊。
   - **預期結果**：得到三個條列重點，且沒有加入通知原文沒有的規定。
   - **快速檢查**：在回答中標記日期、時間、住戶行動與雨天備案。
   - **卡住時**：回答刪掉重要時間 → 回到 `U1-ASK` → 追加「日期、所有時間、住戶行動與雨天備案都必須保留」→ 從步驟 6 重跑；不要清除舊版，留下前後差異。

**Checkpoint U1-CHECK-2**

現在應該看到：五個基本問題都有回答，第 5 題的條列保留四個指定資訊。若沒看到：用離線備援文件先比對「晚餐」或「通知整理」的預期樣子，再回到對應步驟修正。通過後才能進入修改練習，因為你已經有一份可被修改的第一版回答。

**階段 U1-REVISE｜修改一個結果**

7. **Together · 只改一個條件並比較前後版本**

   - **學員操作**：從五個回答中選一個，輸入「太長了，請縮短成 80 字」或「請改成表格，只保留我需要做的事」；把第二版接在第一版下面。
   - **預期結果**：第二版只針對長度、語氣或格式其中一項改變，其他內容大致保留。
   - **快速檢查**：你能說出這次改了哪一個條件，以及哪一項內容被保留。
   - **卡住時**：第二版同時改了很多事情 → 回到 `U1-REVISE` → 刪除多餘要求，只留一個修改條件 → 從步驟 7 重跑；保留兩個版本作為學習紀錄。

**階段 U1-SAVE｜保存與轉移**

8. **Solo · 完成紀錄表的自我檢查**

   - **學員操作**：逐項勾選紀錄表最後的四個完成條件，將填寫版保存成 `unit1-practice-sheet-complete.md` 或貼到自己的文字筆記。
   - **預期結果**：文件包含五題原始問題與回答、一次修改、需要再查資料的地方，以及四項勾選結果。
   - **快速檢查**：把文件交給沒有參加這堂課的人，他能看出你問了什麼、得到什麼、哪一題需要再確認。
   - **卡住時**：缺少某題原始提示詞 → 回到 `U1-SAVE` → 重新開啟工作表複製該題 → 從步驟 8 重做；不要刪除現有回答，安全停止時至少保存目前版本。

   你現在留下的是可重做的紀錄，而不是一次性的聊天內容。第 2 單元會把同一套五欄方法改寫成 Email、LINE 與自我介紹。

### 檢核 / Verification

完成前做三個動作：

1. 打開填寫版紀錄表，確認五題的原始提示詞與回答都在同一份文件中。
2. 隨機挑一題，用螢光筆或文字標記情境、任務、條件、格式四種資訊；缺少哪一種就補回提示詞。
3. 讀第一版與第二版回答，說出修改指令改變的是長度、語氣或格式其中哪一項。

通過標準是：五題皆有回答、至少一題有前後版本、至少一題記錄了需要再查資料的地方，而且你能用一句話說明第 2 單元會沿用哪個方法。

## 講師授課筆記（不進講義）

- **時間建議**：破題與概念 25 分鐘；完整示範 25 分鐘；五題同步演練 80 分鐘；修改與保存 30 分鐘；回顧與緩衝 20 分鐘。
- **主線**：固定使用同一份工作表，避免學員把回答散落在不同對話或裝置中。
- **備線**：網路或 LLM 暫時不可用時，讓學員使用離線備援完成「看輸入條件 → 對照結果 → 填紀錄」；恢復後只重做第 3、5 題即可。
- **教學提醒**：不要要求所有人使用同一個 LLM。講師只比較輸入條件與輸出是否符合任務，不比較平台品牌。
- **NotebookLM 銜接**：只在結尾說明第 3 單元會把「來源、任務、格式」帶入 NotebookLM；本單元不提前操作 NotebookLM。

## 商業情境案例（Case）

- **角色**：阿凱
- **公司**：弄一下行銷工作室
- **任務**：阿凱要把「我不知道怎麼問 AI」改成五個可以保存、比較與重做的日常提問，以便下一單元開始處理文字工作。
- **本單元要他學會**：辨認任務類型、補齊提示詞條件、讀懂第一版輸出並用一個修改指令改善結果。

## 動手練習題（Hands-on Exercise）

**題目**：從自己的生活或工作中再挑一個問題，例如安排週末、整理通知或解釋一個陌生名詞。先用一句模糊問題取得第一版，再補上至少三個條件與一種輸出格式，最後只修改一個條件。

**預期成果**：一組「模糊版 → 條件版 → 修改版」的三段紀錄，並在旁邊寫一句話說明哪一版最適合使用、原因是什麼。

**完成標準**：

- [ ] 條件版明確寫出任務與至少三個限制或資料。
- [ ] 輸出格式可觀察，例如表格、三個條列或 80 字內。
- [ ] 修改版只改一個主要條件，並保留前一版作比較。

## 常見錯誤 3 條（Common Pitfalls）

1. **錯誤現象**：輸入只有「幫我處理一下」，回答看似完整但和需求不相干。**原因**：沒有交代任務、條件與輸出格式。**解法**：回到 `U1-ASK`，補填五欄中的任三欄，先重跑一個小任務。

2. **錯誤現象**：第二輪輸入一次要求縮短、改語氣、改格式，結果無法判斷是哪個要求造成變化。**原因**：一次改了多個主要條件。**解法**：回到 `U1-REVISE`，每輪只保留一個修改指令。

3. **錯誤現象**：學員只保存最後回答，無法說明原本問了什麼。**原因**：沒有把原始提示詞與第一版回答一起保存。**解法**：回到 `U1-SAVE`，把原始輸入、第一版、第二版依序放在同一份紀錄表。

## 檢核題 2 條（Quiz）

**Q1（概念驗證）**：哪一句最適合交給 LLM 產生晚餐初稿？

- [ ] A. 晚餐吃什麼？
- [ ] B. 幫我找晚餐。
- [x] C. 兩人、不吃牛、預算 600 元、30 分鐘內完成，請用表格提出三個晚餐選項。
- [ ] D. 今天很累。

**Q2（應用驗證）**：你得到一篇太長的通知摘要，想保留日期、時間與住戶要做的事。下一輪要怎麼問？

- **預期答案要點**：指出要保留的資訊；指定輸出長度或條列格式；一次只做這項修改，並保留第一版作比較。
