SQL Server 的物件層級

本課約 10 分鐘。目標是讓你能正確說明連線與資料物件的層級。今天沒有可用的 SQL Server 實驗主機，因此本課只驗證概念回想，不把它算成操作能力。

概念

SQL Server Database Engine 以執行個體（instance）服務接受用戶端連線。執行個體管理一個或多個資料庫；資料庫內有結構描述與資料庫物件；資料表則以資料列與資料欄組織資料。

主機 — 電腦或 VM
Database Engine 執行個體 — 接收連線、管理資料庫
資料庫 — 管理資料與物件的容器
結構描述（schema） — 組織及命名資料庫物件
資料表 — 由資料列與資料欄組成

用戶端把 T-SQL 傳給執行個體。執行個體解析要求，對指定資料庫中的物件執行操作，並依登入與權限決定是否允許。這些層級有不同職責，所以診斷連線、找物件、權限或資料列問題時要先定位層級。

  1. 應用程式連到 SQL Server 的哪一層？
  2. 一個執行個體可以管理多個資料庫嗎？
  3. schema 和 table 各在哪一層？
  4. table 的 row 和 column 分別代表什麼？
  5. 用 45 秒向初學者講解這個層級順序。
