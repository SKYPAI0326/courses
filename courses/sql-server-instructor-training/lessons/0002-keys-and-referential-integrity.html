SQL SERVER INSTRUCTOR TRAINING · 02

主鍵、外鍵與資料完整性

本課約 15 分鐘。教材以 Microsoft 官方 AdventureWorks 範例資料庫和官方文件為依據；AdventureWorks 是範例資料，不代表真實客戶資料或生產事故。

先抓住兩個不同問題

主鍵（PRIMARY KEY）回答：「這一列如何被唯一辨認？」它可以是一個欄位，也可以由多個欄位組成。主鍵約束要求鍵值組合唯一且不可為 NULL。

外鍵（FOREIGN KEY）回答：「這個欄位的值可以參照到哪裡？」它把一個資料表的欄位連到另一個資料表的候選鍵，並由 Database Engine 執行參照完整性檢查。

複合主鍵的重點是「組合唯一」，不是要求每個欄位各自唯一。Microsoft 的 AdventureWorks 文件以 Purchasing.ProductVendor 為例，將 ProductID 與 VendorID 合在一起作為複合主鍵。這些是該官方範例資料庫的已記錄結構，不是本課杜撰的企業案例。

在真實範例資料庫查證

  1. 先確認已連線到正確的 SQL Server 執行個體，並選取與版本相符的 AdventureWorks 範例資料庫。
  2. 執行鍵約束盤點查詢。它只讀資料庫名稱、中繼資料和鍵欄位，不會修改資料。
  3. 在結果中找到 Purchasing.ProductVendor 的主鍵欄位，依 ORDINAL_POSITION 看欄位順序；再讀外鍵約束的欄位。
  4. 最後一個查詢找出重複的 (ProductID, VendorID) 組合。若主鍵存在且啟用，這個查詢應不會列出重複組合；實際輸出仍須由你在環境中執行確認。

若物件 ID 是 NULL 或 metadata 查詢沒有列出約束，先核對目前資料庫、AdventureWorks 版本、物件名稱和帳號可見性，不要臆測查詢已成功。

閉卷講解

  1. 為什麼主鍵可以由多個欄位組成？
  2. 複合主鍵保證每一欄各自唯一嗎？它真正保證什麼？
  3. 外鍵由哪一層強制檢查？它保護什麼資料關係？
  4. 把主鍵約束說成「一種索引」是否完整？還缺了什麼語意？
驗收狀態：待本人作答與實機查詢。讀完教材不算掌握；需由你說明主鍵／外鍵差異，並在 AdventureWorks 上提供實際查詢結果。
