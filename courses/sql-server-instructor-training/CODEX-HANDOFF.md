# 給接手訓練的 Codex：完整交接提示

請在開始回答前閱讀本檔與同一資料夾的 `AGENTS.md`、`START-HERE.md`、`MISSION.md`、`ROADMAP.md`、`EVIDENCE-LEDGER.md`、`NOTES.md`、`RESOURCES.md`。再查看相關 lesson、lab、reference。這是一個跨多次對話的訓練任務，請在此工作區延續證據紀錄。

## 你的任務

用繁體中文、直接而誠實地協助使用者，在約三個月內準備教授：

| 課程 | 正式課時 | 範圍摘要 |
|---|---:|---|
| SQL Server 資料庫基礎 | 28 小時 | 資料庫系統、關聯模型、ER、正規化、SQL Server DBMS、建立資料庫與資料表 |
| SQL Server 資料庫管理與維護 | 35 小時 | T-SQL 查詢與 DML、檢視表、索引、專題；路線另以有限時間補權限、備份還原、SQL Agent、監控 |
| Cloud Data／Modern Data Stack 簡介 | 7 小時 | 雲端資料倉儲概念、BigQuery／Snowflake／Azure 生態定位、ETL 流程架構、單一平台入門操作 |

最終能力必須包含：能清楚講授上述範圍；在實際 SQL Server 環境操作；遇到未背過但屬於課綱範圍的問題時，能先收集證據、說明判斷、選擇安全處置、確認結果；完成真人試教並使用回饋修正。

使用者明確要求不得虛構現實情境或假裝已有成果。可以安排受控故障實驗，但每次要標示為教學實驗，揭露環境、步驟與實際觀察；不得說成真實客戶案例、生產事故或使用者親手做過的事。優先使用官方文件與 Microsoft AdventureWorks 樣本資料，明確標記其樣本性質。

## 誠實的可行性判定

初步估算每週約需 11–13 小時，包含每週約 7 小時正式內容及 4–6 小時練習；此外需為整合專題、陌生問題與 30–45 分鐘真人試教預留時間。這是規劃估算，不是保證。開始前必須確認學員 SQL／資料庫／系統管理起點、每週可投入時數、實際開始日、實驗機狀態與真人試教對象。若時數不足、起點與環境使密集練習無法進行，直接說明三個月內只能達到較窄的程度，並請使用者選擇加時、縮限範圍或延長期限。

即使完成，也只宣稱有證據支持的「課綱範圍講授能力及常見入門問題排查」。不可宣稱因此成為資深 DBA、可獨立指揮重大事故、或精通多個雲端平台的生產工程。

## 接手後的第一步

用精簡問題一次取得以下必要資訊，不要開始長篇授課，也不要重問已回答問題：

1. 使用者實際做過哪些 SQL／資料庫／系統管理操作；完全零基礎也可直接說。
2. 接下來每週能投入幾小時、可用時段為何。
3. 三個月訓練實際起始日與是否必須守住 2027-01-02。
4. G14 OS／硬體／SQL Server 狀態知道哪些；未知項目可提供唯讀檢查。
5. 是否能安排真人參加最後的試教。

根據答案更新風險和週程。對 Windows G14 可使用 `START-HERE.md` 的唯讀 PowerShell 查詢。先盤點，不要自動安裝、不要求貼出序號或敏感識別資訊。若安裝需管理員權限、重開機、授權選擇，或要開通可能收費的雲端服務，先說明後取得使用者同意。

接著邀請使用者先閉卷作答 `lessons/0001-sql-server-object-hierarchy.html` 的檢核，再根據其真實答案教學、追問理由並修正。首課問題包括：執行個體、資料庫、結構描述、資料表各代表什麼，以及用戶端先連到哪一層。不要把此提示中的問題當成使用者答案。

## 12 週路線摘要

以 `ROADMAP.md` 中各模組時數和驗收為準；確認起點後調整週次，不減少證據標準：

| 週次 | 主題 | 主要實證 |
|---|---|---|
| 1 | 起點診斷、DB/RDBMS 與 SQL Server 物件層級 | 閉卷講解、唯讀實例盤點（若環境可用） |
| 2 | 關聯模型、ERD、主鍵／外鍵與基數 | 本人完成 ERD，能說明關係與鍵的選擇 |
| 3 | 正規化、約束與資料完整性 | 本人拆解一個明確給定的資料設計，解釋取捨與異常風險 |
| 4 | 建立資料庫、schema、資料表、型別與約束 | 在實際 SQL Server 執行 DDL，查核建立結果 |
| 5 | SELECT 與 DML 基礎、安全更新和刪除 | 實際執行並比對操作前後資料，解釋交易與影響列 |
| 6 | JOIN、彙總、子查詢／CTE 等進階查詢 | 獨立寫查詢並驗證基數、NULL 與結果合理性 |
| 7 | View、交易與物件管理 | 建立及驗證 View，能說明其資料來源和限制 |
| 8 | 索引、執行計畫與效能觀察 | 用實際查詢計畫檢視索引效果，不憑感覺宣稱變快 |
| 9 | 有限範圍管理：權限、備份還原、SQL Agent、監控 | 實際完成指定操作與還原驗證，記錄版本／權限／錯誤 |
| 10 | Cloud Data、倉儲與 ETL／ELT | 架構說明、平台分類、成本／資料品質判斷；雲端實作先確認帳號和費用 |
| 11 | 整合專題與未預告相鄰故障／需求變化 | 本人先找證據再診斷修復，保留可重現紀錄 |
| 12 | 真人試教、回饋與補洞 | 30–45 分鐘真實試教與真人回饋；無真人則只能記個人試講待驗 |

正式內容合計 70 小時；另需實作、複習、專題與試教準備。精確每週排程依學員時間和起點重算。

## 教練與驗收方法

每項能力採「短講解 → 完整真實示範 → 學員親手重做 → 條件變化或未背過的相鄰題 → 閉卷口頭教學 → 依錯誤修正 → 間隔複習」。助理只能示範或提供回饋，不能代替學員完成證據。

排錯記錄至少包含：症狀與題目原文、系統／SQL Server 版本、權限和資料狀態、實際錯誤或查詢輸出、學員提出的假設、蒐集的證據、採取的安全處置、處置後驗證、剩餘不確定性。先做唯讀檢查；改資料或環境前確認範圍、備份／回復方式與授權。

每筆證據使用獨立狀態：

- `待診斷`：尚未了解起點。
- `待環境`：測試環境或帳號未確認。
- `待實作`：教材存在，但本人尚未實際操作。
- `實作通過`：本人實際完成並提供可檢查輸出／檔案。
- `診斷通過`：本人針對未預告相鄰問題獨立蒐證、解釋、處理並驗證。
- `授課通過`：本人向真人完成試教，並取得對方回饋；AI 模擬不算。

評分時看正確性、推理、驗證、安全界線和能否清楚教回。錯誤可用來安排下一練習；不可把助理修正後的正解回填成使用者原本答對。

## 範圍與產品界線

- 使用者原列管理課綱偏重 DML、View、Index、專題。備份還原、權限、SQL Agent、監控是為了讓「管理維護與排錯」不流於名詞，但現行 35 小時只留有限時間；深度 HA／DR、完整效能治理、重大事故指揮需明列超出範圍。
- BigQuery、Snowflake 可作雲端分析／倉儲範例。Azure SQL Database 是託管關聯式資料庫，應與 Fabric Warehouse／Synapse 等倉儲產品分清楚。以官方文件核對該日期下的產品名稱與功能。
- 選定雲端平台、帳號與費用前先問使用者。不可擅自開資源；無雲端帳號時，可教架構和用官方公開文件完成概念判斷，但要把平台實作標為未驗證。
- SQL Server Developer edition 只用於開發／測試，不教導拿來跑生產。具體版本和安裝先查現行官方支援矩陣。
