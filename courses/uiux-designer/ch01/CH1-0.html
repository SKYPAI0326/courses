UI/UX 設計入門｜開場

這是整門課的第一份。讀完你會知道：這門課要解決誰的什麼問題、UI 和 UX 到底在管什麼、我們打算怎麼一步一步教，以及第一章為什麼要從「顏色和文字」開始。這一份只要讀就好，不用動手。

開始前

你需要準備什麼

  • 一台電腦，加上 Chrome 或 Edge 瀏覽器。這門課要在大螢幕上畫畫面，手機不適合。
  • 一個 Figma 免費帳號。點下面的按鈕到 Figma 註冊，可以直接用 Google 帳號登入。免費方案就夠整門課使用。（註冊畫面我這邊沒有實際走過，卡住了就跟我說一聲。）

到 Figma 註冊免費帳號

不需要任何設計或程式基礎，也不用另外安裝軟體。

故事

你接到的案子：一間找不到工作的工作室

整門課都在處理同一個案子。我們先聽聽這間工作室的主管怎麼說：

「我每天早上把當天的工作貼在群組，大家往上滑找自己要做什麼。訊息一多就被洗掉，最後還是跑來問我。」

「工作室每個人都要看。有人整天坐在電腦前，也有人剛到客戶現場，手上只有手機。我最在意的是：用手機能很快找到待處理的工作。」

「怎樣算解決？成員能在手機上自己找到待處理的工作，看完內容就把它完成，不用再回群組問我『現在要做哪一件』。」

你會發現，這段話裡沒有提到任何按鈕、顏色或畫面。主管講的是一個問題：工作散在聊天訊息裡，大家找不到，只好一直問人。

在這個故事裡，你是接下這個問題的設計師。你的任務是設計一個手機 App，讓工作室成員打開就知道今天要做什麼、做完怎麼回報。整門課每一份講義，都是在把這個 App 往前做一步。

這門課在學什麼

UI 和 UX 是什麼

你每天都在用 App：外送、銀行、LINE。打開一個 App，你看到的每個按鈕、每行字、每種顏色，以及你按下去之後會發生什麼事，都是有人事先設計好的。這門課學的，就是怎麼設計這些東西。我們先看最常見的白話說法：

名詞白話意思出問題時長什麼樣
UI
User Interface，使用者介面		畫面長什麼樣：按鈕放哪、字多大、用什麼顏色。結帳按鈕顏色太淡，看不出它可以按。
UX
User Experience，使用者體驗		用起來順不順：使用者能不能很快找到要按的地方、不會按錯、知道下一步。要點五層選單才找得到結帳；按錯了也沒有提示怎麼回去。

再往深一層：UX 一定要先說清楚「誰、在哪、要完成什麼」

「順不順」聽起來很主觀，對吧？其實設計師實際判斷時，會把它拆成四個問題。同一個 App，換一個人、換一個情況，順不順的答案就不一樣：

要先問清楚放到工作室的故事裡
誰在用工作室成員，不是主管，也不是設計師自己。
在什麼情況下用可能在客戶現場，只有手機，只想很快看一眼。
要完成什麼找到今天待處理的工作，看懂內容，做完標記完成。
怎樣算成功 做得到：真的找到正確那一件，沒有標錯。
做得快：不用滑半天，也不用回群組問人。
做得安心：按下去知道有沒有成功，用完不覺得挫折。

「做得到、做得快、做得安心」這三項，就是設計界判斷一個東西好不好用時最常用的三把尺（出自國際標準 ISO 9241-11 對「好用」的定義，原文是有效、有效率、滿意，這裡換成白話）。之後我們做每一張畫面，都會回來用它們檢查。

UI 和 UX 的分工

有了上面四個答案，UI 和 UX 的分工就清楚了：

  • UX 決定「要讓這個人完成什麼、經過哪幾步」：例如成員要先登入，再看清單，點一筆看詳情，最後標記完成；標記前要再確認一次，免得按錯。
  • UI 決定「每一步的畫面上放什麼、怎麼讓人一眼看懂」：例如清單上哪一行字最大、期限用什麼顏色、「標記完成」按鈕要多醒目。

兩者常常一起出問題：流程想得再好，按鈕顏色淡到看不出能按（UI），成員還是會卡住、回群組問人（UX 失敗）；畫面再漂亮，少了「確認完成」這一步，按錯了也救不回來（UX 沒想到）。所以這門課把它們放在一起學。

設計師在工作上做什麼

在工程師寫程式之前，UI/UX 設計師先把 App 的每一個畫面畫出來，讓老闆、同事、甚至真正的使用者看過、試過，確認「看得清楚、用得順」之後，工程師才照著做。放到這個案子，就是：聽懂主管和成員的問題 → 決定成員要經過哪幾個畫面 → 把每個畫面畫出來 → 串成可以點的樣品給成員試 → 修好之後交給工程師。

就像蓋房子前先畫設計圖：設計圖上改一條線幾乎不用成本，房子蓋好才發現廁所門開錯邊，就得敲掉重來。畫面也一樣，在設計階段改，比程式寫完再改便宜很多。
用什麼工具

Figma 是什麼

Figma 是專門用來畫 App 和網站畫面的軟體。打開瀏覽器、登入帳號就能用，不用安裝。

你可以把它想成「專門畫畫面的簡報軟體」：一樣可以拉框、打字、上色，但多了設計師需要的功能。例如：

  • 把顏色存成有名字的色票，改一次、整份檔案一起變（這就是第一章要學的「顏色變數」）。
  • 把同一個按鈕做成可以重複使用的零件。
  • 把畫面串起來，做成可以點來點去的「原型」，在 App 真的寫出來之前就能試用。

檔案存在雲端、會自動儲存，把連結傳給別人，對方就能打開來看。

最後做出什麼

這門課最後會做出的 App

整門課只做一個 App：工作室任務清單，也就是你為這間工作室設計的解法。成員用手機登入，看今天有哪些待處理的任務，點進去看細節，做完後按「標記完成」，系統會再確認一次。對照主管說的「怎樣算解決」，這四個畫面剛好是成員不用問人、自己把一件工作做完的完整路線。

上面是課程最後把設計做成網站後的畫面。你會先在 Figma 裡一張一張畫出這些畫面，再把它們串成可以點的原型，最後做成真正的網站。

怎麼教

我們打算怎麼教

一個案子，從頭做到尾

這門課不會一下教按鈕、一下教海報，而是從頭到尾只做工作室這一個案子。每一章都在同一份 Figma 檔裡往下做，前一章做好的東西，下一章會拿來用。每學一個新技巧，你都能回答「這是為了讓成員怎麼樣」。

為什麼先學畫畫面，而不是先整理需求

真實工作上，設計師通常先訪談、整理需求，才開始畫。這門課刻意倒過來：先學會把一張畫面畫好，到第三階段才正式練「把主管的一長串話整理成需求和流程」。

為什麼這樣安排？因為還不會畫畫面的時候，很難想像一句需求最後會變成什麼樣子，整理需求只會停在紙上談兵。所以故事先講給你聽，讓你每一步都知道是為誰做；等你手上有幾張畫好的畫面，再回頭用需求檢查它們，你會看得出哪裡多做了、哪裡漏了。

整門課的順序

階段在做什麼對工作室成員的意義
畫面基礎先定顏色和文字的規則（第一章）→ 用格線安排版面 → 做出內容變長時會自動撐開的卡片 → 做出改一次、全部一起更新的按鈕在手機上看得清楚，一眼知道哪裡該按；每張畫面長得一致，不會疑惑
畫面零件表單和錯誤提示 → 任務清單 → 提示訊息、彈出視窗和底部導覽登入打錯知道錯在哪；清單找得到自己的工作；按下去知道成功了沒
串成原型把需求整理成流程 → 把畫面串起來能點 → 切換動畫 → 彈出確認視窗 → 長清單捲動在程式寫出來之前，主管和成員就能實際點點看
測試與交付找人試用、修正 → 整理交付給工程師的檔案 → 做成網站並公開確認成員真的不用再回群組問人，再交給工程師做成真的

每一份講義怎麼用

一章會拆成好幾份，一份只做一件事。每一份都是同樣的三段：

段落裡面有什麼
開始前這一份在做什麼、為什麼要做、做完手上會有什麼、需要先準備什麼
跟著做一步一張 Figma 截圖，紅框標出要看或要點的地方，每一步後面寫「做完會看到」，讓你對照自己有沒有做對
做完之後自己檢查的方法、常見問題、這一份學到什麼、下一份要做什麼

每一章都有一份我先做好的範例，不確定的時候打開來對照（下面會說怎麼用）。做完一份，跟我說你看到什麼、卡在哪、哪裡看不懂，下一份我會照你的回報調整。

第一章

第一章為什麼從「顏色和文字」開始

每一張畫面，拆到最小都是「文字」和「顏色」。這門課會畫十幾張畫面，如果每畫一張就重新挑一次顏色、重新決定字要多大，做到後來一定對不起來：

  • 這張的按鈕是深綠，那張變成淺綠，使用者會懷疑「這兩個按鈕功能一樣嗎？」
  • 這張標題 24 號字、那張 22 號字，畫面看起來就是不整齊。
  • 老闆說「主色換成藍色」，你得一張一張找出所有綠色來改，漏一個就穿幫。

再回到故事想一想：成員可能站在客戶現場，拿起手機只想很快看一眼。字太淡看不清、該按的按鈕不夠醒目，他就會放棄，改回群組問人，這個 App 就白做了。顏色和文字，是「做得快、做得安心」最先碰到的一關。

所以第一章我們先把規則定好：什麼用途用什麼顏色、什麼文字用多大的字。再用整門課的第一張畫面，也就是成員每天第一個看到的登入畫面，檢查這套規則好不好用：字看不看得清楚、使用者會不會先看到標題、最後找到登入按鈕。

第一章做完，你手上會有：

  1. 一組有名字的顏色（顏色變數），例如「Primary 主要動作」
  2. 五種有名字的文字樣式，例如「畫面標題」「內文」「提示文字」
  3. 一張全部套用上面規則的登入畫面
  4. 一張規則表，寫清楚每個顏色用在哪裡、為什麼

什麼是顏色變數

顏色變數就是一張有名字的色票。名字寫的是「用途」，不是顏色本身。例如：「Primary（主要動作）」這個名字，背後存的是深綠色；「Text（主要文字）」背後存的是深藍灰色。

裝潢時你跟師傅說：「客廳的牆用 A 號色。」A 號色到底是什麼顏色，寫在色卡上。哪天想換顏色，只要把色卡上的 A 號色換掉，所有塗 A 號色的牆就一起換，不用一面一面去記哪面牆塗了什麼。顏色變數就是 Figma 裡的這張色卡。

用顏色變數的三個好處

好處沒有變數時會怎樣有變數時
一致每次憑感覺挑，深綠、淺綠混著用同一個用途，一定是同一個顏色
好改主色要換，得一張一張找改一次色票，所有用到的地方一起變
好溝通跟工程師說「那個深綠色」，對方不知道是哪個大家都說「Primary」，不會搞錯

你之後會看到像 #245B45 這樣的字，這是色碼，電腦用來表示顏色的編號。不用背，Figma 會把它存在變數裡，你只要記得名字就好。

文字樣式也是同一個概念：把「字型、字多大、多粗、行距多少」存成一個有名字的設定，例如「Type/Page title 畫面標題」。標題要改大一點，改一次樣式，所有標題一起變。

什麼是範例，要怎麼用

範例是第一章做完的樣子，我已經先在 Figma 裡做好了。它就像食譜旁邊的成品照：

  • 開始前：先看一眼，知道這一章的終點長什麼樣子。
  • 做的時候：不確定自己做得對不對，就打開範例，點同一個東西，比對它用了什麼顏色、什麼文字樣式。

檢查自己懂了沒
