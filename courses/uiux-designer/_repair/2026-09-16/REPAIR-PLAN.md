# UI/UX 課程入口修復計畫

日期：2026-09-16
範圍：`uiux-designer/index.html`

## 盤點結論

目前入口頁已經說明課程情境與兩門正式課綱，但「開始前準備」仍把工具列成無關聯的方塊，底部只放一個沒有狀態、前置材料或下一步說明的連結。學員無法從這一區判斷：現在應從哪裡開始、第一個成果是什麼、工具何時出現、完成後要去哪裡。

本機課程規範與成熟入口頁共同採用的路徑原則是：

1. 入口交代情境、成果與學習順序。
2. 每個可進入的單元要有明確名稱、位置與承接關係。
3. 工具要附在任務與產出旁邊，不能以孤立清單代替學習設計。
4. 主要行動要能直接把學員帶到第一個可開始的單元。

## 問題分級

- P1：唯一的開始連結沒有說明起始材料、完成物與下一堂的承接；學員點擊前需要猜測。
- P1：工具方塊沒有任務、時點或產出關係，與本課「介面設計與使用者體驗」的資訊架構要求不符。
- P1：入口沒有顯示「目前位置 → 下一個成果 → 後續階段」的可視路徑，課程兩階段與實際單元入口之間斷開。
- P2：`開始前準備` 把尚未使用的 Photoshop、Git/GitHub、部署平台和第一堂的 Figma 並列，造成前置負擔誤判。

## 修復方式

1. 將「開始前準備」改為「開始位置」：交代目前起點、零基礎所需條件、第一份成果、完成後的承接與主要行動。
2. 將工具方塊改為「工具如何出現在工作路徑」的表格，逐項對應任務、產出與所在階段。
3. 將第一堂連結改成具備明確按鈕語意的主要行動，並提供「先看完整路徑」的次要行動。
4. 在入口底部加入起點與承接說明，讓學員知道完成 A1 後會進入 A2，而不是只收到一個孤立 URL。

## 驗收

- 靜態：`lint-page.py --no-warn`、本課 copy-risk gate、連結檢查、`git diff --check`。
- 瀏覽器：Chrome 重新載入入口，讀取可及性樹；點擊主要行動進入 A1，再點擊 A1 下一堂進入 A2。
- 內容：入口可回答「我現在在哪裡、要處理什麼、第一個產出、用什麼工具、完成後去哪裡」五個問題。
- 邊界：本次只修入口導覽，不宣稱 99 小時所有單元已完成；尚未製作的單元仍需後續按大綱補齊。
