介面元素與設計

讓回饋、決定與導覽各自說清楚

你會沿用 A7 的清單畫面，建立短暫回饋 Toast、需要決定的 Dialog，以及顯示目前位置的 Navigation。這一堂留下三種視覺材料與文字責任表，Prototype 行為交給下一階段。

完成後你會留下
260×48 的 `Toast / Success` 與「已儲存」文字。
260×150 的 `Dialog / Confirm`、標題與取消／確認。
上方的 `Navigation / Header` 與未測試邊界紀錄。
01 · 情境與起始材料

先分清楚訊息的責任與出現位置

清單完成一個動作後，使用者需要知道結果；刪除資料前，需要先看清楚確認內容；頁面變多時，需要知道目前位置。三種訊息各有自己的閱讀時間與位置，混在同一個畫面層會讓後續 Prototype 難以判斷。

本堂承接 A7 的 Row、Title、Empty Message。Probe A 已確認 Toast、Dialog、Navigation 視覺層可在 Figma Starter／Free 建立；自動出現、Overlay、關閉、置頂、滾動與 Prototype 連結尚未測試。

包含三種元素的尺寸、文字與位置規格。

開啟完成檢查表

填入 Layers、W/H、文字責任與未測試邊界。

缺少清單畫面時先回 A7 檢查來源。

本堂環境：使用 Chrome 與 Figma Starter／Free。Probe A A-20～A-22 支援三種視覺層；本頁不把名稱寫成出現或關閉行為。
02 · 先理解三個判斷點

把回饋、決定與導覽放回各自的位置

每個元素都要回答一個工作問題，也要留下可被檢查的證據。

元素要處理的訊息本堂證據
Toast一次動作完成後的短結果。Toast / Success，260×48，含「已儲存」。
Dialog需要使用者確認或取消的內容。Dialog / Confirm，260×150，含標題與兩個選項。
Navigation目前位置與主要去向。Navigation / Header，含首頁／清單／設定。
邊界規則：先驗收名稱、尺寸與內容層級；自動出現、Overlay、關閉、置頂與滾動要在 Prototype 操作後才有證據。
03 · 示範

先建立三個責任清楚的視覺層

示範在 A7 的清單畫面工作區完成。每個結果都在 Layers 或右側尺寸欄確認。

  1. 建立 260×48 Rectangle，命名 Toast / Success，加入「已儲存」。
  2. 建立 260×150 Rectangle，命名 Dialog / Confirm。
  3. 在 Dialog 內加入「刪除這筆資料？」與「取消／確認」。
  4. 建立文字層，輸入「首頁　清單　設定」，命名 Navigation / Header。
  5. 把 Navigation 放在畫面上方，Toast 放在不遮住主要操作的位置。
  6. 保存三個 Layers、尺寸與文字截圖，填入完成檢查表。
Checkpoint 1

你能分別指出 Toast、Dialog、Navigation 的責任、尺寸與文字；三層都能在 Layers 找到。

04 · 跟著做

用名稱與尺寸完成回饋材料

現在重新做一次示範。每一步先讀取可見結果，遇到差異就停在該步修復。

步驟你的操作應看到的結果沒看到時
1開啟 A7 檔與 A8 起始材料，選取清單 Frame。A7 的 Row、Title、Empty Message 仍可找到。回 A7 檢查檔案與 Frame。
2建立 260×48 Rectangle，命名 Toast / Success。Layers 有 Toast，W/H 可讀。重新選取 Rectangle，再設定尺寸與名稱。
3加入「已儲存」文字。Toast 內有短結果，文字不遮邊界。選文字層，從右側 Content 重填。
4建立 260×150 Rectangle，命名 Dialog / Confirm。Layers 有 Dialog，內容區可辨識。回外層 Frame 選取，再建立 Rectangle。
5加入標題與「取消／確認」文字。Dialog 有標題與兩個選項。逐個文字層命名並重新排列。
6建立 Navigation / Header，輸入「首頁／清單／設定」。Layers 有 Navigation，畫面上方有文字。選 Text，再改名稱與位置。
7保存三類截圖與完成檢查表。證據包含 Layers、尺寸、文字三類。逐項補拍，不能只寫「已完成」。
判斷方法：先確認三個 Layer 的責任，再確認尺寸與文字，接著記錄未測行為；三類資料分開保存。
05 · 自己改一個條件

換一個 Dialog 標題，觀察內容是否仍可讀

只改 Dialog 內的標題，換成「要移除這個清單項目嗎？」。保留 260×150、Toast、Navigation 與「取消／確認」文字。

  1. 只選 Dialog 內的標題文字，透過右側 Content 替換。
  2. 觀察長標題是否需要兩行，以及容器是否仍能容納。
  3. 確認 Toast 與 Navigation 名稱、位置沒有被改動。
  4. 記錄行數、容器高度與一個修正點。
Checkpoint 2

Dialog 長標題沒有裁切；Toast 與 Navigation 仍可讀；檢查表保留內容壓力紀錄。

06 · 卡住時怎麼回修

從名稱、尺寸與選取層級分別查找

現象可能原因回修位置重跑起點
三種元素混在一起建立時沒有用責任命名。Layers 名稱。回第 2／4／6 步重新命名。
Dialog 內容被裁切容器固定高度，標題沒有換行空間。Dialog 與文字層的 Resizing。回第 5 步調整文字與容器。
Toast 遮住主要操作只看畫布位置，沒有檢查主要按鈕。Toast 位置與畫面層級。回第 6 步重新放置。
Navigation 文字改到錯的層目前選取了畫面或其他文字。Layers 的選取列。回第 6 步重新選 Header。

把現象、回修位置與重跑結果寫入完成檢查表。互動、Overlay、關閉與置頂仍標成未測，不用圖層名稱代替行為證據。

07 · 驗收與下一步

把視覺材料交給 Prototype 入口

完成本堂代表你能建立三種責任清楚的視覺層，留下尺寸與文字規格。自動出現、Overlay、關閉、置頂、滾動與 Prototype 行為尚未列入本堂驗收。

  • Toast / Success 為 260×48，含「已儲存」。
  • Dialog / Confirm 為 260×150，含標題與「取消／確認」。
  • Navigation / Header 含首頁、清單、設定，位置可辨識。
  • Solo Dialog 長標題的行數、容器高度與修正點已記錄。
  • 三類截圖、Figma 檔連結與未測試邊界已保存。

檢核題 1：Toast、Dialog、Navigation 的責任各是什麼？

答案方向：Toast 傳遞短結果；Dialog 承載確認／取消；Navigation 顯示目前位置與主要去向。

檢核題 2：有了 Dialog 圖層，是否就代表 Overlay 與關閉行為成立？

答案方向：還需要在 Prototype 實際設定、預覽與測試；視覺圖層只能證明內容容器。

請保留三種視覺層、尺寸、文字責任表與檢查表。第 09 堂會把任務拆成畫面清單與 Prototype 入口；完成檢查表後進入第 09 堂：線框、原型與手機介面入口。
