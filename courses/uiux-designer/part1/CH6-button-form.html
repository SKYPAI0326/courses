01 · 情境與起始材料

先處理按鈕與欄位的共同問題

阿凱的登入畫面需要一個主要行動按鈕，也要讓使用者知道欄位名稱、輸入位置和提醒文字各自在哪裡。畫面上有形狀不代表下一位工作者能找到狀態來源；命名和 Property value 要一起留下。

這一堂只處理 Figma Starter／Free 能在目前 Probe A 重跑的範圍：Button component set、兩個視覺 Value、Form 三層圖層。按鈕點擊、欄位輸入、驗證規則與多欄位資料流需要後續 Prototype 或實作測試。

開啟起始材料

包含尺寸、Property Value、圖層名稱和測試邊界。

開啟完成檢查表

填入 Button、Form 截圖與未測試項目。

回看上一堂：Variants

缺少狀態來源時先回 A5，不在 A6 另建來源。

本堂環境：使用 Chrome 與 Figma Starter／Free。Probe A 已確認 Button component／variant 與 Form 視覺圖層；本頁不把靜態圖層寫成輸入互動。
02 · 先理解四個詞

把元件狀態、欄位結構與互動邊界分開

下面的詞會同時出現在 Layers 與右側 Properties。每個詞都對應一個你可以檢查的結果。

詞白話意思本堂證據
Button component set保存同一個按鈕的多個視覺狀態。Layers 有 `Button`，右側可讀 Properties。
Primary／Disabled按鈕的兩個 Value；分別表示主要行動與暫不可用。同一個 component set 有兩個 Value。
Label／Input／Helper表單的視覺層級：說明、輸入容器、提醒文字。Layers 可依名稱與順序找到三層。
互動邊界按鈕點擊與輸入驗證需要 Prototype 或實作證據。檢查表明確列為尚未測試。
03 · 示範

先做 Button，再整理 Form 的三層

示範固定在 `Screen / List Top` Frame。Button 使用 320×48；Form 的 Label、Input、Helper 使用固定命名。每個中間結果都要在 Layers 或 Properties 讀得到。

  1. 建立 320×48 Rectangle，命名 Button / Primary。
  2. 執行 Create component，確認右側出現 Component 與 Properties。
  3. 執行 Add variant，將第二個 Value 改成 Disabled，保留 Primary。
  4. 建立文字層 Form / Email / Label，輸入「電子郵件」。
  5. 建立 320×48 矩形層 Form / Email / Input，放在 Label 下方。
  6. 建立文字層 Form / Email / Helper，輸入「請輸入有效的電子郵件」，放在 Input 下方。
  7. 截圖 Button Value 與 Form 三層，並在檢查表寫下未測試項目。
Checkpoint 1

現在應該能在右側看到 Button 的兩個 Value，也能在 Layers 看到 Label、Input、Helper。若只有畫布上的形狀，回到第 1 或第 4 步補命名。

04 · 跟著做

用可重讀的名稱完成按鈕與表單

現在重新做一次示範。每一步先讀取可見結果，遇到差異就停在該步修復，不要把問題帶到下一層。

步驟你的操作應看到的結果沒看到時
1開啟 A5 檔與 A6 起始材料，選取 Screen / List Top。Frame 與 A5 來源可用。回 A5 檢查 component set 與檔案位置。
2畫出 320×48 Rectangle，命名 Button / Primary。Layers 名稱與尺寸可讀。選取 Rectangle 重新讀 W/H，再用 Layers 改名。
3建立 component、加入 variant、設定 Primary／Disabled。右側 Properties 有兩個 Value。格式警告回到 Property Value，不改 Layers 名稱。
4建立 Form / Email / Label 與 Form / Email / Input。Label 在 Input 上方，兩層名稱可讀。逐層選取，確認沒有把名稱改到外層 Frame。
5建立 Form / Email / Helper，輸入指定提醒文字。Helper 在 Input 下方，文字沒有裁切。回文字層調整寬度與 Auto height。
6保存 Button／Form 截圖與完成檢查表。證據包含名稱、Value、尺寸和邊界說明。先保存 Figma 檔，再補寫未測試項目。
判斷方法：先讀 Button 的 Property／Value，再讀 Form 的圖層順序；互動行為要等另一個測試階段。
05 · 自己改一個條件

換長 Helper，觀察表單結構是否仍可讀

把 Helper 文字換成「電子郵件格式不正確，請重新輸入」。保留 Label、Input、Helper 名稱、Button Properties、320×48 尺寸與相對順序。記錄長句的行數、位置和是否需要調整文字框。

  1. 只選取 Helper 文字層，不修改 Button 或 Input。
  2. 透過 Content 欄位替換長句，觀察文字高度。
  3. 切回 Button 的 Primary／Disabled，確認 Value 名稱沒有被改動。
  4. 把一個需要修正的地方寫進完成檢查表。
Checkpoint 2

Helper 長句沒有裁切、三層名稱仍可讀、Button 兩個 Value 保持不變，並且檢查表列出輸入互動尚未測試。

06 · 卡住時怎麼回修

從名稱、Property 與文字結果分別查找

現象可能原因回修位置重跑起點
Button 沒有 Disabled尚未加入第二個 Variant，或選到外層 Frame。Button component 與 Properties。回第 3 步重新建立 Variant。
Disabled 出現格式警告把 Layers 名稱當成 Property Value。Property 1 的 Value 欄。回第 3 步輸入 `Disabled`。
Form 圖層順序混亂Label、Input、Helper 建立在不同父層。Layers 層級與名稱。回第 4／5 步逐層移回同一個 Frame。
Helper 長句被裁切文字框寬度或高度模式不適合內容。Helper 文字層。回第 5 步調整寬度與 Auto height。

把現象、回修位置與重跑結果寫入完成檢查表；互動未測試也要留下記錄。

07 · 驗收與下一步

把命名與狀態交給 List 單元

完成本堂代表你能建立一個有兩個視覺 Value 的 Button component set，並用固定圖層名稱組成 Form 視覺區塊。按鈕點擊、輸入互動、驗證規則、多欄位增刪與錯誤流程尚未列入本堂驗收。

  • Button / Primary component set 為 320×48，Property 有 Primary、Disabled。
  • Form / Email / Label、Input、Helper 可從 Layers 找到。
  • Helper 長句沒有裁切，三層相對位置可重讀。
  • 檢查表包含截圖、修正點與未測試邊界。

檢核題 1：Button 的 Disabled 是 Property 還是 Value？

答案方向：Property 是狀態欄位；Disabled 是其中一個 Value。

檢核題 2：Label、Input、Helper 三層存在，仍缺少哪些證據才能宣稱輸入互動完成？

答案方向：需要實際輸入、錯誤回饋與多欄位行為的測試結果；靜態 Layers 不足。

請保留 Button component set、Form 三層與檢查表。第 07 堂現在可以開始，請沿用命名與內容壓力處理 List。
