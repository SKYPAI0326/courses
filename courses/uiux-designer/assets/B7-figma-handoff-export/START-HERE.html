第 15 堂 · 起始材料頁

Figma Handoff：把成果交給下一位工作者

你會接手第 14 堂回歸通過的 Prototype，整理來源、輸出檔、Inspect 資訊與限制。這一頁先列出交付欄位；輸出動作在 Figma 完成。

你在這一堂的工作位置

你是阿凱，弄一下行銷工作室的行銷專員。接手者需要來源、可查看輸出、尺寸色彩線索與未驗證限制，單一連結不足以交付。本堂先處理這個問題，讓雯姊在下一個交接點能使用可檢查的成果。

起始材料第 14 堂回歸通過版本、Figma URL、Host／Overlay Frame 與 Handoff 清單。
第一個動作先凍結來源並記錄 URL、日期、方案與 case_id；交付版本應可追溯。
第一個可觀察結果雯姊能依清單找到來源、輸出檔與尚未驗證限制。
本堂完成物Host PNG／PDF、Overlay PNG、Inspect 筆記與 Handoff 清單；Photoshop／Share 狀態如實標記。
下一位使用者／用途第 16 堂會把交付包放入最小網站與 Git 版本流程。
失敗時怎麼回復回來源版本與缺件清單；缺 PNG／PDF／Inspect 就停止，不以截圖冒充。

交付項目

項目規格
來源第 14 堂回歸通過的 Figma 檔、Frame 名稱、URL、日期、方案、case_id
HostPNG／PDF，能在沒有 Figma 編輯權時查看
Overlay320×200 PNG，含預期文字
Inspect只記錄實際看見的 Layout、Colors、Assets 或 CSS 欄位
限制Photoshop 開檔／輸出、Share、GitHub push、公開部署照實標記

操作順序

  1. 凍結來源版本，不在交付前偷偷修改文字、尺寸或 Prototype。
  2. 選取 Host，加入 PNG／PDF Export，確認下載檔案存在。
  3. 選取 Overlay，加入 PNG Export，確認尺寸與文字。
  4. 切到 Dev Mode，記錄實際可見的 Inspect 欄位。
  5. 開啟Handoff 清單，填來源、輸出、限制與證據路徑。
尚未測試項目如何處理

沒有實際開啟 Photoshop、Share 或公開部署時，填寫未驗證狀態與下一個測試責任；不要把 Figma Export 當成 Photoshop 或網站已完成。
