第 16 堂 · 起始材料頁

網頁、Git／GitHub 與雲端部署

你會把第 15 堂的 Handoff 概念放進一個可在 Chrome 開啟的最小網站，完成本機互動、Git 版本紀錄，再依發布 Gate 進入 GitHub 與部署。

你在這一堂的工作位置

你是阿凱，弄一下行銷工作室的行銷專員。設計成果停在 Figma，客戶與接手者沒有可在瀏覽器開啟、可回復的最小版本。本堂先處理這個問題，讓雯姊在下一個交接點能使用可檢查的成果。

起始材料第 15 堂 Handoff、web-starter/README.html、index.html、styles.css 與 app.js。
第一個動作先讀 README、在 Chrome 開起始頁；應看見標題、任務卡片與按鈕。
第一個可觀察結果修改一個任務標題後，桌面與手機畫面仍能操作並可回到上一個 commit。
本堂完成物Chrome 可開啟的本機網站、桌面／手機證據、Git diff 與 commit；公開網址另列 release gate。
下一位使用者／用途雯姊與後續接手者用網站與 commit 判斷成果；GitHub／部署需另行驗收。
失敗時怎麼回復回 README、相對路徑與 Git status；無關檔案先停止，回到上一個可回復 commit。

三個起始檔案

檔案責任本堂先做的事
index.html內容與結構先閱讀現有標題、任務卡片與按鈕
styles.css視覺與手機寬度找到 breakpoint，縮窄視窗檢查可讀性
app.js按鈕事件與狀態點擊「標記完成」，觀察狀態與回饋更新

交付順序

  1. 讀 README，再用 Chrome 開啟起始頁。
  2. 在 VS Code 只改一個任務標題，重開 Chrome 確認互動仍可用。
  3. 在手機寬度檢查標題、任務、狀態與按鈕。
  4. 用 git status、git diff 與 commit 留下可回復版本。
  5. 本機通過後，依講義的 release gate 建立 GitHub repository、push 與公開部署。
你要保存的證據

桌面與手機畫面截圖、按鈕完成狀態、Git diff、commit 訊息，以及公開網址（只有在部署實測完成後才填）。
