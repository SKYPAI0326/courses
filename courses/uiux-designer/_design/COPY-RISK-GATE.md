# UI/UX 課程文案風險閘門

這份閘門把跨專案整理出的文案觀察，轉成製作與驗收規則。它用來檢查句子是否讓學員看見情境、動作、結果與修復位置；它不能判定作者是不是 AI，也不能用單一句型替代人工閱讀。

## 1. 風險分級

### BLOCK：交付前必須改寫

- 公式化對比：`不是 X，而是 Y`、`不在於 X，而在於 Y`、`不只是 X，而是／也／還 Y`。
- 句子把讀者先推進一個假設，再用口號宣布正解，卻沒有提供操作、判斷條件或可見結果。

改寫時直接寫角色、情境、操作與結果。例如：

```text
收到手機任務清單需求後，先固定 Frame 尺寸，再用一條長文字檢查容器是否跟著增高。
```

### REVIEW：需要人工判讀

掃描器會列出下列訊號，但不會因為出現一次就自動判定錯誤：

- 空泛過場：`值得注意的是`、`需要強調的是`、`接下來我們將`、`總而言之`。
- 機械排序與反問：連續使用`首先／其次／最後`，或寫成`你是否曾經想過`、`那麼問題來了`。
- 模糊立場：`可能可以`、`研究顯示`、`專家認為`、`全面改善`。若要保留，必須補來源、範圍、日期或驗證方式。
- 假個人化：`依照自身需求彈性調整`。改成這一課實際的判斷條件，例如方案、權限、輸出格式或完成物。
- 空泛承諾與企業黑話：`賦能`、`創造價值`、`建立閉環`、`推動落地`。改成檔案、欄位、測試結果或交接動作。
- 宣傳形容詞與抽象三連句：`全面`、`深度`、`完整`、`無縫`、`高效`，以及沒有各自判準的三項並列。
- 結構指紋：破折號／括號塞入太多補充、每段都採同一節奏、同一對象反覆換同義詞、結尾重新講一次全文、客服式稱讚。

## 2. 可以保留的情況

否定句本身不是禁語。以下情況可保留，前提是讀者能立即看到限制或修復動作：

- 課程限制：`本課程不要求真實廣告支出`。
- 錯誤排查：`若高度仍是 Fixed height，回到文字容器設定`。
- 產品原文：Figma 面板、Git 指令、錯誤訊息或檔案名稱。
- 可驗收的完整性：`完整顯示兩段壓力句`，且同一段列出寬度、截圖或通過條件。

「完整」「有效」「深度」等詞若保留，附近必須有可觀察證據；沒有證據時改寫成數量、欄位、操作或完成條件。

## 3. 執行流程

每次新增或重寫講義時，依序完成：

1. **掃描**：執行 `python3 docs/audit-copy-patterns.py --strict uiux-designer ../_lessons/uiux-designer`。
2. **人工分類**：BLOCK 直接改寫；REVIEW 逐行判斷是否為必要限制、產品原文或有證據的說法。
3. **改寫**：優先補上角色、起始材料、操作、預期結果與修復位置；刪除只提供語氣的過場。
4. **冷讀**：從入口頁開始，不看製作紀錄，確認學員能回答「我現在在哪裡、要用什麼、做完留下什麼、卡住回哪裡」。
5. **留證**：在審查報告記錄掃描結果、保留的 REVIEW 例外、瀏覽器檢查頁面與尚未通過的人工作業。

## 4. 本次基線

目前試點頁與教案的 BLOCK 掃描應為 0。REVIEW 結果只代表待人工閱讀，不能當成作者判定或自動退件理由。33 小時試點仍與 99 小時正式課程分開記錄；缺少單元、素材、Photoshop 實測或真人冷讀時，維持待驗證狀態。
