## 1. 每頁統一骨架

| 區塊 | 寫法 |
|---|---|
| 頁首 | 標題、副標（一句工作情境）、本堂完成物（2～3 項，用看得見的結果描述，不寫數值） |
| 接上次 | 一段話：上次做出了什麼、這次為什麼需要它；需要的舊成果用內容稱呼（「上次做好的登入卡片」），不寫堂號 |
| 觀念 | 先講這個功能解決什麼問題，再給一張示意或比較表 |
| 示範 | 步驟清單；每步一個動作＋看得見的結果。尺寸、間距、圖層名集中在「本堂規格表」，步驟裡只引用 |
| 跟著做 | 提示減少，學員自己判斷設定位置 |
| 卡住時 | 症狀 → 原因 → 修法，三欄表 |
| 自己完成 | 只給條件與合格標準，不先給答案；答案收在可展開區塊 |
| 收尾 | 收回本堂成果，說下一堂會拿它做什麼 |

## 3. 內容量能否撐起 99 小時

時間帳本（`_design/99h-time-ledger.md`）給每單元 4～7 小時、B8 13 小時，其中「獨立遷移」每單元 50～90 分鐘、「引導練習」55～90 分鐘。現有講義每頁約 2,200～4,400 字：一段觀念、5～7 步示範、4～6 步跟著做、**一段**「自己完成」。以零基礎學員估算，示範＋跟著做約 1.5～2.5 小時，「自己完成」一段約 30～45 分鐘，**單元實際內容約 2～3 小時，只有帳本的四到五成**。帳本裡的引導練習與獨立遷移在頁面上沒有對應活動，課堂會變成講師臨場補題。

另外對照正式課綱（`_design/99h-coverage-matrix.md`），有幾項在頁面上只做了一半：

| 課綱項 | 帳本要求 | 現有頁面 |
|---|---|---|
| 42-09 回饋與通知 | 成功、警告、錯誤與出現時機 | 只有成功提示 |
| 42-12 變體 | Button／Input／Navigation 至少一組 | 只有 Button |
| 57-04 覆蓋層 | Dialog、Menu、Bottom sheet 至少兩種 | 有 Dialog、Menu，沒有 Bottom sheet |
| 57-01 工具介紹 | 線框、原型、工具分工 | 工具分工一句帶過 |
| 57-09 網頁入門 | HTML／CSS、手機寬度 | 以貼完整程式碼代替教學 |

**擴充方案：加一條「練習線」貫穿全課**。素材已有 `assets/shared/SIGNUP-DATA.csv`（12 筆虛構活動報名），目前只在 B6 突然出現。改成：

- **主線**（工作室待處理清單）：示範＋跟著做，維持現狀。
- **練習線**（活動報名確認）：每單元一節「換你做」，學員把剛學的方法用在報名 App 的對應畫面，只給條件與合格標準；B6 的整合作品就是把一路做好的報名 App 測試與修正，不再臨時開新案例。
- **補齊課綱缺口**：A6 加輸入框元件的狀態變體；A8 加警告與錯誤提示；B4 加底部面板（Bottom sheet）；B1 加一節工具分工；B8 程式碼移出正文，改教三個檔各管什麼、手機寬度怎麼處理。
- 每單元另加一個「看圖找問題」判讀練習（給兩版畫面，判斷哪版較好與理由），訓練設計判斷，不只操作。

預估每頁增為 5,000～7,000 字，單元實際內容約 4～6 小時，接近帳本配置。練習線需要新素材：報名 App 的畫面參考圖（SVG），每單元一張，PM 依 CSV 製作。

## 4. 待決：測試一節要不要找真人

可用性測試的本意就是看「第一次用的人」卡在哪；目前講義是「有同學就請同學，沒有就標待補」，兩條路在每頁分岔。三個方向擇一：

| 方案 | 做法 | 代價 |
|---|---|---|
| A 單人完成（建議） | 學員自己扮演第一次使用者：先寫任務卡、隔一段時間後只看任務卡操作，邊做邊記卡住處；不提同學 | 測不到「別人」的誤解，但講義乾淨、獨讀可完成 |
| B 課堂兩人互測 | B6 一節保留兩人輪流當測試者與記錄者；其他頁全部單人 | 獨讀學員做不了這一節 |
| C 單人＋AI 讀截圖 | 把每一步截圖依序貼給 AI，請它扮演第一次使用的人指出看不懂處 | 在非 AI 課中加入 AI 工具，課前要多準備帳號 |
