## 2. 需求與資訊架構（第 4 項）

### A1：需求初稿用表格模板
「換你做」裡的需求初稿改成一張要學員自己填的表（給欄位，不給內容），約 30 分鐘：

| 欄位 | 寫什麼 |
|---|---|
| 目標 | 一句話：誰、在什麼情況、完成什麼 |
| 使用者與情境 | 一到兩句 |
| 必做 | 5～8 項，每項是使用者要完成的事 |
| 之後再做 | 訪談提到但這次不做的，各附一句理由 |
| 畫面清單 | 畫面名稱｜在這張畫面完成什麼 |
| 還沒想清楚的 | 訪談裡模糊或矛盾、之後要決定的地方 |

說明：這張表做需求與流程那一堂會再修正，現在寫錯沒關係。

### A8：底部導覽不再直接給分頁
主線照原示範。練習的三欄表把「底部為首頁／我的預約／會員」這類指定分頁拿掉，改成提示問題：「你的畫面清單裡，哪幾個是使用者常常來回切換、彼此平行的區域？先暫定 3～4 個分頁，做需求與流程那一堂會再檢查。」條件與自我檢查同步改成「分頁來自自己的畫面清單」。

### B1：新增「從畫面清單推出導覽」一節（放在畫面清單之後、流程圖之前）
1. **觀念**：資訊架構是決定「東西放哪、怎麼找得到」。一個人也能做分組：把每個功能與內容寫在小矩形上，依「使用者會一起做的事」分組，用使用者的話替每組命名。
2. **導覽怎麼選**（比較表）：底部導覽適合 3～5 個常用且平行的區域；頂部返回適合一層層往下看詳情；從首頁進入適合不常用的功能。
3. **主線示範**：在流程圖旁開一個 Section `IA / 工作室`，把登入、待處理、詳情、標記完成、已完成、個人設定等寫成小矩形，分組成「待處理」「已完成」「我的」，畫成一張簡單的樹狀網站地圖（用 Arrow 連），再對照 A8 的 `Nav / Bottom`，說明哪些一致、哪些要調整。
4. **練習**：學員用自己的必做與之後再做清單做同樣的分組與網站地圖，檢查 A8 暫定的分頁，必要時修正並寫一句理由。

### B1、B2：建議對應改成提示問題
- B1 練習的三欄表不再直接寫「這次把選擇時段和我的預約列為缺頁」。改成每題兩三個提示問題，例如預約：「飼主送出後要去哪裡確認自己約了什麼？」「服務時間長短不同，選時間時要先知道什麼？」點餐、會員依同樣方式寫。條件與自我檢查裡指定缺頁名稱的句子改成「依你的畫面清單判斷缺頁」。
- B1 練習新增一條條件：**在需求頁裡另外找兩個還沒處理的問題，寫下你的決定（這次就設計，或列入之後再做）與理由。** 提示 details 可舉一例方向（例如預約題「改時間」或「沒到店」），不給答案。這條對應評分表 N4。
- B2 練習的三欄表：關鍵畫面的規格示範保留（那是教學內容），但「換你做」表格把「完整流程要含…」的清單改成提示問題，讓學員依自己的畫面清單決定。
