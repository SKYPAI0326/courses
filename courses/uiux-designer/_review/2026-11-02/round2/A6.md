# 完成表單與錯誤修正
副標：工作室人員登入與新增任務時，要看得懂每個欄位，也要能用正確控制項完成選擇並修正錯誤。
本堂完成物：正常、焦點、錯誤與停用的文字欄元件；一張新增任務表單；四種可重複使用的選擇控制項

## 把上次整理好的按鈕放進表單

工作室人員準備登入待處理清單，登入後還要新增任務。若畫面只有白色矩形、幾個圓點和一顆按鈕，使用者看不出欄位名稱，也不知道每一種選擇能選幾個。這堂會先完成登入欄位的狀態，再把文字欄、下拉、單選、開關與勾選組成新增任務表單。

這項工作會使用上次完成的 Button 元件集。先從 Assets（元件資產面板）插入按鈕，確認 Type 可選 Primary、State 可選 Default，而且 Label 能直接改成「登入」。接著開[本堂起始材料](../assets/A6-button-form/START-HERE.html)，理解登入情境與既有圖層；完成後用[完成檢查表](../assets/A6-button-form/reference/EXPECTED-CHECK.html)逐張核對。沒有上次成果時，先回到[把主次按鈕與狀態做成可選的元件](CH5-variants-properties.html)，依該頁規格表補做 Button 元件集與文字屬性，約需 20～30 分鐘。

先保留 `Screen / Login`（登入畫面）的手機外框與標題，再把舊的卡片測試移到畫面外的參考區。接下來建立的欄位會用 Auto layout（自動排版）管理高度；提示或錯誤說明變長時，下面的內容會跟著移動。

## 一個完整欄位要回答三個問題

完整欄位至少要讓人知道「這格是什麼」「現在填了什麼」「有問題時怎麼修」。固定的 Label 負責欄位名稱，Input 負責承載輸入內容，Helper 負責平常提示或錯誤說明；三者放在同一個容器，閱讀順序才穩定。

例如，帳號欄的 Label 是「工作室帳號」，Input 內可顯示 `studio@example.test`，Helper 平常寫「請使用工作室電子郵件」。當內容只有 `studio` 時，錯誤版保留欄位名稱，並把 Helper 改成「帳號格式不正確，請輸入完整電子郵件」。文字已經交代原因與下一步，紅色只負責加強辨識。

| 部分 | 平常負責什麼 | 錯誤時負責什麼 | 判斷是否用對 |
|---|---|---|---|
| Label | 固定說明欄位名稱 | 保持原名稱 | 輸入後仍看得見這格用途 |
| Input | 顯示輸入值或示意內容 | 保留使用者需要修正的內容 | 內容和欄位名稱相符 |
| Helper | 補充格式或條件 | 說明原因與修正方向 | 句子能回答「哪裡錯、怎麼改」 |
| Button | 提交目前表單 | 依表單是否齊全選狀態 | 文字說明按下後的動作 |

Placeholder 是尚未輸入時放在 Input 內的示意，它會在輸入內容後消失，所以固定 Label 仍要保留。必填欄位可以在 Label 後加上星號，並在表單開頭說明星號代表必填；選填欄位則直接標「選填」。使用者在輸入前就能知道完成條件。

文字欄這次會有四種 State。Default 是平常外觀；Focus 表示游標目前在欄位裡，使用 `Primary` 的 2 px 外框；Error 同時改變外框與 Helper 內容；Disabled 表示這格目前無法編輯，仍保留可讀的 Label 與現有值。四個 Variant 的層級相同，切換時畫面才不會跳動。

## 示範：做出四種狀態的帳號欄

這一節先做一個完整帳號欄，再把它整理成四種 Variant。規格表集中列出所有名稱與數值，步驟只處理一項設定並觀察結果。

| 圖層或畫面 | 規格 | 內容或用途 |
|---|---|---|
| `Screen / Login` | 402 × 874；底色沿用登入畫面 | 正常登入畫面 |
| `Login / Content` | x 24、y 120、寬 354；Vertical；Gap 20；Hug 高 | 表單內容容器 |
| `Field / Account` | Vertical；Gap 8；寬 354；Hug 高 | 帳號欄使用處 |
| `Field / Label` | 字級 16、行高 24；Auto height | 「工作室帳號」 |
| `Field / Input` | 寬 354、高 48；水平內距 16、垂直內距 12；圓角 8 | 輸入內容容器 |
| `Field / Value` | 字級 16、行高 24；Fill；單行 | `studio@example.test` |
| `Field / Helper` | 字級 14、行高 22；Fill；Auto height | 平常提示或錯誤說明 |
| State=Default | `Card` 底；`Border` 1 px 外框 | 一般狀態 |
| State=Focus | `Card` 底；`Primary` 2 px 外框 | 游標正在欄位內 |
| State=Error | `Card` 底；`Error` 1 px 外框與 Helper | 錯誤狀態 |
| State=Disabled | `Disabled` 底；`Muted` 字 | 暫時無法編輯 |

1. 在 `Screen / Login` 內建立垂直 Auto layout，命名為 `Login / Content`（登入內容）；完成後會看到從標題往下排列的表單區。
2. 建立 `Field / Label`（欄位標籤），輸入「工作室帳號」；完成後欄位用途會固定顯示在輸入區上方。
3. 建立 `Field / Value`（欄位內容），輸入 `studio@example.test`；完成後會看到一行符合帳號情境的示範值。
4. 選取內容文字按 **Shift+A**，把新外框命名為 `Field / Input`（輸入區），再依規格表設定尺寸與外觀；完成後文字會位於有邊界的輸入容器中。
5. 建立 `Field / Helper`（欄位提示），輸入「請使用工作室電子郵件」；完成後輸入區下方會出現格式方向。
6. 同時選取 Label、Input 與 Helper，按 **Shift+A**，把新外框命名為 `Field / Account`（帳號欄）；完成後三個部分會進入同一個垂直容器。
7. 選取帳號欄，按右鍵選 **Create component**；再按右鍵選 **Main component → Add variant**；完成後帳號欄會變成紫色虛線框住的元件集。
8. 點元件集下方的加號再建立兩個 Variant；完成後元件集會有四個結構相同的版本。
9. 選取元件集，命名為 `Field / Text`（文字欄位），再將預設的 Property 1 改名為 State；完成後 Layers 與 Assets 都會顯示清楚名稱。
10. 將四個值命名為 Default、Focus、Error、Disabled；完成後使用處能從右側切換完整欄位狀態。
11. 依規格表設定四個版本；Error 的 Value 改成 `studio`，Helper 改成「帳號格式不正確，請輸入完整電子郵件」；完成後會看到結構相同、回饋不同的版本。
12. 從 Assets 插入元件使用處，命名為 `Field / Account`，放入登入內容；完成後帳號欄會跟著內容容器排列。
13. 依序切換四種 State；完成後 Label 與整體寬度保持穩定，Focus 外框加強，Error 顯示修正方向，Disabled 仍可閱讀。

一般版短提示時，欄位高度由上方文字、間距、輸入區與下方提示共同組成。實際排版交給 Hug contents 與 Auto height；當 Helper 變成兩行時，它會增高並把後面的欄位推開。

Focus 代表目前輸入位置，Error 代表內容需要修正，兩者可能先後發生。這份靜態元件先各自呈現一個主要狀態；之後做原型時，再依操作流程決定何時切換。

## 跟著做：完成密碼欄與登入畫面

這一節要自行完成第二個欄位，並把表單整理成正常、焦點、錯誤與修正後幾種結果。每一步先想要達成的畫面，再到對應元件或使用處找設定。

1. 依帳號欄的做法建立密碼欄，使用 Add variant 建出四種 State；完成後每個版本都保有 Label、Input、Value、Helper 四個層級。
2. 將一般版 Label 改成「密碼」，Value 改成八個圓點，Helper 改成「至少 8 個字元」；完成後三段內容各自符合用途。
3. 將錯誤版 Value 改成三個圓點，Helper 改成「密碼不足 8 個字元」；完成後錯誤句會直接指出缺少的條件。
4. 從 Assets 插入密碼欄使用處，放到帳號欄下方；完成後兩欄會依登入內容的 Gap 自動排列。
5. 插入 Button 使用處，選 Primary／Default，Label 改成「登入」，命名為 `Button / Login`（登入按鈕），寬度設為 Fill；完成後表單會有清楚的主要動作。
6. 複製登入畫面，讓帳號欄保持 Focus、密碼欄保持 Default；完成後會看到目前輸入位置只有一處。
7. 再複製一張畫面，把帳號切成 Error；完成後只有出錯欄位呈現錯誤外框與修正文字。
8. 從錯誤畫面複製修正版，改正值並把兩欄切回 Default；完成後能直接比較修正前後。
9. 另做一張空白登入畫面，兩欄顯示示意內容，把登入按鈕切到 Disabled，並在附近放「請先填寫帳號與密碼」；完成後停用外觀會配合具體原因。
10. 把帳號錯誤句加長成兩行，觀察密碼欄與按鈕；完成後兩者會被推開，內容不會重疊。

最後從標題開始順著讀一次：登入工作室、工作室帳號、輸入值、提示、密碼、輸入值、提示、記住我、登入。不同 State 都要保有相同閱讀順序；Helper 留在所屬欄位附近，使用者能直接對照要修改的內容。

## 先選對控制項：單選、勾選、下拉與開關

文字欄處理自由輸入，選擇題則要依「能選幾個、選項有多少、是否立刻生效」挑控制項。選對控制項能讓使用者在看到畫面時就理解規則，也能降低選錯後再修正的成本。

| 控制項 | 適合的選項數 | 可複選嗎 | 選擇後是否立刻生效 | 工作室例子 |
|---|---|---|---|---|
| Radio（單選） | 少量且需要同時看見 | 否 | 通常提交後生效 | 優先順序：高／中／低 |
| Checkbox（勾選） | 少量獨立選項 | 是 | 可先選好再提交 | 記住我、同意條款、加購項目 |
| Select（下拉） | 選項較多，畫面空間有限 | 否 | 選完仍可再確認 | 任務類別、日期時段、取餐時間 |
| Toggle（開關） | 一個可以開或關的設定 | 不適用 | 適合立即生效 | 提醒我、訂閱電子報、需要統編 |

單選要讓所有選項同時看得見，使用者能直接比較。勾選框適合彼此獨立的多個選擇，例如同時加購驅蟲與香氛。下拉把較長清單暫時收起，選定後仍顯示目前值。開關描述一個設定現在是開或關，例如打開「需要統編」後立刻顯示統編欄。

每個控制項都需要可讀的文字標籤。勾選框與單選按鈕本體雖然很小，整列文字和控制項要放在至少 44×44 的可點 Frame 裡；點文字也應視為選取同一項。表單欄位標籤放在控制項上方，必填與說明文字放在使用者開始操作前就看得到的位置。

## 建立四種控制項，再組成新增任務表單

這一節會先建立四個小型元件集，再把它們放進 `Screen / New Task`（新增任務畫面）。每個元件集只有一個真假屬性，兩個 Variant 的名稱、尺寸與文字位置保持一致。

| 元件集 | Variant 屬性 | 兩個值 | 主線用途 |
|---|---|---|---|
| `Checkbox` | Checked | false／true | 登入畫面的「記住我」 |
| `Radio` | Selected | false／true | 優先順序：高／中／低 |
| `Toggle` | On | false／true | 「提醒我」設定 |
| `Select` | Open | false／true | 任務類別的收合與展開 |

1. 在 `Components` 裡建立一個 44×44 的 Auto Layout Frame，放入方形勾選框與「記住我」文字；完成後，整列都具備足夠觸控範圍。
2. 將這列建立為 `Checkbox` 主元件，再用 **Main component → Add variant** 增加第二個版本；完成後會得到結構相同的未勾選與已勾選外觀。
3. 把預設屬性改名為 Checked，兩個值填 false 與 true；完成後，使用處可以從右側切換勾選狀態。
4. 沿用同樣方法建立 `Radio`，把方形改成圓形，屬性命名為 Selected；完成後會有未選與已選兩種狀態。
5. 建立 `Toggle`，讓圓形滑塊在 On=false 與 On=true 兩個版本中位於不同側；完成後，底色與滑塊位置會一起說明開關狀態。
6. 建立 `Select`，收合版顯示目前類別與向下圖示，展開版在下方顯示選項清單；完成後，Open 屬性能切換兩種畫面。
7. 在登入畫面的密碼欄下方插入 Checkbox 使用處，把 Label 保持為「記住我」；完成後，登入表單會多一個可辨識的勾選項。
8. 建立 `Screen / New Task`，加入頁面標題、任務名稱文字欄與類別 Select；完成後，上半部會形成固定 Label 在上的閱讀順序。
9. 在「優先順序」Label 下插入三個 Radio 使用處，文字分別為「高」「中」「低」，只讓其中一個 Selected=true；完成後，畫面會清楚表達三選一。
10. 在表單下方插入 Toggle 使用處，文字改成「提醒我」；完成後，開關會表示提醒設定目前是否開啟。
11. 插入 Primary／Default 的 Button，Label 改成「新增任務」；完成後，表單會有一個清楚的提交動作。
12. 複製新增任務畫面，把類別 Select 切到 Open=true；完成後，可比較收合與展開時後續欄位是否由 Auto Layout 推開。

做完後檢查每個控制項的文字是否描述資料本身。Radio 文字寫優先順序，Toggle 文字寫設定名稱，Select 收合版顯示目前選項。元件的真假屬性只留在設計設定裡，使用者看到的是自然語言。

## 看兩張新增任務表單，判斷哪張較容易完成

這一節要從控制項與錯誤回饋判斷可用性。版本一把「任務名稱」固定 Label 放在文字欄上方，優先順序用三個 Radio 顯示，類別用 Select，提醒用 Toggle；每個單選列都有至少 44×44 的觸控範圍，錯誤 Helper 緊接在任務名稱下方。版本二把欄位名稱只放在 Placeholder，優先順序改成三個互相獨立的 Checkbox，類別與提醒都使用外觀相似的小開關，觸控範圍只包住圖形本體。

請判斷哪一版較適合新增任務，並說明：使用者如何知道優先順序只能選一個？輸入後還能否看見欄位名稱？手指能否容易點到控制項？錯誤訊息是否靠近需要修正的欄位？

## 卡住時，沿著文字、狀態與父容器往外查

這一節把常見問題整理成修復順序。先查文字尺寸模式，再查 Variant 屬性，最後查整張表單的 Auto Layout，通常能找到是哪一層阻止內容變化。

| 看到的現象 | 通常的原因 | 怎麼修 |
|---|---|---|
| 長錯誤句被裁切 | Helper 仍是固定高度 | 到 Layout 將文字尺寸模式設為 Auto height |
| Helper 變高但後續欄位沒下移 | Field 或表單不是 Hug／Vertical | 讓欄位 Hug 高，並確認它在垂直 Auto layout 內 |
| 切換 State 後 Label 跳位 | 四個 Variant 的名稱或階層不同 | 對齊 Label、Input、Value、Helper 的層級 |
| 使用處找不到 Focus 或 Disabled | 元件集的 State 值未整理 | 回主元件確認四種值各出現一次 |
| 單選可以同時出現多個已選 | 各使用處狀態沒有按群組檢查 | 在畫面中只保留一個 Selected=true，並逐列核對 |
| Select 展開後蓋住下一欄 | 展開清單離開表單排列 | 把 Select 使用處放在表單 Auto Layout 內並讓高度 Hug |
| 文字可見但很難點中 | 觸控 Frame 只包住小圖形 | 讓圖形與文字共用至少 44×44 的互動範圍 |

修完後用最長錯誤句與 Select 展開版各測一次。長句能推開後續欄位，展開清單也能保留閱讀順序，表示表單層級能承受兩種內容變化。

## 換你做：你的題目

現在把表單方法移到你選的題目。先照需求頁完成欄位，再做一張具體錯誤畫面與一張修正後畫面；Checkbox 與 Radio 都要建立成可重複使用的元件。

| 預約 | 點餐 | 會員 |
|---|---|---|
| 預約資料：飼主姓名、手機、寵物名字、寵物體型單選、日期時段下拉、驅蟲與香氛加購勾選、備註、同意注意事項勾選且必填。 | 取餐資料：取餐人姓名、手機、取餐時間下拉、付款方式單選、需要統編開關、備註；開關打開時顯示統編欄。 | 註冊資料：姓名、手機、Email、生日月份下拉、喜歡的書類勾選且可複選、訂閱電子報開關、同意會員條款勾選且必填。 |

要達成的條件：

- 所有固定 Label 放在欄位上方，必填與選填在操作前可辨認。
- 依題目需求選用文字欄、Radio、Checkbox、Select 或 Toggle，選項文字完全照需求頁。
- 建立 Checkbox 與 Radio 元件集，兩種狀態都保有相同文字位置與觸控範圍。
- 做出一張具體錯誤畫面，Helper 說明原因與修正方向。
- 做出修正後畫面，欄位順序與主要確認動作保持一致。
- 勾選與單選的整列觸控範圍至少 44×44，點文字也能代表同一選項。

合格的結果要能通過的自我檢查：

- 每個控制項都符合「可選幾個、選項數量、是否立即生效」的選用規則。
- 單選群組同一時間只有一個已選，勾選群組允許依需求複選。
- 下拉的收合與展開版都看得見欄位 Label 和目前選項。
