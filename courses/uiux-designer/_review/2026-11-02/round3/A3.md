# 讓文字變長時，容器與按鈕一起排好
副標：工作室的登入提示可能從一行變成多行，這堂讓卡片跟著內容長高，按鈕也能維持正確間距。
本堂完成物：一張使用間距變數的登入卡片；一組有寬度上下限的元件；一排會自動換行的任務標籤

## 從對齊好的登入內容繼續

工作室的登入畫面已經有共同邊界，但真正使用時，提示文字不會永遠只有一行。密碼規則可能變長，錯誤訊息可能需要補上修正方法，之後也可能加入帳號範例。若標題、訊息與按鈕只是分別放在畫布上，文字增加時就會蓋住下一個物件。這堂要把它們組成能回應內容變化的容器。

先找出上次做好的手機登入內容區，確認卡片可用寬度已對齊格線。開啟[本堂起始材料](../assets/A3-auto-layout-pressure/START-HERE.html)，先認識這次要建立的訊息、按鈕與卡片層級；完成操作後，用[完成檢查表](../assets/A3-auto-layout-pressure/reference/EXPECTED-CHECK.html)核對長句、增刪子層與窄版測試。若手上沒有格線與響應式比較，先回到[安排格線與 Constraints](CH2-grid-layout.html)，依本堂規格表補做約 20～30 分鐘。這些物件都留在同一份設計檔中，下一次會直接把其中的按鈕轉成共用元件。

這次會同時處理兩種變化：內容高度改變，以及容器寬度改變。前者檢查文字換行後能否推開按鈕，後者檢查畫面變窄時，子層是否能使用父容器剩餘空間。

## 先分清楚：文字長高和卡片長高是兩件事

這一節要理解不同設定作用在哪一層，因為 Auto Layout 失效時，問題通常在於設定放錯物件，而非某個數值。文字層的 Auto height 讓文字框隨著行數增加高度；父容器的 Hug contents 則讓外框包住所有子層、間距與內距。兩者一起使用，長句才會推動下面的按鈕。

Auto Layout 可以把父容器想成一個會排隊的盒子。方向設為 Vertical 時，子層由上到下排列；Gap 控制相鄰子層之間的距離；Padding 控制內容和盒子邊緣的留白。當上方文字增加一行，父容器重新計算高度，下方按鈕自然往下移。

| 設定 | 放在哪一層 | 解決的問題 | 做對時會看到 |
|---|---|---|---|
| Auto height | 文字層 | 句子換行後末尾被裁掉 | 文字框隨行數增高 |
| Vertical | 父 Auto Layout Frame | 子層各自漂在畫布上 | 訊息、提示、按鈕由上到下排列 |
| Gap | 父容器 | 相鄰內容距離不一致 | 每組相鄰子層保持同一間距 |
| Padding | 父容器 | 內容貼住卡片邊緣 | 四周留白穩定 |
| Hug contents | 父容器高度 | 卡片固定高度而裁切內容 | 卡片包住所有子層 |
| Fill container | 子層寬度 | 子層沒有使用可用空間 | 文字或按鈕填滿父容器內部 |
| Fixed | 已知尺寸的容器 | 需要穩定的外部基準 | 畫面或卡片寬度保持指定值 |

例如登入卡片寬度已由格線決定，就可以保持 Fixed；卡片高度會受訊息行數影響，因此設為 Hug contents。卡片裡的訊息和按鈕寬度則用 Fill container，讓它們使用父容器扣除左右 Padding 後的空間。當子層設為 Fill container，父層在同一方向會自動變成 Fixed，這是 Figma 用來確定可分配空間的正常結果。

層級比畫面位置更重要。兩個物件即使看起來上下相鄰，只有位於同一個 Auto Layout 父層時，內容變化才會帶動彼此。判斷時先看 Layers 的縮排，再看右側設定；這比手動拖動到漂亮位置更能證明版面真的會回應內容。

尺寸模式還要分方向判斷。同一張卡片可以在水平方向保持固定寬度，在垂直方向包住內容；訊息文字則可在水平方向填滿容器，在垂直方向隨行數長高。把「寬」和「高」分開說明，會比只記 Hug、Fill 或 Fixed 三個名稱更容易找到正確設定。

間距也需要共同規則。本課使用 4、8、12、16、24、32 這組 4 的倍數，涵蓋圖示和文字的貼近距離、同一群組內的間隔、卡片內距與區塊之間的留白。規律的數列能讓畫面節奏一致，也讓工程師看到設計時能快速對照。這不代表所有地方都用同一個距離；距離越小，兩個內容看起來越屬於同一組，距離越大，越能表示段落切換。

判斷時可以問兩個問題：這個物件的空間由誰提供？內容增加時誰要跟著改變？卡片寬度由手機格線提供，所以有明確基準；文字高度由句子行數決定，所以需要自動增加；按鈕位置由父容器的排列決定，所以跟在前一個子層之後。每個答案都對應一個層級和方向。

## 示範：把訊息與按鈕包進會長高的卡片

這一節會完整建立一次登入卡片。所有主線尺寸、文字與層級集中在規格表，步驟只引用名稱，方便你把注意力放在父子關係與變化結果。

| 類型 | 圖層名 | 規格 | 內容或用途 |
|---|---|---|---|
| 手機畫面 | `Screen / Login` | 402 × 874 | 登入畫面外層 |
| 畫面標題 | `Title` | 套用 `Type / Page title` | 「登入工作室」 |
| 訊息文字 | `Message` | 套用 `Type / Body`、W 322、Auto height | 「請輸入工作室帳號」 |
| 按鈕文字 | `Label` | 套用 `Type / Label` | 「登入」 |
| 練習按鈕 | `Button / Draft` | H 48、水平 Padding 16、垂直 Padding 12 | 水平排列、置中、綠底白字 |
| 登入卡片 | `Login / Card` | x 24、y 200、W 354、Padding 16、Gap 12 | Vertical、Height Hug、白底 |
| 輔助文字 | `Hint` | 套用 `Type / Supporting` | 「範例：studio@example.test」 |
| 窄版卡片 | `Login / Card 360` | W 312 | 測試畫面變窄後的換行 |

1. 在 `Screen / Login`（手機登入畫面）中建立 `Title`（畫面標題），套用規格表的標題樣式；完成後，登入畫面會保留清楚的第一層資訊。
2. 建立 `Message`（訊息文字），輸入短提示並到 Layout 把文字尺寸模式設為 **Auto height**；完成後，文字框具備隨行數增高的能力。
3. 建立 `Label`（按鈕文字），輸入「登入」後按 **Shift+A**；完成後，Figma 會新增一個包住文字的 Auto Layout Frame。

![Shift+A 後右側出現 Auto layout：Flow 方向、寬高的 Hug、Gap 與 Padding（紅框）](../assets/shared/ui/figma-auto-layout-panel.webp)

4. 把新外框命名為 `Button / Draft`（練習按鈕），依規格表設定排列、對齊、內距與顏色；完成後，白色文字會位在綠色按鈕中央。
5. 在 Layers 同時選取訊息文字與練習按鈕，再按 **Shift+A**；完成後，兩個物件會進入同一個新的 Auto Layout 父層。
6. 把父層命名為 `Login / Card`（登入卡片），依規格表設定 Vertical、Gap、Padding、寬度、Height Hug 與白底；完成後，卡片會包住訊息與按鈕。
7. 將登入卡片放到規格表的位置，再把訊息與按鈕寬度設為 **Fill container**；完成後，兩個子層會填滿卡片內側可用寬度。
8. 在 Layers 展開登入卡片，確認 `Message` 與 `Button / Draft` 是同層子物件，`Label` 則在按鈕裡；完成後，圖層縮排會清楚呈現三層關係。
9. 把訊息改成「密碼至少需要包含一個英文大寫字母與一個數字」；完成後，訊息會換行，卡片跟著長高，按鈕向下移動。
10. 把訊息改回短句，再切換一次長句；完成後，Gap、左右寬度與底部 Padding 都會保持一致。

短句測試可以用一個高度算式理解容器如何加總：上 Padding、文字高度、Gap、按鈕高度與下 Padding合起來就是卡片高度。依規格表的短句狀態，計算為 `16＋24＋12＋48＋16＝116`。文字若多一行，只替換實際文字高度；其他間距會自動維持。

## 跟著做：增刪內容，再改變容器寬度

這一節要讓卡片經過幾種常見內容壓力。提示會比示範少，請先判斷該改文字層、父容器或外層畫面，再動手設定。

1. 把訊息改成完整的帳號錯誤句，觀察換行、卡片高度與按鈕位置；完成後，三者應一起形成連續變化。
2. 在訊息和按鈕之間加入 `Hint`（帳號範例），再從 Layers 調整子層順序；完成後，卡片會增加一個文字高度與一段相鄰間距。
3. 刪除帳號範例，觀察卡片收回空間，再使用 Undo 還原；完成後，你會看到內容增刪能雙向改變容器高度。
4. 複製登入卡片作為窄版測試，縮小父容器寬度；完成後，Fill container 的訊息與按鈕會使用新的內側寬度。
5. 在窄版副本中，把訊息寬度暫時改為 Fixed，記錄它和 Fill container 在換行上的差異；完成後，再把主線卡片維持原本的寬度與填滿方式。
6. 在另一個測試副本中暫時固定卡片高度，加入長句觀察裁切；完成後，把高度恢復 Hug contents，確認內容重新完整出現。
7. 對照短句、長句、加入提示與窄版四種結果，寫下每一次真正改變的是哪一層；完成後，你會有一份可用來排查的父子層紀錄。

接著做一次連續內容測試：依序輸入短提示、完整錯誤句與更長的密碼規則，每次都只改 Message 文字。觀察卡片底部和按鈕之間的關係，並確認左右寬度維持一致。這個測試能排除「剛好只有某一句看起來正常」的情況。

再從 Layers 把提示拖到按鈕下方，觀察排列順序改變後卡片是否仍包住所有內容；完成記錄後移回原位置。這一步練習的是子層排序，讓你知道 Auto Layout 會依圖層順序排版，而非依物件原本在畫布上的座標。

## 把間距存成 Number 變數

目前登入卡片的 Gap 與 Padding 已經是 4 的倍數，但若每個欄位都各自輸入數字，後續仍可能出現 15、18 或 23 之類難以追蹤的間距。Number（數字）變數會把常用距離收進 `Studio`，套用後欄位顯示變數名稱，日後也能從同一處更新。

| 變數 | 值 | 適合的關係 |
|---|---:|---|
| `Space 4` | 4 | 圖示與很貼近的文字 |
| `Space 8` | 8 | 標籤內或同一群內容 |
| `Space 12` | 12 | 卡片內相鄰欄位 |
| `Space 16` | 16 | 卡片內距與主要群組 |
| `Space 24` | 24 | 不同內容區塊 |
| `Space 32` | 32 | 大段落或畫面區域 |

1. 點左側圖示列的 **Variables**，進入 `Studio` 集合，再點 **Create variable** 並選 **Number**；完成後，表格會出現可輸入名稱與數值的新列。
2. 建立 `Space 4`，輸入對應值，再按 Tab 移到下一欄；完成後，第一個間距變數會留在 `Studio`。
3. 依規格表建立其餘五個間距變數；完成後，顏色與間距會在同一集合中各自按名稱辨識。
4. 回到畫布選取登入卡片，把滑鼠移到 Padding 數值欄右端，點出現的變數圖示並選 `Space 16`；完成後，卡片四周內距會綁定變數。

![滑鼠移到 Padding 欄右端出現變數圖示，點開後選本檔的間距變數（紅框）](../assets/shared/ui/figma-padding-variable.webp)

5. 在 Gap 欄用相同方法套用 `Space 12`；完成後，相鄰子層的間隔會顯示對應變數。
6. 檢查登入卡片、練習按鈕與新增提示所用的 Gap、Padding；完成後，所有間距都能對應到這組數列。若發現不是 4 的倍數，選最接近且能表達原本群組關係的變數，再比較修改前後。

數字變數用在距離與必要尺寸，字級仍維持文字樣式管理。兩者分開後，調整間距不會意外改到文字角色，也不會把每個數字都塞進同一份清單。

## 用 Min 與 Max 守住元件寬度

Fill container 讓卡片使用父層可用空間，但桌面畫面一旦很寬，登入卡片也可能被拉成一條長帶，文字行長變得難讀。Min／Max 為 Auto layout 物件設定寬度界線：空間不足時仍可縮到合理下限，空間充足時則停在容易閱讀的上限。

1. 把登入卡片放進一個較寬的桌面測試 Frame，並讓卡片寬度回應父層；完成後，拉寬父層會看到卡片跟著變寬。
2. 選取登入卡片，點 W 欄的下拉箭頭，選 **Add max width…**，輸入 480；完成後，父層繼續拉寬時，卡片會停在這個上限。

![W 欄下拉選單裡的 Add min width 與 Add max width（紅框）](../assets/shared/ui/figma-min-max-width.webp)

3. 把桌面測試 Frame 拉窄再拉寬，觀察卡片何時開始變化、何時停止；完成後，你會確認 Max width 保護的是閱讀行長，而非固定畫面座標。
4. 選取主要按鈕，從 W 欄下拉選 **Add min width…**，輸入 160；完成後，把按鈕文字暫時改成短字時，按鈕仍保留足夠的視覺與觸控範圍。
5. 將按鈕文字換回「登入」，並把測試 Frame 還原；完成後，正式卡片保留原本版面，Min／Max 也持續作為尺寸保護。

卡片上限選 480，是為了避免桌面上出現過長的單行內容，同時保留比手機卡片更寬的彈性。按鈕下限選 160，則讓短標籤仍保有穩定份量。這兩個值屬於主線示範決策；換成自己的題目時，要依內容和畫面檢查後留下理由。

## 讓任務標籤在空間不足時自動換行

待處理清單之後會同時出現優先順序、對象與期限等標籤。固定排成一列時，只要文字變長或卡片變窄，最右邊的標籤就會超出範圍。Wrap 讓水平 Auto layout 在可用寬度不足時，把後面的子層移到下一列。

1. 建立五個短文字標籤：「高優先」「客戶」「本週」「交付」「待確認」，每個文字外面用 **Shift+A** 包成有淺底與內距的小 Frame；完成後，五個標籤都能獨立調整內容。
2. 同時選取五個標籤，再按 **Shift+A** 建立水平 Auto layout，命名為 `Tags`；完成後，標籤會排成一列。
3. 在 Auto layout 的 Flow 按鈕右側點 **Wrap**；完成後，`Tags` 具備多列排列能力。
4. 把 `Tags` 的寬度縮窄，直到最後一個標籤移到下一列；完成後，容器會增加高度，標籤之間仍維持設定的 Gap。
5. 把其中一個標籤改成較長的「等待客戶確認」，再測一次寬版與窄版；完成後，換行由真實內容與可用空間共同決定。
6. 把 `Tags` 放到一張任務卡片裡，確認父卡片採 Hug contents；完成後，標籤增加一列時，整張卡片也會跟著長高。

這排 `Tags` 會在後續清單列中繼續使用。現在先保留文字可改、能換行的結構；標籤的共用元件與狀態會在建立元件後再整理。

## 看兩版長訊息，判斷哪一版真的能適應內容

這一節比較兩種合理的寬度策略。版本一的登入卡片在桌面上設定 Max width，畫面再寬也維持容易閱讀的行長，兩側會留下較多空間。版本二讓卡片 Fill container，充分使用桌面主區，欄位較多或內容需要左右並排時能放下更多資訊；文字行長也會跟著增加。

請說明哪一類內容適合版本一、哪一類內容適合版本二。判斷時要提到內容量、欄位排列、閱讀行長與所在版面；再補一句你會用什麼畫面變化測出目前策略的界線。

<details><summary>看完自己的判斷再展開</summary><p>兩版都有適用情境。單欄登入或長段說明適合設定 Max width，讓視線不必橫跨太遠；多欄資料、篩選工具或需要並排比較時，可讓卡片使用較多可用寬度。實際選擇要用窄版、一般桌面與寬版逐一測試，確認內容沒有過度換行或拉得太散。</p></details>

## 卡住時，先找出哪一層沒有回應

這一節把現象對應到設定位置。先觀察是文字沒長高、卡片沒長高，還是子層不在正確隊伍裡，再去修改相應層級。

| 看到的現象 | 通常的原因 | 怎麼修 |
|---|---|---|
| 長句末尾被裁掉 | 文字尺寸模式仍是固定高度 | 選取文字層，到 Layout 改為 Auto height |
| 文字變高但按鈕不動 | 兩者不在同一個垂直父層 | 在 Layers 把兩者放進同一張 Auto Layout 卡片 |
| 卡片裁掉最下方內容 | 父容器高度設為 Fixed | 選取卡片，把高度改成 Hug contents |
| 新提示沒有參與排列 | 圖層在卡片外或忽略排列 | 把提示移入卡片，確認與其他子層同層 |
| 子層沒有 Fill container | 所選物件缺少 Auto Layout 父層 | 先確認父子層級，再選子層設定寬度 |
| 按鈕文字偏向一側 | 按鈕父層沒有置中 | 選取按鈕外框，檢查水平與垂直對齊 |
| Padding 旁找不到變數圖示 | 滑鼠尚未移到數值欄右端 | 選取 Auto layout 物件，再把游標移到對應欄位右側 |
| Max width 沒有限制效果 | 物件目前沒有隨父層變寬 | 先確認寬度模式與父層空間，再拉寬父層測試 |
| 標籤超出容器 | `Tags` 仍是單列水平排列 | 選取標籤父層，在 Flow 右側開啟 Wrap |

修復後要重新切換一次短句與長句。只有當內容變化能再次帶動卡片與按鈕，才表示修到真正原因，而非只把某一張畫面拖回好看的位置。

## 換你做：你的題目

從你的畫面清單挑出這次對應的畫面。接著用間距變數完成自己題目的清單卡片，以需求資料中最長的那筆測試長高，再替卡片設定寬度上下限，做一排會自動換行的標籤。下面三欄提供可採用的對應；若你的畫面清單採用不同名稱或拆法，以自己的需求初稿為準。

### 三個題目的建議對應

要達成的條件：

- 這次做的畫面在你的畫面清單上；清單沒有的，先補進清單並寫一句理由。
- 題目指定的卡片內容位於同一個垂直 Auto layout，Layers 看得出父子關係。
- Padding 與 Gap 套用自己建立的間距變數，選擇能說明內容群組關係。
- 最長資料完整顯示，文字增加行數時卡片高度會配合變化。
- 卡片設定合理的 Min／Max 寬度，並用窄版與寬版留下選擇理由。
- 標籤列開啟 Wrap，空間不足或標籤變長時能移到下一列。

合格的結果要能通過這些自我檢查：

- 需求頁中最長的名稱或說明完整可讀，沒有蓋住狀態或超出卡片。
- Layers 中卡片內容與標籤都在正確父層內，而非只在畫布上靠近。
- 卡片變窄時沒有縮小文字，改由換行與容器高度吸收變化。
- 拉寬桌面測試區時，卡片會在 Max width 停止；縮窄時不低於可用的 Min width。
- 換回短資料時，卡片與標籤列會收回多餘高度，間距節奏維持一致。

## 把會長高的卡片交給下一個共用元件

回到工作室登入情境，你現在有一張能承受長句、提示增刪與窄版畫面的登入卡片。訊息層負責自己的換行，父容器負責包住內容，按鈕則在同一個排列中維持位置。下一次會把這顆按鈕從單一畫面中的練習物件，轉成可放到登入、詳情與確認畫面的共用來源。

完成條件：

- 登入卡片以 Vertical Auto Layout 排列訊息與按鈕。
- 訊息使用 Auto height，卡片高度使用 Hug contents。
- 長句、增加提示與改窄畫面時，內容都不重疊。
- 固定寬度與 Fill container 的比較紀錄能說明差異。

想一想：為什麼只把訊息文字設為 Auto height，仍不足以保證下面的按鈕會移動？

<details><summary>展開參考答案</summary><p>Auto height只改變文字框自身高度；訊息和按鈕還需要位在同一個垂直Auto Layout父層中，父層以Hug contents重新計算高度，後面的子層才會跟著移動。</p></details>
