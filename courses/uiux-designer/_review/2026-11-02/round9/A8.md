# 設計能讓人知道下一步的回饋、彈窗與導覽
副標：工作室人員完成任務、遇到提醒或失敗時，都要立刻知道發生什麼事、怎麼返回，以及下一步能做什麼。
本堂完成物：可切換三種類型的 Toast 元件；一個確認完成彈窗；有頂部返回與底部導覽的手機畫面

## 從任務詳情接著做，補上操作後的回應

工作室人員已能從待處理清單打開「整理交付包」詳情，但按下「標記完成」之後，畫面還沒有說明結果。若操作成功卻沒有回應，使用者可能重複按；若資料尚未核對，系統需要先提醒；若儲存失敗，更要說清楚可以怎麼恢復。這堂會用同一個 Toast（短暫提示）元件的成功、警告、錯誤三種類型處理結果，再用 Dialog（對話框）處理需要先確認的決定。

這項工作會使用上次完成的 `Screen / List`（待處理清單）、`Screen / List Empty`（空清單）、`Screen / Detail`（任務詳情）與 `Button / Complete`（完成按鈕）。先看[本堂起始材料](../assets/A8-toast-dialog-navigation/START-HERE.html)，確認這些畫面與 Button 元件都在同一頁；需要按鈕時從 Assets（元件資產面板）插入。完成 Toast 元件集、彈窗、頂部標題列與導覽後，再用[完成檢查表](../assets/A8-toast-dialog-navigation/reference/EXPECTED-CHECK.html)逐項比對。沒有上次成果時，先回到[清單、空狀態與詳情](CH7-list-content.html)依規格表補做，約需二十到三十分鐘。

先把任務流程用一句話寫在畫布旁：「登入 → 待處理清單 → 任務詳情 → 按 `Button / Complete` → `Screen / List Done`，畫面上方顯示成功 Toast。」這句話會幫你判斷回饋放在哪個時刻：確認彈窗先放在旁邊準備，完成結果直接放進完成清單；資料有風險時需要 Warning Toast，儲存失敗時需要 Error Toast。頂部返回處理頁面層級，底部導覽則持續告訴使用者目前位於待處理或已完成。

## 先選回饋方式，再決定外觀

這一節要先分清楚每個元素處理的問題。Toast 用來告知剛剛發生的結果；Warning 指出目前有風險，但仍可能繼續；Error 說明動作沒有完成，並給出恢復方向；Dialog 會停下流程，讓使用者做出選擇；Navigation（導覽）則維持位置感。

例如，「任務已移到已完成」是已發生的結果，適合 Success。「這筆任務還有未核對的檔名」是繼續前要注意的風險，適合 Warning。「無法儲存變更，請檢查網路後再試一次」表示動作失敗，適合 Error。「確認要把這筆任務標記完成嗎？」需要明確回答，適合 Dialog。

| 工作情境 | 使用元素 | 文字要回答什麼 | 使用者下一步 |
|---|---|---|---|
| 任務完成並移出待處理 | Toast／Success | 完成了什麼、結果在哪裡 | 繼續工作或查看完成清單 |
| 資料仍有需要注意之處 | Toast／Warning | 有什麼風險、繼續會怎樣 | 回去檢查或決定繼續 |
| 儲存或連線失敗 | Toast／Error | 哪個動作失敗、如何恢復 | 重試或回到安全狀態 |
| 重要狀態即將改變 | Dialog | 要確認什麼、結果是什麼 | 取消或確認 |
| 詳情回到清單 | Top Bar | 目前頁面與上一層在哪裡 | 返回原清單 |
| 待處理與已完成切換 | Navigation | 目前在哪裡、還能去哪裡 | 前往另一個主要區域 |

三種 Toast 都要有「類型＋具體文字」，顏色與圖示只負責加快辨認。Success 可以寫「任務已完成，已移到完成清單」；Warning 可以寫「尚有檔名未核對，請確認後再完成」；Error 可以寫「無法儲存變更，請檢查網路後再試一次」。只寫「成功」「注意」「錯誤」會讓使用者知道情緒，卻不知道發生了什麼。

Dialog 只用在需要決定的時刻。它的順序是「問什麼」「會造成什麼結果」「有哪些選擇」；按鈕文字要直接寫動作，例如「取消」與「確認完成」。導覽則應在每張主要畫面保持同一位置，用文字和底線共同標示目前頁，讓位置感不只依賴顏色。

## 示範：建立 Toast 元件集與確認彈窗

這一節會先做共用的 Toast 結構，再用 Variant 建立 Success、Warning、Error。規格表保存現稿的主要尺寸與間距；三種類型沿用相同結構，只切換圖示、色彩與 Message。

| 圖層或元件 | 規格 | 內容或用途 |
|---|---|---|
| `Toast` | Horizontal；W 354（Fixed）；Fill `Card`；1 px `Control Border` 外框；圓角 8；水平 Padding 16；垂直 Padding 12；Gap 8；Hug 高 | 共用提示元件集 |
| Variant `Type` | Success／Warning／Error | 切換結果、風險與失敗類型 |
| Text property `Message` | 套用 `Type / Body`；Fill container；Auto height | 預設值「已完成」；各使用處可改具體訊息，長句會換行 |
| Toast 圖示 | Success 用 `Icon / Check`；Warning、Error 都用 `Icon / Alert`；Stroke 依 Type 套用 `Success`、`Warning`、`Error` | 用圖示與線條色辨認提示類型 |
| `Screen / List Done` | 402 × 874 | 標題「已完成」；只顯示「整理交付包」且 Status 為 Done；成功 Toast 顯示在畫面上方 |
| `Screen / Detail Warning` | 402 × 874；由 `Screen / Detail` 複製 | 顯示 Warning Toast 的詳情測試畫面 |
| `Screen / Detail Error` | 402 × 874；由 `Screen / Detail` 複製 | 顯示 Error Toast 的詳情測試畫面 |
| `Overlay / Confirm` | Vertical；Gap 16；四邊 Padding 24；寬 320；Hug 高；白底；圓角 8 | 確認完成彈窗 |
| `Dialog / Title` | 套用 `Type / Section title`；Fill；Auto height | 「確認完成？」 |
| `Dialog / Body` | 套用 `Type / Body`；Fill；Auto height | 「這筆任務將移到已完成清單。」 |
| `Dialog / Actions` | Horizontal；Gap 12；寬 272；Hug 高 | 取消與確認按鈕列 |
| `Button / Cancel` | Secondary／Default；W 130（Fixed）；高 48 | 「取消」 |
| `Button / Confirm` | Primary／Default；W 130（Fixed）；高 48 | 「確認完成」 |
| `Nav / Bottom` | Horizontal；W 402；H 64；Gap 0；y 810；Fill `Card` | 手機底部導覽；兩個項目各 W 201、H 64 |
| `Top Bar` | x 24；W 354（Fixed）；Horizontal；Hug 高 | 詳情頁返回與標題 |

1. 從 Assets 插入 `Icon / Check`（勾選圖示），把圖示向量的 Stroke 套用 `Success`。完成後會看到 Success 線條色的勾選圖示。
2. 建立 `Toast / Message`（提示訊息），輸入「已完成」。完成後勾選圖示旁會顯示這段預設訊息。
3. 同時選取圖示與文字按 **Shift+A**，命名為 `Toast`（提示），再套用規格表中的 Auto layout。完成後會看到固定寬的卡片提示，勾選圖示在左，成功訊息在右。
4. 選取 Toast 按右鍵選 **Create component**。完成後 Toast 會變成紫色外框的主元件。
5. 選取主元件，在 Properties 按加號建立 Text property `Message`，預設值填「已完成」。完成後主元件會出現可改訊息的文字屬性。
6. 選取 `Toast / Message` 文字層，從 Content 旁的 Apply variable/property 圖示綁定 `Message`。完成後右側的 Message 欄位會控制畫面上的「已完成」。
7. 選取主元件，以 **Main component → Add variant** 增加第二個版本。完成後會得到含兩個版本的紫色虛線元件集。
8. 點元件集下方的加號建立第三個 Variant。完成後元件集會有三個結構相同的版本，各版本的文字層旁都會顯示 Message 屬性圖示。
9. 將預設屬性改名為 `Type`，三個值填 Success、Warning、Error。完成後使用處能從右側切換提示類型。
10. 將 Warning 版本的圖示替換為 `Icon / Alert`，並把圖示向量的 Stroke 套用 `Warning`。完成後會看到 Warning 線條色的警告圖示。
11. 將 Error 版本的圖示也替換為 `Icon / Alert`，再把圖示向量的 Stroke 套用 `Error`。完成後同一個警示圖示會顯示 Error 線條色。
12. 從 Assets 插入三個 Toast 使用處，Type 依序選 Success、Warning、Error。完成後三種提示都由同一個元件集產生。
13. 將三個使用處的 Message 改成規格中的成功、風險與失敗訊息。另用一則超過 18 字的訊息測換行，測完改回。完成後三則訊息完整顯示。
14. 在手機畫面外建立 Frame，命名為 `Overlay / Confirm`（確認彈窗）。完成後會得到可包含文字與按鈕的父容器。
15. 建立 `Dialog / Title`（彈窗標題）與 `Dialog / Body`（彈窗說明），填入規格表內容。完成後彈窗會先問問題，再解釋結果。
16. 從 Assets 插入兩個 Button 使用處，分別設定為取消與確認。完成後會看到兩個沿用既有按鈕家族的選擇。
17. 逐一選取兩個按鈕；若右側曾設過 Min width，先移除。完成後兩個按鈕都不再受最小寬度限制。
18. 將兩個按鈕的 W 都設為 130（Fixed）。完成後兩個按鈕會顯示相同的固定寬度。
19. 同時選取兩個按鈕按 **Shift+A**，命名為 `Dialog / Actions`（彈窗動作列），再套用規格表設定。完成後兩顆 130 寬的按鈕會以 12 的間距並排。
20. 將 Title、Body、Actions 放入確認彈窗，套用垂直 Auto layout。完成後彈窗會依標題與說明長度自動增高。

在動作列寬 272、間距 12 的情況下，兩顆等寬按鈕各占 130。這個算式只用來理解現有版面；如果按鈕文字變長，先比較水平與垂直排列的可讀性，再決定結構。保留文字大小與按鈕高度，比把長文字壓成難讀的一行更穩定。

接著把 Body 改成較長的說明：「確認後這筆任務會移到已完成清單；如果資料尚未核對，請先取消並返回詳情修正。」文字使用 Auto height，外層使用 Hug，Actions 會自然往下移。這次測試證明彈窗能承受內容變化，也為警告情境留下足夠說明空間。

## 跟著做：把結果放回清單，再建立導覽

這一節要把元件使用處放回工作室流程。先為完成結果準備畫面，再補上手機與桌面位置感；每一步都要能看到清楚的頁面狀態。

1. 複製待處理清單。完成後會看到內容相同的第二張清單畫面。
2. 將副本命名為 `Screen / List Done`（完成清單畫面）。完成後 Layers 會出現可辨認的完成清單名稱。
3. 把畫面標題改成「已完成」。完成後畫面頂端會顯示目前所在的清單類型。
4. 刪除其他待處理列，只保留「整理交付包」。完成後完成清單只會顯示這一筆任務。
5. 把「整理交付包」的 Status 切成 Done。完成後這一筆會顯示已完成外觀。
6. 插入 Toast 使用處，把 Type 選成 Success，Message 改成「任務已完成，已移到完成清單」。完成後使用者會知道任務已移動。
7. 複製 `Screen / Detail` 兩次，命名為 `Screen / Detail Warning`、`Screen / Detail Error`。完成後會得到兩張可分別檢查警告與錯誤的詳情畫面。
8. 在 `Screen / Detail Warning` 插入 Toast 使用處，把 Type 選成 Warning，Message 改成「尚有檔名未核對，請確認後再完成」。完成後畫面會在確認前指出尚未核對的內容。
9. 在 `Screen / Detail Error` 插入 Toast 使用處，把 Type 選成 Error，Message 改成「無法儲存變更，請檢查網路後再試一次」。完成後會清楚說明儲存失敗與重試方向。
10. 建立「待處理」與「已完成」兩個導覽項目，分別包進 W 201、H 64 的小 Frame。完成後會得到兩個等寬的主要區域入口。
11. 將兩個項目水平排列，命名為 `Nav / Bottom`（手機底部導覽），再套用規格表中的手機值。完成後 `Card` 底的導覽會以 y 810 貼在手機畫面底部。
12. 在待處理清單用 Primary 文字與底線標示「待處理」。完成後這張畫面會直接顯示目前位於待處理分頁。
13. 把 `Nav / Bottom` 複製到 `Screen / List Done`，把「已完成」標成目前分頁。完成後完成清單底部會有相同導覽，且選中狀態改到「已完成」。
14. 複製一份桌面參考，建立 `Nav / Desktop`（桌面導覽）。完成後導覽會位於桌面上方，並能容納工作室名稱與較完整的連結。
15. 對照手機與桌面兩版，寫下位置與資訊密度的理由。完成後你能說明兩者服務相同目的，但因畫面空間採用不同配置。

手機導覽的現稿規格是兩個項目各寬 201、高 64，合起來寬 402、Gap 0，放在畫面底部；桌面導覽寬 1200、高 64，位於上方。此時先完成視覺與內容，後面處理捲動時再決定固定位置。桌面空間較大，可以加入品牌名稱；手機優先保留兩個短而清楚的目的地。

最後把工作室流程排成四個畫面節點：登入、待處理清單、任務詳情、完成清單。確認彈窗放在詳情與完成清單旁，保留給後續插入流程；成功結果直接顯示在 `Screen / List Done` 上方的 Toast。現在先用畫布位置與文字說明表達，後面的原型階段再建立實際連線。

## 在詳情上方加返回，讓每個可點範圍都按得到

有了底部導覽之後，這一節要補上頁面層級。底部導覽在主要區域之間切換，例如待處理與已完成；Top Bar（頂部標題列）的返回則從任務詳情回到剛才的清單。兩者位置不同，解決的問題也不同。

手機上的圖示看起來可以只有二十四像素，但手指需要更大的命中範圍。這裡把每個可點元素的外框做到至少 44×44；圖示維持清楚的視覺大小，外面再包透明 Frame。使用者看到的是俐落的小圖示，實際上能在移動中穩定按到。

| 圖層或元件 | 規格 | 內容或用途 |
|---|---|---|
| `Top Bar` | x 24；W 354（Fixed）；Horizontal；Hug 高 | 詳情頁返回與標題 |
| `Button / Back` | 44 × 44；透明 Frame | 全課唯一的返回按鈕；返回清單的觸控範圍 |
| `Icon / Arrow Left` | 24 × 24；置中 | 返回圖示 |
| `Top Bar / Title` | 套用 `Type / Section title`；Fill | 「任務詳情」 |
| 導覽項目 | 觸控範圍至少 44 × 44 | 待處理、已完成 |

1. 刪除任務詳情裡原本的「← 返回清單」文字。完成後詳情頂部不再顯示舊的文字返回入口。
2. 從 Assets 插入 `Icon / Arrow Left`（返回圖示）。完成後會看到二十四像素的向左箭頭。
3. 選取返回圖示按 **Shift+A**，將 W、H 都設為 44（Fixed），對齊選置中，命名為 `Button / Back`（返回按鈕）。完成後圖示會置中顯示在 44 × 44 的透明觸控範圍內。
4. 在返回按鈕右側加入 `Top Bar / Title`（頂部標題），輸入「任務詳情」。完成後使用者能同時辨認所在頁與返回方向。
5. 同時選取返回按鈕與頂部標題按 **Shift+A**，命名為 `Top Bar`（頂部標題列），X 設 24、W 設 354（Fixed）。完成後會看到一個對齊詳情內容寬度的頂部容器。
6. 把標題設為 Fill container。完成後標題會使用剩餘寬度，返回按鈕維持固定尺寸。
7. 檢查完成按鈕、彈窗按鈕、底部導覽與頂部返回的外框。完成後每個可點範圍都至少符合相同的觸控基準。
8. 暫時把透明 Frame 加上淡色外框，比較圖示大小與命中範圍。完成後會看出「看起來的圖示」和「實際可點區」是兩個層次。
9. 移除檢查用外框，保留透明 Frame。完成後畫面恢復乾淨，觸控範圍仍然存在。

Top Bar 標題應描述現在的頁面，而非把返回按鈕寫成模糊的「上一頁」。例如從「整理交付包」詳情返回時，箭頭可搭配「任務詳情」；真正連線時再讓它回到待處理清單。底部導覽的選中狀態則持續指出目前屬於哪個主要區域。

## 看兩版詳情頁，判斷哪一版比較容易操作

這一節要同時看位置感與觸控範圍。版本一的詳情頁只有一個二十四像素返回箭頭，互動只綁在箭頭線條上；底部「已完成」只有顏色改變，文字和其他項目相同。版本二把返回圖示包在四十四像素透明 Frame 中，Top Bar 顯示「任務詳情」；底部選中項目同時有文字色與底線。

請判斷哪一版較符合本頁教過的方法，再指出另一版看起來仍算整齊，實際操作卻會遇到的具體問題。

## 卡住時，回到元素的工作重新檢查

這一節用「這個元素本來要解決什麼」來找原因。Toast 處理結果與風險，彈窗處理選擇，頂部返回處理頁面層級，底部導覽處理主要區域；把責任分清楚，修復會更直接。

| 看到的現象 | 通常的原因 | 怎麼修 |
|---|---|---|
| 三種提示只靠顏色區分 | Message 只寫成功、注意、錯誤 | 補上具體結果、風險或恢復方向 |
| 使用處無法改提示文字 | Message 尚未綁定 Text property | 回 Toast 主元件綁定 `Message` |
| 切換 Type 後圖示或文字跳位 | 三個 Variant 的階層不同 | 對齊圖示與 Message 的名稱、順序與尺寸 |
| 提示長句被裁切 | 文字或外層使用固定高度 | 將文字設 Auto height，外層設 Hug |
| Dialog 的子層無法一起排列 | 外層使用 Rectangle | 改用 Frame，將 Title、Body、Actions 移入 |
| 兩顆按鈕文字太擠 | 水平 Actions 不適合目前文案 | 比較改短文字或垂直排列，保留可讀尺寸 |
| 返回圖示很難按 | 互動範圍只有圖示線條 | 在外面包至少 44×44 的透明 Frame |

修完後先遮住顏色，只讀文字與排列。若仍能分辨成功、警告、錯誤、取消、確認、返回與目前頁，代表資訊沒有只依賴視覺色彩。

## 換你做：你的題目

從你的畫面清單挑出這次對應的畫面。接著把 Toast、確認、Top Bar 與底部導覽移到自己的題目，讓使用者在主要動作前後都能看懂結果、風險、返回方向與所在區域。

三個題目的範例（可以照做，也可以依你的需求改）：

| 預約 | 點餐 | 會員 |
|---|---|---|
| 成功「預約成功」；警告「大型犬需多 30 分鐘」；錯誤「網路中斷，請確認連線後再按一次『送出預約』」；主要動作「送出預約」。 | 成功「訂單已送出」；警告「取餐時間在尖峰需多等 10 分鐘」；錯誤「網路中斷，請確認連線後再按一次『送出訂單』」；主要動作「送出訂單」。 | 成功「兌換成功」；警告「兌換後點數剩不到 50」；錯誤「網路中斷，請確認連線後再按一次『確認兌換』」；主要動作「確認兌換」。 |

底部導覽請從自己的畫面清單判斷：你的畫面清單裡，哪幾個是使用者常常來回切換、彼此平行的區域？先暫定 3～4 個分頁，做需求與流程那一堂會再檢查。

要達成的條件：

- 這次做的畫面在你的畫面清單上；清單沒有的，先補進清單並寫一句理由。
- 寫一句理由，說明你的做法回應了需求頁裡店主或使用者的哪一句話（引用原句）。
- 建立一個 `Toast` 元件集，Type 有 Success、Warning、Error，Message 可在使用處修改。
- Toast 若沿用主線元件，要用複製並換綁的方式做成題目自己的元件；做法同元件那一堂。
- 三種提示都由 Toast 使用處產生，文字要交代發生的事與可採取的下一步。
- 製作題目主要動作的確認彈窗，包含明確標題、結果說明、取消與確認。
- 在詳情畫面加入含返回圖示與頁面標題的 Top Bar。
- 從自己的畫面清單暫定 3～4 個分頁，製作底部導覽並標示目前頁。
- 檢查所有可點元素的觸控範圍，圖示較小時用透明 Frame 擴大。

合格的結果要能通過以下自我檢查：

- 三種提示遮住顏色後，仍能從文字辨認用途與下一步。
- 三個 Toast 使用處切換 Type 後，圖示、文字位置與內距保持一致。
- 理由引用的原句真的在需求頁裡。
- 彈窗能回答要確認哪一個動作，以及確認後會改變什麼。
- 取消與確認是兩個完整按鈕，按鈕文字能預測結果。
- Top Bar 的返回圖示容易按到，標題能說明目前頁面。
- 底部導覽的 3～4 個分頁來自自己的畫面清單，選中狀態使用至少兩種視覺線索。
- 每個可點範圍至少達到本頁的觸控尺寸基準。

## 收回工作室流程，準備把畫面連起來

這堂讓工作室的「標記完成」有了完整回應：同一個 Toast 元件集用 Success 交代結果與去向，用 Warning 指出尚待確認的內容，用 Error 提供恢復方向；確認彈窗讓重要變更有安全出口，Top Bar 提供返回，手機與桌面導覽則持續標示目前位置。自己的題目也完成 Toast 元件集、確認彈窗、暫定 3～4 個分頁的底部導覽與觸控尺寸檢查。

下一堂會拿登入、清單、詳情、彈窗與完成清單規劃流程，先整理需求、畫流程圖與線框，再建立原型起點。今天的圖層名稱、畫面內容與動作文字越清楚，之後連線時越容易判斷每個熱區應前往哪個目的地。
