# 把任務做成會增高、可增刪的清單
副標：工作室任務有長有短，清單要能隨資料增減重排，也要在沒有任務時說清楚現在的狀態。
本堂完成物：可隨內容增高的任務清單；有說明的空清單；一張任務詳情畫面

## 從會長高的表單，接到會變動的任務資料

工作室每天收到的任務數量不同，標題長度也不同。若每一列都靠手動定位，長標題會撞到期限，新增資料又得把後面所有列往下搬；當最後一筆被移除時，整張畫面還可能只剩一片空白。這堂要把任務內容包成有層級的 Row（任務列），再用 List（清單容器）管理多筆資料。

這項工作會接著使用上次在表單裡練過的 Auto height（自動增高）、Hug contents（貼合內容）與 Fill container（填滿容器）。先開[本堂起始材料](../assets/A7-list-content/START-HERE.html)，了解任務資料與要保留的畫面；完成清單、空狀態與詳情後，再用[完成檢查表](../assets/A7-list-content/reference/EXPECTED-CHECK.html)逐項核對。主線資料來自[任務資料](../assets/shared/TASK-DATA.csv)，所有畫面仍放在同一個 Figma 檔案的同一頁。

先在畫布空白處規劃一個新的清單區，不必改動已完成的登入表單。這樣能保留「登入」與「待處理清單」兩個工作階段，後面做原型時再把它們串起來。按鈕元件也繼續沿用，詳情畫面會插入「標記完成」作為主要動作。

## 清單由兩層規則組成

這一節要看懂 Row 與 List 各自解決什麼問題。每一個 Row 包住同一筆任務的標題、期限狀態與前往詳情的線索；外層 List 再包住多個 Row，負責列與列之間的間距。內外兩層各管一件事，資料變長或筆數改變時，版面才知道該推開誰。

例如，「整理交付包」只佔一行，而「確認活動報名資料並補上聯絡電話」在同樣寬度下可能換成兩行。兩筆任務都使用相同字級與內距，長標題所在的 Row 自然增高，下一列由外層 List 往下排。這比為每一列指定固定高度更能保留內容，也不用為了塞進一行而縮小文字。

| 層級 | 包含內容 | 負責的變化 | 用得對的畫面線索 |
|---|---|---|---|
| `Row / Task` | Title、Meta、Link | 同一筆內容變長或變短 | 標題換行時該列增高 |
| `List / Content` | 多個 Row | 任務增加、刪除與排序 | 增刪後其他列自動重排 |
| `Screen / List` | 畫面標題、List | 手機頁面的整體閱讀順序 | 畫面標題不會混入清單一起移動 |
| `Screen / List Empty` | 空狀態標題與說明 | 沒有資料時解釋目前情況 | 使用者看得懂這不是載入失敗 |

空狀態也是清單的一種結果。好的空狀態要回答「現在怎麼了」與「接下來會發生什麼」；例如「目前沒有待處理任務」說明狀態，「新任務會顯示在這裡」建立預期。只留下空白框，使用者會猜測資料是否還在載入、是否被刪掉，或畫面是否壞了。

詳情畫面則把一筆任務展開。清單列只保留掃讀需要的標題、狀態、期限與前往線索；較長的說明和主要動作放進 Detail。這種資訊分工讓清單保持可掃讀，也讓詳情有足夠空間說清楚任務內容。

## 示範：先做一列，再讓三筆資料自動排列

這一節會從第一筆任務建立可重複的 Row，再把三列放進 List。規格表列出名稱與設計值，步驟中只要確認內容是否進入正確層級。

| 圖層或畫面 | 規格 | 內容或用途 |
|---|---|---|
| `Screen / List` | 402 × 874；Surface 底色 | 待處理清單畫面 |
| 畫面標題 | x 24、y 48；24／32 | 「待處理清單」 |
| `Row / Task` | Vertical；Gap 8；四邊 Padding 16；寬 354；Hug 高；白底；圓角 8 | 單筆任務容器 |
| `Row / Title` | 18／28；Fill；Auto height | 任務名稱 |
| `Row / Meta` | 14／22；Fill；Auto height | 狀態與期限 |
| `Row / Link` | 14／22；Primary 色；Fill | 「檢視詳情 →」 |
| `List / Content` | x 24、y 110；Vertical；Gap 12；寬 354；Padding 0；Hug 高 | 多筆任務容器 |
| `Screen / Detail` | 402 × 874 | 任務詳情畫面 |
| 詳情內容 | x 24、y 120；寬 354；Vertical；Gap 20；Hug 高 | 說明與主要動作 |

1. 按 **F** 建立手機 Frame（畫框），命名為 `Screen / List`（清單畫面），再套用規格表中的尺寸與底色。完成後會得到一張獨立的工作室清單畫面。
2. 加入「待處理清單」標題。完成後使用者會先知道自己位於哪一類任務中。
3. 建立 `Row / Title`（任務標題），輸入「整理交付包」。完成後會看到第一筆任務的主要識別文字。
4. 建立 `Row / Meta`（任務摘要），輸入「待處理 · 今天18:00」。完成後狀態與期限會集中在次要文字中。
5. 建立 `Row / Link`（詳情線索），輸入「檢視詳情 →」。完成後這一列會表明還有更完整內容。
6. 同時選取三個文字層按 **Shift+A**，命名為 `Row / Task`（任務列），再套用規格表中的 Auto layout。完成後第一筆資料會被同一個白色容器包住。
7. 複製任務列兩份，依資料改成「確認活動報名資料並補上聯絡電話」與「更新本週任務說明」。完成後會看到三筆內容各自留在自己的 Row 中。
8. 將第二筆 Meta 改為「待處理 · 明天12:00」，第三筆改為「待處理 · 星期五17:00」。完成後每一列都能直接讀到自己的期限。
9. 同時選取三列按 **Shift+A**，命名為 `List / Content`（清單內容），再套用規格表中的外層排列。完成後三列會依固定間距垂直排列。
10. 把清單內容放進清單畫面。完成後它會位於標題下方，長標題會讓第二列增高並把第三列推開。

短標題時，一列高度可以用一個例子理解：上下內距、標題、兩段間距、摘要與詳情線索相加會得到 120。這個算式只說明容器如何組成；當標題變成兩行，Auto height 會增加文字高度，Row 的 Hug 會跟著增高，外層 List 再重新排列後續內容。

完成後打開 Layers（圖層面板），依序展開 `List / Content`、第二個 Row 與 `Row / Title`。你應該能清楚看到「清單包列、列包文字」的階層。若第二筆文字看似在卡片上，卻是清單外的孤立圖層，下一次增加內容時它不會跟著排版；把它移回所屬 Row 才能恢復規則。

## 跟著做：測試增刪，再補空清單與詳情

這一節要主動改變資料筆數。每次修改後先觀察外層 List 怎麼重算，再決定要修 Row、List 或 Screen。

1. 複製最後一列，改成「核對本週發票」，期限改成「明天17:00」。完成後清單會增加一列，原有列不需手動移動。
2. 刪除「確認活動報名資料並補上聯絡電話」。完成後下面兩列會自動上移，列與列之間仍只有一段 Gap。
3. 復原刪除，再移除剛新增的「核對本週發票」。完成後主線會回到原本三筆資料。
4. 複製整張清單畫面，命名為 `Screen / List Empty`（空清單畫面），移除其中的所有 Row。完成後會保留畫面結構與標題。
5. 在原本清單內容的位置放入「目前沒有待處理任務」與「新任務會顯示在這裡」。完成後空畫面會交代狀態與後續預期。
6. 複製「整理交付包」那一列，把狀態改為「已完成」，並加入文字或圖示線索。完成後會得到後續完成清單可使用的版本。
7. 建立 `Screen / Detail`（任務詳情畫面），加入「← 返回清單」。完成後畫面會提供回到上一層的明確線索。
8. 在詳情內容放入「整理交付包」、任務說明與「今天18:00」。完成後這筆任務的完整資訊會集中在同一區。
9. 從 Assets 插入 Primary／Default 的 Button，Label 改為「標記完成」，命名為 `Button / Complete`（完成按鈕）。完成後詳情畫面會有清楚的主要動作。
10. 將詳情文字與按鈕包成垂直 Auto layout。完成後說明變長時，按鈕會隨內容往下排列。

增刪測試完成後，將三張畫面排在畫布上：待處理清單、空清單、任務詳情。這三張圖各回答不同問題：有資料時怎麼掃讀、沒資料時看到什麼、需要更多資訊時去哪裡。互動連線會在後面的原型階段處理，這裡先把內容與層級做完整。

## 看兩版清單，判斷哪一版經得起資料變化

這一節要從畫面差異判斷 Auto layout 的層級。版本一的三張白卡高度都固定相同，第二筆長標題只顯示第一行，第三筆仍停在原座標；刪除第二筆後，原位置留下大段空白。版本二讓每個 Row 使用 Hug，標題使用 Auto height，外層 List 也使用 Hug；第二筆變高時第三筆下移，刪除後其餘列自動補上。

請先判斷哪一版保留了完整內容，再指出「文字層、Row、List」三層各自要負責什麼。最後想像清單從三筆變成十筆，哪一版需要較少手動整理？

## 卡住時，先找內容屬於哪一層

這一節用症狀判斷修復層級。清單問題常由內層一路影響外層，因此先從文字開始，再看 Row 與 List，會比拖曳座標更快找到原因。

| 看到的現象 | 通常的原因 | 怎麼修 |
|---|---|---|
| 長標題只顯示一行 | Title 是固定高度 | 在 Layout（版面區塊）將文字設為 Auto height，寬度設 Fill |
| 標題變高但白卡沒變高 | Row 使用固定高度 | 將 Row 高度改為 Hug contents |
| 新增一列後與舊列重疊 | 新 Row 不在 List 內 | 在 Layers 把它移入 `List / Content` |
| 清單左右越縮越窄 | List 與 Row 同時留下多餘內距 | List 使用 Padding 0，內部留白交給 Row |
| 刪除最後一列仍留空白 | List 有固定高度或空佔位層 | 改成 Hug，移除不需要的空層 |
| 空清單像載入失敗 | 畫面只剩空白容器 | 加入清楚的狀態標題與後續說明 |

修完後用最長的「確認活動報名資料並補上聯絡電話」再測一次，接著刪除它。能同時通過內容變長與筆數變少，代表三層規則都在正確位置。

## 換你做：報名確認 App

現在把清單方法移到活動主辦單位。行政人員要用手機查看十二筆報名，快速掃讀姓名、備註與狀態，並能開啟張家豪的詳情；當沒有符合條件的報名時，畫面也要清楚說明空清單。

要達成的條件：

- 使用[報名資料](../assets/shared/SIGNUP-DATA.csv)製作十二筆報名清單。
- 每列至少包含姓名、備註、狀態，並使用自己的 Auto layout 容器。
- 外層清單能在新增、刪除或重新排序時自動重排。
- 用張家豪的長備註測試 Row 增高，下一列要跟著下移。
- 製作有說明文字的空清單，讓行政人員知道目前沒有符合條件的報名。
- 製作張家豪的詳情畫面，保留姓名、完整備註、狀態與主要動作。

合格的結果要能通過以下自我檢查：

- 十二筆姓名都能在清單中找到，最後一筆是劉思妤。
- 張家豪與蔡庭安的長備註完整換行，沒有蓋住下一筆。
- 刪除任一列後，下面資料會自動補上，沒有遺留空白高度。
- 空清單能分辨是「沒有資料」，而非畫面尚未完成。
- 詳情畫面只展開一筆資料，清單仍保持可掃讀。
