# 讓文字變長時，容器與按鈕一起排好
副標：工作室的登入提示可能從一行變成多行，這堂讓卡片跟著內容長高，按鈕也能維持正確間距。
本堂完成物：一張會隨文字長高的登入卡片；一組增刪內容的版面測試；一份固定寬度與填滿容器的比較紀錄

## 從對齊好的登入內容繼續

工作室的登入畫面已經有共同邊界，但真正使用時，提示文字不會永遠只有一行。密碼規則可能變長，錯誤訊息可能需要補上修正方法，之後也可能加入帳號範例。若標題、訊息與按鈕只是分別放在畫布上，文字增加時就會蓋住下一個物件。這堂要把它們組成能回應內容變化的容器。

先找出上次做好的手機登入內容區，確認卡片可用寬度已對齊格線。開啟[本堂起始材料](../assets/A3-auto-layout-pressure/START-HERE.html)，先認識這次要建立的訊息、按鈕與卡片層級；完成操作後，用[完成檢查表](../assets/A3-auto-layout-pressure/reference/EXPECTED-CHECK.html)核對長句、增刪子層與窄版測試。這些物件都留在同一份設計檔中，下一次會直接把其中的按鈕轉成共用元件。

這次會同時處理兩種變化：內容高度改變，以及容器寬度改變。前者檢查文字換行後能否推開按鈕，後者檢查畫面變窄時，子層是否能使用父容器剩餘空間。

## 先分清楚：文字長高和卡片長高是兩件事

這一節要理解不同設定作用在哪一層，因為 Auto Layout 失效時，問題通常在於設定放錯物件，而非某個數值。文字層的 Auto height 讓文字框隨著行數增加高度；父容器的 Hug contents 則讓外框包住所有子層、間距與內距。兩者一起使用，長句才會推動下面的按鈕。

Auto Layout 可以把父容器想成一個會排隊的盒子。方向設為 Vertical 時，子層由上到下排列；Gap 控制相鄰子層之間的距離；Padding 控制內容和盒子邊緣的留白。當上方文字增加一行，父容器重新計算高度，下方按鈕自然往下移。

| 設定 | 放在哪一層 | 解決的問題 | 做對時會看到 |
|---|---|---|---|
| Auto height | 文字層 | 句子換行後末尾被裁掉 | 文字框隨行數增高 |
| Vertical | 父 Auto Layout Frame | 子層各自漂在畫布上 | 訊息、提示、按鈕由上到下排列 |
| Gap | 父容器 | 相鄰內容距離不一致 | 每組相鄰子層保持同一間距 |
| Padding | 父容器 | 內容貼住卡片邊緣 | 四周留白穩定 |
| Hug contents | 父容器高度 | 卡片固定高度而裁切內容 | 卡片包住所有子層 |
| Fill container | 子層寬度 | 子層沒有使用可用空間 | 文字或按鈕填滿父容器內部 |
| Fixed | 已知尺寸的容器 | 需要穩定的外部基準 | 畫面或卡片寬度保持指定值 |

例如登入卡片寬度已由格線決定，就可以保持 Fixed；卡片高度會受訊息行數影響，因此設為 Hug contents。卡片裡的訊息和按鈕寬度則用 Fill container，讓它們使用父容器扣除左右 Padding 後的空間。當子層設為 Fill container，父層在同一方向會自動變成 Fixed，這是 Figma 用來確定可分配空間的正常結果。

層級比畫面位置更重要。兩個物件即使看起來上下相鄰，只有位於同一個 Auto Layout 父層時，內容變化才會帶動彼此。判斷時先看 Layers 的縮排，再看右側設定；這比手動拖動到漂亮位置更能證明版面真的會回應內容。

尺寸模式還要分方向判斷。同一張卡片可以在水平方向保持固定寬度，在垂直方向包住內容；訊息文字則可在水平方向填滿容器，在垂直方向隨行數長高。把「寬」和「高」分開說明，會比只記 Hug、Fill 或 Fixed 三個名稱更容易找到正確設定。

判斷時可以問兩個問題：這個物件的空間由誰提供？內容增加時誰要跟著改變？卡片寬度由手機格線提供，所以有明確基準；文字高度由句子行數決定，所以需要自動增加；按鈕位置由父容器的排列決定，所以跟在前一個子層之後。每個答案都對應一個層級和方向。

## 示範：把訊息與按鈕包進會長高的卡片

這一節會完整建立一次登入卡片。所有主線尺寸、文字與層級集中在規格表，步驟只引用名稱，方便你把注意力放在父子關係與變化結果。

| 類型 | 圖層名 | 規格 | 內容或用途 |
|---|---|---|---|
| 手機畫面 | `Screen / Login` | 402 × 874 | 登入畫面外層 |
| 畫面標題 | `Title` | 24／32 | 「登入工作室」 |
| 訊息文字 | `Message` | 16／24、W 322、Auto height | 「請輸入工作室帳號」 |
| 按鈕文字 | `Label` | 16／24 | 「登入」 |
| 練習按鈕 | `Button / Draft` | H 48、水平 Padding 16、垂直 Padding 12 | 水平排列、置中、綠底白字 |
| 登入卡片 | `Login / Card` | x 24、y 200、W 354、Padding 16、Gap 12 | Vertical、Height Hug、白底 |
| 輔助文字 | `Hint` | 14／22 | 「範例：studio@example.test」 |
| 窄版卡片 | `Login / Card 360` | W 312 | 測試畫面變窄後的換行 |

1. 在 `Screen / Login`（手機登入畫面）中建立 `Title`（畫面標題），套用規格表的標題樣式；完成後，登入畫面會保留清楚的第一層資訊。
2. 建立 `Message`（訊息文字），輸入短提示並到 Layout 把文字尺寸模式設為 **Auto height**；完成後，文字框具備隨行數增高的能力。
3. 建立 `Label`（按鈕文字），輸入「登入」後按 **Shift+A**；完成後，Figma 會新增一個包住文字的 Auto Layout Frame。

![Shift+A 後右側出現 Auto layout：Flow 方向、寬高的 Hug、Gap 與 Padding（紅框）](../assets/shared/ui/figma-auto-layout-panel.webp)

4. 把新外框命名為 `Button / Draft`（練習按鈕），依規格表設定排列、對齊、內距與顏色；完成後，白色文字會位在綠色按鈕中央。
5. 在 Layers 同時選取訊息文字與練習按鈕，再按 **Shift+A**；完成後，兩個物件會進入同一個新的 Auto Layout 父層。
6. 把父層命名為 `Login / Card`（登入卡片），依規格表設定 Vertical、Gap、Padding、寬度、Height Hug 與白底；完成後，卡片會包住訊息與按鈕。
7. 將登入卡片放到規格表的位置，再把訊息與按鈕寬度設為 **Fill container**；完成後，兩個子層會填滿卡片內側可用寬度。
8. 在 Layers 展開登入卡片，確認 `Message` 與 `Button / Draft` 是同層子物件，`Label` 則在按鈕裡；完成後，圖層縮排會清楚呈現三層關係。
9. 把訊息改成「密碼至少需要包含一個英文大寫字母與一個數字」；完成後，訊息會換行，卡片跟著長高，按鈕向下移動。
10. 把訊息改回短句，再切換一次長句；完成後，Gap、左右寬度與底部 Padding 都會保持一致。

短句測試可以用一個高度算式理解容器如何加總：上 Padding、文字高度、Gap、按鈕高度與下 Padding合起來就是卡片高度。依規格表的短句狀態，計算為 `16＋24＋12＋48＋16＝116`。文字若多一行，只替換實際文字高度；其他間距會自動維持。

## 跟著做：增刪內容，再改變容器寬度

這一節要讓卡片經過幾種常見內容壓力。提示會比示範少，請先判斷該改文字層、父容器或外層畫面，再動手設定。

1. 把訊息改成完整的帳號錯誤句，觀察換行、卡片高度與按鈕位置；完成後，三者應一起形成連續變化。
2. 在訊息和按鈕之間加入 `Hint`（帳號範例），再從 Layers 調整子層順序；完成後，卡片會增加一個文字高度與一段相鄰間距。
3. 刪除帳號範例，觀察卡片收回空間，再使用 Undo 還原；完成後，你會看到內容增刪能雙向改變容器高度。
4. 複製登入卡片作為窄版測試，縮小父容器寬度；完成後，Fill container 的訊息與按鈕會使用新的內側寬度。
5. 在窄版副本中，把訊息寬度暫時改為 Fixed，記錄它和 Fill container 在換行上的差異；完成後，再把主線卡片維持原本的寬度與填滿方式。
6. 在另一個測試副本中暫時固定卡片高度，加入長句觀察裁切；完成後，把高度恢復 Hug contents，確認內容重新完整出現。
7. 對照短句、長句、加入提示與窄版四種結果，寫下每一次真正改變的是哪一層；完成後，你會有一份可用來排查的父子層紀錄。

接著做一次連續內容測試：依序輸入短提示、完整錯誤句與更長的密碼規則，每次都只改 Message 文字。觀察卡片底部和按鈕之間的關係，並確認左右寬度維持一致。這個測試能排除「剛好只有某一句看起來正常」的情況。

再從 Layers 把提示拖到按鈕下方，觀察排列順序改變後卡片是否仍包住所有內容；完成記錄後移回原位置。這一步練習的是子層排序，讓你知道 Auto Layout 會依圖層順序排版，而非依物件原本在畫布上的座標。

## 看兩版長訊息，判斷哪一版真的能適應內容

這一節要分辨「目前看起來整齊」和「內容改變後仍能工作」。版本一把訊息、帳號範例與按鈕分別放在畫布上，短句時三者距離剛好；換成長句後，訊息壓到帳號範例，設計者再把下面兩個物件手動往下拖。版本二把三者放進垂直 Auto Layout 卡片，文字採 Auto height，卡片採 Hug contents；換成長句後，下面內容自動往下移。

請判斷哪一版適合後續重複使用，並說明「層級、尺寸模式、維護成本」各造成什麼差異。再想像新增第二段提示：哪一版能直接插入子層，哪一版每次都要重新量距離？

<details><summary>看完自己的判斷再展開</summary><p>版本二較好。物件共享垂直父層，文字與卡片分別處理自身高度，新增或刪除子層時會自動重排；版本一只能維持某個固定內容狀態，每次變動都要手動調整位置。</p></details>

## 卡住時，先找出哪一層沒有回應

這一節把現象對應到設定位置。先觀察是文字沒長高、卡片沒長高，還是子層不在正確隊伍裡，再去修改相應層級。

| 看到的現象 | 通常的原因 | 怎麼修 |
|---|---|---|
| 長句末尾被裁掉 | 文字尺寸模式仍是固定高度 | 選取文字層，到 Layout 改為 Auto height |
| 文字變高但按鈕不動 | 兩者不在同一個垂直父層 | 在 Layers 把兩者放進同一張 Auto Layout 卡片 |
| 卡片裁掉最下方內容 | 父容器高度設為 Fixed | 選取卡片，把高度改成 Hug contents |
| 新提示沒有參與排列 | 圖層在卡片外或忽略排列 | 把提示移入卡片，確認與其他子層同層 |
| 子層沒有 Fill container | 所選物件缺少 Auto Layout 父層 | 先確認父子層級，再選子層設定寬度 |
| 按鈕文字偏向一側 | 按鈕父層沒有置中 | 選取按鈕外框，檢查水平與垂直對齊 |

修復後要重新切換一次短句與長句。只有當內容變化能再次帶動卡片與按鈕，才表示修到真正原因，而非只把某一張畫面拖回好看的位置。

## 換你做：報名確認 App

現在把會回應內容的容器用在報名資料。行政人員需要在一張卡片中看見姓名、備註與狀態；一般備註很短，但張家豪的備註包含場次、交通與無障礙座位需求。請做一張報名卡片，先放入一般報名資料，再換成張家豪的長備註，確認卡片會長高並把狀態維持在正確位置。

要達成的條件：

- 姓名、備註與狀態位於同一個垂直排列的卡片中，Layers 看得出父子關係。
- 備註文字可以增加行數，卡片高度會配合內容變化。
- 一般備註與張家豪長備註共用相同 Padding、Gap 與文字規則。
- 改變卡片寬度後，備註重新換行，其他子層仍保持順序。
- 增加一段輔助資訊再移除，卡片能自動展開與收回。

合格的結果要能通過這些自我檢查：

- 張家豪的完整備註可讀，沒有蓋住狀態或超出卡片。
- Layers 中三項內容都在報名卡片內，而非只在畫布上靠近。
- 卡片變窄時沒有縮小文字，改由換行與容器高度吸收變化。
- 從長備註換回「一般報名」時，卡片會收回多餘高度。

## 把會長高的卡片交給下一個共用元件

回到工作室登入情境，你現在有一張能承受長句、提示增刪與窄版畫面的登入卡片。訊息層負責自己的換行，父容器負責包住內容，按鈕則在同一個排列中維持位置。下一次會把這顆按鈕從單一畫面中的練習物件，轉成可放到登入、詳情與確認畫面的共用來源。

完成條件：

- 登入卡片以 Vertical Auto Layout 排列訊息與按鈕。
- 訊息使用 Auto height，卡片高度使用 Hug contents。
- 長句、增加提示與改窄畫面時，內容都不重疊。
- 固定寬度與 Fill container 的比較紀錄能說明差異。

想一想：為什麼只把訊息文字設為 Auto height，仍不足以保證下面的按鈕會移動？
