## 1. 第一項：完整 App 與題目關鍵設計（B1、B2、B3、B6）

### B1：補齊缺頁
在流程圖之後、線框之前加一節「對照畫面清單，補齊還沒做的畫面」。主線示範：把需求摘要推出的畫面清單和已做畫面並排成一張表（畫面｜已有嗎｜缺什麼），主線缺的是「完成清單裡的已完成項目詳情」之類的小缺口（自擬一個合理的），說明缺頁用線框先補，下一堂再做成正式畫面。B1 原本「畫兩張線框」改成：**為缺的畫面畫線框**，並用線框回頭檢查已做畫面有沒有偏離需求。練習：學員比對自己題目的畫面清單與已做畫面，至少找出「我的紀錄」那一頁（預約＝我的預約、點餐＝訂單、會員＝點數紀錄）和題目關鍵畫面（見下）為缺頁，畫線框。

### B2：題目關鍵設計＋串成完整流程（新增兩節，放在主線跟著做之後）
**節一「三個題目各自最難的那一個畫面」**：三段短示範，每段一張規格表＋4～6 步。學員只做自己的題目，另外兩段可以只讀。

| 題目 | 關鍵畫面 | 要示範的設計決策 |
|---|---|---|
| 預約 | 選擇時段 | 日期用一排 7 天的日期鈕（橫向，可捲動）；時段用格狀小卡 10:00～18:00 每小時一格。時段卡做成元件 `Slot`，屬性 State：Available／Selected／Full／Unavailable。Full 是灰底加「額滿」文字、不可點；Unavailable 是「時間不夠」——服務超過 1 小時（`BOOKING-DATA.csv` 的 duration，例如大型犬全套 180 分鐘）時，只有後面連續空格足夠的起點能選，選中後把佔用的格都標成 Selected，並在下方顯示「10:00～13:00，共 3 小時」。用文字說明為什麼額滿要在選擇前就看得到（需求頁店主的抱怨） |
| 點餐 | 數量加減與訂單徽章 | `Stepper` 元件：減號｜數字｜加號，數量 1 時減號是 Disabled；`Badge` 元件放在頂部訂單圖示右上，數字和訂單裡的總數量一致；訂單畫面列出品項、客製選項、數量、小計與總計（用 `ORDER-DATA.csv` 的價格算）。售完品項在清單就顯示「售完」且加入鈕 Disabled |
| 會員 | 點數餘額與紀錄 | 首頁頂部 `Points / Balance` 卡片顯示目前點數（320）；兌換品卡片在點數不足時顯示「還差 N 點」並讓兌換鈕 Disabled；`Screen / Points History` 用 `MEMBER-POINTS.csv` 8 筆做清單，增加用 `Success`、扣除用 `Text` 色並帶正負號，最後一列餘額與首頁一致 |

`BOOKING-MINE.csv`（我的預約 3 筆）與 `MEMBER-POINTS.csv` 在這節第一次使用；需求頁 `../assets/shared/practice/*-BRIEF.html` 的店主說法要引用一句，說明設計在解決哪個抱怨。

**節二「把所有畫面串成一條完整流程」**：主線示範把登入→清單→詳情→確認→完成清單全部連起來後，從 Preview 起點走一遍不中斷。練習：依自己題目的畫面清單，把開頭畫面→清單→詳情→表單→確認→成功→我的紀錄全部連起來；表單用第 3 項的「模擬填寫」做法。完成標準：從起點不靠手動跳畫面走到「我的紀錄」，看到剛送出的那一筆。

### B3

## 2. 第二項：設計系統矛盾（A1、A4、A5、A6、A7、A8、B7）

- **A1 文字樣式改 5 種**，字型統一 **Noto Sans TC**（Figma 字型清單直接搜尋得到）：

| 樣式 | 字級／行高 | 字重 | 用途 |
|---|---|---|---|
| `Type / Page title` | 24／32 | Bold | 畫面標題 |
| `Type / Section title` | 18／28 | Bold | 任務名稱、頂部標題列、彈窗標題 |
| `Type / Body` | 16／24 | Regular | 內文、欄位內容 |
| `Type / Label` | 16／24 | Medium | 按鈕文字、欄位標籤 |
| `Type / Supporting` | 14／22 | Regular | 提示、錯誤說明、日期 |

  「三種文字樣式」的說法全課改成「五種」；後面各頁規格表的字級欄改寫成引用樣式名（例如 `Row / Title` 寫「套用 `Type / Section title`」）。A1 排錯表「中文顯示成方框」改成：字型改成 Noto Sans TC。
- **A1 `Disabled` 拆兩個變數**：`Disabled` #E2E8F0（停用底色）、`Disabled Text` #5F6C80（停用文字）。全課引用處同步。
- **A1 第 11 步**：寫明用 Rectangle（R）畫白色卡片區、用 Frame（F）畫按鈕底；規格表 `Login / Card` 的 H 改成固定值（取 A3 規格表的卡片高度或合理值），並加一句「下一次學 Auto layout 後會改成隨內容長高」。
- **題目與主線分開**：A1 練習寫明「為你的題目在 Variables 另建一個集合，命名為題目名稱（例如 `Booking`），變數名稱可以和 `Studio` 相同」；A4 練習寫明「在同一頁另開一個 Section，命名 `Components / 你的題目`」。課前準備說的「同一頁」不變，但畫面區分：主線放左、題目放右，各自用 Section 包起來（A1 第一次說明）。
- **A6 文字欄元件加文字屬性**：`Field` 元件集加 Text property `Label`、`Value`、`Helper`（Value 預設「請輸入」）。密碼欄不另做元件集：用同一個 `Field`，Value 改成「••••••••」，右側用 A5 學過的 Boolean 屬性 `Show icon` 放眼睛圖示（圖示可自畫圓形代替）。刪掉另建密碼欄元件集的步驟。
- **A7 任務列做成元件**：`Row / Task` 元件，Text property `Title`、`Due`，Variant 屬性 `Status`（Todo／Done）。12 筆用複製使用處再改文字完成，說明這樣比逐列重做快。練習同樣把題目的清單卡片做成元件。
- **A8 提示做成元件集**：`Toast` 元件集，Variant `Type`：Success／Warning／Error，Text property `Message`；三種提示都由它產生。
- **B7**：規格表 `Hierarchy` 改成 `Type`（與 A5 一致）。

## 3. 第三項：表單控制項規格與表單互動（A6、B2）

- **A6 加一張控制項規格表**（放在表單控制項小節開頭）：

| 元件 | 尺寸與外觀 | 狀態 |
|---|---|---|
| `Checkbox` | 方框 20×20、圓角 4、外框 `Border` 2 px；勾選時底色 `Primary`、內放 `Icon / Check`（線條白色）；整列最小高度 44 | Checked true／false |
| `Radio` | 圓 20×20、外框 2 px；選取時內點 10×10 `Primary` | Selected true／false |
| `Toggle` | 44×24、圓角 12；圓鈕 20×20；On 底色 `Primary`、Off 底色 `Border` | On true／false |
| `Select` | 沿用 `Field` 外框，右側放向下箭頭（可用 `Icon / Chevron Right` 旋轉 90 度）；展開時下方接一個選項清單，每列高 44 | Open true／false |
| `Field / Multiline` | 寬同 `Field`、高 96，文字 Auto height 但外框固定，用於備註 | Default／Focus／Error |

- **A6 修正**：「44×44 的 Auto Layout Frame」改成「最小高度 44 的水平 Auto layout，放勾選框與文字」；第 1 步「在 `Screen / Login` 內建立垂直 Auto layout」改成先放入欄位與按鈕，再全選按 Shift+A。
- **A6 新增示範**：必填欄位在標籤後加「＊」與一句說明「標＊為必填」；「開關打開才出現的欄位」做成兩張畫面（開關 Off 一張、On 一張多一個欄位），下一次做原型時用 Change to 或 Navigate 切換。
- **B2 新增「讓表單在原型裡動起來」**（放在 Hover／Pressed 那節之後）：
  1. 勾選、單選、開關：在元件的 Checked false Variant 加 On click → Change to Checked true，反過來也加一條；Preview 點了就會切換，所有使用處自動有效。
  2. 模擬填寫：Figma 原型不能真的打字。做法是準備「已填寫」的同一張畫面（欄位 Value 改成範例內容），在空白畫面的欄位上加 On click → Navigate to 已填畫面（動畫 Instant），看起來就像填好了。說明這是原型的常見做法。
  3. 開關打開才出現的欄位：Toggle 點下時 Navigate to 開關 On 的那張畫面。
- **B2 修正**：Hover／Pressed 表格刪掉 Mouse leave、Mouse up 兩列，改寫一句：While hovering、While pressing 放開後會自動回到原本的 Variant，不需要另設返回。

## 5. 第五項：B6 測試證據與排程

- **觀察紀錄素材**：另寫 `round3/B6-observations.md`（PM 會轉成素材頁 `../assets/B6-prototype-task-test/reference/OBSERVATIONS.html`）。內容：主線「完成一筆任務」的三份虛構觀察紀錄（使用者 A、B、C，各有背景一句），每份是逐步表格：步驟｜畫面｜做了什麼｜說了什麼（放聲思考原句）｜停頓秒數｜備註。三份合計要能找出至少 5 個問題，其中至少 1 個「做不下去」、2 個「容易誤會」、2 個「小問題」，且至少一個問題是三人中只有一人遇到（教學生判斷頻率）。不要寫出答案；答案放在 B6 正文的 `<details>`。詞彙避開「受測者」「他人」「別人」，一律稱「使用者 A」等。
- **B6 正文新增一節「讀三份觀察紀錄，練習找問題與分級」**（放在走查之前）：學員讀完三份紀錄，列出問題、標出幾人遇到、分級，再展開 details 對照。說明這和自己的測試怎麼互補：紀錄練的是看出別人的誤解，自己的測試練的是走完整條任務。
- **B6 排程**：加一張時段表（以一堂 6 小時、主線＋題目兩條流程為例）：寫計畫與任務卡 → 主線走查 → 題目走查 → 讀觀察紀錄（此時主線已隔開超過一小時）→ 主線任務測試 → 題目任務測試 → 分級與修正 → 重測與評分。每段標建議分鐘數，加總 360。說明一小時間隔用來做另一條流程的工作。
- **B6 檢查方法**：評分前怎麼查——選整張畫面看右側 **Selection colors**，沒套變數的顏色會顯示色碼而非變數名；選文字看 Typography 是否顯示樣式名；選 Auto layout 看 Gap、Padding 是否顯示變數名。（介面名稱 Selection colors 已實機確認存在。）
- **評分表**：PM 依本檔重寫 CAPSTONE-SCORE，新增兩項「解決需求」（預約：額滿與時間不夠在選擇前就看得出且不能選、大型犬佔多時段清楚顯示；點餐：售完在加入前看得出、數量與徽章一致；會員：點數不足在兌換前看得出並說差多少、紀錄增減與餘額一致）。B6 正文提到評分表時要提這兩項。
