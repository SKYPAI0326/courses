# uiux-designer 改寫規格書

發包人：產品經理（Claude Opus 5.5）。承作：GPT-5.6 Sol（high）。日期：2026-11-02。
大綱方向已由課程負責人確認（`outline-draft.md`）。本檔與課程資料夾其他規範衝突時，以本檔為準。
本課是 **Figma UI 設計技能課**，不是 AI 課：不要加入任何 AI 工具或提示詞。

---

## 1. 讀者與目標

- 學員：零設計、零程式基礎的成人，第一次打開 Figma。每堂 4～7 小時（B8 13 小時），講師現場示範，但講義必須讓缺課的人能自己讀懂跟做。
- 兩個要修的問題：
  1. **不說人話**：現稿像查核清單，一句塞一個指令加三四個數字和英文圖層名，段落之間沒有接續，充滿寫給稽核者的防禦語。
  2. **脫離現況**：介面名稱與路徑沒對照現行 Figma，有 8 處照做會做不出來。第 5 節是逐條裁定，**一律照第 5 節寫**，不要沿用現稿說法。
- 第三個目標：**內容要撐得起時數**。現稿每堂實際只有 2～3 小時的活動。本輪加「練習線」與「看圖判斷」，每頁目標 5,000～7,000 字（不含頁尾自我檢查與事實核對）；B8 目標 7,000～9,000 字。

## 2. 每頁骨架（固定順序）

```
# 頁面標題
副標：一句話，寫這堂要解決的工作情境
本堂完成物：第一項；第二項；第三項（2～3 項，用看得見的結果描述，不寫數值）

## （接上次）小節名自訂
## （觀念）小節名自訂
## （示範）小節名自訂
## （跟著做）小節名自訂
## （看圖判斷）小節名自訂
## （卡住時）小節名自訂
## 換你做：報名確認 App
## （收尾）小節名自訂
## 本堂查證來源
## 自我檢查
## 事實核對
```

括號是用途，不是小節名。小節名用學員聽得懂的話，例如「從上次的登入畫面接著做」「先想清楚：格線只是對齊參考」「看兩版清單，判斷哪一版好讀」。

各區塊寫法：

1. **第一個 `##` 之前只放三行**：`# 標題`、`副標：…`、`本堂完成物：…；…；…`。
2. **接上次**：第一段寫工作情境（誰要用、遇到什麼問題）。第二段說這堂要用到上次的哪個成果，用內容稱呼（「上次做好的登入卡片」）。同一段自然帶出本堂兩個連結：起始材料 `../assets/<單元資料夾>/START-HERE.html` 與完成檢查表 `../assets/<單元資料夾>/reference/EXPECTED-CHECK.html`（B6、B7 的檢查表檔名見第 4 節）。不要寫「先開啟本堂起始材料（HTML），讀取輸入與圖層名稱」這種樣板句。
3. **觀念**：先說這個功能解決什麼問題、不用會怎樣，再說怎麼判斷用得對。可以用比較表。至少一個「例如」。
4. **示範**：開頭放一張「本堂規格表」（Markdown 表格），集中列出本節要用的圖層名、尺寸、間距、字級。步驟用有序清單，**每步一個動作＋做完會看到什麼**；步驟裡引用表中的名稱，不要一句塞三個以上數字。
5. **跟著做**：提示比示範少。每步先說要達成什麼，讓學員自己找設定位置；必要時在步驟末尾用一句提示位置。
6. **看圖判斷**（新增）：用文字描述兩個版本（版本一、版本二）的畫面差異，請學員判斷哪一版較好、理由是什麼；理由收在 `<details>` 裡。題目要扣緊本堂觀念，不需要另做圖。
7. **卡住時**：三欄表格「看到的現象｜通常的原因｜怎麼修」，4～6 列。
8. **換你做：報名確認 App**（練習線，第 3 節）：只給情境、要達成的條件（清單）、合格的結果要能通過的自我檢查（清單）。**不給步驟、不給數值答案**。需要時在最後放 `<details><summary>真的卡住再看：提示</summary><p>…</p></details>`，提示只指方向（「先檢查是哪一層設了 Fixed」），不寫完整答案。
9. **收尾**：一段話收回本堂成果，再一段話說下一堂會拿這些成果做什麼（用內容稱呼下一堂）。最後放「想一想」一題，答案收在 `<details>`。完成條件清單也放這裡（3～4 項，與「本堂完成物」對應）。
10. **本堂查證來源**：清單，每項 `[說明](官方網址)`，網址只用第 5 節列出的官方頁。最後一行「來源查證：2026-11-02。」
11. **自我檢查**、**事實核對**：見第 7 節，只給 PM 看，不會進網頁。

`<details>` 一律單行寫成 `<details><summary>…</summary><p>…</p></details>`，內文是純文字（不要 Markdown、不要換行）。

## 5. 平台事實裁定（照寫，不要沿用現稿）

證據：`platform-figma-design.md`、`platform-figma-prototype.md`、`platform-git-pages.md`。凡下表標「以畫面為準」的，寫法是「…（介面名稱以你看到的畫面為準）」，每個小節最多一次，不要寫成兩條路徑的備援。

### 通用

- 介面名稱寫 Figma 英文原名，第一次出現附中文解釋，例如「Typography（文字設定區）」。之後只用英文原名或中文其中一種，不要每次並列。
- 不寫新舊名並列（不要「Layout guides／Layout grid」）。
- Figma 會自動儲存；不要叫學員等同步狀態。
- 本課作品全部放在**同一個檔案的同一頁**（Starter 方案設計檔有頁數上限）。

### Part A

| 主題 | 裁定 |
|---|---|
| 建立設計檔 | 在檔案首頁進入 Drafts（草稿），右上點 **+ Create**，選 **Design**。不要選 FigJam、Slides、Sites、Buzz 或 Make。Starter 方案的草稿不限數量 |
| 文字設定 | 右側 **Typography** 區塊設字型、字級、行高、字重。建立文字樣式：Typography 區塊的樣式圖示 → **Create style** |
| 文字長高 | 文字尺寸模式（Auto width／Auto height／Fixed size）在右側 **Layout** 區塊 |
| 格線 | 選取 Frame，在右側點 **Add layout guide**（只有 Frame 能加）。新增後預設是 **Uniform grid**，從類型下拉改成 **Columns**。顯示或隱藏格線按 **Shift+G**。提醒：Auto layout 裡也有一個「Grid」選項，是另一個功能，本堂不用 |
| Hug 與 Fill | 子層設 Fill container 後，父層在同一方向會自動變成 Fixed。不要寫「互相等待的衝突」 |
| 圓角 | Shift+A 包出的 Frame 預設圓角是 0。A4 示範：主元件先設圓角 8，改成 16 觀察兩個使用處同步，再改回 8。全課按鈕、卡片、彈窗圓角都是 8 |
| 插入使用處 | 從左側 **Assets** 拖曳元件到畫面；或按 **Shift+I** 快速插入；或複製一個已有的使用處。**沒有**右鍵 Create instance |
| 重設覆寫 | 選使用處，右側 **Reset → Reset all changes**；也可只重設單一屬性 |
| 回到主元件 | 選使用處，右側 **Go to main component** |
| Variant | 同時選四個主元件，右側 **Combine as variants**。新增第二個屬性：Properties 區塊的 **Add property** 旁新增鈕 → **Variant**。組合重複時 Figma 會標示衝突（警告文字以畫面為準） |
| 文字屬性 | 選元件集，右側 **Properties** 區塊新增 → **Text** → 填名稱 Label 與預設值「登入」→ **Create property**。接著逐一選各 Variant 裡的文字層，在文字內容欄的 **Apply variable/property** 綁定 Label。完成後，選使用處可直接在右側改 Label |
| 快捷鍵 | F 畫 Frame、T 文字、R 矩形、Shift+A 加 Auto layout、Shift+I 插入元件、Shift+G 格線 |

| 多動作 | 同一個觸發疊多個動作、條件判斷、變數，只開放付費方案。本課每個熱區只做一個動作，Starter 就夠 |
| 返回 | 用 Navigate to 指定清單畫面最穩；Back 依瀏覽紀錄返回，從中間畫面開始預覽時可能沒反應 |
| B2 故障練習 | 把「整理交付包」那列的目的地故意改成第二筆的詳情，預覽時會看到錯的內容；照「熱區對嗎 → 觸發對嗎 → 動作對嗎 → 目的地對嗎 → 起點對嗎」排查，改回後從登入重跑。不要用 Destination None |

| B3 動畫分支起點 | 把 Before 連到 After 時 Figma 會自動建立新流程，把它改名為「狀態動畫」 |
| Overlay | Open overlay／Close overlay／Swap overlay。位置選項：Centered、Top left、Top center、Top right、Bottom left、Bottom center、Bottom right、Manual。**Manual 是相對觸發按鈕的偏移，不是畫面座標**；選單用 **Top right**，底部面板用 **Bottom center**。Close when clicking outside 可勾選。背景遮罩可設顏色與透明度 |
| Swap | 只有從已開啟的彈層內觸發 Swap overlay，才會在原位置換成另一個彈層；從一般畫面觸發，效果接近整頁切換。Swap 不寫入返回紀錄，所以不要用 Back 回上一個彈層 |
| 捲動 | 選最外層畫面 → Prototype 分頁 → **Scroll behavior** → **Overflow**：No scrolling／Horizontal／Vertical／Both directions。外框保持手機高度並開 Clip content，內容超出才會捲 |
| 固定 | 同一區的 **Position**：Scroll with parent／Fixed／Sticky。設 Fixed 的物件會移到其他圖層上方，Layers 會出現 Fixed 標示，這是正常的。Sticky 只在 Vertical 捲動時有效，且只在直接父層範圍內黏住。外層若是 Auto layout，固定物件先設 **Ignore auto layout** |
| 回頂按鈕 | 漂浮按鈕 On click → **Scroll to** → 目的地選 `List / Content`（捲動畫面的直接子層，下拉選得到）。不要指定 List 裡面的某一列 |
| 分享 | Starter 沒有原型分享與連結權限控制；B6 採單人測試，不需要分享 |

### B6 單人測試方法

不找別人，學員自己做三件事：

1. **寫任務卡**：只寫目標，不寫怎麼點（「找到『整理交付包』，看期限，把它標記完成」）。
2. **隔開再測**：寫完任務卡先去做別的事（至少休息一段時間，最好隔天），回來時假裝第一次使用，只看任務卡在 Preview 操作，邊做邊把想法說出來並記下：在哪裡猶豫、點錯什麼、看不懂哪個字。
3. **走查清單**：再用一張固定清單逐畫面檢查（按鈕文字有沒有動詞、目前在哪一頁看得出來嗎、錯誤有沒有說怎麼修、取消會不會回到原處、最後一筆看得到嗎）。

問題分三級：做不下去（例如連錯目的地）、做得到但容易誤會（例如確認後沒有狀態文字）、小問題（例如圓角不一致）。先修做不下去的。修完先重做受影響那一步，再從登入重跑整條任務。故障練習：先在測試紀錄寫下某一列原本的目的地，故意改錯，照紀錄找回並改回，**不需要複製檔案**。測試紀錄用 TASK-TEST-FORM；整合作品（報名 App）用 CAPSTONE-SCORE 評分，80 分以上且沒有「做不下去」的問題才算完成。

## 6. 必守規則（每條都來自現稿或前一門課的真實問題）

1. **段落要接得上**：每段第一句接住上一段（「有了格線之後，下一步是…」「這就是為什麼…」）。每個 `##` 開頭一句說這節要做什麼、為什麼現在做。
2. **一句一件事**：一句最多一個動作；一句最多兩個數值。三個以上數值進規格表。
3. **圖層名**：第一次出現寫「命名為 `Login / Card`（登入卡片）」，之後可以只用中文名或圖層名其中一種。規格表列全部圖層名。
4. **不寫堂號與代碼**：不出現「第08堂」「前堂」「T01」「S02」「TASK-01」「SCROLL-01」「MOTION-01」「A3」「B6」。跨頁引用寫內容：「做清單那一堂」「上次的確認彈窗」。主線任務用名稱稱呼（「整理交付包」「確認活動報名資料並補上聯絡電話」「更新本週任務說明」），圖層名可保留 `Row / T01` 這類命名但正文稱呼用任務名。
5. **限制語**：每個 `##` 小節正文最多一句「不要／不能／不是／不算」類句子，其餘改成正面寫法（「保留 874 的高度，讓內容超出」取代「不能把外框加高」）。
6. **刪掉寫給稽核者的話**：不出現「假裝」「待補」「PENDING」「不能宣稱」「不能據此寫成」「真人試跑」「證據」「機器 PASS」這類詞。
7. **單人可完成**：不出現同學、同伴、他人、別人、受測者、分組、講師示範時如何。全部活動一個人能做。
8. **不給答案**：「換你做」「跟著做」的數值答案（例如 360 寬的欄寬）只能出現在 `<details>` 裡；「想一想」答案同樣。
9. **每頁一個工作情境貫穿**：開頭的情境，在收尾要回來。
10. **用詞**：繁體中文、台灣用語（檔案、資料夾、預覽、登入、按鈕、畫面）。英文介面名照 Figma 原名大小寫。
11. **不加 AI**：不提 AI、Figma Make、Figma AI。
