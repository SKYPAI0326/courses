(B6) · 6 小時

用固定任務測試修正 Prototype

把「我覺得可以」改成可重跑的任務測試、最小修正與回歸證據。

學習成果
寫出另一個人能照做的任務腳本。
分類內容、結構、互動與方案限制。
只改一個主要變因，重跑同一條 B4 action。
(01)

先固定任務，再記錄修正

阿凱把 B4 的 Host 與 Overlay 交給雯姊試用。第一份測試產物要寫出角色、起始狀態、單一任務、操作與預期結果；完成後才有條件分類問題、進行最小修正與回歸。

起點：接手一條 On click → Open overlay → Dialog / Overlay；不新增第二個 action，也不把登入流程當成已完成。
(02)

四個概念

任務腳本描述誰在什麼狀態做什麼；可觀察結果是 Preview 真正顯示的內容；問題分類把現象分成內容、結構、互動、可讀性與方案限制；單一變因修正讓回歸結果有因果。

現象分類最小修正
點擊後沒有目的地互動指定 Dialog / Overlay
預覽從錯誤畫面開始結構設定 Host 為 Flow 起點
第二個 action 跳升級方案限制拆成另一份測試檔
(03)

Stage B6-1：建立測試基準

  1. 開啟 B4 Figma 檔，確認 Host、Overlay、文字與 interaction。
  2. 填入測試者「雯姊」、起始狀態「Preview 從 Host 開始」、任務「確認任務回饋」、操作「點擊 Host 一次」、預期「看到確認完成」。
  3. 實際按一次，先記錄通過或未通過，不先修正。

測試欄位：case_id、starting_state、task、expected、actual、severity、root_cause、repair、rerun_result、evidence_path。

(04)

Stage B6-2：同步演練與 Checkpoint

步驟模式結果／修復
1Together填齊角色、起始狀態、任務、操作、預期。
2Demo從 Host 開 Preview，實際點擊一次。
3CheckpointActual 與 Expected 分開；找不到證據就標 BLOCK。
4Solo只改一個主要變因，不同時改文字、尺寸與動畫。
5Check重跑同一任務，回歸可重現才進 B7。
若 Starter 顯示多 action 限制，這是平台條件；記為 CONDITIONAL，不要按 Upgrade。
(05)

Solo 變化與回歸

把 B4 的預期文字改成「已儲存，回到任務清單」，只改內容；用同一腳本回歸。再另開一筆測試，故意把 Destination 留空，記錄為互動問題並修復。不要同時調整 Animation。

  • 通過：另一個人能照表執行。
  • 未通過：保留原始失敗證據，回到上一個可重開檔。
  • 安全停止：沒有證據就停在 Checkpoint，不刪除整個檔案。
(06)

交付檢查與自我測驗

  • 我沒有把預期答案填成 Actual。
  • 每次修正只有一個主要變因。
  • 回歸測試重跑同一條 action。
  • 我能指出方案限制與拆檔策略。

測驗：為什麼要先記錄 Actual？因為要保留原始失敗證據，才能判斷修正是否改善同一個任務。

開始前材料：B6 起始頁、測試表。完成後把回歸紀錄交給 B7。
