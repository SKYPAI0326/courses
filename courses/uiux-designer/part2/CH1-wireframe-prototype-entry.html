UI/UX 原型製作與資料打包 · B1

把一句需求拆成手機流程

工作室收到「請做一個手機服務，讓使用者登入後查看待處理清單，選一筆資料準備處理」。你會先寫任務卡與畫面清單，再建立兩個 402×874 Frame，並指定 Preview 的起始畫面。互動連結留給下一堂，這一堂先把入口做得可讀、可追溯。

完成後你會留下
TASK-01 任務卡：角色、起點、目標、限制。
SCR-01／SCR-02 畫面清單：進入條件、內容、離開條件。
兩個 402×874 手機 Frame 與 TASK-01 Login Prototype 起始點。
01 · 情境與起始材料

先把需求寫成一條可檢查的工作路徑

一句「做登入與清單」還沒有交代畫面順序、每頁的內容與開始位置。你要先回答：誰要完成什麼工作？從哪裡開始？完成一個步驟後會看見哪個畫面？

本堂承接 A8 的 Button、List、Dialog、Navigation 視覺材料。A6–A8 的完成物只在需要時沿用；本堂的學習重點是任務拆解、畫面對應與 Prototype 入口。

02 · 五個工作物

先知道每一份材料要解決哪個判斷

畫面清單讓設計與測試使用同一組名稱；Frame 呈現資訊位置；起始點讓 Preview 有固定入口。五個工作物的責任分開後，下一位工作者才能接手。

工作物用途本堂驗收證據
任務卡寫角色、起點、目標與限制。TASK-01 含登入、查看清單、選取一筆。
畫面清單把任務拆成可製作的畫面。SCR-01 Login、SCR-02 List，各有進／出條件。
Wireframe安排標題、內容與下一步線索。兩個手機 Frame 內能辨識任務。
Prototype 起始點指定 Preview 從哪個 Frame 開始。TASK-01 Login 指向 Login。
工具邊界說清楚本堂與 B2–B4 的分工。檢查表列出尚未測的 action。
手機基準：兩個 Frame 都使用 W402、H874；名稱以 Flow / 開頭。沿用 A1–A8 的規則，不在本堂重新建立視覺系統。
03 · 示範

先寫任務卡，再讓每個 Frame 有來源

示範先在檢查表建立任務，再把任務拆成兩列畫面。這樣每個 Frame 都能回指需求，不會變成孤立的畫板。

任務卡

TASK-01｜待處理清單
角色：工作室行政人員
起點：尚未登入的手機畫面
目標：找到一筆待處理資料，準備查看詳情
限制：手機寬 402px；先驗收畫面入口，不加入真實帳密

畫面清單

ID畫面名稱進入條件要看見的內容離開條件
SCR-01Flow / Login尚未登入登入、帳號、密碼、按鈕按下登入後進入清單（B2）
SCR-02Flow / List已登入清單標題、兩列資料、選取線索選取一列查看詳情（後續單元）

Frame 與起始點

  1. 建立 402×874 Frame，命名 Flow / Login，加入登入標題、帳號、密碼與主要按鈕文字。
  2. 複製 Frame，命名 Flow / List，保留尺寸，換成 A7 的 List／Title 視覺材料並加入兩筆資料。
  3. 在 Prototype 面板選取 Login，建立 Flow starting point，名稱用 TASK-01 Login。
  4. 開啟 Preview，確認第一個畫面是 Login，截圖包含 Frame 名稱、起始標記與 Preview。
Checkpoint 1

你能由檢查表說出任務起點與目標，也能在 Figma 找到兩個 402×874 Frame；Preview 從 Login 開始。

04 · 跟著做

每一步都讀取可見結果

按表格完成；只在預期結果出現後進入下一列。這一堂的檢查重點是任務、名稱、尺寸與起始點。

步驟你的操作應看到的結果沒看到時
1開啟起始材料，寫好 TASK-01。角色、起點、目標、限制都存在。逐格補寫任務卡，不先開 Prototype。
2寫 SCR-01、SCR-02。每列有進入條件、內容、離開條件。把模糊動詞改成可看見的內容。
3建立 Login Frame，W402、H874。Layers 有 Flow / Login。選外層 Frame 再設定尺寸。
4放入登入標題、帳號、密碼、按鈕文字。畫面能辨識登入任務。回 A6 檢查 Button／Form 材料。
5複製並命名 List Frame，維持尺寸。兩個 Frame 名稱不同、尺寸相同。選副本重新命名，確認父層是 Frame。
6放入清單標題與兩筆資料。畫面能辨識清單與兩列。回 A7 檢查 Row／Title 材料。
7指定 Login 為 TASK-01 Login 起始點。Prototype 面板顯示起始標記。重新選外層 Frame，再建立起始點。
8保存任務、畫面、Frame、Preview 證據。檢查表可交給 B2。補拍名稱、尺寸或 Preview 缺口。
05 · 自己改一個條件

用長標題檢查手機畫面的閱讀空間

保留流程與起始點，只修改 List 第二列標題為「本週待處理的合作申請需要補上聯絡電話」。這個修改會讓你檢查文字行數是否遮住下一步線索。

  1. 只選第二列標題，替換文字。
  2. 記錄行數、是否遮住操作線索、需要調整的層。
  3. 在畫面清單補上「長標題仍須在手機寬度內可讀」的限制。
  4. 保存修改前後截圖，交給 B2 使用。
Checkpoint 2

長標題的行數與修正點已記錄；兩個 Frame 仍為 402×874；Preview 仍從 Login 開始；檢查表保留 B2 尚未測的 action。

07 · 驗收與下一步

把畫面入口交給互動測試

B1 的成果是一組有來源的畫面入口。任務卡說明要完成什麼，畫面清單說明要經過什麼，Frame 呈現內容，起始點固定 Preview 的第一站。

  • TASK-01 含角色、起點、目標與限制。
  • SCR-01／SCR-02 與兩個 Frame 名稱對應。
  • Flow / Login、Flow / List 都是 402×874。
  • TASK-01 Login 起始點指向 Login，Preview 首畫面可辨識。
  • Solo 長標題的行數、修正點與前後截圖已保存。
  • 檢查表列出 B2 的核心 action，以及 B3–B5 的未測範圍。

檢核題 1：畫面清單與 Frame 名稱為什麼要使用同一組 ID？

答案方向：讓需求、設計、測試與交接能指向同一個畫面，不靠猜測對應。

檢核題 2：Preview 能從 Login 開始，代表登入按鈕已經可以切到 List 嗎？

答案方向：起始點只證明 Preview 入口；按鈕 action 要在 B2 設定、預覽與記錄。

請保留任務卡、畫面清單、兩個 Frame、起始點截圖與完成檢查表。下一堂會使用這些名稱建立一個核心互動，請進入第 10 堂：觸發事件與互動連結。
