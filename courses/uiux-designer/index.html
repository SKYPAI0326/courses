給第一次做介面的你

把一個手機介面，做成可以測試、交接、繼續開發的作品

你接到一個看似簡單的需求：做出一個手機服務畫面。你要處理長文字、按鈕狀態、彈窗與任務測試，最後讓別人拿到檔案就能繼續做。這門課帶你從介面規則走到可交付的原型與最小網站。

總時數 99h
主要工具 Figma + Chrome
最後留下 原型、測試紀錄、交付包、網站

你會解決哪一種工作問題？

這門課把焦點放在一條完整工作路徑：把需求整理成畫面規則，做出原型，實際測試，再整理成可交接成果。

課程情境 · 一個小型手機服務任務

客戶只給你一句「請做一個登入與內容列表」。你要自己補出畫面規則，處理錯誤與長文字，讓使用者完成一個任務，再把設計檔、輸出素材和網頁原始檔整理給下一位工作者。

學完後，你會走完三段路

01

先建立設計規則

用色彩、字型、格線、Auto Layout 與元件，讓畫面在文字變長、項目增減時仍然穩定。

02

再做成可操作原型

把畫面串成任務流程，加入按鈕回饋、Overlay、滾動與狀態，並用固定任務測試找出問題。

03

最後整理成可交付成果

輸出 PNG／PDF、留下 Inspect 與測試紀錄，再用最小 HTML／CSS／JavaScript 和 Git 保存可接手的版本。

這門課最後會留下什麼？

每一段練習都會留下下一段可以接手的材料；你會同時練習說明、測試與交付。

F

Figma 原型檔

手機 Frame、元件／狀態、畫面與一條可在 Preview 執行的核心互動。

測

任務測試紀錄

任務腳本、Actual／Expected、問題分類、修正與回歸結果。

交

設計交付包

PNG／PDF、Inspect 資訊、命名與限制清單，讓下一位工作者知道怎麼接手。

網

最小網站與版本紀錄

可在 Chrome 開啟的 HTML／CSS／JavaScript，以及可回復的 Git 變更紀錄。

完整學習路徑

行政課程分成兩段，學習上會以前一段的完成物推動下一段；每個單元都會有示範、跟做、變化練習與檢查點。

Part A｜介面元素與設計

42 小時

先讓你能做出一致、可維護、經得起內容變化的介面。

  1. A1–A2 色彩、字型、格線與版面基準
  2. A3 Auto Layout 與內容壓力
  3. A4–A5 Component、Instance、Variants 與 Properties
  4. A6–A8 Button、Form、List、Toast、Dialog、Navigation

Part B｜原型製作與資料打包

57 小時

再把靜態畫面變成可測試、可交接、可延續的工作成果。

  1. B1–B3 線框、原型入口、觸發與轉場
  2. B4–B5 Overlay、Swap、滾動、置頂與漂浮按鈕
  3. B6–B7 任務測試、修正、輸出與 Handoff
  4. B8 最小網站、Git／GitHub 與部署

現在可以從哪裡開始？

目前公開的是一條代表性試點路徑

完整的零基礎順序應從 A1 → A2 → A3 開始；A1、A2 尚在製作，所以目前先提供 A3 → B4 → B6 → B7 → B8 的 33 小時機器試點，讓你看見成果如何從介面規則走到交付。A3 適合用來閱讀流程與測試工具，尚未取代完整的零基礎起點。

使用工具的現實限制：這條試學路徑以 Figma Starter 免費方案和瀏覽器為前提，因此每個測試檔先完成一個核心 Prototype action；需要多步驟互動時，課程會說明拆檔或升級方案的差異。Photoshop、GitHub push、公開部署與真人完整跟做，仍需通過後續驗證後才會標示為正式完成。
