14.5 小時 · 雲端到本機的完整路徑

個人自動化工作流：
Make × n8n 雲地協作實戰

先把工作說清楚，再決定哪一段交給雲端、哪一段留在自己的電腦。

這是一條連續的學習路徑。你先在 Make 建立資料契約、測試與交接材料，再經過 Bridge 把同一份規格轉成 n8n 可以理解的節點與資料引用，最後處理本機檔案與雲地協作。每一階段都有獨立完成物，下一階段只承接已完成的成果。

01 · 先建立共同語言Make 先完成設計與驗收

從工作需求、輸入輸出欄位、控制條件到測試紀錄，先留下下一位接手者看得懂的規格。

02 · 再做平台轉譯同一份契約帶進 n8n

Bridge 會對照 Bundle／Item、Filter／If、Router／分支與錯誤出口，指出哪些欄位與邏輯需要重新驗證。

03 · 最後處理本機責任雲地分工有邊界

n8n 補上本機檔案與批次處理能力，同時把 Docker、權限、備份、API 與資料離開本機的責任寫清楚。

跨平台共同產物

每階段都能驗收
workflow-spec-v1

寫清楚目的、模組責任、控制條件與人工出口，作為 n8n 重建的範圍界線。

contract-input-v1

定義來源欄位、型別、必填與缺值處理，讓雲端與本機輸入可以逐欄對照。

contract-output-v1

固定處理模組的輸出欄位與下游用途，避免平台轉換後資料形狀悄悄改變。

mapping-v1

記錄來源欄位到處理模組的映射，並標出轉成 n8n Expression 後必須重測的路徑。

test-cases-v1

固定成功、需要人工、資料缺值三種條件，在兩個平台重跑並分開保存證據。

handoff-pack-v1

彙整原版與轉譯版規格、測試證據、限制、還原方式與下一位接手者的最短驗證路徑。

觸發與資料來源表單、Webhook、Google Workspace 等雲端訊號Manual／Webhook／Schedule 或掛載資料夾來源位置、認證方式、資料是否離開本機
資料單位BundleItem一筆是否變多筆、批次邊界與欄位路徑
條件控制Filter／RouterIf／Switch／分支未匹配資料、人工出口與停止位置
檔案處理雲端檔案服務與文件交付可讀寫已掛載的本機檔案與資料夾權限、路徑、備份、重跑與環境差異

證據狀態：已在平台實跑的結果標為 MAKE 或 N8N；固定輸出與離線演練標為 SIMULATED；尚未完成的項目標為 NOT_RUN。三種狀態不可互相代替。
