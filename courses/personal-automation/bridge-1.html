BRIDGE-1 · MAKE → N8N

把 Make 成果轉成 n8n 的平台地圖

你已在 Make 留下一份客戶回饋流程。現在先不急著建立節點，跟著一筆資料看清楚欄位、條件、停止位置與證據，再把同一份契約帶進 n8n。

前置條件
完成 Make CH1-1～CH1-6，或取得 Make 交接包
本節時間
30 分鐘；可閱讀、填表與完成三案例演練
完成物
platform-map-v1＋A／B／C 測試紀錄
證據邊界：本頁使用去敏資料與固定 fixture。候選 n8n fixture 標為 DRAFT_IMPORT_CANDIDATE；未在你的工作區執行前，結果只能標為 SIMULATED 或 NOT_RUN。
(01)　先知道自己要解決什麼

同一份工作，換平台後仍要守住責任

情境
阿凱在 Make 讀取一列客戶回饋，交給 AI 整理，再決定是否交給文件或人工處理。團隊希望把部分批次工作放到本機 n8n；這個決定要先確認「欄位與條件是否仍然成立」，再檢查平台畫面上的模組差異。

若只把 Make 的模組名稱換成 n8n 的節點名稱，容易遺漏資料形狀、條件不通過時的終態，以及哪個平台真的執行過。Bridge-1 的工作是把已完成的 Make 交接包整理成一張下一位同事看得懂的地圖，讓下一節能從明確欄位開始建立 n8n Expression 與 If。

輸入：Make 交接包

來源欄位、契約欄位、AI 輸出、Filter 條件與測試紀錄。

輸出：platform-map-v1

同一筆資料在 Make 與 n8n 的責任對照、差異、重測項目與證據狀態。

(02)　準備材料與共同語言

先開檔案，再開始填地圖

請依序開啟下列材料。每個連結都指向課程實際提供的檔案；若你只有列印版，請在交接包註明「由教師提供，未直接讀取原檔」。

材料用途證據提醒
CH1-1-reference-4module.sanitized.blueprint.json觀察原始四模組的資料流與位置鍵。結構參考；不能當作契約版實跑。
CH1-1-import-map.md對照原始位置鍵與下游欄位。只有表格時，記錄未直接讀取 Blueprint。
CH1-2-contract-input-template.md、mapping-template固定共同輸入欄位與映射格式。缺檔時使用本頁示範，仍標示限制。
CH1-3-gemini-output-fixtures.json重跑 A／B／C 的固定輸出。固定輸出是 SIMULATED。
platform-map-v1.md本節完成物的欄位順序與交接格式。請建立副本，不覆寫原模板。
m4-bridge-contract-fixture.json比較 n8n 候選流程結構。DRAFT_IMPORT_CANDIDATE；匯入與執行需另驗證。

三個名詞先對齊

資料契約是下一步可以放心接手的欄位、型別與條件。Bundle／Item都能承載單筆資料，但引用語法與批次邊界不同。終態是本次流程的明確結束狀態：通過、待人工或契約錯誤停止。

(04)　跟著做

七步完成你的 platform-map-v1

下面每一步都沿用剛才的林小姐案例。先完成當步的快速檢查，再往下走；後面的判斷會讀取前面留下的值。

B1｜確認版本與證據

複製 platform-map-v1.md，檔名改為 platform-map-v1-你的姓名.md。開頭填入「source version = contract-driven CH1-3 fixture」與「evidence mode = SIMULATED」。

看見
檔案開頭能辨認契約版模擬轉譯。
檢查
沒有把原始四模組畫面寫成 Make 執行紀錄。
卡住
回到材料表找固定 fixture；不要請 AI 另生一份輸出。

B2｜填三個欄位映射

新增 customer_name → customer_identity、feedback → message_text、rating → urgency_signal 三列，寫出示範值、型別、不可空白規則與限制。不要新增沒有來源的 owner_email。

看見
接手者能從共同欄位反查原始欄位與值。
檢查
rating 備註寫著「代理訊號，正式規則待業務定義」。
卡住
看到 {{1.`1`}} 時，回到本頁示範；那是 Make 位置鍵。
Checkpoint B2｜資料契約閉合
三個共同欄位都有來源、值、型別與缺值處理；沒有來源的欄位標為未提供。通過後才寫控制條件。

B3｜記錄 AI 輸出

從固定 fixture 複製案例 A 的 summary、reply_draft、needs_review=true，保留欄位名稱與型別，並說明它們如何讓下一步做路由判斷。

看見
輸出區有完整三欄 JSON。
檢查
needs_review 必須是布林；文字值要列為型別錯誤。
卡住
只有 result 時，回到契約版 fixture，不要混用原始參考版。

B4｜寫清楚控制與停止出口

在地圖新增控制列：布林 false 才能進交付；true 停在待人工；文字 "false" 進契約錯誤停止。記下每條路徑的負責人與重跑位置。

看見
A 不建立 Docs；B 可交付；C 不猜測型別。
檢查
每個終態都有停止原因或下一步。
卡住
回看示範流程圖，逐條填入 A／B／C。

B5｜比較責任，不比較按鈕

完成 Scenario／Workflow、Module／Node、Bundle／Item、Mapping／Expression、Filter／If 五列。每列補一個本案例差異與一項重測。

看見
讀者知道下一節先建立 Expression，再建立 If。
檢查
至少一列指出相同責任不代表相同路徑或錯誤行為。
卡住
將尚未實跑的 n8n 內容標成「規格草稿」。
Checkpoint B5｜平台地圖可交接
版本、證據、三欄輸入、A／B／C 終態與五項責任差異都可被另一位讀者找到。缺一項就回到對應 Stage。

B6｜變化練習：只換輸入入口

把來源想像成 Make Webhook，傳入同樣三個共同欄位；契約、AI 輸出、needs_review 與 A／B／C 測試保持不變。記錄要重測的欄位路徑、缺值、型別與認證。

看見
地圖能指出來源變了，契約與下游責任仍要固定。
檢查
至少列出三個重測位置。
卡住
不要現在建立 Webhook；先寫轉譯紀錄四欄。

B7｜封裝交接

將你的地圖、來源版本、A／B／C 測試紀錄與 Make 證據放入同一交接資料夾。沒有工作區時使用固定 fixture，檔名與內容標記 SIMULATED，不要填假的 URL 或 execution ID。

看見
下一位接手者知道資料來源、停止點、重跑位置與未驗證部分。
檢查
交接說明寫出下一節要從哪個欄位開始。
卡住
刪除虛構 ID，改記錄固定 placeholder 與限制。
(05)　用三個案例驗收

同一份契約，三種可觀察終態

每次只改變主要條件，完成後在地圖記錄 evidence mode。固定輸出能檢查規則，不能代替平台執行紀錄。

案例輸入／條件預期終態記錄
A｜需要人工needs_review=truemanual_review；不建立文件SIMULATED、停止原因、人工接手與重跑位置
B｜通過needs_review=falseready_for_delivery；可交給後續節點MAKE 或 SIMULATED，不可混用
C｜型別錯誤needs_review="false"contract_error_stop；不進下游錯誤欄位、未執行下游、修正後重跑方式

變更練習

把人工判斷門檻從 3 改成 4，先在地圖寫出受影響的欄位、Filter／If、A／B／C 預期，再決定是否到平台重跑。尚未執行就標為 NOT_RUN。

(06)　交接與下一步

交給 n8n 前，確認地圖能回答七個問題

  • 一筆 Sheets 原始資料如何變成三個共同輸入欄位？
  • rating 為什麼只是本案例的代理訊號？
  • A 為什麼停在待人工，人工後從哪裡重跑？
  • C 為什麼不能把文字 "false" 猜成布林？
  • 原始四模組參考版與契約驅動測試版差在哪裡？
  • Make 與 n8n 至少有哪一個資料形狀差異需要重測？
  • 哪些內容仍是 SIMULATED、DRAFT_IMPORT_CANDIDATE 或 NOT_RUN？

七題都能回答後，將 platform-map-v1 交給 n8n 的 M1-3／M2。下一節會沿用同一組欄位建立 Expression 與 If；若輸入、控制或證據仍說不清楚，先回到缺失的 Stage 修正地圖。
