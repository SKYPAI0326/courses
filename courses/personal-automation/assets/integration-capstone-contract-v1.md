# integration-capstone-contract-v1｜跨平台個人自動化專題契約

## 專題目的

使用 Make 課程已完成的基準契約，設計一條可在雲端觸發、由 n8n 本機處理的個人工作流。案例可以是回饋整理、文件分類或批次彙整；輸入方式可替換，但契約、控制條件與驗收證據必須保持清楚。

核心路徑：

```text
雲端訊號（Make／表單／Webhook）
        ↓
n8n 接收與欄位檢查
        ↓
本機檔案或資料處理
        ↓
安全判斷：交付／停止／待人工
        ↓
Google Docs／Email 或明確的模擬輸出
```

## 必填成果

- `workflow-spec-v1`
- `contract-input-v1`
- `contract-output-v1`
- `mapping-v1`
- `platform-map-v1`
- `test-cases-v1`
- Make `scenario-v1` 或 `scenario-v1-offline-map`
- n8n workflow JSON（去除 credential）
- `handoff-pack-v1`

## 固定測試矩陣

| 案例 | 輸入條件 | 預期狀態 | 必須留下的證據 |
|---|---|---|---|
| A 成功 | 必填欄位完整、控制條件通過 | 完成本機處理並交付 | 執行 ID／輸出檔案／Docs URL；模擬路徑填固定輸出並標 `SIMULATED` |
| B 需要人工 | `needs_review=true` 或安全規則命中 | 停在人工出口，不產生未審核交付 | 停止節點、原因、負責人與重試位置 |
| C 資料缺值 | 必填欄位空白或型別錯誤 | 在來源／契約檢查停止 | 缺值欄位、未執行的下游、修正後重跑方式 |

## 平台證據規則

- `MAKE`：必須是學員自己的 Make 工作區執行紀錄，含執行 ID 或真實輸出位置。
- `N8N`：必須是學員本機 n8n 執行紀錄，含執行時間、輸入檔名／資料與輸出位置。
- `SIMULATED`：只能使用課程固定 fixture 與預期結果；不得填寫虛構 URL、執行 ID 或平台錯誤訊息。
- 同一案例若在兩平台執行，分開記錄，不以其中一平台的成功推定另一平台成功。

## 資料邊界與安全說明

在流程圖上標記：

1. 資料首次進入雲端服務的位置。
2. 呼叫 Gemini 或其他雲端 LLM 的位置。
3. 本機檔案讀寫與暫存位置。
4. 公開 Webhook／Tunnel 的驗證與可見範圍。
5. 需要人工審核、刪除或還原的位置。

## 交接者最短路徑

接手者不看課堂口頭說明，也應能依序：

1. 讀 README，確認執行模式與前置條件。
2. 讀契約與平台映射，知道每個欄位從哪裡來、要去哪裡。
3. 讀差異與限制，知道哪些行為不能直接照搬。
4. 依 A／B／C 測試矩陣執行或模擬。
5. 找到停止、重試與還原位置，並能說明資料邊界。
