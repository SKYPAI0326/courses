# 會計函式工具箱與 AI 協作歷程簡報：設計規格

日期：2026-08-20
狀態：待使用者審閱

## 1. 目標

建立兩個可離線開啟、零外部依賴的單一 HTML 檔案：

1. `accounting-calculator.html`：把常用會計公式介面化，讓使用者直接貼上 Excel 或 CSV 表格後批次計算，不需拖拉公式，也避免儲存格格式或公式位移造成錯誤。
2. `ai-development-story.html`：以實際開發問題為基礎，說明如何運用生成式 AI 輔助工作、辨識 LLM 的片面或錯誤輸出，並透過提示詞限制、測試與逐輪修正完成工具。

本工具是計算與覆核輔助，不取代會計、稅務或核准判斷。

## 2. 交付範圍

### 2.1 檔案

- `accounting-function-lab/accounting-calculator.html`
- `accounting-function-lab/ai-development-story.html`

兩檔皆使用原生 HTML、CSS、JavaScript；不使用框架、CDN、後端、外部字型或網路 API。

### 2.2 不納入第一版

- 登入、多人協作、雲端儲存與資料庫
- 直接讀寫 `.xlsx` 檔案
- 自動申報、傳票生成、科目判斷或稅務裁決
- 依企業所在地自動推測法規與稅率
- 將資料傳送給任何 LLM 或第三方服務

## 3. 應用程式設計

### 3.1 核心流程

1. 使用者選擇計算模組。
2. 應用程式顯示該模組需要的欄位與可複製的表頭範例。
3. 使用者從 Excel 複製資料，或貼上逗號分隔 CSV／Tab 分隔 TSV。
4. 解析器顯示資料預覽，使用者將來源欄位映射到必要欄位。
5. 驗證器逐列檢查缺值、非數字、無效日期、重複表頭與不合理範圍。
6. 僅對通過驗證的資料列計算；問題列保留原值並顯示列號、欄位、原因與修正提示。
7. 結果表顯示輸入值、公式、計算結果與狀態，並可複製為 TSV 或下載 CSV。

### 3.2 計算模組

#### A. 營業稅／含稅未稅換算

- 模式：未稅轉含稅、含稅拆未稅與稅額。
- 未稅轉含稅：稅額 = 未稅金額 × 稅率；含稅金額 = 未稅金額 + 稅額。
- 含稅拆分：未稅金額 = 含稅金額 ÷（1 + 稅率）；稅額 = 含稅金額 − 未稅金額。
- 稅率由使用者明確輸入；介面可提供預設值，但不得宣稱適用所有情境。
- 公式與捨入規則在計算前顯示，使用者可選擇四捨五入到整數或指定小數位。

#### B. 毛利、淨利與損益兩平

- 毛利 = 營業收入 − 銷貨成本。
- 毛利率 = 毛利 ÷ 營業收入；收入為 0 時回報錯誤，不輸出 Infinity。
- 淨利 = 營業收入 − 銷貨成本 − 營業費用 − 其他費用 + 其他收入。
- 損益兩平銷售額 = 固定成本 ÷ 邊際貢獻率；邊際貢獻率必須大於 0。
- 各公式所需欄位分開定義，不自行把空值當 0；是否允許空值視為 0 必須由使用者明確選擇。

#### C. 折舊與攤銷

- 第一版採直線法。
- 年折舊額 =（成本 − 殘值）÷ 耐用年限。
- 可依起始日期與計算截止日期按月計算；第一版以起始月份算一個月、截止月份算一個月，累計折舊不得超過可折舊金額，且介面必須明示此規則。
- 殘值不可大於成本，耐用年限必須大於 0，截止日不可早於起始日。
- 不自動判定資產類別、耐用年限或稅法處理。

#### D. 應收／應付帳款與帳齡

- 必要欄位：項目識別、到期日、未結金額；計算基準日由使用者指定。
- 帳齡區間預設為未到期、1–30、31–60、61–90、91 天以上，並允許使用者修改區間。
- 以到期日和基準日的日數差分類；無效日期不得自動猜測。
- 輸出逐筆分類與各區間彙總，不自行判定呆帳或催收動作。

### 3.3 CSV／TSV 解析規則

- 自動比較 Tab、逗號與分號三種分隔方式，以欄數一致性選出候選，並讓使用者覆寫。
- 支援雙引號包住含分隔符的欄位，以及成對雙引號跳脫。
- 保留空白欄位；只清除欄位前後空白，不改寫欄位內容。
- 數值解析支援千分位、負號與會計括號負數；遇到貨幣符號時先標示並由使用者確認移除規則。
- 日期只接受介面明列的格式；像 `03/04/2026` 這類歧義日期必須要求使用者選擇日月順序。
- 解析結果在計算前顯示筆數、欄數、表頭與前幾列預覽。

### 3.4 錯誤處理與可追溯性

- 禁止靜默補值、靜默捨棄問題列或把 `NaN` 顯示為正常結果。
- 每個結果保留來源列號、使用公式、參數及捨入設定。
- 錯誤分為「阻止整批計算」與「僅阻止該列」；摘要顯示成功、警告、失敗數量。
- 切換模組或清除資料前要求確認，避免意外遺失貼上的資料。
- 所有運算在瀏覽器本機完成，介面明示資料不會上傳。

### 3.5 介面結構

- 左側／上方：四個計算模組切換。
- 主工作區：資料貼上、分隔符設定、欄位映射、計算參數。
- 結果區：摘要、錯誤清單、結果表、複製與下載。
- 公式說明區：顯示目前公式、欄位定義、限制與人工覆核提醒。
- 桌面與平板可完整操作；手機版以垂直流程呈現，寬表格允許區域橫向捲動。

## 4. 簡報設計

### 4.1 核心立場

簡報不是「AI 一次做完應用程式」的成果展示，而是「人如何把不可靠的生成，逐步收斂成可檢查工具」的工作紀錄。所有錯誤案例須來自實作期間真實發生或可由測試穩定重現的問題；可以濃縮對話，但不可捏造不存在的成功或失敗。

### 4.2 建議頁序

1. 問題：Excel 拖拉公式、格式漂移與錯誤不易察覺。
2. 任務：把會計函式變成可批次使用、可追溯的瀏覽器工具。
3. 第一個提示詞為何不夠：只說「做會計計算器」讓 LLM 自行補需求。
4. 語意辨識錯誤：例如把「帳齡」理解成交易日起算，或把空值自動當 0。
5. 生成片面：只做正常案例，漏掉收入為 0、負數、歧義日期、CSV 引號等邊界。
6. 網頁版 LLM 的限制：上下文長度、輸出截斷、無法可靠保留整份檔案狀態、局部修改破壞既有功能。
7. 提示詞第一次收斂：定義角色、使用情境、輸入欄位、公式與禁止事項。
8. 提示詞第二次收斂：要求先列假設、一次只改一個區塊、回報受影響功能。
9. 用測試案例對話：先給預期答案，再要求 LLM 修正程式，而非接受「看起來合理」。
10. 錯誤前後比較：模糊提示詞、錯誤輸出、診斷提示詞、修正結果。
11. 人機責任分界：AI 可生成介面與重複邏輯，人負責公式、規則、測試與核准。
12. 可重用提示詞框架與結論。

### 4.3 對話卡格式

每個案例固定呈現：

- 人的原始提示詞
- LLM 的關鍵回覆或行為摘要
- 問題症狀
- 問題根因：語意歧義、缺少限制、上下文遺失或未要求測試
- 修正版提示詞
- 可驗證的修正結果
- 仍需人工判斷的部分

簡報不得使用大段虛構逐字對話；若為整理後的內容，標示「依實際互動濃縮」。

### 4.4 提示詞框架

簡報最後提供可複用的七段式框架：

1. 角色與任務
2. 使用者情境與資料來源
3. 欄位定義與計算公式
4. 禁止自行推測的事項
5. 邊界條件與錯誤處理
6. 輸出格式與修改範圍
7. 驗收案例與預期結果

## 5. 真實 AI 協作紀錄方式

開發期間維護一份暫存的問題紀錄，至少包含：

- 使用的提示或任務描述
- LLM 初次輸出的缺陷
- 能重現缺陷的輸入資料
- 修正限制或規則
- 修正後的測試結果

簡報完成後只把必要證據內嵌進 HTML，不額外交付聊天紀錄或可能含敏感資訊的原始內容。

## 6. 視覺與互動方向

### 6.1 應用程式

- 調性：會計工作台，清楚、克制、可核對。
- 色彩：低彩度墨綠／深藍作主色，米白或淺灰背景，錯誤使用明確但不刺眼的紅色。
- 字體：使用系統可用的繁中字型堆疊，避免外部字型依賴。
- 動效：只用於步驟切換、錯誤定位與狀態回饋；支援 `prefers-reduced-motion`。

### 6.2 簡報

- 調性：開發紀錄／案例調查，不做產品廣告。
- 主要視覺：提示詞版本、對話卡、錯誤輸入輸出、測試通過狀態與決策轉折。
- 操作：上一頁、下一頁、鍵盤方向鍵、頁碼、總覽模式與全螢幕。
- 每頁只承擔一個敘事任務，程式碼只顯示與問題直接相關的片段。

## 7. 驗證策略

### 7.1 計算正確性

每個模組至少包含：

- 正常案例
- 邊界案例
- 無效輸入案例
- 人工計算得出、寫死預期值的回歸案例

測試入口內嵌於應用程式的開發／說明區，可一鍵執行並顯示通過與失敗明細。

### 7.2 解析與安全

- 驗證 CSV 引號、Tab、逗號、空欄、括號負數、千分位與歧義日期。
- 將貼上內容視為純文字，使用 `textContent` 或等價安全方法呈現，不執行其中的 HTML 或 JavaScript。
- 匯出 CSV 時處理引號與換行；避免公式注入，對以 `=`, `+`, `-`, `@` 開頭的文字欄位進行安全處理並告知使用者。

### 7.3 使用性與相容性

- Safari 與 Chromium 系瀏覽器手動走完四個模組。
- 鍵盤可操作主要控制項，輸入元件有標籤，錯誤不只靠顏色表達。
- 在窄螢幕檢查欄位映射、錯誤清單與結果表。
- 離線開啟時所有功能正常。

### 7.4 簡報驗收

- 所有對話案例能對應到實際問題或可重現測試。
- 清楚區分 LLM 回覆、人的判斷與最終驗證結果。
- 至少呈現一個語意誤解、一個片面生成、一個上下文／局部修改問題。
- 最後的提示詞框架能直接套用到另一個辦公工作情境。

## 8. 完成條件

- 兩個 HTML 均可直接雙擊離線使用。
- 四類會計計算皆能以貼上 CSV／TSV 的方式批次處理。
- 每筆結果可追溯至來源列、公式與參數。
- 問題列不被默默忽略或自動補值。
- 內建回歸案例全部通過，並留下可重跑的驗證入口。
- 簡報以真實或可重現問題呈現至少三輪「初始生成 → 發現問題 → 提示詞收斂 → 驗證」歷程。
- 簡報明確說明網頁版 LLM 的限制及人工責任邊界。
