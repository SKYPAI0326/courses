## 課程定位

教初學者使用 Make 與 Gemini，從拆解工作流、建立資料契約，到讓 LLM 協助設計、修改與除錯，完成一條可測試、可還原、可交接的自動化工作流。

本課程不把 Gmail、Google Sheets 或任何單一輸入方式設定為主軸。案例是教學素材；真正的學習目標是學員能辨識可替換的資料來源、穩定的資料契約，以及可驗證的模組與測試。

## 受眾畫像

- **職業**：行政、行銷、專案、教學工作者，或需要處理重複資料工作的知識工作者
- **技術底子**：會使用瀏覽器與基本雲端文件；不要求程式設計、API 或 JSON 先備知識
- **痛點**：不知道如何拆解自動化需求、不知道模組與欄位怎麼接、擔心 LLM 產出的 JSON 無法驗證

## 學習成果

完成課程後，學員能夠：

1. 用資料來源、資料映射、處理、控制與後續動作五個角度，讀懂一條 Make 工作流。
2. 建立資料契約與欄位映射，讓不同資料來源可以共用同一個 AI 任務。
3. 以 Google Sheets 完成 Make＋Gemini 基準流程，再將同一份契約轉用到 Gmail 來源練習。
4. 要求 LLM 先產生模組清單、欄位映射、限制條件與測試案例，再進行建置。
5. 在移除憑證的前提下，讓 LLM 協助提出 JSON 的最小修改，並執行單一變因測試與還原。
6. 完成一個可展示、可測試、可說明的工作流變體與交接紀錄。

## 教學方式：通用概念＋範例練習

每個單元都採用以下順序：

1. **通用概念**：說明可以跨工具、跨資料來源使用的設計原則。
2. **範例示範**：使用教師提供的藍圖、測試資料或逐字稿說明概念。
3. **跟做練習**：學員選擇一個範例，完成指定操作與中間檢查。
4. **產出驗收**：以工作流圖、欄位表、測試案例或變更紀錄驗收。
5. **換案例轉移**：說明更換輸入或輸出後，哪些元件維持不變、哪些需要調整。

## 6 小時單元矩陣

| 單元 | 時間 | 通用概念 | 範例練習 | 學員產出 |
|---|---:|---|---|---|
| 一、看懂工作流 | 40 分鐘 | 資料來源、映射、處理、控制、動作的共同結構 | 比較 Sheets 讀列與 Gmail 收信案例 | 工作流地圖與失敗點說明 |
| 二、建立資料契約 | 60 分鐘 | 穩定欄位、格式、必填規則與可追蹤欄位 | 將 Sheets 與 Gmail 欄位映射至同一契約 | 資料契約與欄位映射表 |
| 三、建立範例流程 | 60 分鐘 | 依任務選擇資料來源、LLM、Filter 與後續動作 | 以 Sheets 建置基準流程，再做 Gmail 來源替換判斷 | Make 路徑的可執行流程，或離線路徑的模擬流程設計 |
| 四、LLM 協同設計 | 60 分鐘 | 將需求轉成模組、欄位、限制、例外與測試 | 把模糊需求改寫為可檢查的協作提示 | 工作流設計規格 |
| 五、JSON 修改與除錯 | 60 分鐘 | 局部、單一變因、可測試、可還原 | 使用去除憑證的 JSON 片段做最小修改 | 變更紀錄、測試案例與除錯紀錄 |
| 六、變體專題與交接 | 80 分鐘 | 把設計原則轉用到新資料來源或新任務 | 將案例改造成另一種輸入或輸出 | 可展示的工作流變體與交接說明 |

## 試跑包交付規格

- 去除 credential、token、固定帳號與個資的參考 JSON
- Make Scenario 建置清單與模組順序說明
- 範例資料（CSV、測試 JSON、逐字稿或教師提供的固定輸出）
- 資料契約與欄位映射表
- LLM 協作提示範本
- JSON 最小修改前後對照
- 測試案例、預期結果與還原步驟

## G1 驗收條件

- 每個單元都能指出一個通用概念與一個具體範例。
- 範例不被寫成唯一正解；至少存在一個可替換資料來源或後續動作。
- 每個單元都有可交付的學員產物與可觀察驗收條件。
- 不以付費連接器、固定帳號或含憑證藍圖作為學習門檻。
- G1 通過後，才進入 course-designer 產出第一個代表性教案。
