(06) · CH1-6

變體專題與交接：證明你真的會轉用

從既有流程選一個可控變因完成變體，留下可展示、可測試、可還原的交接包。

學習成果
完成 variant-v1：只改一個主要變因的工作流變體。
完成 handoff-pack-v1：契約、差異、測試、限制與還原。
完成 demo-record-v1：五分鐘展示成功與安全停止／待人工路徑。
(01)

最後不是加工具，而是證明能轉用

為什麼這很重要
前五節的成果只有在能被改、被測試、被交接時才真正有用。本節保留核心契約，只改一個明確變因，讓接手者知道哪裡變了、哪些證據要重跑。

阿凱把一次處理一筆回饋改成每週彙整多筆回饋。來源、Gemini 輸出、Filter 安全條件與 Docs 交付先保持不變；批次整理是唯一主要變因。基準流程仍是 Sheets → Gemini → Filter → Docs；Gmail 只作為來源替換練習。

完成標準　variant-v1、handoff-pack-v1、demo-record-v1 三份成果可讓沒有參與課堂的人開始驗證；`MAKE` 附平台證據，`SIMULATED` 附固定輸出與預期路由，且正式版本或離線地圖不被覆寫。
先開本節材料　請先開啟 變體選擇單、變體規格模板、交接 README 模板、測試矩陣、五分鐘展示紀錄 與 固定輸出 fixture。固定輸出是離線備援，不代表實際執行成功。
(02)

變體與交接包的最低規格

變體只改一個工作條件；交接包則把目的、起始狀態、欄位、測試、限制與還原串在一起。先用「交接內容 → 可觀察證據」確認文件不是檔案堆，再判斷哪些內容保持不變、哪些一定要重新驗證。

流程結構模組與欄位映射圖

安全與限制去敏 JSON、未實作出口與不得做的事
還原原始版本、差異摘要與還原步驟

批次彙整輸入／輸出契約、人工確認出口批次整理模組、批次測試

正例：選擇批次彙整，保留 summary、reply_draft、needs_review，只增加資料集合與彙整規則；或選擇 Gmail 來源，只重做 sender、subject + body 的欄位映射。錯例：同時換來源、改 prompt、刪 Filter、加入額外動作，最後無法知道哪個變更造成結果不同。

判斷方式　Gmail 變體只改來源映射與相關測試；既有的 Gemini、Filter、Docs 與待人工確認出口保持不變。

(04)

跟著做：選變因並建立規格

示範已把「唯一變因 → 保持不變 → 重新驗證」走過一次。現在建立自己的變體，不覆寫正式流程。

1
Together · 選擇一個變因
學員操作：從 A 批次彙整、B Gmail 來源兩個選項選一個；建立 variant-v1，寫變更目的與不變條件。
預期結果：變體只有一個主要變因，正式 scenario-v1 保持不動。
快速檢查：同學能用一句話說出變體和原版的差異。
卡住時：回到「變因／保持不變／重新驗證」三欄，先選最小範圍。
2
Together · 建立變體規格
學員操作：列出變體的模組、輸入、輸出、控制條件、未實作出口與需重新驗證項目，沿用 CH1-2 契約欄位。
預期結果：variant-v1 有完整模組表與欄位映射，不只有一句「加入批次」。
快速檢查：每個新增或移除的模組都有責任與下游影響。
卡住時：先畫原版，再標記新增、保留與移除。
3
Demo → Together · 請 LLM 找影響範圍
學員操作：把去敏原版規格、變更目的與契約貼給 LLM，要求只輸出受影響模組、需重跑測試、未知事項三張表。
預期結果：得到可審查的影響清單；未提供的連線與欄位標為需人工確認。
快速檢查：影響清單至少指出一個不變模組與一個必須重測模組。
卡住時：補上不得新增未定義欄位、不得使用 credential、不要產生完整藍圖。
Checkpoint：變體是否只改一個變因

現在應該看到：變更目的、不變條件、影響模組與重測項目一致；原版檔案沒有被覆寫。

若沒看到：退回步驟 1 或 2，刪除順手加入的工具與未經需求支持的欄位。

通過後才能繼續：接手者能判斷哪些 CH1-3 測試可沿用，哪些必須重跑。

(05)

測試、交接與展示

變體規格通過後，再建立測試與交接包；停止證據與還原步驟和成功結果同樣重要。

4
Together · 建立變體測試表
Make 路徑：設計三個案例，填輸入、預期結果、平台證據與負責人；
離線路徑：設計同三案，填固定輸出、預期路由與 SIMULATED，不填真實 URL。沿用既有待人工確認出口，不增加新的文件或通知動作。
預期結果：測試能逐案判斷建檔、停止、重試與還原。
快速檢查：Make 每案有文件 URL、待人工確認狀態或平台錯誤；離線每案有固定輸出、預期停止位置與模擬標記。
卡住時：沿用 CH1-3 的成功、人工與錯誤路徑，再把變體差異寫進輸入。
5
Together · 執行或模擬成功案例
Make 路徑：執行成功案例，保存實際輸出、文件 URL、資料筆數、執行 ID 與執行時間；
離線路徑：用固定輸出填寫預期文件內容、{{simulated_document_url}}、資料筆數與 SIMULATED，不稱為可查證文件。
預期結果：Make 成功案例有完整輸出與可查證文件；離線案例有固定輸出與預期文件內容，並寫明尚未在平台驗證。
快速檢查：Make 接手者能依紀錄重現成功條件；離線接手者能依固定輸出重建預期判斷。
卡住時：使用教師固定輸出，將實際連線問題記為限制。
6
Together · 執行或模擬停止案例
Make 路徑：執行 needs_review=true 與 message_text 空白案例，記錄平台停止模組、執行 ID、下游影響、負責人與重試／還原位置；
離線路徑：依固定輸出推演兩條出口，記錄預期停止模組與重試／還原位置，標示 SIMULATED。
預期結果：needs_review=true 案例停在 CH1-3 的待人工確認出口，不建立文件；缺值案例仍停止在來源檢查。
快速檢查：Make 交接者能指出平台狀態；離線交接者能指出預期狀態，且不把它當成已完成的 Make 執行。
卡住時：回看 CH1-2 失敗處理表與 CH1-5 diff log。
Checkpoint：測試與交接是否閉合

現在應該看到：每個變更有至少一個測試；`MAKE` 有執行 ID／URL／平台停止訊息，`SIMULATED` 有固定輸出／預期路由／模擬標記；每個失敗有負責人與還原位置。

若沒看到：回到步驟 4～6 補測試或修正紀錄，不要先寫展示稿。

通過後才能繼續：handoff-pack-v1 能讓未參與課堂的人開始驗證。

7
Solo · 整理交接包
學員操作：建立 handoff-pack-v1，放入 README、variant-v1、契約與映射、blueprint-safe、diff-log、test-cases、限制與還原說明；檔名與版本一致。
預期結果：接手者可依 README 找到起始狀態、操作順序、預期結果與修復方式。
快速檢查：移除口頭說明後，另一個人仍能依文件開始。
卡住時：用「先讀 README → 看契約 → 看差異 → 跑測試 → 查還原」五步補齊。
8
Check · 寫五分鐘展示腳本
學員操作：先在 demo-record-v1 寫明執行模式，再依序寫需求、原版、唯一變因、操作、成功／停止結果、限制與下一步；`SIMULATED` 段落指向固定輸出與預期路由，`MAKE` 段落指向平台證據。
預期結果：五分鐘內可展示一條成功路徑與一條安全停止或待人工路徑。
快速檢查：每個結論都有文件、欄位、URL 或測試紀錄證據；沒有平台證據就標示尚未驗證。
卡住時：刪除背景口號，只保留「問題 → 改變 → 操作 → 結果 → 證據」。
變化練習　若原本做批次彙整，改成 Gmail 來源；若原本做 Gmail，改成批次彙整。只保留原有契約與控制條件，列出新的來源映射或批次規則，以及必須重跑的三個測試，不重寫整個交接包。

完成驗證

  • variant-v1 只改一個主要變因，並列出不變條件與重新驗證項目。
  • handoff-pack-v1 包含 README、契約／映射、去敏 JSON、diff log、測試與還原。
  • 測試涵蓋成功、需要人工、資料缺值三條路徑；`MAKE` 有平台證據，`SIMULATED` 有固定輸出與預期路由。
  • 交接紀錄說明資料來源、輸入／輸出、控制條件、負責人與既有人工出口。
  • demo-record-v1 可在五分鐘內展示一次成功與一次安全停止／待人工路徑。
  • 正式原版檔案保持不變，變體未使用 credential、token、固定帳號或個資。
(06)

常見錯誤：交接不是把檔案丟出去

三個錯誤都會讓變體看似完成，卻無法被別人重做。

同時改太多東西

現象：來源、prompt、資料格式與額外動作一起變。

修正：只保留一個主要變因，其他變更另開版本。

交接包只放 JSON

現象：接手者不知道起始狀態、測試與限制。

修正：用 README 串起契約、diff、測試與還原。

展示只講成功

現象：觀眾看不到安全出口。

修正：固定展示一條成功與一條停止／待人工路徑。

(07)

檢核題：用交接證據說明成果

最後用兩題確認你能從成果與證據判斷可交接性，而不是只看畫面是否漂亮。

Q1：哪一項最能證明工作流變體可交接？
顯示答案與理由
正確答案：B。交接需要可重現的文件與證據，不是只有展示畫面；若選 Gmail，則只需驗證來源映射；其他模組與人工出口保持不變。
Q2：變體只改來源為 Gmail，哪些內容必須重新驗證？
顯示答案與理由
正確答案：B。來源替換影響輸入映射，但不應無理由破壞既有輸出與控制契約。
(08)

試跑包：把成果帶回工作

本節不需要新的付費工具。使用前五節的去敏檔案、固定輸出與測試資料即可完成變體、交接與展示；選批次彙整時，三筆輸入、模組卡與中間輸出是必要材料。

選擇與規格

開啟變體選擇單，再用規格模板寫唯一變因與影響範圍。

交接模板

複製交接 README，建立 handoff-pack-v1 的可讀入口。

測試矩陣

開啟測試矩陣，`MAKE` 填平台實際證據，`SIMULATED` 填固定輸出與預期路由。

固定輸出

開啟離線 fixture；沒有 Make 連線時用 placeholder 模擬並標記限制。

批次三件組

三筆批次輸入、批次模組卡、批次中間輸出；提供逐筆與聚合後的預期結果。

展示紀錄

複製五分鐘展示紀錄，每段指向檔案、欄位或測試證據。

交付限制

不得含 credential、token、固定帳號或個資；正式原版與變體分開保存。
