# test-cases-v1｜測試案例模板

> `預期`是設計標準；`實際結果`必須填寫 MAKE 或 SIMULATED。離線模擬不能填寫不存在的 Docs URL。

| 案例 | 執行模式 | 只改哪一個主要變因 | 測試輸入 | 預期 Gemini 輸出 | 預期 Filter | 預期 Docs | 實際結果／證據 | 判定 |
|---|---|---|---|---|---|---|---|---|
| A｜需要確認 |  | `needs_review=true` | 林小姐／物流延遲 | 三欄且型別正確 | 不通過 | 不建立 |  |  |
| B｜一般回饋 |  | `needs_review=false` | 陳先生／問題已解決 | 三欄且型別正確 | 通過 | 建立 URL／模擬 placeholder |  |  |
| C｜型別錯誤 |  | `needs_review` 改成文字 | 固定輸出 | `needs_review="false"` | 停止 | 不建立 |  |  |

## 測試完成條件

- A 能停在待人工確認出口。
- B 能建立含摘要與回覆草稿的文件。
- C 能辨識型別錯誤，不把文字猜成布林值。
