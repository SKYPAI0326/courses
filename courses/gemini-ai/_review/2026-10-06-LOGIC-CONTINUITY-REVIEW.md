## BLOCKER：錯誤會直接進入學員交付物

### B01｜KPI 改成達標後，要求寫出未達標的月報

- 類別：對齊／教學邏輯。
- 位置：[PRAC3-3 第189行，core-2](../part3/PRAC3-3.html#core-2)；源頭 `_source/fragments/part3-PRAC3-3.fragment:7`。
- 證據：第2步把處理時間由 5 改成 2 天，答案為「已達標，較上期 -50%」；第3步卻要求寫「本期處理時間未達標，需要調查流程卡點」。恢復原始資料安排在第4步。
- 影響：學員照順序完成時，圖表與敘述相反，會交付數字正確、結論錯誤的報告。這也抵觸本課「先核對再交付」的核心成果。
- 修正方向：擇一固定資料狀態：先對原始 5 天資料寫未達標判讀，再做 2 天變更；或在 2 天狀態寫「已達標、較上期縮短50%」。匯出前同時核對數字與敘述。
- 回修驗收：依正文逐步走完，不自行重設；每個截點的實際值、狀態、文字判讀與 CSV／PDF 必須一致。

- 位置：`part1/CH1-3.html:236`（core-3）→ `part4/CH4-1.html:189`（core-1）；兩頁源頭片段相同區塊。

- 回修驗收：以刻意保留壞 v1 的情境走到第9站，交付包只把通過測試的 v2 標為使用入口。

### M02｜KPI 尚未建立 JSON 備份，下一站已要求用備份恢復

- 類別：DoD／產物依賴。
- 位置：`part3/PRAC3-3.html:188–190`（core-1–3）→ `part4/CH4-1.html:189–190`（core-1–2）。
- 證據：KPI 生成指令要求工具具備 JSON 備份功能，但學員操作只安排保存 CSV／PDF、恢復原始資料及測例外。第9站移動整理工具後，要求「若本機資料未保留，還原 JSON」。
- 影響：工具有備份按鈕不等於學員已下載備份；走到恢復步驟時，可能沒有指定來源檔可用，也不清楚應恢復正常資料或例外資料。
- 修正方向：KPI 離站前明確選定交付資料狀態，下載具名備份、完成一次還原核對，再交接至第9站。簡短區分 CSV 報告與 JSON 還原檔的用途，不需教授 JSON 語法。
- 回修驗收：關閉原分頁，只拿實際交付的 HTML 與備份完成恢復，核對三個指標、期間、來源及數值。

### M03｜Build 專案的保存與重開仍是結果要求，缺少可跟做的操作

- 類別：DoD／環境轉換。
- 位置：`part6/CH6-1.html:191`（core-2）、`part6/PRAC6-1.html:201`（core-4）、`part4/CH4-1.html:190`（core-2）。
- 證據：教材已區分生成描述框與應用輸入框，但保存只有「在 AI Studio 保存專案，記錄可再次開啟的專案位置／網址；重開專案預覽」。沒有說明可觀察的保存成功狀態、從何處找回指定專案、重開到哪個畫面才算完成。
- 影響：前段學會另存 HTML 的零基礎學員，到這裡要自行補出不同的保存流程；第9站再依賴同一項未教清楚的能力。

### M04｜反覆要求填驗收表，但表格沒有提供變更案例的填寫示範

- 類別：DoD／驗收可操作性。
- 位置：`assets/materials/acceptance-template.csv:1–5`；`part1/CH1-3.html:235–236`；`part2/PRAC2-1.html` core-2–4。
- 證據：表頭為 `case,input_file,expected,observed,pass_or_pending,repair_prompt,retest_result`，僅有預算正常、KPI 正常、A 與保存四列。第一次暖身即要求記錄實測，後面要求每次修改都記錄，但未示範新增測試列、填寫觀察、區分自製／參考品及記錄版本。
- 影響：餐點改45人後，模板原列仍寫估算26000；KPI改2天後，原列仍寫「時間未達標」。學員可能覆寫同一列，失去正常、變更、例外與修復前後的差異。
- 修正方向：先提供一列已填好的暖身範例與中文欄位說明，明示每個測試新增一列，寫入工具版本、資料條件與來源模式。預期答案在操作前填，觀察結果在操作後填。表格保持簡短，不增加重複驗收清單。
- 回修驗收：看紀錄即可還原「哪個工具、哪份資料、改了什麼、期望什麼、實際什麼、修好沒有」。

### M05｜獨立改造的替代選項，尚未要求相同程度的需求變更

- 類別：對齊／遷移驗收。
- 位置：`part4/PRAC4-3.html:182–184`（core-1–3）。
- 證據：預設預算有新增「低於10%提醒」規則；替代選項只寫「KPI 新指標、AI 交辦新匿名逐字稿」。這兩種資料輸入本來就由第6、8站工具支援，並不必然需要改需求或生成工具的新版本。
- 影響：選預算者需設計新行為，另兩條路可能只換資料即宣稱完成同一項「有效需求變更」。沒有自備資料的零基礎學員也缺少可直接開始的替代材料。
- 修正方向：為可獨立驗收的替代路線各定一項新規則、提供虛構備援材料與預期結果；或明確將單純換資料列為再應用，將獨立改造驗收保留給有規則變更的路線。
- 回修驗收：每條可選路線都能說明「原工具為何不能滿足新需求、改了哪條行為、如何證明改動有效」。

### M06｜KPI 舊指令仍保留互相衝突的兩套達標規則

- 類別：對齊／指令一致性。
- 位置：`part3/PRAC3-3.html:279–295`，legacy-reference 的 `instruction-box`。
- 證據：原規格以「實際／目標≥100%」判已達標，末尾追加「越小越好 actual<=target、不以百分比統一判所有方向」。
- 影響：處理時間5／3會同時滿足舊規則的「已達標」及新規則的「未達標」。這是學員仍能複製的生成指令，折疊成延伸不能消除指令內的矛盾。
- 修正方向：在原規格位置改成唯一的方向判定；如需「接近目標」，另定義各方向適用的規則，或先移除該狀態。同步舊操作敘述與示例，不只在末尾加覆寫句。
- 回修驗收：指令中每個例子只導出一個狀態；用 higher、lower、空值及零目標四組核對。

### M07｜甘特頁要求判斷前置任務與延期，但示範只描述日期條

- 類別：對齊／教學充分性。
- 位置：`part3/PRAC3-2.html:163、172、248–268`。
- 證據：入口承諾辨識「關鍵路徑」，新增用途要求「前置任務、檢查延期影響」；實際指令欄位只有任務名稱、開始日期、持續天數，沒有依賴關係、傳遞規則或一筆延期前後的答案。負責人仍留在後面的挑戰。
- 影響：只看時間條的重疊，不能推出哪個任務會阻擋下一項工作。學員缺少達成新目標的方法與核對依據。
- 修正方向：先收斂為日期、重疊與時程溝通；若保留延期與關鍵路徑目標，需補帶前置關係的完整小案例、規則及預期變更結果。
- 回修驗收：給一個前置任務延後的具體輸入，學員能說出受影響任務及理由，而非只觀察長條移動。

### M08｜熱點圖的進階挑戰會重新引入「忙碌也推薦開會」的問題

- 類別：對齊／規則回退。
- 位置：`part5/PRAC5-11.html:287、302`。
- 證據：修訂指令規定只有全員明確空閒才列候選；進階挑戰仍要求挑「忙碌程度總分最小的前3個時段」，沒有先排除忙碌與未知，也沒有無候選時的處理。
- 影響：沒有全員空閒時仍可能推薦3個時段，讓剛學到的有效候選規則失效。
- 修正方向：先按「全員明確空閒」篩選，候選不足3個就顯示實際數量，沒有候選就明示。若保留忙碌評分，將結果命名為待協調時段，不能當全員可用。
- 回修驗收：全空閒、有人忙、有人未知、無候選四種資料得到不同且正確的結論。

### M09｜Prompt 庫把備份還原列為成果，卻仍放在選做擴充

- 修正方向：選定這頁的實際用途。若要保管本課指令，將備份／恢復納入基礎生成與驗收；若只展示資料庫介面，就縮減成果承諾，正式指令仍保存到課程資料夾。
- 回修驗收：依基礎正文即可完成頁首要求，不能額外自行挑進階功能才達標。
