6.2

內建上架：Share 與 Publish

AI Studio Build 可分享 app 或部署公開網址；本節示範兩種情境，帳號資格、API 額度與費用依當前方案確認。

選修成果
在成果通過查核後選擇分享方式
依目前官方說明確認權限、額度與費用

部署／平台參考，使用前先核對當前官方說明

官方文件（2026-09-28 更新）記載符合資格的 Starter Tier 最多可部署 2 個 app；Workspace 帳號可能不符合資格，標準部署需連結並啟用帳單。分享時 API 呼叫計入使用額度，付費模型可能收費。每次操作前仍需查看目前畫面和官方文件；不列入核心必修。

本頁可以跳過；需要此工作案例時，先具備 生成並驗證 AI 會議交辦表 的能力。原始示範、完整提示詞與操作內容均保留在下方並預設展開。 Google AI Studio Build 官方說明；官方部署與資格說明。 返回必修路線。

先查官方 Build 分享與部署說明；本課不保證公開服務全程免費。

原始完整單元內容、案例與提示詞（保留）
(01)

第一步：Share——最快讓同事用起來

打開設定面板的 Share 分頁，最上面是 General access，有兩種模式：「Public: Anyone with the link can view」讓拿到連結的人都能開；或者輸入特定人的 email 邀請，只有被邀請的人能用。下面有兩個開關：Default to fullscreen（打開就是全螢幕介面，不會看到 AI Studio 的編輯器外框）跟 Include your Gemini chat history（要不要把你跟 Gemini 的對話紀錄也一起分享出去）。設定好之後按底部的 Copy link 就能把網址傳給同事。

✦
Include your Gemini chat history 建議不要勾。對話記錄裡可能留著你調整 app 時講過的內部細節（例如公司內部的分類規則、範例資料），分享出去等於把這些內容一併曝光。

分享 app 後，使用者可在 app 介面操作；官方說明指出，API 呼叫會計入你的使用額度，使用付費模型可能產生費用。獲分享的使用者也可能查看程式碼並 fork，因此不要放入機密規則或未審核資料。操作前查看Build 分享說明。

(02)

第二步：Publish——公開網址

Publish 部署後會提供公開 app 網址。原始教材引用的「Chat history & code will stay private」是舊版介面文字，不宜當作所有目前帳號與發布情境的隱私保證：現行部署文件說明公開網址與資格，但未交代專案原始碼及對話紀錄的可見範圍。發布前查看目前確認畫面並移除個資與機密；AI Studio Share 的權限另見Build 分享說明。

01
打開設定面板的 Publish 分頁
公開網址提供 app 存取入口；不要單憑舊版提示推定對話紀錄或原始碼在所有情境都私密。先核對當前確認畫面和官方部署說明，移除個資與機密後再發布。
02
按 Get started
進入發布流程，接下來的畫面會依帳號狀態不同而不同。
03
依帳號狀態走不同流程
Starter Tier 最多可部署 2 個 app，但已有或曾有 Google Cloud Billing 的帳號，以及部分 Google Workspace、Workspace for Education 或 Google for Nonprofits 帳號可能不符合資格；標準部署需要連結 Google Cloud 專案並啟用帳單。依目前發布畫面與官方資格說明確認。

完成後拿到公開網址

ℹ
Starter Tier 細節：符合資格的帳號可在未建立 Google Cloud 專案或帳單時發布最多 2 個 app，並部署在單一 Cloud Run 區域。資格依帳號而異；部署資格不代表 app 的 API 使用必然免費。請依官方部署與資格說明及當下畫面確認。
(03)

例外狀況：為什麼你可能看不到 Starter Tier

Starter Tier 不是每個帳號都能使用。已有或曾有 Google Cloud Billing 的帳號，以及關聯免費或付費 Google Workspace、Workspace for Education、Google for Nonprofits 訂閱的企業帳號可能不符合資格。若不符合，標準部署需要選擇 Google Cloud 專案並啟用帳單；最終流程依帳號畫面與官方資格條件為準。

✦
對策：個人帳號也不保證符合 Starter Tier 資格；先確認當前發布選項及 API 使用費用。若標準部署需要帳單，先評估預算，不要把 Railway 當成免 API 費用的替代方案；Railway 另有自己的方案與資源費用。可參考AI Studio 部署說明與Railway 方案。
(04)

使用限制與費用：分享前要查什麼

Share 或 Publish 後，app 的 Gemini API 呼叫會計入建立者的使用額度；限額依模型、專案與使用方案而異，付費模型可能產生費用。不要預設所有模型都有相同的每分鐘或每日上限；分享前查看 AI Studio 的 Usage／Billing，以及官方各模型使用限制與帳務說明。

(05)

收尾：管理你的 app

不管做了多少個 app，都可以在左側選單的 My apps 裡看到列表，需要清掉不用的可以直接刪除。如果之前 Publish 過、後來想收回，只要取消發布，那個公開網址（包含你設定的 名稱.ai.studio）就會被釋出，之後別人也可以申請同一個名稱。

(06)

延伸提醒：公開網址不是免費的午餐

★
分享與成本提醒：公開網址可能讓更多人使用 app；API 呼叫計入建立者的使用額度，付費模型可能產生費用。AI Studio 分享的 app 使用者也可能查看程式碼並 fork。內部測試可限制分享對象，但仍須檢查資料、權限和成本。下一節介紹 GitHub + Railway 外部部署；它是選修方案，也有自己的費用，官方 Build 說明列出目前分享行為。
