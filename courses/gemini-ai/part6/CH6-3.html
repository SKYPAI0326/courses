6.3

GitHub + Railway：備援上架路線

示範將 AI Studio Build 專案同步到 GitHub，再部署至 Railway。這是選修外部部署路線；先比較AI Studio GitHub／Cloud Run 選項，並核對 Railway 當前條件與費用。

依平台現況確認環境、金鑰位置與成本

部署／平台參考，使用前先核對當前官方說明

AI Studio Build 支援 GitHub 同步與 Cloud Run 部署；本頁示範 Railway 外部託管，屬於選修。Railway 的 Trial 驗證、資源與費用可能變動，按需查閱Trial 條件和目前方案。這條路不會免除 Gemini API 使用費。

本頁可以跳過；需要此工作案例時，先具備 生成並驗證 AI 會議交辦表 的能力。原始示範、完整提示詞與操作內容均保留在下方並預設展開。 Google AI Studio Build 官方說明；官方部署與資格說明。 返回必修路線。

原始完整單元內容、案例與提示詞（保留）
(01)

情境：這是選修外部部署路線

AI Studio Build 目前可將完整應用部署到 Cloud Run，也支援與 GitHub 同步；Starter Tier 符合資格時最多可發布 2 個 app，標準部署需設定帳單，API 使用費另依模型方案計算。Railway 是可選的外部主機，適合需要比較 GitHub 工作流程或管理方式時評估，不代表免除 API 成本。查閱官方部署說明與Build 說明後，再判斷下列情境是否適用：

帳號不符合 Starter Tier 資格
Google Workspace、Workspace for Education、Google for Nonprofits 或曾有 Google Cloud Billing 的帳號可能不符合 Starter Tier；以官方資格說明與目前帳號畫面確認。
需要超過 Starter Tier 的 2 個 app
Starter Tier 限符合資格帳號最多 2 個部署；更多 app 可評估標準部署與帳單，或其他主機。各方案用量與費用依當前官方說明確認。
想要版本控制與備份
工具會持續修改，想要有 commit 紀錄可以回溯，或想把程式碼備份在自己的 GitHub 帳號下。
ℹ
先比較內建選項：AI Studio Build 可同步 GitHub，也可部署到 Cloud Run；Starter Tier 僅適用符合資格的帳號。Railway 是外部選修路線，不能用來規避 Gemini API 使用費。先看AI Studio 部署說明與Railway 方案費用，再決定是否需要下方操作。
(02)

步驟 1：把程式碼推上GitHub

在 AI Studio 的 Build 編輯器裡，設定面板有一個「GitHub」分頁，這就是「Sync to GitHub」功能。第一次點擊會走 GitHub OAuth 授權——同意讓 AI Studio 幫你建立 repo。授權完成後，AI Studio 會為這個 app 自動建立一個專屬的 repo（main 分支），程式碼就在裡面了。

之後每次你在 Build 裡改了東西，回到這個 GitHub 分頁，它會自動草擬一段 commit 訊息、列出這次變更了哪些檔案。確認沒問題後按「Stage and commit all changes」，就會同步推上去。面板上也有解除連結與直接開啟 repo 網址的按鈕。

★
Secrets 不會被推上 GitHub。你在 Secrets 分頁設定的 GEMINI_API_KEY 是安全設計上刻意排除在同步範圍外的。這是好事——代表你的 API key 不會意外出現在公開 repo 裡。但也代表部署到 Railway 之後，你要自己補一次環境變數，下一步會說明。
(03)

步驟 2：Railway 接上GitHub

Railway 可從 GitHub 專案部署。Trial 分為 Full 與 Limited，能否取得完整網路功能取決於 Railway 的帳號驗證條件；僅連結 GitHub 不保證驗證通過。請在註冊時查看目前帳號狀態與Railway Trial 官方條件。

Railway 官方目前列出一次性 US$5 Trial credit，最長 30 天或額度用完即止；Trial 資源上限、外連網路條件與資料保存依帳號狀態而異。官方文件未在此保證免信用卡；開始前查看Trial 條件。

01
用 GitHub 帳號登入 railway.app
首次登入會請你授權 Railway 讀取你的 GitHub repo 清單。
02
New Project → Deploy from GitHub repo
從清單裡選出 AI Studio 剛才幫你建的那個 repo。
03
等待自動偵測與建置
Railway 會依 repo 中的專案檔案偵測建置與啟動方式；實際指令可能不同。若部署失敗，先看 Build／Deploy Logs，再依專案設定調整。
(04)

步驟 3：補上API key

建置完成之後，app 還不會動——因為它需要 GEMINI_API_KEY 才能呼叫 Gemini。到服務的 Variables 分頁，新增一筆 GEMINI_API_KEY，值貼上你在 AI Studio「API keys」頁面產生的那把 key。儲存後 Railway 會自動重新部署一次。

✦
資安鐵則：key 只放在環境變數（Variables）裡，永遠不要把它直接寫進程式碼、更不要 commit 進 GitHub repo。上一步提到 Secrets 本來就不會跟著同步，就是為了避免這件事發生。
(05)

步驟 4：拿到公開網址

最後一步，到服務的 Settings → Networking，點「Generate Domain」，Railway 就會給你一個 *.up.railway.app 的網址。這個網址可以直接分享出去，跟內建 Publish 拿到的網址一樣是公開可存取的。

結論：先比較 AI Studio Build 的 GitHub 同步與 Cloud Run。Railway 適合需要其外部部署工作流程時再評估；Starter Tier 資格、API 費用和 Railway 主機費用分別確認，不能只因名額或帳號限制就假設 Railway 更便宜。

(07)

GitHub Pages 能託管靜態檔，但不能提供伺服器端 API 執行環境

ℹ
GitHub Pages 的邊界：它可以用 GitHub Actions 建置並託管靜態網站，但不支援伺服器端語言。含 Gemini API 呼叫的 app 必須把金鑰放在伺服器端，不能把 key 寫進公開前端程式；可評估 AI Studio Cloud Run 或其他具伺服器端執行環境的主機。參考GitHub Pages 官方說明與AI Studio Build 金鑰說明。
