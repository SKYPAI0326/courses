整理交付包，不再建一個保存工具

在 AI工作工具 資料夾建立「工具」「資料」「指令」「報告」「驗收」「歷史版本」六個子資料夾。每種工具只把最後通過驗收的檔案放在「工具」：例如 meeting-timer-v2.html、activity-budget-v2.html、department-kpi.html。實際檔名依你的驗收紀錄填入 README；沒修過的工具仍可用原檔名。未通過的舊版放「歷史版本」，不要讓它成為開啟入口。CSV、逐字稿與 JSON 放「資料」；完整生成與修復指令放「指令」；PDF 與交辦 CSV 放「報告」。

AI 交辦需要 Build 專案與伺服器模型呼叫；在 README 寫下專案標題、可重開的書籤網址、登入條件與重新測試方法。專案 ZIP 是程式碼備份，不能取代平台內專案重開與預覽測試。

關閉、重開、更新、再輸出

  1. 依 README 的實際檔名，關閉單檔工具分頁後從「工具」資料夾重開；核對資料或匯入備份。KPI 資料未保留時，匯入第6站的 department-kpi-backup.json，確認回到 120 件、5 天、1%；無效備份不能覆蓋正常資料。
  2. 預算改一個備註再輸出；KPI 改一個實際值，先預判狀態、再輸出月報。打開新 CSV／PDF，確認內容更新，並把這個測試記在新列。
  3. 點 AI Studio 專案書籤；確認專案標題和既有預覽回來後，用 A 重跑，核對至少兩項有效交辦與原文。若書籤沒有回到同一專案，依當下畫面找同名專案；仍找不到時保存網址、標題與登入／權限狀態，標記「平台重開待完成」，回看官方 Build 說明和帳號存取條件。不能以 Share 或 ZIP 代替重開證據。
  4. 從資料夾開交辦 CSV，確認原文、未知、確認欄都在。打開驗收表，記實際檔名與版本，區分學員生成、參考品及待完成，不以捲動進度代替工作成果。

使用說明與修復入口

新增 README.txt，寫「工具用途、打開方式、資料來源、正常答案、未知如何處理、備份位置、失敗回到哪個步驟」。例如預算公式錯回預算生成對話；副檔名錯回存檔；AI 整理錯回 Build 規則並重測 A/B。不要在修復時刪掉所有原資料。

本機文件含資料時，只交給需要使用的人。公開網址、多人同步與背景通知另學；保存好檔案、可重新查核與更新，已能支持下次工作。

(01)

情境：本機執行是最安全的部署方式

我們整個課程做的工具都是純 HTML 檔案，這代表一件事：它們不需要伺服器就能運作。直接用瀏覽器打開，就是完整功能。

這個特性在企業環境裡是一個巨大的優勢。計算薪資、處理報價、分析客戶數據——這些工作如果上傳到雲端服務，就涉及資料外洩風險。工具做好、部署到本機之後，執行階段所有運算都在你自己的電腦裡進行，資料不會離開你的裝置。（提醒：這裡指的是工具「用起來」之後的階段——請 AI 生成或修改工具時，Prompt 內容會送進雲端，機密數字別寫進生成用的 Prompt，一律用假資料示範。）

ℹ
純 HTML 工具的本質：它其實就是一個網頁，但不需要連網。瀏覽器（Chrome、Safari、Edge）就是它的「執行環境」，打開即用，關閉即停，沒有安裝、沒有更新、沒有訂閱費。
(02)

核心要點：整理你的工具資料夾

工具越做越多之後，最常見的問題是「那個計算機存在哪裡？」建議從一開始就建立一個固定的資料夾結構，讓每個工具都有明確的家。

📁 AI工具庫/
📁 計算類/ 報價計算機.html  ← 客戶報價、快速試算 薪資試算器.html 匯率換算工具.html 📁 排程類/ 排班生成器.html 跨時區會議板.html 📁 視覺化類/ 銷售漏斗圖.html 專案路徑圖.html 📁 其他/ 倒數計時器.html

分類方式不需要完全照上面。重點是讓你自己三秒內找到想要的工具。可以依照工作性質改成「業務類 / 行政類 / 報告類」，或依照使用頻率「每天用 / 每週用 / 偶爾用」來分。

(03)

範例演練：讓工具像 App 一樣好用的三個技巧

工具存好之後，下一步是讓它「夠方便」——打開不超過兩個動作，才會真的被使用。以下三個技巧可以大幅提升工具的可及性：

01
瀏覽器書籤列
把最常用的工具拖拉到瀏覽器的書籤列（Bookmarks Bar）。每次打開瀏覽器都看得到，一秒點開。Chrome / Safari / Edge 都支援，也可以建立「AI 工具」資料夾分類存放。
02
桌面捷徑
Windows：對 HTML 檔案按右鍵 → 傳送到 → 桌面（建立捷徑）。macOS：按住 Option 鍵拖拉檔案到桌面建立別名。雙擊就能用預設瀏覽器打開。
03
釘選到瀏覽器分頁
對正在使用的工具分頁按右鍵 → 釘選分頁（Pin Tab）。它會變成一個小圖示常駐在左側，每次開啟瀏覽器都自動恢復，不佔空間又隨時可用。

(05)

注意事項：命名與機密資料別上公開網址

✦
命名技巧：直接用功能命名（「報價計算機」而不是「tool_v3_final」），讓三個月後的你也看得懂。如果有多個版本，在後面加日期：報價計算機_2024-03.html

機密資料的工具，絕對不要放 GitHub Pages 或任何公開網址。GitHub Pages 這類服務預設是公開可見的，含公司機密、客戶名單、薪資計算邏輯的工具只能本機執行——這不是「不方便」的問題，是外洩風險的問題。
(06)

延伸應用：決策原則

★
決策原則：工具裡有沒有公司機密或個人資料？有的話就本機執行。只是通用計算工具或展示用圖表？可以考慮 GitHub Pages 讓同事用網址存取，省去每次傳檔的麻煩。下一節我們把課程做過的所有 Prompt 整理成一份專屬 Prompt 庫，讓這些工具真正變成你隨時能重用的資產。
