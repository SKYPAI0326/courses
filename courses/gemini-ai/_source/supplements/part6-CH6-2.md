<main class="lesson-body"><section class="lesson-section" id="share-publish-1"><h2 class="section-heading">先選受眾，再決定分享方式</h2><p class="body-text">你已在 AI Studio Build 預覽測過一個會議交辦 app。現在要讓同事試用，或讓不特定使用者取得網址。兩種情境的受眾、資料風險和費用不同；本頁完成物是一份有理由的分享決策，不要求為了上課把工具公開。</p><div class="table-scroll"><table><thead><tr><th>方式</th><th>適用情境</th><th>操作前要核對</th></tr></thead><tbody><tr><th>Share</th><td>指定同事測試或協作</td><td>目前存取範圍、程式可見性、可否 fork／編輯、API 使用者與用量</td></tr><tr><th>Publish</th><td>需要公開網址給較廣受眾</td><td>帳號部署資格、公開內容、API 用量、可能費用和撤回方法</td></tr></tbody></table></div><p class="body-text">官方目前說明：AI Studio app 預設為私有；分享 app 後，使用者可能查看程式碼並 fork。分享或部署後的 Gemini API 呼叫會計入建立者用量，付費模型可能收費。分享前先讀 <a href="https://ai.google.dev/gemini-api/docs/aistudio-build-mode" rel="noopener" target="_blank">Build 分享說明</a> 和 <a href="https://ai.google.dev/gemini-api/docs/billing/" rel="noopener" target="_blank">Gemini API 帳務說明</a>。</p></section>
<section class="lesson-section" id="share-publish-2"><h2 class="section-heading">Share：先用假資料做受限試用</h2><ol class="body-text"><li>在 AI Studio 打開正確的 Build 專案，進入當前分享設定。核對分享對象和權限，不要只複製網址就假設只有同事能開。</li><li>優先用講師／團隊允許的測試帳號或假資料。確認受邀者能否操作、能看到哪些程式或專案內容，以及是否具有 fork／編輯能力。</li><li>查看 AI Studio 的 Usage／Billing 和模型限制。所有測試都用假資料；不要輸入客戶名單、會議機密或敏感個資。</li><li>測試結束後，回分享設定移除不再需要的對象或連結權限，並留下試用回饋和仍待修正項。</li></ol><p class="body-text">如果你無法確認當前存取範圍、程式可見性或費用，就暫停分享並查官方說明；不要靠舊版截圖推測目前帳號行為。</p></section>
<section class="lesson-section" id="share-publish-3"><h2 class="section-heading">Publish：把公開服務當成另一項交付</h2><p class="body-text">AI Studio 可從 Build 將 app 部署到 Cloud Run 並提供公開網址。符合資格的 Google Cloud Starter Tier 帳號最多可發布 2 個 app；已有或曾有 Google Cloud Billing 的帳號及部分 Workspace 帳號可能不符合資格。標準部署需要連結 Google Cloud 專案並啟用帳單。每次操作前查看 <a href="https://ai.google.dev/gemini-api/docs/aistudio-deploying" rel="noopener" target="_blank">目前部署資格與步驟</a>；不要把 Starter Tier 當成每個學員都能使用的保證。</p><ol class="body-text"><li>先用假資料測過 app 的主要成功、空白輸入、模型／網路失敗與重試情況。</li><li>確認公開頁面不含個資、內部指令或機密樣本；再於 Publish 流程核對帳號、網址和當前費用提示。</li><li>發布後用不帶編輯權限的測試窗口打開公開網址，驗證使用者實際看到的畫面、失敗訊息和資料邊界。</li><li>記錄如何取消發布或刪除服務。自訂網址可能在取消發布／刪除後釋出；若不再需要，完成撤回並確認連結無法再使用。</li></ol><p class="body-text">Starter Tier 的部署資格與模型用量費用是不同問題。若帳號要求啟用帳單，先評估費用再繼續；不要以「網址已產生」推定長期運作免費。</p></section>
<section class="lesson-section" id="share-publish-4"><h2 class="section-heading">用證據完成決策</h2><p class="body-text">選一種情境並寫下受眾、資料敏感度、程式可見性、API 用量負擔者、帳號資格與撤回方式。若任何關鍵項目仍未知，結論寫「暫不分享／發布，待查證」。內部試用不必公開；分享與發布操作不是本課會議交辦工具的核心驗收。</p><p class="body-text">若確實需要公開服務，完成前保存 Build 專案名稱、部署網址、測試紀錄、費用核對位置和撤回步驟。每當平台介面或帳號條件改變，重新閱讀官方 Build、部署與帳務說明。</p><div class="callout key"><div aria-hidden="true" class="callout-icon">✓</div><div class="callout-body"><strong>本單元驗收：</strong>能清楚說明何時用 Share、何時才考慮 Publish；能指出程式可見性、建立者用量、帳號部署資格及撤回方法。只完成決策與假資料測試即可，不需真的公開 app。</div></div></section><section class="lesson-section" id="completion"><h2 class="section-heading">讓分享範圍與撤回方式有依據</h2><p class="body-text">保留受眾、權限、資料、用量與撤回方式的決策紀錄；未知項目先查證。需要實際分享時，按當前帳號再次確認，不把能複製網址視為權限已正確或服務長期免費。</p><p class="body-text">回到<a href="../index.html#supplements">補充教材目錄</a>，依下一個工作需求選擇教材。</p></section></main>
