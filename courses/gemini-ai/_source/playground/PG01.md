# CSV 清理與品質檢查

<!-- learner-content:start -->
<section class="lesson-section" id="pg01-purpose">
<h2 class="section-heading">先把資料問題列出來，再決定每列怎麼處理</h2>
<p class="body-text">整理名單或紀錄時，空白欄位、重複列和文字混進數字欄，常讓後續排序或統計不可靠。這個案例要做的是一個離線 CSV 清理工具：你指定欄位、唯一鍵和檢查規則，工具逐列顯示可接受資料與需要修正的原因，最後匯出兩份 CSV。完成物是清理預覽、拒絕原因清單，以及可再用試算表開啟的檔案；它協助你找出問題，不能替你猜測或補造缺失值。
</p>
<p class="body-text">先下載 <a href="../assets/playground/PG01/input-a.csv">input-a.csv</a> 作為 A 的原始資料，並先看 <a href="../assets/playground/PG01/cases.txt">cases.txt</a> 的欄位設定。你也可用純文字編輯器打開 CSV；若試算表顯示亂碼，改用 UTF-8 匯入功能。第一步是確認標題列和欄位對應，然後把同一份資料輸入稍後生成的工具。另有 <a href="../assets/playground/PG01/input-b.csv">input-b.csv</a>，留到換條件檢查時使用。無法下載時，可在新 CSV 輸入標題列及下方附件內容；不要直接修改唯一原件。
</p>
<p class="body-text">資料清理先分清「格式可依明確規則整理」和「內容需要人確認」。首尾空格可去除、空白列可辨識，但不能因此自行猜出姓名、數字或身分。唯一鍵由使用者指定，用來判斷哪些列鍵值相同；規則必須說清楚保留策略。若鍵值重複，本課工具把後續列送入拒絕清單供核對，不自行刪掉或合併。有效資料也必須在預覽與輸出中保留，不能為了讓報表整齊而消失。
</p>
<p class="body-text"><a href="../assets/playground/PG01/author-reference.html">開啟作者參考工具</a>可直接操作一個離線示範品。這是作者依提示詞製作的參考工具，不是 Gemini 生成成果，也不代表平台或真人測試通過。</p>
<ol class="step-list"><li>複製 A 的 CSV，先核對標題列與編碼。</li><li>在工具選擇唯一鍵、必填欄和數字欄規則。</li><li>檢查每列預覽及待修正原因，再分別匯出兩份 CSV。</li><li>修改一筆資料並重跑，確認有效列和待修正列數有對應變化。</li></ol>
</section>
<section class="lesson-section" id="pg01-demo">
<h2 class="section-heading">示範 A：一列可用，不代表整份都可直接匯出</h2>
<p class="body-text">在 input-a.csv 中，設定 record_id 為唯一鍵；item、quantity、unit_price 為必填欄；quantity 與 unit_price 是非負數字欄，允許小數位數由使用者設定為最多兩位。這些是本次案例設定，提示詞不會固定這些欄名或限制。讀取第一列 R101：欄位都有值，quantity 為 2、unit_price 為 35，唯一鍵只出現一次，因此它留在清理預覽。R103 的 unit_price 是「待補」，不能轉成數字，拒絕原因是「unit_price 不是有效數字」；R104 缺 item，原因是「必填欄位 item 空白」。兩筆資料的 record_id 都是 R102，依本次唯一鍵規則，先出現者保留，後一列列為重複鍵待核對。R106 的 quantity 是 -1，違反本次非負規則，拒絕原因需指出欄位和規則。工具不會默默把 -1 改成 0。
</p>

<tr><td>R101</td><td>必填齊全、數字有效、鍵唯一</td><td>保留並顯示於清理預覽</td></tr>
<tr><td>R102 第一列</td><td>第一個唯一鍵值</td><td>保留</td></tr>

<p class="body-text">這種核對讓「清理」有可追查的邊界。拒絕清單仍帶著原始列，不代表資料已刪除；修正來源後可重新匯入重跑。CSV 只是文字欄位資料，工具不能保證讀懂試算表公式、格式或巨集，因此本案例只接受有標題列的純 CSV，不把 Excel 公式解析當作功能。
</p>
</section>
<section class="lesson-section" id="pg01-build">
<h2 class="section-heading">把可重用規則和本次案例分開提供</h2>
<p class="body-text">先複製結構提示詞建立一個單檔離線網頁工具，再把案例附件另外貼入工具或作為測試資料。結構提示詞負責描述使用者可設定什麼、每列怎麼檢查、結果如何保存；它不包含本案例的人名、欄名、門檻或答案。請在提示詞中指定原生 HTML、CSS 與 JavaScript 同檔，不使用外部套件或 API；初次開啟是空白輸入，可新增、修改、刪除列，亦可載入 CSV、重設資料與匯出結果。</p>
<div class="prompt-wrap">
<div class="prompt-label">可重用結構提示詞｜先單獨複製</div>
<p class="policy-guide">提示詞只定義工具結構與規則。先產生空白可用版本，再以獨立附件提供資料與本次欄位設定。</p>
<pre class="prompt-box" data-policy-prompt="工具生成或修改" id="pg01-prompt">請製作一個單檔、離線可用的 CSV 清理與品質檢查工具，供使用者整理一般名單或紀錄。只用原生 HTML、CSS 與 JavaScript，所有內容寫在同一個 HTML 檔，不使用外部套件、CDN、伺服器或 API。首次開啟時顯示空白資料，不自行編造案例。

【輸入與設定】
- 使用者可載入 UTF-8 CSV，並在畫面確認標題列與欄位對應；也可手動新增、修改和刪除資料列。
- 由使用者選擇唯一鍵欄位、必填欄位清單、數字欄位清單及每個數字欄是否允許負值與小數位數。欄位名稱、規則和資料均不得寫死。
- 可清除本次資料並重新開始。匯入前保留原始文字值供核對。

【逐列檢查】
- 去除欄位值首尾空格後檢查；空白列可單獨標示，不當作有效資料。
- 必填欄位空白、數字欄空白或格式無效、超過使用者設定的小數位數、違反正負值設定、唯一鍵空白或重複時，將該列列入待修正清單，說明每個命中原因及欄位。
- 數字只接受明確可解析的十進位數字文字；不推測千分位、貨幣符號、日期、公式或地區格式。不能確定格式時標記待修正，保留原文。
- 唯一鍵重複時保留所有原始列；不自行刪除、合併或覆寫。畫面可依使用者指定的第一筆保留規則，把後續同鍵列標記為重複待確認；所有列都可回看。
- 任何列不得靜默消失。顯示匯入列數、有效列數、待修正列數及兩者加總是否等於匯入列數。

【畫面與輸出】
- 顯示可編輯的清理預覽和待修正清單；每列可看到原始欄值、整理後值、狀態與拒絕原因。
- 提供匯出有效資料 CSV、匯出待修正資料 CSV、重新匯入及清除按鈕。匯出的文字需正確處理逗號、雙引號、換行及 UTF-8 BOM，以利試算表辨識繁體中文。
- 匯出前再次顯示列數摘要；不得只輸出有效列而遺失待修正資料。
- 表單有清楚標籤，桌機與手機均可閱讀；所有錯誤須指出欄位和回修方式。

【交付與驗收】
只交付從 DOCTYPE 到 html 結尾的完整單一 HTML 原始碼。請檢查空白值、錯誤數字、重複鍵、合法列、修改後重算、兩種 CSV 匯出與清除重來。處理規則必須依畫面上的使用者設定運作；沒有附加資料時，工具仍可從空白狀態開始使用。</pre>

<section class="lesson-section" id="pg01-check">
<h2 class="section-heading">換欄位測試後再修正漏掉的規則</h2>
<p class="body-text">用 input-b.csv 換一組欄位設定與唯一鍵，確認工具沒有把上一個案例的欄名寫死。再手動改掉一個錯誤數字，觀察它能否重新進入清理預覽；新增一列重複鍵，確認原列仍可查看；刪除一列時應有明確操作，不能與自動清理混淆。如果輸入字串含逗號或雙引號，匯出後重新匯入，確認欄位仍對齊。遇到拒絕原因空泛、有效列數對不上，回到提示詞的逐列檢查與列數摘要條款，要求工具顯示原始列、命中欄位及修正後結果，再重跑同一份資料。</p>
<p class="body-text">這個工具適合每次收到新 CSV 時先做格式與資料完整度初檢，例如整理活動報名、產品清單或庫存紀錄。規則由使用者依工作情境設定；它不代替資料權責人決定缺值、重複或異常列的實際含義。保存原始檔和兩份匯出檔，才能回頭說明哪些列被納入、哪些仍需確認。</p>
