把需求寫成可核對的規格

沿用計時器，追加「會議主題」需求；讓 AI 知道你要看到什麼結果。

本次成果
寫清輸入、規則、例外與輸出
為一項修改訂出可觀察的通過標準

一條需求要能對應到一個可觀察的行為

活動主持人已經能用基本計時器開始、暫停和重設。現在他還需要讓螢幕顯示會議主題、在時間快到時提醒發言者，並避免錯誤秒數造成混亂。把所有要求寫成一段可直接交給 AI 的完整提示詞，能讓生成結果有依據，也讓你知道失敗時該檢查哪一條。

先把需求拆成「對誰有用、要產生什麼、使用者輸入什麼、各操作如何反應、什麼輸入不接受、結果以什麼形式交付、如何驗收」。這些部分比一個聽起來專業的角色名稱更重要；角色可以幫模型理解工作角度，不能保證邏輯或程式正確。

需求撰寫練習：先自己寫一條

主持人準備示範計時器時，不小心把秒數設成 0。先不要看下面的完整提示詞，在筆記寫出「遇到這種輸入時工具要怎麼反應」以及「你要怎麼操作才能確認它真的照做」。這是在寫工作規格，不需要寫程式。

✎
請先完成再往下對照

自己的需求：秒數為＿＿時，工具應＿＿。

對應的驗收：輸入＿＿並按「開始」，我應看到＿＿；修正成有效秒數後應＿＿。

先完成再往下對照；不確定時可以從「不能開始、說明原因、改正後可用」三個結果組句。

參考作答

需求：秒數空白、0、負數或非整數時，不可開始，並顯示清楚的修正提示。

驗收：輸入 0 按「開始」，倒數不得啟動並應出現修正提示；改成 10 秒再按開始，倒數應正常進行。把這兩行和你自己的版本比較，若有漏掉「可恢復」或沒有寫出可觀察結果，就補完整。

規格面向計時器的完整要求與寫作理由怎麼檢查
情境與使用者活動會議主持人需要掌握發言者的剩餘時間；這能讓工具用途和畫面文字有明確對象。畫面顯示主題與時間，主持人能快速讀取。
任務與輸入製作會議倒數計時器，可輸入主題與正整數秒數，預設 25 分鐘（1500 秒）；這說清楚工具要做什麼，以及使用者提供哪些值。首次開啟應顯示 25:00；輸入「活動籌備」和 10 秒後可開始。
操作規則開始每秒減一、暫停保持、重設回設定秒數、改主題不重設、重複開始不加速；這把按鈕動作和後續結果連起來。逐一操作，確認秒數變化和預期相符。
提醒與結束剩餘時間大於 0 且小於或等於 300 秒時以紅色提醒；歸零後停止、顯示「時間到」、播放本機提示音且不得小於零。這精確界定提醒邊界和結束狀態。秒數設為 301，按重設再按開始，確認 5:01 不紅；秒數改為 300，再按重設和開始確認 5:00 轉紅；秒數設為 1，按重設和開始檢查歸零與提示音。
例外秒數空白、0、負數或非整數時不可開始並顯示修正提示；清空主題則顯示「未命名會議」。這能防止無效值被當成有效時間。逐一輸入空白、0、-1、1.5 並按「開始」；清空主題確認顯示「未命名會議」；最後設為 10 秒、按「重設」和「開始」確認可恢復。
輸出與限制繁體中文、分:秒、大字體；單一完整 HTML，內嵌 CSS 與原生 JavaScript，不用外部套件、CDN、框架或 API；手機寬度可操作。單檔可減少初次保存的檔案與路徑錯誤，固定規則不需外部服務。保存為一個 HTML；窄化到手機寬度時沒有水平捲動，欄位和按鈕仍可操作；在安全可行時離線重開。
驗收與交付以已知輸入執行正常、邊界和例外測試；只輸出從文件開頭到結尾的完整程式。明確邊界可避免說明文字、Markdown 或半份程式混進檔案。回覆從 `<!DOCTYPE html>` 開始並以 `</html>` 結束；另存後依檢查表操作。

單一 HTML 不是所有軟體都該使用的架構；它適合這個初學者的固定規則小工具，因為內容、外觀與操作可以一起保存。CSS 負責呈現、JavaScript 負責計時；原生程式碼和瀏覽器內建的 Web Audio API 不需下載函式庫或音效檔。此處的「不連 API」描述的是計時器執行時不向外部服務傳資料；在 AI Studio 產生工具的提示詞仍會送到雲端，機密內容不可貼入。

這是一份完整提示詞，不是生成保證

下面把角色、用途、功能、輸入、規則、例外、交付限制和測試寫在同一份可複製提示詞裡。標籤讓初學者比較容易檢查有沒有漏項；模型不需要看到「角色」這個標籤才會理解內容。明確規格能降低猜測，但 AI 仍可能誤解或漏做，所以每一項都要在生成後驗收。

完整規格提示詞｜供 CH1-3 原樣生成
你是協助初學者製作瀏覽器單檔工具的前端工程助手。
工作情境：活動會議主持人需要掌握每位發言者的時間，並在時間接近結束時提醒。
任務：製作一個「會議倒數計時器」，供主持人於會議中使用。
輸入：使用者可輸入會議主題與正整數秒數；秒數預設為 25 分鐘（1500 秒）。主題留白時顯示「未命名會議」。
操作規則：按「開始」後每秒減一；按「暫停」時數字保持；按「重設」回到目前設定的秒數；倒數中修改主題不得重設剩餘時間；重複按「開始」不得建立多個倒數或加速。
提醒與結束：剩餘時間大於 0 且小於或等於 5 分鐘時，以紅色顯示提醒；時間歸零後停止、顯示「時間到」，不可顯示負數，並播放一次短提示音。提示音請使用瀏覽器內建 Web Audio API 產生，不讀取或下載外部音效檔。
例外：秒數空白、0、負數或非整數時不可開始，並顯示清楚的修正提示；修正為有效正整數後可以開始。使用者清空主題時仍可操作，畫面顯示「未命名會議」。
畫面：使用繁體中文，以分:秒顯示剩餘時間，時間數字要清楚易讀；提供主題欄、秒數欄、「開始」、「暫停」、「重設」按鈕。桌面投影及 390 像素寬的手機畫面皆須可操作，手機畫面不得出現水平捲動。
工程限制：只交付一個完整 HTML 檔案。HTML、CSS 與原生 JavaScript 都放在同一檔案；不得使用外部函式庫、框架、CDN、外部字型、圖片、音效檔或 API。計時器保存後只依固定規則運作，不呼叫 AI、不需網路。
驗收：首次開啟秒數欄預設 1500，畫面顯示 25:00；清空主題後顯示「未命名會議」。輸入「活動籌備」和 10 秒，開始約三秒後剩約 7 秒；暫停兩秒數字不變；重設回 10 秒；倒數中改主題時剩餘秒數不重設；重複按開始不加速。將秒數設為 301 秒，按「重設」再按「開始」，確認 5:01 不標紅；將秒數改為 300 秒，再按「重設」和「開始」，確認 5:00 標紅。將秒數設為 1 秒，按「重設」和「開始」測歸零，確認停止、顯示時間到、不出現負數並播放一次提示音。空白、0、-1、1.5 各自輸入後按「開始」都不可啟動；最後設為 10 秒，按「重設」和「開始」確認可恢復。窄化至 390 像素寬時，欄位和按鈕仍可操作且頁面沒有水平捲動。只用本機 HTML/CSS/JavaScript，保存檔在離線時仍能開啟與操作。
交付格式：請只輸出從 <!DOCTYPE html> 到 </html> 的完整 HTML 程式碼，不要加說明文字、Markdown 圍欄、佔位符或程式片段。

這份提示詞保留本章與原課程中完整單檔工具的核心限制，並把「時間接近結束時提醒」寫成可測條件。角色描述工作角度，不能替代需求；單檔與無外部依賴限定交付方式；Web Audio API 讓聲音由瀏覽器本機產生，維持無外部音效檔；驗收行則把每項規則變成可以操作的測試。學員不需要讀懂程式碼，但需要核對這些行為。

預測一項修改會影響哪些測試

在新分頁打開會議計時器參考品，用 10 秒重做開始、暫停和重設。參考品示範的是基本操作；紅色提醒與提示音是這份規格新增的功能，會在 CH1-3 生成後測試。

  1. 在提示詞中找到「倒數中修改主題不得重設剩餘時間」，先說出它要防止什麼問題。
  2. 想像刪掉這一句，列出至少一個會失去依據的測試。正確答案是：倒數中改主題後檢查剩餘秒數是否繼續，而不是重新開始。
  3. 指出哪些驗收仍應通過：開始、暫停、重設、非法秒數、歸零以及單檔離線執行都沒有依賴「主題修改」這項規則。
  4. 在自己的筆記中保留這份完整提示詞和你的預測；不要只保存一個短摘要，否則生成時會丟失其他要求。

若不同規則一次改動，生成結果失敗時就很難找到原因。這次只改一項並預測受影響的測試，能把失敗定位到具體要求；這不是保證模型遵守，而是讓你有可重跑的驗收方式。下一站會把同一份提示詞送給 AI、保存完整 HTML，再按整套測試檢查。
