PART 1 · 解鎖 AI 開發者模式
1.1

從一個工作需求開始

用會議計時器觀察工作需求與工具行為，分清 AI 生成和瀏覽器執行，再準備下一步的工作位置。

本次成果
操作計時器並說出開始、暫停、重設與歸零的結果
分辨 AI 生成階段與瀏覽器執行階段的工作
確認 AI Studio 登入並建立工具資料夾

主持人要看著發言者，也要掌握時間

小組例會輪流報告時，主持人一邊聽內容，一邊提醒下一位何時開始。一直切換手機或心算剩餘時間，容易漏聽發言。這次用會議倒數計時器處理一件範圍清楚的工作：輸入秒數，開始倒數，暫停時保留時間，重設後回到原設定。

本章的實際成果是一份可以交給下一步使用的「工作需求與驗收紀錄」：你會寫出誰遇到什麼問題、工具需要哪些輸入與反應，以及怎樣才算通過。接著兩章會沿用這份需求，寫成完整提示詞，再生成並測試你自己的 HTML 工具。

先在新分頁開啟會議計時器參考品。這是供你觀察行為的現成範例，還不是你用 AI 生成的成品。

  1. 秒數欄保留 10，按「開始」。約三秒後看數字，應比開始時少約三秒。
  2. 按「暫停」並等兩秒。記下目前數字；等待期間它應維持不變。
  3. 按「重設」讓數字回到 10，再按「開始」。在倒數中修改會議主題；主題文字應更新，剩餘秒數應繼續減少。
  4. 再按一次「重設」並開始，讓它倒數到零；畫面應顯示時間到並停止。
主持人的動作畫面應有的結果這項檢查回答什麼
按開始每秒少一，倒數只進行一次。工具是否真的執行計時規則？
按暫停後等兩秒數字固定不變。暫停是否保留目前狀態？
按重設回到欄位中設定的秒數。使用者能否重新開始一輪？
倒數時改主題主題更新，秒數不跳回起點。修改標籤會不會意外改變計時？
重設並再次開始，讓時間走到零顯示時間到並停止，不出現負數。工具是否有明確的結束狀態？

如果參考品沒有載入，先確認新分頁是否開啟，再重新整理。操作與預期結果不一致時，記下實際看到的狀況；不要把參考品當成已通過的自己生成版本。表格列出的五項行為就是本章示範使用的驗收依據。

留下工作需求與驗收紀錄

現在先在課堂筆記或工作便條抄下以下五欄，依你剛才觀察到的實際情況填寫。沒有親自確認的項目寫「未確認」，不要把預期結果當成已通過。這份紀錄會在下一站轉成提示詞。

✎
工作需求與驗收紀錄
  • 使用者與工作情境：小組例會主持人要在聽取報告時掌握每位發言者的時間。
  • 目前問題：一直看手機或心算時間，容易漏聽內容。
  • 必要輸入：會議主題、倒數秒數。
  • 預期結果：開始倒數、暫停保留時間、重設回已設定秒數、修改主題不重設計時、歸零停止且不顯示負數。
  • 驗收證據：記下開始、暫停、重設、主題修改、歸零五項的「預期／實際／通過或未確認」。

上面是根據本次情境整理的參考紀錄，不是替你代填的操作結果。請用自己剛看到的秒數更新「實際」欄；若參考品行為不同，把差異保留下來。到下一站時，你會把這些需求寫得更精確，再補上無效輸入和提醒邊界。

分清楚模型產生工具、瀏覽器執行工具

製作時，你把需求送到 Google AI Studio，Gemini 根據文字產生程式碼。使用時，瀏覽器讀取保存的 HTML，並依裡面的 JavaScript 執行每秒倒數、暫停和重設。模型回覆的是程式文字；按下「開始」後持續改變數字的，是瀏覽器裡的程式。這個計時器只執行明確規則，不需要在使用時再請 AI 判斷或呼叫 API。

本課要求交付「單一 HTML 檔案」，是為了讓零基礎學員先處理一個清楚的檔案：另存一次、雙擊一次，就能在瀏覽器檢查。若 HTML、CSS 和 JavaScript 分散成多個檔案，還要維持檔名和路徑正確；少一個檔案就可能載入失敗。把 CSS 放在 HTML 的 <style> 區塊、把原生 JavaScript 放在 <script> 區塊，則能避免另外安裝函式庫或設定建置工具。固定倒數不連外部 API，也能在檔案保存後離線使用。

離線執行不代表生成步驟也離線：送到 AI Studio 的提示詞會傳給雲端服務。練習時使用虛構的會議資料，不要貼入真實客戶名單、個資、薪資或公司機密。生成的程式仍須實際測試，單檔格式與清楚指令都不能保證程式必然正確。

先把工作需求寫成可以核對的結果

下面是一份可獨立使用的基礎提示詞。它已說明使用者、輸入、操作、無效值、交付格式和驗收方式；這不是刻意省略條件的短句。下一站會在這份基礎上加入新的會議主題與提醒要求，並說明每項新增條件要如何測試。

完整基礎提示詞｜會議倒數計時器
你是協助初學者製作瀏覽器單檔工具的前端工程助手。
工作情境：小組會議主持人需要提醒發言者剩餘時間。
任務：製作一個會議倒數計時器。
輸入：使用者可以輸入會議主題與正整數秒數；主題留白時顯示「未命名會議」。
操作規則：按「開始」後每秒減一；按「暫停」後數字保持；按「重設」後回到目前設定的秒數；倒數中修改主題只更新文字，不改變剩餘秒數。
例外與結束：秒數空白、0、負數或非整數時不可開始，須顯示修正提示；時間歸零後停止並顯示「時間到」，不可出現負數；重複按「開始」不可讓倒數加速。
輸出與限制：使用繁體中文，提供主題與秒數欄位及「開始」、「暫停」、「重設」按鈕。只交付一份完整 HTML；CSS 寫在同一檔案的 style 區塊，使用原生 JavaScript，不使用外部函式庫、框架、CDN 或 API。保存後的固定倒數操作不需要網路。
驗收：輸入 10 秒；開始約三秒後應剩約 7 秒；暫停等待兩秒數字不變；重設回到 10；倒數時改主題不重設；連按開始不加速；測試空白、0、-1、1.5 均不能開始，修正為 10 後可以使用；歸零後停止並顯示時間到。
交付：請只輸出從 <!DOCTYPE html> 到 </html> 的完整 HTML 程式，不要加說明、Markdown 圍欄或不完整片段。

逐項對照提示詞與表格：會議主持人說明用途；秒數與主題是輸入；按鈕規則說明操作因果；無效值與歸零條件處理邊界；單一 HTML 與內嵌程式碼界定交付方式；最後一行測試則告訴你怎麼判定結果。提示詞讓要求明確，並不替代測試。

把上方「工作需求與驗收紀錄」中的五項驗收結果連同完整提示詞保存在同一份筆記中；已填寫的部分不必再抄一次。這份基準會供 CH1-2 擴寫需求和 CH1-3 驗收工具使用。若帳號尚不能使用，先完成上面的參考品檢查，並把「AI Studio 生成待完成」明確記下，不要把參考品算成自己的成品。

下一站會把基礎需求擴成更完整的規格。你會保留原有行為，只增加有實際用途的條件，再把每條條件連到一項可觀察的測試。

確認生成入口與保存位置

下一站會把計時器規格交給 AI Studio，之後再把自己生成並通過測試的檔案保存下來。現在只確認帳號和位置，不要先下載提示詞或建立額外教材檔。

  1. 用電腦瀏覽器開啟Google AI Studio並登入可使用的 Google 帳號。官方快速入門目前以 Playground 的 Chat prompt 示範輸入及執行提示詞；介面名稱或位置若有調整，請查看官方快速入門。
  2. 在桌面或文件資料夾建立「AI工作工具」資料夾。CH1-3 會將實際生成的 HTML 放在這裡，方便你關閉後重開。
  3. 確認目前帳號能看見提示詞輸入欄與執行按鈕；若組織帳號限制使用，依組織規定申請核准，不要反覆重送登入。

帳號暫時無法使用時，仍可完成本章的參考品操作和需求紀錄，並在自己的筆記標記「AI Studio 登入待處理」。之後必須真的生成、保存和測試，才能把 CH1-3 標成完成；參考品不能代替自己的成果。

離開本章前，確認你能說出：計時器為誰解決什麼問題、開始／暫停／重設各會看到什麼結果、模型在哪個階段產生程式、瀏覽器在哪個階段執行程式，以及你要保存在哪個資料夾。這些就是下一站需要的起點。
