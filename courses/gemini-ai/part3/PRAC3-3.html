實例演練 3

用 KPI 月報做一項工作判斷

同樣的比值，會因指標方向產生不同結論；先核對數字再選圖表。

本次成果
正確判斷三種指標與缺值
交付有期間、來源與例外說明的月報

必修第 6／10 站 · 前站 做出能查核的活動預算表 · 從固定計算進到資料方向與缺值判斷；下一站開始讀懂會議原文。 · 下一站 開始會議語意判斷，不必先做完所有圖表練習。 · 查看十站完成證據。

先判斷，再生成月報

下載 三項 KPI 資料。件數越大越好；處理時間與錯誤率越小越好。先寫下 120 件、5 天、1% 各自是否達標，再看 月報參考品 · 下載 HTML 參考檔。

完成預判後核對答案

受理件數 120≥100，已達標；處理時間 5>3，未達標；錯誤率 1≤2，已達標。處理時間變長 25%，不能解讀成績效更好。件數較上期 +33.3%；錯誤率較上期 -33.3%。

下載完整生成指令 TXT

請製作部門 KPI 月報，單一完整 HTML，CSS/JavaScript 全內嵌、不用外部套件，不呼叫 AI。
每個指標有 metric 指標、unit 單位、direction（higher 越大越好／lower 越小越好）、target 目標、actual 實際、previous 上期、period 期間、source 來源。可新增編輯；CSV 匯入要驗證欄位、引號及非負數值。缺值不當零。
higher:actual>=target 達標；lower:actual<=target 達標。達標文字必須遵照方向，不用同一個 actual/target 百分比當所有指標的分數。圖表顯示目標與實際的比較，補文字、單位和方向，不能只靠顏色。上期變化=(actual-previous)/previous×100%；previous=0 或缺值時顯示不可計算。target=0 仍可判斷達標，但不計達成率。錯誤率以1代表1%，不可變成100%。
預設：受理件數 件 higher 目標100 實際120 上期90；處理時間 天 lower 目標3 實際5 上期4；錯誤率 % lower 目標2 實際1 上期1.5。期間2026-09，來源分別案件台帳、結案台帳、複核紀錄。
下載月報 CSV、列印另存 PDF、本機保存、JSON備份還原；匯入 JSON 先驗證資料再覆蓋，無效檔案保留目前資料並提示。缺數值可交付但須顯示待確認；指標、單位、期間或來源缺漏須阻止匯出。數字只說結果，不生成沒有證據的原因。手機表格容器可橫向滑動。只輸出完整 HTML 不省略。

同步操作：讓資料可以更新

沿用第3站的存檔方法，將這次完整 HTML 保存為 department-kpi.html。雙擊後應開成工具；看到程式文字時，回存檔步驟檢查純文字格式與 .html 副檔名。若修復後另存 v2，完成重測後以通過驗收的版本作為交付入口，保留舊版作歷史。

  1. 生成後核對三個達標狀態與上期變化，檢查圖表單位；每個測試在驗收表新增一列，先填版本、資料條件與預期答案。
  2. 在原始 5 天資料下下載 JSON 備份，命名 department-kpi-backup.json，存入「資料」資料夾。
  3. 將處理時間由 5 改成 2 天，先預判再操作；應改為已達標。工作判讀寫：「本期處理時間為 2 天，低於 3 天目標；較上期 4 天縮短 50%。」註明結案台帳為來源，不推測原因。
  4. 保存此狀態的 CSV 與 PDF，再用 department-kpi-backup.json 還原；三項數值應回到 120 件、5 天、1%。將還原觀察記入另一列，保留這份 JSON 並交給第9站。

例外：基期零、缺值與零目標

匯入 例外資料。新增服務上期為 0，本期 12：可判達標，但變化百分比不可計算。回覆時間實際缺漏：狀態待確認。錯誤率目標 0、實際 0：達標，不算 actual/target。

若未知被顯示為 0%，用這筆資料回原對話要求修復：「空值保持未知；基期為零顯示不可計算；不要以達成率統一判所有指標。」保存 v2，再測正常三項與例外三項。這次新增的判斷是方向與缺值，無須再做雷達、甘特與漏斗才能進下一站。

儀表板的設計核心是「狀態語言」：不同的顏色傳達不同的緊急程度。綠色代表好消息，橘色代表需要關注，這是一套不需要解釋的視覺語言。在製作工具時，把「條件判斷 → 顏色輸出」的邏輯描述清楚，Gemini 就能自動處理。

複製以下指令貼入 Gemini Canvas

→ 複製這段 Prompt 貼入 Gemini
你是一位擅長製作數據儀表板的前端工程師。 製作一個「KPI 成果儀表板」的單頁 HTML 工具，可輸入及編輯多組指標，每組包含名稱、單位、方向（higher 越大越好／lower 越小越好）、目標與實際值。 依方向判斷狀態：higher 時 actual≥target 為已達標；lower 時 actual≤target 為已達標。缺值顯示待確認，不當成零。target=0 時仍按方向判斷，但不計比值。狀態文字必須清楚；顏色只輔助閱讀。不要用同一個 actual/target 達成率或固定百分比區間替不同方向判定狀態。 每張卡片顯示指標名稱、方向、目標、實際、單位與文字狀態。圖表應能比較目標和實際，標出數值，不得讓裝飾性色條取代判讀。 【設計要求】 - 背景 #f5f3ee，卡片 #ffffff，邊框 #d8d4cb - 達標色 #5a7a5a，待確認或未達標以可辨識的文字和輔助色標示 - KPI 卡片排成 3 欄格狀，窄螢幕改為單欄 - 字體：Shippori Mincho + Noto Sans TC（Google Fonts） - 圓角 6px，無陰影、無漸層 生成完整單一 HTML 檔案，不省略。
