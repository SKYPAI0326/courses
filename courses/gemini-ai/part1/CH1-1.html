PART 1 · 解鎖 AI 開發者模式
1.1

從一個工作需求開始

看工作工具與貪食蛇範例，用白話提示詞生成單檔網頁、開啟並完成一項修改。

本次成果
生成並保存一份可在瀏覽器開啟的單一 HTML 遊戲
操作遊戲核心功能，觀察瀏覽器如何執行程式
提出一項修改並說明前後差異，區分生成與執行階段

先看工作工具，知道這件事跟工作有關

行政工作常有固定、重複的計算。例如活動承辦人要把預算明細整理成估算、實支、差額與餘額。你可以先開啟活動預算差異工具看它怎麼把欄位和計算結果放在同一頁。這份參考工具讓你先看到網頁應用程式能承接工作；它是現成展示品，不能算成你自己生成的成果。

接著看一個趣味例子：直接開啟你提供的貪食蛇遊戲。遊戲和預算工作不同，但都能用白話說明「要做什麼、畫面要怎麼反應」，再讓模型產生可以在瀏覽器操作的網頁。這一站的重點，是親自經歷描述、生成、開啟、修改；不要求你閱讀遊戲程式或學會遊戲演算法。

本節完成後，你會留下自己生成的 sushi-snake-v1.html、修改後的 sushi-snake-v2.html，並能指出一項修改前後的可見差異。這個成果用來體驗「白話需求也能變成可操作工具」；下一站才回頭分析，提示詞裡哪些句子讓模型比較知道要交付什麼。

模型產生程式，瀏覽器負責執行

先把兩個容易混在一起的階段分開。你把文字需求送給生成式 AI 時，模型是在產生程式文字；你把存好的 HTML 檔在瀏覽器打開後，瀏覽器才依照檔案中的程式執行遊戲。這款遊戲的規則在生成後由瀏覽器本機執行，不需要遊戲每走一步都再詢問 AI。

這次要求「單一 HTML 檔案」，是為了讓第一次做出的成果容易保存、開啟與交接。HTML 負責頁面結構，CSS 負責顏色與版面，JavaScript 負責移動、得分和碰撞等互動；把它們放在同一檔案，學員只需管理一個檔案。提示詞禁止外部函式庫、CDN、圖片檔和外部／雲端 API，避免成果依賴另一個網站或額外安裝；但允許使用瀏覽器內建的 localStorage 與 Web Audio API，它們在本機運作，不會把遊戲資料送出瀏覽器。單檔不會自動保證正確，所以仍要實際開啟並操作。

生成程式時仍需要連線到 AI 服務；存成單一 HTML 之後，這份提示詞要求遊戲核心在離線時也能執行。兩件事不要混為一談：生成階段會連線，執行階段則不呼叫 AI 或外部服務。

第一輪先做出完整可玩的經典版

現在先從一個範圍明確、可以實際玩一局的版本開始。這份提示詞不要求壽司店視覺、最高分、音效或自動代打；它仍然把遊戲規則、操作方式、錯誤情況和交付格式交代完整，讓你可以不用會寫程式，也能請模型產生一份可開啟的工具。

首輪完整提示詞｜經典貪食蛇，可直接複製
你是一位擅長把明確需求製作成單檔網頁工具的前端工程師。請為第一次使用網頁工具的玩家製作一款完整可玩的經典貪食蛇，讓我能在桌上型電腦或手機瀏覽器開啟。

【畫面與操作】
- 開始前顯示遊戲名稱、簡短操作說明和「開始」按鈕；遊戲中持續顯示分數；遊戲結束後顯示本局分數和「重新開始」按鈕。
- 蛇和食物要清楚可辨識，格線大小一致，畫面對比足夠。遊戲區在手機上縮放到螢幕寬度內，不出現水平捲動。
- 桌機使用方向鍵或 W、A、S、D 移動。手機提供上、下、左、右的大型觸控按鈕，點按時不要意外捲動頁面。

【遊戲規則】
- 開始時蛇長三格、分數為 0，初始方向向右；每次移動一格。
- 蛇每次只能往上、下、左、右移動，不可直接反向撞回自己的身體。
- 食物隨機出現在空格，不可和蛇身重疊。吃到食物後分數增加 10，蛇身增加一格，並在新的空格出現下一個食物。
- 蛇撞到牆壁或自己的身體時，遊戲結束並停止移動。
- 按「重新開始」後，蛇回到三格、分數歸零，遊戲可再次開始；重複點擊開始或重新開始，不可讓遊戲速度越來越快。

【交付限制】
- 只交付一份完整 HTML 檔案；HTML、CSS 和原生 JavaScript 全部寫在同一檔案內。
- 不使用外部函式庫、框架、CDN、圖片、字型檔；不呼叫外部／雲端 API 或伺服器。遊戲在離線時仍可遊玩，字型使用系統字型。
- 按鈕要有清楚的繁體中文名稱和足夠的點擊範圍。畫面文字簡短易懂，不使用尚未實作的按鈕或占位內容。

【完成前自我檢查】
請確認：開始後方向鍵或觸控按鈕可以移動蛇；吃到食物會增加 10 分且蛇身變長；食物不會出現在蛇身上；撞牆或撞到自己會停止並顯示結束畫面；重新開始會重設蛇和分數。最後只輸出從 <!DOCTYPE html> 到 </html> 的完整 HTML 原始碼，不加說明或 Markdown 圍欄。

第一輪的成果是一款可玩、可重開的經典遊戲。提供的參考檔還有更完整的視覺和功能；接下來你可以先做一項自己的修改，後面也會看到三份可依序使用的完整追加提示詞，示範怎麼把這個小工具逐步擴充成接近參考檔的版本。

把生成結果存好，親自開啟一局

在瀏覽器操作前，先把生成和執行分清楚：生成平台負責依提示詞產生程式文字；你保存並開啟 HTML 後，瀏覽器才執行遊戲。課堂需要使用文字生成平台，教師必須在課前提供已確認可用的模型與登入路徑，且不要求學員啟用付費；學員不需要自己挑模型。若教師尚未提供，先把生成狀態記為「待完成」，不要猜選模型、開通計費或把參考檔當成自己生成的成果。若指定的平台是 Google AI Studio，可參考官方快速入門了解 Chat prompt；介面名稱可能隨平台更新。

  1. 貼上首輪完整提示詞。在教師指定的生成平台開啟新的對話，複製上方「經典貪食蛇」整段提示詞並執行。若使用 AI Studio，依教師提供的模型路徑建立 Chat prompt。若畫面提示付費或要求啟用計費，先停止並請教師確認。
  2. 確認模型交付完整檔案。回覆應從 <!DOCTYPE html> 開始，直到 </html> 結束。若只有功能說明、程式片段或省略號，回覆：「請依原規格重新輸出完整單一 HTML，不要省略任何部分。」不要把片段當成完成品。
  3. 用純文字方式存檔。把完整 HTML 複製到文字編輯器。Windows 記事本使用「另存新檔」，檔名存為 sushi-snake-v1.html、編碼選 UTF-8；Mac TextEdit 先選「格式 → 製作純文字」再存同名檔案。確認檔名結尾是 .html，不是 .txt。這樣瀏覽器才會把它當成網頁開啟。
  4. 在瀏覽器開啟並核對核心功能。從檔案管理器找到 sushi-snake-v1.html，用瀏覽器開啟；按「開始」後用方向鍵、WASD 或手機觸控按鈕移動；吃到食物時分數應增加 10，撞牆或撞到自己時應結束，按「重新開始」後蛇和分數應回到起始狀態。你現在看到的是瀏覽器執行自己生成的程式。
i
卡住時：若瀏覽器顯示程式文字，先確認檔名不是以 .txt 結尾；若按鈕沒有反應，回到生成對話說明「實際看到什麼、原本預期什麼」，請模型重新交付完整 HTML，並保留舊檔。若帳號或平台暫時不可用，可打開上方的參考品觀察，但自己的生成狀態仍記「待完成」。

本堂先看五個核心行為：能開始、能移動、吃到食物後得分、碰撞後結束、失敗後能重新開始。若其中一項不工作，請模型修正並重新開啟檔案；不用因為有程式碼就把它當成已完成。

自己提出一項修改，觀察模型怎麼接續

若你的 v1 已能開啟，現在從外觀或規則中選一項你真的想調整的地方，再請模型修改同一個成果。這一步讓你體驗連續提出需求，不必一開始就把所有功能都設計好。

下面提供一個完整示例：只調整配色，明確說明要改哪裡、哪些玩法要保留，以及修改後要交付什麼。你也可以換成自己的要求，但一次先選一件事，才看得清楚修改前後差異。

連續修改提示詞示例｜只調整配色並保留原有玩法
請只修改我在目前對話中剛生成的經典貪食蛇單一 HTML：把遊戲區背景改成淺米色、蛇頭改成鮭魚橘、蛇身改成抹茶綠，並讓食物和背景保持清楚對比。
這次只改外觀，不改遊戲規則、鍵盤與觸控操作、分數、開始或重新開始功能；保留目前版本已能正常使用的行為。
修改後請交付一份從 <!DOCTYPE html> 到 </html> 的完整單一 HTML 原始碼，不要只給差異、程式片段、說明或 Markdown 圍欄。
  1. 先寫一句你想改變的外觀或規則；例如調整遊戲速度或增加一項操作。
  2. 在原生成對話貼上修改要求，等待模型交付完整 HTML，再另存為 sushi-snake-v2.html，不要覆蓋 v1。
  3. 重新開啟 v2，確認新要求有出現，再做一次原本的核心操作。若新功能出現但舊行為壞掉，描述觀察到的現象，請模型修正，並保留 v1 作比較。

到這裡你留下兩個可開啟的版本，並能用自己的話說明修改前後差異。下一站會拆解提示詞裡的角色、任務、限制與交付格式，說明每一項資訊如何讓需求更容易核對。

資料提醒：本次遊戲不需要真實工作資料。之後若把方法用在工作上，不要直接貼入個資、客戶資料、薪資或尚未公開的內部資訊；先使用假資料或經授權的去識別資料。

想逐步接近參考檔？依序追加這三份提示詞

以下三份提示詞都接續在前一份完整 HTML 的同一段生成對話中使用；每次只貼一份，取得完整新檔後另存一個版本，再重開檢查原有玩法仍正常。三份提示詞依序補上壽司店視覺、進階玩法和展示功能，讓你看到簡單版本如何透過連續修改接近你提供的參考檔。它們是課後或自選延伸，本堂只需完成一次自己的修改。

延伸提示詞 1｜加入壽司店視覺，保留核心玩法
請在目前對話中最新的經典貪食蛇單一 HTML 上，加入壽司店復古街機風格。遊戲區使用 400×400 畫布與 20px 格線，背景為淺米色、蛇頭為鮭魚橘、蛇身為醋飯白、食物為抹茶綠；加上清楚的遊戲標題、分數區、開始畫面和結束畫面，按鈕與字體風格一致，文字使用繁體中文，桌機和手機版都不能水平捲動。
這次先改畫面，不改蛇的移動、吃食物加分、碰撞、鍵盤與觸控操作、開始或重新開始規則。不要載入外部圖片、字型、CDN、框架，也不要呼叫外部／雲端 API。
交付修改後從 <!DOCTYPE html> 到 </html> 的完整單一 HTML，不能只回傳 CSS、差異、程式片段或 Markdown 圍欄。
延伸提示詞 2｜加入難度、暫停與本機最高分
請在目前對話中最新的貪食蛇單一 HTML 上，新增「入門、標準、進階」三種難度，預設標準。入門可穿越邊界並從另一側出現；標準和進階撞到邊界時結束。入門最慢、進階最快；吃到食物後可逐步加速，但要設最低速度，避免快到無法操作。
新增暫停／繼續、重設和重新開始；重設要清除本局蛇身與分數，但保留最高分。遊戲結束時顯示本局分數及該難度的最高分，最高分只保存在目前瀏覽器的 localStorage，不得宣稱跨瀏覽器或跨裝置同步。保留鍵盤控制，並確保手機觸控方向按鈕及在棋盤上滑動都能改變方向，遊戲時不意外捲動頁面。
保留既有視覺、分數規則與核心玩法，不使用外部函式庫、框架、CDN、伺服器或外部 API；localStorage 是瀏覽器內建能力，資料只留在本機。交付修改後從 <!DOCTYPE html> 到 </html> 的完整單一 HTML，並確認新難度及原有核心行為都能使用；不要只回傳程式片段或 Markdown 圍欄。
延伸提示詞 3｜加入音效、代打示範與視覺回饋
請在目前對話中最新的貪食蛇單一 HTML 上，增加預設關閉的音效開關；啟用時使用瀏覽器內建 Web Audio API 合成簡短音效，不載入音效檔。若瀏覽器不支援音效，遊戲仍須正常進行。
新增「觀看 DEMO」和遊戲中的「代打」功能：由本機 JavaScript 自動控制蛇，優先朝食物移動並避開撞牆或撞到蛇身；找不到安全路線時選擇可存活方向。DEMO 最長 30 秒，時間到即停止並回到可開始畫面；遊戲中可切回手動控制，暫停、重設和手動接管不可造成狀態錯亂。吃到食物時顯示短暫粒子效果，遊戲結束時棋盤可輕微震動；DEMO 時間到時顯示簡短提示；效果不能遮住分數和操作按鈕。
不要呼叫雲端 AI、外部／雲端 API 或伺服器；Web Audio API 是瀏覽器內建能力。保留既有玩法、視覺、難度和最高分功能。交付修改後從 <!DOCTYPE html> 到 </html> 的完整單一 HTML，確認代打不會連網；不得只回傳程式片段或 Markdown 圍欄。

逐項追加時，每次重新開啟最後版本並確認核心玩法仍可使用；哪個功能沒出現，就描述它原本應如何運作、實際又看到了什麼，再請模型只修正該項。這條練習路徑展示了連續修改能逐步把小工具補成參考品，不代表你必須在六小時課堂完成三份延伸提示詞。
