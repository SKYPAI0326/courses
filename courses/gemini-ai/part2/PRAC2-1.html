實例演練 1

做出能查核的活動預算表

沿用四項活動資料，改一個條件，找出差異並完成可交付報告。

本次成果
生成與核對兩個預算公式
處理缺值並輸出 CSV／PDF

必修 5／10 · 路線與成果自檢 · 本頁上方為正式步驟，下方保留原有延伸。

生成與載入標準資料

下載完整生成指令 TXT

請製作活動預算與核銷差異表，單一完整 HTML，CSS/JavaScript 全內嵌，不用外部套件、不呼叫 AI/API。
欄位：項目、數量（非負整數）、單價、實支總額、備註；可新增刪除明細。核定預算獨立輸入。空值、負數、非有限數值應阻止計算與匯出，不能默認零；金額最多兩位小數。所有費用已包含必要費用，不另外加稅。
逐項估算=數量×單價；估算合計加總逐項；實支合計加總實支總額；較估算差異=實支合計-估算合計；核定餘額=核定-實支合計，負餘額顯示超支。金額以分為單位計算避免小數累加誤差。
預設：講師4×2500實支10500（交通費）；場地1×8000實支8500（延長）；餐點40×150實支6500（配送）；印刷40×50實支2300（加印）；核定30000。
支援以 item,quantity,unit_price,actual,note 欄位貼上 CSV 匯入（中文與引號可用）；錯誤資料不覆蓋原資料。下載明細 CSV 與總額；列印／另存 PDF；本機保存；備份 JSON 並可還原，還原先驗證再覆蓋。手機表格在自己的容器內橫向滑動。
預期：估算26000、實支27800、差異1800、餘額2200。只輸出 <!DOCTYPE html> 到 </html> 的完整內容，不省略。

沿用第3站的存檔方法，將這次完整HTML保存為 activity-budget.html。雙擊後應開成工具；看到程式文字時，回存檔步驟檢查純文字格式與 .html 副檔名。保留上一版，不用覆蓋原有計時器。

打開自製工具，核定填 30,000。若預設資料缺漏，把 標準資料 以純文字打開，貼入 CSV 匯入區。核對 26,000／27,800／1,800／2,200 四個值；來源檔 actual 是逐項實支總額，不再乘數量。

同步修改：餐點改為 45 人

每個測試各新增一列驗收紀錄。操作前先填工具檔名／版本、資料條件、來源模式和預期答案；操作後再填觀察結果與結論，不覆寫原本的正常測試。

  1. 先預判哪個值會改。只把餐點數量改 45，單價與實支暫時不動。
  2. 重新核對：估算、實支、差異與餘額。告訴同桌為什麼餘額沒有跟著改。
  3. 核定改 27,000，應顯示超支；改回 30,000。每個狀態分開記錄，修復後另新增一列再測。
完成預判後核對答案

餐點估算 6,750；總估算 26,750；實支仍 27,800；差異 1,050；餘額仍 2,200。核定 27,000 時餘額 -800。

例外與修復：未知不能當零

下載 缺值／負數資料，先不要覆蓋已完成資料。匯入應拒絕並保留目前明細；或直接清空餐點數量，工具應停止總額與匯出。填回 45 後應恢復。

若空值被當零，回原對話貼：「餐點數量空白時仍有總額；請將空值與負值判為錯誤，停止計算與匯出，修正後恢復，輸出完整 HTML。」保存 v2 並重跑正常與空值測試。只修改提示而仍顯示舊總額不算修好。

交付並確認可再次更新

  1. 下載明細 CSV，用試算表打開，確認中文、逐項估算與總額。
  2. 選列印，目的地選「另存 PDF」，保存 activity-budget-report.pdf，開檔核對四個總額與備註。
  3. 下載 JSON 備份，關閉工具後重開；修改一個備註，重新輸出。若換電腦，以 JSON 還原並核對。
  4. 保存完整指令與驗收紀錄。若修復另存了 v2，先完成原測試再以 v2 作為交付版本；在 README 寫明實際檔名，把未通過的舊版移至「歷史版本」。工具資料只存在目前瀏覽器時，必須交付資料備份。

卡關時可用 參考預算工具 · 下載 HTML 參考檔 比對公式、匯入與輸出，記錄哪些步驟仍是待完成。

HOW TO REPLICATE · 如何自己做出這個工具

讓 Gemini 幫你做一個專屬的計算工具

1
想清楚你需要哪幾個計算欄位
這個工具的核心是「多列 × 多欄 → 即時加總」。你可以把工時費用改成：材料用量 × 單價、出差天數 × 日費……任何乘法加總都適用。
2
複製並貼入以下 Gemini 指令
注意指令中「動態新增列」的描述方式——這是讓 Gemini 理解你要可互動的表格，而不是靜態的 HTML 表格。
3
用你實際的報價項目測試
填入幾個真實的工作項目，確認計算結果正確，再調整格式和欄位名稱，然後存檔。
→ 複製這段 Prompt 貼入 Gemini
你是一位擅長製作互動計算工具的前端工程師。 製作一個「專案工時費用試算機」的單頁 HTML 工具，功能如下： 【功能需求】 - 一個可動態新增列的計算表格，每列包含： · 工作項目（文字輸入） · 預估工時（數字輸入，單位：小時） · 時薪（數字輸入，單位：元） · 小計（自動計算，唯讀，即時更新） · 刪除按鈕 - 預設有 3 列範例資料 - 「新增項目」按鈕，點擊後在表格末尾新增一空白列 - 表格下方顯示費用摘要區： · 工時費用小計（所有列的小計加總） · 管理費加成（可輸入百分比，預設 20%） · 稅前合計 · 加值稅（可輸入百分比，預設 5%） · 含稅總報價（以粗體大字顯示） - 「複製報價摘要」按鈕，將摘要以文字格式複製到剪貼簿 【設計要求】 - 背景色 #f5f3ee，卡片 #ffffff，邊框 #d8d4cb - 強調色 #c9963a（芥末黃），按鈕與重點數字使用此色 - 字體：Shippori Mincho + Noto Sans TC（Google Fonts） - 圓角 6px，無陰影，無漸層 生成完整的單一 HTML 檔案。
CHALLENGE · 進階挑戰

把這個工具升級成你的報價神器

PRACTICE VARIATIONS
01
把「工時 × 時薪」改成你工作中實際的計算邏輯（字數×單字稿費、辦公用品請購的數量×單價、活動訂餐的人數×餐費單價）。
02
讓 Gemini 幫你加入「匯出為 PDF」功能，讓這份報價單可以直接寄給客戶。指令中加一句：「新增列印/PDF 匯出按鈕」。
03
加入「預算上限」欄位——當總報價超過設定的預算時，顯示紅色警示，提醒需要調整工作項目或時數。
