## 1. 設計目標與已確認方向

課程對象是程式零基礎學員。六小時主線要讓學員先體驗白話提示詞如何生成單一 HTML 網頁工具、再理解提示詞如何描述工作規則，接著完成一件有工作用途的成果，並親自修改、核對、修復與保存。課後案例庫承接其他職務與工具類型，每個案例都要能獨立操作，並附完整可直接使用的提示詞。

本設計依使用者最新指示採用「一個完整工作案例」作為課堂主軸，並在第一階段放入貪食蛇小型生成例子。貪食蛇是趣味入口，不能取代工作案例或使課堂變成遊戲程式設計課。薪資案例移至補充教材；時區協調案例從新版移除；貪食蛇提供的是既有成品參考，並另寫完整提示詞讓學員嘗試生成相近玩法。

目前推薦的唯一工作案例是「活動預算與核銷差異表」：有虛構 CSV、既知答案與可重複驗算資料，適合展示固定規則如何成為可重用工具。此候選以班級工作情境包含行政承辦為前提；若本梯明確以業務報價為主，應在正式定稿前改選報價工具，不能把不同商業計算規則拼在同一案例。

## 2. 建議課堂順序與時間

以下為 **360 分鐘教學活動**的規劃估值，暫以休息時間不計入六小時計算。尚未經真人試教，實際時長要依 AI Studio 帳號、學員生成速度和操作卡點調整。

| 階段 | 規劃時間 | 建議單元 | 學員要完成的事與學習增量 |
|---|---:|---|---|
| 1. 應用生成初體驗 | 50 分鐘 | CH1-1：白話需求到可用小工具；貪食蛇作章節小型範例 | 先簡短展示工作小工具與遊戲成品，再用貪食蛇提示詞完成一次生成、開啟與核心操作；學員選一項外觀或規則要求模型修改。貪食蛇用來讓初學者感受「描述→生成→執行→再修改」，不把整階段變成遊戲設計課，也不要求閱讀 Canvas 尋路程式或測遍所有進階功能。 |
| 2. 應用程式提示詞設計 | 85 分鐘 | CH1-2：黃金公式；CH1-3：提示詞類型 | 先回看貪食蛇提示詞，理解角色、任務、限制、呈現各句的用途；再比較單檔互動工具、固定計算函數與多條件判斷各自要說清楚的輸入、規則、例外和結果。這裡拆解需求，不要求重做多個工具。 |
| 3. 工作情境應用 | 140 分鐘 | CH2-1：手算預算規則；PRAC2-1：生成預算工具 | 先用同一份資料算出估算、實支、差額和核定餘額，再把已知規則寫入完整提示詞、生成工具並產出可交付報表。每個數字都要知道比較基準，避免把「超出估算」誤當「超出核定預算」。 |
| 4. 延伸、保護與修正 | 60 分鐘 | CH4-1：保存與重開；PRAC4-3：獨立改造 | 沿用預算工具，由學員選一項新規則或工作呈現需求；先預測會影響什麼，再修改、重跑原測試和新增測試，最後保存可重開成果與使用說明。這是同一工作案例的獨立遷移，不另起第二套案例。 |
| 5. 課後補充與收束 | 25 分鐘 | 補充案例庫導覽 | 學員依工作挑一個後續案例，知道其先備條件、素材、完整提示詞、預期結果和限制。課堂不把剩餘案例快速演示一輪來充數。 |
| **合計** | **360 分鐘** |  | 規劃值；不代表真人試教通過。 |

順序先讓學員看到成果，再回頭拆解提示詞，符合「先體驗、再理解」的課程定位。第一階段只做一次生成和一次自選修改；詳細規則驗收集中到預算工具，避免貪食蛇的按鈕或遊戲狀態變成課堂主題。

### 各階段完成證據

- **生成與修改體驗**：學員能開啟自己生成的 HTML，指出一項修改前後的差異；若生成失敗，使用參考品觀察仍須標記為「參考品」，不能記成學員生成通過。
- **提示詞設計**：學員能指出一項輸入、一項規則、一項例外、一項交付限制，並說明它對結果的影響；黃金公式是需求整理方式，不是正確性保證。
- **工作案例**：學員能說明四個預算數字的計算依據，並用提供的資料生成可查核工具及報表。
- **修改與保存**：學員留下修改前後提示詞、原測試與新增測試結果、可重開版本及簡短使用說明；尚未實際執行的項目保持待測。
- **課後補充**：學員能依工作需求選案例，並知道可在哪裡取得提示詞與測試資料。

## 3. 貪食蛇章節小型範例

使用者提供的 HTML 是單一檔案（45,313 bytes；SHA-256：`74c0f38632572ffb0a622244313c0bd519944b411a1b707a6a520ce48886c892`）。靜態檢視未發現外部字型、圖片、函式庫或 API 連線。畫面使用 Canvas，包含三種難度、穿牆／撞牆規則、速度隨得分增加、分難度最高分保存、鍵盤與手機觸控控制、暫停／重設、Web Audio 音效及 30 秒代打示範；吃到食物有粒子效果、結束畫面有震動效果，代打中止會出現提示氣泡；代打有尋路與無路可走時的生存策略。這是功能完整的參考品，不能把它簡化描述成只有方向鍵和吃食物。

在課堂中的角色：它是 CH1-1 的趣味小型範例，與工作小工具的成品展示並列，用來具體呈現白話提示詞可以生成可操作的單檔網頁。學員可以複製以下完整提示詞生成同類型、具相同核心玩法的遊戲，開啟後試玩，再自行挑一項外觀或規則要求模型修改。範例聚焦「提示詞能產生並修改應用程式」；不拆解 BFS、不要求重建每一段 JavaScript，也不把所有進階功能測試列成必修。代打需由本機程式執行，不呼叫 Gemini API，也不把遊戲內的「代打」說成雲端模型判斷。

### 可直接使用的生成提示詞（課程設計稿）

```text
你是一位擅長製作單檔互動網頁遊戲的前端工程師。請製作一款「壽司店風格的貪食蛇」遊戲，讓我能直接在桌上型電腦或手機瀏覽器遊玩。

【角色與任務】
製作一個完整可玩的貪食蛇遊戲。玩家控制蛇吃食物、累積分數；蛇撞到自己，或在不允許穿牆的難度撞到邊界時，遊戲結束。介面要有溫暖、有趣的壽司店視覺，讓人一打開就看得懂如何開始。

【畫面與技術限制】
- 最後只輸出一份完整、可直接存成 `.html` 並以瀏覽器開啟的單一 HTML 檔案。
- 所有 HTML、CSS 和原生 JavaScript 都寫在同一檔案；不可交付多個檔案、程式片段、偽程式碼或要求我自行補完。
- 不使用外部函式庫、框架、CDN、圖片、字型檔、API 或伺服器。遊戲核心功能在離線時仍可遊玩；字型使用系統字型並提供一般 sans-serif 後備。
- 遊戲主畫面使用 400×400 的 Canvas 與 20px 格線，畫面在手機窄螢幕可完整顯示，不出現水平捲動。
- 視覺以米飯米色背景、木炭棕文字與外框、鮭魚橘蛇頭、醋飯白蛇身、抹茶綠食物為主；可讓食物在數種清楚可辨識的顏色間輪替。按鈕、分數區、開始畫面和結束畫面需有一致的復古街機風格。

【遊戲規則】
- 開始時蛇長三格、分數為 0；食物不得出現在蛇身上。
- 每吃到一個食物加 10 分，蛇身增加一格；食物被吃掉後，在空格重新出現。
- 蛇每次只能往上、下、左、右移動，不接受直接反向撞回自己的身體；撞到自己時結束遊戲。
- 提供「入門、標準、進階」三種難度，預設標準。入門可穿越邊界並從另一側出現；標準與進階撞到邊界就結束。入門最慢、標準其次、進階最快；吃到食物後速度逐步增加，但需設速度下限，避免快到無法操作。
- 遊戲結束時顯示本局分數、該難度最高分，以及重新開始按鈕。最高分依難度分開保存於目前瀏覽器的 localStorage；不得宣稱可跨瀏覽器或跨裝置同步。
- 支援暫停／繼續、重設和重新開始；重新開始時清除本局蛇身與分數，但保留已保存的最高分。

【操作方式】
- 電腦可用方向鍵或 WASD 控制；Space 可暫停／繼續，Enter 可在結束後重新開始。
- 手機提供上、下、左、右觸控按鈕，也支援在遊戲區滑動改變方向。操作遊戲時不可意外捲動頁面。
- 按鈕需有清楚的中文名稱及足夠的點擊範圍；鍵盤控制與觸控控制都必須可用。

【音效與代打示範】
- 提供預設關閉的音效開關；若啟用，用瀏覽器原生 Web Audio API 產生簡短音效，不載入音效檔。音效無法播放時，遊戲仍須正常進行。
- 提供「觀看 DEMO」和遊戲中的「代打」功能。代打由本機 JavaScript 自動控制蛇，優先朝食物移動並避開撞牆或撞到蛇身；找不到安全的吃食物路線時，改走可存活的方向。不得呼叫雲端 AI 或外部服務。
- 遊戲中的代打可切換回手動控制；DEMO 最長 30 秒，結束後停止並回到可重新選擇難度的畫面。代打進行期間暫停按鈕不得造成狀態錯亂。
- 吃到食物時顯示短暫粒子效果；遊戲結束時棋盤可輕微震動；代打時間到時顯示趣味提示。這些效果不能遮住分數、控制或重新開始按鈕。

【狀態與錯誤處理】
- 初始畫面可選難度並按「開始」或「觀看 DEMO」；開始後隱藏初始選項，遊戲結束後再顯示。
- 遊戲計時器不可重複啟動；快速連點開始、暫停或重設時，畫面及遊戲狀態仍須一致。
- 蛇不能反向移動；食物不能與蛇重疊；最高分讀取失敗時以 0 分開始，不可使遊戲停止。
- 若瀏覽器不支援音效或 localStorage，需安全降級並讓核心遊戲仍可操作。

【完成前自我檢查】
請確認輸出的 HTML 中沒有外部依賴或未完成占位內容，並檢查：開始後方向鍵能控制蛇、吃到食物增加 10 分、入門難度穿牆而標準難度撞牆結束、暫停後能繼續、重設能清除本局分數、手機觸控按鈕可操作、音效關閉時仍可遊玩、代打不會呼叫網路服務。最後只交付完整 HTML 原始碼，不要只提供功能清單或片段。
```

這份提示詞把使用者能觀察的行為寫成規格，不要求學員決定內部尋路演算法。原檔的 BFS／生存策略可供教師理解代打難度，但第一階段只看生成、執行和一次自行選擇的修改。提示詞本身沒有在本次驗證中實際送入模型生成；輸出是否能完整實作，仍須用課程採用的平台做作者試跑及學員冷讀。

### 章節內的最小操作與檢查

1. 教師先展示一個工作小工具與貪食蛇的完成畫面，讓學員看到單檔網頁可以承接不同用途；不先講程式碼。
2. 複製上方完整提示詞，要求模型輸出 HTML，存檔並以瀏覽器開啟。先用方向鍵或觸控移動、吃到一個食物，觀察分數變化，確認成果可操作。
3. 學員自行選一項想改的外觀或規則，請模型在原成果上修改，再比較前後差異。這一步呈現連續修改能力；其餘難度、音效與代打留給有興趣的學員探索，不把完整遊戲 QA 變成第一階段的學習目標。

將使用者提供的 HTML 原樣複製至課程 `assets` 並記錄來源雜湊，讓學員能從章節連結開啟或預覽，不要求學員另找雲端硬碟路徑或下載一包資料。生成提示詞與學習說明直接列在章節內，不能只連到下載檔。

## 4. 唯一工作主案例：活動預算與核銷差異表

課堂主要工作案例採一份預算工具，不再同時把 KPI 和 AI 會議交辦當成完整必修案例。現有素材目錄已有 `budget-normal.csv`、`budget-invalid.csv`、`budget-transfer.csv`、`reference-answers.json` 與 `prompt-budget.txt`；正式定稿前仍須逐項核對檔案內容、提示詞完整度、答案及下載／頁面內呈現方式。

核心計算需維持以下區別：

- 預算估算合計：26,000 元。
- 實際支出合計：27,800 元。
- 實支比估算多：1,800 元。
- 核定上限 30,000 元時，尚餘：2,200 元。

**階段三**讓學員先手算以上關係，再依固定規則生成工具。提示詞和教材需明訂金額計算、缺值／負值處理、輸出欄位與技術交付方式；若接受的資料皆為已含稅最終價，需寫明本例不另外計算稅額。CSV、列印或其他匯出只有在成果真的需要交付時保留，並提供能驗收的檔案內容。

**階段四**沿用同一工具，讓學員選擇一項貼近自身工作的需求修改。預設素材 `budget-transfer.csv` 可用來檢查核定上限 25,000 元時低餘額提示；同時重跑原始正常資料及缺值／負值例外，避免新增功能破壞原有計算。未實際匯出、重開或還原的行為不得記成通過。

## 7. 待確認事項與風險

1. **貪食蛇範例範圍**：本設計把「相同遊戲」解讀為相同核心玩法及可辨識的主要互動，不承諾逐像素複刻。完整提示詞涵蓋參考品的主要玩家可見功能，包括代打；提示詞用可觀察行為描述代打，不指定 BFS。作者尚未用實際課程帳號測試整段提示詞。
2. **六小時是否含休息**：時間表暫以 360 分鐘實際教學時間、不含休息為基準。若六小時是活動總時長，必須扣除休息與行政時間後重新配置，不能照表宣稱可完成。
3. **主工作案例適配**：活動預算較接近一般行政承辦情境；如果這梯學員主要做業務報價，應在正式路線定稿前改用報價案例並重新核對計價規則與答案。
4. **平台與帳號**：正式課堂需確認可用生成平台、登入權限、輸出完整 HTML 的路徑及無法使用時的備援。這份設計不宣稱平台 UI 或帳號已實測。
5. **生成時間與跟做負擔**：貪食蛇全功能提示詞可能生成大量程式碼；本次 50 分鐘只是規劃值。需做一輪作者試跑和零基礎冷讀，再決定是否保持全部功能或把代打列為完整的選修追加提示詞。
6. **補充案例的可教性**：歷史提示詞稽核顯示沒有一個舊提示詞區塊可直接通過完整案例驗收。課堂路線獲准不代表補充頁已完成；每一個案例仍要完整重寫提示詞、示例、操作、結果判讀、修正及限制。
